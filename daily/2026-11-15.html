1/8 · RL / Preference Alignment · JEV / Process Reward · 作者 2026-11-12 v1；2026-11-13 arXiv 公告

Actor, Judge, or Teacher? Understanding Decision Models in Long-Horizon Agents

一个自己当 Actor 只有 42.9% 完成率的 JEV，却能在全轨迹 Hindsight + Progress 监督下把 1.5B 策略的 ALFWorld 成功率从 72.8% 推到 82.9%，WebShop 从 56.8% 推到 71.4%。这说明 Reward 教师的好坏不能以其独立生成能力判断。

1. 背景与业务动机

在商品评价生成式重排中，Generator 负责选择 List，Reward/Judge 负责评价 List 或各位置动作。多步 Agent 也有同样的信用分配难题：最终结果成功不代表每个操作都有贡献，且一些关键步骤当下没有立即收益。

2. 现有方法和关键矛盾

作者让同一 Decision Model 分别扮演 Actor（事前选动作）、Judge（事后评价）和 Teacher（把评价给 RL）。Actor 很容易先执行更简单、但次序错误的子目标；评价模型有可能在事前不会做、事后却能准确识别依赖步骤。比较 Prefix/Hindsight × Value/Progress 四种问法，是本工作的关键对照。

3. 技术方案与关键模块

输入为任务、备选动作以及已记录的轨迹；Decision Model 输出每个选择的概率/评分。Hindsight 让 Judge 看到完整轨迹；Progress 问当前动作是否推进目标，而非问剩余任务最终能否成功。因而它能把先做铺垫的动作与无用动作分开。

4. 训练方法、Loss 与监督信号

训练时在 rollout 结束后，使用冻结的 JEV 给每一步打 Progress 分；这些分数在每个 rollout group 内中心化后加到 GRPO 的 outcome advantage，形成 step-level credit。重要的是 Teacher 只作用于训练；不要求推理时调用 JEV，也不把最终结果直接复制成每步 Reward。

5. 推理 / Serving 方案

Serving 是普通策略 Actor 独立执行；Teacher 训练离线使用，无测试时额外 API 调用。把方法搬到评价列表时可在线只运行已训好的 Generator，对匿名列表替代方案使用离线 Teacher；明确不能在在线决策时读取未来用户行为。

6. 实验设置、数据集与基线

对照三种 Decision Model、三种通用 LLM 的 Actor/Judge；Teacher 用 Qwen2.5-1.5B/7B 在 ALFWorld 与 WebShop 训练。使用 150 训练步、每批 16 任务、每任务 8 rollouts；评价取三个推理随机种子，ALFWorld 最多 30 动作，WebShop 最多 15 动作。

7. 离线指标、消融与结果

1.5B 的 GRPO → Hindsight+Progress：ALFWorld 72.8%→82.9%（+10.1pp），WebShop 56.8%→71.4%（+14.6pp）；7B 分别为 77.6%→83.8%、66.1%→73.6%。Hindsight+Value 在 ALFWorld 仅 69.3%，显示打分问题设计可比模型规模更重要。均为作者模拟任务结果而非线上成交指标。

8. 线上 A/B 与工业证据边界

**没有可核验的真实用户/电商评价列表随机 A/B**；WebShop 是模拟购物交互任务，不能把 71.4% 称为生产 GMV 或评价满意度增长。

9. 效率、延迟与成本收益

表中 JEV 教师调用约 22.21–30.07 美元/训练实验（按论文时点价格和特定配置），可训练离线摊销，但未包括全部 GPU、数据生产与线上监控成本。训练监督更密集、测试侧没有额外模型调用，是其系统优势。

10. 与主流方法的优劣势

相比纯 outcome GRPO，它识别步骤贡献而非全轨迹同奖惩；相比 PRM 人工逐步标注，它用冻结 Decision Model 降低监督工程成本；相比让 JEV 直接当 Actor，Teacher 用事后信息反而可帮助较小模型超过自身 Actor 表现。

11. 推荐 / 搜索算法适用场景

评价场景可把候选 List 生成视为一条选择轨迹，评价『该条评价/该位置是否带来了有效信息与用户决策进展』，在 List-level 成交/满意度监督之外加入过程信用。先采用离线训练与既有曝光回放，做同候选集的反事实排序评价。

12. 局限与失败模式

只验证两种文字模拟环境且最长 30 步；Judge 能看到真实完整轨迹，标签的因果性、样本选择偏差、线上低时延推理收益未验证；训练期事后信号不能泄露进在线输入。

13. 尚未解决的问题和未来研究方向

下一步将 Hindsight Credit 改为可校准的 exposure-aware causal contribution，研究同候选集合中多评价互补与替代的交互，以及不确定性低时自动关闭教师权重。

14. 工程实验优先级与职业技能启发

优先做四格实验：Prefix/Full × Value/Progress，固定 Generator 和候选池；比较 List-NDCG、成交流程转化、满意度校准、位置敏感性、OOT 跨类目稳定性。技能重点是 credit assignment、GRPO/DPO、Reward calibration 与反事实实验设计。

2/8 · RL / Preference Alignment · Partial Verifier · 作者 2026-11-12 v1；2026-11-13 arXiv 公告

Negative-Only Policy Optimization for One-Sided Verifiable Rewards

在只能确定『失败』、不能确定『成功』的验证器环境，NOPO 不奖励看似通过的候选，而只抑制经过可靠检查的负样本；它把 Reward 正例的认识不对称显式纳入策略训练。

1. 背景与业务动机

生产推荐的『未投诉』『没有跳出』『某个质检没报错』常只是未发现失败，不能等价于满意；代码/推理 Agent 的单元测试也可能出现通过但错误的候选。基于不完整检查器给所有“通过”样本正奖励会驱动投机。

2. 现有方法和关键矛盾

标准 RLVR 把 verifier=pass 当作真阳性；在 one-sided verifiability 条件下，确定 fail 才有确证力，pass 仅意味着未被反驳。假阳性随策略强化，会产生 Reward Hacking。

3. 技术方案与关键模块

定义 OSV：verified negative 可信，verified positive 只是 unlabeled。NOPO 用参考策略相对的 negative suppression 抑制已确认坏轨迹；group-level adapter 根据组内未被证伪的比例调整抑制强度。关键不是设计更强 verifier，而是改变谁有资格获得梯度。

4. 训练方法、Loss 与监督信号

训练端只对确定的负样本做策略更新，非证伪候选不直接获得正向奖励。参考相对约束降低远离初始策略的风险；组比例自适应避免所有候选皆坏/皆未证伪时不稳定。作者论文摘要未提供完整超参数与精确 Loss 公式，此处不臆造实现细节。

5. 推理 / Serving 方案

推理可保持原策略采样、增加 pass@k 预算；校验器用于训练采样阶段，不代表部署中必须串联复杂 Judge。若训练负样本支持集窄，线上容易转移到未知失败模式。

6. 实验设置、数据集与基线

论文报告 unit-test、constraint-check 与 LLM self-verifier 三种不完全检查环境，覆盖代码、逻辑、数学任务，并与一般 RLVR 基线比较；尚无来自推荐/评价场景的公开验证。

7. 离线指标、消融与结果

作者报告在无 oracle reward 时，NOPO 的 pass@k 相对基线改善，且在 inference-time scaling 和跨 benchmark 转移中有效；当前已核实摘要没有可安全转录的统一百分点，禁止杜撰数值。

8. 线上 A/B 与工业证据边界

**无可核验真实推荐 A/B**，也没有电商成交/评价满意度的线上随机试验；仅能作为训练思想迁移。

9. 效率、延迟与成本收益

训练需多条采样和可信 falsifier，可能增加 sample/verification 成本；但避免把不可靠正例加权，也可能降低后续 Reward 修复费用。作者未给可直接套用的推荐 Serving 成本收益。

10. 与主流方法的优劣势

相较经典正负双向 RLVR，NOPO 更保守且抗虚假正奖；相较 DPO 的人类成对偏好，不依赖正例可被证明，但对负例覆盖度更敏感；在有高精度真实正标签的任务中可能反而浪费监督。

11. 推荐 / 搜索算法适用场景

可将『内容违法/与商品不符/错误事实/强广告/重复评价』等高可信负例用于 List Generator 的约束对齐；不可把『没有投诉』当满意标签。保持商业价值 Reward 和可靠违规信号双通道。

12. 局限与失败模式

论文验证器的可靠负例假设仍需审计；如果负例本身误报，就可能压制正确内容；只压负样本是否会损害多样性/长尾覆盖尚无电商证据。

13. 尚未解决的问题和未来研究方向

下一步研究正例部分识别、PU-learning / selective risk、负样本置信权重，以及 NOPO 与 exposure-aware List Reward 的双目标边界。

14. 工程实验优先级与职业技能启发

落地先标定标签 precision：通过人审核对 verified-negative 的真错率，再做 outcome-GRPO、普通 DPO、NOPO 三组比较；看线上风险率、Reward 与成交长期背离、OOD，以及 sample efficiency。技能：partial identification、离线 RL、可信标签设计。

1. 背景与业务动机

商品评价问答、RAG 购物决策和评价摘要均常提供『来源于某条评价』的引用。传统可归因只要求原文支持生成句子，不能证明该句真由那条评价促成；模型可能先用先验回答，再找一致的评价作引用。

2. 现有方法和关键矛盾

作者区分 corroborative support（引文与断言一致）与 contributive/faithful provenance（引文对生成确有影响）。NLI entailment 可测前者却天然无法断言因果使用，因此标准引用精度容易高估证据可信。

3. 技术方案与关键模块

测量方法：把检索段落及标题里的某个事实数值替成明确相反的假值，再重新生成；若回答跟着替代值变化，说明上下文有作用；若坚持旧值，说明参数记忆可能主导。这是操作性定义，不是内部神经机制的真实证明。论文比较十种 attribution signal。

4. 训练方法、Loss 与监督信号

本论文主要是评估/检测，而非训练新 Generator；实验采用 greedy decoding 与记录替换值。可将此干预构成 contrastive provenance labels，为后续引用忠实度 Reward 训练提供监督，但这种训练收益不是论文已验证结论。

5. 推理 / Serving 方案

部署式检测通过比较有/无 context 的 token 分布，局部化到存在争议的事实 token ；每个断言需要两次前向。它仍不够准确到作为稳定的自动线上拒答策略；应先用于采样审计。

6. 实验设置、数据集与基线

测试多个 Qwen2.5 尺寸和另一模型族；对模型已知事实进行替换，检查拒绝、引用、记忆等行为，并对十种 attribution 方法做统一对照。作者显式指出标题替换遗漏会让原先测得的归因失败率约夸大一倍。

7. 离线指标、消融与结果

默认替换距离下 parametric provenance 率约 1.2%–15.7%；保守 near 设置下两个模型是 4.6% 与 8.5%。NLI 级支持性判别接近随机水平；不等同于所有 RAG 引用有 15.7% 错误，比例依赖任务和替换强度。

8. 线上 A/B 与工业证据边界

**无线上 A/B**；研究的是离线生成与引用，不是线上评价列表转化、满意度或申诉率。

9. 效率、延迟与成本收益

本地检测约每 claim 两次 forward；相较需多次抽样/反向的 attribution 方法更便宜，但用于高 QPS 大规模页面仍应按被引用内容重要性分层抽检。

10. 与主流方法的优劣势

2. 现有方法和关键矛盾

一般 memory benchmark 每个任务重置工作区或只测解题率。CoReMem 设定连续代码仓库任务：上一任务修改的仓库保持，下一任务未知，跨任务只能带一份 memory；这迫使系统在写记忆时预测真实未来价值。

3. 技术方案与关键模块

提出 prospective segment valuation：在相同继承仓库状态下，比较下个任务用不同记忆与不用记忆的 resolve、步数和 tokens；按剔除轨迹片段后的增量价值筛选内容。有效 anchors 多是路径、关键位置、检查命令和返回码，而非冗长 reasoning narrative。

1. 背景与业务动机

检索增强 Agent 经常从网页/文档读取非可信字符串，如果外部文本能改写目标、金额、收件人或写入路径，业务系统将面临越权行动。小模型尤其难稳定生成完整安全规则。

2. 现有方法和关键矛盾

CaMeL、Progent、IPIGuard、DRIFT 依赖 Agent 生成的程序/权限/依赖图作为被执行的安全产物；产物生成错误后，代码执行再严格也无法修复原始授权漏洞。

3. 技术方案与关键模块

CapLite 使用工具 schema 静态派生字段权限，Planner 在读取任何工具响应前承诺所有允许的写操作，Binder 仅从经准入候选中填参数，Mediator 对所有决定写入对象的 authority arguments 与用户原文严格匹配；模型只提出动作，确定性代码最终授权。

4. 训练方法、Loss 与监督信号

本文不是用 RL 学出安全策略，而是用系统约束将决策从自然语言模型迁到确定代码；计划与绑定可由小模型生成，但安全关键检查来自 schema 和请求。因此可验证安全性质基于具体威胁模型。

5. 推理 / Serving 方案

Serving 增加固定检查与 schema 元数据，反而能减少多轮模型自行编写/审查安全策略的 token；在写文件、外呼接口、发消息的 Agent 流程中须事前声明授权目标，预读外部数据不能新增写目标。

6. 实验设置、数据集与基线

15 个 open-weight 模型，13 个在 1.7B–12B；AgentDojo 929 项工具目标 × 多个模型形成 13,935 个被攻击 episode。与 CaMeL、Progent、IPIGuard、DRIFT 及 undefended 基线比较攻击成功、任务 utility 和 tokens。

7. 离线指标、消融与结果

论文报告 CapLite 在其测试威胁模型下 13,935 次攻击没有一次成功；受攻击任务 utility 29.0% vs CaMeL 27.2%，平均 17.1k token/episode 约为 CaMeL 的 18%。这不是现实世界『100% 防御』的保证。

8. 线上 A/B 与工业证据边界

**没有真实线上推荐 A/B 或安全生产渗透证明**；对电商评价工具链的迁移是工程建议，不是已证商业增益。

9. 效率、延迟与成本收益

成本统计含 AgentDojo token/episode，强调静态校验减少防御额外模型回合；但权限 schema 维护、人员审核、复杂授权工作流和失败任务处理成本未包含。

10. 与主流方法的优劣势

相比 Prompt 提示『不要听恶意文档』，CapLite 的可信边界在代码层；相比由 Agent 自动写安全政策，减少自我授权风险。代价是对用户未明确指定的合法动态写入更保守，易降低任务完成率。

11. 推荐 / 搜索算法适用场景

适用于带 RAG/评价内容 Agent 自动生成站点、写实验报告、修改配置等流程：抓取不可信内容后可以提出建议，但真正写仓库、发邮件需对目标路径/接收方有用户级独立授权。

12. 局限与失败模式

只覆盖给定工具 schema 和一类写完整性威胁；复杂交易授权、跨 API 代理、隐式引用、合法动态目标与人类审批并未完整解决。

13. 尚未解决的问题和未来研究方向

未来可结合能力令牌（capability token）、精确参数权限、预授权模板与人审流程，实现更高 utility 而不放松越权边界。

14. 工程实验优先级与职业技能启发

推荐工程里把训练数据/网页文本与执行指令严格分离；设计注入红队 case，检查是否能修改权重路径、调用外部 webhook、改写归档；建立审计日志和审批前后差分。技能：Agent 安全、权限建模、数据血缘、可控工具调用。

1. 背景与业务动机

图协同过滤仍是推荐召回的重要经典强基线。复杂几何消息传递不一定值得改动已有 Serving；将表达能力增加到 scorer 可能更低风险，但也会改变全量候选打分成本。

2. 现有方法和关键矛盾

传统 LightGCN 用点积，难表达 user-item 对的结构化非线性关系；新 scorer 能处理局部差异，却必须排除只是多了 MLP 参数的收益。另一个核心是 NDCG 与 catalog coverage 可能出现取舍。

3. 技术方案与关键模块

使用三层 LightGCN、64 维 embedding，不改变图传播；打分 s(u,i)=u·i+αuᵀΔ(u,i)i，Δ 用 diagonal、rank-one 或 dense matrix；MLP residual scorer 作为参数近似匹配对照。它只是 sheaf-inspired，并没有形式化 sheaf Laplacian。

4. 训练方法、Loss 与监督信号

原始训练使用 BPR pairwise 排序损失加 embedding L2；论文另有对比学习实现但不与主表混合。研究目标主要是 scorer 表征能力，而非新的 list-level RL。

5. 推理 / Serving 方案

更复杂的 pair-dependent 评分使全量 ANN 点积召回难以直接索引，因此作为精排/粗排候选可能比放在第一阶段召回更现实；必须评估候选 K 与 P99，论文未报告生产 Serving。

6. 实验设置、数据集与基线

Amazon-Book、Gowalla、MovieLens-1M、Yelp2018 四套公共数据；比较 identity、结构化 scorer、参数匹配 MLP，在 K=10/20 上测 Recall、NDCG、MRR、Precision、Coverage。

7. 离线指标、消融与结果

Amazon-Book NDCG@10 0.024627→0.024974（diagonal），Gowalla 0.129695→0.129984（rank-one），ML-1M 0.040098→0.040953（full），Yelp2018 0.041142→0.041121（diagonal 略降）；变化小，不能夸为范式突破。

8. 线上 A/B 与工业证据边界

**无生产线上 A/B**；作者指出 Amazon-Book 仅一个 seed、其他多种子未给方差，且 test NDCG@20 用于挑 comparator 形成后验选模偏差；这些都限制可信度。

9. 效率、延迟与成本收益

对于轻量召回模型，增加 pairwise matrix 网络的 token 消耗并不相关，但乘加/内存/候选数成本可能显著增加；论文无真实 GPU QPS/P99，不能假定『轻量』。

10. 与主流方法的优劣势

相比纯 LightGCN 增强打分灵活性，但相比参数匹配 MLP 没有一贯压倒性优势；真正的 Sheaf Diffusion 研究问题（图算子、异配传播）并未由此解决。

11. 推荐 / 搜索算法适用场景

可用于评价内容召回的用户-评价向量交互精修，更推荐接在 topK 粗排/精排，而非替换数亿条评价的第一阶段 ANN 全量召回。

12. 局限与失败模式

后验 test 选模型和缺少方差削弱统计结论；coverage 收益未给因果解释；复杂 scorer 改变点积索引的可分解性。

13. 尚未解决的问题和未来研究方向

下一步在验证集选型、固定全量候选和随机种子、多业务 OOT 下比较残差 MLP 与结构 scorer；记录召回—覆盖—算力 Pareto。

14. 工程实验优先级与职业技能启发

做基线审计练习：保留 LightGCN/BPR 固定训练数据，逐个对比 identity/diagonal/rank-one/MLP 的 NDCG、coverage、长尾命中、GPU 延迟；严禁使用 test 选超参。技能：负例采样、指标置信区间、复杂 scorer 服务化。
