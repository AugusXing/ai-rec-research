从“更大模型”转向“更精确地分配信息、时间与精度”

统计窗口为北京时间 2026-08-31 09:57 → 2026-09-01 09:57。周一 arXiv 新批次进入窗口后，今天值得关注的信号高度集中：企业 RAG 开始用视觉页图 + Late Interaction 替代昂贵 OCR 流水线；电商复购从多个固定时间窗分类器转向可校准的 time-to-event；Agent 开始主动管理 context 并用细粒度 RL 学“什么时候压缩、记忆、卸载”；Serving 则从统一低比特进一步转向 token / scale 级的精度预算。共同主题是：不要平均地使用算力、上下文和表示能力，而要把预算分配给真正敏感的部分。

今日核心结论：① PULSAR 是今天最强的工业证据：78K 文档 / 2.4M 页真实部署，视觉优先两阶段 Late Interaction 在 ViDoRe V3 上以 <0.01 的 NDCG@10/Recall@10 损失换来 15.1× median vector-search 加速、约 14× 更低 RAM，并把 OCR+图表 verbalization 的 ingestion 成本估算降低约 20×；② Timing-Aware Repurchase 把“7/14/30 天会不会复购”统一成 AFT survival model，用约 1/3 的树数量覆盖多个时间窗，同时揭示“排名最优分布”和“概率校准最优分布”并不相同；③ ContextPilot 把 context management 变成 Agent 的 action space，用 context-aware partial rollout + snapshot-level credit assignment，让 8B 模型平均分 65.78→69.40；④ HyQuant / H-Scale 分别在 token 与 per-group scale 维度做敏感度感知的低比特分配，说明 Blackwell 时代量化优化正在从“选 bit-width”进入“优化量化结构本身”；⑤ ITER 说明 Agentic Search 的 retriever 不应只看本轮 sub-query，而应把主问题、历史 sub-query 与已访问文档当作 trajectory state；⑥ Logos 则把 Agent fault domain 从单进程拆到跨进程 bus，证明基础设施也正在围绕“state ownership + resumability”重构。

重点精读 01 · Production Visual RAG / Late Interaction

PULSAR：视觉页图直接检索，正在替代 OCR-first 企业 RAG

Research Impact Score / 研究价值 9.8/10工业成熟度 ★★★★★创新性 ★★★★☆与你方向的相关度 ★★★★★是否官方开源 PULSAR 完整系统未确认开源是否有线上 A/B 无经典 A/B；有真实生产部署与内部对照阅读优先级 最高

背景 / 业务动机

机构投资、并购尽调、董事会材料里大量信息不是自然语言段落，而是图表、表格、版式和混合视觉元素。传统 pipeline 往往是 PDF→OCR→图表 verbalization→文本 embedding；问题在于材料临近 deal closing 时更新频繁，OCR / 图表转写既贵又可能损失视觉细节。PULSAR 的目标不是做一个更强 reader，而是让“检索”直接在页面图像空间工作，并且必须满足企业级 refresh 与并发要求。

现有问题

ColPali/ColQwen 类视觉 Late Interaction 能保留细粒度 page token，但如果每页都保存大量 multivector 并对全量候选做 MaxSim，索引 RAM 和查询延迟很快不可接受。另一方面，单纯做全局 pooling 又会损失图表中的局部证据。因此核心矛盾是：如何保留 Late Interaction 的局部匹配能力，同时把第一阶段 candidate search 压缩到可生产规模。

技术方案与关键模块

系统使用冻结的 ColPali-style 视觉 retriever（论文采用 Tomoro ColQwen3-4B），把页面以约 150 DPI 渲染用于 embedding，并保留约 500 DPI 页图给 answer-time VLM。检索采用两阶段 pooled late interaction：第一阶段对页面 token 做行/列方向的紧凑 pooling，并配合二值化向量与 HNSW 做 prefetch；第二阶段只对候选页使用更细的 hierarchical-pooled multivector 做 exact MaxSim rescoring。Query 保持 multivector，不把查询信息过早压成单向量。

训练方法

这项工作最值得注意的一点是没有依赖新一轮 retriever fine-tuning：backbone 冻结，主要创新发生在 indexing / pooling / retrieval system。它证明很多生产收益并不要求再训练一个新模型，而可以来自表示的存储方式、分层 candidate selection 和系统数据面。

推理 / Serving 方案

向量库使用 Qdrant；ingestion 由事件驱动的优先队列处理，并用文档/页面 SHA-256 hash 跳过未变化页面，避免整份材料反复重建。检索后只把 top-5 高分辨率页面图送入 VLM 回答。这个设计把“检索 embedding DPI”和“回答视觉 DPI”解耦：索引不必为 reader 的视觉清晰度承担全部成本。

实验设置与离线指标

在 ViDoRe V3（14,514 queries）上，生产 pooling 配置相对 unpooled Late Interaction 的 ΔNDCG@10=-0.0088、ΔRecall@10=-0.0074，但 median vector-search latency 从约 752.7ms 降到 49.9ms，约 15.1×；论文同时报告约 14× 更低 RAM footprint。并发压力下 pooled index 约可提供 88× 更高 QPS。

线上 / 生产证据与成本收益

PULSAR 自 2026 年 3 月起在 Mubadala 部署，覆盖约 78K 文档、2.4M 页面、3,000+ deals；生产 rolling 7-day median vector-search latency 约 156ms，p95 约 0.6s、p99 约 1.5s，峰值约 62 QPS。相对原 OCR+verbalization baseline，在生产 top-K 上 answer-fact recall 超过 2×；按调用次数估算 ingestion 成本约降低 20×。

与主流方法的优劣势

对比 OCR-first RAG，优势是避免结构损失与昂贵文本化；对比 unpooled ColPali，优势是 RAM/QPS/latency；代价是 pooling 带来不到 0.01 的 retrieval metric 损失，而且高分辨率页图仍要在 reader 阶段承担视觉模型成本。它不是“视觉模型替代所有文本检索”，而是告诉我们：视觉重文档的检索层可以先视觉原生化，再把 text extraction 变成可选能力。

适用场景 / 局限 / 尚未解决的问题 / 未来方向

适合 PDF、slides、报告、表格/图表密集知识库。局限包括：生产数据不可公开复现、没有随机线上 A/B、page-level retrieval 对跨页证据仍依赖后续 reader。下一步值得研究 query-aware pooling、page→region 二级定位、fresh-index consistency、视觉与文本 dual-index router，以及把 retriever quality / reader quality / ingestion TCO 统一为端到端目标。

对推荐 / 搜索算法工程落地和职业技能的启发

对于搜索/推荐工程师，Late Interaction 已经不只是模型问题，而是 token geometry × pooling × ANN × index lifecycle × reader budget 的联合系统设计。做多模态召回时，应开始把 build time、refresh、RAM、p95/p99、page rendering 和 downstream fact recall 一起纳入实验表。

重点精读 02 · Recommendation Objective / Survival Modeling

Timing-Aware Repurchase：把多个复购时间窗模型统一成 Time-to-Event

Research Impact Score / 研究价值 9.5/10工业成熟度 ★★★★★创新性 ★★★★☆与你方向的相关度 ★★★★★是否官方开源 未发现官方代码是否有线上 A/B 论文未披露阅读优先级 最高

背景 / 业务动机

电商“复购”常被拆成多个任务：7 天内会不会买、14 天内会不会买、30 天内会不会买。每个 horizon 单独训练 binary classifier 会产生三类问题：模型和特征栈重复；不同时间窗概率可能互相矛盾；模型只回答“是否发生”，却没有显式学习事件何时发生。

现有问题

固定窗口分类把 censoring 和时间结构丢掉了。同一个用户-商品 pair 如果 31 天复购，对 30-day model 是 negative，但它并不是“永远不复购”；另外，不同 surface 需要不同语义：排序页只关心相对次序，而提醒/补货/促销策略可能要求绝对概率可校准。

技术方案与关键模块

论文直接预测 time-to-repurchase，比较多种 AFT survival 分布。边际 hazard 分析发现形状参数约 k≈0.9，略微下降，并不支持“离上次购买越久，复购 hazard 必然越来越高”的简单直觉。Log-Normal 对边际分布拟合最好（R²=0.998）且 ranking 最强；Weibull 对条件残差拟合最好。作者进一步用 4 参数校准函数把 survival CDF 映射到各 horizon 概率，并保证跨 horizon 单调性。

训练方法

核心模型采用 tree-based Accelerated Failure Time objective，在 millions of customers 的主流 grocery e-commerce 数据上做超过 30 组 ablation。一个 AFT 模型替代 3 个 horizon-specific binary classifiers，模型总树数约减少 3×。更值得注意的是 feature importance 发生结构性变化：channel cadence 与 recency 权重上升，aggregate frequency 降低，说明 survival objective 真正改变了模型对“复购节奏”的理解。

推理 / Serving 方案

一次模型打分得到时间分布，再由不同 surface 读取需要的输出：纯排序 surface 可以使用 Log-Normal score；需要绝对概率的 surface 则使用更好校准的 Exponential AFT。这样共享主干/特征与推理调用，不再为每个 W 独立部署整套模型。

实验 / 离线指标

单个 AFT model 在三个目标 horizon 上匹配或超过对应的 binary classifier。排名指标上不同 AFT family 相差很小（约 0.3% relative），但 calibration 差异可达一个数量级：Exponential AFT 的 ECE 约 1e-4，约比 Log-Normal 低 10×；校准后跨 horizon probability monotonicity violation 为 0。

线上 A/B、效率 / 成本收益

论文没有披露线上 A/B，因此不能把离线结果直接等价为 GMV/CTR 增益。但模型数量从 3 个 horizon classifier 压成 1 个 survival model，树数量约降 3×，会直接降低训练、上线、特征一致性与迭代维护成本。

优劣势、场景与局限

优势是统一多 horizon、处理 censoring、概率天然具备时间结构；劣势是分布假设仍可能错配，并且 ranking-optimal distribution 与 calibration-optimal distribution 不一致。适合补货、复购、通知、CRM、订阅流失等 time-to-event 场景。未来值得做 neural survival / sequence survival、cause-specific hazard、多商品 competing risk，以及和库存/价格/促销 policy 的联合优化。

对推荐 / 搜索工程的启发

最重要的不是“把 XGBoost 换 survival”，而是学会重新定义目标：业务问题如果天然包含时间，binary label 往往是信息压缩。 推荐工程师应掌握 censoring、hazard、AFT、calibration、time-dependent ranking metric，并能区分“排序 score”和“可决策概率”。

重点精读 03 · Agent / Context Management / RL

ContextPilot：把“上下文怎么管理”本身训练成 Agent Policy

Research Impact Score / 研究价值 9.5/10工业成熟度 ★★★★☆创新性 ★★★★★与你方向的相关度 ★★★★★是否官方开源 是，Tencent 官方仓库 + 模型是否有线上 A/B 否阅读优先级 最高

背景 / 业务动机

Deep Search、Research Agent、长任务助手不断检索和调用工具，context 会随着 trajectory 线性甚至超线性膨胀。传统 truncation / summarize 属于被动清理；更先进的 proactive context management 虽允许模型主动编辑历史，但通常只有 search/delete/summarize，且 RL 把最终 reward 粗暴地分给所有中间编辑动作。

技术方案与关键模块

ContextPilot 把工具扩展到三组能力：Planning（显式计划/预算检查）、Soft Offloading（建立 index、搜索、按 chunk 回读，而不是永久删除）、Long-term Memory（note/memory 的写入、更新、读取），再加 delete/summarize/compress/foldHistory。关键思想是：context 不再是静态 prompt，而是 Agent 可写、可索引、可压缩的工作内存。

训练方法：为什么不是普通 GRPO

第一步 SFT 教会模型正确使用 context tools。RL 阶段采用 context-aware partial rollout：用 context length variation + token entropy variation 找到“真正影响后续结果”的编辑动作，从关键 snapshot 分支采样，而不是平均探索所有 action。然后做 snapshot-level fine-grained credit assignment：一个 snapshot 的 reward 由所有经过该 snapshot 的下游 branch terminal reward 聚合，并在 query group 内归一化后进入 GRPO。这样 credit 更接近“这次 context 编辑到底有没有帮助”。

实验设置与结果

Qwen3-8B 的 SFT 基线平均 65.78，加入普通 GRPO 为 66.84，context-aware branching 后 67.37，最后细粒度 credit 到 69.40；其中 BrowseComp+ 从 48.84→54.18。ContextPilot-14B-RL 平均 72.20。工具本身也很重要：在 Qwen3.5-397B-A17B 上，原始工具平均 77.89，加入 planning / offloading / long-term memory 后到 87.16，BrowseComp+ 从 63.49→80.96。

推理 / Serving 方案

在线时模型自己决定何时 plan、压缩、fold、索引旧 context、把事实写入 note/memory，再按需要读取。它不是简单“扩大 context window”，而是用较短 working context + 外部结构化 state 支撑长任务。对生产 Agent 而言，这比无限堆 token 更接近可控 TCO。

线上 A/B、效率与局限

没有线上 A/B；主要证据来自长上下文 QA 和 deep-search benchmark。工具越多，tool-use failure modes 也越多，论文观察到 memory/offloading tools 在 RL 早期失败率较高，训练后才下降。另一个限制是 tool schema 与 context store 都属于系统设计，跨产品迁移时可能需要重新 SFT/RL。

与主流方案优劣势 / 未来方向

对比 truncation，ContextPilot 保留可恢复证据；对比单次 summarization，它允许按需回读；对比只做 trajectory-level RL，它把 credit 定位到 context action。未来方向包括 context action 的 cost-aware reward、memory freshness/forgetting、cross-session state、retrieval + context manager 联合训练，以及在 recommendation Agent 中把 user long-history state 也纳入相同 control plane。

对推荐 / 搜索职业技能的启发

Agentic Search 的核心技能正在从 prompt engineering 迁移到 state machine、tool protocol、memory/index、RL credit assignment、token budget。对于推荐工程师，用户长序列同样可以被看作“需要主动压缩/召回的 context”，ContextPilot 的思路与 User State、memory retrieval、context ranking 高度同构。

重点精读 04 · Attention / KV Cache Quantization

HyQuant：Attention 不应该被“平均量化”，关键 Token 值得保留高精度

Research Impact Score / 研究价值 9.3/10工业成熟度 ★★★★☆创新性 ★★★★★与你方向的相关度 ★★★★☆是否官方开源 是是否有线上 A/B 否阅读优先级 很高

背景 / 问题

Attention/KV cache 是长上下文 Serving 的内存瓶颈，但统一 4-bit 会把所有 token 当成同等重要。论文观察到 attention mass 高度集中在两类位置：跨 query 都被持续关注的 vertical-line tokens，以及当前位置附近的 local window。例如 window=128 时，Llama3.1-8B 的 top 5% 全局 token + local window 可覆盖约 85.63% attention mass，Qwen3-8B 约 82.53%。

技术方案

Prefill 阶段，大多数 attention state 使用低比特后端，而 vertical-line + local-window 保留 FP16/BF16，并用 fused hybrid operator 避免拆成两个昂贵路径。Decode 阶段，大部分历史 K/V 压成 4-bit，关键 vertical-line token、local window 与 staging buffer 保持高精度；dequantization 融合进 online-softmax attention，不先物化完整 FP KV cache。

训练方法

HyQuant 本质是推理时量化/运行时方案，不要求重新训练 backbone。关键 token 通过轻量 attention-pattern signal 确定，降低了为了量化而再训练模型的门槛。

实验与效率

论文覆盖 Qwen3-8B/32B、Llama3.1-8B、GLM4-9B 与 LongBench/GSM8K/MATH500。H100 上相对 FlashAttention2，kernel speedup 随长度扩大，从 1K 约 1.32× 到 32K 约 3.58×；端到端 decode 约 1.04–1.17×。在 32K、Qwen3-8B 的单 H100 测试中，低比特 KV 还显著提高可承载 batch；论文表中 batch=16 的 HyQuant 可达约 231.6 tok/s，而 FP baseline 已 OOM。

收益 / 代价 / 局限

优势是“把精度花在敏感 token 上”，长上下文越长收益越明显；代价是需要维护混合布局与关键 token 集合，full-precision vertical tokens 也使非窗口 KV 相对纯 4-bit 多出一定空间。适用长 CoT、RAG、Agent、生成式推荐长历史。未来值得做 request-adaptive vertical budget、head/layer-aware precision、与 speculative decoding/MLA 的联合设计。

工程启发

低比特 Serving 不应只有 W4A4/W4A16 这种“模型级标签”。更成熟的设计会出现 layer × head × token × time 的 precision policy。推荐算法工程师如果要进入 LLM/生成式推荐 Serving，理解 KV layout、online softmax、dequant fusion 和 memory-bandwidth roofline 会越来越重要。

H-Scale：Blackwell NVFP4 的下一步，不只是量化权重，而是优化 Scale

背景 / 业务动机

NVIDIA Blackwell 原生支持 NVFP4。它常以很小的 micro-block（如 group size 16）共享一个 scale，灵活性高，但意味着模型里存在巨量 per-group scaling factor。过去 PTQ 主要花精力在 quantized weight reconstruction，却往往把 scale 选择当作简单 rounding/min-max 步骤。

方法

Qwen Team 提出的 H-Scale 把 scale selection 本身变成敏感度优化：使用 calibration activation 构建对角二阶/Hessian proxy，让每组从硬件合法 scale 中选择更能最小化 layer-output perturbation 的值，而不是只最小化 weight-space MSE。它可作为 RTN-style scale selection 的 drop-in post-process，不改变 NVFP4 的硬件格式。

训练 / 推理 / 成本

不重新训练模型，只需要 modest offline calibration；推理时 scale 已固化，因此论文强调 strictly zero inference overhead。这点使其特别适合已有 NVFP4 pipeline：离线多做一点二阶敏感度估计，线上 kernel / checkpoint schema 不变。

实验与判断

论文在多种主流 LLM 和多个 NVFP4 baseline 上报告一致改进，使若干变体更接近 BF16 reference；价值重点不是某一个 benchmark 的绝对百分点，而是证明量化 scale 是一个独立、可优化且硬件约束明确的自由度。这与 SmoothQuant/GPTQ/AWQ 主要围绕 weight/activation transform 的视角不同。

局限 / 未来方向 / 工程启发

局限是收益依赖 calibration distribution 与 diagonal approximation，且目前没有线上 Serving benchmark。未来可做 per-layer calibration budget、scale-aware kernel co-design、MoE expert sensitivity、与 activation/KV quantization 联合优化。对工程师而言，Blackwell 时代要理解的不只是“4bit”，而是 E2M1/E4M3、group geometry、global/per-group scale 和 checkpoint-to-kernel contract。

重点解读 06 · Agentic Search / Retrieval Training

ITER：Retriever 终于开始“记得 Agent 前面搜过什么”

核心问题与方案

Deep Research Agent 的第 t 次检索不是独立 query：它由主问题、已经查到的证据、前几轮 sub-query 决定。但现有 dense retriever 往往只用当前 sub-query 做训练。ITER 将 main question + current sub-query + previous sub-queries 共同编码为 query state，并从 agent trajectory 构造 relative supervision。一个很有价值的 trick 是：某个文档早期是 useful positive，后续如果再搜到它就可能变成 redundancy negative，因为它不再带来新信息。

训练 / 推理 / 实验

训练依赖真实 agent trajectory，而不是额外 LLM judge。推理时 retriever 接受历史交互摘要/queries 后返回本轮证据。跨 6 个 agent backbone、3 个模型家族，ITER 相对 LRAT 平均提升约 7.5%（InfoSeek-Eval） 和 13.5%（BrowseComp-Plus），并比依赖外部 judge/pre-search reasoning 的 AgentIR 有更强 cross-agent robustness。

适用场景与未解问题

非常适合 deep research、复杂购物/旅行搜索、企业知识 Agent。未解决的问题是 trajectory state 会不断增长；直接拼接历史 sub-query 仍可能把 retrieval encoder 变成长上下文模型。下一步自然连接 ContextPilot：一个负责决定“保留什么 state”，一个负责让 retriever 消费 state。

工程启发

这对推荐也很熟悉：召回 query 不应该只有“当前请求”，而可以包含 session intent、已经曝光/消费的 item、已覆盖 topic，甚至把已满足兴趣转成 dynamic negative。Agentic Retrieval 与 session-based recommendation 正在共享同一种状态建模语言。

重点解读 07 · Agent Infrastructure / Fault Domain

Logos：当 Agent 变成长期服务，插件也需要进程隔离与可恢复 Transcript

问题与架构

LangGraph/AutoGen 一类 Agent harness 常把 capabilities、session state 和 loop 放在同一个 host process；一个 crash、OOM 或 blocked event loop 会中断所有 co-resident session。Logos 借鉴 ROS：每个 plugin 是独立进程，通过 name-routed bus 通信；router 只持有可重建 routing table，session 的 source of truth 是不属于任何单进程的 append-only transcript。

训练 / 推理

没有新的模型训练；语言模型仍被看作 stateless call。关键是把 input synthesis、tool call settlement、state recovery 外置。进程死亡后新 harness 从 transcript 重建 projection 并继续，已经 durable record 的 effect 不重复执行。

实验 / Correctness

80 个 session 在 tool-cycle 四个边界被杀死后均恢复且没有重复 effect；另有 12 个端到端 session 经 6 次 process kill 后 cold-switch 完成。bus hop median 约 0.215ms，论文对照的 model first-token latency 约 177ms，说明进程隔离的路由成本在模型时间尺度上很小。压力审计还覆盖 3,500 calls / 200 concurrent callers。

局限与启发

目前仍是 draft v0.0.7，真实云环境、多机网络分区、exactly-once 外部副作用、权限与安全边界仍需更强验证。但方向很重要：Agent Infra 正从“prompt + tools”走向 durable state、fault isolation、idempotency、replay、routing。未来 Recommendation Agent / Ads Agent 真进入线上长任务后，这些分布式系统能力会和模型能力同等重要。
