LLM 推荐开始进入社交图推理与自适应计算

今日重点：ConnectionMind、REAM、Anchor-based LLM Reranker Study、DocsChisel，以及多模态检索与个性化 Agent。

01 · ConnectionMind

Meta · Social Recommendation × LLM Reasoning × RL

不是把整个社交图做 Message Passing，而是让 LLM 主动在异构 Social Graph 中寻找高价值推荐路径，再通过 Teacher–Student Serving 控制成本。

背景与问题

传统 Social GNN 会把大量邻居信息传播并压缩到一个 Dense Embedding，中间混入大量与当前请求无关的噪声，也不易解释“为什么推荐这个内容”。

技术方案

把用户、朋友、Creator/Page、Group、Item 组织成异构图。LLM 根据当前路径、可选 Relation 和节点语义逐步探索，得到 Candidate 与 Evidence Path；训练流程为 SFT → GRPO，并使用 Format、Recommendation、Step Reward。

效果与 Serving

作者报告离线 Recall@10 相比生产 GNN 大幅提升；线上 A/B 覆盖数千万用户、持续数周，Exposure、Watch Time、Video Sessions 均获得正向增益。

部署上并非所有请求都跑 LLM：高价值/重度用户使用 Full Reasoning，大部分用户由 Student GNN 学习 LLM Path 后毫秒级执行。

未来方向

Graph Retrieval + LLM Reasoning + Distillation 可能形成通用推荐范式，并与用户行为序列、Semantic ID 和长期 Reward 结合。

02 · REAM

Efficient Reasoning in LLM-based Recommender Systems

Reasoning 有用，但并非每个 Attention Head 都同样重要；REAM 通过 Head-aware Model Merging，把 Slow-thinking 与 Fast-thinking Model 融合，减少不必要的推理 Token。

方案

使用 Retrieval Criticality、Decision Faithfulness 和 Fisher Sensitivity 判断哪些 Head 承担关键 Recommendation Reasoning，再为每个 Attention Head 分配不同 Merge Coefficient。

效果

作者在 Amazon Music、Book、Yelp 上报告 Reasoning Length 最多降低约 24.3%，同时保持较好的 Accuracy–Efficiency Trade-off。

工程启发

Reasoning Efficiency 可能进一步演化成 Per-request Adaptive Reasoning Budget：简单请求 Fast，复杂意图 Think，真正困难的用户状态才 Think Longer。

03 · When Do Anchor-Based Pointwise LLM Rerankers Help?

这是一篇很有价值的“拆台型”研究：LLM Reranker 的收益强烈依赖 First-stage Retriever 的质量。

核心发现

作者复现 Anchor-based Reranker 时发现，Prompt 大小写、Tokenization、Normalization 等实现细节会造成巨大性能差异；同时，当 First-stage 从 BM25 换成强 Dense Retriever 后，复杂 Reranker 的边际收益明显缩小，个别数据集甚至出现负收益。

工程启发

未来更合理的系统不是“所有 Query 强制 LLM Re-ranking”，而是根据 Query Difficulty / Retriever Confidence 路由：Skip → Cheap Rerank → Expensive LLM/Listwise Rerank。

04 · DocsChisel

Agent Infra · Tool Documentation Optimization

Agent 调错 Tool，不一定是模型不够强，也可能是 Tool Documentation 不适合当前 Agent。

DocsChisel 用失败 Trace 诊断文档问题，自动 Add / Remove / Rewrite Tool Documentation Field，并维护 Domain-level Failure Memory。作者在多工具、多领域 Benchmark 上报告明显成功率提升。

趋势：Agent Stack 正从 Model + Prompt + Tools 继续演化为 Model + Tool Retriever + Tool Router + Adaptive Tool Description + Execution Feedback。

05 · Sequential Modality Dropout

多模态推荐的线上现实问题不是“怎么把模态融合得更复杂”，而是图片/文本缺失时系统还能不能稳定工作。

训练时随机删除整段用户行为中的一个 Modality Stream，让模型学会对模态缺失保持鲁棒；作者报告在极端缺失场景下明显提升 HR@10 保留率。

06 · DistilVDR

Visual RAG / Document Retrieval 开始从“效果优先”转向“Index 是否能真正放得下”。

把 8B Vision-Language Retriever 蒸馏为 524M End-to-End Retriever，同时大幅缩小百万文档 Index；适合关注商品图文检索、视觉 RAG 与多模态搜索。

07 · UserToolBench

Personal Agent 的难点不仅是会不会调用 Tool，而是能否基于历史行为为“这个具体用户”做正确决策。

Benchmark 聚焦缺失约束推断、多工具协调与长期行为一致性，提示 Memory 的真正价值是形成稳定用户决策模型，而不只是保存聊天记录。
