今日最值得看

🥇 LiteRAG · Algorithmic Graph Retrieval

不再用 LLM 在 query-time 驱动图遍历，而是 semantic/lexical/community anchor → query-adaptive expansion → reasoning-chain context。DistComp 上质量 0.798，延迟 1.42s；相对 GraphRAG Global/DRIFT，论文报告超过 100× latency reduction 与 99%+ cost reduction。

🥈 KVShareArena · KV Reuse Contract

把“非 prefix KV reuse”拆成 context shift 与 checkpoint shift 两个轴，并同时记质量恢复、重算量、KV bytes 与 TTFT。关键发现：单 source 只做 position correction 常常够用，多 source 需要重新建立 cross-source attention；错误复用甚至可能低于 no-cache floor。

🥉 Low-bit Vector Search · Decision-level Quantization

真正决定 ANN 是否坏掉的不是平均 distortion，而是 exact margin 附近的 boundary mass + quantization residual tail。对 Vamana，论文进一步证明 pruning action 的局部 flip 会沿 frozen trace 组合成最终邻居集合差异。

技术趋势

Retrieval controller 去 LLM 化

图结构仍有价值，但 query-time LLM orchestration 太贵。LiteRAG 的方向是让模型负责 embedding / final generation，把 traversal、threshold、hub penalty 变成算法。

Reusable state 进入 compatibility 时代

过去只问“能不能 cache”；现在要问 cache 的 birth context、position、跨 source attention、producer checkpoint、dtype/layout 是否仍兼容。

Quality metric 从 representation 走向 decision

低比特向量检索工作提醒：对推荐召回，最该监控的是 top-k pair flip / graph prune flip / hard-margin slice，而非只看 cosine reconstruction。

Hard constraint 回到 RAG 可信性核心

CHyD 不再用 soft faithfulness score 希望模型少幻觉，而是把 extractive span 的合法 token 集直接写进 logits mask。

Deep Dive 01 · Graph RAG / Retrieval

LiteRAG：GraphRAG 真正昂贵的不是“图”，而是 query-time 的 LLM 控制环

Research Impact Score / 研究价值 8.9/10工业成熟度 ★★★☆☆创新性 ★★★★★与你方向的相关度 ★★★★★是否官方开源 计划开源，当前未确认公开仓库是否有线上 A/B 否阅读优先级 S

时间：arXiv v1 提交于 2026-09-09 14:32 UTC。

背景 / 业务动机：Dense RAG 对 lookup query 很有效，但 multi-hop、跨文档比较和关系追踪往往需要显式结构。GraphRAG 用 entity/relation/community 提升了结构化检索，但不少实现又在 query-time 用 LLM 做 graph navigation、community summary 和 evidence aggregation，导致延迟、token 与 API cost 随 corpus/graph 扩张。

现有问题：第一，LLM-mediated traversal 把 retrieval 变成多轮生成任务；第二，检索结果常是大片 summary/raw chunks，generator 仍要自己还原“谁和谁通过什么关系连接”；第三，固定 hop 或静态中心性会让高 degree hub 把搜索带离 query intent。

技术方案与关键模块：LiteRAG 是三段式。① Anchor Selection：先 top-K vector search 得候选节点，再融合 semantic similarity、lexical match 和 community relevance；exact term / 专有名词因此不会完全被 embedding 吞掉。② Query-conditioned Expansion：动态阈值由初始 anchor 质量决定；强 anchor 时收紧探索，弱 anchor 时放宽。再叠加 community-aware hub penalty，对跨社区高 degree node 惩罚更重。③ Reasoning-chain Context：不把整个 subgraph 丢给 LLM，而是综合 anchor reach-rate、semantic similarity、topological proximity、PageRank/betweenness，挑实体和关系后线性化为紧凑 reasoning chain。

训练方法：核心 retrieval controller 不需要额外 LLM training。论文沿用 Microsoft GraphRAG 的 indexing 产出，在 retrieval/context construction 层替换 query-time 控制；超参数通过 validation grid search。生成统一使用 Gemini 2.5 Flash Lite，embedding 使用 gemini-embedding-001。

推理 / Serving：在线路径本质上变成 embedding → top-K anchor → bounded graph traversal → compact chain → 单次 generation。最大 hop 与 per-anchor expansion cap 给出了天然 budget boundary。这对搜索/推荐的价值很直接：可把 graph exploration 放进可预测 CPU/ANN runtime，而不是把 SLA 交给多次 LLM call。

实验设置：DistComp 从 2020–2022 分布式计算论文构建，5 个 corpus scale（40/80/160/640/1280 文档），最大约 50 万 token；160 个专家 query 覆盖 literal citation、local reasoning、global synthesis、drift-style multi-hop。另在 UltraDomain Mix（农业/法律/医疗）验证。对比 GraphRAG Basic/Local/Global/DRIFT、LightRAG、HiRAG、LinearRAG。

离线指标：DistComp D1280：LiteRAG Q_total=0.798、1.42s、2,291 tokens、$0.0003/query；LinearRAG 为 0.784、8.01s、3,077 tokens、$0.0006。GraphRAG Global 为 0.714、162.66s、643,909 tokens，DRIFT 为 0.657、142.04s、6.44M tokens。UltraDomain 上 LiteRAG 与 LinearRAG 同为 0.801，但 LiteRAG 4,862 tokens vs 68,774，约 14× 更少。

线上 A/B：无。效率 / 成本收益：论文报告相对 GraphRAG Global/DRIFT 的 query latency 超过 100× 改善与 cost 超过 99% 降低；相对 LinearRAG 在 UltraDomain 约 74% latency reduction、92% cost reduction。

与主流方法优劣势：相比 GraphRAG，优势是可控、低成本和上下文更密；相比 flat dense retrieval，优势是 multi-hop relation 显式化。代价是必须已有质量足够的 entity/relation graph，且 graph indexing cost 并没有被消除；算法阈值与社区结构也会引入新的 domain calibration。

适用场景：企业知识库、多跳技术问答、需要跨文档关系整合但又有严格 latency/token budget 的 RAG。局限：DistComp 是自建数据集；Q_total 含 LLM-as-a-judge；没有线上 workload / failure-tail latency；目前论文只承诺 GitHub release，未在 arXiv 页面看到可确认仓库链接。

尚未解决 / 未来方向：动态 graph freshness、增量 entity merge、hybrid sparse+dense anchors、query-adaptive hop budget、graph build cost amortization，以及将 traversal confidence 暴露给 model router。

对推荐/搜索工程的启发：不要把“Agentic Search”理解成所有步骤都要 Agent。最值得搬到推荐召回的是 LLM offline structure + deterministic online controller：在线只保留可观测、可设预算、可压测的图探索逻辑。

Deep Dive 02 · RAG / KV Serving Benchmark

KVShareArena：非 Prefix KV Cache 复用的真正问题，是“出生上下文”已经变了

Research Impact Score / 研究价值 8.8/10工业成熟度 ★★★★☆创新性 ★★★★★与你方向的相关度 ★★★★★是否官方开源 论文称已开源 pip/leaderboard，URL 在 arXiv HTML 中为占位是否有线上 A/B 否阅读优先级 S

背景 / 业务动机：Prefix caching 成功的前提是 reused tokens 仍处在原 prompt 开头。RAG 会把不同 retrieved chunks 任意重组；multi-agent coordinator 会把其他 agent 新写的 report 拼入新 prompt。此时 KV 的 position 错了，而且不同 source 在独立编码时彼此从未 attention。若 producer/consumer 还是不同 checkpoint，值分布又多了一层 shift。

核心贡献：它不是提出一个新的万能 repair，而是定义一个更合理的 benchmark contract：两个变化轴 context change × checkpoint change；两类 workload Retrieved Evidence × Agent Reports；质量用 no-cache floor 与 full-recompute ceiling 之间的 PGR（performance gap recovered）；成本同时记 payload recompute、KV bytes 与 TTFT。

关键发现：仅做 position correction 在单文档/弱 source interaction 场景常已足够；一旦问题需要多 source joint attention，free alignment 失效，multi-hop 中甚至可低于 no-cache floor。selective recomputation、calibration 或 trained repair 能恢复部分 gap；在论文主板上，多 source 场景的付费 repair 通常恢复约一半上下。跨 checkpoint 时，大部分 training-free repair 变化很小，而绑定某 producer KV distribution 的 trained adapter 会明显掉点，并可能“流畅地答错实体”。

训练方法：Benchmark 本身无训练；它统一纳入 CacheBlend、EPIC、APE、KVCOMM、DroidSpeak 等不同 repair family，并把训练式和 training-free 方法放在同一 cost plane 上比较。

推理 / Serving：最关键的 Serving policy 是分层：single-source → 先 position alignment；multi-source → 根据 dependency 与 SLO 决定 selective recompute；cross-checkpoint → 做 compatibility gate，优先 receiver-side rebuild。这比“所有 cache 一律复用”更接近生产 controller。

实验与指标：使用 LongBench 子集等官方指标，所有比较在 frozen samples 上成对评估；FRAMES autorater 还用其他模型家族交叉核验。主结果显示 multi-hop free alignment PGR 可到 -0.196；CacheBlend 等 paid repair 可拉回约 0.39–0.46 gap。跨 checkpoint 六个 cell 中，除 producer-fitted repair 外，多数方法平均 shift 保持在 ±0.02 内。

线上 A/B：无。效率 / 成本：这篇工作的价值是把 cache reuse 从单纯 TTFT 指标升级成 quality × recompute × bytes × latency 的 Pareto 问题，而不是给一个单一“加速倍数”。

优势：把过去分散在 RAG、Agent、checkpoint reuse 社区的实验口径统一；明确区分 build-cache 一次性成本和 request-time 成本。局限：主排行依赖一个 8B 模型，其他 board 只验证趋势；input cap 29K；Agent Reports pipeline 是作者构造；跨 checkpoint 只覆盖同 architecture/tokenizer/RoPE base。

未来方向：cache schema/version、producer fingerprint、cross-source dependency estimator、按 query 动态 recompute ratio、跨模型 KV adapter 的 OOD gate，以及与 disaggregated prefill/cache routing 结合。

工程启发：推荐系统里 user state / candidate state / document state 未来也会碰到同类问题：reuse 不是布尔变量，而是带 birth context 和 compatibility metadata 的数据资产。

资源：① Paper；② 官方项目页：论文称有 public leaderboard；③ 官方代码/数据：论文写明 pip install kvsharearena、frozen querysets、automated submission workflow 已发布，但 arXiv HTML 当前将 repo/leaderboard/data URL 渲染为占位符，因此不猜测具体 GitHub 地址；④ 中文解读：截至今日未发现可靠深度解读。

Deep Dive 03 · ANN / Retrieval Quantization

低比特向量检索：从“embedding 还像不像”转向“ANN 的关键比较会不会翻转”

Research Impact Score / 研究价值 8.8/10工业成熟度 ★★★★☆创新性 ★★★★★与你方向的相关度 ★★★★★是否官方开源 未确认是否有线上 A/B 否阅读优先级 S

背景：Binary / 2-bit / PQ / BBQ 等量化能显著降内存与 bandwidth，但相同 bit budget 在不同 embedding 上可能一个保持高 recall、另一个直接崩。平均 reconstruction error、cosine correlation 或 Spearman rank correlation 往往解释不了这种 sharp failure。

核心思想：搜索算法最终消费的不是“整个向量像不像”，而是大量局部 pairwise comparison：A 是否比 B 更接近 query？Vamana pruning 时某 candidate 是否应该保留？论文把精确比较 margin 记为 Ψ，把校准后的量化 residual 记为 R，得到 distribution-free decomposition：flip risk ≤ exact margin 靠近 0 的 boundary mass + residual tail。因此 hard query / hard pair 天生对量化更敏感。

关键模块：① covariance-aware residual：共享 query/node 的 residual 不是独立噪声；在 Cohere selected pair 上忽略 covariance 会把 measured difference variance 高估 7.4×。② frozen-trace coupling：对 Vamana neighbor selection，把 exact candidate order 冻结后，approximate replay 最终邻居集合保持完全一致，当且仅当沿 trace 的所有 candidate-level pruning action 都一致。③ held-out block certificate：当解析分布假设不可靠时，用校准块估计 selective failure risk。

训练 / 推理：这不是新 quantizer，也无需训练主模型；它更像量化上线前的 decision-risk diagnostic。对生产 ANN，可在 sampling query 上记录 exact margin distribution 与 quantized residual，构造 hard-margin bucket，再决定 bit-width / rotation / fallback。

实验设置：覆盖 Cohere、MiniLM、BGE-M3、Jina、MSMARCO，视觉 Wolt-CLIP/Landmark-DINO，经典 SIFT/GIST/GloVe，以及 synthetic；维度 100–2048。局部决策实验固定 32-neighbor candidate set，每数据集 80 calibration query + 160 held-out query；cross-quantizer 使用 1,200 fit + 2,000 held-out vectors。框架覆盖 binary codes、RaBitQ、Lucene BBQ、PQ。

离线结果：即使 scalar int4 在整体 edge correlation 达 0.997、总体 ranking flip 仅 2.1%，最难 20% margin 中 flip 仍达到 10.1%。GIST 上未旋转 1-bit 的 flip 可达 100%；随机 rotation 后 margin correlation 提升并让 flip 降到 14.8%，2-bit 从 35.83% 降到 9.33%。这正说明“平均很好”不能替代 hard-boundary 分析。

线上 A/B：无。效率 / 成本：论文没有主打新的 latency benchmark；它提供的是更靠谱的上线风险判据，可用于避免为了节省 memory/IO 牺牲关键 top-k/prune decision。

优劣势：优势是跨量化方法、跨 ANN primitive 的统一语言；比 reconstruction MSE 更贴近 recall failure。缺点是需要 exact scorer 的 calibration/held-out sample，且 frozen-trace certificate 并不等同于完整动态图构建/搜索过程的端到端保证。

适用场景：亿级召回 embedding 压缩、edge ANN、GPU/CPU memory-tight vector store。未来方向：query-adaptive bit-width、hard-margin fallback、index-build-time certificate、在线 drift detector、与 learned retriever training 联合优化 margin robustness。

工程启发：你做召回量化时，监控面板最好增加 top-k boundary margin、pair flip rate、graph prune flip rate、hardest quantile recall，而不是只看平均 cosine error。

Deep Dive 04 · Long-context RAG Serving

KV Cache 拼接感知微调 + 15% 选择性重算：模型适配与 Serving 修复不是二选一

Research Impact Score / 研究价值 8.7/10工业成熟度 ★★★★☆创新性 ★★★★☆与你方向的相关度 ★★★★★是否官方开源 未确认是否有线上 A/B 否阅读优先级 S

背景：长 RAG 把大量 chunk 拼成 32k–124k context，prefill 成为 TTFT 大头。预计算 chunk KV 能节省 O(n²) prefill，但独立 chunk 的 KV 缺少拼接后的跨 chunk attention。已有两条路线：让模型在训练时适应 block-wise cache，或在线重算一部分 cache。

方案：论文把两者叠加：先从 Llama3.1-8B-Instruct / Qwen2.5-7B-Instruct 训练 KV-concatenation-aware Block-attention model，再用 CacheBlend-style selective recomputation，仅对约 15% payload 重算。模型降低“独立缓存”造成的 representation shift，在线重算补最关键 cross-chunk interaction。

训练：Llama 路线使用 Tulu3 40k 样本与约 20k 2Wiki / 20k TQA 数据；Block-attention 有效训练样本略少（Tulu3 33,532）。Qwen2.5-7B 学习率 5e-6，作者报告约 7.5 小时得到 Block-attention 模型。

Serving：KV 以 safetensors 在 SSD 保存；每层用 8 worker 读入 CPU，随后搬 GPU、merge + position adjustment，并通过 CUDA streams 将 I/O、H2D 和 transformer-layer recomputation 流水重叠。这一点比“只给算法分数”更接近真实系统实现。

实验：RULER 从 4k 一直到 124k，同时评 2Wiki/HQA/NQ/TQA 与通用 benchmark。124k 时 Proposed（Block-attention+15%）RULER 平均 56.7，CacheBlend-only 为 47.0，提升 9.7 分；full recompute 为 80.2。四个 RAG benchmark 上 Proposed 分别 70.8/72.6/58.1/75.2，均优于其他非 full-attention 方案。

效率：当 KV 从 SSD 加载，124k context TTFT 相比 full attention 降约 80%。但论文也给出重要反例：4k 时 full prefill 反而更快；若每个 cache file 太小导致文件数过多，优势要到 32k 左右才出现；使用 FlashAttention-2 后 full attention TTFT 也能逼近 15% recompute + FlashInfer。

优劣势：比纯 CacheBlend 更准，比纯 Block-attention 更能恢复跨 chunk interaction；但仍明显低于 full recompute 的 124k 上限，且要额外维护专门 fine-tuned checkpoint、cache file layout 与 SSD pipeline。

局限 / 未来：最佳 recompute ratio 是否随 query/source dependency 动态变化仍未解决；大规模 multi-tenant serving 的 SSD contention、KV version 与 checkpoint compatibility 也未覆盖。未来最自然是与 KVShareArena 的 compatibility/PGR protocol 结合，形成动态 repair router。

工程启发：对于推荐里的超长用户序列/多域 candidate context，也不要把“模型侧适配”和“Serving 侧近似”分开看。让模型学会容忍可复用 state，再把昂贵精确计算留给少数高价值位置，会是一条通用路线。

RobustSGPO：Agent 自我改进的瓶颈，开始从“会不会改 Prompt”变成“如何控制搜索空间”

背景：这篇来自武汉大学与快手，直接承接 AgentX 的工业推荐研发 workflow。原 SGPO 从失败 trace 生成 natural-language loss/semantic gradient，再编辑 agent specification，通过 paired replay 决定 accept/rollback。问题是：允许改整个 harness，并不代表 LLM 真能探索到有用的结构修改。

核心矛盾：nominal search space ≠ realized search space ≠ valid/effective search space。自由生成倾向熟悉的 instruction rewrite，跨 agent handoff、add/remove agent、routing 等结构动作即使被允许，也可能根本生成不出来或生成无效 patch。

技术方案：RobustSGPO 显式控制三件事。① Edit planning：先选 scope、operation、targets，再让 LLM 写内容；② Typed patch construction + exact-target check：预定义 add/remove 等结构操作，检查“请求修改哪些对象”和“实际改了哪些对象”完全一致；③ Category archive：按 edit scope × operation 保存最好但未必成为 incumbent 的完整 harness snapshot，后续可从 retained parent 继续搜索，所有 descendant 仍必须超过当前 incumbent 才能正式接纳。

训练 / 优化：没有更新 base model weight；优化对象是 harness。每轮用 optimization traces 产生更新，validation 控制选择/retention，test feedback 不进入 search。所有 candidate 都做相同任务与 execution seed 的 paired replay，平均 validation gain 超过 0.05 且通过 safety 才 accept。

实验：120 tasks，分 local instruction failure 与 cross-agent handoff/structure failure 两类；每类 30/15/15 optimization/validation/test。95 runs、7,350 candidate attempts；五个 paired seeds；每轮 3 proposals；proposal 上限 120 changed lines / 6,000 added chars。

结果：periodic permission 1→2→3 最终 4.34，固定最大权限 α3 为 4.06，领先 0.28。完整 RobustSGPO round-30 score 4.30 vs SGPO 3.82；effective-category coverage 68% vs 48%；结构 proposal validity 通过 typed operation 明显改善。30 个 held-out tasks completion 从 18/30（60%）升到 24/30（80%）。在固定 20M-token search budget 下，SGPO 3.77，RobustSGPO 4.14。

成本 / 局限：archive 不是免费的：RobustSGPO 每轮约 0.95M tokens，固定预算下只跑到 round 21；与 Structured Search 的领先会从等轮数 0.10 缩到等 token 0.04。实验仍只覆盖 AgentX brainstorming workflow，不能直接外推为所有 Agent harness 的 SOTA。

与推荐工程的关系：这是今天最值得推荐算法工程师关注的 Agent 工作之一，因为它把“Agent 替工程师做实验”继续往平台化推进：实验假设、代码修改、评估、回放、版本保留都要有 contract。对长尾排序模型与重复实验任务，价值可能大于单纯换一个更强 LLM。

未来方向：typed ML experiment DSL、自动 regression suite、跨模型/业务线 archive transfer、真实线上实验 guardrail、成本感知 search scheduler，以及把 offline replay score 与真实 A/B uplift 连接起来。

CHyD：把“引用必须来自检索证据”直接变成解码时的硬约束

Research Impact Score / 研究价值 8.5/10工业成熟度 ★★★☆☆创新性 ★★★★★与你方向的相关度 ★★★★☆是否官方开源 未确认是否有线上 A/B 否阅读优先级 A+

方案：Constrained Hybrid Decoding 在普通生成和 Evidence Extraction Constraint（EEC）两种模式间切换。模型生成“[”触发 EEC 后，下一 token 只允许属于检索上下文中某个连续 verbatim span 的合法 continuation，其他 token logits 直接设为 -∞；生成“]”退出提取模式。保证的是：显式引用 span 一定逐字存在于输入 context。

实验：Qwen3-4B、Llama-3.1-8B、Mistral-Nemo，覆盖 MedMCQA、MESAQA、QuoteSum 与作者构建的 SEMAeroSQuAD（航空航天、1,420 questions）。已有 hybrid 方法在技术域 exact extraction accuracy 可掉到 40% 以下，CHyD 在多模型上接近完美 extraction faithfulness；同时保持较强 answerability detection，相关设置 F1 多数高于 0.88。

重要边界：主实验对多数据集直接给 gold context，是为了隔离 retrieval error，因此它证明的是 decoding faithfulness，不是端到端 RAG factuality。span 来自 context 也不代表 span 本身相关/正确，trigger selection 仍可能错。硬约束还会牺牲一部分 MAUVE/ROUGE 类 fluency。

工程启发：高风险搜索、客服、合规问答可把输出拆成“自由解释 + 可验证 evidence span”两条 channel；推荐解释也可借鉴，要求 price/库存/政策类事实必须 pointer 到 source。

WRP：不用 calibration data，也不用 forward pass，直接从权重冗余做 Depth Pruning

Research Impact Score / 研究价值 7.9/10工业成熟度 ★★★☆☆创新性 ★★★★☆与你方向的相关度 ★★★★☆是否官方开源 未确认是否有线上 A/B 否阅读优先级 A+

方案：Weight-Redundancy Pruning 比较不同 Transformer block 的 attention output projection 与 MLP down-projection 权重，再结合相对 projection scale，形成 all-pairs similarity matrix；随后 spectral-style clustering 决定哪些层属于相近 redundancy group，并分配删除预算。全程不需要 calibration corpus 或 model forward。

结果：论文在 LLaMA、Qwen、Mistral 等多设置的一次性、无恢复 depth pruning 中优于已有 forward-free magnitude baseline，并接近需要 activation 的方法；同时评估 prefill latency、decode latency 和 peak GPU memory。核心价值不是新的 dense operator，而是“拿到 checkpoint 后快速裁深度”的部署灵活性。

局限：权重相似不一定等价于具体 domain activation redundancy；没有任务自适应 calibration 也意味着极端 domain shift 下风险更难估计。对推荐 foundation model，更适合做 deployment candidate 生成，再用业务离线集/蒸馏做最终验证。
