今天最值得注意的变化：
推荐 / 搜索开始重新定义“计算单元”

今天的 8 条重点进展不是简单地继续放大 backbone，而是在重构系统里最基本的计算单元：UniCon 把 CTR 的基本单元从 feature/token 提升为一次完整展示 context；DoPR 把 reranking 中可复用的 document-side computation 从 query-time 搬到 offline prefix；EPIC 把 Semantic ID diffusion 从逐位置 token 决策提升为完整 item posterior 竞争；HypRQ-VAE 则改变 SID 的几何空间，使长尾目录不再被 Euclidean quantization 系统性压扁。SelfDR、SciLENS、RuleMem 与 Perplexity serving 分别从 reasoning、agent retrieval、memory 与 runtime 侧给出同一信号：价值越来越来自“结构化地决定什么值得算、什么时候算、怎样复用”。

今日核心结论：① CTR/Ranking 的统一建模正在从 token-level fusion 走向 context-level structure；② LLM reranking 的大机会不只是量化，而是把 document-side computation 变成可缓存资产；③ Semantic ID 的下一阶段开始同时处理 item-level posterior、long-tail geometry 与 collision；④ reasoning 的工业化方向不是“所有请求都输出 CoT”，而是训练时用 reasoning、线上蒸馏成 direct inference；⑤ Agent/RAG 正把 rule、citation topology、visual structure 变成主动检索控制信号；⑥ Embedding/Ranking serving 与 LLM serving 的 runtime 正在共享同一套 kernel、CUDA Graph、scheduler 与 load-balancing 基础设施。

重点精读 01 · CTR / Unified Ranking · Meituan

UniCon：把 CTR 的基本建模单元从“特征与行为 token”提升为“完整决策 Context”

Research Impact Score / 研究价值 9.7/10工业成熟度 ★★★★★创新性 ★★★★★与你方向的相关度 ★★★★★是否官方开源 否；截至今日未发现官方代码仓库是否有线上 A/B 是，Meituan 搜索广告 7 天、20% 流量阅读优先级 最高

背景 / 业务动机

工业 CTR 模型长期沿用“行为序列 vs 非序列特征”的划分：历史点击进入 DIN/Transformer，当前候选、query、用户画像、环境特征走另一条 feature-interaction 路径。这个划分更多来自历史 feature engineering，而不是用户真实决策过程。真实点击发生在一次曝光/搜索页/货架中，用户选择某 item 的含义取决于当时一起展示的竞争项、位置、query、环境；如果只留下被点击 item，就丢掉了“为什么在这一组候选里选它”的局部上下文。

现有问题

OneTrans、HyFormer、RankMixer 等统一模型能把 heterogeneous tokens 放进共享 backbone，但仍把 impression boundary 当隐式信息。这样会混淆“同一展示页内的竞争/互补”与“不同时间请求之间的相邻”，而且 pointwise candidate scoring 很难显式表达当前 candidate set 的局部竞争结构。

技术方案与关键模块

UniCon 定义 context unit：同一次曝光中的 items + query/intent/category/time/location/device/environment + user state。历史曝光和当前请求在结构上同构，区别只是历史 feedback 已知、目标 feedback 未知。每个 UniConBlock 先做 intra-context attention，只在一个 unit 内建模 item competition/complementarity（Locality）；再做 inter-context attention，连接多个历史 unit 与当前 target latent context，建模用户决策状态随时间变化（Dynamics）。Inter-context FFN 使用 dense MoE；目标侧同时预测 click、是否进入最终曝光、绝对位置。

训练方法

主任务是 CTR binary loss；辅助 exposure / absolute-position supervision 用 incumbent production log 中最终展示结果去塑造 target latent context。click loss 只在曝光候选上计算，position loss 也只在曝光候选上计算；exposure 预测不喂给 click head，click gradient 也不回 position head，三者通过 shared contextual representation 间接协同。历史压缩训练用 Gumbel-TopK straight-through estimator：forward 真剪枝，backward 用连续 relaxation。

推理 / Serving 方案

系统不是把论文结构“硬塞进线上”后接受高成本，而是同步设计了 context-aware sequence compression、padding-free variable-length attention、candidate sharding、dense MMoE fused execution 与 AOTInductor + C++ runtime。第一层先看完整历史，之后每层根据 target context 与历史 context 的 Q/K pooled similarity 只保留 Top-K context。线上 hard TopK，不需要 sampling；完整图用 dynamic-shape compilation，Python 被移出在线 inference path。

实验设置 / 离线指标

数据来自 Meituan 搜索广告连续一年 production window，验证/测试为随后两天；用户和 item 都是亿级，单个历史可包含数百 context unit，production candidate shard 最大 300。指标包括 AUC、LogLoss、request-level GAUC。UniCon-Large 从约 0.05B 扩到 0.33B 参数时 AUC 从 0.8668→0.8698；0.33B 模型使用 context compression 后计算从 801.29 GFLOPs 降到 197.14 GFLOPs，AUC 仍为 0.8697。

线上 A/B

7 天实验将 20% 流量分给 UniCon-Large：RPM +3.09%、CTR +2.07%、Revenue +2.95%，三项均 p≤0.01。这种结果比单纯“离线 AUC 小涨”更重要，因为它证明 list/context structural modeling 没有在 Serving 约束下失效。

效率 / 成本收益

production keep ratio 0.5 时，相对不压缩从 801.29 降至 197.14 GFLOPs，AUC 仅 0.0001 变化；variable-length attention 单独使 throughput +64.5%，再叠加 context compression 后相对 fixed/uncompressed baseline throughput +258.1%，并满足 latency SLA。

与现有主流方法的优劣势

优点是它真正改变了 input abstraction：不是再加一个 context feature，而是让 context boundary 决定 attention scope、sequence compression 与 supervision。相对 DIN/DIEN，能够利用“当时还有哪些替代项”；相对 flat Transformer，避免把不同曝光页混成局部邻居。代价是训练数据必须保留完整 impression/candidate structure；target exposure/position supervision来自旧策略日志，仍有 policy bias，且 candidate sharding 太小会切断竞争关系。

适用场景 / 局限 / 尚未解决的问题

最适合 search ads、电商货架、短视频 feed、瀑布流和 slate/list ranking。难点包括 exposure policy bias、跨请求 context 的 freshness、超大 candidate pool 的 shard boundary，以及如何把 CTR context modeling 与后续 rerank/slate optimization 联合训练。

未来研究方向

值得继续做 counterfactual target-context supervision、listwise reward、context-aware generative ranking、跨阶段 context state reuse，以及让 context compression 直接优化 marginal business value / GPU-ms。

对推荐 / 搜索算法工程落地和职业技能的启发

做精排的人应开始把“曝光页/候选集合”作为一级训练对象，而不是只保留 user-item pair；工程能力上要补 variable-length attention、AOT compile、CUDA kernel fusion 与 candidate sharding。真正的 industrial scaling 往往是 architecture 与 Serving co-design。

重点精读 02 · Search / LLM Reranking / Serving

DoPR：把“文档计算”从每次 Query 重做，变成可离线复用的 Compressed Prefix

Research Impact Score / 研究价值 9.5/10工业成熟度 ★★★★☆创新性 ★★★★★与你方向的相关度 ★★★★★是否官方开源 是是否有线上 A/B 否阅读优先级 最高

背景 / 业务动机

Pointwise LLM reranker 的隐性浪费很大：同一个热门文档会被不同 query 反复召回，而每次 rerank 都重新编码整段 document。对长文档或大 candidate set，这部分 document-side compute 常常比 scoring token 本身贵得多。

现有问题

传统 KV cache 很难直接解决，因为 query-document joint encoding 会让 document hidden state 受 query 影响；简单离线 embedding 又会损失 LLM reranker 的深层 token interaction。问题本质是：能否训练出一小组query-independent、但对 ranking 足够的 document states，并让它们以模型原生 prefix 形式进入后续层。

技术方案与关键模块

DoPR 三阶段：训练时从 document token states 选择 Ktrain 个 salient representations，并用 structured attention mask 强制 document→query 信息经过这个 bottleneck；离线阶段对每个文档仅运行 document-only selection，再把选中的 representations 作为 prefix 输入模型，得到每一层的 compressed prefix KV states；线上阶段只处理 [query; score token]，文档信息由预存 prefix states 注入。

训练方法

Qwen3 0.6B/4B/8B，AdamW lr 5e-6，总 batch 32，8×A100；默认 Ktrain=32。ranking head 用 pairwise RankNet，使 compression selection 直接为相关性服务，而不是做 reconstruction。一个很实用的设计是 Kinfer 可与 Ktrain 不同，因此上线后无需重训就能在 quality / memory / latency 间切档。

推理 / Serving 方案

Document collection 预处理后，把 prefix states 当成 retrieval index 的附属资产。文档被再次召回时直接取状态；真正 online 的 forward 只覆盖 query 与 score token。这里保存的不是“document-only forward 的普通 KV cache”，而是选中 compressed representations 作为 prefix 重新前向后得到的 multi-layer KV states。

实验设置 / 离线指标

在 TREC DL、BEIR、BRIGHT 上评估。与同尺寸 Qwen3-Rerank 相比，0.6B 平均 NDCG@10 retention 97.1%，4B 为 99.3%，8B 为 99.5%；部分数据集甚至略高于 full-document baseline，说明 bottleneck 兼具轻度 regularization 效果。

线上 A/B

无生产线上 A/B；目前是公开 benchmark + controlled reuse workload。

效率 / 成本收益

文档侧 online memory 最高减少 8.0×，latency 最高 8.04× 加速；BRIGHT 12 个 subset 上 0.6B 平均仍保留 98.6% NDCG@10，平均 8× document-state reduction 与 4.89× latency speedup。长文档收益更明显：Covid workload 的 speedup 远高于短文档。

与现有主流方法的优劣势

相对 embedding reranker，它保留多层 LLM prefix state；相对 full LLM reranking，它把重复文档计算摊薄。最大代价是存储：每个 document 要保存多层 prefix states，catalog 很大时离线 index footprint 可能变成新瓶颈；文档频繁更新时需要重建 prefix；cross-encoder 最强的 query-specific document transformation 被瓶颈化后仍会损失少量质量。

适用场景 / 局限 / 尚未解决的问题

最适合热点文档会被大量 query 重复召回的 Web Search、Enterprise Search、商品详情 reranking、FAQ/知识库。对高度 query-dependent 的短文本或极低复用率文档，离线构建成本可能不划算。还需要回答 prefix cache 的 versioning、冷热分层、multi-tenant storage、更新传播，以及 listwise reranking 能否共享 prefix。

未来研究方向

可以与 semantic cache、ANN doc embedding、KV offload、prefix dedup、quantized prefix state、query-adaptive Kinfer、reranker routing 联合。对工业系统最值得做的是“文档复用频率 × prefix size × quality loss”的动态经济模型。

对推荐 / 搜索算法工程落地和职业技能的启发

搜索工程师应把 reranker cost 拆成 query-side 与 document-side，而不是只看总 FLOPs。会设计 offline/online boundary、cache lifecycle、state compression 与 rank loss 的工程师，会比只调 cross-encoder 更接近下一代大规模 reranking。

重点精读 03 · Generative Recommendation / Semantic ID / Diffusion

EPIC：Semantic ID Diffusion 不该只做 Token Prediction，而要显式维护完整 Item Hypotheses

Research Impact Score / 研究价值 9.3/10工业成熟度 ★★★☆☆创新性 ★★★★★与你方向的相关度 ★★★★★是否官方开源 否；截至今日未发现官方代码是否有线上 A/B 否阅读优先级 最高

背景 / 业务动机

Masked-diffusion generative rec 能双向修复 SID token，并灵活决定解码顺序。但推荐最终必须落到 catalogue 中一个完整 item；当 SID 只解出一两位时，可能对应几十甚至几百个合法 item。逐位置 token probability 并不知道这些 token 组合在 item 层面是否形成一致、个性化的候选假设。

现有问题

现有方法在 token-space 做独立/局部决策，容易出现一个 promising item 的不同 SID 位被分别削弱，最后被“每个位都还不错、整体却不是最佳 item”的组合挤掉。把 item scorer 放到最后 rerank 又太晚，因为错误 trajectory 已经在前几步 denoising 被剪掉。

技术方案与关键模块

EPIC 在每个 active denoising step 构造当前 feasible item set，根据已解 SID、backbone likelihood 与用户最近交互形成候选支持集；一个轻量 item-level adapter 使用 personalized transition evidence 给完整 item 分配 posterior。然后把 complete-item posterior 精确 marginalize 回每个 unresolved SID position，形成 item-informed token distribution，再通过 ambiguity-aware residual gate 与 backbone logits 融合。

训练方法

使用 LLaDA-Rec 的 Sentence-T5 tokenizer，每个 item 4-position SID、每位 256 code。backbone 完全冻结，只训练 item adapter；hidden dim 256，4 heads，batch 512，最多 8000 updates，AdamW weight decay 0.01，validation NDCG@5 early stop。训练参数仅 0.391M，对比完整 LLaDA-Rec 6.847M，减少 94.3%。

推理 / Serving 方案

关键是 inline feedback：item posterior 在每一步 active denoising 都介入，而不是生成结束后做 post-hoc rerank。论文还发现只先显式 resolve 两个 SID position 就能获得 Beauty 最佳 NDCG@5，并比 resolve 全 4 位快 1.72×，说明“partial SID → item posterior”可能成为 future adaptive decoding 的抓手。

实验设置 / 离线指标

Beauty、Sports、Toys、Musical Instruments 四个 Amazon benchmark；EPIC 在 16 个 metric×dataset 组合上均取得最佳均值，相对每列第二名提升 1.2%–16.8%。Toys NDCG@5 +16.8%、NDCG@10 +14.1%，Beauty NDCG@10 +13.1%，Sports NDCG@10 +12.9%。

线上 A/B

无线上 A/B。

效率 / 成本收益

单 T4 上 adapter training throughput 333.8→476.3 ex/s（+42.7%），peak training memory 4299.6→1895.4 MiB（-55.9%）；代价是 inference latency 93.0→124.8 ms/user（+34.2%），peak inference memory 基本不变。这是必须正视的 trade-off：精度提升来自每步 item-level reasoning，并非免费。

与现有主流方法的优劣势

相对 TIGER/LLaDA-Rec，EPIC 的核心创新不是另造 tokenizer，而是显式保持完整 item competition；相对 final rerank，inline feedback 能救回早期即将丢失的 target hypothesis。缺点是需要 catalogue feasible-set operations 与 personalized transition scorer，超大 catalogue 的 candidate-support 构建和频繁 catalogue 更新仍是工程难点。

适用场景 / 局限 / 尚未解决的问题

适合 SID collision/ambiguity 明显、用户近期转移模式强的电商 next-item generation。尚未验证亿级 catalogue、在线 freshness、beam/batch Serving、长序列用户状态，以及与 query-aware/domain-aware SID 联合时是否仍增益。

未来研究方向

最值得押注的是 item posterior × prefix survival × adaptive stopping × dynamic catalogue，以及将业务 constraint（库存、地理、类目、价格）直接放进 item posterior 而非只放 SID。

对推荐 / 搜索算法工程落地和职业技能的启发

做生成式推荐不要只盯 sequence token loss；真正的业务对象仍是 item。要同时理解 token-level decoder、catalogue lookup、candidate pruning、transition prior 与 serving latency，才能把生成式模型从 benchmark 拉到生产。

重点精读 04 · Semantic ID / Long-tail / Hyperbolic Geometry

HypRQ-VAE：为什么长尾 Catalogue 的 Semantic ID 可能天然不该放在 Euclidean Space

Research Impact Score / 研究价值 9.1/10工业成熟度 ★★★☆☆创新性 ★★★★★与你方向的相关度 ★★★★★是否官方开源 是，代码与数据处理脚本是否有线上 A/B 否阅读优先级 最高

背景 / 业务动机

Semantic ID 通常先把 item text embedding 压进 RQ-VAE，再生成离散 code。现实 catalogue 却是典型 power-law：少数 head item 很密集，大量 niche item 稀疏分布。Euclidean space 的体积增长是多项式级，很容易让 sparse tail 被挤成 outlier 或在 quantization 时受更高误差。

现有问题

TIGER/LC-Rec/LETTER 等主要在 Euclidean codebook 上处理 reconstruction、collision、code diversity。它们能改善 token assignment，但没有改变“用平坦空间承载层级/树状/幂律目录”的几何错配。

技术方案与关键模块

HypRQ-VAE 把 residual quantization 移到 hyperbolic space，利用负曲率空间指数级体积扩张，让 head item 更靠近“树干”、tail item 更自然分散到边界。为保证唯一 SID，还增加基于 hyperbolic distance 的 cascading token reassignment：从最后一级 codebook 开始解决 collision，不够时向前一级回退，直到所有 item 唯一。

训练方法

先训练 hyperbolic tokenizer 生成 SID，再把用户行为转成 SID sequence，第二阶段可用 T5 encoder-decoder 或 Llama decoder-only 做 generative next-item fine-tuning。官方仓库已经给出 tokenizer training、index generation、T5/Llama fine-tuning/testing 脚本。

推理 / Serving 方案

Serving 仍是标准 autoregressive SID generation，因此 runtime 改造小；主要变化集中在 offline namespace/tokenizer。相比 EPIC，它更像“先把 item space 建得更合理”，而不是“解码时再纠偏”。

实验设置 / 离线指标

MovieLens、Amazon Instruments、Arts。相对 strongest baseline，MovieLens H@10 +4.8%；Instruments H@5 +11.3%、N@5 +13.2%、N@10 +14.0%；Arts 各项约 +2.4%–4.3%。更值得注意的是 long-tail split：MovieLens tail item Hit@10 相对 Euclidean TIGER 提升超过 52.71%，head item 为 +14.09%。

线上 A/B

无线上 A/B。

效率 / 成本收益

论文核心证据是 quality/long-tail fidelity，而非 wall-clock serving；超曲率 distance、Riemannian optimization 与 collision reassignment 会增加 tokenizer training complexity，但在线 generative inference 没有引入额外模型 stage。

与现有主流方法的优劣势

优势是直接对齐 power-law/层级结构，长尾提升非常有针对性；相对额外 long-tail loss，它把 inductive bias 放到 representation geometry。风险是 hyperbolic geometry 是否在亿级 item、多模态 embedding、频繁增删 item 下仍稳定；不同 catalogue 的最优 curvature 可能需要调节。

适用场景 / 局限 / 尚未解决的问题

适合 item 长尾特别重、niche discovery 很重要的内容/电商推荐。未解决 online remapping、new-item insertion、codebook versioning、极端 collision、head-tail business trade-off，以及与 query intent / geographic constraint 结合后的 geometry。

未来研究方向

可以研究 learnable curvature、product manifold、hyperbolic + constraint-aware SID、continual SID insertion、tail-aware beam search，以及 hyperbolic ANN 与 generative namespace 的联合。

对推荐 / 搜索算法工程落地和职业技能的启发

Semantic ID 不是“把 embedding 聚类一下”这么简单。未来高价值问题包括 geometry、collision、namespace stability、freshness、tail coverage 与 serving contract。对生成式推荐方向，这些比单纯换 LLM backbone 更值得深挖。

重点精读 05 · LLM Recommendation / Reasoning Distillation

SelfDR：把 Reasoning 留在训练期，把 Direct Recommendation 留给线上

Research Impact Score / 研究价值 9.0/10工业成熟度 ★★★★☆创新性 ★★★★☆与你方向的相关度 ★★★★★是否官方开源 是是否有线上 A/B 否阅读优先级 最高

背景 / 业务动机

LLM Rec 引入 reasoning 后，模型更能解释文本属性、用户偏好与候选差异，但线上生成几十到几百个 reasoning token 的成本对高 QPS 推荐不可接受。真正的工程目标是获得“reasoning 带来的决策质量”，而不一定要把 reasoning trace 本身 serve 给用户。

现有问题

直接 SFT 只学最终 label，难吸收复杂 preference signal；外部大模型 teacher 蒸馏成本高且模型分布不一致；test-time CoT/RecR1 等方式推理慢。SelfDR 试图用同一 base LLM 自己做 reasoner、teacher、student，减少外部依赖。

技术方案与关键模块

第一步训练 Reasoner，以 downstream recommendation performance 为 reward，生成针对当前用户/候选的 rationale；第二步把 rationale 放进 teacher recommender 的输入形成更强 posterior；第三步训练同 backbone 的 direct student，不看 rationale，通过 reverse-KL distill teacher logits，同时保留 ground-truth CE。dynamic weighting 会在 teacher 排错或弱于 student 时降低蒸馏权重。

训练方法

采用 offline self-distillation，teacher 固定。所有 LLM baseline 使用 LLaMA-3.1-8B-Instruct；reverse KL 鼓励 student 集中到 teacher 高概率候选区域。dynamic weight 同时考虑 positive item 在 teacher ranking 中距 top-k 的距离与 teacher/student rank gap。

推理 / Serving 方案

线上 student 直接输出 candidate character identifier，不生成 rationale。Clothing 上平均 input 1198.06 token、output 1 token、109.46ms/instance；与无 reasoning 的 SOFT 109.48ms 基本相同，而 COT4Rec 250.03ms、EXP3RT 529.83ms、RecSAVER 623.38ms、RecR1 665.12ms。

实验设置 / 离线指标

Amazon Clothing、Home、MovieLens-1M。Clothing H@1=0.0132，高于最佳 baseline RecR1 0.0114；NDCG@3=0.0200、NDCG@5=0.0228，均显著优于 best baseline。Home H@1=0.0148，也高于 COT4Rec 0.0142。论文还做 rationality 与 ablation 验证。

线上 A/B

无线上 A/B。

效率 / 成本收益

推理几乎回到 non-reasoning SFT 的成本，但训练更贵：单 A800 上 SelfDR 总训练 54.18h，SOFT 37.79h。换言之，它把 cost 从高频在线阶段搬到低频训练阶段，这正是推荐系统更容易接受的成本结构。

与现有主流方法的优劣势

相对 test-time reasoning，Serving 优势极大；相对外部 teacher distillation，没有 teacher model mismatch。但 rationale 的“知识”是否真的被 student 内化、是否在 distribution shift 下保持，以及 teacher 自身偏差是否被蒸馏放大，仍需长期线上验证。

适用场景 / 局限 / 尚未解决的问题

适合文本丰富、LLM reasoning 有增益但 latency 受限的 rerank/recall-enhance 场景。对亿级 candidate full-catalog generation、实时用户状态、高频 item churn 仍未覆盖。

未来研究方向

reasoning-to-ranking distillation、process reward + self-distill、multi-teacher uncertainty、candidate-adaptive reasoning，以及只有 hard request 才触发 reasoner 的 Fast/Slow rec 都很值得做。

对推荐 / 搜索算法工程落地和职业技能的启发

“Reasoning”应被当作训练/数据生成工具，而不是默认线上接口。算法工程师需要同时会 RL/reward、distillation、logit calibration、Serving cost modeling，才能把 LLM rec 的研究收益做成可上线系统。

重点进展 06 · Agentic Search / RAG / RL

SciLENS：把 Citation Topology 与 Visualization 变成 Agent 的主动检索动作

Research Impact Score / 研究价值 8.9/10工业成熟度 ★★★☆☆创新性 ★★★★★与你方向的相关度 ★★★★☆是否官方开源 是，代码与数据生成/评测工具是否有线上 A/B 否阅读优先级 很高

背景 / 现有问题

Deep Research Agent 通常依赖 Web/API，复现性、隐私和稳定性差；长链路文献综述还会把 citation topology 压成大量文字，导致 context exhaustion。单纯“多检索几篇”无法表达论文间结构。

技术方案 / 训练 / Serving

SciLENS 在本地构建约 12M academic records 的 MongoDB + distributed FAISS 双层索引，工具集同时提供 dense/keyword search、citation graph traversal、shortest path 与结构化图表生成。训练数据从 citation graph 做 random walk 采 subgraph，再由 20 个 frontier models 中随机 4 个做一致性核验；先用 DeepSeek-V3.2 蒸馏约 2 万条 tool trajectory，再用 rubric-based RL 对 early planning、reverse decomposition、evidence grounding 等过程信号奖励。推理完全离线，统一 toolbox。

实验 / 指标 / 成本

6 个 scientific benchmarks；SciLENS-RL 在 QASA 47.62、SciFact 88.94、PubMedQA 77.53，并取得强 citation accuracy；结构综合任务上 tool access alone 很弱，SFT+RL 才显著提升。论文称整体可与 GPT-5.2 / Gemini-3.0-pro 相比。没有线上 A/B；成本主要是 12M local index、GPU dense retrieval 与 agent multi-step rollout。

优劣势 / 适用场景 / 局限

真正新意是把 visualization 当 action，而不是结果展示；这与推荐/搜索的“group/cluster/page-level navigation”高度同构。局限是 scientific domain 特化、评价仍依赖 judge、12M local infrastructure 对普通团队并不轻；跨领域 generalization 与真实 user task 价值尚未验证。

未来方向与工程启发

值得迁移到企业搜索的 knowledge graph navigation、推荐内容簇/类目图导航、source-level planning；尤其可研究“结构图先压缩，再让 LLM 推理”的 context-budget policy。Agent 工程能力应覆盖 retrieval index、graph traversal、tool schema、process reward 与 eval，而不是只写 prompt。

重点进展 07 · Agent Memory / Retrieval

RuleMem：长期 Memory 从 Passive Facts 进化为 Active Retrieval Rules

Research Impact Score / 研究价值 8.7/10工业成熟度 ★★★☆☆创新性 ★★★★☆与你方向的相关度 ★★★★☆是否官方开源 否；截至今日未发现官方仓库是否有线上 A/B 否阅读优先级 高

背景 / 现有问题

长期对话 memory 通常把历史压成事实，然后按语义相似召回。问题是问题与证据经常没有词义邻近：“为什么缺席？”的证据可能是“订了假期”。仅靠 embedding similarity 会出现 semantic gap，即使事实召回了，LLM 也可能缺少显式 reasoning structure。

技术方案 / 训练 / Serving

RuleMem 从历史 interaction path 诱导自然语言 Horn clauses，把实体抽象成 [Person]/[Event]/[Location] 等 typed placeholders。Rule Perplexity Consistency（RPC）同时检查 rule body→head 是否降低语言模型困惑度，以及加入外部 fact evidence 后是否进一步降低困惑度；只有超过阈值的规则写入 memory。回答时先按 question 匹配 rule head，再用 rule body 作为 Guided Recall query，最后按规则做 Explicit Reasoning。

实验 / 指标 / 成本

LoCoMo 与 LongMemEval_s*；LoCoMo 对比 14 个 memory/RAG baseline，最高 accuracy，较 baseline 平均 +27.47 points（+54.3% relative）。Guided Recall 让多个 framework 平均 recall 从 0.56→0.79（+41.1%）。实验使用 gpt-4o-mini 做 rule abstraction/final reasoning，ChromaDB + all-MiniLM-L6-v2；因此不是纯本地、也没有 production latency/A-B 数据。

优劣势 / 局限 / 未来方向

优势是 rule 能跨 semantic gap 主动改写 retrieval intent；相比 graph memory，它的 rule 更可解释。风险是 LLM induced rule 可能过度泛化，RPC 只能降低而不能消除错误；规则失效/时效冲突也未解决。推荐领域可以把它迁移到“用户偏好条件 → item/category/source”的可验证规则 memory，但必须增加 freshness、counter-example 与 online feedback。

工程启发

长期用户建模不一定只靠更长 sequence encoder。显式 rule memory 可以成为 personalized retrieval 的高层 prior；值得结合 user interest state、query rewrite 与 candidate source routing。

工程进展 08 · Search Infrastructure / Embedding Serving · Perplexity

Perplexity：Embedding Serving 不应是另一套系统，而应复用 LLM Runtime 的 Kernel 与 Scheduler

Research Impact Score / 研究价值 9.2/10工业成熟度 ★★★★★创新性 ★★★★☆与你方向的相关度 ★★★★★是否官方开源 核心生产栈 Ivy/Tulip/ROSE 未整体开源；相关 kernel 有 upstream 贡献是否有线上 A/B 否；官方 production benchmark阅读优先级 很高

背景 / 业务动机

Search、ranking、RAG 都依赖 embedding：离线 reindex 是 throughput-first，在线 query embedding 是 latency-first，ranking batch 又介于两者之间。很多团队因此维护独立 encoder serving stack，但 Perplexity 的经验是小 Transformer embedding 与 LLM prefill/decode 在 GPU 行为上高度相似，可以共享大量 runtime。

技术方案与关键模块

端到端链路拆成 Ivy（Rust HTTP gateway：JSON/tokenization/batch split/load balance）→ Tulip（Rust tokio/tonic gRPC scheduler）→ ROSE（Python model engine + kernels + CUDA Graph）。批量 embedding 类似 compute-bound prefill；短 query embedding 类似 memory-bound decode。ROSE 直接复用 LLM kernels，pplx-embed 与 Qwen3.5 decode 甚至走同类 kernel path。

推理 / Serving 方案

小于 1B 的 embedding model 大约 512 token 就能把 GPU 吃满，因此 scheduler 不需要过度复杂。全模型 CUDA Graph 降低 CPU launch overhead；为了避免一次性 capture 数千种 shape 导致启动几分钟，采用 lazy capture：第一次 eager warmup、第二次 capture/replay、之后直接 replay。LazyTensor 用 pinned host buffer + cudaMemcpyAsync event 跟踪结果，让 Rust task 不阻塞 GPU/CPU pipeline。Embedding 不建立 KV cache，使用 ragged attention；FlashAttention 4 通常更快，但极长 Qwen-based shape 有时 FlashInfer 3 更好。

实验 / 效率 / 成本

官方以 vLLM v0.22.0、BF16、真实权重和 eval-derived input 做 benchmark，并同时覆盖 batch=1 低延迟、scoring batch、高吞吐和高并发端到端场景；文章强调自研 stack 在 latency/throughput 上扩展 Pareto frontier，但图表未给出统一单一 speedup 数字，因此不在这里硬写倍数。更重要的工程结论是：优化目标覆盖 tokenization、网络、scheduler、kernel、CUDA Graph 与 load balance，而不是只看 GEMM。

线上 A/B / 局限

无公开 A/B；属于 production infrastructure disclosure。自研 Rust + Python stack 的维护成本高，且收益依赖 workload shape；开源 vLLM/SGLang 对大多数团队仍更经济。

未来方向与工程启发

Embedding/Reranking 与 LLM Serving 会进一步共享 request scheduler、kernel registry、quantization、GPU graph 与 observability。对推荐/搜索工程师，GPU runtime、Rust/C++ service、tokenizer cost、batching 与 p99 已经逐渐成为算法系统能力的一部分。
