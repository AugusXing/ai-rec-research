S ① · Generative Retrieval / 地理约束 / GMPO · Research Impact 89/100

TS-GEAR｜TS-GEAR: Taobao Shangou GEnerative Ad Retrieval

arXiv:2611-12180 · 首次提交 2026-11-09 UTC；本期源于 arXiv 2026-11-10（周二）cs.IR 公告。首稿日、公告日与站点整理日不同，切勿混同。

研究结论：生成式召回如果不把地理可达性写进语义地址与解码，相关但不可履约的商家就是无效候选；GMPO 将个体转化与群体覆盖放入同一策略优化。

业务动机与现有问题

即时零售广告的候选有效性由距离、配送范围、营业状态与用户意图共同决定。传统双塔 ANN 依赖多路召回与地理后过滤，生成式 SID 虽能学习历史互动，却容易把远店、重复同类商家排到前列；单纯 next-token 点击监督也难直接优化整个广告候选集合。

技术架构与关键模块

先编码商家的地理位置与商品/店铺语义，构造三层 geo tokens 加三层 semantic tokens 的联合 Geo-Semantic ID；Query-Geo Target Attention 连接用户位置与地理邻域；User-Geo Gate 在解码前阻断明显无效地域前缀，随后生成商家 SID。地理前缀提供空间局部性，语义后缀区分经营内容，避免把地理过滤完全推迟到生成之后。

训练方法 / Loss / 监督信号

第一阶段以历史互动商家做自回归 SID next-token prediction；第二阶段采用 Group Marginal Policy Optimization（GMPO），将组内单商家点击/下单效用与整个候选集合的边际覆盖合并成优势信号。奖励不是只看 CTR：订单、点击、广告商业价值构成不同强度的业务反馈；此设计与传统 GRPO 的组内标准化不同，要审查候选多样性奖励是否产生低相关内容的投机。

推理与 Serving 方案

线上约 0.1B 生成器在 NVIDIA A10 上借助 TensorRT 执行；预处理/前缀计算覆盖附近九个 geo-hash 单元，地理门控控制候选合法空间，再约束解码生成 SID。论文称面向约 1.5 亿日级检索请求并控制在约 70ms 的服务预算内，需将该口径与总体链路 p99、实际库存/营业实时校验区分。

实验设计 / 离线指标 / 线上 A/B

Foursquare NYC 的 HR@20 为 0.8246（OneLoc 0.7868），TKY 为 0.7218（0.6812）；工业距离约束下 20km HR@50 相对 OneLoc 提升 36.3%。7 日生产广告随机 A/B 中，展现 +3.8%、广告效率 +0.4%、收入 +4.2%，作者报告 p<0.01；不能直接外推到商品评价 List 成交。

效率 / 成本收益

生成侧用小参数模型与先验地理单元收窄搜索，减少高并发 beam 的无效分支；但地理索引更新、SID 碰撞、生成到真实商家的映射、实时动态约束仍需依赖业务系统，论文未提供可跨系统比较的每千次请求 GPU-ms 与全链路峰值 p99。

与主流方法的优劣势

相对纯 TIGER/OneRec，TS-GEAR 将空间可用性与群体覆盖纳入训练及推理，优势是结果可消费且有生产证据；相对传统分层地理 ANN，结构更端到端但码本刷新、冷店覆盖、商业公平性与解释性更复杂。

局限、未解决问题与未来方向

仍需评估商家新开/关停时地理前缀漂移、极端密集商圈的同码碰撞、稀疏郊区长尾、送达半径的时间动态，以及点击/下单 reward 对非商业质量的挤压。评价推荐可以将 geo gate 替换成‘话题/观点/合规’门控，以 List-level 成交+满意度和负面观点覆盖评估 GMPO，而不是复制原始广告业务提升。

评价推荐落地与职业技能

建议实验：固定真实曝光候选池，比较 Generator NTP、NTP+合法性 Mask、NTP+Group Reward、完整 GMPO 四组；审查每条评论/商家的真实有效性、List 多样性、长尾 coverage、用户满意度及 P99。职业技能关注约束 Trie、Group Policy RL、线上随机实验及增量 ROI。

研究结论：下一代推荐基础模型未必统一所有场景的终端预测：共享长历史表征、缓存可复用状态，让垂直模型按候选和目标独立训练服务。

业务动机与现有问题

多个推荐场景各自拥有长序列大模型，重复读用户历史、重复算注意力 KV；虽然共享 backbone 能减少存储，却让短视频、电商、广告目标梯度互相干扰。统一预测头在用户意图迁移、实时特征更新和不同业务的 GPU SLO 上很难兼顾。

技术架构与关键模块

将共同的推荐基础模型 RFM 拆成只读用户长期行为的 candidate-agnostic 编码器，产出最终层状态/KV；不同 vertical model（VM）针对当前商品/广告建立 query，利用 cross-attention 读取共享状态，保留业务自有特征、目标与轻量的近期行为编码。RFM 可被多个 VM 复用，不必对每个候选重复历史编码。LG-Store 承担分布式 KV/状态管理与时间戳一致性。

训练方法 / Loss / 监督信号

RFM 进行多任务行为学习，不同目标通过权重平衡；各 VM 使用对应场景的候选条件监督独立优化，训练流量的时间切分须防止未来行为渗入 cached KV。这里的‘foundation’是多场景表征与状态迁移，不能推断为通用 LLM 文字生成；无需把所有评价满意度标签反向更新全业务 backbone。

推理与 Serving 方案

RFM 编码长历史后按用户缓存最终层 KV；VM 请求读取并按候选执行 cross-attention，近期短序列用本地轻量编码补新鲜度。作者给出缓存压缩的存储/传输权衡：INT8 约 50% 存储与 100% 传输保留，INT4 约 25% / 99%；用户级压缩约 1.3% 存储、92% 传输比率口径需回查原表，不能把保留率误当缩减率。

实验设计 / 离线指标 / 线上 A/B

工业 A/B：GIP 广告 9 天、约 20% 流量，ADSS +1.961%、ADVV +2.107%；抖音电商 14 天、约 30% 流量，短视频 Order/U +4.6306%、GMV/U +4.8077%，直播 Order/U +0.3673%、GMV/U +0.3524%。离线比较共享/独立架构与序列长度，并审查 TR 指标指‘迁移比例’而非直接 GMV。

效率 / 成本收益

论文基于同等 30 个独立端到端 VM 模型的假设测算 ROI，广告约 8.62×，电商约 2.62×；这是作者定义成本和模拟独立模型基线下的 ROI，不是用户收入直接增长倍数。GPU 计算复用换来跨服务网络读取、缓存过期和热用户管理成本，必须测全链路 p99/跨 AZ bytes。

与主流方法的优劣势

相对所有业务单独 HSTU/Transformer，SepLRM 显著减少重复历史长序列计算；相对彻底共享模型，它允许各 VM 保留本地快速上线与局部迭代。风险是中心 RFM 更新会影响全部下游，用户状态版本、缓存 TTL、冷启动和监督泄漏导致回滚边界复杂。

局限、未解决问题与未来方向

论文的跨业务 ROI 取决于可复用流量比例、用户聚合存储与网络带宽；对长尾低活跃用户是否值得缓存未得到充分通用解答。评价推荐建议共享‘用户长期评价关注主题/负面观点偏好’隐状态，独立训练成交与满意度两个 reward heads，再由 List-level 校准器合成，避免一组标签漂移污染全场景。

评价推荐落地与职业技能

按 A/B 分三组：独立历史编码、共享 RFM+实时 KV、共享 RFM+量化 KV；固定模型总 FLOPs，测用户分层 GAUC、评价满意度、Reward calibration、p99 与跨系统成本。技能路线是 foundation representation、KV Store 版本治理、分布式 Serving 和多业务因果指标。

RoutingTrie｜RoutingTrie: Metadata Routing for Constrained Generative Retrieval

业务动机与现有问题

一个三层 SID 的 token 都在目录中不代表它满足地区、品牌、价格、商家和属性过滤。生成完再删不合格候选会浪费有限 beam，尤其高过滤率或标签组合下最终不足 K 条；仅扩大 beam 又会显著伤害 tail latency。

技术架构与关键模块

保留目录 Semantic ID trie 作为词法合法性基座，为每个可过滤属性额外建立条件节点-候选映射：低基数字段使用 dense bitset，较高基数字段使用 sparse list，在 beam 搜索每一步预先评估子树内是否存在合法叶，动态屏蔽不满足 metadata 的后继分支。与每个过滤组合预建独立 Trie 相比，复用同一 catalog 索引减少组合爆炸。

训练方法 / Loss / 监督信号

方法属于检索侧约束索引与推理逻辑，不提出全新的 LLM/NTP/RL Loss；使用原有生成式推荐模型和训练权重，把‘可选择的合法 token’注入 decoding。需注意过滤规则是否可变更、候选集是否可靠，不能从 Hit@K 改善推出 Reward Model 更准确。

推理与 Serving 方案

Shopify 三层 8192 codebook 的 SID，14B 模型在 H200、TensorRT-LLM、beam 100 条件下测试；可在生成前路由，避免后过滤丢失高分合格结果。高基数字段 sparse list、低基数 dense bitset 具有不同缓存和访存特性，生产应控制 SQL 多条件布尔规则、组合爆炸、索引新鲜度与容量。

实验设计 / 离线指标 / 线上 A/B

ShopTrie 合成基准分析 SID 深度、beam 宽度、索引表示与过滤强度；作者用 23,167 个购买 session 的生产回放测 Hit@100 从 67.5% 升到 96.1%（+28.6 个百分点），median latency 27.1ms→28.2ms（+1.1ms）。这是约束下的离线命中回放，并非真实在线买单 uplift。

效率 / 成本收益

优点是对小幅中位延迟增加换取显著更多合格候选；但论文未完整给多种负载下的 P99、索引更新、活跃用户并发和动态库存的线上统计，若属性变更高频更新 bitset 反而可能成为瓶颈。

与主流方法的优劣势

与后过滤的纯 SID 解码相比，RoutingTrie 将预算花在可用候选上；与 LEGIT 的‘整张页面中的商家/商品组合、不可重复’约束不同，RoutingTrie 偏重通用元数据的合法路径选择。两者构建于不同任务和硬件，不能直接比较吞吐倍数。

局限、未解决问题与未来方向

动态价格区间、复杂布尔条件、数值比较与部分 SID 相同但叶属性不同等情况会产生保守掩码、误留或维护困难；还需验证不可售库存/语言/用户屏蔽规则的一致性。评价重排可按语言、是否真实购买、时效、风险词标记建 Trie 级条件，再让 Generator 只在安全可展示候选内优化 List Reward。

评价推荐落地与职业技能

落地实验：固定每次原始召回池，比较 post-filter、hard-prefix mask 和 metadata-indexed trie；评估合法 List 率、有效 Recall@K、负面观点覆盖、同 SID 多评价映射、索引维护成本及高负载 p99。补强索引/数据结构与 GPU beam 调试能力。

业务动机与现有问题

传统 grammar decoding 只保证语法 token 有效，而食物/商家异构结果页还需满足当前地理覆盖、营业、店内商品存在和整页不能重复。静态 SID trie 本身不知道 request-time eligibility；GPU 每 token 执行跨多级索引查找则会破坏高并发加速器利用率。

技术架构与关键模块

商家和商品分层建立 CSR-style compact tries，为叶节点做 DFS 排序，因此每个前缀子树对应连续的 [lo,hi) 叶区间。用 sorted eligible-leaf index 和 blocked-leaf 集，通过区间二分计数判断‘仍有未被消费的合法叶’才允许下一 token；店到菜品映射也用 CPU CSR 索引查询。校验商家商品同源、去重及动态可用性与解码语法统一。

训练方法 / Loss / 监督信号

核心工作是模型无关的 decoding algorithm 而非改造 Transformer 训练 loss；可直接配合先前训练的 SID Generator。与训练时 reward penalty 不同，这些 hard constraints 在动作空间级执行，不会让模型偷偷选择不可用前缀后再依赖后置清洗。

推理与 Serving 方案

CPU walk 与 GPU 生成并行，在同机/跨内存域下需协调 token masks、异步信号及批次；论文为约百万商家建立约 0.16GB trie、千万商品约 4GB trie，store→item 关联索引约 11GB CPU RAM。仅 CSR 信息稠密是其优势，在线仍需为请求刷新可配送叶集。

实验设计 / 离线指标 / 线上 A/B

基于 Uber Eats 一周脱敏生产请求回放，在单 B200 上按每 token 端到端耗时（含队列）比较 36 种方案，控制低负载与饱和两种模式。最佳 CPU 方案比 GPU-trie 控制耗时每 token 下降约 65.9%，但约为无约束解码 token 成本的 1.7 倍，绝非‘CPU 比无约束快 65.9%’。

效率 / 成本收益

GPU-tied 每一步分支检索可近约 5 倍于无约束控制开销，CPU 方案显著降低违规列表成本；但一旦 CPU 核数或内存带宽成为热点、请求 eligible 集过大，或者 GPU 批队列很短，收益可能改写。需要评估 GPU/CPU P99、batch blocking、索引跨版本错配。

与主流方法的优劣势

与 RoutingTrie（通用元数据路由以保留合格候选）不同，LEGIT 覆盖一张异构推荐页的父子逻辑和重复抑制，强调在线 eligibility 与 CPU-GPU 分工。索引全局化降低菜单级 Trie 数量，却扩大系统一致性要求。

局限、未解决问题与未来方向

仅核对 leaf count 不能防止目录顺序变更后错误配对；论文指出应添加同版本 fingerprint 但未实现。还需研究大量用户级个性化屏蔽条件、连续价格、软多样性限制、热更新期间快照一致性，以及与 reward 优化的训练/推理失配。

技术架构与关键模块

Structured Reasoning 将查询、AI Overview 和后续交互轨迹拆成行为级判断，逐条给出行为的语境含义、正负极性与不确定性，最后聚合输出有序满意度评分。STaRS 的解释步骤可被审查，而非仅输入行为特征向量后吐出一个 scalar。

业务动机与现有问题

Cross-encoder、LLM Judge 与 Jev typed decisions 都能给 relevance score，但这类输出一般只保证顺序，不保证 score=0.9 就有九成相关。电商评价混排如果把 Judge 概率直接乘成交预估或拿它当 List Reward，概率失准会放大低质内容和策略 reward hacking。

技术架构与关键模块

研究先用 typed categorical probability 读取 Jev 对相关级别的预测，再比较 pplx-decider、cross-encoder 的排序；针对二元 relevancy 采用 Platt scaling（对原始 log-odds 学两参数的 sigmoid 映射），在 DL19 拟合、DL21 不重新调参评估迁移校准与 ranking。可将校准概率按 query 自适应 threshold/f-score cutoff 决定返回条数。

训练方法 / Loss / 监督信号

论文不训练新的大模型/Generator；后处理拟合校准器，通过独立 dev split 学温度/截距，不应在 test label 上调阈值。与 DPO/GRPO List Reward 的重要区别：校准的是 pointwise relevance likelihood，仍需额外因果标定才能作为成交或满意度真实奖励。

推理与 Serving 方案

Jev API 返回有限类别 typed probability，重排依然需要 query×doc 成对调用。Platt 两参数服务开销可忽略，但调用 Jev 的模型费用和 p99 未量化；可缓存 query-document 判别并对高信心直接保留，对近阈值的 case 走二级交叉编码器校准。

实验设计 / 离线指标 / 线上 A/B

作者在 DL19 2,257 对样本拟合，迁移至 DL21：Brier score 0.213→0.147、ECE 0.211→0.100、log loss 1.315→0.478；DL21 Jev nDCG@10=0.705，对照 MiniLM=0.655，pplx-decider=0.726。Jev 自报≥0.9 的配对实际仅约 66% 相关；基于校准概率的动态 cutoff F1 0.638，对照固定 top10=0.506。

效率 / 成本收益

仅增加两参数映射，不增加昂贵 LLM 推理；但校准器需要持续收集独立的真实相关标注，跨 domain、跨类别和业务版本的时间漂移可能让离线 Brier 再次恶化。

与主流方法的优劣势

相比简单按 logit 做排序，calibration 使分数具备决策含义；相比让 LLM 直接生成相关性理由，typed probability 可做快速阈值。论文也发现某些 BEIR 跨域迁移使 Brier 变差，因此不能声称校准普遍提高所有任务的指标。

局限、未解决问题与未来方向

在线评价排序往往是多标签：有帮助、覆盖负面、促进成交、降低退货；分别校准 marginal probabilities 不能保证 List-level 联合效用可加。还需研究组别可靠性、偏差校正、query 难度迁移，以及 calibration under policy shift。

评价推荐落地与职业技能

先冻结 Jev/精排评分，按真实 query 与商品类目分桶绘制可靠性曲线、ECE/Brier、TopK 校准前后阈值对照；再用独立 exposure-list reward 做 Doubly Robust 校验。对低置信度曝光集中抽样标注，避免相似度与因果价值混淆。

业务动机与现有问题

TIGER/RQ-VAE、RQ-Means 一般每层固定码本大小，真实商品类目大小不均匀，结果是热门类目过密、冷品过稀，许多生成 token 把空间浪费在不可区分的兄弟商品；碰撞和冷启 item 需额外处理。

技术架构与关键模块

把商品 embedding 建成自顶向下的 Adaptive Silhouette Tree：每个节点根据内部样本 silhouette score 选分叉数 Kv，分层 KMeans；AST-V1 固定中心修复小概率分支质量下限，AST-V2 对概率质量做受约束重新优化，平衡前缀频率和聚类语义。生成码是根到叶路径，不再必须每层统一固定 K。新商品可按最近中心路由插入。

训练方法 / Loss / 监督信号

SID 构造独立于推荐生成训练：Qwen3-Embedding-0.6B 编商品标题/类目/描述，随后对所有 tokenizer 使用同一 T5 6+6 encoder-decoder 及 next-item token 监督，训练 batch256、学习率 1e-3、bf16；这样把 tokenizer 与生成器 capacity 尽量分离，未引入 List-level RL。

推理与 Serving 方案

推理需处理不等宽和可变深度树的合法 token mask，路径对齐与 catalog version 更复杂；热门类目大量分叉提高首层 softmax/beam 负担，长尾更短路径可能减少平均解码步数。论文在单 RTX6000 实验，未报工业百万 QPS 的实际吞吐和增量重建 SLA。

实验设计 / 离线指标 / 线上 A/B

5 个 5-core Amazon 数据集 Beauty/Sports/Toys/Health/Home，leave-last-out、最大历史长度 20。AST-V2 跨 5 域平均 Recall@5=4.00（论文百分数表）、Recall@10=5.95、NDCG@5=2.67、NDCG@10=3.29；相对最强非 AST tokenizer 四指标相对提升约 12.68%、13.55%、12.66%、13.45%，整体相对收益 13.08%。指标绝对值与场景规模需要配表解读。

效率 / 成本收益

动态分叉的 silhouette 优化需重复 KMeans 和子树评估，构建计算与目录更新比固定码本复杂；仅报告模型离线精度，不说明长尾实际增量候选覆盖或稳定 p99。

与主流方法的优劣势

相对 RQ-VAE/RQ-Means，AST 避免统一分叉的结构先验偏差，且同一生成器基线做了 fair comparison；但 AST 的训练/建索引/增量更新成本尚不足以证明比 Shopify SID、RedMall 工业系统整体更优。

局限、未解决问题与未来方向

商品实时新增会导致树结构漂移，SID 变化污染用户历史、缓存和已训练 logits；需对 cold item 插入、prefix 频次、碰撞公平、负面评价小类目做分桶验证。能否直接把‘商品 SID’转成‘用户评论观点 SID’尚不确定。

业务动机与现有问题

图像+一句模糊 query 不足以表达用户预算、偏好、距离和属性权衡；纯 CLIP/BGE 重语义相似、未必理解‘像图里的环境但适合带孩子’。直接用大视觉语言模型逐候选评分成本极高，且工具推理可能无目标地乱调用。

技术架构与关键模块

两阶段：Grounder 先通过视觉解析、episodic/semantic 用户记忆、候选属性工具进行 query-side disambiguation 和 item-side enrichment，得到可审查的显式约束；Scorer 不调用工具，对 grounded query 与候选文本用 BGE-M3 共享双塔编码、CLS pooling、L2 norm 后点积做低成本排名。将昂贵工具调用集中在前置澄清。

训练方法 / Loss / 监督信号

轻量双塔使用 InfoNCE，对真实匹配候选作正例、同类 hard negative 作负例。Grounder 使用任务反事实排名 reward：执行策略选择的工具后由冻结 ranker 评价最终候选排序，并加入 query-side/item-side 工具奖励；trajectory-level masked GRPO 对有实际策略梯度的调用 token 更新，rollout group size=4，避免仅靠答案 token 算 reward。

推理与 Serving 方案

Grounding 依赖多次外部工具查询、视觉与用户长期记忆检索，具体 p99 和工具失败回退没有完整工业数据；推断可缓存 image attributes 和候选侧 enrichments，给 user memory 设置 TTL/授权边界，若工具超时退回普通双塔/精排。大模型不要对每个候选重复推理相同图片。

实验设计 / 离线指标 / 线上 A/B

构造 GoogleReview-MMTool（3,000 用户、773 query、每 query 平均候选 40）与 Yelp-MMTool（2,315 用户、1,727 query、平均候选 63），按用户交互生成模糊 query 再做泄漏检查。IntentLens 7B 在 Google 的 Hit@10=62.1%、MRR=40.2%；Yelp Hit@10=70.4%、MRR=46.7%，相对 3B 版本有所提升。Google 7B Hit@1 31.0% 并不显著高于全部强基线，需实事求是。

效率 / 成本收益

收益来自将昂贵多模态推理次数限制到少量工具决定，后续双塔批量算分；代价是 query memory 隐私、视觉解析服务费与工具调用不确定性，论文未披露线上每千次 request 的全链路 GPU-ms、检索 cache hit 和尾延迟。

与主流方法的优劣势

相对直接把图片与商品一起送入 LLM 判断，ground-then-rank 可复用证据和低成本 scorer；相对 RAG 类固定召回链路，包含用户记忆和学习后的何时查工具策略。若 Grounder 错取偏好或缓存过期，轻量 ranker 只能忠实放大错误，这也是两阶段系统的脆弱点。

局限、未解决问题与未来方向

合成 benchmark 的语义偏好是否反映真实交易和评价满意度、工具结果是否存在信息泄漏、记忆/位置数据隐私授权以及动态属性更新需线上验证。还需测试没有历史的冷用户、主观审美和多个相互冲突的购买约束。

评价推荐落地与职业技能

评价内容场景将商品图/规格与买家模糊问题结合，工具抽取关键评价观点、尺寸/物流/真实负面证据，最终生成 List 前先做 evidence coverage；离线测 query intent coverage、hard-neg 判别、多观点覆盖，再 A/B 测成交/满意度。职业技能关注 Agent tool routing、行为记忆、反事实奖励。
