Daily Research Brief · 2026.08.26

推荐系统的 Scaling 正从“更多数据 / 更大上下文”
转向“更高信息密度 / 更主动的预算分配”

过去 24 小时最值得追踪的是 arXiv 2026-08-25 新批次。今天几篇强工作形成了非常一致的信号：蚂蚁 DeepFind 在支付宝十亿级行为数据上观察到原始用户数、历史长度和模型参数都会遇到明显饱和，提出 User Behavioral Densing Law，把问题改写成“单位 token 承载多少有效行为信息”；北大 × 腾讯则在 Generative Search 中证明把更多文档一次性塞进 context 会产生 relevance dilution，真正有效的是多轮、闭环、因果反馈驱动的 Context Allocation。生成式推荐侧，SST 又进一步证明 history token grammar 与 target token grammar 不应强行一致；Reasoning Trace 研究则提醒我们：解释得更漂亮，不代表推荐得更准。

今日核心结论：“Scaling”正在从纯粹扩大容量，变成提高信息密度并主动分配计算。 对推荐 / 搜索工程最重要的三个方向是：① User Representation 从 Raw History Scaling → Behavioral Tokenization / Densing；② RAG / Agent Search 从 Wider Context → Causal Measurement + Closed-loop Allocation；③ GenRec / LLM Rec 从统一 token / 显式 CoT → Task-specific Representation Grammar + Utility-aligned Objective。真正长期有价值的系统资产会是 Tokenizer、Context Scheduler、Reward / Re-rank Objective，而不仅是 Backbone。

01 · User Representation / Scaling Law · 今日精读

Towards a Densing Law：十亿级用户表征的瓶颈不是“模型不够大”，而是“行为信息密度不够高”

Research Impact Score / 研究价值 9.7/10工业成熟度 ★★★★★创新性 ★★★★★与你方向相关度 ★★★★★是否官方开源 未确认是否有线上 A/B 否 / 未披露阅读优先级 最高

背景 / 业务动机

工业推荐常见的 scaling 路径很直接：更多用户、更长历史、更大 encoder。但支付宝 PayBill 的真实数据给出一个很重要的反例。论文覆盖约 100M–2B 用户、30–270 天行为窗口、0.05B–0.4B 参数用户模型，每个用户约 2200 个行为文本 token，并在分类、文本用户检索和 U2U 检索上做固定下游评估。结果显示，原始行为输入在约 0.03B 用户和 60 天附近就出现明显边际收益衰减；把 encoder 从 0.2B 扩到 0.4B，训练 loss 继续下降，但下游表示质量几乎不再增长。

现有问题

长历史并不等于高信息量。支付、常用小程序、重复消费包含大量周期性与习惯性事件，raw token 数增长远快于新的 task-relevant signal。继续扩大参数只是让模型更擅长拟合重复细节，形成 loss–quality dissociation。这意味着工业上的“Long Sequence”如果没有压缩 / 去重 / 结构化，很可能只是把算力花在冗余行为上。

技术方案与关键模块

作者提出 User Behavioral Densing Law：把最小充分 tokenization capacity 与输入数据规模建立定量关系，经验上二者在 log-space 近似线性，且斜率取决于 tokenizer 方法与数据源内部独特性。论文进一步提出 ALGN（Adaptive Length Gated Network），在 RQ-VAE residual quantization 上为不同用户 / 行为样本动态决定需要多少层 code，复杂、高熵行为分配更多 token，重复、可预测行为使用更短表示。

训练方法

预训练将用户序列切成 past / future。Past 由 Transformer user encoder 编码；Future 行为通过模板转成文本描述，再由 LoRA-tuned Qwen3-Embedding 生成监督向量，LoRA rank=16；两侧使用 InfoNCE 对齐。Tokenizer 则单独学习压缩的行为离散表示，并通过 densing law 选择足够而不过量的 codebook / residual capacity。

推理 / Serving 方案

论文重点不是在线 ranker latency，而是共享用户表征资产：预训练后的 user embedding 可用于广告 / 风控分类、自然语言人群 targeting、U2U 检索与推荐。工程上真正的收益来自输入侧——如果 tokenizer 能把重复行为压成更少、更高密度的 token，就可以在相同 context / compute budget 下覆盖更长真实历史，或在相同质量下减少 encoder FLOPs 与存储。

实验设置 / 离线指标 / 线上 A/B

下游分类覆盖 50 个数据集，文本检索与 U2U 检索各 22 个数据集，每组约 50 万用户。Raw scaling 实验显示用户量超过约 30M、历史超过约 60 天后收益显著变平；模型超过约 0.2B 参数后继续降低训练 loss，却没有对应下游收益。ALGN 相比固定或其他 adaptive tokenization 在更小 capacity 下取得更优效果；论文报告其容量约为 RQ-VAE 基准的 63.47%，分类 AUC / KS / Accuracy 达 76.43 / 43.31 / 83.52，并相对强 adaptive baseline 在性能与容量上同时改善。未披露线上 A/B。

效率 / 成本收益

价值不在单点速度，而在 capacity planning：过去需要靠经验选“保留 90 天还是 180 天、codebook 多大、encoder 多大”，现在可以先测出当前数据源的饱和曲线与 densing slope，再决定 token capacity。对十亿用户级系统，这种方法带来的存储、训练 token、离线 embedding refresh 成本可能远比换一个 backbone 更重要。

与主流方法的优劣势 / 适用场景

相对 Long Sequence Transformer，它没有直接追求让 attention 吃下所有行为，而是先解决输入冗余；相对普通 RQ-VAE，它不再为所有用户固定 residual depth。最适合支付、电商、内容消费、广告等大量重复行为的平台。缺点是“什么是最小充分信息”仍依赖下游任务分布，数据源变化后 scaling slope 需要重新校准。

局限 / 尚未解决 / 未来方向

当前 law 主要在特定工业用户行为与离线任务上验证，尚未证明对实时推荐线上目标、强时效兴趣、多模态行为同样成立；动态 token 长度也会给 batching、KV cache 和下游 feature schema 带来复杂度。下一步值得研究 task-conditioned densing、freshness-aware token capacity、multi-source token budget、以及 token density 与 online GMV/CTR 的直接关系。

对推荐 / 搜索算法工程落地和职业技能的启发

推荐工程师要开始把“数据规模”拆成 raw volume、unique information、token density、minimum sufficient capacity。Long Sequence、Semantic ID、User Foundation Model 未来都会需要类似 Scaling Dashboard：历史窗口、用户覆盖、tokenizer capacity、encoder 参数量分别在哪个区间继续有边际收益。

02 · Agentic Search / RAG · 今日精读

The Laws of Context Allocation：RAG 的下一步不是“塞更多文档”，而是闭环决定下一轮该看什么

Research Impact Score / 研究价值 9.4/10工业成熟度 ★★★★☆创新性 ★★★★★与你方向相关度 ★★★★★是否官方开源 是是否有线上 A/B 否阅读优先级 最高

背景 / 业务动机

Deep Search / Generative Search 通常把 retrieval top-k 扩大，希望更大的 context 提供更高 evidence recall。但文档越多，LLM attention 越容易被弱相关内容稀释；同时传统 relevance score 只能说明“文档看起来相关”，不能回答“模型最终到底用了哪条证据”。

技术方案与关键模块

论文先用 causal leave-one-out probe 测量某条 evidence 对生成结果的真实贡献：对 k 个 evidence 做可并行 teacher-forced 对比，而不是用 lexical similarity 或 self-reported citation。之后提出 closed-loop scheduler：每轮生成后更新 evidence utilization matrix，再通过 submodular scheduling 惩罚已被充分覆盖的文档，把后续轮次预算推向未覆盖 facet；可选 attribution-steered contrastive decoder 用于打破模型继续依赖旧证据的惯性。

训练方法

核心并不是重新训练大模型，而是 test-time orchestration。模型本身保持固定，通过 causal measurement 建立“query × evidence × generation”反馈，再调度下一轮 context，因此更接近可插拔 Search Controller / Re-ranking Policy。

推理 / Serving 方案

关键是将总 context slot budget 从一次性宽 prompt 改成多轮窄 prompt。论文比较同样 24 个 evidence slots：24 docs × 1 round 与 2 docs × 12 rounds。后者把计算从大 prefill 转为多轮 sequential decode / generation，质量显著提高，但 wall-clock latency 明显增加，因此适合高价值 Deep Search，而不适合每个低延迟检索请求。

实验设置 / 离线指标 / 线上 A/B

在 ASQA / QAMPARI 等 generative search 设置中，多轮 allocation 带来约 16.7–20.5 个百分点 portfolio recall 增益。预算匹配下，Qwen2.5-14B pooled portfolio recall 从 0.266 提升到 0.400；Qwen2.5-32B 从 0.291 提升到 0.429。闭环 scheduler 相比 open-loop 进一步提升终局 evidence utilization / recall。无线上 A/B。

效率 / 成本收益

它明确给出一个 trade-off：2×12 sequential setting 约 17.5s，而 24×1 约 1.7s。也就是说“更聪明的 context allocation”不是免费午餐，而是在高 recall 需求下获得更好的 compute-quality frontier。生产系统最合理的做法是先做 query value / difficulty routing：简单问题走单轮宽度适中 context，复杂研究类请求才进入闭环多轮。

与主流方法的优劣势 / 适用场景

相对 top-k RAG，它能显式发现 evidence 被忽略；相对 agent 自由 search，它的反馈信号更可测、更可复现。最适合 research assistant、复杂多 facet 查询、长报告生成。缺点是 sequential latency 高，而且 causal LOO 仍增加额外 forward pass。

局限 / 尚未解决 / 未来方向

还需要解决低成本 attribution、跨轮 cache reuse、事实 freshness、tool/search API 成本，以及用户何时愿意等待更久。最值得迁移到推荐 / 搜索的是：把 Context Allocation 当成一个 Ranking / Budget Allocation 问题，reward 不只是 relevance，还包括 coverage、novelty、cost 与已消费信息。

对推荐 / 搜索算法工程落地和职业技能的启发

这和重排非常像：第一阶段召回候选 evidence，第二阶段不是简单 top-k，而要根据“已覆盖信息”动态重排剩余候选。未来做 Agentic Search / RAG 的算法工程师，需要同时掌握 retrieval、slate / submodular reranking、causal attribution 和 inference budget routing。

03 · Generative Recommendation / Semantic ID · 今日精读

Semantic Subword Tokenization：历史序列需要“语义词”，但生成目标仍需要稳定的“语义字”

Research Impact Score / 研究价值 9.2/10工业成熟度 ★★★★☆创新性 ★★★★★与你方向相关度 ★★★★★是否官方开源 是是否有线上 A/B 否阅读优先级 最高

背景 / 业务动机

GenRec 常把每个 item 拆成固定长度 SID，例如四个 residual code。用户有 100 个 item，就变成约 400 个低层 token。Transformer 不得不反复学习“这四个 token 其实属于同一件商品”，论文把这种浪费称为 Intra-item Attention Overload。

技术方案与关键模块

SST 有两部分：IST 将历史侧高频、稳定的相邻 SID atom 合并成 semantic subword，让一个历史 item 可由更少 token 表示；BCA 从真实行为序列挖 item semantic prefix 的 co-occurrence / transition 关系并做 replay augmentation，把被释放出来的建模能力引导到真正重要的 inter-item behavior transition。

训练方法

最关键的是非对称 tokenization：只改变 history / encoder side，target / decoder 仍使用固定长度 SID 和原 constrained decoding trie。三个 backbone——TIGER-KM、TIGER-VAE、LETTER——均验证同一设计。T5-style encoder-decoder 为 4+4 层，hidden 128，beam size 20。

推理 / Serving 方案

Target grammar 不变，因此线上生成和 trie 约束几乎无需重构；history 平均 token 数减少，prefill / encoder attention 更便宜。Beauty 上平均 history length 28.61→26.73，完整训练+评测时间 0.718h→0.659h；Instruments 27.92→23.41，0.729h→0.691h，整体没有系统性变慢。

实验设置 / 离线指标 / 线上 A/B

在 Beauty、Musical Instruments、Yelp 三个数据集和三个 GenRec backbone 上均提升。TIGER-KM 的 NDCG@10 相对最强非 SST baseline 分别约 +10.0%、+5.3%、+8.3%；TIGER-VAE 与 LETTER 也一致收益。更重要的负结果：Yelp 上 fixed history / fixed target NDCG@10=0.0205，variable history / fixed target=0.0219，而 variable history / variable target 降到 0.0178；含 merged subword 的 target bucket 几乎崩到 0.0001。

效率 / 成本收益

IST 减少 history token 的二次 attention 成本，BCA 会增加训练样本，两者大体抵消。它的工程优势是不用重写 decoder vocabulary / trie，而先从 prefill 侧获益，这比直接让 target 变成 variable-length 更容易落地。

与主流方法的优劣势 / 适用场景

相对固定 SID，它提高 history 信息密度；相对简单 item pooling，它仍保留 code-level 结构；相对 history/target 全部可变长，它避免 autoregressive long-tail token frequency 问题。适合 SID 已稳定、但长序列 prefill 成本高的 GenRec 系统。

局限 / 尚未解决 / 未来方向

Subword vocabulary 会随 catalog 和行为分布漂移，需要 versioning；不同用户群是否应使用不同 subword grammar 仍未研究。未来可继续做 user-conditioned merge、frequency-aware target subword curriculum、Dynamic SID × SST 联合优化。

对推荐 / 搜索算法工程落地和职业技能的启发

一个非常值得记住的设计原则：History Representation 的最优 token 单位，未必等于 Prediction Target 的最优 token 单位。 推荐模型做统一 tokenization 前，应分别审视 encoder context efficiency 与 decoder search stability。

04 · LLM Recommendation / Reasoning Alignment · 今日精读

Reasoning Trace 与推荐效果脱钩：更会“解释”，可能并没有更会“推荐”

Research Impact Score / 研究价值 9.3/10工业成熟度 ★★★☆☆创新性 ★★★★☆与你方向相关度 ★★★★★是否官方开源 未确认是否有线上 A/B 否阅读优先级 最高

背景 / 业务动机

生成式推荐越来越喜欢在 SID prediction 前加入自然语言 reasoning，希望模型先解释用户偏好再生成 item。但“reasoning trace 更可读”与“Top-K 推荐更好”往往被混为一谈。该论文用统一 Qwen3-1.7B backbone，在 SID vs Title、轻量 vs 深度语义对齐两个轴上做控制实验。

现有问题

SID 是不透明离散码，因此要让 LLM 在其上自然语言 reasoning，需要额外 alignment；Title 则天然有语义。若 reasoning 真能提升推荐，那么在更 grounded 表示、更完整对齐之后，offline Recall 应该同步提高。实验恰恰没有得到这个结论。

技术方案与关键模块

作者比较 no-reasoning baseline、Reasoning SFT、GRPO accuracy reward、以及 GRPO + Judge。完整 SID alignment 包含 8 类任务，例如 next-item、Title↔SID translation、cross-representation recommendation 与 grounding。Judge reward 将 accuracy、trace quality、recommendation relevance 组合为 0.5 / 0.25 / 0.25。

训练方法

SFT 先让模型输出 descriptive trace + recommendation；GRPO 再用 prefix / item match reward 优化。关键诊断是 reward sparsity：70%–96% prompt 的 16 个 sampled generations 全部得到 0 reward，因此没有 advantage、几乎没有学习信号。加入更 dense 的 relevance reward 后能恢复部分效果。

推理 / Serving 方案

Reasoning 会增加 decode token 与 latency，但论文没有发现这种额外计算稳定换来更好 Recall。因此生产环境如果最终目标是 CTR / order / retrieval metric，应该先验证“CoT token 的增量收益”，而不是默认解释层必需。很多场景更适合 hidden reasoning / dense reward / lightweight intent state，而不是长自然语言 trace。

实验设置 / 离线指标 / 线上 A/B

三类 Amazon domain 上，显式 reasoning 在标准 SFT / RL 下普遍降低传统推荐指标，即使 Title 的 trace 明显更 grounded。更完整 SID alignment 可提升 representation grounding，却不能让 reasoning 的 recommendation gain 变成正向。GRPO+Judge 能在部分 Office / Industrial 设置恢复或略超 baseline，说明关键更可能是 reward density 与 relevance supervision，而不是 trace 本身。

效率 / 成本收益

负结果本身就是重要成本结论：不要为“可解释感”无条件支付训练对齐成本 + 推理 decode 成本。如果线上不需要展示 explanation，应优先把预算投入 candidate grounding、dense reward、retrieval supervision 或 reranking。

与主流方法的优劣势 / 适用场景

它不是提出更强模型，而是在纠正研究目标。对需要用户可解释界面的产品，trace 仍可能有 UX / trust 价值；但对纯推荐效果优化，trace quality 不应当被当作 ranking utility 的 proxy。

局限 / 尚未解决 / 未来方向

实验仍是离线 Amazon、单一小型 backbone，不能证明大模型或线上 RLHF 也会同样脱钩。下一步应直接研究 reasoning token marginal utility、online behavior reward、latent reasoning vs verbalized reasoning、以及 recommendation-calibrated judge。

对推荐 / 搜索算法工程落地和职业技能的启发

评估 LLM Rec 时至少拆三条轴：Recommendation Utility、Reasoning Quality、Explanation UX，不要把其中一个指标当成另两个。做 RL 还必须先看 reward hit-rate / zero-reward ratio，否则算法换成 GRPO 也不会产生有效梯度。

05 · CTR / Trigger-Induced Recommendation · 今日精读

CRRN：相关推荐不能只看“用户长期喜欢什么”，还要显式建模“他刚刚为什么点了这个 trigger”

Research Impact Score / 研究价值 9.2/10工业成熟度 ★★★★★创新性 ★★★★☆与你方向相关度 ★★★★★是否官方开源 是是否有线上 A/B 是阅读优先级 最高

背景 / 业务动机

Trigger-Induced Recommendation（TIR）是典型“点进一个商品后继续刷相关推荐”的场景。Trigger 比普通历史行为更接近当前即时兴趣，但又不像搜索 query 那样显式。传统 DIN/SIM 主要从长期序列抽 user interest，容易忽略 trigger-target relevance；只强调相关性又会把页面做成同质化列表。

技术方案与关键模块

CRRN 包含三部分：Trigger-Target Interaction 用 personalized gate 学 trigger 与 target 的显式 / 隐式交互；Cascading Interest Fusion 先估计 trigger intention，再通过级联 attention 自适应融合即时兴趣与长期个性化兴趣；Category-assisted Pairwise Loss 用 trigger / target category association 额外约束相关性。

训练方法

工业数据约 769 万用户、2251 万 item、4.50 亿样本；序列长 100，Adagrad，batch 1024。Intention label 只在训练阶段提供监督，线上 inference 不需要额外 label；category pairwise auxiliary loss 与 CTR 主任务联合优化。

推理 / Serving 方案

模型已部署到 NVIDIA L20，论文给出的线上 latency 从 baseline 约 42ms 增至 CRRN 约 45ms，仍远低于 150ms 服务预算。说明即时兴趣建模不一定需要 LLM / heavy cross encoder，结构化 gating + attention 可以以很小开销进入精排。

实验设置 / 离线指标 / 线上 A/B

工业数据 AUC 从 DIN+trigger baseline 0.6648 提升到 0.6752，RelaImpr +6.31%；公开数据 AUC 0.6448。天猫 4 月 10–17 日线上 A/B 相比此前 online model：IPV 0.87→0.92（+5.75%）、PV 19.70→20.34（+3.25%）、CTR 3.11%→3.23%（+3.87%），论文称已在线 serving。

效率 / 成本收益

训练阶段比 DIN 增加有限额外时间，在线只增加约 2–3ms，却带来明显 CTR / 浏览深度提升，属于很典型的“工业上高 ROI 的小结构创新”。

与主流方法的优劣势 / 适用场景

相对 DIN，它显式利用 trigger；相对只做 item-to-item similarity，它保留 personalized history；相对 LLM reranker，成本低、容易部署。非常适合电商相关推荐、短视频“看完这个继续看”、新闻 related feed 等有强当前 anchor 的场景。

局限 / 尚未解决 / 未来方向

Category 是较粗粒度 proxy，可能对跨类目互补关系不足；pairwise relevance 与 diversity / novelty 仍需后续 slate 层协调。未来可以做 multi-trigger session state、semantic trigger intent、candidate-aware long sequence、以及 trigger relevance × diversity 的重排约束。

对推荐 / 搜索算法工程落地和职业技能的启发

对精排工程师，这是今天最实用的一篇：不要把所有历史行为等价处理。当前 request 的 anchor / trigger 往往应该进入 attention query、feature interaction、auxiliary loss 和线上指标体系。

06 · Agent / Retrieval Safety · 高价值补充

Risk-Aware Reranking：Tool Retrieval 的 Top-K 本身就是安全边界

Research Impact Score / 研究价值 9.0/10工业成熟度 ★★★★☆创新性 ★★★★☆与你方向相关度 ★★★★★是否官方开源 是是否有线上 A/B 否阅读优先级 高

核心：在固定一阶段 retriever 后，用冻结 ToolRet-BGE encoder 上的轻量 relevance head 与 risk head 做 score = relevance − λ·risk，再用 ToolGraph 平滑与 rule filter 控制 permission / high-risk exposure。论文标注 6108 个 tools、5 个风险级别。它的重要性在于把 Agent Safety 提前到 retrieval / reranking，而不是等 tool 已执行后再拦截。

训练 / Serving / 实验：仅训练小 head，模型成本远低于大 LLM reranker；rule-filtered setting 可显著降低 risky tool exposure，但 λ 太大也会误伤“任务确实需要的高风险工具”，因此真正生产化仍需 query-conditioned policy。无线上 A/B。

工程启发：它与广告/推荐多目标重排高度同构：relevance、risk、permission、redundancy 都是 slate objective。Agent 工程师应把 candidate action space 当成可学习、可审计的 ranker 输出。

07 · Diffusion Generative Recommendation · 高价值补充

ANR-DiffRec：离散 Diffusion 的 noise schedule 也应该看 item 协同结构

Research Impact Score / 研究价值 8.8/10工业成熟度 ★★★☆☆创新性 ★★★★☆与你方向相关度 ★★★★★是否官方开源 是是否有线上 A/B 否阅读优先级 高

核心：当前 discrete diffusion GenRec 往往 SID 偏 semantic，denoising 又用统一 noise schedule，协同过滤中的 item-item co-occurrence 没有真正进入生成动力学。ANR-DiffRec 一方面用 item co-occurrence 引导 Semantic ID generation，另一方面根据 local recoverability + behavior-aware item dependency 自适应调整 denoising 权重。

实验 / Serving：在多个 Amazon Reviews 2023 category 上优于若干 GenRec baseline；无线上 A/B。Diffusion 的现实问题仍是多步 denoising latency，因此当前更偏研究价值，但“collaborative structure should affect generation schedule”这一思想值得迁移到 masked generation / draft refinement。

工程启发：Semantic ID 不应只由 content embedding 决定，协同共现应该同时进入 tokenizer、training noise / corruption policy 和 retrieval reward。

08 · Agent Memory / Context Management · 高价值补充

The Compaction Cliff：统一摘要会把“可压缩记忆”和“必须逐字保留的规则”一起压坏

Research Impact Score / 研究价值 9.0/10工业成熟度 ★★★★☆创新性 ★★★★☆与你方向相关度 ★★★★☆是否官方开源 是（论文声明）是否有线上 A/B 否阅读优先级 高

核心：20 个生产 Agent 配置中，Claude Code /compact 在 Sonnet 4.6 上一次压缩后仅保留约 53% safety rules，五轮后仅约 10%。论文提出 Knowledge Triage：先按知识类型分类，再分别执行 TypeCompact、TypeDecompose、TypeRetrieve；安全规则与约束被 pin / replicate，而 episodic log 可以更激进压缩。

实验：五个公开语料上 safety-rule retention 比最强 single-shot LLM compactor 高 2–4×，五轮后 96% recall；TypeDecompose locality violation 0% vs uniform partition 93%；TypeRetrieve Recall@50 100% vs 73%。论文同时声明发布 396,934 个 agent configs 的 AgentArtifactCorpus、classifier 与 reference implementation。

工程启发：Memory / Context 不应有统一 TTL 与 compression ratio。规则、用户偏好、任务状态、历史对话、检索证据需要不同 retention policy；这和推荐 Feature Store 的 feature type / freshness 管理非常相似。

09 · Long-term Agent Memory / Stateful Reranking · 高价值补充

EARM：Retriever 也应该积累“哪些 Memory 曾经有用”的经验

Research Impact Score / 研究价值 8.9/10工业成熟度 ★★★☆☆创新性 ★★★★☆与你方向相关度 ★★★★★是否官方开源 未确认是否有线上 A/B 否阅读优先级 高

核心：Semantic Retriever 很便宜，但不知道某条 memory 在过去实际回答中是否有用；LLM reranker 更准，却每个 query 都重新打分。EARM 把历史 query×memory 的 LLM relevance score 存成稀疏矩阵，用 causal matrix completion 估计未观察 pair；新 query 只对少部分候选调用 LLM，再把 observed + estimated score 混合重排。

实验 / 成本：长程对话 memory benchmark 上，answer accuracy 相对 semantic retrieval 最高 +6.62%，即使只有 17.5% candidate 直接接受 LLM relevance scoring 仍有效。核心价值是把 reranking 从一次性 request expense 变成 lifetime-amortized learned asset。

工程启发：这可以直接迁移到推荐：过去 ranker / LLM judge 对 user-item、query-doc、intent-memory 的高成本打分，不一定要丢弃；可以沉淀成 stateful relevance cache / teacher matrix，再通过低成本模型估计未见 pair。

今日串联 · What changed?

把 9 篇放在一起，真正变化的是“计算预算的分配单位”

Raw History→Densed User Tokens→Asymmetric SID Grammar→Candidate / Trigger-aware Ranking→Causal Context Allocation→Stateful Memory / Risk-aware Rerank

过去的 Scaling 单位主要是参数、样本、历史长度、context window；今天这些论文共同把它换成了 information density、token grammar、evidence slot、risk budget、retrieval experience。对推荐 / 搜索算法工程而言，这意味着下一阶段能力边界越来越来自“如何分配有限 budget”，而不是单纯“能不能训练一个更大的模型”。
