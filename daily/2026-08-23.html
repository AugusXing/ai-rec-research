缓存不再只是命中率：
Routing、State 与 Index Geometry 正变成系统一等变量

北京时间 8 月 23 日是周日，过去 24 小时没有新的 arXiv 日更批次；最新公开批次仍是 8 月 21 日（论文主要于 8 月 19–20 日提交/修订）。因此今天不把旧论文伪装成“24h 新投稿”，而是从最新批次中补齐昨日未覆盖、但对推荐/搜索/Agent/Serving 最重要的工作，并纳入 8 月 21 日 NVIDIA 官方研究更新。今日最强信号：Prefix Cache 的收益首先是 Routing/Placement 问题；Agent Memory 的核心从 Recall 升级为 State Tracking；Semantic Cache 上线前最该校准的是“命中答案能否替代”，而不是先发明更复杂的 eviction policy。

今日核心结论：系统优化正在从“局部模块指标”升级到 State / Cache / Routing / Index Contract。CacheRoute 证明 KV hit 提升若伴随负载倾斜，容量反而可能下降；StateMem 证明长期记忆必须显式表示 supersession 与 dependency propagation；CLEVER 证明 Semantic Cache 51–60% 的 raw hit 在答案可替代性审计后可能只剩 1.1–2.2%。对推荐工程最直接的启发是：用户兴趣、Item Embedding、Semantic ID、缓存与路由都需要版本、状态、失效与校准机制，而不能只作为一个离线向量或静态特征存在。

01 · Serving / Prefix Cache Routing · 今日精读

CacheRoute：Prefix Cache 命中率高，不代表 Serving 容量一定高

Research Impact Score 9.5/10研究价值 ★★★★★工业成熟度 ★★★★☆创新性 ★★★★★与你方向相关度 ★★★★★官方开源 否 / 未发现线上 A/B 否阅读优先级 最高

背景 / 业务动机

多租户对话式 LLM 服务通常有一段稳定、可复用的租户前缀。请求若再次落到仍持有该 prefix KV 的 GPU，就能跳过部分 prefill；但 cache-blind load balancing 会把同一租户打散，而简单 sticky hashing 又会把热门 key 压到少数机器，尾延迟恶化。论文使用来自匿名化 operational serving telemetry 的半合成 workload：128,824 个 business key，Gini 0.756，约 4% key 贡献 47% 请求，80.8% 请求属于多轮线程。平均 prompt 约 1.2K token，但真正稳定可复用的 per-business context 只有约 180 token。

技术方案与关键模块

CacheRoute 把问题拆成离线/周期性 Planner 与快速 Dispatch。Planner 先根据每个 key 的请求率 λ 和单目标服务 knee q_cap 计算需要分配的 destination 数量 k=max(1,ceil(λ/q_cap))；再按 key rate 从高到低做 warm-set admission，在总 cache slot 预算内决定哪些 key 值得保留 affinity；最后用 LPT（Longest Processing Time）式 placement 把预计负载放到当前最轻的 destination。未被 admission 的长尾请求继续走普通 load balancer。它没有预留或迁移 KV，也不假定 plan 一定等于实际 cache residency，而是建议先做 shadow replay。

训练 / 推理 / Serving

这是纯 Serving 路由工作，不改模型训练。旗舰实验用 Llama-3.3-70B FP8，30 个 TP=2 destination，共 60 张 H100；每个 destination 约 40,071 KV block（约 641K tokens）。请求到来时只查稳定 assignment table，因此在线开销很小；planner 在控制路径外周期运行。这里的关键工程思想是：把 cache locality 当作可规划的资源，但不把 cache hit 当作硬保证。

实验 / 指标 / 效率收益

在五次 paired run 中，p99≤3.5s 时 CacheRoute 达到 176±11 QPS，Preble-style 强基线为 76±11 QPS，Flat-LB 为 42±20 QPS；100 QPS 下 p99 为 1.8s，五类基线约 3.8–8.5s。8B 机制实验尤其重要：只做 affinity 将 KV hit 56%→88%，但 load imbalance 升至 3.46×，容量仍停在 240 QPS；加入 proportional replication 后 imbalance 2.60× 仍没有提容量；再加 LPT placement 后 imbalance 降至 1.24×，容量才达到至少 500 QPS。

优劣势 / 局限 / 尚未解决

优点是把“命中率”和“负载均衡”放进同一个决策问题，并用较大硬件规模验证。局限也很明确：主 workload 是基于真实 telemetry 统计特征生成的半合成 replay，不是 production online A/B；固定 slot 近似不适用于 prefix 大小差异很大的租户；分布突变时 fresh plan 会引发 cache warm-up，论文观察到最多 13.6 个百分点的暂时 KV-hit 下跌，因此 churn-aware replanning 仍未解决。论文还给出反例：某些 workload 中 KV hit 上升但 SLO capacity 反而下降，所以不能把 hit rate 当最终 KPI。

对推荐 / 搜索工程的启发

这个结论可以直接迁移到大规模推荐：Embedding/Feature/Intent cache 的“命中率”也必须与 hot-key skew、shard balance、freshness 和 P99 联合优化。更值得做的是 value-aware affinity：按请求价值、重算成本、cache size 与 TTL 决定哪些 user/item state 值得稳定 affinity，而不是所有 key 一视同仁。

02 · Agent Memory / User State · 今日精读

StateMem：Memory 的核心不是“记住过什么”，而是“现在什么仍然有效”

Research Impact Score 9.4/10研究价值 ★★★★★工业成熟度 ★★★☆☆创新性 ★★★★★与你方向相关度 ★★★★★官方开源 未确认线上 A/B 否阅读优先级 最高

背景 / 现有问题

大多数 Agent Memory benchmark 本质上仍是 recall：历史里有一个事实，系统能否检索出来。但长期交互中的真实困难是事实、规则、偏好和决策会被更新；旧信息并没有“消失”，却已不再是当前有效状态。对推荐而言，这正对应“用户以前喜欢 A，后来明确改成 B”“预算上限从 500 调到 300”“某偏好只在工作日有效”等状态变化。

技术方案

StateMem 显式建模 supersession 与 relational dependency：不是简单把每条 memory append 到向量库，而是维护哪些状态被新状态替代、哪些派生结论依赖上游变量，并在上游更新后做 dependency propagation / recomputation。StateMemBench 则专门构造 Status、Salience、Sequence、Compound、Anti-trap 五类 failure mode；其中 Sequence 错误就是“上游变量变了，但派生值没重算”。

Benchmark / 实验设置

StateMemBench 共 234 个多 session scenario、322 个 graded probe，覆盖 research、shopping、personal finance。短集每个 scenario 18 sessions、median 165 turns、约 3K token；长集约 38 sessions、median 599 turns、约 7–15K token。作者用 closed-pool grading 区分 current-state、superseded-state 和其他错误，从构造上隔离“检索不到”和“拿到了旧状态”两类失败。

结果 / Ablation

Qwen-3.5-9B 上最强 memory baseline Mem0 当前状态准确率 0.149，StateMem 0.233；DeepSeek-V4-Flash 上 strongest same-backbone dense baseline 0.205，StateMem 0.363。更有价值的是单次 wrapper 实验：同样的六种 backend，在完全相同 retrieved chunks 上，只增加 state structure，StateMemWrapper 在 StateMemBench 上相对 backend alone 提升约 +31.7 到 +66.6 points；长度/成本匹配 control 仍显示其中约 +15 到 +31.7 points 来自结构，而不是“塞了更多上下文”。

Serving / 成本

论文的 wrapper 设计意味着现有 BM25、Dense、Mem0、A-Mem 等存储不必全部重写：可以在检索结果之后做单次 state normalization / update，再将当前 operative state 注入回答。它比长期把所有历史重新塞进长上下文更适合作为中间层，但状态提取和依赖图本身仍需要可靠 schema 与错误恢复。

局限 / 未来方向

场景是程序化构造并由强 LLM render，虽然做了严格验证，但仍不等价于真实线上多年用户偏好流；依赖关系在 benchmark 中被显式陈述，真实业务里往往还要从行为中推断；state conflict、privacy deletion、跨设备一致性、状态 TTL 以及因果依赖错误都值得继续研究。

对推荐算法落地的启发

长期用户建模应从“history embedding”升级为 Event Log + Current State + Supersession Graph。召回/排序模型不一定要直接理解所有历史，只要拿到经过状态机清洗后的 current preference 与 freshness metadata。尤其适合会员权益、预算、地域、设备、内容禁忌、长期偏好等可显式变化的用户状态。

03 · LLM Semantic Cache / Evaluation · 今日精读

Semantic Cache：先验证“答案能不能复用”，再讨论淘汰算法

Research Impact Score 9.2/10研究价值 ★★★★★工业成熟度 ★★★☆☆创新性 ★★★★☆与你方向相关度 ★★★★☆官方开源 未发现线上 A/B 否阅读优先级 最高

问题定义

Semantic Cache 有三件事：indexing、threshold/routing、eviction。社区常把主要精力放在“几何感知 eviction”上，但不同论文在不同 workload / capacity / encoder 下比较，结论互相矛盾。CLEVER 把 FIFO、LRU、LFU、ARC、GDSF、streaming SISO 和 semantic-redundancy policy 放到统一协议中比较。

实验与关键发现

实验覆盖 LMSYS-Chat-1M、QQP、MOSS 三个有序去重语料 × 三种 cache capacity × MiniLM/gte-base 两个 encoder，共 18 个核心 setting。结果非常“反复杂度”：没有任何策略比 LFU 高超过 0.041 percentage point；相反 FIFO 与 streaming SISO 在小容量下最多分别落后 8.67 和 8.55 points。论文给出的解释是 insert-on-miss + exact lookup 下，新 miss 天生处在所有 resident hit radius 之外，因此“附近已有可替代项”这个 redundancy signal 没有想象中丰富。

更重要的 Quality Audit

真正打击 deployment intuition 的是 answer substitutability：在 MiniLM 的 median nearest-neighbor threshold 下，LMSYS/QQP 的 raw hit 约 51–60%，但抽样判断只有 2.1–3.9% hit 的答案真正可替代，quality-adjusted hit 只剩 1.1–2.2%。而同一个 absolute threshold 换到 gte-base 甚至会退化成 100% hit，说明 threshold 不能跨 embedding model 直接迁移。

Serving 结果

论文还测了 499K vector 的 ANN 路径：HNSW 在其条件下 Recall@1=0.989、P50=0.52ms，相比 exact search 约 34× speedup、只损失约 1.1pp recall；cost-based adaptive router 在五个 seed 中平均 nominal latency savings 60.33%。这说明 semantic cache 的工程重点应按顺序是：答案安全性 → encoder-specific threshold calibration → ANN / router → eviction fine-tuning。

对推荐 / RAG 的启发

这和推荐中的“相似用户/相似 Item”完全同构：embedding 距离小不等于业务上可互换。做缓存、蒸馏、近邻标签传播前应定义 substitutability metric，并对 encoder version 做 threshold calibration。尤其在价格、库存、政策、个性化状态等 freshness-sensitive 内容中，semantic match 必须叠加版本与时效约束。

04 · Retrieval Index / Embedding Compression

Quantization Beyond Uniform Bit Allocation：Embedding 每一维不应该拿到一样多的 Bit

Research Impact Score 9.1/10研究价值 ★★★★☆工业成熟度 ★★★☆☆创新性 ★★★★☆与你方向相关度 ★★★★★官方开源 ✅线上 A/B 否阅读优先级 必读

核心问题：PQ/SQ 通常默认各维度均匀分配 bit，但 Matryoshka Representation Learning 会把更多信息集中在前部维度，实际可以观察到沿维度索引递减的 variance。作者将连续维度切成 bucket，用 validation recall 的 marginal gain 做 greedy allocation，在固定全局 memory budget 下把更多 bit 分给更有价值的区域。

实验：在 MS MARCO、DBpedia、Quora、FiQA、SciDocs、SciFact 等 BEIR 数据上，用 OpenAI/Cohere 一类具 MRL 特性的 embedding 做 PQ/SQ；固定压缩率下 variable allocation 对 PQ recall 最多 +8%，对 SQ 最多 +18%，收益集中在低 bit budget。作者公开了基于 DiskANN 的 C++ 实现分支。

工程判断：这不是“又一个 quantizer”，而是提示 ANN/RecSys 的 compression policy 也应读取 representation geometry。未来可以进一步从静态维度方差扩展到 query-conditioned bit allocation、hot/cold item 分层精度、fresh item 高精度 bootstrap，再用访问频率和召回价值动态回收内存。

05 · Ranking Supervision / LLM Labeling

Can LLM Annotations Replace User Clicks for LTR?：答案是“不要替代，按 Query Frequency 组合”

Research Impact Score 9.1/10研究价值 ★★★★★工业成熟度 ★★★★☆创新性 ★★★★☆与你方向相关度 ★★★★★官方开源 ✅线上 A/B 否阅读优先级 必读

版本说明：该论文最初于 2025-11 提交，本周 2026-08-20 发布 v2，并已被 CIKM 2026 接收；因此今天把它作为“重要修订/重新进入最新 IR 列表”而不是新投稿。

业务问题：Click 便宜但有 position/exposure bias，LLM relevance label 没有真实用户反馈却能提供更强语义判断。作者在 TianGong-ST 与工业 Baidu-Click 上比较两类 supervision：高频 Query 上 Click-supervised 更强，因为行为量足够并含 authority/quality 等文档侧真实偏好；中低频 Query 上 LLM label 更好，更擅长 query-document semantic matching 与 relevant/non-relevant discrimination。

方案：不是直接用 LLM 替换 clicks，而是做 data scheduling 和 frequency-aware multi-objective learning，让模型按 Query frequency 学会组合两种监督。两种融合都提升各频段排序性能，frequency-aware multi-objective 更有效。

落地启发：推荐系统里 Teacher/LLM label 最应该补的是 sparse/long-tail/cold-start region，而不是把巨量真实行为全覆盖。可进一步做 uncertainty × frequency × exposure-aware teacher budget，把昂贵 LLM annotation 用在行为最少、语义最难、业务价值最高的 query/item 上。

06 · Inference / Edge CPU

Daedalus-150M：不是把 Transformer 压到 CPU，而是从 CPU 约束反推模型结构

Research Impact Score 8.8/10研究价值 ★★★★☆工业成熟度 ★★★☆☆创新性 ★★★★☆与你方向相关度 ★★★★☆官方开源 ✅线上 A/B 否阅读优先级 重点

设计：150M 模型共 18 blocks，只在 6 个 block 保留 full attention，另外 12 个用短 convolution，其状态只保留两个 timestep，因此 2/3 网络不会随着 context 变长反复读取 KV。模型针对单用户、逐 token、4-bit、普通 CPU 的 serving 目标从头设计，而不是训练完再量化。

训练 / 实验：从头训练 59.9B tokens，五任务分数 47.31；相同数据和参数规模下，作者额外训练 conventional all-attention control，hybrid 的目标 quality metric +0.81%，4-bit 文件小 6.3%，2048 context 下 decode 1.76×；与类似规模外部模型相比最多 2.08×。速度优势在空 context 几乎消失、随 context 增长，支持“减少 growing-cache reread”这个机制解释。

局限：作者主动报告 4-bit quality cost、约一半 convolution channel 最终 inert 却无法直接删掉、词表相对模型规模偏大。推荐工程上，它提示低延迟 side model / router / intent model 可以从硬件目标出发做 attention–conv hybrid，而不是一律从大 Transformer distill。

07 · Agent / Harness / Long-horizon Control

NVIDIA AVO：Agent 的“模型外系统”开始成为主要能力来源

Research Impact Score 9.2/10研究价值 ★★★★★工业成熟度 ★★★★☆创新性 ★★★★★与你方向相关度 ★★★☆☆官方开源 未确认线上 A/B 否阅读优先级 重点

NVIDIA 8 月 21 日官方博客进一步展示 Agentic Variation Operators（AVO）的统一 long-horizon harness：模型之外长期维护 persistent memory、candidate lineage、工具执行结果与 supervisor；Agent 自己决定 inspect→plan→implement→evaluate→commit 的循环。官方报告使用 Claude Opus 5 的完整 AVO 系统在 ARC-AGI-3 public set 达到 100.00 RHAE、完成 25 个 environment 的 183 levels，且比 VISTA 少 12% environment action；同一架构用于 B200 GPU kernel 优化时探索超过 500 个方向、commit 40 个 kernel version，报告相对 FlashAttention-4 最多 +10.5%、相对 cuDNN 最多 +3.5%。

对推荐/搜索的价值：这类 Agent 不一定直接替代在线 ranker，但很适合 offline experiment agent、特征/召回策略搜索、kernel/serving optimization 与 A/B workflow orchestration。最值得学的是 harness contract：每次实验必须有可恢复 state、可验证 objective、candidate lineage、execution feedback 与 supervisor，而不是把所有“记忆”塞回 prompt。

注意：100% 指的是 ARC-AGI-3 public set，不能外推到 semi-private/private；kernel 结果来自官方研究环境，也不是线上业务 A/B。

今日工程落地 Checklist

对推荐 / 搜索算法团队最值得直接带回去的 6 件事

  1. Cache KPI 从 hit rate 改成 hit × imbalance × P99 × recompute cost。命中率变高不保证容量变高。
  2. 用户长期状态分出 Event Log 与 Current State。明确 supersession、TTL、dependency、privacy deletion。
  3. Semantic Cache / Similarity reuse 先做 substitutability audit。embedding threshold 必须随 encoder version 校准。
  4. ANN compression 读取 embedding geometry。MRL / variance / hotness 可以参与 bit allocation。
  5. LLM Teacher Budget 按 frequency / uncertainty 分配。高频真实行为保留，LLM 重点补长尾语义。
  6. Agent 评估从 prompt 走向 harness。状态、执行、回归测试、lineage 和 supervisor 是长期可靠性的基础设施。
