美团 HGE：容器级排名如何对齐商品级真实交易额

Hierarchical GTV Estimation: Bridging the Gap between Container-Level Ranking and Item-Level Conversion

一句话：把一组动态商品作为候选容器建模，再把容器的商业价值分解到实际成交的商品层，避免只看容器分数。

背景 / 业务动机

O2O 搜索中某个直播间/店铺/商品容器可承载动态子商品。传统搜索只为容器预估 CTR/CVR/GTV，但用户真正购买的是容器内的具体商品；当主推商品、库存、价格变化时，容器级标签不足以表达细粒度贡献。对应评价列表，列表被展示不代表每条评价被消费、助攻成交相同。

现有方法的问题与核心矛盾

简单聚合商品价格或均值 embedding 会抹去集合异质性；独立建模容器和商品存在标签错配与冷启动；对容器预测 GTV 既受购买概率又受选购件数和价格影响，单一回归头难保持可解释/可迁移。

技术方案、模型架构与关键模块

HSAE (Hierarchical Set-Aware Encoder) 从候选容器内可变长 item 集合构造上下文编码，支持交互与稀疏性；PLL (Product-level Purchase Likelihood) 将期望价值拆为 POI 转化概率、转化条件下商品购买概率、购买件数和价格的层次乘积/加权和；RCEF (Residual Correction and Ensemble Fusion) 对容器级信号与商品级信号作残差补偿，处理缺失商品与动态上下文。注意论文的分解是条件期望的工程近似，并非纯因果贡献。

训练方法 / Loss / 数据构造

在真实搜索曝光/转化日志上联合训练容器转化与商品条件购买及 GTV 相关目标；HSAE 将子商品嵌入编码成容器上下文，PLL 辅助头将预估校准到商品粒度，RCEF 修正商品集合稀疏造成的系统偏差。需要防止商品级正例只来自已成交容器的选择偏差，并以曝光口径校验漏标。

推理 / Serving / 链路成本

线上请求先按容器召回候选，再读取当前可售商品摘要/价格、库存与行为特征，批量构造变长 set embedding，产出 GTV 分数与辅助预测；集合规模设置上限并监控跨商品特征 join、缓存过期与 P99。真实业务要考虑商品更新/直播改款触发特征刷新。

实验设置与 Baseline

作者对比 WLR、DLRM、RankMixer、CREAD 等工业排序基线，评测 XAUC、PCOC、MAE 并开展模块消融、13 天随机在线实验。评价样本构成与业务口径有领域特定性，不能直接外推所有平台。

离线指标与作者实验数字

XAUC 0.8158，对比 RankMixer 0.8105（绝对 +0.0053），PCOC 0.9858、MAE 4.9915；消融取消 PLL 时 XAUC 为 0.7873，去 HSAE 为 0.8031，去 RCEF 为 0.8146。PCOC 接近 1 表示校准更接近业务统计值，仍需分桶验证。

真实线上 A/B / 证据等级

13 天 A/B Revenue Per Search 相对提升 1.42%，95% CI [+0.80%,+2.05%]；存在真实随机生产证据且已规模化。线上收益限搜索商业化容器场景，不应误报为评价推荐 GMV A/B。

效率、成本收益与计算复杂度

变长 set 编码和 item-level 多头训练增加商品特征与推理成本；相对收益来自价值分解更准，论文未给可直接移植到评价页的 GPU/QPS 测试。线上应以 RPM/GMV、请求 P99 与特征 freshness 联合验收。

相对主流方法的优势与代价

对只预测容器 GTV 的 DLRM/RankMixer，优势是能解释商品贡献、适应容器内动态内容；代价是集合建模、商品标签要求更高，且线上涉及更多 feature join。对独立 item 排名，容器特征能表达上下文效应，但不能解决未知曝光反事实。

适用场景

电商搜索商品卡、店铺直播间、商品详情页评价 List、短视频商品集合和内容卡包，尤其适合列表级转化价值不等于各元素独立价值之和的情况。

局限、未解决问题与风险

容器内商品选择高度依赖用户与位置，条件概率分解仍可能因样本选择偏差失真；复杂特征链路需要 TTL/滞后处理；货币价值优化可能挤压评价覆盖与满意度。

未来研究方向

研究边际列表贡献与因果归因、内容集合协同价值、容器/商品双层 counterfactual、满意度约束的价值分解，并加入在线监控闭环。

推荐/搜索算法工程落地及职业技能启发

在淘宝商品评价生成式重排中可把 List-level 交易与用户评价消费行为拆分建模：用户看到了什么、阅读哪条、是否购买、事后满意，生成器用多头 Reward 做约束，先做按价位/品类分桶校准，再随机 A/B。

Deco：生成式推荐将“思考下一物品”与“拼写 Semantic ID”解耦

Separating Thinking from Spelling for Efficient Generative Recommendation

一句话：不让重型 LLM 为 SID 的每个码位反复推理：主干思考一次，再由小 Decoder 沿合法码树生成物品地址。

Research Impact Score / 研究价值8.2/10；本站独立判断；六因子[范式,工业,创新,相关,空间,可复现]=9/6/9/10/9/5

背景 / 业务动机

TIGER/MiniOneRec 等把商品 ID 量化成多级 Semantic ID 后按 token 自回归生成；每个候选的多级码需要重型 backbone 每步反复计算，beam 数与码位数越大，延迟越高。

现有方法的问题与核心矛盾

“推荐哪个物品”的高阶兴趣判断与“逐个写对商品 SID 的字符/码位”被同一昂贵网络承担，导致计算冗余；历史序列与重复消费还需要不同的数据流处理。

技术方案、模型架构与关键模块

先将用户历史 item 的多级 SID 聚合成较短 item-level 输入；backbone 单次生成下一物品的 compressed concept。轻量 prefix-conditioned trie decoder 根据当前位置/合法前缀映射选择下一码位，并缓存小解码器 KV；对历史重复物品可用 pointer 分支，避免强制全局新码生成。

训练方法 / Loss / 数据构造

概念 backbone、轻量码字预测器按 SID 序列的 token-level cross-entropy 联合学习，可引入 teacher distillation 对齐重型逐 token 模型的分布。训练时注意 prefix teacher forcing 与 beam search exposure bias、尾部码位的误差传播。

推理 / Serving / 链路成本

重主干每请求一次前向，构造 pooled user state 后由轻量 prefix decoder 在 SID trie 上做合法 beam 扩展；增大候选 topK 时不再线性增加重主干层数。应用量化压缩、KV cache、CPU/GPU 异步解码，持续记录 P50/P95、每用户 GPU 时间与显存。

实验设置与 Baseline

涵盖电商、音乐、电影 7 个公开数据集，与自回归生成器、轻量学生及双塔基线比较 Recall/NDCG 与推理吞吐，报告多 batch、多 topK 和严格延迟预算下曲线。

离线指标与作者实验数字

作者报告在多个数据集基本保持生成式推荐精度；受控吞吐在 P95 <50ms 预算下提升 3.2–8.6 倍。代表配置：Sports NDCG@10 0.0191，Recall@100 0.1301；BPC-23 对应 0.0132/0.0905。注意数字要配合数据集、负采样/全库口径解读。

真实线上 A/B / 证据等级

无推荐业务随机 A/B；“production-style serving benchmark”是生产式条件模拟基准，不代表已在电商真实线上灰度。

效率、成本收益与计算复杂度

加速主因是把 B×SID-depth 次重主干解码收敛成约一次 backbone forward + 小头扩码；可能增加 trie 索引和前缀 cache 维护。吞吐倍数与 beam、batch、GPU 型号高度相关。

相对主流方法的优势与代价

相较逐 token TIGER，降低 serving 费用、保留合法 SID 约束；相比纯双塔 ANN，可直接表示多级 token 分布；劣势是轻量 decoder 容量受限，对新物品、码树版本和模态融合仍需重新校准。

适用场景

大规模商品候选生成、音乐推荐、长历史序列商品检索，以及逐码生成成本成为瓶颈的低延迟推荐服务。

局限、未解决问题与风险

SID trie 与 embedding/catalogue 强绑定，版本迁移影响历史、候选合法性与缓存；生成概念压缩可能损失组合兴趣；缺少真实线上 P99/收益。

未来研究方向

语义码树动态更新、基于 Query difficulty 调整 beam/K、对齐多目标列表奖励、GPU 核融合与端到端线上成本/质量联合优化。

推荐/搜索算法工程落地及职业技能启发

先把现有生成式重排的 Generator 模型计算与 List decoding 两部分 profile，尝试 backbone 一次判断 + 小排列 head，并测序列合法性、候选覆盖、GMV/满意度代理和 P99；重点积累 constrained decoding、trie Serving、teacher/student distillation 能力。

From Item Scores to Semantic Tokens: Test-Time Collaborative Adaptation for Generative Recommendation

一句话：后融合救不回已被生成器丢弃的商品；先把强协同模型的得分转换成 prefix 势能，引导 beam 路径生存。

背景 / 业务动机

生成式推荐善于学习层级商品语义，但语义码与协同点击规律不总一致。当特定商品的热门/共现信号偏离语义中心时，模型在很早 SID prefix 上错误剪枝，后续排序再强也召不回该 item。

现有方法的问题与核心矛盾

把 SASRec 全库 item score 与最终生成结果后融合只能重排 beam 已存活的对象，不能解决搜索路径漏召；直接对所有 SID 前缀加分容易被高置信低相关的 discriminator 污染，形成曝光偏置。

技术方案、模型架构与关键模块

冻结基座生成器 TIGER/MiniOneRec 与判别式 SASRec/GRU4Rec；将打分靠前的 item 投射到 SID trie，依据协同 score margin 构造每条合法 prefix-edge 的 additive potential；根据分布 margin/置信度做 gating 和 bound，让额外偏置只影响必要的 beam 竞争；在 beam pruning 前注入，而不是最终列表后处理。

训练方法 / Loss / 数据构造

方法为 test-time plug-in，无需重新训练生成器；协同教师沿原有 next-item objective 训练，然后离线校准分数尺度/温度；作者给出针对目标前缀生存的条件与扰动上界，说明不会无限改写生成器分布。

推理 / Serving / 链路成本

请求时得到用户向量与协同模型 top-R item 的分数，查询 SID->edge 的倒排映射，对 beam prefix 叠加 sparse potential。缓存 trie 结构、版本并设置安全上限；额外成本来自一次协同模型推断、top-R 取回及 edge 更新，必须与 beam 宽度共同优化。

实验设置与 Baseline

Science、Music、Office、Yelp 四个数据集，生成基座 TIGER 与 MiniOneRec，协同教师 SASRec/GRU4Rec，完整目录 Recall@10 与新兴趣 1-touch/2-touch 分桶；有模型消融、门控和路径存活研究。

离线指标与作者实验数字

TIGER 在 Science Recall@10 由 0.0426→0.0467（配 SASRec）；Yelp 0.0458→0.0571；Science 1-touch 0.0698→0.0781，2-touch 0.1143→0.1619。数据集间提升不均，需避免把极端桶的相对增幅当整体线上增量。

真实线上 A/B / 证据等级

无线上 A/B；尚未证明额外协同模型与 trie 更新之后的 P99/GPU 成本仍有净收益。

效率、成本收益与计算复杂度

冻结生成器省去大规模训练成本，但在线双模型叠加增加 serving 和缓存成本。与纯 beam 增宽相比，定向修正可能在同 K 下更有效，但需要评测路径投票/索引更新开销。

相对主流方法的优势与代价

优于后融合的关键在召回可达性（beam survival），优于盲目分数融合在 gate/上界；弱点是协同教师强弱与内容冷启依赖，继承教师的热门偏差。

适用场景

语义码商品召回、在新兴趣/跨品类情境漏召较多且已有协同模型的推荐场景；可与 Deco 轻量解码结合但应先测试相互作用。

局限、未解决问题与风险

只影响束搜索路径、无法解决 SID 表示本身不可分；teacher score 与 beam logprob 的标度对齐困难；商品变更会改变 trie edges。

未来研究方向

学习 per-query 动态偏置、从离线 beam survival 到在线转化/多样性收益、联合语义码版本与协同 teacher 蒸馏，并监控 TopK 供应侧公平。

推荐/搜索算法工程落地及职业技能启发

可直接抽取生成式召回日志，区分“语义码无法表达”与“beam 过早剪枝”造成的候选损失；针对评价生成式重排可用轻量判别器在 list generation 早期防止高 Reward 文本项被不可逆剔除。

背景 / 业务动机

生成式 SID 推荐一般逐码生成，推理序列化。并行预测每个 SID head 虽可低延迟生成，但码位空间与商品目录合法路径并不天然一致，损伤排名和协同偏好。

现有方法的问题与核心矛盾

只用每个 code-head hard CE 无法表达商品间相对偏好；只用原始 SASRec item score 与每头 code logits 做 KL 又有不同空间/多对一码的结构错配。

技术方案、模型架构与关键模块

AsymRec 学生并行产生 48 个 SID sub-code heads（16 子空间×3 残差层，每个 256 类）。IDM 通过取合法商品对应的各 head logit 得分，映射成 catalogue-level softmax 再与 SASRec 教师分布对齐；CMM 将教师概率按 item 的各码位投影成 code marginal，按头做 KL。通过两个方向连接“有效商品分布”与“语义码边际”。

训练方法 / Loss / 数据构造

先训练 SASRec item-space 教师及 SID 量化 tokenizer；学生优化硬样本 CE + λm(t)×(IDM 与 CMM 蒸馏)。蒸馏权重渐进 ramp-up，并采用梯度范数校正，避免 soft target 早期冲掉主任务；负例/全目录 softmax 的成本单独核算。

推理 / Serving / 链路成本

学生一次前向并行输出各码位 logits，再通过合法 item 字典重构分数或 ANN 候选，避免 48 步逐码生成。目录级重建可形成高额 memory bandwidth 与 O(|I|×H) 代价，离线预计算 item-code 索引并采用 TopK 近似才能真正落地。

实验设置与 Baseline

Amazon 2014 Beauty、Toys、Sports 5-core，留最后交互作为测试，对比 SASRec、TIGER、HSTU、RPG、AsymRec；Recall@10 / NDCG@10 与不同教师/蒸馏模块消融。

离线指标与作者实验数字

作者摘要报告 IDM 的平均 Recall@10 提升约 15.39%，CMM 的平均 NDCG@10 提升约 8.28%（需按作者给定基线和相对定义解释）；Beauty IDM R@10 0.1094 对 AsymRec 0.0940；Toys 0.1176 对 0.1002。不是线上转化率变化。

真实线上 A/B / 证据等级

未报告任何线上 A/B，也缺完整生产真实 QPS/P99。

效率、成本收益与计算复杂度

学生并行头理论节约自回归步骤，但输出 48×256 logit 与目录重构不可忽略；教师需要额外训练，蒸馏与 catalogue-softmax 增加离线 GPU 成本。

相对主流方法的优势与代价

对单头 SID CE，可以恢复 item-level 协同排名；对普通 teacher logits 蒸馏，跨空间映射更合理；代价是 SID 碰撞、合法目录依赖、教师分布过时和较大训练显存。

适用场景

候选空间有限、需一次性高吞吐产生多个 SID 码的推荐检索与粗排；对更大目录先验证重建成本。

局限、未解决问题与风险

48 头独立输出并非天然合法完整码序列；冷启商品与品类跨域 teacher bias；研究以离线排序为主，没有工业尾延迟和动态目录。

未来研究方向

学习依赖性 code head 与 constrained parallel decoding，联合 catalogue validity loss、在线增量蒸馏，进一步接入 List-level preference alignment。

推荐/搜索算法工程落地及职业技能启发

建议把传统精排/召回 teacher 分布压到生成模型，不只蒸馏 Top1：使用 listwise KL + 合法码路径正则，监测相同物品空间的 Recall 及 SID 空间利用率，探索重排 Generator 一次性输出结构化列表。

背景 / 业务动机

Cross-Encoder 适合难例 relevance 判断，但每个 query×document pair 都需昂贵联合编码；late-interaction ColBERT 支持文档离线编码，却可能损失跨 token 深层交互，且文档向量索引大。

现有方法的问题与核心矛盾

降低 CE 推理成本不能只报告 rerank latency，真实链路还需初召、压缩文档缓存、解压、TopK late interaction 与最后上层交互；质量与索引成本往往在不同预算下被不公平比较。

技术方案、模型架构与关键模块

MICE 通过保留必要的跨输入交互让下层 query/doc 独立 contextualize，文档编码可离线存储；上层使用有限 query-document interaction。MICE-P 以紧凑 128-d 文档表示、残差压缩与 FastPLAID/PLAID 相关存储机制串联第一阶段召回，再作 MICE 局部融合。文中具体 pipeline 的一阶段为 SPLADEv3 Top100；切忌把 PLAID 存储机制说成该实验唯一第一阶段召回器。

训练方法 / Loss / 数据构造

用大型 Cross-Encoder 对约 1.43 亿 query-doc pair 打软标，学生做两阶段 pointwise distillation（MSE 对齐评分），使删去或稀疏化部分交互后仍保持教师相关性判断；Ettin-68M/150M 参数级进行量质对比。

推理 / Serving / 链路成本

离线编码并压缩文档，对在线 Top100 用 SPLADEv3 候选池进入 MICE 推理，上层融合查询与解压文档特征；部署测吞吐需包含 SPLADE 召回、HNSW/倒排、PCIe 读取、解压和 batch 编排，非仅模型前向。

实验设置与 Baseline

13 个去污染 BEIR 子集 + LoTTE，比较 Ettin Cross-Encoder、ColBERT 与 MICE-P，做 2bit/4bit 压缩、模型大小、索引体积与受控吞吐实验。

离线指标与作者实验数字

BEIR13 平均 nDCG@10：Ettin CE 68M 为 58.1，MICE-P 61M 不压缩 57.8、压缩后 57.3，同规模 ColBERT 为 56.7；MICE-P 130M 为 58.5 对 150M CE 的 58.8（注意配置不同）。2-bit 过度压缩导致的 nDCG 损失明显，应评估 4-bit。

真实线上 A/B / 证据等级

没有可核查生产搜索 A/B。

效率、成本收益与计算复杂度

相较每候选完整 CE，多数文档计算前移到索引阶段，能接近 late interaction 吞吐，但压缩/解压引入 CPU/GPU 访存，文档库更新和索引重算是长期成本；离线算力投入需列 TCO。

相对主流方法的优势与代价

比同规模 ColBERT 容量更能保留 CE 相关性表达；比全 CE 减少重复文档编码；缺点是多阶段系统复杂度、索引/压缩损失、query/doc 上下文独立性假设。

适用场景

电商 Query→商品评价检索、文档级 RAG、多向量召回后高精度少量 rerank，尤其适合高复用静态商品内容。

BEIR 评测不含生成式多目标列表效用，非线上商业化质量；文档编码更新、冷热 cache 和跨语言评论稳定性待验。

动态 2/4bit 自适应压缩、query-aware 模型路由、与 List-level Reward 联训及首阶段实际 TCO 共同优化。

现有方法的问题与核心矛盾

历史比较混杂 backbone、模型大小、指令 prompt、训练数据；“模型很会遵循指令”与“对 Top100 细粒度相关度排序稳定”被混为一谈。

技术方案、模型架构与关键模块

固定 Qwen 同家族 0.6B–27B 规模，比较未训练、decision fine-tune（Kev/Clef）与 relevance-specific fine-tune（Qwen3 Reranker、Prism 等）；BM25 Top100 作为统一候选池，将 yes/no token logit/相关性分值转成排序分数，区分 calibration 与 nDCG 指标。

训练方法 / Loss / 数据构造

控制决策任务和重排任务的训练目的；decision instruction tuning 强化绝对标签判别、校准，而 reranker-specific 学习成对/点式相关性。该研究是诊断评估，并未推出必须使用某种新 Loss 的生产模型。

推理 / Serving / 链路成本

相同候选集、query 模板、token budget 运行模型，比较 pointwise logits、专职交叉编码器和 listwise LLM；如果用 yes/no 评分，切换 prompt 模板必须重新校准，不要用低 ECE 取代排序质量。

实验设置与 Baseline

TREC DL 2019–2023 + 5 个 BEIR，共 10 数据集，固定 BM25 Top100，评估 nDCG@10 与 ECE，对多个参数规模、任务调优策略、Prompt 敏感性进行系统分析。

离线指标与作者实验数字

在 ≤9B 档，重排专训比通用决策路线领先约 5–29 个 nDCG 点；到 27B 差距减小甚至持平。不同模型/配置整体参考：Jev 平均 nDCG@10 约 59.1、Kev 27B 约 60.1、Qwen3-Reranker 8B 约 59.4；不可把跨规模均值解释为确定胜负。

真实线上 A/B / 证据等级

未提供业务随机化 A/B，也没有 GMV/满意度结果。

效率、成本收益与计算复杂度

较小的专职模型可在排序质量/成本上取得明显 Pareto 优势，而更大的通用决策模型需要更高推理费用；论文本身主要分析质量与校准，不能据此断言特定 GPU 成本比例。

相对主流方法的优势与代价

专职 Reranker 擅长相对次序与难负例，决策模型可能在校准和 yes/no 决策上更好；选择取决于所需输出：Relevance Ranking、Absolute Label 还是 List Reward，不应一个模型全包。

适用场景

10 套学术 IR benchmark 的相关性标签不同于成交/满意度，prompt 敏感且数据分布偏移；从判别相关度到全列表效用仍需训练。

背景 / 业务动机

用户描述同一商品问题时常带个人语言习惯：省略主语、方言表达、错拼、不同句式。经典检索集每个意图通常仅一个 Query，无法量化模型面对语义等价不同表述的差异。

现有方法的问题与核心矛盾

跨 Query 的模型质量提升不能自动证明同一个用户意图的鲁棒性；直接用生成改写可能偷偷改变核心语义、词频与检索目标，使所谓 robustness 指标失真。

技术方案、模型架构与关键模块

将原查询控制成同一商品意图，再基于评论风格估计用户个体语法表示（16 维 style feature 与分布）、语法噪声/错拼模拟，辅以语义相似阈值 ≥0.9 等过滤，生成可配对的多风格查询；用 pairwise consistency 和 ranking drift 检验检索器。

训练方法 / Loss / 数据构造

本工作主要构建 benchmark，不推出必须训练的新模型 Loss；可据此生成 consistency pair，后续采用 margin ranking、SimCSE 或蒸馏约束同义 Query 对的 score ordering，并在保留核心实体条件下增强。

推理 / Serving / 链路成本

在线先测 query 规范化/GEC 对召回的收益，轻量 spellcheck 与 query expansion 可灰度；召回使用 BM25+Dense 混合、长尾词 lexical fallback，重排模型独立监控 style-bucket drift、错误改写率与 latency。

实验设置与 Baseline

来自 Amazon 三类产品，6516 条评价查询，比较 BM25/稀疏神经/稠密/late interaction/hybrid 与两个 LLM reranker；按用户语言风格切片、同一意图 query pair 统计排序稳定性。

离线指标与作者实验数字

6516 queries、三大产品域是实测评测规模。论文结论是更强的平均检索效果未必对应更好的个体表达稳定性；不同子集的确切 nDCG 不宜在未核实表格口径时虚构。

真实线上 A/B / 证据等级

没有生产业务 A/B 或用户长期满意度实验。

背景 / 业务动机

长期使用的 Agent 处理重复数据清洗、实验对账与代码修复时，即使同类任务反复出现，仍重复搜索工具、试错和调用大量 token，传统 memory retrieval 容易只记住经验文本而非可执行能力。

推理 / Serving / 链路成本

包括重复工作流、SWE-bench 类任务、Genome Pegasus I/O 测试等，比较冷启动/热启动成功率、可复用技能数、token 消耗与正确性。作者报告部分设置 warm-start 首次成功率 93–95%，每任务新能力形成率由 7.6–30.8 降到 <2。

跨论文判断：哪些可结合，哪些不应混淆？

生成式检索一条主线：TIGER/MiniOneRec 用 SID 统一内容与协同召回，但逐码解码昂贵且 Beam 易漏召。TCBSA 是“提前纠正路径”，Deco 是“缩小展开码位的模型”，IDM/CMM 是“并行头的知识迁移”。三者可以概念上组合，但并未共同在同一真实场景做端到端消融，工程上必须做统一 SID 版本、全库 Recall@K、topK diversity 与每千用户 GPU 成本对照。

召排目标一条主线：HGE 有真实 Revenue Per Search A/B，而 MICE-P 仅证实文本相关性/索引质量，System One 证实重排专训优于部分通用决策模型。把 CE relevance、List Reward、GMV 与用户满意度划成独立 metric layer，再靠真实曝光归因联结。

Agent 控制一条主线：SkillRep 负责找到正确工具，Phronix 负责把执行经验变成可校验技能；PersonalQuery 用同意图不同表达的鲁棒性评估筛出输入分布风险。需要测完整“检索→调用→执行→最终目标”成功率和资源开销。

建议的下一周工程实验

① 对评价生成式 List 构建独立 User/Item/List 三层 Reward head 与归因校验，像 HGE 一样按业务层级拆目标；② 对生成式召回跑 TCBSA / Deco / IDM-CMM 三向消融，指标含全库 Recall、SID 路径存活率、P99 和有效曝光比例；③ 对评价检索比较专职小 reranker、MICE-P 与通用决策模型，并用 PersonalQuery 的口语/错字子桶监控稳定性。所有收益进入真实随机 A/B 前均称离线潜力，不先称“增长”。
