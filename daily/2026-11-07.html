重排别只预测点击，Reward 别把热门当个性化

11 月 6 日 arXiv cs.IR 公告聚焦三种被忽视的成本：真实浏览/曝光路径、RL Reward 的用户无关偏置、Semantic ID 量化后的语义结构丢失。工程基础设施方面 Google GINGER 开源了压缩图向量搜索库；跨域 CORE/MEMOIR/CacheGraft 给 Agentic RAG 低成本证据管理提供新思路。

发现窗口：2026-11-06 10:00 至 2026-11-07 10:00 北京时间。10 项选择基于 2026-11-06 cs.IR 公告：9 项该分类新提交 + 1 项 cs.CL 首发后的 cs.IR cross-list；论文原始首稿均为 2026-11-05 UTC。公告/首稿日期不等于今日首次研究完成日。全部数据为作者公开报告，本站未独立复现实验。

核心结论：① 淘宝 ICE 先校正真实曝光与点击竞争，再用 Evaluator 排 List，14 天 A/B 点击 +0.70%、商业收入 +3.67%；② RL 的 CF Reward 中 item-mean 可导致曝光塌缩，per-item standardization 的 distinct top-1 最多增至 9.8×（离线）；③ BRIDGE 把码本几何知识回灌 SID 解码，广告一周 5% A/B eCPM +0.65%；④ Google GINGER 在 95% Recall 约束下 ANN 平均吞吐优于各数据集最快对手 1.8×（基准测试）；⑤ 大模型系统正在转向“离线重处理 + 在线轻推理 + 证据来源可回查”。

最值得读 ① ICE + Reward

对“成交+满意度”的评价生成式重排最直接：先把未真正读到的尾部评论从点击目标中区分，再剔除跨用户共享的热门奖励偏置。优先修 Reward 与曝光数据，随后再做策略优化。

最值得读 ② BRIDGE + OptST

SID 不仅是字符串地址，更含连续语义簇与量化层级。精读“码本先验如何回灌生成”和“离散画像如何下游任务适配”，注意训练/Serving 的 snapshot 与成本边界。

工程试验 ③ GINGER + CORE

同等语义 Recall 下的向量检索 QPS/内存，与长段召回→短 span 证据引用，是比盲目加深模型更可控的两条路线。

ICE / Joint Behavior Modeling

Beyond Independent Predictions: Learning the Browsing Journey for Sequence-Level Re-ranking · 原始 arXiv 首稿 2026-11-05 UTC，2026-11-06 cs.IR 公告

同一展示 List 不是所有位置都会被用户看到：仅将各 item 的 pCTR 相加会给尾部高估、把未曝光 item 当作真实上下文。ICE 不改 Generator，把业务价值提升放在 Evaluator 物理一致性。

背景 / 业务动机

工业 Generator–Evaluator 用多个候选 List 的预测收益选择最终曝光排序，评估器偏差直接放大为上线收益损失。对商品评价列表亦如此：尾部评价可能从未进入可视区域，长评价会挤占其他观点的注意力。

传统方法与核心矛盾

传统 Independent Behavior Modeling 把列表行为分解为独立点击，默认每个展示位都有机会被读且 item 之间互不争夺注意力，导致多点点击分布与真实浏览过程不一致。即使是 Transformer Evaluator，也可能只在架构层交互但训练目标仍是点式。

技术方案与关键模块

提出 Joint Behavior Modeling：p(impression,click | S,U)=p(impression | S,U)·p(click | impression,S,U)。浏览深度 T 的分类分布经尾部累加形成 pITR(k)=P(T≥k)，天然保证随位置单调；点击头的 Transformer attention 添加 log[pITR(a)pITR(b)+ε] 作为 bias，DNN 使用 confidence gating；最后让 List 内点击概率归一化并用 KL 约束真实点击分布，显式表达竞争。

训练 Loss / 优化方法

共享 embedding、Impression Branch 与 Click Branch。L=L_ITR(BCE 所有展示位置)+L_CTR(只在已曝光位置加权 BCE)+λ KL(真实 List 点击分布 || 预测分布)。应防止真实未来曝光作为推理输入；在线时仅用预测的浏览深度与输入候选。

推理 / Serving

每条候选 List 计算 pITR(k)×pCTR(k|impressed)×价值 w_k，再求和选最大 R(List)。可作为现有 PRM/Transformer 重排 Evaluator 的 plug-in，Generator 固定，有利于识别改进来源；增加一条曝光头与 mask/归一化运算，需实测单 List 推理 P99。

实验设置与离线/线上证据

工业日志多 backbone 验证；PRM+ICE 消融：SeqAUC 85.65，去曝光建模 83.29，去动态 Mask 85.58，去点击分布损失 85.50（各数值来自论文表3，百分制）。淘宝猜你喜欢 14 天 A/B，5% 流量，曝光 +0.58%、点击 +0.70%、商业收入 +3.67%，长期价值 LT-14d +0.23%。

对比主流方法与效率/成本

比简单 List-wise sum of pCTR 更符合展示→真实曝光→点击的先后顺序，优于只调 Generator 的方法，因为可先修正上游 Reward 目标；但依赖深度标注、曝光可靠性及列表位置的物理意义。

适用场景与尚未解决的局限

论文 A/B 是淘宝猜你喜欢 feed，不是商品评价页；收入升幅不能直接外推到成交满意度。若页面是折叠评价、图片网格、搜索混排，则单调深度假设和阅读路径需要修改；离线数据存在旧策略选择偏差。

未来研究路线

把单一点击链扩为展开阅读→停留→加购→成交→满意度多状态过程；建立随机小流量干预和 off-policy list 评估，验证 pITR 的校准、尾部负面观点覆盖和差评可信度。

商品评价推荐落地与技能启发

P0 先审阅评价列表真实 viewport / 展开曝光埋点；将候选评分拆为“读到概率×读后有用性×对成交/满意度贡献”，对 Reward 标定 ECE、ITCTR 和 List 顺序对准确率做 ablation。Generator 不变做一次纯 Evaluator 的 A/B，减少 Generator-Reward 联合变更的归因难度。

Collaborative Reward Mean / Reward Hacking

What Gets Hacked in a Collaborative Reward for LLM Recommenders: The Part That Does Not Depend on the User · 原始 arXiv 首稿 2026-11-05 UTC，2026-11-06 cs.IR 公告

Reward 模型在独立排序时看似个性化，作为 RL 优化目标却可能驱动 Generator 统一偏好热门 item，形成曝光塌缩；问题来自跨用户共享的 item 常数项。

背景 / 业务动机

当把协同过滤打分当作 LLM/Generator 的奖励，策略不是仅拟合每个用户的偏好，而是最大化更容易稳定得到高分的项。这与评价重排中“大量用户都喜欢的模板化好评”可能挤出有信息密度的差评类似。

传统方法与核心矛盾

仅看 Reward 相关系数或 HR@10 很难发现跨用户的曝光集中度。论文在 Beauty+SID 的 CF reward arm 中 distinct top-1 从 SFT 的 1,317 减为 837，HR@10 却几乎不变（0.0851→0.0843）。普通全局 reward standardization 无法移除每个 item 的独立偏置。

技术方案与关键模块

定义 r(u,i)=m(i)+ε(u,i)，其中 m(i)=E_{u~Q}[r(u,i)]，Q 为统一训练用户分布；中心化 r_c=r-m(i)，标准化 r_s=(r-m(i))/(σ_i+ε)。对均值分量和残差分量分别训练策略，以机制干预辨认哪一部分驱动塌缩。

训练 Loss / 优化方法

先 SFT，再使用冻结协同模型对策略输出打分进行 RL；提前从一组固定训练用户历史统计每个 item 的均值/方差，训练时实时对 Reward 做校正。与模型常规 per-user normalization 不同，校正轴是跨用户的每 item 统计。

推理 / Serving

在线生成不必再调用统计器，只需部署修正奖励训练完成的策略；训练阶段需维护 item 统计表和冷启动回退统计。对 List Reward 可改用 position/topic/group residual baseline 并审查是否误删真实通用质量信号。

实验设置与离线/线上证据

Amazon Beauty/Sports，两类 identifier（Semantic ID/Atomic ID），多 CF 架构和 LLM backbone；论文报告标准化相对原始 Reward 使 distinct top-1 最多增加 9.8×，同时排序准确率相近。无线上交易或用户随机实验。

对比主流方法与效率/成本

相对“给长尾 item 加固定曝光权重”，它从奖励形成机制着手且不需要改生成器结构；但不是普适公平性保证，热门度也包含真实共识，中心化可能削弱所有用户都需要的可靠优质内容。

适用场景与尚未解决的局限

日志的曝光机制决定 Q 的选择；冷启动或低曝光 item 方差估计噪声大。Distinct top-1、Coverage、Gini 改善不代表 GMV/满意度必升；离线训练结果需与真实 List 竞争和库存约束结合。

未来研究路线

将 r(List,u) 分成全局 List prior、item 质量、user residual 和 interaction residual；引入不确定度 shrinkage，建立成交/满意度 Pareto 守护，联合 ICE 的浏览暴露概率避免统计偏差。

商品评价推荐落地与技能启发

对当前评价 List Reward 做 item/商品/评论类型的分桶均值残差审计：冻结 Reward、固定用户、替换可曝光的评价 List，看高频好评是否提供无条件 bonus。P0 对中心化、截断标准化、原 Reward 三组做离线 List diversity/满意度校准，再小流量 A/B 验证。

BRIDGE / Semantic Quantization Gap

BRIDGE: Bridging the Semantic Quantization Gap for Generative Recommendation · 原始 arXiv 首稿 2026-11-05 UTC，2026-11-06 cs.IR 公告

生成式 SID 的离散 token 把 RQ-VAE 码本的几何关系丢在了编码端；BRIDGE 把 codebook centroids 与邻域知识回灌到解码训练，兼顾效率。

背景 / 业务动机

TIGER 等 SID 范式解决“用生成路径召回 item”，但语义量化时的局部邻域、码本簇中心和每层 token 难度没有被逐 token CE 充分利用，造成第一层决策失误逐层放大。

传统方法与核心矛盾

三类 Gap：Grounding（首 token 无连续语义锚）、Neighborhood（hard ID 使邻近 item 错当完全不相关）、Difficulty（所有 level 均匀分配模型计算而第一层更难）。仅增大 Decoder、Beam 不能自动弥合。

技术方案与关键模块

CGLR 用冻结 RQ-VAE 一级码本的粗簇 centroid 做隐式 reasoning anchor；PESD 给 EMA teacher 目标 item 的 top-k 邻居均值作为 privileged view，将 soft distribution 蒸馏给仅见在线可用输入的 student；EAR right-aligned recurrence 把循环层数更多分配给早期 SID（如三层 4/2/1）。共享 recurrent block 减少参数复制。

训练 Loss / 优化方法

基本 SID token CE + codebook anchor 的粗 prototype 分类/回归损失 + EMA teacher/student 的分布一致性（JSD 等）与 on-policy student 采样。Privileged teacher 只在训练阶段访问目标 item 的邻居；online 不得泄漏目标。

推理 / Serving

上线只用 student 与共享 recurrence block，无 teacher 查询。优先算首层，深层少算；需固定 codebook/snapshot、Beam 合法 path 约束、冷品增量路径服务和时延分桶监控。

实验设置与离线/线上证据

Amazon 三个公开 benchmark：相对最强基线平均 Recall@10 +10.9%、NDCG@10 +9.7%，Beauty ablation EAR R@10=0.0740，BRIDGE=0.0835；大型电商广告一周 5% 流量 A/B，eCPM +0.65%。

对比主流方法与效率/成本

对传统逐层 SID CE，BRIDGE 显式引入连续语义结构；相对 CAP-Mix 的软 prototype 输出，它仍保留离散合法路径，工程可控性更强。但多目标损失和码本冻结增加复杂度，未直接解决实时 supply constraint。

适用场景与尚未解决的局限

线上只报告 eCPM 单一目标，未完整公开随机设计、显著性、GMV/用户满意度；粗聚类质心稳定性、SID 更新迁移与多任务约束需进一步验证。

未来研究路线

对一级粗簇 Vc 和 neighbor-k 做敏感性/多种子实验；与 Supply-Constrained GR 的请求级合法 prefix mask 合并，在动态商品库存下评估可用率、P99、CTR/GMV。

商品评价推荐落地与技能启发

可将商品评价聚类/观点表示编码成分层 SID；先做抽样 hard-negative 邻域一致性和先验分层 token entropy，再做 teacher-student；不可直接将电商广告 eCPM 移植成评价成交结论。

背景 / 业务动机

大规模评价语义召回需要在高维向量和大量长尾文本上保障 recall@K，同时避免全精度 embedding 对内存带宽与索引构建吞吐的成本。

传统方法与核心矛盾

单独的 HNSW/IVF/PQ 优化往往忽略图邻接编码、向量精度和 NUMA/SIMD 实现的整体权衡；极度压缩会牺牲高 Recall 下的延迟。

技术方案与关键模块

以 PiPNN 图构建为基础，Nested TurboQuant 形成共享双层编码：低精度近邻导航+高精度候选 rerank，保持接近 float 的精度但压缩向量；邻居图重排并用 AdaptiveGap（基于 StreamVByte）无损编码缩短跳转字节数。集成 C++ 高效 SIMD。

训练 Loss / 优化方法

不训练推荐模型：主要是向量量化参数估计、图构建/图布局与查询搜索参数调优；与 embedding encoder 的对比学习应在独立 pipeline 完成。

推理 / Serving

召回阶段用紧凑向量和压缩图导航，选出的候选做更高精度重排；图/量化码本、build 版本、删除更新、K、efSearch/探测预算和 warm-cache 状态影响延迟。能直接替换的是 ANN 内核，不是整个索引平台。

实验设置与离线/线上证据

14 个数据集在 Recall 95% 条件下，平均查询吞吐相对各数据集最快竞争者 +1.8×；双层向量编码约 2.6× 省内存，图压缩最高 2.5×；高维 embedding 对比紧凑库的吞吐优势更大。论文未提供随机线上业务实验。

对比主流方法与效率/成本

较 Faiss/ScaNN/Hnswlib/DiskANN 属检索基础设施竞争，优势是全链路图内存与量化工程；代价是 C++ 构建/部署依赖、动态索引更新、向量混合查询场景适配。

适用场景与尚未解决的局限

基准吞吐未必覆盖在线混合过滤、热冷数据、跨机 fanout、写入频率与 tail-latency；95% recall 的对比不代表 99.9% 或多样性指标下仍占优。

未来研究路线

做 index version/snapshot consistency，探索 Hybrid sparse+dense、过滤场景与可增量重构；以同等 Recall@K 下每千 QPS 机器成本和 P99 做选型。

背景 / 业务动机

LLM 生成用户画像/评论语义向量可作为推荐特征，但稠密向量存储/查表昂贵；RQ-VAE 离散 token 更轻，若预先固化语义码本却可能错过交易目标相关的小差异。

传统方法与核心矛盾

hard nearest-code 不可微；完全微调码本会破坏预训练几何；固定层数不能匹配不同用户与候选交互需要的语义分辨率。

技术方案与关键模块

固定预训练 Encoder 与 base codebook，在每层对所有码字共享近恒等低秩变换，并以 anchor 正则限制偏离；hard forward + soft backward Straight-Through 允许下游梯度回传；另由交互条件 stop/continue gate 决定使用几层 prefix。

训练 Loss / 优化方法

Qwen3-8B 离线产生语义画像、all-MiniLM-L6-v2 得到 384-d profile；任务损失为下游二分类推荐 BCE 结合 codebook anchoring 与 prefix-depth regularization；训练可采用 DCN 等推荐骨干。验证/测试交互不进入画像，降低未来信息泄漏。

推理 / Serving

LLM 不在线调用；部署缓存用户画像离散 token 与自适应 prefix gate。必须验证 token 码本版本一致性与不同用户/商品变化时的特征再计算成本。

实验设置与离线/线上证据

四个公开数据集，论文报告相较传统和 LLM 增强基线最高 AUC，且跨五个其他 recommendation backbone 仍有提升；具体绝对提升以原文表格为准，未发现随机线上 A/B。

对比主流方法与效率/成本

相比完全冻结 SID，OptST 任务适配更强；相比端到端改写 codebook，低秩/anchor 可降低漂移；但提升的证明主要是 AUC，不代表 GMV、满意度和在线可服务性。

适用场景与尚未解决的局限

用户画像离线提取与 tokenization 的 pipeline SLA、跨域漂移、长序列缓存更新、量化版本迁移成本未充分量化。

未来研究路线

分别测被分桶的长尾意见/差评是否被压平，并用推荐重排目标指导 prefix-depth；联动 BRIDGE 的语义锚点和 GINGER 的向量成本。

商品评价推荐落地与技能启发

先在评价粗排/精排做 AUC 与满意度校准、长尾观点 recall；选固定 SID vs OptST vs 直接 384-d embedding，比较性能/缓存/内存/CTR，防止只追 AUC。

背景 / 业务动机

传统 RAG 先检索长文档、再让小语言模型从 text prompt 理解；小模型在事实关系与细节整合上可能受限，而大模型在线执行又贵。

传统方法与核心矛盾

文本片段失去教师隐藏态中的知识；强模型缓存跨模型架构注入难以保证语义对齐，缓存亦有模型版本兼容风险。

技术方案与关键模块

基于 Cache-to-Cache (C2C) fusion：离线对每个 corpus passage 生成 sharer 4B→receiver 0.6B 融合 KV cache；请求时检索对应 passage，将预构建的 KV 注入小模型，在线不用再调用 4B。

训练 Loss / 优化方法

本文初步试验中，fuser 没有在 retrieval QA 专门训练（zero-shot）；离线预计算 cache，任务训练阶段和推理检索阶段严格分离。

推理 / Serving

离线文档缓存需按 passage/version/model/tokenizer 编址，在线检索 cache 并注入小模型 KV；内存与磁盘容量、网络传输、跨模型更新、缓存缺失回退是主要落地风险。

实验设置与离线/线上证据

五个 QA benchmark，两个独立本地 Judge，在 30 次评审比较中 29 次优于纯文本 receiver，17/30 达显著性；论文为 workshop work in progress，未报告生产 SLA 或 A/B。

对比主流方法与效率/成本

与 Text RAG 相比有潜在质量收益；与在线大模型 RAG 比可能降低算力。注意融合 KV 不是免费的，离线构建和缓存带宽可能吞噬省下的 FLOPs。

适用场景与尚未解决的局限

需防缓存失效、版本不一致、证据污染；法务/隐私敏感文档缓存比纯文本更难审计与删除；评审并非业务随机实验。

未来研究路线

研究多文档缓存组合与冲突检测、cache provenance、模型升级后无损迁移，和 Reward 对齐下的可靠性。

记忆压缩与检索独立优化使 data loss 无人负责；热门记忆被频繁查到形成 feedback loop，未曝光记忆难证明价值。

检索优先级融合语义相似度+可审计使用贡献+UCB；merge 移到离线定时维护，支持回滚与引用来源跟踪。

相比永不更新 memory score 有反馈适应性，相比每轮全量 LLM 总结有较低线上 write cost；但依赖 judge 可信度、反馈自增强纠偏和历史数据合规。

背景 / 业务动机

检索阶段 embedding 距离捕获语义近似而不总等于业务相关性；用户评价匹配有大量属性/极性/事实约束，JEV 类判别模型值得作为高成本重排候选。

传统方法与核心矛盾

召回排序与相关性概率判别不同：topK 截断影响所有方法的上限；加入正例的控制池与真实全库召回的偏差必须分开统计，避免“作弊候选池”。

技术方案与关键模块

BGE-M3 dense-only 对比 TypeSafe Jev Noul 和 OpenAI Decisions Predicate，官方 SciFact test 的 300 queries；比较正例注入的固定 100-doc 池，以及无正例注入的 full-corpus 检索后 depth=50/100 rerank。

训练 Loss / 优化方法

这项工作主要是 API 判别对照，不训练新推荐模型；不报告用于校准多任务 Reward 的参数训练 Loss。

推理 / Serving

先 ANN 召回，再对 K=50/100 文档调用 Decision API；候选评分可以缓存，但去重、exact-zero ties、API 唯一调用成本、并发和尾延迟需要计量。

实验设置与离线/线上证据

full-corpus depth=50 的 nDCG@10：BGE-M3 0.6413、OpenAI 0.7545、Jev 0.7805。depth 50→100 增强候选已知正例覆盖，但最终排序变化 bootstrap 区间均包括 0；作者亦强调不能证明一般性优越或概率校准。

对比主流方法与效率/成本

可做 dense stage 的强重排对比，尤其多条件 query 与证据筛选；但同协议的 API 价格和延迟混用缓存与新请求，不能当生产端到端 P99。

适用场景与尚未解决的局限

只覆盖 SciFact，不能外推电商评论极性、可信度或成交；成本和时延口径并不完全统一。Decision score 也未证明是真正校准概率。

未来研究路线

统一按新鲜 API 请求测 API dollar/1k query、CPU/GPU-ms、P99，评测商品评论 query-intent/事实验证与跨域鲁棒性。

商品评价推荐落地与技能启发

在评价 query 相关性场景做两阶段实验：双塔 Recall@100 固定后，比较现有精排、Jev 类决策模型与交叉编码器，按 NDCG、正反观点覆盖、成本和 P99 绘 Pareto，不直接替换整个精排。

Trainable [DUMP] Prefix Embedding

Reducing Representational Interference in Retrieval Embeddings with Trainable Prefix Tokens · 原始 arXiv 首稿 2026-11-05 UTC，2026-11-06 cs.IR 公告

embedding 模型把长文本压成向量时，attention sink 和低信息 token 可干扰 pooled representation；可学习 prefix 提供一个更低成本的表示侧干预。

背景 / 业务动机

长商品评价混合模板好评、物流术语、细节批评，mean/EOS pooling 可能偏向高频噪声词，导致真正查询相关的观点被压平。

传统方法与核心矛盾

扩大 encoder 或修改 pooling/contrastive objective 有部署复杂度；简单清洗可能丢必要语境，不能解决模型内部表示干扰。

技术方案与关键模块

训练时在输入前加一个或多个 trainable [DUMP] token，通过 self-attention 与原文 token 交互，使低价值激活在新的 prefix 位置消散；整体 encoder 结构、pooling 和 contrastive retrieval loss 保持不变。

训练 Loss / 优化方法

常规 contrastive loss 同时优化可学习前缀参数和 embedding 模型，验证 encoder 和 decoder embedding 双类架构；论文报告长上下文与标准检索有持续正增益，具体大小依模型/数据集而变。

推理 / Serving

要明确推理是否同样需要 [DUMP] prefix 与 tokenizer/config 一致性，按 token 个数计量增加的 prefill latency；如果向量库重建则存在索引更新成本。

实验设置与离线/线上证据

标准 IR 与长上下文 benchmark，对微调基线一致性改善；同时观察 token activation 与 attention 机制。无线上 A/B 或可直接比较的工业 CTR 指标。

对比主流方法与效率/成本

与 LoRA/新增 reranker 相比，是 embedding 端轻量结构干预；但仅对 pooling 编码和 attention 干扰有效，不能替代 hard-negative、正负观点标注和跨域训练。

适用场景与尚未解决的局限

任务是通用相关性，不保证评论中否定词精度；新前缀也可能学成新的 token sink 或随数据漂移。

未来研究路线

加入商评难例：同一商品相反观点、短查询长评价、模板重复、否定极性，做 Recall@K 和语言子群鲁棒性。

商品评价推荐落地与技能启发

可以做成本较低的 encoder ablation：基线 vs DUMP-prefix 在固定文本、固定索引和统一 Hard Negative 下看 Recall@50、跨商品泛化与推理 P99；显著后再考虑重建生产索引。

商品评价生成式重排：本期实验优先级

P0 · 重新定义曝光 List Reward：埋点实际 viewport/展开/阅读深度，冻结 Generator，对照 Independent CTR Sum 与 ICE 的 joint exposure-click 评估器。离线评估 SeqAUC、位置校准 ECE、真实 List 收益排序一致率；线上成交、满意度、长尾观点覆盖、P99 同步守护。

P1 · 诊断 Reward Hack：冻结现有 Reward，在同一用户不同商品、同一商品跨用户计算 item-mean / user-residual；三组训练：原 Reward、per-item mean centering、Shrinkage standardized residual。检查热门好评吸附、内容信息密度和反向观点覆盖，不因 Coverage 改善自动声称收益上升。

P2 · SID 与检索成本：BRIDGE 回灌码本连续锚点、OptST 任务适配 token、GINGER 的 ANN serving 成本各自做独立消融，必须保留相同候选池、曝光和在线流量约束，记录 Recall@K、冷品召回、索引刷新、GPU/CPU-ms、P99 与 ROI。

P3 · Agent 证据管理：CORE 段落→span→引用；MEMOIR 离线合并审计与命中反馈，评测否定意见和真实差评是否在长会话中保留。所有个性化记忆都要提供 TTL、删除、血缘和纠错通道。
