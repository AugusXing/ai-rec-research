Weight Coding: Evolving Web-Scale Recommenders through Direct Weight Edits with LLM Agents

Research Impact Score / 研究价值：90/100工业成熟度：96/100创新性：94/100与你方向的相关度：98/100是否官方开源：未核验官方公开实现是否有线上 A/B：有：Pinterest 双塔召回线上A/B阅读优先级：S+

Impact分项（范式/工业/创新/相关/后续/复现）：96 / 96 / 94 / 98 / 94 / 35；本站研究判断。

背景与业务动机 / 现有问题

重训与微调把模型迭代绑定在梯度训练及代理损失上，离线目标和线上业务目标之间存在错位。直接修改已有权重能否成为低成本、可审计的模型演进通道，是本文的问题。

技术方案与关键模块

Agent 在沙箱中读取模型、定位参数块，再执行缩放、重置、低秩压缩、插值、方向偏置等编辑；先扫描，再跨日过滤，再搜索和组合。对图像搜索147M参数双塔，重点检查DHEN交互结构、LayerNorm及检索头；正负概念均值差可用于新鲜度等方向控制。组合时重新搜索以处理偏置与shortcut相互作用，而非把独立编辑机械叠加。

训练方法

不是常规梯度训练：采用16对反向高斯扰动的进化搜索，每步以32个候选目标排序更新Adam，目标模型只需前向。开发日内部划分搜索和选择，独立过滤日剔除方向反转编辑，最终留出日不能参与迭代。对并列打分使用悲观排序，避免塌缩Embedding虚增Recall。

实验设置与离线/线上证据

表3：PinRec生成式召回无序R@1 +2.31个百分点、有序+2.64个百分点，精排Utility NDCG相对+0.53%。主双塔组合L07留出日提升15.7个百分点（四日平均），生产评估器+15.0个百分点。表4线上各组约1000万用户、约一周；save目标A2人均save +10.7%，但长点击−24.9%、商品曝光占比−37.8%。L07长点击+97.0%而save−0.3%。均为该召回源归因指标，不是全站成交。

推理 / Serving 与效率成本

既有模型架构可维持不变，前向缓存适合批量试验；但搜索总成本、索引刷新和跨版本适配需要独立预算。不能由单源实验推断全站ROI。

主流方法对比、局限与未解决问题

相比全量fine-tune更易审计、回滚，能直接用不可微评价目标；相比LoRA未必更泛化。仍缺同算力梯度微调、随机搜索和后续模型刷新复用对照；业务指标竞争明显。

未来研究、工程落地及职业技能

评价推荐可先在独立List Reward上做轻量权重编辑（校准头、门控、任务权重）；同算力对比随机搜索/梯度微调/Agent，严格冻结未来日期和人群，检查候选多样性、负评覆盖与成交/满意度。只有回归、影子流量和人审通过才随机A/B。技能：模型诊断、无梯度优化、实验治理、可回滚发布。

MADRec: Reliable Multi-Agent Reasoning with Evidence-Grounded Debate for Recommendation

Research Impact Score / 研究价值：76/100工业成熟度：55/100创新性：85/100与你方向的相关度：98/100是否官方开源：未核验官方公开实现是否有线上 A/B：未披露阅读优先级：S+

Impact分项（范式/工业/创新/相关/后续/复现）：83 / 55 / 85 / 98 / 94 / 35；本站研究判断。

背景与业务动机 / 现有问题

多Agent相互反馈可能放大错误；协同交互信号与语义信号都重要，但语义推断不一定有事实依据。推荐需要将证据可靠度与排序效用区分。

技术方案与关键模块

先用冻结SASRec/BERT4Rec召回30个候选，Interaction Agent与Semantic Agent互评并更新排序。语义分支构建claim–evidence表，通过独立一致性验证器修正候选分数；Judge自适应融合交互和语义分支。证据验证不能替代偏好判断，二者分别输出。

训练方法

召回器独立训练；DeBERTaV3-base验证器用跨域证据/主张二分类微调，AdamW 2e-5、batch16、3 epoch、512 token，按验证Macro-F1选模型；推理冻结。其余Agent通过提示和交互运行，不是端到端RL。

实验设置与离线/线上证据

Beauty、Book、ML-1M按时间留一；每域2000用户、3次独立重采样，同次比较同用户，候选缺失记0。表5 ML-1M NDCG@10 0.1487（InteRecAgent 0.1220、MACF 0.1301）；消融分别移除证据检索、验证器、辩论、Judge。离线结果不代表用户满意度。

推理 / Serving 与效率成本

ML-1M顺序请求平均5次LLM调用、输入/输出36k/8.3k token、35.6秒/用户、0.0051美元/用户（表5）；显然不适合直接替代毫秒级商品评价重排。

主流方法对比、局限与未解决问题

相对单Agent或直接辩论有独立事实验证和协同约束，但验证器依赖标签与证据覆盖，Judge仍会偏置。部分基线使用不同候选生成过程；离线next-item指标未衡量成交或观点覆盖，线上尚无证据。

未来研究、工程落地及职业技能

适合离线Teacher：评价内容证据抽取→支持概率→List效用评分。设计同候选、同预算的单Judge/多Agent/独立证据校验消融；测试错误主张、正负观点遗漏，再蒸馏给轻量重排器。技能：NLI、证据监督、Judge校准、Teacher蒸馏。

传统重排多优化相关性或用手工多样性规则；图像能否带来额外信息取决于文本是否已足够表达物品属性。

技术方案与关键模块

将历史交互与候选标题、图片构造成多模态提示，并指示兼顾相关性和类别覆盖；在SASRec候选上使用InternVL3-38B或Claude Sonnet 4.6排序。拼图减少独立图像输入数量，但不一定减少实际视觉token。

CO-GRAFT: Attributing Reinforcement Learning Gains in Search Agents via Role-Level Policy Grafting

Research Impact Score / 研究价值：77/100工业成熟度：48/100创新性：91/100与你方向的相关度：93/100是否官方开源：未核验官方公开实现是否有线上 A/B：未披露阅读优先级：S

Impact分项（范式/工业/创新/相关/后续/复现）：88 / 48 / 91 / 93 / 94 / 42；本站研究判断。

背景与业务动机 / 现有问题

RL终局EM提升不能说明搜索、思考、停止、答案抽取究竟哪一步改善；独立离线组件评分忽略闭环交互。

技术方案与关键模块

把原始与RL模型按四个角色（推理、搜/答决策、query生成、答案抽取）交替控制同一条实时检索轨迹。枚举16种配置，将得分作为合作博弈价值；Shapley分摊总增益，Möbius分解识别协同或冗余。无需为每个组合再训练模型。

训练方法

作者适配Search-R1 GRPO：终局EM奖励加0.2格式奖励，检索token屏蔽Loss，最多4轮搜索，组大小5；NQ与HotpotQA训练后分别评测。也比较公开GRPO/PPO checkpoint，归因过程不依赖训练时Reward形式。

实验设置与离线/线上证据

原文报告RL增益最高约32 EM点。Llama-3.2-3B base的推理×决策交互在NQ/HotpotQA分别+8.8/+5.4点，单角色效果弱。Qwen2.5-3B instruct在NQ的推理×答案交互−8.9点，体现冗余。指令微调后停止搜索可能损害多跳收益。

推理 / Serving 与效率成本

四角色需要16个闭环配置，计算按角色数量指数增加；这是离线诊断，而非生产Serving路径。线上无需增加推理开销，前提是只据此选择训练方案。

主流方法对比、局限与未解决问题

比独立角色指标更能捕获相互作用；角色划分和切换兼容性会影响归因，Shapley不是跨用户因果收益。EM和格式分不覆盖电商复杂满意度，真实用户实验缺失。

未来研究、工程落地及职业技能

将生成式重排拆成候选选择、位置决策、局部Reward、停止/约束四角色（此为迁移设计），固定候选池与曝光条件，先做混合策略回放识别互补/冗余，最后独立线上随机实验。技能：RL诊断、合作博弈、反事实回放。

The abc index: Exact Retrieval for Learned Sparse Representations

Research Impact Score / 研究价值：75/100工业成熟度：63/100创新性：86/100与你方向的相关度：85/100是否官方开源：未核验官方公开实现是否有线上 A/B：未披露阅读优先级：S

Impact分项（范式/工业/创新/相关/后续/复现）：80 / 63 / 86 / 85 / 88 / 40；本站研究判断。

背景与业务动机 / 现有问题

学习稀疏向量的长加权query使传统动态剪枝变慢，近似检索可能漏召；如何在CPU上保持严格topK并提高效率？

技术方案与关键模块

把文档划分硬窗口，使用TAAT累计分数，紧凑布局存储非零block、posting及权重；对子块最大值构建保守上界，优先访问高潜力块并做Block-Max MaxScore剪枝，最后补全候选得分。文档ID重排提高局部性，二进制packing减少存储。

训练方法

研究索引而非Encoder训练，使用已有学习稀疏表征。精确性取决于上界保守、统一tie-breaking和权重表示；8bit量化下只对量化空间精确，不自动等价于原始float32。

实验设置与离线/线上证据

四组数据CoCondenser、OS-gte、SparseUp、SPLARE；单线程表4 abc-bmms相对穷举abc在K=10快2.9–4.1倍，K=1000仅1.1–1.3倍。表5 CoCondenser f32 packed K=10 1.476ms、K=1000 5.040ms，Recall均1；8bit版本K=10 Recall 0.9925。

推理 / Serving 与效率成本

剪枝附加空间约3.4–5.6%；packed+剪枝比未压缩剪枝慢至多19%，空间约少四分之一。需要同时测CPU核数、索引构建、缓存命中和P99；结果不是生产QPS。

主流方法对比、局限与未解决问题

相对HNSW/Seismic可避免近似剪枝损失，但小K部分近似方案更快；长query、量化、动态写入和分片合并仍需评估。

未来研究、工程落地及职业技能

评价观点检索构建稀疏语义+词法索引，比较BM25/SPLADE/双塔混合；用f32全量扫描做golden，单独记录量化损失和剪枝损失，并测长尾词、差评召回、P99与更新成本。技能：倒排、SIMD、动态剪枝、检索基准。

MoR4Rec: Mixture-of-Recursion for Sequential Recommendation

Research Impact Score / 研究价值：68/100工业成熟度：45/100创新性：77/100与你方向的相关度：85/100是否官方开源：未核验官方公开实现是否有线上 A/B：未披露阅读优先级：A+

Impact分项（范式/工业/创新/相关/后续/复现）：76 / 45 / 77 / 85 / 87 / 35；本站研究判断。

背景与业务动机 / 现有问题

序列模型对所有历史交互使用固定深度，但重复点击与复杂跨周期意图需要不同计算量。

技术方案与关键模块

共享中间递归Transformer块，通过逐token路由确定递归深度，并复用跨递归步KV；门控注意力控制信息传播。浅层处理简单交互，深层可处理复杂依赖，但深度本身不等于可解释兴趣。

训练方法

背景与业务动机 / 现有问题

并行草稿能一次预测多token，但后续token未充分依赖已选前缀；提高接受率可能增加草稿成本，未必降低总体延迟。

技术方案与关键模块

并行生成候选shortlist，使用轻量前缀条件纠正打分，并将交互编译成候选pair表，避免反复执行大型串行模型。最终由目标模型一次因果前向验证；贪心保持目标输出，采样用点质量提案拒绝采样保持目标分布（限定论文数值条件）。

训练方法

共享backbone以正确前缀的全词表预测辅助监督（权重0.2），selector用shortlist交叉熵；失去正确前缀后降权，selector权重逐渐升至0.5，并使用replay guard防止缩短已正确前缀。
