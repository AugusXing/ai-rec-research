从“Proxy Metric 更高”走向
Decision Validity、Causal Value 与 Serving Correctness

周末没有新的 arXiv 批次，因此今天不把“过去 24 小时”机械理解成提交时间：主论文来自 8 月 28 日 Friday new-list 中昨天尚未纳入、但对推荐 / 搜索最有价值的工作；同时加入过去 24 小时真实出现的 SGLang Top-K correctness 问题。共同信号很清楚：下一阶段不只优化 nDCG / AUC / Recall，而要验证这些 proxy 是否真的改变正确的下游决策、业务因果增量与在线数值正确性。

今日核心结论：① PailitaoGR 把视觉“裁剪 / OCR 工具调用”蒸馏进生成式检索器本身，代表 Generative Retrieval 开始内化 perception policy；② OC-SFT 证明相同 nDCG 的 LLM scorer 可以做出完全不同的保留 / QA 决策，重排评测必须进入 decision layer；③ Evidence-aware RAG 进一步说明“更像下游需求的 retrieval metric”也不自动具有 downstream validity；④ Stageboost 用反事实估计驱动 eBay 页面信号推荐，线上 GMB +0.08%，再次说明工业排序最终要优化 causal utility；⑤ misi 把 ANN 取舍从峰值 QPS改写成 build cost × memory × rebuild frequency × metric generality；⑥ SGLang 的 silent wrong Top-K bug 提醒：Serving 优化若没有 correctness invariant，吞吐提升没有意义。

重点精读 01 · Generative Retrieval / Multimodal

PailitaoGR：把“Zoom / OCR”从工具调用变成模型内部能力

Research Impact Score / 研究价值 9.8/10工业成熟度 ★★★★☆创新性 ★★★★★与你方向的相关度 ★★★★★是否官方开源 暂否；论文承诺接收后发布数据/模型是否有线上 A/B 否 / 未披露阅读优先级 最高

背景 / 业务动机

淘宝拍立淘这类图搜，用户上传的不是干净商品图：目标商品、品牌/型号文字、其他物体、水印和背景会同时出现。传统多阶段视觉搜索可以先定位、裁剪、OCR，再做召回；但生成式检索若直接从原图生成商品 Semantic ID（SID），就必须同时学会“目标在哪里”和“哪些辅助信息值得用”。显式调用 grounding/crop/OCR 工具虽强，却增加在线步骤和 latency。

现有问题

第一，直接对完整图做 SID generation 容易被背景和非目标区域干扰；第二，OCR 文本有时是关键型号，有时却是水印/无关字符；第三，teacher 使用 crop/OCR 能看得更清楚，但把它们在线保留会破坏生成式召回追求的单模型低时延路径。

技术方案与关键模块

PailitaoGR 的核心是 Latent Think-with-Images：训练期借助 Crop Teacher / OCR Teacher，推理期只输入原始 query image。Target Enhancer 对视觉 token 做轻量相关性打分，并通过 residual modulation 强化目标 token；随后用 Crop Teacher 对 student 自己采样出的 SID prefix 做 on-policy distillation，减少 teacher-forcing 与自回归推理之间的 exposure mismatch。论文还对 SID→visual attention 加两类 guidance：Region-of-Target 约束让细粒度 SID token 越往后越集中到目标区域，entropy guidance 则配合 SID 的 coarse-to-fine 语义层级控制注意力粒度。

第二条支路是 Selective Auxiliary-Evidence Utilization：Auxiliary Enhancer 强化可能包含可用文字证据的视觉 token；OCR Teacher 同时读取 crop 与外部 OCR 文本，但 student 并不是无脑模仿，而通过 in-capacity incremental contrastive distillation 只吸收“相对 Crop Teacher 真正带来增益、且当前 student 有能力从原图感知”的那部分 OCR 能力。这一点非常像把工具能力蒸馏成可选择的 latent evidence。

训练方法

基础目标仍是 autoregressive SID cross-entropy；目标聚焦支路叠加 on-policy JSD distillation 与 granularity-aware attention guidance；辅助证据支路再加入增量式对比蒸馏。数据来自真实 Pailitao 在线图搜日志，覆盖 7 个代表性类目。这里最值得复用的是 teacher 设计：teacher 不必和线上 student 拥有相同输入预算，可以用更强工具/更干净输入，然后把“增益能力”而不是输出本身选择性蒸馏下来。

推理 / Serving

Serving 时不需要 crop、OCR 或多步 tool call，只在原图上运行一次生成式 retriever，自回归生成 Top-K SID，再映射到商品。它对工业系统的关键价值不是“多一个视觉模块”，而是把 training-time expensive perception 换成 inference-time latent capability，避免工具链串行 latency。

实验、离线指标与线上证据

论文使用真实在线日志构建训练/验证集，报告相对现有 generative image retrieval 与 contrastive retrieval baseline 平均提升 13.8%；并指出完整模型能够超过只看 target crop 的 Crop Teacher 和加入外部 OCR 的更强 OCR Teacher，说明两类能力的组合并非简单 teacher upper bound。论文目前没有披露线上 A/B。

优劣势、局限与下一步

相对显式 Think-with-Images，它在线更快、更稳定；相对纯 end-to-end 原图模型，它又显式注入了“目标区域”和“辅助证据”的训练归纳偏置。局限是训练链更复杂、需要目标框/OCR teacher supervision，且离线平均增益尚不能替代真实 latency、CTR/CVR、长尾类目 A/B。下一步最值得研究的是：Target/Auxiliary routing 能否和 SID hierarchy、candidate budget、动态 decoding 统一成 request-aware policy；以及 tool teacher 能否进一步扩展到属性抽取、价格/品牌实体识别和视频局部搜索。

对推荐 / 搜索工程与技能的启发

如果做生成式召回，不应只盯 tokenizer 与 decoder。更重要的新能力是 teacher–student capability internalization、on-policy distillation、visual-token routing、SID coarse-to-fine attention。这套思想也可迁移到推荐：训练期让强 LLM/Agent 读更多历史、图谱或工具结果，线上 ranker 只读被蒸馏的 compact state。

重点精读 02 · Re-ranking / LLM Scorer

Equal Ranking Quality, Different Decisions：重排真正该稳定的是“决策”，不只是 nDCG

Research Impact Score / 研究价值 9.4/10工业成熟度 ★★★☆☆创新性 ★★★★☆与你方向的相关度 ★★★★★是否官方开源 是是否有线上 A/B 否阅读优先级 最高

背景 / 核心矛盾

LLM listwise reranker、reward model、multi-document QA scorer 常把多个候选一起放进 prompt。于是候选的 score 不仅取决于内容，还取决于 presentation order。工业上我们通常用 nDCG@10 选 scorer，但真正执行的是阈值截断、reader 读取哪些文档、preference model 选哪个 response——这三者都是离散决策。

关键发现

论文找到一个非常重要的 measurement gap：5 个训练 scorer 的 nDCG@10 差异都在 0.010 内，但换候选顺序后，阈值保留集合 overlap 只有 0.66–0.84；一个公开 reranker 即便 retained-set F1 最好，overlap 也只有 0.667。也就是说“ranking quality 看起来一样”并不能推出“系统做出一样的决策”。

OC-SFT

Order-Consistency SFT（OC-SFT）把候选顺序不变性写进权重训练：同一个 candidate 在不同 permutation 下的 score 应保持一致，而不是靠推理期多排列平均来补救。论文还比较了多种 prompt-time 修补和 order-targeting objectives；没有一种 prompt 改写同时消除三类下游 order dependence。

实验 / 效率

OC-SFT 在保持 ranking quality 的同时，在三类 decision-stability 指标上领先其他训练 scorer；以 multi-document reader 为例，permutation pair 导致答案翻转的比例降到 0.125，其他三类 order-aware objective 为 0.149–0.164。在 12 个 base model 上，它也比 order-averaged distillation 更稳定；更有工程意义的是，单次 OC-SFT permutation 的 retained-set overlap 可超过 off-the-shelf scorer 做十次以上 permutation averaging，把推理期开销换成训练期一致性。

与主流方法的优劣势

相比 pointwise scorer，listwise LLM 能看候选间关系但天然暴露 order bias；相比 inference-time permutation ensemble，OC-SFT 不需要把 serving cost 乘数倍。局限是它优化的是 order consistency，不等于 calibration、causal utility 或 business constraint consistency；线上阈值和 candidate distribution 变化后仍需重新验证。

对重排工程的启发

未来评测 LLM reranker 建议至少同时报：nDCG/Recall、retained-set Jaccard/F1、阈值稳定性、下游 answer/decision flip rate。对推荐重排尤其重要：同样的 NDCG 可能对应完全不同的曝光集合、广告收入和 diversity。Decision Stability 应成为 listwise model 的一等线上前置指标。

重点精读 03 · Causal Recommendation / Industrial A/B

Stageboost：eBay 用反事实估计决定“页面上该展示什么购买信号”

Research Impact Score / 研究价值 9.3/10工业成熟度 ★★★★★创新性 ★★★★☆与你方向的相关度 ★★★★★是否官方开源 否 / 未发现是否有线上 A/B 是阅读优先级 最高

业务问题

eBay View-Item 页面会展示短文本或视觉“signals”，例如与当前商品相关的购买提示。这里不是传统“给用户排商品”，而是 在已经确定的商品页上决定展示哪个上下文信号。最危险的做法是直接学历史点击/转化：一个 signal 在过去被展示得多、恰好出现在高意向用户上，就会被模型误认为有增量价值。

技术方案

论文采用两阶段 XGBoost。核心不是模型复杂度，而是把 counterfactual estimation 作为 signal recommendation 的依据：先估计不同展示动作下的潜在结果，再由第二阶段选择最可能带来增量的 signal。这个设计把“预测用户会不会买”改成“展示这个 signal 是否会让用户更可能买”，目标从 correlation 转向 treatment effect / incremental value。

训练、Serving 与为什么两阶段合理

树模型在页面级决策中有三个工业优势：结构特征、价格/类目/上下文交叉直接；推理便宜；反事实估计结果可作为中间 feature 进入第二阶段 selection。论文公开信息较短，没有给出完整 propensity / holdout 细节，因此不能推断它使用了哪一种具体 uplift estimator；但“先估反事实、再推荐”的结构本身值得迁移到广告创意、优惠券、解释文案、促销 badge 和通知触达。

线上 A/B

在线实验报告整体 GMB（Gross Merchandise Bought）+0.08%，Parts & Accessories 类目 GMB +0.58%，主要由高客单价商品转化提升驱动。对超大规模电商来说，0.08% 的全站 GMB 增量比离线 AUC 提升更有说服力，也正好体现“causal utility > proxy accuracy”。

局限 / 下一步

公开版本没有充分披露离线 counterfactual validation、treatment overlap、长期用户效应、signal saturation 与 cross-signal interference。下一阶段更值得做的是 doubly-robust / causal forest / uplift learner 与深度 ranking 结合，以及把 short-term conversion、长期信任、页面拥挤度统一成 constrained policy。

工程启发

推荐算法工程里“动作不是 item”越来越常见：理由、解释、角标、权益、促销、通知、排序策略本身都可以是 treatment。此时只做 CTR/CVR prediction 往往不够，必须补齐 实验设计、counterfactual estimation、uplift / heterogeneous treatment effect。

重点精读 04 · RAG / Retrieval Evaluation

Evidence-aware Retrieval：更“贴近生成”的指标，也可能不支持你的下游结论

Research Impact Score / 研究价值 9.2/10工业成熟度 ★★★☆☆创新性 ★★★★☆与你方向的相关度 ★★★★★是否官方开源 否 / 未发现是否有线上 A/B 否阅读优先级 最高

问题：Validity-composition

RAG 检索评测正从 topical relevance 转向“这段 evidence 能否支持最终回答”。直觉上这更对齐生成任务，但论文追问了一层：metric 更合理，是否意味着用它做 retriever 比较、训练、system selection、answer-quality prediction 都更可靠？答案是否定的。

实验设计

作者把 answer-support signal 放进四种角色：①重新比较 retriever；②作为 retriever training supervision；③用于 system selection / 预测下游 answer quality；④直接过滤送给 generator 的 evidence。覆盖 5 个 retrieval benchmark，并加入 TREC RAG 2025 end-to-end setting。answer support 通过将 passage 分解为 atomic claims、再判断 query–passage 支持程度构造。

主要结果

Evidence-aware label 会显著改变 retriever leaderboard，但变化并不稳定传递到下游：不同 benchmark 上原始排序与 answer-support 排序的 Kendall 相关度约 0.378–0.746，Top system 在 5 个集合中有 4 个发生变化；然而把 answer support 直接用于 RankNet-style retriever 训练，多个数据集的收益只有几个千分点且置信区间覆盖 0。system selection 是否更好又依赖 generator prompt 如何要求模型使用 evidence。

最重要的 direct intervention 是：人工标注明确确认 evidence filtering 更能保留“可支持答案”的 passage，但不同 answer evaluator 对最终答案是否变好给出不同结论。这说明“retrieval evidence quality → answer quality → evaluator score”之间每一层都可能破坏 validity。

与传统评测的关系

论文不是说 nDCG 或 answer-support 没用，而是要求 metric 必须按 intended use 做 validation。想比较 retriever、想训练 retriever、想选 RAG system、想预测最终 QA 质量，是四个不同的统计问题；不能因为标签更语义化，就默认它们都成立。

工程 / 未来方向

对搜索与推荐同样适用：AUC/NDCG 的 offline gain 不等于 candidate-set 改善，更不等于线上 GMV/retention；LLM judge 的 relevance 也不等于真实用户效用。建议实验平台把 metric → decision → business outcome 的验证链显式建模，并对每个 proxy 记录“它被允许支持什么结论”。

重点精读 05 · ANN / Retrieval Infrastructure

misi：当索引要频繁重建、内存受限时，ANN 不该只比 QPS

Research Impact Score / 研究价值 9.1/10工业成熟度 ★★★★☆创新性 ★★★★☆与你方向的相关度 ★★★★★是否官方开源 是；arXiv 标注 Links to code是否有线上 A/B 否阅读优先级 最高

核心结构

misi（Metric Inverted Sample Index）从数据库随机抽取约 αn 个对象作为“vocabulary”。每个对象不存完整图边，而是存它最接近的 k_b 个 sample token；查询也先找到自己的 sample neighbors，再通过 IDF 加权的 shared-neighbor vote 聚合候选，最后对 C 个候选做真实 metric exact verification。它可以理解为“用样本邻居词表把任意 metric-space ANN 变成倒排表问题”。

为什么可能适合推荐 / 搜索

与 HNSW/SSD graph 相比，它不是追求峰值单查询速度，而是追求构建可并行、可确定、低内存、可移植。因为构建本质是 n 个独立 search，天然 embarrassingly parallel；vocabulary 随 n 线性增长后，posting list 期望长度可保持近常数 ρ=k_b/α。内部 sample search 又是 pluggable 的，因此可以把任何高 recall 小索引当 inner index。

实验与成本

在 10^8 vectors 规模上，64 CPU cores 构建约 5,250 s，比 matched-recall graph build 快 3.7×；构建强制控制在 3 GiB 内存；持久化 artifact 可从 NVMe 在 8 GB memory budget 下 serving 10^8 vectors。这对每天/小时级重建目录、批量相似检索、黑盒 metric 或内存受限部署很有吸引力。

代价与边界

代价非常明确：在纯 RAM、索引已充分优化的场景，graph baseline 查询仍快 6–16×；为了 0.99 recall，verification budget 随规模约按 n^0.30 增长。其概率模型还指出 overlap 差异小于约 1/√k_b 时，投票本身无法区分。也就是说 misi 不是“HNSW killer”，而是把 ANN 的 Pareto 面扩展到了 build/rebuild/memory/determinism。

工程启发

推荐召回选索引时建议把 KPI 从 QPS/Recall 二元扩成 Recall × Build Time × Peak Build RAM × Artifact Size × Refresh Cost × Query QPS。对 fresh catalog、快速变更 embedding、A/B 多索引并存，这些常常比峰值 QPS 更决定真实成本。

UGC 推荐的两个真实痛点是“interaction 没 review”和“review 只覆盖少数属性”。MOSAIC 从邻居用户 reviews 聚合 attribute–sentiment evidence，为目标用户构造 meta-review，再用 MMoE 联合优化 rating prediction 与 meta-review attribute-sentiment prediction，并通过 attention 个性化这些聚合证据。四个真实数据集上同时改善 recommendation accuracy 与 explanation quality，且对低交互用户更稳定。它的价值不在网络本身，而在把 missing semantic evidence 当作可从协同邻域重构的 state。

SGLang fast_topk_v2：高性能 Top-K 可以“形状正确、结果静默错误”

Research Impact Score / 研究价值 9.0/10工业成熟度 ★★★★★创新性 ★★☆☆☆（Correctness Issue）与你方向的相关度 ★★★★☆是否官方开源 是是否有线上 A/B 不适用阅读优先级 最高（Serving 用户）

8 月 28 日 SGLang 官方仓库 issue #36807 报告：AOT `fast_topk_v2` 对 k=2048 使用 coarse radix threshold bucket，再把阈值桶候选暂存到固定 4096-entry shared-memory buffer；长 row 下阈值桶超过 4096 时，多余候选被静默丢弃。64×256K、k=2048 的复现实验中 64/64 rows Top-K 集合错误，每行有 6–42 个选中值不属于真实 Top-K；64×1M 时错误增到 98–157。输出 shape、index range、数量、去重全部正常，因此常规 sanity check 抓不到。

该 kernel 的 k=2048 与 DeepSeek V3.2 DSA 配置相关；issue 还指出 fused AOT variants 共用同一 device function。工程上最重要的教训是：高性能 kernel 的 correctness test 不能只覆盖典型长度（现有 test 最大 65,536，恰好低于 cliff），必须做 adversarial size/distribution sweep + reference topk set comparison + deterministic replay。修复方向包括 overflow spill、触发后 fallback 到重新扫描全 row，至少也应 fail loudly 而不是 silent corruption。
