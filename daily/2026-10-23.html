Deep Dive · 生成式召回 / SID / 可控多样性 · v1 2026-08-27

ReGen

从 SID 自回归前缀锁定转向全局掩码修订，使多样性控制不再轻易生成无效 ID。

Controllable Generative Recommendation via Guided Token Refinement
Haichao Zhang 等 · arXiv v1: 2026-08-27（UTC）· 本期为 10/22 arXiv 新列表的研究扫描，v1 原提交日不等于新列表日期

Research Impact Score / 研究价值 9.2/10 · 工业成熟度 ★★★☆☆ · 创新性 ★★★★★ · 与你方向的相关度 ★★★★★ · 是否官方开源 是，作者论文声明代码仓库 · 是否有线上 A/B 无公开生产线上 A/B · 阅读优先级 S

背景 / 业务动机

生成式推荐用离散 Semantic ID 直接生成商品，但业务通常不是只最大化 Recall：列表还需要类目覆盖、新颖性、质量和商家约束。传统 TIGER 类逐层自回归 decoding 先锁定前缀，再对局部 token 施加多样性干预，容易把路径推离真实商品目录；扩大 beam 也有算力开销。

现有问题 / 核心矛盾

核心矛盾是控制自由度与目录可行性：早期 SID 前缀携带粗粒度语义，决定了可选子树；后期才对候选 rerank 无法恢复已丢失的语义分支。方法需要在不重训每个业务权重的前提下，对整个 SID 进行全局改写并保证解码路径存在。

技术方案与关键模块

ReGen 将多 token SID 当作整体 mask-filling 任务：并行给出所有位置的分布，针对高层语义 token 加入可调指导信号，再由 confidence-aware iterative refinement 反复修正低置信位置。推理时把真实商品的 SID 前缀组织为 Trie，通过受约束 beam 搜索保留合法 codebook 路径，生成商品后去重，并在集合级权衡准确率与多样性。与完全自由生成不同，拓扑约束是有效商品校验，不是事后简单过滤。

训练方法 / 推理与 Serving

论文使用 RQ-VAE 等离散化编码建立 SID 词表，用用户序列到目标 SID 的 masked token learning 训练并行生成器；报告设置包含 256 维隐藏层、8 注意力头与 AdamW，训练/控制信号应与 SID 版本绑定。部署时 SID 码本与 Trie 同步更新，控制强度可配置；批量 mask refinement 比每步仅出一个 token 更易并行，但每轮仍需模型前向。

实验设置 / 离线指标

在 Amazon Reviews 2023 的 Instruments、Scientific、Video Games 子集上比较 TIGER 系、传统多兴趣召回与多样性解码，考察 Recall@K、Diversity@K、SID 有效性及不同指导强度。作者报告在 Instruments 的相近多样性水平（约 0.54）时 Recall@10 为 0.0398，对照 TIGER-MMR 约 0.0351；高控制下受约束输出的有效 SID 比例约 99.97%，无拓扑约束约 27.63%。数字是特定数据集/配置，不宜推广为全部业务收益。 [核对原文]

线上 A/B 与工程效率 / 成本

线上证据：没有可核验的生产随机流量 A/B。精度/覆盖之间是 Pareto 权衡，过强指导可能使 Recall 下降；应给出固定召回预算、固定商品目录和同分群条件下的多点曲线。 效率边界：关键开销由 refinement 轮数 × 全并行 token 前向、Trie beam 扩展及去重组成。作者消融说明去掉 refinement 会显著损失质量，约四轮后趋于稳定；但 GPU 并行不等于低服务成本，需另测 P50/P99、显存与候选数。

和主流方法的优劣势 / 适用场景

与 TIGER 的优势是可直接干预多个 SID 位置，与 MMR 纯后处理相比更有机会触达不同语义前缀；缺点是需要维护有效 Trie、迭代前向开销、控制目标与 GMV 等真实 Reward 不完全等价。 适合电商列表级覆盖、兴趣多样化、去同质化候选生成；当前更适合召回候选层探索，不宜把多样性提升直接视为订单收益。

局限、未解决问题与未来研究方向

数据集主要是公开行为集，尚无用户体验或线上 GMV 的反事实验证；SID 新旧目录同步、促销及商品冷启的动态码本成本仍需实测。 下一步：值得研究多目标约束直接与 list-level reward 联训、生成器和评估器一致性、带硬规则的 beam/Trie 解码及在线预算自适应。

工程落地与职业能力启发

建议复现四组：原生 TIGER、TIGER+MMR、ReGen 无 Trie、完整 ReGen，固定候选 100/beam 50，分新老 item、热门/长尾、类目覆盖与购买率代理指标做 Pareto；职业技能点是 SID 编码、约束解码、多目标重排与 Serving profiling。 （工程建议由本站基于论文作出，非论文已验证结论）

Our Own Jev

从长链文本裁决转向一次前向读 option logits 或轻量指针头，为推荐 Reward/重排提供低成本候选评估器。

Our Own Jev: Typed Decisions in One Forward Pass, from an In-House Judge to Open LoRA Models
Yuchuan Weng 等 · arXiv v1: 2026-10-21（UTC）· 本期为 10/22 arXiv 新列表的研究扫描，v1 原提交日不等于新列表日期

Research Impact Score / 研究价值 9.0/10 · 工业成熟度 ★★★☆☆ · 创新性 ★★★★☆ · 与你方向的相关度 ★★★★★ · 是否官方开源 部分开放：2B LoRA 模型；内部数据未公开 · 是否有线上 A/B 无生产线上 A/B；有离线评测 · 阅读优先级 S

背景 / 业务动机

推荐评价内容的 List-level Reward、Agent 轨迹筛选和多目标 router 往往要一次评估大量候选。如果每次让生成式 LLM 写解释、解析答案，吞吐、稳定性、选项顺序偏置和成本会成为瓶颈。

现有问题 / 核心矛盾

传统分类头需要固定任务，生成式裁判成本高且评估器会因问法或顺序漂移。关键是对一组明确选项输出可校准概率并保持一次前向、可组合的决策接口。

技术方案与关键模块

Typed decision 输入证据、问题和固定选项，通过输出层选项 token logits 或小型 pointer head 读数，无须逐 token 解码推理理由。Part I 在冻结 4B/27B 等基础上使用 rank-16 LoRA 和指针头，一次回答三类判断；Part II 在开源 Eikos 约 2.5 万决策数据上训练 1B/2B/35B 的 LoRA 并直接读字母选项概率。

训练方法 / 推理与 Serving

内部任务来自约 148K 编程 Agent 会话记录，训练监督为多问题类型判断；公开实验用决策对构造静态选项训练。评估应固定 evidence、question、options、位置扰动和人工金标准，不能把模型对旧教师的一致率当最终正确率。

实验设置 / 离线指标

内部系统报告单 GPU 约三分钟评估 1000 条 session，按论文参考费率约 $0.06，相对原 frontier judge 成本约 1%。公开 JevBench 111 条 hard case 上 35B 的单次实验准确率 79.3%，商业参考 73.0%，差异 p=0.12 未达显著；论文承认开发时接触公开测试集、小样本和单种子的不确定性。 [核对原文]

线上 A/B 与工程效率 / 成本

线上证据：没有生产流量 A/B。这里的高准确率是特定公开判别集而非电商订单/满意度 Reward 的人类一致性，不应把「超过商业模型」解释为普适优势。 效率边界：节约来自省掉自回归答案生成，以及把少量固定维度选项转换成批量前向推断；生产仍要算 tokenizer、长证据 prefill、选择题长度与吞吐/显存；适合对同一真实曝光 list 多个维度一次打分。

和主流方法的优劣势 / 适用场景

相比 generative LLM-as-judge，接口更稳定、吞吐更高、适合知识蒸馏；相比任务专属轻量 CTR/Reward Model，更通用但可能受选项表达、label bias 和长证据截断影响。 商品评价列表 Reward、用户体验满意度裁判、重排候选 list 批量打分、Agent action gate、模型路由。

局限、未解决问题与未来研究方向

对不同选项排列、同义改写、候选大小变化的稳定性仍需测试；离线判别正确率无法证明可用于 RL/DPO 的 reward ranking calibration。 下一步：多任务 typed head、带 human pairwise 标注的 listwise calibration、温度校准与 OOD 拒答门；评估器和生成器之间用 counterfactual list 进行一致性检验。

工程落地与职业能力启发

建议固定真实曝光 List 构造「成交/满意度」两头的 typed reward，先做离线偏序 AUC、ECE、pairwise consistency、顺序打乱稳定性，再用独立策略曝光数据或在线实验验证；重点能力是 Reward 建模、离线校准和大规模批处理 Serving。 （工程建议由本站基于论文作出，非论文已验证结论）

Chat vs Filter / Hybrid

真实用户随机实验提示纯聊天检索比筛选式检索更差，混合入口不显著优于传统筛选。

Can AI Chat Replace Traditional Search? Evidence from a RAG-based Live Events Experiment
Rakesh Allu、Evgeny Kagan · arXiv v1: 2026-08-20（UTC）· 本期为 10/22 arXiv 新列表的研究扫描，v1 原提交日不等于新列表日期

Research Impact Score / 研究价值 8.9/10 · 工业成熟度 ★★★☆☆ · 创新性 ★★★★☆ · 与你方向的相关度 ★★★★★ · 是否官方开源 未核验官方代码或数据仓库 · 是否有线上 A/B 有预注册在线用户随机实验；不是生产业务 A/B · 阅读优先级 S

背景 / 业务动机

业界常假设 Agentic Search 能替代筛选器，用户只需自然语言表达需求。但浏览是探索过程：用户未必知道库存中有什么，菜单、类目 facet、可比较列表会帮助形成需求。

现有问题 / 核心矛盾

许多研究只看自动 QA 准确率或 LLM 偏好，不回答完整搜索会话中用户投入了多少时间、是否看了足够多候选、是否最终做了满意决定。

技术方案与关键模块

预注册、带激励的线上随机用户研究：Filter=传统属性筛选；Chat=RAG 约束于活动目录的聊天界面；Hybrid=二者共存。把所有检索限制于同一批数千个线下活动，以消除聊天凭空编造外部事件的影响；比较满意度、行为、时间与最终选择。

训练方法 / 推理与 Serving

研究重点是交互实验，不是新模型训练；在不同 GPT 底座（包括 gpt-4.1-mini、gpt-5.2、gpt-5.4）上做稳健性分析；需区分用户层随机分组与真实电商大盘线上 A/B。

实验设置 / 离线指标

招募约 389 人、分析 362 人，典型分组 Filter 104、Chat 156、Hybrid 102；真实活动目录约四千条，参与者有实际激励。纯 Chat 的结果/过程体验低于另外两组，Hybrid 与 Filter 的主要差异未达统计显著；探索式用户受损更明显。 [核对原文]

线上 A/B 与工程效率 / 成本

线上证据：这是一项真实在线受控随机实验，但不是生产平台 A/B；不能移植成电商 CTR 或 GMV 变化百分比。模型基础能力和任务库存、奖励设计、参与者人群均限制外推。 效率边界：Prompting fatigue 让成本从点击过滤转移为编写、修订描述，用户倾向直接选最先生成的几个候选，降低探索深度；需要把「用户操作成本」纳入效率而不仅是模型 tokens。

和主流方法的优劣势 / 适用场景

Chat 强于自然语言表达复杂偏好、弱于可见的候选空间与显式过滤；Hybrid 保留 facet 和列表比较，但并不保证带来增量，应检验边际价值和默认入口。 商品评价页，AI 摘要/问答最好辅助「相关/有图/追评/低分/同款」过滤与完整评价列表，而不是替代浏览。

局限、未解决问题与未来研究方向

线下活动属于价格/时间/地域约束显著的目录，用户需求与电商复购不同；随机实验不保证长期习惯与回访效应。 下一步：检索系统应学习何时展现选项菜单、何时请求澄清、何时调用代理；区分 exploratory / navigational / transactional 三种 intent。

工程落地与职业能力启发

建议评价推荐 A/B 同时追踪阅读覆盖率、用户主动筛选、首屏评价信任、决策时间与购买满意度，避免只看聊天 engagement；职业技能是用户实验因果解释与检索 UX。 （工程建议由本站基于论文作出，非论文已验证结论）

把 KV 缓存的保留决策建成「预期复用概率 × 重算成本 − 传输/占用成本」，而非通用 LRU。

To Keep or Not to Keep: Learning KV Cache Retention in Disaggregated LLM Serving Systems
Dong Liu 等 · arXiv v1: 2026-08-10（UTC）· 本期为 10/22 arXiv 新列表的研究扫描，v1 原提交日不等于新列表日期

背景 / 业务动机

在 prefill/decode 分离的推理服务中，缓存命中可能省去大量 prefilling，却不等于局部内存命中：还要从全局缓存传输 KV 到 decode 节点。大图像/视频上下文更放大网络带宽与显存约束。

现有问题 / 核心矛盾

LRU 只看访问新近程度，无法按前缀长度、重算代价、跨节点传输和实际缓存压力定价，不合理的保留会造成命中率表面提高而 TTFT 变坏。

技术方案与关键模块

三个组件分别控制预测与执行：PRP 基于前缀结构/时序特征预测复用概率，CARS 将它换算成不同类型请求的预期效益评分，ATC 根据当前命中情况与内存压力动态调整 admission 阈值。调用者不需要改 LLM 权重。

训练方法 / 推理与 Serving

训练轻量 reuse predictor，而非重训主模型；日志应严格按时间切分，避免把未来前缀出现作为泄漏特征；在线决策只使用可观测前缀元数据和当前资源价格。

实验设置 / 离线指标

作者在文本与多模态 KV block 工作负载以及 MM-Session benchmark 与 NoCache、LRU-Pool、Mooncake-style 等缓存策略比较，报告 TTFT 相对三个基线最大下降 56%、38%、33%，节点间 KV 传输量相比 LRU-Pool 最大下降 53%；MM-Session 吞吐与 oracle 相差约 5%。 [核对原文]

线上 A/B 与工程效率 / 成本

线上证据：论文报告的是 serving workload 评测而非用户随机线上 A/B。「up to」为各实验下最好变化，不可作为全域平均收益或确定的 p99 改善。 效率边界：关键成本是每块 KV 重算 FLOPs、传输 bytes、占用显存的机会成本和 predictor/controller 自身执行；需要同时监控 cache hit、TTFT、TPOT、吞吐、网络峰值、OOM 与成本分摊。

和主流方法的优劣势 / 适用场景

比 LRU 多了 workload-aware economics 和在线阈值自适应，但预测错误、统计分布漂移和资源价格估计误差会使收益回撤；可退化回简单 TTL/LRU。 推荐系统中多个候选共享用户历史/图文上下文时的 prefix reuse；大量同会话用户多轮 RAG、视频理解、分离式推理池。

局限、未解决问题与未来研究方向

隔离业务与缓存污染、公平分配、multi-tenant QoS、跨模型版本 KV 不兼容等仍需补充论证。 下一步：与 token pruning、prompt compression、model routing 联动优化总边际效益，按客户/请求 SLA 自适应设置分层缓存价格。

工程落地与职业能力启发

建立请求 trace 回放：把延迟分为 prefill、cache read、网络传输、decode；对照 LRU/TTL/成本门槛，不能只比较 hit-rate。技能方向是 ML Systems、缓存经济学与 SLO 监控。 （工程建议由本站基于论文作出，非论文已验证结论）

RESEARCHHUB: A Personalized Literature Discovery System for Biomedical Preprints
Viswonathan Manoranjan 等 · arXiv v1: 2026-08-05（UTC）· 本期为 10/22 arXiv 新列表的研究扫描，v1 原提交日不等于新列表日期

Research Impact Score / 研究价值 8.8/10 · 工业成熟度 ★★★☆☆ · 创新性 ★★★★☆ · 与你方向的相关度 ★★★★★ · 是否官方开源 未核验独立官方实现仓库 · 是否有线上 A/B 无公开生产线上 A/B · 阅读优先级 A+

背景 / 业务动机

科研资料推荐容易被语义接近的已读主题吞噬，实际探索需要在保持相关性的前提下适度引入新方向。直接用通用 embedding 检索专业预印本，领域概念和特殊搜索目的经常对不齐。

现有问题 / 核心矛盾

单阶段语义相似性既不能区分 novelty 与 relevance，也难同时满足用户已有研究线和跨主题覆盖；如果全靠生成式理由补偿，召回候选同质化仍无解。

技术方案与关键模块

系统先训练领域 bi-encoder prism 检索候选，再用用户历史定义 frontier novelty，采用 DPP 在候选集合上做 diversity 重排，最后借 Local Intrinsic Dimensionality 组织从基础到专精的阅读顺序，并提供可追溯 attribution cards。

训练方法 / 推理与 Serving

从目标生物医学预印本生成自然语言查询作为正例，结合 multiple-negatives ranking 与 cross-encoder soft-label MarginMSE 训练领域双塔；索引采用 FAISS。离线多样性参数与新颖性权重可视作策略控制器，不应该与 embedding 训练损失混为一谈。

实验设置 / 离线指标

使用 2023–2025 年 44,937 篇 medRxiv 预印本，prism Recall@10 比 SPECTER2-Search 高 12.4 个百分点；报告 DPP 中等强度时 ILD 约从 0.479 到 0.557、主题覆盖从 2.83 到 3.52；主检索召回仍需按候选固定条件解读。服务报告检索 P50 约 10.8ms、P95 约 11.5ms（特定硬件/规模）。 [核对原文]

线上 A/B 与工程效率 / 成本

线上证据：没有用户生产线上 A/B；主题覆盖与 ILD 属于离线多样性指标，不足以断言长期科研发现价值或满意度上升。 效率边界：约 4.5 万篇索引较小、在线 DPP 时间论文报告低于数毫秒，但百万级商品集合需要 ANN 粗召回+局部重排，复杂度对候选数敏感。

和主流方法的优劣势 / 适用场景

比只用 dense retrieval 更系统化、具有可调控探索，但复杂度增加、对用户历史冷启和主题聚类质量依赖明显；直接迁移电商评价还需显式过滤失实和无关内容。 商品评价列表按质量/观点/使用场景覆盖做重排：先选高相关高信任评价，再用 DPP/MMR 保证正负不同理由、规格不同角度的可读性。

局限、未解决问题与未来研究方向

静态数据、预印本质量与后续引用不可直接等价；DPP kernel 若由不稳定 embedding 构造，可能出现过分追求差异。 下一步：学习评价观点的业务效用，而非只看语义差异；强化匹配商品细粒度属性，加入公平曝光与 List-level reward。

工程落地与职业能力启发

搭建固定曝光候选池的 DPP/MMR/list-Reward 三组重排对照：离线分为 relevance、review trust、aspect coverage、GMV proxy，线上验证边际价值。技能点是多目标重排、集合优化及跨阶段链路。 （工程建议由本站基于论文作出，非论文已验证结论）

A Small Model Asks Better: Fine-Tuning Query Clarification for Retrieval-Augmented Generation
Lihong He、Lucian Popa、Marina Danilevsky · arXiv v1: 2026-10-19（UTC）· 本期为 10/22 arXiv 新列表的研究扫描，v1 原提交日不等于新列表日期

Research Impact Score / 研究价值 8.6/10 · 工业成熟度 ★★★☆☆ · 创新性 ★★★★☆ · 与你方向的相关度 ★★★★☆ · 是否官方开源 是，官方开放数据集；未核验官方模型权重 · 是否有线上 A/B 无公开生产线上 A/B · 阅读优先级 A+

背景 / 业务动机

Agentic Search 在用户 query 含糊时直接检索很容易召错货，但每次都请求用户补充条件会破坏体验。检索前语义歧义与检索后发现多个合理实体是两类不同决策。

现有问题 / 核心矛盾

训练集若只有明显有歧义的正例，模型会过度澄清，忽略历史对话或已知过滤条件可以消歧的 hard negatives；需要学「当前证据是否足够」而非文字是否短。

技术方案与关键模块

ClariEdge 建立约 3900 条样本（包括无需澄清的难负例），训练 LoRA 小模型同时预测需不需要澄清、以及合适的澄清问题。相同模型可部署于 pre-retrieval 与 post-retrieval 两个门；后者可针对检索候选实体分歧决定是否追问。

训练方法 / 推理与 Serving

作者报告 Granite-4.1-3B 系 LoRA 在数据集上的分类准确率 96.6%，高于文中测试的多种大模型 prompting 基线；训练与测试主要基于此特定构建集合，不能视为真实用户开放域准确率。

实验设置 / 离线指标

区分 pre/post 检索问题，重点通过 hard negatives 防止误判；分类精度、澄清问题适切性与少量模型的对照评估。报告数字 96.6% 仅对应分类集合，生成澄清文本还须人评或答案完成率。 [核对原文]

线上 A/B 与工程效率 / 成本

线上证据：无公开生产 A/B。真实产品可使用「用户有意愿补充信息的比例、澄清后购买/满意率、误追问率」作为转化漏斗。 效率边界：3B LoRA 比多轮大型推理模型成本可控，但前置每次调用增加 TTFT；门控模型只有在减少昂贵 rerank/错误结果时才产生系统级节省。

和主流方法的优劣势 / 适用场景

相对大型 LLM 纯 prompt，训练后门控更稳定、更便宜；相比手工置信度阈值，对语义冲突敏感，但跨语种、跨商品品类更易漂移。 电商多轮商品搜索、评价中「这款耐用吗」等缺少商品对象的问题、客服 RAG。

局限、未解决问题与未来研究方向

开放数据集有可控构建偏差，未知的用户容忍度和产品语种影响阈值；澄清问题可能泄露用户敏感信息，需要可解释退避。 下一步：建立 expected value of clarification：预估追问收益大于时间成本才执行；结合 query rewrite 与无须澄清的默认安全检索。

工程落地与职业能力启发

先以问答日志构建 positive、无需澄清的 hard negative，部署前后两级门；分模糊实体、语义缺失、已消歧三个群测误追问率。 （工程建议由本站基于论文作出，非论文已验证结论）

SpecEvo: Speculative Evolution with Large Language Models for Cost-Efficient Scientific Discovery
Ha Minh Hieu 等 · arXiv v1: 2026-10-20（UTC）· 本期为 10/22 arXiv 新列表的研究扫描，v1 原提交日不等于新列表日期

Research Impact Score / 研究价值 8.5/10 · 工业成熟度 ★★☆☆☆ · 创新性 ★★★★☆ · 与你方向的相关度 ★★★★☆ · 是否官方开源 是，作者代码仓库 · 是否有线上 A/B 无公开生产线上 A/B · 阅读优先级 A

背景 / 业务动机

多 Agent 研究、自动代码优化和推荐策略搜索经常将昂贵 frontier 模型用在每个平凡候选，导致 API 费用随进化次数线性上升，也让已验证无效方向反复被尝试。

现有问题 / 核心矛盾

传统多模型级联按问题难度选一次模型，却不能因当前研究轨迹连续失败、饱和、发现新规律而动态改变模型组合。

技术方案与关键模块

Speculators 使用低成本模型并行提出/修改程序；Advisor 把成功、失败、饱和探索方向压成可持久使用的状态；Navigator 是高成本模型，在停滞 checkpoint 做跨轨迹综合、局部重写或策略重构。把决策升级从「每次调用选模型」变成「基于历史进展的预算策略」。

训练方法 / 推理与 Serving

主要是提示、角色及外部评估的代理工作流，不意味着对所有模型做梯度训练。候选由任务可运行评估器给出反馈，Advisor 定期归纳，Navigator 稀疏触发；正式部署需标定检查点频率和失败恢复。

实验设置 / 离线指标

论文覆盖四类科学与算法发现任务共 176 项，报告 API 成本最多减少 80%，在特定方程发现任务上评价效率最高达 1.5 倍，CO-Bench 对最强对照约有 3.8% 改进。不同域和预算设置的结果不可当作统一平均提升。 [核对原文]

线上 A/B 与工程效率 / 成本

线上证据：仅研究任务 benchmark；无生产模型路由 A/B、用户 GMV 或端到端服务延迟验证。 效率边界：区分 token/API 成本与实际墙钟：大量并行廉价候选可能压低费用却增加等待或评估器资源；需要为失败重试、上下文累计长度和 frontier navigator 激活费用建账。

和主流方法的优劣势 / 适用场景

比固定 cheap model 或固定 frontier model 更有「何时升级」的显式机制；缺点是多代理协调复杂、对程序评估器反馈质量依赖高，在无客观 reward 的推荐满意度任务会受影响。 推荐排序公式自动优化、Reward 特征筛选、offline A/B 模拟策略探索、自动 ML 工程。

局限、未解决问题与未来研究方向

科学发现任务具有可重复外部得分，电商排序的用户偏好和反事实评估更困难；不能将其成本率直接映射到线上评价重排。 下一步：引入带不确定性的价值函数，估计 frontier 模型边际胜率/费用，在进度停滞与未知任务切换时自动调整调用预算。

工程落地与职业能力启发

构建 replay 可复现的排序候选搜索环境，让廉价模型提出权重与约束，单独验证 Reward 的稳定性，只有新增候选超过统计阈值才请求强模型。 （工程建议由本站基于论文作出，非论文已验证结论）
