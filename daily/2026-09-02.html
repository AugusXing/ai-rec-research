今天最强的信号来自工业检索：Snap 的 SetMIR 把多兴趣召回从“固定 K 个向量”改成可变大小的 set prediction，并把 ANN 调用数下降 33%；百度 ICEGR 把 Query Intent 一路贯穿 SID 构造、SFT 与 Preference Optimization，在 20% 线上流量两周 A/B 中获得 CTR +3.52%、订单 +15.96%、GMV +7.53%；Snap CAMIE 则说明多模态 I2I 的主要增益未必来自更大的 MLLM，而来自与真实 co-engagement 对齐的监督信号。生成式推荐侧，TAAL 把 91.9%–96.6% 的失败定位到 SID 前两步，说明 beam-search 的真正瓶颈是 early-prefix survival；Serving 侧，vLLM 对 QSA prefill/decode 分路后，GB300 上 prefill microbenchmark 达 4.15×–9.37×。

重点精读 01 · Retrieval / Multi-interest · Snap

SetMIR：把多兴趣召回从 K 个向量改成 Set Prediction

Research Impact Score / 研究价值 9.4/10工业成熟度 ★★★★★创新性 ★★★★★与你方向的相关度 ★★★★★是否官方开源 未发现官方代码是否有线上 A/B 是阅读优先级 最高

背景 / 业务动机

工业召回往往从百万到十亿级 catalog 中先拿几千候选。单 user embedding 会把街头服饰、母婴、护肤等不同兴趣平均掉；MIND/ComiRec/KuaiFormer 等多兴趣方法虽然输出 K 个向量，却仍有两个生产问题：interest collapse——多个 target 追同一个 head，未匹配 head 没梯度；以及 static dispatch——每次固定发 K 个 ANN query，不管用户实际上只有几个活跃兴趣。

技术方案与关键模块

SetMIR 把任务类比 DETR 的 set prediction。历史商品先用冻结的多模态 content embedding（title/brand/category/image）得到 item vector，加位置 embedding 与从 0 开始学习的 event-type gate；Transformer Encoder 编码历史，K 个 learnable interest queries 通过 Transformer Decoder 的 self-attention + cross-attention 读历史。每个 query 输出两个 head：一个 L2-normalized retrieval embedding，一个 presence score。

关键变化不是“又加了 K 个 query”，而是 Hungarian one-to-one matching：target 与 interest query 做全局一一分配，assignment cost 同时含 embedding similarity 与 presence logit，后者前 10% step 线性 warm-up。这样每个 matched query 都拿到独立 retrieval gradient，unmatched query 则显式学习 no-interest，而不是被 argmax 训练丢在一边。

训练方法

目标来自最近 3 天的高意图行为，purchase > add-to-cart > swipe-up，去重后最多 15 个；历史取窗口前最近 40 个事件。总 Loss 由 matched query 的 in-batch InfoNCE、presence BCE 与 active-query margin diversity loss 组成，diversity margin 为 0.3。K=10 时 Hungarian 只是在很小的 K×W 矩阵上求解，论文认为开销可忽略。

推理 / Serving

单次 forward 先产出 K 个 (embedding, presence)，之后三步动态 dispatch：presence threshold τ=0.3；query cosine NMS（δ=0.9）；对剩余 K̃ 个 query 分配近似 N/K̃ 的 ANN 深度，结果按 max score merge。没有 query 过阈值时保留最高 presence 的 fallback。重要的是 item 侧仍是单向量 ANN index，不需要改现有索引基础设施。

实验、离线指标与线上 A/B

Snap DPA catalog 为数亿商品；离线 test 约 100 万用户、约 530 万 target products。K 从 1 提到 10 时，R@10 达到单兴趣模型的 155%，而实际 active query 仅 6.70；K=7 已达到 K=10 R@10 的 99.8%，说明“可表达兴趣上限”和“实际活跃兴趣数”应分开。Serving ablation 中，10 个固定 ANN query → presence 7.73 → presence+NMS 6.70，保留 99.2% 的 R@10，同时 R@1 反而到 101.8%。

生产一周 A/B，downstream ranker 固定，向现有 retrieval mix 新增 SetMIR 且总 quota 不变：impression +0.10%、CTR +0.21%、CVR +3.11%。在 treatment 内与同 item embedding / ANN index / quota 的 I2I source 对比，SetMIR CTR +44%、CVR +51%。这组对照很干净：主要隔离了“直接拿历史 item 当 query”与“学习一组当前兴趣 query”的价值。

与主流方法相比

相比 MIND/ComiRec，SetMIR 的优势不是更复杂的 extractor，而是把 assignment 和 dispatch 变成一等公民；相比 ColBERT，多向量只放在 user/query 侧，item 仍是单向量，生产迁移成本低。最值得迁移到你实际召回系统的不是 Hungarian 本身，而是“每个召回 head 既要学 representation，也要学 should-fire probability”。

局限、未解问题与未来方向

论文 item embedding 是冻结的，尚未讨论 user-interest 与 item space 联合训练后是否稳定；presence 是 query-level，不直接优化 downstream utility；NMS 用固定 cosine 阈值，未考虑 category/intent-aware redundancy；线上实验新增一个 source，而不是完全替换原有 retrieval stack。下一步很适合研究 learned dispatch cost、candidate marginal utility、跨 source budget allocation、presence × latency/TCO reward。

对推荐/搜索工程落地与职业技能的启发

召回工程的能力边界正在从“双塔训练”扩展到 assignment、ANN budget、source orchestration、online attribution。值得掌握 DETR/Hungarian matching、multi-interest retrieval、ANN serving、query gating/NMS、source-level A/B 设计。

重点精读 02 · Generative Retrieval / E-commerce Search · Baidu

ICEGR：Query Intent 要贯穿 SID → SFT → Preference Optimization

Research Impact Score / 研究价值 9.1/10工业成熟度 ★★★★★创新性 ★★★★★与你方向的相关度 ★★★★★是否官方开源 未发现官方代码是否有线上 A/B 是，20% 流量两周阅读优先级 最高

背景 / 业务动机

大多数生成式检索 pipeline 是“先用商品内容做 SID → 用日志 query 做 SFT → 再用点击/交易做 preference”。三个阶段各自合理，但目标并不一致：内容 SID 不一定代表用户搜索意图；低曝光商品缺少真实 query-to-SID 监督；业务偏好又可能把高价值但不相关的商品推上来。ICEGR 的核心贡献是把这三个局部问题统一成一个系统问题：Intent Coherence。

技术方案

IA-SID：先用历史 query-product click 做 InfoNCE 对齐，把通用 encoder 改造成 search-aligned embedding；再注入 query-induced product co-click relation 与商品历史 query-intent profile，最后用 RQ-KMeans 生成分层 SID。SQE-SFT：从商品名、品牌、类目、系列、型号、属性自动构造 entity-specifying 与 attribute-constraining query，先用 synthetic query→SID 覆盖全 catalog，再用真实 query→SID 做第二阶段分布对齐。RCPO：先从 beam candidate 中约束到语义相关集合，再结合 click/pay/GMV 形成 business preference，并让 DPO 强度随 pairwise relevance/business margin 动态变化，避免“商业价值压过相关性”。

训练与数据

离线用 held-out 最后一天日志采样 20,000 个 distinct queries，以 clicked products 作为相关 item。SQE-SFT 是最大增益来源，占累计 Recall@20 增益 76.7%；IA-SID 与 RCPO 分别约 5.6% 与 17.7%。Synthetic supervision 对 Low-popularity item Recall@20 +36.2%、Tail +21.2%，而 Hot item 增益较小，说明 catalog-wide synthetic query 主要补的是 exposure/supervision coverage，而不是简单数据增广。

离线指标

对 ProdGR baseline，Recall@20 0.4247→0.5169（+21.7%），MRR@20 0.1982→0.2509（+26.6%），NDCG@20 0.2318→0.2935（+26.6%）。固定 β 的 DPO 把人工 top-5 relevance 从 0.87 拉低到 0.58，而动态 relevance-calibrated preference 恢复相关性，直观展示了“业务 reward 没有 relevance guard 会跑偏”。

推理 / Serving 与线上 A/B

论文测试 0.5B/1.5B/3B/7B，Recall@20 从 0.5043 单调到 0.5334，但线上最终选择 0.5B，因为 accuracy/efficiency 更平衡。生产部署使用 67 张 NVIDIA L20，beam size=50，峰值 2,200 QPS，平均延迟 156ms。两周 A/B 覆盖 20% live traffic：Show PV +8.84%、CTR +3.52%、Long-click +5.27%、Product Landing Page PV +8.75%、Order Volume +15.96%、GMV +7.53%。固定数量的 ICEGR top-k 会直接插入最终曝光列表，形成真正 query→generated SID→product impression 的端到端路径，其余候选仍走现有过滤/排序。

与主流方法优劣势

相比只改 tokenizer/SID 的工作，ICEGR 强在 cross-stage objective consistency 和生产证据；相比传统 ANN 搜索，Autoregressive GR 的 156ms/67 L20 成本仍明显更重。值得注意的是 0.5B 已上线，而不是把 offline 最好的 7B 搬上去，这说明生产 GR 仍首先是系统工程问题。

局限与未来方向

20K query 的离线 ground truth 仍受 click bias；synthetic query 与真实尾部 query 的 gap 从 Tail 增益低于 Low 已可见；beam=50 的成本高，且 SID refresh / catalog churn 没有成为主线。未来最值得做的是 fresh SID、beam pruning、distillation、query-conditioned semantic code、generative source 与 ANN source 的联合 routing。

工程/职业启发

如果你做生成式推荐/搜索，不能只会“RQ-VAE + Transformer”。需要把 SID construction、query supervision、preference objective、beam serving、线上插流策略 串成一条链路。ICEGR 是今天最接近真实“全栈 Generative Retrieval”设计评审的一篇。

重点精读 03 · Multimodal I2I Retrieval · Snap

CAMIE：MLLM Item Embedding 的最大增益，来自行为监督而不是 Backbone

Research Impact Score / 研究价值 8.5/10工业成熟度 ★★★★★创新性 ★★★★☆与你方向的相关度 ★★★★★是否官方开源 未发现官方代码是否有线上 A/B 是阅读优先级 最高

背景与问题

工业 DPA 的 I2I 经常分别维护 image encoder、text encoder、multimodal encoder；而这些 encoder 多数按内容语义训练，并不等于“用户会连续互动/转化的商品彼此接近”。CAMIE 想解决两件事：统一 modality stack，以及把 embedding geometry 从 content similarity 对齐到 co-engagement behavior。

技术方案与训练

从用户 journey 中挖无序 co-engagement item pairs，包含 page view/click/add-to-cart/purchase；30 天数据去重，每用户最多 2 pair，时间衰减半衰期 7 天，并要求 attribution exact、title/image 非空、同 advertiser、同大类等。商品用原生 MLLM 接口输入 image + title + brand + description + category；共享 backbone + projection 输出 512-d L2-normalized embedding。训练使用 symmetric in-batch InfoNCE，跨 device all-gather negatives。

主模型是 Qwen3-VL-Embedding 2B：backbone 冻结，仅在 q/k/v/o attention projection 上加 LoRA r=32、α=64，同时训练 projection head；AdamW、BF16、cosine schedule。offline 10M pairs / 100K test pairs，production checkpoint 用 100M pairs。

推理 / Serving

Catalog item 在 refresh 时离线编码并写入常规 ANN；线上 seed item 如果已有 embedding 直接 lookup，否则按对应 modality 新鲜编码，再发单次 ANN top-K。它没有发明新的 ANN runtime，真正价值是让同一 checkpoint 能服务 multimodal/text-only/image-only input，从而降低模型与 index 体系碎片化。

关键实验

Qwen3-VL 同 backbone 从 pretrained 到 co-engagement fine-tune，R@10 从 normalized 100.0% → 137.7%；最强商业 multimodal embedding 为 129.9%，CAMIE 相对约再高 6%，同时 embedding 512d 对 3072d。更有价值的 matched-backbone 实验显示，在完全相同 pairs/objective/negative/512d/LoRA/训练步数下，Qwen3-VL、SigLIP2、CLIP multimodal R@10 只差 5.5pp，远小于 co-engagement fine-tuning 本身给 Qwen3-VL 带来的 37.7% relative gain——监督信号是第一杠杆。

还有一个很工业的结论：过滤到 add-to-cart/purchase 虽然样本更“纯”，但只有全部 pair 的约 1/3；同样数据规模下高意图样本仅 +1.6% R@10，而保留全 funnel 通过规模换来的增益 +8.9%，最终 full all-event 比 high-intent-only 高 +7.2%。

线上 A/B

CAMIE 已替换 Snap DPA 的 multimodal I2I_MM 与 text I2I_TEXT 两个 encoder：总体 DPA traffic CTR +0.211%、CVR +1.911%；对 multimodal control CTR +0.390%（不显著）但 CVR +10.832%；对 text control CTR +18.958%、CVR +13.12%。全局 CTR +0.211% 未显著，而三个 CVR lift 与 text CTR lift 达 99% confidence。

局限与适用场景

Image-only 是明显例外：SigLIP2 image-only R@10 87.3%，CAMIE 68.8%，说明 MLLM 的 last-token pooling 并不天然适合作纯视觉 embedding。结论不是“一模统一所有 modality”，而是 multimodal + text 可以统一，纯视觉 surface 仍可能保留专用视觉塔。另外 embedding build cost、catalog refresh cost 与 online fresh encoding latency 没有完整量化。

工程/职业启发

做多模态推荐时，优先问“监督是否与业务行为一致”，而不是先问“换哪个 MLLM”。技能上应补齐 contrastive learning、pair mining、multimodal embedding、LoRA、ANN refresh、线上 source replacement A/B。

重点精读 04 · Generative Recommendation / Semantic ID

TAAL：Generative Rec 的真正故障点，是 SID 前两步被 Beam 永久剪掉

Research Impact Score / 研究价值 8.3/10工业成熟度 ★★★☆☆创新性 ★★★★★与你方向的相关度 ★★★★★是否官方开源 未发现是否有线上 A/B 否阅读优先级 很高

背景 / 核心诊断

Semantic ID 是层级路径：c1 选粗语义分支，c2 再细化；一旦 beam 在前两步把 ground-truth prefix 剪掉，后面 decode 再准也没用。TAAL 在 Amazon Beauty/Instruments/Yelp 上分解失败，发现 91.9%–96.6% 的 retrieval failures 发生在前两步。这把 Generative Rec 的问题从“token NTP 不够强”具体化为 early-prefix coverage。

技术方案

训练侧统计相邻 item 的联合 prefix (c1,c2) transition table，并从最近 K_hist=5 个历史 item 以 γ=0.7 指数衰减聚合为 history-conditioned soft target。不是把一个 hard ground-truth token 做 label smoothing，而是显式保留当前 history 下多种合理 prefix transition。

TAAL 用 forward KL 对齐 joint-prefix distribution，因为 forward KL 更偏 mode-covering。为了不枚举所有 c1→c2 分支，它把 KL 分解成 c1 marginal 的 exact KL + c2 conditional expectation，并用 K_mc=2 个 branch Monte Carlo 估计第二项。

推理 / Serving

原来的 trie-constrained beam search 不改；在完整 Top-B candidate 上加一个 O(B) 的 PMI calibration：用 history-conditioned transition probability 除以 global prefix marginal，得到局部时间关联相对“全局热门”的 lift，再加到模型 log-prob。低 support context 用 empirical-Bayes shrinkage（τ=30）回缩到 global prior。它只重排 survivor，不改变 beam candidate set。

实验结果

LETTER-TIGER/RQ-VAE SID + T5，beam B=20。TAAL + PMI 的 NDCG@10 在 Beauty/Instruments/Yelp 分别为 0.0484/0.0881/0.0293，相对标准 baseline +39.5%/+6.7%/+28.6%。其中主要增益来自 joint-prefix training：不做 PMI 就已经 +37.5%/+5.9%/+25.7%；PMI 只再带来约 +1.5%/+0.8%/+2.3%。full-SID survival 提升 3.9%–16.6%，beam 越窄收益越大，B=5 相对 survival gain 可到 39.4%。

为什么重要

这篇不是单纯又一种 SID tokenizer，而是在提醒：Generative Retrieval/Rec 的离线指标必须分解成 prefix survival、candidate generation、post-survival ranking。如果 95% 的错误在 c1/c2，继续优化 c3/c4 decoder 或 final reranker 的 ROI 很低。

局限与未来方向

transition table 是统计式、数据集内的，并未证明大规模工业 catalog 下 memory/freshness；只对前两级 prefix 建模；实验没有线上 latency/A-B。下一步可把 joint-prefix prior 学成 neural transition model，或让 beam budget 动态分给不确定 prefix；也可以与 ICEGR 的 intent-aware SID 结合——先让 SID 本身更 query-aligned，再让 decoding 对 early survival 更鲁棒。

工程/职业启发

生成式推荐调优应建立“故障树”：SID quantization error → prefix survival → beam candidate recall → rerank。只看 final NDCG 会隐藏真正瓶颈。需要掌握 beam search、trie constraint、KL mode-covering、calibration、semantic ID diagnostics。

重点精读 05 · Inference / Sparse Attention · vLLM

vLLM：QSA Indexer 分离 Prefill / Decode Kernel

Research Impact Score / 研究价值 8.0/10工业成熟度 ★★★★★创新性 ★★★★☆与你方向的相关度 ★★★★☆是否官方开源 是，已 merge是否有线上 A/B 不适用；有 E2E benchmark阅读优先级 很高

问题

QSA sparse indexer 原先用同一 kernel 同时处理 decode 与 prefill，但两类 shape 完全不同：decode query 极短，prefill query 很长。通用 kernel 让两边都无法针对 memory access / parallelism 做 specialization。

方案

PR #54513 把混合 batch 拆成 decode/prefill 两路：decode/spec-decode 使用 uniform Triton kernel，prefill 使用单独 prefill kernel；同时把 visible_blocks 前移到 metadata，decode kernel 增加 warmup，并把 sparse indexer logits workspace 从硬编码 128 MiB 改为环境变量 VLLM_SPARSE_INDEXER_MAX_LOGITS_MB，默认 512 MiB。当前 heuristic 针对 GB300 调优。

性能

GB300 microbenchmark 中 prefill speedup 约 4.15×–9.37×：例如 1×8K query + 100K prefix，4,752.939µs → 524.830µs（9.06×）；1×16K +100K 达 9.37×。spec-decode DQL=4 多请求场景可到 1.54×–2.22×。

GB300 TP4、Qwen3.8-Flash-Next E2E：Non-MTP P50 TTFT 在 concurrency 1/16/64 分别约 -16.1%/-9.6%/-9.2%；MTP3 TTFT 在 c1/c4/c16/c64 约 -18.1%/-15.2%/-12.2%/-12.9%，c64 token throughput +8.1%。准确性测试 GSM8K 0.9674→0.9682、MMMU-Pro 0.7671→0.7746，没有观察到 regression。

工程启发

这是很典型的“phase-aware kernel specialization”：Serving 性能问题越来越不是一个 universal attention kernel 能解决，而是按 prefill/decode/spec-decode、batch shape、context length 分路。对推荐/搜索里的 LLM reranker、Generative Retrieval 也一样，prefill-heavy 与 decode-heavy workload 应分开 benchmark。

SGLang PR #37300 修复一个很容易被忽略的容量耦合：ragged target verification 中，“graph 可接受的 request slots”与“captured packed token rows”是两个独立上限。自定义 runner 可能裁掉 token bucket 网格，却仍保留完整 request capacity；把两者都从 max_bs × captured_req_width 推导会一边 over-allocate token buffer，一边错误降低 request admission。新改动保留原始 request-slot capacity，并按真实 captured token buckets 分配 attention CUDA graph buffer；默认 ragged 与 non-ragged 行为不变，12 个单测通过。启发：CUDA Graph 优化不只看 capture 成功，还要把不同维度的 capacity contract 显式拆开。
