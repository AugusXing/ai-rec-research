Whole-Page Policy Improvement｜Learning Generative Ranking Policies for Whole-Page Optimization

把完整页价值分解为每个位置同前缀候选的相对价值，以随生成器滚动更新的策略改进训练，而非给所有位置同一标量回报。

Research Impact Score / 研究价值：89/100工业成熟度：84/100创新性：95/100与你方向的相关度：100/100是否官方开源：未发现官方代码是否有线上 A/B：无 / 另见证据区阅读优先级：S+

评分口径：范式变化25% + 工业证据20% + 技术创新20% + 与推荐搜索相关度15% + 后续研究空间10% + 开放可复现性10%；各维主观判断，不等于引用量或榜单官方评分。本篇维度：范式98 / 工业84 / 创新95 / 相关100 / 研究空间94 / 开放38。

研究背景 / 业务动机

电商评价卡片、信息流和搜索混排的收益来自整个列表的互补性：位置、重复、可见性与约束均会改变单条价值。

现有核心问题

点式分数排序忽略集合交互；给完整列表每个 token 相同 reward 会产生信用分配混淆；预先计算的最优伪标签列表在模型更新后迅速过时。

技术方案与关键模块

状态 s_t=(请求,已选前缀)，在合法候选中采样当前策略 π_k 的完整页；对同一 s_t 的不同下一物品 a，分别由当前策略补全剩余位置，计算 Q^{π_k}(s_t,a)=E[r(完整页)]。仅在已评分候选内按 π_k(a|s_t)·exp(Q/τ)重分配概率，未评分质量不变。

训练方法 / Loss / 学习过程

每轮采样请求和当前生成列表；针对每个前缀枚举/采样少量合法 next-action，用固定 page evaluator 打分其补全页；按局部闭式提升分布构造软目标，以交叉熵拟合 π_{k+1}；新策略再生成下一轮样本。理论保证针对固定 evaluator 的精确更新改善期望分数，并非真实成交保证。

推理与 Serving 方案

服务只运行训练好的自回归 List Generator，按合法位置 mask 逐位输出；无需在线 beam 批量调用 Reward。应为非法重复/类目配额/业务保护留硬约束与回退。

实验设置与对照

KuaiRand-1K、RL4RS-SeqSlate、约19.5万训练页与23.97万测试页的工业日志，以及可求最优页的合成集；对照 PPO、GRPO、DeGRe、GoalRank 与在线 evaluator beam。

离线指标与结果

KuaiRand 各页长平均相对已记录页 score +34.35%（最强对照+32.75%）；RL4RS +7.09%（对照+6.43%）；工业离线 evaluator +13.92%（DeGRe +12.75%），均是模型/裁判分数而非线上业务指标。

线上 A/B 证据

没有报告真实线上随机 A/B，工业日志上的 learned evaluator 分数不能替代增量 GMV/满意度。

效率 / 成本收益

把昂贵的 Reward 搜索迁往训练，在线只保留 Generator；但训练要对同前缀多个补全页评价，真实成本与评分噪声随页长放大。

与主流方法的比较

相较 List-level PPO/GRPO 的序列级优势分配，位置反事实更细；相较离线定稿的 DeGRe 等蒸馏标签，目标随策略自更新；相比在线束搜索更快，但优化受固定 evaluator 偏差约束。

适用场景及局限

理论推导要求评价器固定、精确更新与可行列表；工业实验未校准 reward 误差、曝光偏置与行为反馈回路。

尚未解决的问题与未来研究

优先做 same-prefix counterfactual 的 Reward 可靠性检验；尝试 DR/IPS 校正与多目标保守下界；测 token-position 残差、列表中相似评价的边际价值和延迟预算。

对推荐 / 搜索工程与职业技能的启发

建议在商品评价重排上将成交+满意度 Reward 拆为完整 List 回报与 leave-one-position-out marginal gain；从现有 Generator 采样对照列表，先离线训练 soft-target，再分桶进行线上 A/B。

DNA｜DNA: Unlocking Depth Scaling in CTR Models

阿里淘宝搜索以请求级双向更新历史序列解决深层 CrossAttention 每层只读取同一固定 KV 的收益饱和。

Research Impact Score / 研究价值：89/100工业成熟度：99/100创新性：91/100与你方向的相关度：99/100是否官方开源：未发现官方代码是否有线上 A/B：有（详见证据区）阅读优先级：S+

评分口径：范式变化25% + 工业证据20% + 技术创新20% + 与推荐搜索相关度15% + 后续研究空间10% + 开放可复现性10%；各维主观判断，不等于引用量或榜单官方评分。本篇维度：范式94 / 工业99 / 创新91 / 相关99 / 研究空间90 / 开放38。

研究背景 / 业务动机

长行为序列常成为 CTR 精排增益上限；增加精排网络深度会吃掉 GPU 预算，但当 KV 固定时高层只能重复读取同一信息。

现有核心问题

Taobao search 的 CrossAttn 从16堆到28层仅多+0.02 AUC pt；目标商品感知的历史 token 更新又使成本随候选数成倍增长。

技术方案与关键模块

Dual-stream Nexus Attention 每层先由请求 token U 读取历史 S，再让每个行为 token attend 更新后的 U，得到与请求相关的下一层历史 S_{l+1}；候选 F 也读取 S，但不参与历史更新。

训练方法 / Loss / 学习过程

在同一淘宝搜索训练协议下替换骨干；端到端 CTR 监督。论文比较等单样本 forward FLOPs 的 CrossAttn/DNA/DNA-T，并做只 FFN、仅 attention、减参和等深度消融。不是新增 RL 或 Reward 模型。

推理与 Serving 方案

对于一个 request 先执行一次 U↔S 历史更新，再把更新后的 K/V 共享给 N 个候选读流；历史更新对序列长度近线性、候选数量增加时可摊销。

实验设置与对照

淘宝搜索私有训练/评测，6档计算预算、多个深度、请求候选数 N=5000 的分析 FLOPs；与自家 CrossAttn 栈和候选感知 DNA-T 比，缺大范围外部架构对照。

离线指标与结果

等 FLOPs 下 AUC +0.08—0.26 pt；DNA-4 超过 CrossAttn-28 约+0.09 pt，只需约40%的单样本 FLOPs；DNA-4 与同4层 CrossAttn 在 5000 候选请求 FLOPs 约4.70 vs4.69 TFLOPs。

线上 A/B 证据

有：DNA-4 已部署淘宝搜索；论文报告线上随机 A/B 相对生产模型 CTR +0.8%、GMV +0.5%；未披露流量占比/时长/置信区间。

效率 / 成本收益

DNA-T-4 将历史更新绑定候选，在5000候选时约78.4 TFLOPs/请求，DNA-4约4.70 TFLOPs；论文成本是模块 forward FLOPs 估算，不等同实测 P99 与显存峰值。

与主流方法的比较

相较单向 cross attention，不是堆更多固定读层，而是让历史经请求演化；相较全序列 self-attention，仍保持低成本读流；请求侧共享是技术与工业价值的共同来源。

适用场景及局限

高度依赖搜索 query/scene request 语义；评价类精排需检验 request token 表征质量。未全面验证训练稳定性、KV 缓存碎片、尾延迟与多模态变体。

尚未解决的问题与未来研究

验证先更新行为 KV 对不同类目、长尾用户、商品评价场景的收益；增加历史演化层数对 CPU/GPU 请求级共享缓存及 P99 的影响；与 HSTU/MLP-Transformer 对比。

对推荐 / 搜索工程与职业技能的启发

评价排序中可用 user+商品+场景作为 request token 读取评价交互历史，再让历史更新一次供多条候选评价共用；优先对照 DNA-4/静态 CrossAttn，守住每请求 FLOPs 和 P99。

CACO｜CACO: Coverage-Aware Coordinated Optimization for Continuous Generative Retrieval

联合优化连续生成式召回多个 ANN 查询的集合覆盖，而不是只优化单 query 的距离或多样性。

Research Impact Score / 研究价值：86/100工业成熟度：77/100创新性：96/100与你方向的相关度：96/100是否官方开源：未发现官方代码是否有线上 A/B：无 / 另见证据区阅读优先级：S+

评分口径：范式变化25% + 工业证据20% + 技术创新20% + 与推荐搜索相关度15% + 后续研究空间10% + 开放可复现性10%；各维主观判断，不等于引用量或榜单官方评分。本篇维度：范式93 / 工业77 / 创新96 / 相关96 / 研究空间96 / 开放38。

研究背景 / 业务动机

20 个 embedding query 各取 top20 并不等于获得400个有效候选；不同 query 的 ANN 邻域重叠浪费固定召回预算。

现有核心问题

flow matching / diffusion 的单样本兴趣分离目标不能穿过不可微 topK；Query-level cosine diversity 不等于检索结果集合的去重覆盖。

技术方案与关键模块

冻结连续生成器与物品向量，采样参考 queries 统计 item 被召回频次为无标签代理权重；用 query 间双向注意力+有符号相对方向门预测调整，在单位球面切空间投影并 retraction，保持 embedding 检索接口。

训练方法 / Loss / 学习过程

切向正负扰动生成两组反事实 query，仅替换一个 query 并固定其余，计算集合覆盖边际差；经 antithetic estimator 给平滑非可微 ANN 覆盖目标提供无偏梯度估计。只训练轻量协同调整器。

推理与 Serving 方案

原始 flow/diffusion 一次生成 L 个用户 query→约0.6M参数调整器做 L-query 协同→每 query ANN topK→去重/过滤/粗排；不增加 ANN 调用数。

实验设置与对照

8个公开集和24分区工业流式离线数据；6个冻结生成底座及30个 backbone×dataset 设置，报告 Recall@100/400、query 邻域 Jaccard、部署开销。

离线指标与结果

相对最强基线 Recall@100 最多 +23.7%、Recall@400 最多 +23.9%，query 邻域重叠减少53.3%—64.9%；稠密的 KuaiRec/ML-25M 场景与最强基线接近而非全面大胜。

线上 A/B 证据

无真实线上 A/B；工业数据只展示召回离线指标，不能推断 GMV。

效率 / 成本收益

附加推理延迟约0.5%—3.0%；训练需要参考采样池和多次 ANN 检索，端到端规模化成本需另测。

与主流方法的比较

比独立多 query 的每个局部优化更贴近集合召回效用；与 SetMIR 的动态 query 数和 NMS 可互补：先选预算再学 query 分布。

适用场景及局限

频次代理由底座召回产生，相关性自指；未进入底座 support 的优质评价仍不能被发现；过度追求覆盖可能损失最强相关项。

尚未解决的问题与未来研究

加入在线成交/满意度加权的覆盖边际；探索 query 数 L 与 ANN 深度 K 的联合优化；监控去重率、冷启动、session intent drift。

对推荐 / 搜索工程与职业技能的启发

商品评价召回可构建若干用户关注点 query（物流、质量、尺寸、性价比）并评价每个 query 的边际新增相关评价；联合 Recall@K、Unique@K、下游成交覆盖做预算搜索。

Cost-Aware Feature Agent｜Cost-Aware Agentic Feature Optimization System for Fleet-Scale Ranking Models

把排序特征生成、重要性融合、预算内搜索和跨模型共享的 Feature Pipeline 成本管理做成闭环 Agent。

Research Impact Score / 研究价值：86/100工业成熟度：97/100创新性：87/100与你方向的相关度：92/100是否官方开源：未发现官方代码是否有线上 A/B：有（详见证据区）阅读优先级：S+

评分口径：范式变化25% + 工业证据20% + 技术创新20% + 与推荐搜索相关度15% + 后续研究空间10% + 开放可复现性10%；各维主观判断，不等于引用量或榜单官方评分。本篇维度：范式89 / 工业97 / 创新87 / 相关92 / 研究空间93 / 开放36。

研究背景 / 业务动机

一个业务会维护多种场景的上百个排序器；特征处理成本同时占 GPU/CPU、吞吐和共享 pipeline 资源，单模型最优选择往往拖累全域总预算。

现有核心问题

手工堆特征时不仅显存、FLOPs、QPS 变差，还会重复承担上游 pipeline；现有自动特征工程多数只考虑一个模型和离线精度。

技术方案与关键模块

LLM 先提议交叉特征；多种重要性度量混合与多目标 Pareto 前沿；Researcher Agent 在试验历史上提出 greed/explore/evolution/recipe 变体；确定性 trainer/evaluator 真正运行实验；Trimming 在类别内重选已存在特征确保共享成本。

训练方法 / Loss / 学习过程

使用线上模型原有监督标签，以 normalized entropy (NE) 作离线效果；Agent 不是直接梯度训练主模型，而是每模型10—25次异步调参，4—8个并行槽，目标 min NE subject to FLOPs/QPS/内存约束。

推理与 Serving 方案

上线保持原排序模型 Serving；新特征配置在部署前逐项校验资源约束；新增已有上游共享特征的边际 pipeline 成本接近零，减少全局重复计算。

实验设置与对照

7个高影响生产模型做预算内搜索、6个模型做Trimming对照，并报告多次真实 launches 和线上 A/B；举例展示25次试验的 NE–QPS Pareto frontier。

离线指标与结果

线上 A/B 证据

研究背景 / 业务动机

TIGER 系列用 Semantic ID 做统一编码，但 ID 变长虽然量化误差降低，decoder 延迟、显存和排序质量未必改善。

现有核心问题

传统 GR 在前向解码每个 token，ID 长度变大带来二次复杂度与误差传播；单纯增加 code depth 不能保证召回排序精度单调。

技术方案与关键模块

用户侧 encoder 与 scoring 在连续向量空间，Item 侧以端到端 Residual Quantizer 得到 M层残差码；通过 additive error decomposition、pairwise-order bound 解释量化失真对真实排序的影响。

推理与 Serving 方案

Item 库存量化 code，在线可截取前 L 层动态调整码长/内存与匹配精度；不走生成式自回归逐 code 采样。实际大规模 ANN 候选构建与倒排接口需要另验证。

Amazon Toys、Beauty、Sports和Yelp 四个5-core基准，和 SASRec、TIGER、LETTER、RPG、VQ-Rec等对比；Stage1+Stage2 在单RTX5090上约18+19分钟。

R@10：Toys 0.1037、Beauty 0.0995、Sports 0.0613、Yelp 0.0640；Toys相比RPG 0.0869提升约19%；单模型码长 L=4/8/16 的 R@10 单调提升。

线上 A/B 证据

无生产线上 A/B；测试仅公开推荐数据。

效率 / 成本收益

支持按请求/资源条件裁剪码长度而无需重训，有利于在线预算分层；但算子优化、存储压缩比与真实QPS/P99尚无大型集群数据。

与主流方法的比较

与 TIGER/OneRec 的自回归 Semantic ID 路线不同，LQ 把量化后置为索引表达，缓解随 ID 长度扩展的模型负担；代价是放弃端到端文本自回归 item 生成表达能力。

适用场景及局限

理论的 pairwise bound 并不保证跨域线上 CTR/CVR 提升；大量 cold item、实时增删与码本版本共存未充分检验。

尚未解决的问题与未来研究

持续编码训练可否实时适配热/冷项？不同码长在同一索引的 join/how-to-search？与 Learned index/late-interaction retrieval 的结合。

与主流方法的比较

相较常数beam更细粒度分配算力；相较ABS部分平均性能更优，但尾延迟可能更差；研究只覆盖若干 DiskANN 图和公开集。

研究背景 / 业务动机

用户有跨会话隐性偏好，Agent 只存对话片段就会在每次请求重新推断“为什么选择”，推理冗余且冷启动泛化难。

现有核心问题

传统 flat memory 混杂事实与判断、难维护来源和时间变化；原始事件与归纳偏好无法进行跨用户上下文相似迁移。

技术方案与关键模块

事件图记录时间/因果/语义连接；洞察图聚合LLM抽取的行为 insight，事件既是 insight 间边又支撑置信证据；可投影到关系 embedding 空间作相似条件跨用户迁移。

训练方法 / Loss / 学习过程

通过 LLM extraction 构建洞察并基于事件支持度计分，推理检索 grounded insight；不是统一 CTR end-to-end loss，监督主要来自记忆/问答和生成任务评估。

推理与 Serving 方案

在线先查询 insight graph 而非逐段遍历 episodic memory，减少重推断；实际存储拓扑更新和过期删除需做权重、TTL、隐私边界治理。

实验设置与对照

LongMemEval 信息抽取、LoCoMo 开放问答、LongLaMP 摘要生成和稀疏图用户迁移；比较现有长时记忆方案和基准 Judge。

离线指标与结果

LongMemEval Judge score 相较 SOTA +1.48，LoCoMo +0.93；LongLaMP 5%图稀疏度跨用户 transfer 的 Judge +0.7、ROUGE-L +3。各任务标尺不一不可直接汇总。

线上 A/B 证据

无推荐生产线上 A/B。

效率 / 成本收益

声称洞察直检替代多跳episode读取；未给大用户量图更新写放大、P99吞吐或硬件成本公开部署曲线。

与主流方法的比较

比单层向量记忆多了可溯源的行为结论与跨用户关系，但构图更复杂；在业务召回里需警惕高支持度≠稳定真实偏好。

适用场景及局限

Insight 由 LLM 抽取存在偏差与幻觉，跨用户迁移存在 privacy/分布漂移和虚假相似风险。

尚未解决的问题与未来研究

设计事件证据审计、用户明确纠错、时效衰减和公平性实验；关联真实评价点击/成交标签评测记忆是否改善长期满意度。

对推荐 / 搜索工程与职业技能的启发

用户评价偏好长期记忆可以存“喜欢具体尺码解释/物流细节”洞察，并保留对应曝光-点击-成交事件溯源；每次使用只检索高置信且近期证据。

Generative Popularity Bias｜Generative News Recommendation Reproduces Popularity: A Memorization-Based Analysis

生成式推荐可能因为训练样本中热门标题的字符重复而更容易记住并生成热门内容，分布集中程度高于用户实际点击分布。

研究背景 / 业务动机

推荐生成器以标题为预测token可能把曝光与历史行为偏差写入记忆，导致列表即便优化训练loss，也持续给热门内容更高概率。

现有核心问题

流行度偏差不只是优化目标/样本采样问题，文本串重复与记忆效应会放大目标项频率；需拆解频率→记忆→生成分布三层因果可能路径。

技术方案与关键模块

用约2000万日本新闻会话构造多标题序列，在Llama3 8B instruct上继续训练下一标题生成；测字符串逐字共享前缀、编辑距离相似度、生成标题频率、洛伦兹集中度。

训练方法 / Loss / 学习过程

持续因果语言模型训练 next-title，比较原始训练和探索性 target-level 去重；不是完整 list-level RL，也没有对实际消费转化的端到端训练。

推理与 Serving 方案

服务生成标题再映射物品/去重输出；应在发布前校验有效 itemID、多样性和新颖度并对热门复制做阈值告警。

实验设置与对照

日本 Nikkei Online 约2000万session；以当前真实日志目标标题的分布作为参照，与生成输出做频率和词串记忆相关性分析。

离线指标与结果

生成标题种类 20,689 vs日志后继标题101,026，生成 entropy 7.169 vs参照9.147；生成集中度0.9072 vs参照0.9003。频率-近似记忆相关r≈0.3344，记忆-生成频率相关r≈0.3084。

线上 A/B 证据

无线上 A/B；无法证明实际用户行为导致过滤气泡或长期留存损失。

效率 / 成本收益

去重减小记忆与集中度但同时削减训练样本量且损害准确率，收益不能归因为去重本身；论文未给推理成本。

与主流方法的比较

补充了传统去流行度的频次重加权/探索机制之外的模型记忆角度；但标题生成与真实大规模Item ID列表推荐的工作机制有差异。

适用场景及局限

相关系数中等且非因果结论；目标字符串长短、模型参数、训练语料分布、产品曝光策略均可能混杂。

尚未解决的问题与未来研究

探索反事实曝光样本重加权、跨时序新鲜度、tail item校准与生成式输出去流行度；分析样本质量不降低的频次平衡训练。

对推荐 / 搜索工程与职业技能的启发

评价生成式重排的样本和Reward需分组监测高曝光评价重复率、长尾有效覆盖与满意度；即使整体成交提升，也要检查是否只是热门评价被反复复制。
