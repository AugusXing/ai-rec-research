研究背景 / 业务动机

金融研究 Agent 往往让一个大模型完成查询、计算与解释；评价推荐链路的 Generator / Reward / Judge 也容易同源互相验证，形成自证循环。

现有问题

语言模型可能错误计算比例、把旧行情当实时价格，最危险的是 writer 与 validator 使用同一条被污染的证据，引用和计算看似自洽但结果仍错误。

技术方案与关键模块

使用紧凑 typed-decision 模型 Laya 做路由，数据与市场工具获取财报和行情，Python 执行精确计算，Mistral-7B 撰写带引用回答，代码验证器检查笔记与引用ID，MCP 暴露工具链；强调生成、计算、来源三条责任边界。

训练方法 / Loss

路由模型使用类别监督而非生成式 Reward RL；计算是确定性程序而非 LLM 猜数字。污染上界实验替换单条证据，测同源验证与独立原文验证的差别。

推理与 Serving

Serving 应隔离 evidence ingestion、writer 与独立 audit read；记录每条来源的文档版本、日期、实体、原文片段。注意原型中部分 SEC/XBRL 接入仍在进行中，不能当作成熟线上生产系统。

实验设置与对照

包括路由分类任务、100道财务计算、50道 SEC 证据检索题，以及 FinRank 共享证据受污染测试；比较 Laya、Mistral-7B、R1-8B 和同源/原文校验器。

离线结果与指标

Laya 路由 0.85 对 Mistral-7B 的0.52；Mistral 数值正确率29/100对Python 100/100；Hybrid retrieval Hit@5为76%。污染实验中准确率0.50→0时一致率仍0.55→0.59，同源验证错误发现率35%，独立原文验证77%。

线上 A/B 证据

没有推荐生产流量随机 A/B。文中的 live 是实时数据环境/实验，并不代表线上转化证明；实际案例中错误公司映射答案依然通过校验。

效率 / 成本收益

小型路由器和可复用 Python 计算减少不必要大模型推理，R1-8B路由较强但速度约慢9.9倍；论文未给推荐服务P99和端到端GPU成本。

与主流方法优劣势

相较 LLM-as-Judge 自评，原始证据独立回读可查出共享证据错位；但 validator 本身只能检查可验证规则，无法消除源头实体映射错误。

适用场景与局限

适合 RAG 引证、商业报告、评价内容真实性审计与 Reward 样本复核；小样本、金融特定流程、部分组件未打通限制了工业泛化。

尚未解决的问题 / 未来研究

设计被篡改 item ID、评价对象和订单标签的反事实污染测试；分别测共源Judge、独立Judge、原始日志规则的错判，并量化误判在成交/满意度优化中的代价。

对推荐与搜索算法工程的启发

商品评价 List Reward 训练应从真实曝光、订单、满意度原始事实另建独立审核路径。首先解决样本证据可信度与Generator-Reward的相关误差，再投入复杂 RL。

Active Feature Acquisition by Distilling an Oracle Teacher

推荐场景中的在线LLM语义、跨域行为与图片特征提取具有IO和时延成本，是否每个候选都要获取所有特征是值得优化的策略问题。

Research Impact Score / 研究价值：81/100工业成熟度：65/100创新性：90/100与你方向的相关度：98/100是否官方开源：未核验论文专属公开代码是否有线上 A/B：无阅读优先级：S+

Impact非官方评分，六维按范式25%、工业证据20%、技术创新20%、相关度15%、研究空间10%、开源可复现10%加权；各分项为主观研判：87 / 65 / 90 / 98 / 94 / 45。

研究背景 / 业务动机

推荐场景中的在线LLM语义、跨域行为与图片特征提取具有IO和时延成本，是否每个候选都要获取所有特征是值得优化的策略问题。

现有问题

传统 Active Feature Acquisition 用自建 utility surrogate 联合优化，teacher 含糊且不清楚特权信息能否在部署时被可观测状态恢复。

技术方案与关键模块

训练阶段拥有真标签、全部尚未获取的特征值，计算每个下一特征对下游错误的潜在下降作为闭式 myopic oracle；部署学生只输入已读特征及mask，逐步选择下一特征。

训练方法 / Loss

OracleImitator 从 oracle action 排序蒸馏 soft target，随机mask条件下用soft-KL训练。标签与未观测特征只供训练teacher，不可泄漏到在线student。

推理与 Serving

请求开始以便宜特征预测，学生决定读取哪一个高成本模态；采集之后更新mask，在预算到期/边际收益不够时停止。线上需并行预取、特征超时回退与隐私成本约束。

实验设置与对照

多模态医学诊断和AFABench合计6个数据集，比较专门的AFA utility learners，按不同cost budget绘制预测效果曲线，还度量oracle排序被student恢复的程度。

离线结果与指标

医学队列中在不到四分之一获取成本下恢复全部特征可获得增益的90%，是该任务特定离线 accuracy–cost 结果，不是推荐GMV改善。

线上 A/B 证据

无线上推荐随机 A/B；应以同一流量 cohort 评估评价 List Reward、P99、QPS、不同消费分层的特征读取率。

效率 / 成本收益

减少特征IO可以节省近线计算，但每步决策、RPC和缓存会消耗延迟；离线cost定义未直接等价于工业生产综合成本。

与主流方法优劣势

与全局特征选择Agent不同，OracleImitator优化单请求的逐步feature获取；优势是监督teacher显式，弱点是myopic teacher忽略特征组合。

适用场景与局限

可迁移至粗排、文本评价/图像证据检索、辅助跨域语义加载；若训练时无法获取完整的特权信息，教师将出现监督偏差。

尚未解决的问题 / 未来研究

做固定topK、feature gate、teacher蒸馏对照，检查缺失机制与曝光选择偏差；进一步研究联合取两个特征的非加性收益和异步多步决策。

对推荐与搜索算法工程的启发

评价生成式重排可先用标签完备的昂贵Teacher选关键属性/证据，再蒸馏成低延迟student；要学会可观测性约束下的策略学习与预算管理。

LSP-RAG: Latent Scoring Perspectives for Knowledge Graph Retrieval-Augmented Generation

KG-RAG 中局部相关三元组未必构成完整的多跳证据，电商评论检索也存在单句相关但缺少互补证据链的问题。

Research Impact Score / 研究价值：84/100工业成熟度：66/100创新性：89/100与你方向的相关度：91/100是否官方开源：是（作者仓库已核验）是否有线上 A/B：无阅读优先级：S

Impact非官方评分，六维按范式25%、工业证据20%、技术创新20%、相关度15%、研究空间10%、开源可复现10%加权；各分项为主观研判：84 / 66 / 89 / 91 / 90 / 93。

研究背景 / 业务动机

KG-RAG 中局部相关三元组未必构成完整的多跳证据，电商评论检索也存在单句相关但缺少互补证据链的问题。

现有问题

大LLM逐步挑选图邻居过贵，轻量模型单相似度得分又忽略角色差异、跨跳上下文和推理一致性。

技术方案与关键模块

每个候选三元组由K个 perspective-specific soft prompts 形成不同的潜在打分视角；contextual soft prompt 将 query 与已选 path 编码以在多跳间携带状态；聚合多视角得分选择扩展边。

训练方法 / Loss

冻结Flan-T5-3B、LLaMA2/3底座，只训练soft prompts、投影和aggregation；Adam lr=1e-4、batch20、5 epochs，默认视角K=3。

推理与 Serving

推理限制最多H=1或2跳、每跳M=20 triples；要管理图邻接索引、实体映射、hop beam与P99，作者未公布推荐服务延迟。

实验设置与对照

WebQSP、WikiMovies、MetaQA 1-hop/2-hop；5个种子，retrieval-free、ChatGPT-guided及轻量KG检索对照，两个soft prompt分量的消融。

离线结果与指标

Flan-T5-3B WebQSP accuracy为88.59%；LLaMA3-8B WebQSP 76.63%、WikiMovies 98.33%、MetaQA-2hop 94.99%。去掉perspective prompt使LLaMA3 WebQSP降至68.62%；均为实体问答离线正确率。

线上 A/B 证据

无推荐线上 A/B，QA accuracy不能证明商品评价列表提高了成交或满意度。

效率 / 成本收益

冻结底座降低训练参数，但多视角候选打分与图扩展仍有开销；实验用4×A100 80GB，并无工业级 QPS/成本曲线。

与主流方法优劣势

比纯embedding能使用多跳结构，比大型Agent每跳搜索的训练参数更轻；反面是依赖图谱覆盖与实体链接，超出领域时不一定稳定。

适用场景与局限

可用于评价属性证据链、商品FAQ和多模态关系检索；不适合直接取代海量商品向量ANN第一层召回。

尚未解决的问题 / 未来研究

研究将视角定义为相关性、证据可信度、属性互补与列表多样性，用同预算对照固定单评分；检测图更新滞后、跨跳自证循环。

对推荐与搜索算法工程的启发

可以将List Reward中的“信息增量”拆成视角打分，为Generator提供软标签；重点观察评价集合属性覆盖而非只看单条点击率。

The Window Lever: Longer Observation Windows Outweigh Data, Capacity, and Architecture

长期用户偏好往往持续数月，算法团队习惯先扩大参数或训练量，但输入窗口的跨度可能先决定模型性能上界。

Research Impact Score / 研究价值：79/100工业成熟度：76/100创新性：77/100与你方向的相关度：95/100是否官方开源：未核验论文专属公开代码是否有线上 A/B：无阅读优先级：S

Impact非官方评分，六维按范式25%、工业证据20%、技术创新20%、相关度15%、研究空间10%、开源可复现10%加权；各分项为主观研判：82 / 76 / 77 / 95 / 91 / 42。

研究背景 / 业务动机

长期用户偏好往往持续数月，算法团队习惯先扩大参数或训练量，但输入窗口的跨度可能先决定模型性能上界。

现有问题

拉长历史窗口既增加信息，又改变用户样本覆盖和日期条件，不能把不同时间跨度下的指标差异直接归因于长记忆。

技术方案与关键模块

将forecast anchor前的8/16/24/32周历史作为实验轴，在同一客户周的matched cohort上比较；同时跨Transformer、GRU、LSTM、GBDT、ridge和单特征模型测量。

训练方法 / Loss

保持训练目标和模型架构，主要改变观测窗口；另外做模型容量、数据规模、时间位置编码、seed及预测目标空间的受控扫描，并注明不足。

推理与 Serving

长序列上线需安排近期原始序列、中期时窗聚合、长期稳定偏好分层，调节KV缓存/离线更新频率，不能无视特征存储和读取成本。

实验设置与对照

内部客户行为预测与5个外部数据集，8类模型family与matched客户测试；读数区分log-space R²和另一raw target recipe。

离线结果与指标

1M级别8→16周的log-space R²提升约+0.070至+0.107；对照数据规模、结构等因素的差距多约一个数量级，另一个raw-target实验从0.648到0.718但指标口径不同。

线上 A/B 证据

没有线上推荐 A/B；研究目标为客户行为预测，不是CTR、CVR和成交评价。

效率 / 成本收益

更长时窗会增加数据ETL/离线特征计算成本，论文未证实超长原始token全注意力可零成本部署。

与主流方法优劣势

与淘宝DNA的动态历史KV互补：前者验证“历史有多远有用”，后者解决“如何高效读取历史”；不能只比较网络深度。

适用场景与局限

作者明确承认无法完全区分窗口与日历覆盖效应，长窗可引入额外冷用户，部分连续时间基线的计时机制不完整。

尚未解决的问题 / 未来研究

设置锚点匹配、季节性平衡、同窗口不同token密度、历史截断/摘要实验；拆清历史跨度增益与模型容量增益。

对推荐与搜索算法工程的启发

评价推荐应先测试7/30/90/180天偏好时间窗，并监控短期成交和长期满意度的相互影响，避免先上复杂Transformer却忽略历史数据质量。

无推荐线上A/B，语言模型val loss提升不是GMV或用户满意度提升。

现有问题

启发式置信阈值反复窥看并更换领先答案，会破坏传统Wald固定假设的错误控制保证。

技术方案与关键模块

将生成候选按最终答案聚类，以reward-weighted self-consistency构造优势，再为每种答案维持e-process/赌注超鞅；当有答案越过置信边界才提前认证。

训练方法 / Loss

无需重训生成器，推理阶段使用数学可验证的停止规则，α限制误认证非占优答案风险；Reward分数改变停止效率而非其理论有效性条件。

推理与 Serving

线上维护每个答案的累计统计、最大采样N与token预算，满足停机条件输出代表性高reward答案；List空间需要定义可验证的等价簇。

实验设置与对照

MATH500等数学任务，多种generator/reward模型，比较固定BoN、自一致性、启发式SPRT和e-RWSC，并观察成本随KL分离度变动。

离线结果与指标

Qwen2.5-3B + ArmoRM 的MATH500提前认证子集准确率94.5%；摘要报告比基线降低token成本并改善准确率。该值不是整体测试正确率。

线上 A/B 证据

没有推荐生产A/B；理论界限针对采样分布里的多数答案，不等于人类点击满意度Reward的准确率。

效率 / 成本收益

平均样本复杂度与log(1/α)/KL(θ∥1/2)正相关：容易请求可早停，分歧大请求需要额外预算。

与主流方法优劣势

比固定BoN更精确分配计算，比普通动态阈值有anytime-valid错误率控制；但在高维排列列表上聚类困难。

适用场景与局限

适用离线候选采样与反事实Reward评估，不宜未经验证直接推成业务在线强化学习策略。

尚未解决的问题 / 未来研究

需要把“多数答案”扩展为“列表效用置信区间”，并对独立Reward模型的系统偏差作稳健校正。

研究背景 / 业务动机

Agent技能一般通过文本说明加入上下文，离散的自然语言提示不便梯度优化且上下文成本高。

现有问题

对单模型的微调提高任务技能却难以跨模型迁移；纯文本Skill难以在多VLM间协同优化。

技术方案与关键模块

冻结视觉语言底座，在图像像素空间反向传播更新一张技能图；多模型联合优化可得到可迁移skill，文本+图像hybrid可叠加。

训练方法 / Loss

优化像素而非底座参数，使用目标任务损失对多个冻结VLM视觉编码器求梯度；属于Agent技能优化而非推荐精排训练。

推理与 Serving

推理把技能图片随prompt附给VLM，论文报告约64–256视觉token而传统文本skill约900–2000文本token；GPU视觉预处理和图像读取时延另测。

实验设置与对照

四个VLM乘四个benchmark共16个设置，对比最先进文本技能优化，以及图像/混合/ensemble方法。

离线结果与指标

16种设置中9种超过文本技能；混合技能还能提升。9/16不是全场景获胜，更不能称为模型参数更新。

线上 A/B 证据

无推荐线上 A/B；研究评估是Agent benchmark任务。

效率 / 成本收益

视觉token更短但不能与文本token等价比较真实成本，且硬件与图像编码器复杂度不同。

与主流方法优劣势

相较prompt搜索可微，相较LoRA更具跨模型可能；然而图片难解释且兼容性、可治理性较弱。

适用场景与局限

适合多模态工具Agent技能压缩；纯文本推荐系统没有直接输入技能PNG的条件。

尚未解决的问题 / 未来研究

建立技能可解释性/鲁棒性评测，排除视觉prompt注入与跨VLM迁移失败，并用版本化注册表控制回滚。

对推荐与搜索算法工程的启发

推荐平台可借鉴参数外可学习技能与跨模型路由的设计，但不要把此方法描述成直接提升CTR的工业方案。
