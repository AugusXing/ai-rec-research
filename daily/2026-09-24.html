8 条工作汇成 6 个持续值得押注的问题

1. 行为统计不是“传统特征”，而是 LLM 的可缺失证据

Spotify 最有价值的点不是简单把 QSS 拼进 prompt，而是用 paired feature dropout 训练模型在“有强行为先验”和“冷启动/统计缺失”两种 regime 下都工作。对推荐/搜索，这比一味追求全特征模型更贴近真实生产流量。

2. Serving 正在 phase-specialize

Disaggregated Quantization 把 prefill 与 decode 分开量化；Flash-dLLM 把 cache refresh 与 verify 联动；HySparse2 重新定义哪些层拥有 KV。统一 runtime 的下一步不是统一策略，而是统一调度不同 specialist path。

3. Test-time compute 从 sampling 走向 policy learning

Beyond Repeated Sampling 把“探索哪个思路”变成小模型可学习的 search policy。对应推荐系统，可以类比成：先用低成本 controller 决定 recall source / candidate budget / reasoning depth，再让昂贵模型执行。

4. 量化误差真正伤的是 trajectory

OPD 与 precision-invariance 两篇论文指向同一个事实：单 token 的小数值扰动会沿自回归轨迹放大。量化评估不能只看单步 KL / perplexity，更应看 trajectory completion、loop rate、exact agreement 与 downstream reward。

5. Agent scaling 的瓶颈从模型能力转到组织协议

Agensh 的结果说明 agent 数可以成为 scaling axis，但收益依赖共享任务板、意图广播、冲突处理与验证/合并协议。真正的研究问题不是“开 1000 个 agent”，而是并行效率与 coordination overhead 的相变点。

6. “硬件友好”正在成为训练目标的一部分

昨天的 expert coactivation 与今天的 OPD / DQ / HySparse2 延续同一方向：训练、架构和 serving 的边界持续消失。模型若不知道部署精度、KV layout 与阶段瓶颈，后处理优化空间会越来越小。

Deep Dive 01 · Personalised Search / LLM Reranking · Spotify

Robust Fusion of Semantic and Behavioural Signals：行为特征可以很强，但模型必须学会在它缺失时继续工作

Research Impact Score / 研究价值 9.6/10 · 工业成熟度 ★★★★★ · 创新性 ★★★★☆ · 与你方向的相关度 ★★★★★ · 是否官方开源 否 · 是否有线上 A/B 是 · 阅读优先级 S+

一句话：Spotify 用 0.6B LLM cross-encoder 把 Semantic ID 与历史行为成功率 QSS 融到同一个 reranker 中，再用 dual-sample feature dropout 防止模型“只会抄行为统计”，从而同时兼顾 warm query 收益与 cold-start 鲁棒性。

背景 / 业务动机

个性化搜索的核心矛盾是：文本语义是可泛化的，但往往不够个性化；历史行为统计很强，却会在新 query、新 item、新地区和分布漂移时缺失或失真。传统做法常把这些特征交给不同模型层处理，导致 semantic representation 与 behavioral prior 很难共同优化。

现有问题

如果把 query-item-country 的历史成功率直接作为强特征，模型会学会依赖它，离线 warm slice 很漂亮，但一旦 QSS 缺失，排序会明显退化；如果完全不用行为统计，则浪费平台最有价值的 interaction signal。真正目标是“有就用、没有也能退化得优雅”。

技术方案与关键模块

模型是约 0.6B 参数的预训练开源 LM cross-encoder。词表加入由平台交互数据学习的 Semantic ID，prompt 同时包含 user country、近期 Semantic ID 序列、query、候选 title/creator/type/SID、popularity 与 QSS（query-item-country 历史成功率）。QSS 被离散成 very_low→very_high 等 bucket，使模型可以像语言 token 一样消费。

核心训练技巧是 dual-sample feature dropout：每个样本生成“有 QSS”和“去掉 QSS”两种视图，联合训练 pointwise binary relevance，输出 Y/N，使用 log p(Y) 排序。这样 ranking loss 同时约束两个 regime。

训练方法

训练仍是普通 SFT / token-level classification 范式，关键超参是两种视图的 loss 权重。论文中 α=0.5 在行为信号利用与缺失鲁棒性之间给出最优折中。它不需要新 reward model，也没有在线 RL，因此迁移到现有 LLM rerank pipeline 的成本相对可控。

推理 / Serving

双样本只发生在训练阶段；线上仍是一次 forward。也就是说，鲁棒性几乎不增加 serving FLOPs。若候选共享 user/query prefix，还可以进一步利用 shared-prefix KV cache。真正新增的是 feature freshness、QSS bucket 计算与 Semantic ID lookup，而不是模型请求次数。

实验设置与离线指标

训练数据约 100 万 sessions、45.2 万 unique queries、5.17 亿 candidates、4615 万 unique items；评估约 1 万 sessions / 514 万 candidates。冷启动 query 约 34.7%，长尾 query 约 97.8%。在 QSS 存在时，NDCG@7 从约 0.549 → 0.622（+13.3%）；在 QSS 去掉时，α=0.5 仍约 0.547，接近 control 0.550，而只训练 feature-present 的版本明显更差。

线上 A/B

Spotify 在真实流量做 A/B/C，QSS-aware 两个 treatment 的 session-level search success 都相对 control 提升约 2%；aggregate 指标暂时不足以把 dual-sample 与 features-only 的差异显著拉开，但 cold-start / missing-feature slice 的方向支持 paired training 的鲁棒性价值。

效率 / 成本收益

主要增量成本在训练数据翻倍，而不是 serving。对大规模搜索，这种 trade-off 很划算：将额外训练吞吐换成在线稳定性，往往比为 cold-start 再维护一套 fallback ranker 更简单。

相对主流方法的优劣

优点：把 Semantic ID、文本、行为统计放入同一 representation；训练期显式模拟 missing feature；不增加在线模型调用。缺点：仍然是 pointwise scorer，没有显式建模候选集合互斥/多样性；QSS 的统计偏差、曝光偏差和 freshness 仍在模型之外。

适用场景 / 局限 / 未解决问题

适合电商搜索、音乐/视频搜索、推荐精排中“历史 CTR/CVR/购买率很强但不稳定”的场景。下一步值得研究：propensity-corrected behavioral token、feature uncertainty token、query coldness gating、以及把 dual-view consistency 扩成多 source / 多 inventory 的 robustness training。

对推荐 / 搜索工程与职业技能的启发

对推荐算法工程师最值得学的是：不要把 LLM feature engineering 理解成“把更多文本塞进 prompt”。未来能力栈会更偏向如何设计行为统计的离散化、缺失机制、因果偏差校正、Semantic ID namespace 与 serving freshness。

Deep Dive 02 · Diffusion LLM Serving

Flash-dLLM：dLLM 真正的敌人不是算力，而是 KV cache 与并行验证叠加后的 HBM I/O

Research Impact Score / 研究价值 9.5/10 · 工业成熟度 ★★★★☆ · 创新性 ★★★★★ · 与你方向的相关度 ★★★★☆ · 是否官方开源 是 · 是否有线上 A/B 否 · 阅读优先级 S+

一句话：把 KV cache kernel 和 draft/verify 分开优化不够；Flash-dLLM 把它们当成一个 IO 系统联合设计，让 dLLM 自己同时承担 drafter 与 verifier。

背景 / 业务动机

Diffusion LLM 可以并行更新多个 token，但每轮反复访问长序列会制造大量 KV 读写。过去方法要么只做 cache，要么只做 parallel decode；两者叠加后，中间 K/V materialization、cache refresh 与 verification 反而成为 HBM 带宽瓶颈。

技术方案

Flash-Cache 融合 QKV projection、RoPE 与 cache write，避免中间 K/V tensor 反复落 HBM；用 block table 支持可变 query length。Selective refresh 只更新 newly decoded token 与固定预算的高影响 token；论文观察到中间层 top-32 attended tokens 可覆盖约一半 attention mass。

Flash-Verify 不引入额外 draft model：模型先根据高置信度产生候选，再将其同时作为 draft view 与 [MASK] view 进行校验；只有二者一致且达到置信阈值才接受，并在首个 rejection 截断。

训练方法

完全 training-free，直接作用于已有 dLLM。这一点对生产部署很重要：不需要重新对齐模型，只需换 runtime / decoding path。

Serving / 系统实现

重点是 kernel fusion、KV ownership 与并行 verify scheduling。RTX 3090 微基准中 fused pipeline 单层约 1.37×；A100 80GB 上，Flash-dLLM 的 cache 与 batch 扩展明显优于此前方法。

实验与指标

在 LLaDA-1.5 上，相对 greedy no-cache 报告 22.3×–148.2× speedup，吞吐约 148–210.6 tok/s；相对此前最强 Elastic-Cache，在 GSM8K-512 与 HumanEval-512 分别 5.1× / 11.0×。batch=16 时显存约 26GB，而 Fast-dLLM 约 50GB；Flash-dLLM 可扩到 batch 32。

质量代价

速度并非免费：例如某些 HumanEval 配置中 confidence-aware baseline accuracy 约 42.07，而 Flash-Verify 约 40.24。真正落地时应联合画 quality–latency Pareto，而不是只看 speedup。

与主流方法比较

相对 autoregressive speculative decoding，dLLM 有天然并行 token 维度；相对普通 cache，Flash-dLLM 更强调 I/O fusion 与 selective refresh。优势是无需小 draft model；不足是高度依赖 dLLM 架构，目前生态、kernel 稳定性和生产 observability 远弱于 AR serving。

适用场景 / 未解决问题

适合代码生成、数学推理等长输出且允许 diffusion decoding 的场景。下一步关键是 continuous batching、prefix cache、multi-tenant KV allocator、长 context 下 refresh policy，以及与 tensor/pipeline parallel 联合优化。

工程 / 职业启发

Serving 能力正在从“会调 vLLM 参数”升级到理解 HBM traffic、fused kernel、cache coherence、acceptance policy。推荐工程中的大规模 embedding join / sequence cache 也具有同类 memory-bound 特征。

Deep Dive 03 · Long Context / Agent Runtime · Xiaomi

HySparse2：把“谁拥有 KV、谁在 prefill 必须执行”变成架构设计问题

Research Impact Score / 研究价值 9.3/10 · 工业成熟度 ★★★★☆ · 创新性 ★★★★★ · 与你方向的相关度 ★★★★☆ · 是否官方开源 未发现官方代码 · 是否有线上 A/B 否 · 阅读优先级 S+

一句话：HySparse2 通过 outer KV Bridging + inner KV Reuse，把 cross-decoder 的 KV 从 self-decoder hidden state 重建，因此 prefill 可提前退出，专门针对“短 action + 超长 tool observation”的 Agent workload。

背景

多轮 Agent 的 workload 很不对称：动作短、工具返回长；每轮新增 observation 都可能触发昂贵 prefill，而长历史又不断膨胀 KV cache。普通 sliding-window 会丢远程证据，全 attention 又撑不起百万 token。

技术方案与模块

Outer level：KV Bridging。 类 YOCO 地拆 self-decoder / cross-decoder，但只桥接 full-attention layer。cross-decoder 的 full-attention KV 由 self-decoder 对应 hidden states 生成，因此 prefill 时可在 self-decoder 后退出，不必运行整个 cross-decoder。

Inner level：KV Reuse。 sparse layer 复用 full-attention layer 的 KV 与选择索引；从 HySparse 的 block-level sparsity 改为 token-level sparsity，并把最近 sliding window 强制并入 top-k selection，去掉独立 SWA branch。

训练

论文基于 80B-A3B MoE，49 层、hidden size 2048；对比模型在相同 data mixture / schedule 下训练，并以轻量 post-training 扩展至 256K context。说明收益并非简单来自额外训练数据。

推理 / Serving

prefill 只走 self-decoder，decode 再使用 cross-decoder；KV cache 使用 MQA 等结构进一步缩减存储。真正的系统价值是把 prefill compute 和 decode capacity 解耦，更容易形成针对 Agent workload 的异构 worker。

实验

长上下文 retrieval 与 agentic tasks 上优于 HySparse / Hybrid SWA；例如 256K 的 RULER-v2 约 58.45 vs 32.61（HySparse）。1M tokens 下，prefill FLOPs 相对 HySparse / Hybrid SWA 分别降低约 2.92× / 5.02×；FP8 KV cache 约 2.69GB，对比 6.72GB / 12.09GB。

效率证据如何解读

论文主要报告理论/统计 FLOPs 与 KV size，而不是端到端 wall-clock prefill latency；且 HySparse2 使用 MQA、baseline 用 GQA，这也贡献了 cache 下降。因此不能直接把 5.02× FLOPs 解释为 5× 服务吞吐。

优势 / 局限

优势是架构原生解决长 context prefill，而不是在 runtime 末端打补丁；token-level sparse retrieval 也比 block 更细。局限是 general benchmark 并非全面占优，强制 local window 在部分任务有损；新架构意味着训练、kernel、checkpoint 和 serving 都要配套改造。

推荐 / 搜索落地启发

推荐长序列同样可以借鉴“prefill 可跳过的 state encoder”思路：把长期行为编码成可复用 state，在线 target-aware 层只在必要阶段执行，而不是每次重算完整 history。

Deep Dive 04 · Quantization / Prefill–Decode Specialization

Disaggregated Quantization：prefill 与 decode 本来就是两种 workload，为什么还要共享一种量化方案？

Research Impact Score / 研究价值 9.2/10 · 工业成熟度 ★★★★☆ · 创新性 ★★★★★ · 与你方向的相关度 ★★★★☆ · 是否官方开源 论文基于 llama.cpp / vLLM，未确认独立官方仓库 · 是否有线上 A/B 否 · 阅读优先级 S

一句话：prefill compute-bound、decode memory-bound，DQ 因此为两个阶段分别选择 precision / weights / storage placement，而不是被“单 checkpoint”这个工程惯性绑住。

背景与问题

prefill 要对长 prompt 做大矩阵计算，低精度 arithmetic 很值钱；decode 每步只处理少量 token，瓶颈常是反复读权重，因此权重体积更关键。传统 PTQ/QAT 为整个模型选择一个量化格式，必然让其中一个阶段妥协。

技术方案

Disaggregated Quantization 允许两阶段有不同 format、weights 和 placement。训练侧用 QADD 让 phase-specific pathway 在一个训练流程中逼近共同 response；可以共享 master weight、使用两套权重，或只训练 prefiller adapter、冻结 decoder。

一个关键观察是：decode-heavy 任务去掉 activation quantization 可以明显恢复精度，而不会像 prefill 那样显著增加计算成本。

Serving：ODP

为了单 GPU 容纳额外 prefiller checkpoint，Offloaded Disaggregated Prefill 从 SSD 按 block 流式载入 prefill weights，复用 device buffer，并用计算覆盖 I/O。长 prompt 越长，权重搬运越容易被 amortize。

实验

在 released Qwen3.8-27B GGUF decoder 上训练 NVFP4 prefiller，1-bit accuracy 在 MMLU-Pro / MMMU-Pro 分别提高 32.5 / 35.3 个百分点，decode checkpoint 不变。27B、8K prompt 在 llama.cpp 上 TTFT 相对 weight-only baseline 提升 1.78×；4K 起开始有收益，16K 以上 offload overhead 可压到约 5% 以下。

工业价值

这比“再发明一种量化格式”更重要，因为它改变部署抽象：checkpoint 不再必然等于一组全阶段权重。未来 P/D disaggregation、heterogeneous GPU 和 model routing 都可以进一步利用 phase-specialized artifact。

局限

额外 checkpoint 增加存储、发布与版本一致性复杂度；论文主要是 batch-1 / 特定硬件评估，多 batch、多租户、multi-turn KV reuse 与 agent traffic 还没有充分验证。多轮场景若缓存 token 的 KV 来自不同 prefill pathway，还需明确兼容性 contract。

推荐 / 搜索启发

同样思路可迁移到推荐：召回与精排即便共享 backbone，也不必共享相同 precision / feature path；“共享 representation + phase-specialized execution”比强制 one-model-one-format 更现实。

Deep Dive 05 · Low-bit Reasoning / Distillation

Train Where the Quantized Model Goes：低比特 reasoning 的核心不是静态误差，而是量化后自己的错误轨迹

Research Impact Score / 研究价值 9.2/10 · 工业成熟度 ★★★☆☆ · 创新性 ★★★★★ · 与你方向的相关度 ★★★★☆ · 是否官方开源 未发现官方代码 · 是否有线上 A/B 否 · 阅读优先级 S

一句话：QAD 只在 teacher/corpus prefix 上教学生，但真正部署时低比特模型会走到自己的错误 prefix；OPD 让量化 student 在线生成，再让 full-precision teacher 在这些 prefix 上纠偏。

背景 / 现有问题

Sub-3-bit QAD 往往能恢复短 QA，却在数学/代码长 reasoning 中出现重复 loop、预算耗尽。论文诊断为 quantization-amplified exposure bias：一次微小 token 偏差改变后续条件分布，量化误差会在长轨迹中累积。

技术方案

先得到稳定的 QAD checkpoint，再进入 On-Policy Distillation：student 使用部署时完全一致的 quantized forward 自己 rollout；冻结的 BF16 teacher 对 student 当前 prefix 给 dense token guidance，同时用 task verifier reward 约束最终答案。也就是说，teacher 不再只讲“标准答案路径”，而是去学生实际犯错的地方教。

训练设置

覆盖 Qwen3 0.6B / 1.7B / 4B 与 Falcon3 1B，effective bits 约 2.79 / 1.88；embedding/output head 4-bit，activation 8-bit。数学阶段约 80–140 steps，代码约 80–150 steps，使用多 rollout 采样。

实验

四个模型平均 MATH-500 BF16 retention 35%→70%，HumanEval 66%→91%。例如 Qwen3-1.7B W2.79，MBPP 35.3→52.0，HumanEval 41.5→59.1；极端 Qwen3-4B W1.88 的 MATH-500 可从约 2.2→36.0，HumanEval 11.0→60.4。

Serving

部署路径仍是原 quantized student，不新增 teacher，因此 inference cost 不增加；代价集中在 post-training rollout。相比继续 teacher-forced QAD，OPD 在 matched training budget 下对长 reasoning 的增益更大。

优势 / 局限

优势：目标与部署分布完全一致；显式优化 trajectory 而不是静态 logits。局限：训练需要 quantized rollout + full-precision teacher，成本不低；verifier 依赖任务可验证性；尚未证明对开放式 agent/tool use 同样有效。

未来方向

把量化误差、tool-call error、retrieval error 统一成 on-policy recovery；动态决定哪些 trajectory segment 需要 teacher；用 uncertainty / repetition detector 触发局部 teacher guidance。

工程 / 职业启发

做模型压缩不能只懂 GPTQ/AWQ 参数，必须懂 post-training data distribution 与 deployment trajectory。这与推荐系统的 exposure bias 完全同构：模型部署后看到的是自己策略造成的数据。

Deep Dive 06 · Reasoning / Search Policy / Model Routing

Beyond Repeated Sampling：小模型不必负责回答，它可以专门学习“往哪里想”

Research Impact Score / 研究价值 9.0/10 · 工业成熟度 ★★★☆☆ · 创新性 ★★★★★ · 与你方向的相关度 ★★★★☆ · 是否官方开源 未发现官方代码 · 是否有线上 A/B 否 · 阅读优先级 S

一句话：把 test-time search 从 token-level 随机性提升到 semantic-level policy——先生成不同概念、提示、策略，再让冻结的大模型沿这些方向回答。

背景

Best-of-N / repeated sampling 的探索来自 token sampling noise，同一个高概率 basin 会被反复采样，所以即使 N 很大，也可能得到大量近重复解法。增加 compute 不等于增加有效搜索宽度。

技术方案

第一步让 concept generator 一次轨迹输出多个 problem-specific concepts / hints / strategies；第二步分别条件化 answer generator。进一步用 RL 训练较小 concept generator，使它最大化冻结大模型的 downstream success。于是 concept generator 成为一个 可复用 search policy。

训练 / 实验

主要配置使用 Qwen2.5-7B-Instruct 作为 concept generator、Qwen2.5-32B-Instruct 作为 answer generator；总 answer rollout budget 128。在 hard DeepMath 上，naive sampling 的 pass@128 约 19.0，而 learned concept policy 可到约 39.2；多 concept 的改进版在同等 128 rollout 预算下从约 22.7→39.8。训练出的 7B policy 还能迁移到不同 family 的更大 answer model。

推理 / Serving

多了一次较小模型的 concept generation，却减少大模型无效重复采样。真正衡量应是“每单位大模型 token / GPU-second 获得的 pass@k 增益”。如果 concept 可批量产生并缓存，对复杂 query 的 economics 可能优于盲目 Best-of-N。

优势 / 局限

优势是把 search policy 与 answer capacity 解耦，可跨模型复用；局限是目前主要证明在可判分 hard math，concept diversity 与真实 utility 的关系仍可能被 benchmark reward 过拟合。

对推荐 / 搜索的直接类比

这是很值得推荐工程师关注的范式：小 controller 负责决定“查什么 / 走哪条召回 / 花多少预算”，大模型只负责重执行。 可映射到 query rewrite、retrieval source routing、candidate budget routing、reasoning rerank depth、甚至精排专家选择。

未来问题

如何学习跨任务通用 search policy；如何加入 latency/cost reward；如何避免 concept collapse；如何让 policy 在 evidence retrieval 与 model routing 之间共同优化。

Deep Dive 07 · Multi-Agent Systems · Microsoft Research

Agensh：当 agent 数扩到 1024，中央 orchestrator 本身会成为系统瓶颈

Research Impact Score / 研究价值 8.8/10 · 工业成熟度 ★★★☆☆ · 创新性 ★★★★☆ · 与你方向的相关度 ★★★☆☆ · 是否官方开源 论文生态出现仓库引用但当前未确认可访问 · 是否有线上 A/B 否 · 阅读优先级 A+

一句话：Agensh 去掉中央任务分配器，让 worker 基于 shared workspace、message interface 与 shared context 自己发现、认领、验证和合并任务，把“组织协议”作为 agent scaling 的核心。

背景 / 问题

多 Agent 可以并行缩短复杂任务 latency，但常见 supervisor architecture 的 orchestrator 要不断分解、调度和汇总；agent 数变大后，中心节点既有 context bottleneck，也有串行决策瓶颈。

技术方案

每个 worker 循环执行：gather context → claim/self-assign task → act/share → verify → merge。基础设施只有三类共享对象：workspace 保存 proposed/ongoing/completed work，message interface 做通信，shared context 保存复用发现与意图。实现中使用 Gitea / Mattermost，并可接 Claude Code 与 Copilot 类 worker。

实验

在 ProgramBench 最难 5 个任务上使用 GPT-5.6-sol（high），固定 6 小时时间预算：1→128 agents，平均最终 test-pass 从 19.31%→28.78%，相对约 +49%，且更多 agent 更早到达同等质量。在 pandoc 单任务上 1→1024 agents，最终 test-pass 33.89%→55.06%。

Serving / 成本

论文证明的是 time-budget frontier，而不是成本效率：1024 个 agent 的 token / tool / sandbox 成本巨大。要落地必须同时报告 parallel efficiency、idle ratio、duplicate work、merge conflicts、LLM tokens 与 wall-clock。

优势 / 局限

优势是移除单点 orchestrator、组织协议可扩展；局限是 benchmark 数量小、成本核算不足，且更大组织可能产生重复劳动与验证风暴。它证明“能 scale”，还没有证明“经济地 scale”。

对搜索 / 推荐的启发

在线推荐当然不会开 1000 agents，但离线 research / feature discovery / experiment analysis 可以使用类似自组织模式。更重要的是，shared workspace 的思路与推荐系统的 shared state + specialist executor 很一致。

Deep Dive 08 · Inference Correctness / Numerical Stability

Greedy Decoding Is Not Precision-Invariant：所谓 deterministic decoding，其实还隐含了 precision contract

Research Impact Score / 研究价值 8.7/10 · 工业成熟度 ★★★★☆ · 创新性 ★★★★☆ · 与你方向的相关度 ★★★☆☆ · 是否官方开源 未发现官方代码 · 是否有线上 A/B 否 · 阅读优先级 A+

一句话：temperature=0 并不等于跨 precision 可复现；当 top-2 logit margin 足够小时，BF16/FP16 的微小方向性扰动会翻转 argmax，并沿自回归轨迹放大。

背景

生产团队常把 greedy decoding 当作确定性基线，用来做 regression test、shadow diff 与模型发布验收。但不同 GPU kernel、precision、量化配置可能让输出分叉，导致“模型没变但答案变了”。

核心发现

在 6 个 1.1B–7B 模型、4 个 family、3 个 benchmark 上，同模型同 prompt 同硬件，只切 BF16 / FP16 就有 49–100% prompt 的最终输出发生 divergence。误差传播分析发现，关键并不是累计 body error 的绝对大小，而是 top-2 logit margin 与定向 perturbation 的相对关系。

干预方法

最有效的低开销方案是：仅当 top-2 margin 低于阈值时，用 FP32 重新计算 LM head。A10G、batch≤4 的单流推理中 exact agreement 可提升 22–36 个百分点，额外 latency <4%；L4/A100 也有 12–21pp 改善。

反直觉结果

“更多 FP32 就更稳定”不一定成立：更广泛改变 precision 会改变误差方向，反而可能降低与某个 reference path 的 agreement。batch≥8 或 end-to-end FP8 时，body-originated error 占主导，selective head recompute 的收益消失。

工业意义

这对 A/B shadow、离线 replay、模型压缩验收非常关键：应把 precision + kernel + batch regime 写进 reproducibility contract。对推荐模型也一样，极小 score margin 的 top-k 候选会因数值差异发生排序翻转。

局限 / 下一步

论文目标是 cross-precision agreement，不代表某 precision 的输出一定更“正确”。未来更值得做的是 task-aware stability：只在会改变最终 reward / ranking 的 margin 区域花高精度成本。

今天最应该带走的 5 个能力建设方向

  • LLM Rerank + 行为特征融合：会把 CTR/QSS/人群统计做成可缺失、可校准、可离散化的模型输入，而不只是文本 prompt。

  • Learned Routing / Search Policy：从“人工 if-else 路由”升级到用小模型学习 candidate budget、source、reasoning depth 与 model choice。
  • Trajectory-level Evaluation：量化/蒸馏/推理优化不能只看静态 loss，要看 loop、completion、pass@k、agreement 与 downstream reward。
  • Stateful System Design：无论 recommendation、RAG 还是 agents，都在走向 shared state + specialist executor + controller；这是未来几年比单一模型结构更稳定的工程主线。
