背景 / 业务动机

推荐评价的多目标重排和搜索问答都存在查询难度差异：简单查询一步即可，复杂问题需要多轮检索或并行专家。如果对每个请求都套同一个 Agent 工作流，成本过高；固定单轮策略又会漏掉需要分解推理的长尾。

现有问题 / 核心矛盾

传统 Model Router 只在既定执行模式里选择 LLM，无法在“模式选择”和“内部模型调用”之间作联合最优。直接对整个轨迹打一个 GRPO 优势值，无法识别错误来自选错模式还是模式内执行失误，训练早期还可能出现模式坍缩。

技术方案 / 关键模块

一个 Qwen3-4B 路由策略先输出模式，然后以统一 action grammar 调用六个冻结 Worker。单轮模式调用一次，多轮串行调用 2–4 次，Agent 模式通过角色和引用组织最多 8 次调用；Worker 的回答作为上下文，不向策略反传梯度。

训练方法 / Loss 设计

COMET-GRPO 将奖励优势分为跨模式 A_mode=(μ_m−μ)/(σ+ε) 与模式内部 A_inner=(r_i−μ_m)/(σ+ε)，两者相加仍是全轨迹归一化优势，但分别作用于模式选择和具体执行 token。逐步探索先强制覆盖各种模式，随后退火至自由选模式，避免单轮路径垄断训练数据。

推理 / Serving 方案

路由器在请求入口对问题编码并决策调用图；运行时需要追踪 Worker 调用、超时、重试、累计 token 与尾延迟。生产落地可把最昂贵的 Agent 模式设成有预算上限、带回退路径的条件分支，而非单纯根据置信度无约束扩张。

实验设计与离线指标

9 个 benchmark、5 个领域（数学、代码、知识、推理、事实回忆），对比 10 个路由基线与固定模式。平均准确率 61.4%，最强对照约 55.3%，相对提升 11.03%；论文声明 5 个领域全部领先，但这些仍是任务正确率而非电商成交。

消融 / 关键数字

取消 COMET-GRPO 的平均分约 58.8%，取消渐进探索约 55.6%，且自由模式选择发生全部偏向单轮的坍缩。引入成本惩罚后，项目页报告中等惩罚下成本降约 23%、准确率损失约 1 个百分点，更强惩罚约降 61%、准确率损失 3.1 个百分点；不同预算不可横向只比精度。

线上 A/B 与效率 / 成本收益

未见线上 A/B、请求 P99 或真实生产 GPU 成本报告。作者测的是给定 Worker 池、benchmark 与价格假设下的实验代价，生产收益取决于业务流量难度分布及 Worker 并发策略。

与主流方法优劣势

相比静态单轮 Router，可以提升高难问题解法覆盖；相比统一全量 Agent，能节省简单请求的多余调用。代价是新策略训练复杂、路由决策与下游 Worker 分布相互耦合，换一批 Worker 后策略可能失效。

适用场景 / 局限 / 未解决问题

适合分层客服搜索、评价问答、条件性生成式重排、复杂购物咨询；不适合极低延迟、必须一跳完成的主链路直接替换。关键未知是跨平台 Worker 稳定性、费用变化和错误放大、动态超时控制、奖励延迟与曝光偏差。

未来研究方向与工程启发

对评价推荐可将“经典重排 / 小模型列表打分 / 大模型生成 / Agent 校验”视为执行模式，并以 List GMV+满意度−推理成本为带约束奖励。先在离线固定候选上做路径 ablation，再按样本难度分桶灰度；算法工程技能重点是分层 credit assignment、成本敏感 RL、异构 Serving 与可观测链路。

背景 / 业务动机

长会话 Agent 和记忆个性化推荐需要跨多次交互寻找事实、时间约束与关系链。业界常把原始历史变成摘要、图谱、原子事实或可修改记忆，以换取更短提示；但压缩和结构化会改变真实证据分布。

旧方法问题 / 核心矛盾

评价查询与历史记忆一样，不只依赖答案词，还依赖谁说的、发生在哪次交互、原因与转折。把一条原始评价改写为属性标签可能丢掉否定、场景和证据出处；更复杂的记忆写入策略也可能产生永久性的幻觉。

核心方案 / 模块拆解

Raw-RAG 直接保存带时间语境的原始聊天片段，先用稠密向量召回，再用 Reranker 对候选重排序，将 TopK 原文证据交给 LLM 阅读。它有意不引入图编辑、复杂的 memory mutation 或训练一个额外的 Agent Controller。

训练方法 / 样本构造

系统本身不依赖专用 Agent Memory 强化学习，主要复用现成的 Embedding、Reranker 和 Reader；其经验关键在原始片段切分、时间边界、Query 表达、负例与重排质量。工程上应把检索模块与 Reader 评估解耦，以免 Reader 的补全能力掩盖漏召。

推理 / Serving / 缓存

在线典型链路为历史写入→切片索引→Query 向量化→ANN 候选→交叉 Rerank→证据组装→Reader，难点转移到数据规模、隐私授权、向量新鲜度与 TopK 长度。缓存高频查询证据有收益，但需要防止跨用户污染、已删除内容被旧缓存恢复。

实验设置 / 数据证据

覆盖 LoCoMo、LongMemEval、MEME、MemoryAgentBench 四个数据集，以及七组数据集/Reader 设定，Raw-RAG 在 6/7 组优于比较的 Agentic Memory，领先最强比较系统 0.13–5.53 个百分点。跨不同 Reader 使用同一记忆基线有助于识别模型容量干扰。

离线指标 / 消融数字

论文报告 LoCoMo 上按 Reader 不同取得 89.07 和 93.70；MemoryAgentBench 的 Raw-RAG 为 48.32，对照强系统 43.84，相差约 4.48 点。去掉 Reranker 为 44.40；仅用原子事实记忆降至 28.70，Raw-Summary 和扩展图分别约 42.51 与 42.54。TopK 从约 15 扩大到 120 反而可显著变差，说明召回覆盖并非越长越好。

线上 A/B / 成本

没有公开线上 GMV、CTR、用户满意度 A/B。所谓简单指架构复杂度低，不等于零成本：Reranker 与 Reader API 调用可能吞噬收益；需要报告每千次检索价格、context token、P95/P99、证据采样与冷启动。

与主流方法对比

相比 Memory Graph、摘要和写时更新策略，Raw-RAG 的信息损失较少，排错时可回溯原文；弱点是原始历史膨胀、索引冗余、敏感内容清理与跨多文档推理依旧昂贵。不能由当前测试得出“复杂记忆普遍无用”的结论。

适用场景 / 局限

适合商品评价问答、客服历史、长期对话与审计型推荐；对超长重复历史、多模态视频记忆、合规限制强、需要长期抽象推理的任务未必最优。实验仍以问答正确性为主，不等价于成交因果效果。

研究方向 / 技能启发

建议实验矩阵为原始评论片段 vs 属性压缩 vs 混合，固定候选与预算，在信息头/问答检索里测 evidence recall、hard-negative nDCG、答案忠实度、满意度和成交；再讨论摘要生成或可变记忆。关键技能是检索证据归因、Reranker 蒸馏、上下文裁剪与数据治理。

背景 / 动机

搜索、风控与推荐候选检索经常需要 Recall 0.999 以上才能避免漏掉关键候选，但常规 IVF-Flat 要扫描大量倒排簇中的全精度向量；只提高 nprobe 往往使内存带宽和 GPU 计算开销线性膨胀。

现有问题 / 关键假设

HNSW/CAGRA 高吞吐区表现好，但在极高召回尾部容易饱和；PQ 压缩后还要全精度回排才能保证可靠度。Lychee 不承诺全局所有向量的正确 TopK，而是精确复现‘已探测 IVF 列表的全精度 TopK’，这一区分直接决定工程可用性。

关键技术模块

对被探测列表的向量利用列表内部锚点建立距离界，并经低维张量核运算快速证明一部分向量不可能进入当前 TopK；只对未被证伪的少量候选读取并计算完整维度距离，保证已探测子集的排序结果与 Flat 扫描一致。

训练 / 索引构建

不以可学习重排 Loss 为主要创新；离线阶段仍需训练/建立 IVF 粗量化中心、分配列表、选择锚点并构建轻量筛查索引。上线成本应加上构建时间、增量写入与删除、anchor 更新，而非只比较 Query 运行时。

推理 / GPU Serving

流程为 Query→coarse centroid Top nprobe→Tensor Core 批量低维筛查→只读取幸存全精度向量→精确 TopK；适用于 GPU 端较高 nprobe、向量库很大且带宽昂贵的负载。分布式 1B 规模要注意多 GPU 分片和返回合并、跨卡复制开销。

实验设置 / 基线

11 个 100 万到 10 亿规模的数据集，与 10 个 GPU/CPU 索引方案对照。对比时固定 Recall 和探测列表规模，而不是仅拿不同质量等级的检索速度相除，防止把 Recall 降级当性能提升。

离线指标 / 关键结果

在不超过 1 亿向量、nprobe=200 且同召回条件下，相对 cuVS IVF-Flat 快 9.7–117 倍；在 BIGANN-1B、4 GPU、Recall 0.9999 目标下快 44.5 倍。论文强调每个 Query 只读取数百个全精度幸存向量，适合高召回极限区而非所有 ANN 配置。

线上 A/B / 效率与成本

没有公开生产流量上的用户指标、P99、负载突发成本或真实部署账单。上述倍数主要是受控 benchmark 的查询性能；生产系统需要把列表探测、更新、网络、GPU 占用、召回下游质量汇总统计。

与 IVF-PQ/HNSW 优劣

它保留 Flat 子集内精确性、不需要 PQ 引入量化误差，是高 recall 备选；劣势是复杂索引管理、额外筛查逻辑与 GPU 特定优化，低 recall 或 CPU-only 环境可能不如成熟 HNSW。

适用场景 / 限制

背景 / 动机

层级 RAG 在搜索文档树时需要从 k 个 section 中选择 b 个后继续下钻；工业系统常要求输出合法 JSON 或满足特定 grammar，自回归吐出若干 token 导致决策链路小模型也有不可忽略的串行延迟。

核心矛盾

普通 free-form JSON 可能不合法，语法约束解码虽稳定却串行；并行一次预测所有 action 又可能改变依赖前缀的条件概率。论文观察有限动作集的合法未来可以提前编译成一棵浅前缀树。

方案 / 关键模块

把受控动作 grammar 映射为所有可达的前缀状态树；一次根 prompt prefill 后，用带树状 causal mask 的一轮 probe 在 GPU 上批量评估每个合法前缀条件下的下一个动作分布。需要边际化输出顺序的集合 MAP 时加一轮 probe，避免暴力枚举完整解码路径。

训练 / 理论保证

研究侧不再训练新的 Controller；用同一已训练 LLM 的概率分布计算原策略的动作。论文的 prefix-state lemma 在精确算术下说明编译策略和串行策略保持一致，但 BF16 舍入、near-tie 与 kernel 实现会造成实际不一致，应避免写成‘线上完全 bitwise 保真’。

Serving 设计

关键路径从随选择长度增长的 token 步数，改成一个 prefill + 一个树状 probe，生成 token 数为零但仍需 GPU 前向计算、显存放下展开的状态。状态树规模随候选 k 和选取 b 组合增长，因此只适合动作空间受约束、可提前枚举的层级决策。

实验设置与离线质量

作者在 4 组文档互斥拆分、两个 Qwen2.5-Instruct 模型规模及不同设备设置比较串行、优化 chunk 引擎和编译控制；真实动作路径匹配率 84–89%，不匹配案例仪器化定位到浮点临界概率的 near-tie。

时延收益 / 关键数字

控制器延迟较逐 token 串行解码下降约 35–47%；相较理想化 chunked 引擎仍可下降约 6–7%，在另一 H800 配置上方向保持。必须对比同 model、同 grammar、同 prefix tree 大小；不能外推至任意自由格式 LLM 生成。

线上 A/B / 成本

没有生产 A/B、真实总 RAG pipeline E2E P99 或 GPU 多租户调度数据。缩短 controller 局部延迟不一定等比例提高完整搜索体验；如文档抓取与 Reader 生成占主要耗时，收益会被摊薄。

对比主流与局限

优于串行 JSON 约束解码的同步开销，且在理论定义上保持原选择政策；弱点是离散动作空间大时状态爆炸、细粒度浮点差异、动态动作词表变更和复杂工具交互的非封闭状态。

适用场景与未来问题

模型权重存储可能降低，但对每个 token 的 FFN 乘加不一定等比例减少；跨层共享可能改善模型加载与 CPU→GPU 参数搬运，也可能加重路由热点。P99、HBM bandwidth、专家并行和多卡布局要另做 Serving benchmark。

实验设置 / 离线结果

报告以相同激活专家数、专家粒度为主要约束，比对 Vanilla MoE 的损失和下游精度；使用约 6B-A1.6B 的模型配置与约 200B 预训练 token。性能可比时仅需大约 70–80% 的 Expert 数量；不能直接把这个比例宣称为 GPU 推理延迟下降 20–30%。

成本和收益边界

收益属于参数与存储效率，计算节省取决于真实并行配置。论文在固定活跃计算下讨论性能保持，缺乏电商线上交易、请求吞吐、峰值显存与整体 TCO 的统一统计。

线上 A/B 与主流对比

无生产流量 A/B；相比单层 MoE 它有更少冗余参数、参数扩展空间更大，劣势是 expert 热点、跨层通信、故障域和可维护性复杂。量化、蒸馏、层共享可以互补，不应该用单项 benchmark 替代端到端成本预算。

应用场景 / 局限

适合数据中心大模型、多模态生成、较大 Reward Model 与需要频繁加载权重的稀疏模型；小规模精排 DNN 或 GPU 算力瓶颈而非显存瓶颈场景可能并不划算。

未来研究方向

需要跨层专家选择的负载均衡、热缓存调度、量化共享专家、专家替换与持续学习、跨业务域负迁移验证。比较与 MoEZip 的 KV 压缩侧重点不同：一个压存储专家，一个压历史注意力状态。

算法工程启发

推荐侧若尝试共享生成式召回/精排/重排大模型专家，应先分清静态存储、激活 FLOPs、跨卡通信、请求 latency 四个独立约束，并制定离线 accuracy、P99、GPU-hour 和部署回滚的联合评估。

跨论文综合判断：把证据、选择和成本分开建模

研究承接 ①：通用 Dense/RAG 基线（随机负例）→ FormBench 结构相近难负例揭示区分能力缺口 → Raw-RAG 证明原始证据与二阶段 Reranker 仍可形成强系统；下一步需要真值可核验的评价相关性、曝光偏差与 List-level 满意度指标。

研究承接 ②：固定 Execution Mode → RouteWeaver 用分层信用分配选择执行图 → Policy-Exact RAG 编译有限控制动作以压缩推理关键路径；下一步需要将路由质量与可测的 P99/成本目标联合优化。

研究承接 ③：IVF-Flat 暴力距离计算 → Lychee 在已探测列表内认证剔除无效点 → 下一步结合 GPU 筛查与分布式增量索引；MoE 的 Meta Expert 进一步从跨层专家共享挖掘模型加载成本，但别混淆参数节省与时延下降。

现实证据边界：七项研究都是近期论文，不是 10/24–10/25 期间新发表的七篇论文；不能把没有公布的线上 A/B 写成有。部分高价值实验是领域特定 benchmark，其规模、指标、资源可用性应独立审阅。
