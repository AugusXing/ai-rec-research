技术趋势

Stage Boundary 正在被重新训练

过去跨阶段优化通常是 ranking teacher → pre-ranking student；UniRec 让两阶段 fusion 在 shared embedding 上对称耦合，把 cascade consistency 直接写进训练目标。

Historical Execution 变成一等资产

REVA 保存“模型过去看过哪里”，VikingRAG 保存“Agent 过去怎么找到证据”。这与 user/document state reuse 是同一趋势：compute-once、reuse-many，但必须带 compatibility / freshness。

Controller 比另一个 LLM 更重要

GeneralQPP、SWRouter、TimelyRAG 都说明：是否足够、保留哪段历史、哪个版本有效，这些决策可以由低成本统计/embedding/规则化 controller 先解决。

Embedding Storage 进入“生成式解码”

GLIE 不只量化/裁剪 embedding，而是把少量 anchor 当 code，在 top-L 候选上再生完整 late-interaction representation，形成 retrieve cheap / rerank exact 的新设计面。

Deep Dive 01 · Cascaded Recommendation

UniRec：跨阶段推荐的下一步，不是“精排教粗排”，而是让两阶段 fusion 真正联合优化

Research Impact Score / 研究价值 9.5/10工业成熟度 ★★★★★创新性 ★★★★☆与你方向的相关度 ★★★★★是否官方开源 UniRec 代码未确认；RecFlow 数据公开是否有线上 A/B 是阅读优先级 S+

背景 / 业务动机：工业推荐的召回→粗排→精排→重排是为 SLA 被迫切开的。问题是各阶段有不同候选分布、特征、目标与算力预算；粗排一旦把精排真正喜欢的 item 丢掉，后面再强也无法恢复。已有 COPR/Rethink/HCCP 多数把精排信号单向传给粗排，但最终决定候选去留的 multi-task fusion 仍是阶段内独立优化。

技术方案：UniRec 同时训练 pre-ranking fusion agent 与 ranking fusion agent。两者共享部分 input embedding，因此两个 stage 的 loss 都能更新同一表示；粗排用 DCN + 轻量 MLP-Mixer，精排用 DCN + AutoInt-Lite；另有一个 stop-gradient adapter 把粗排表示作为显式特征送入精排。目标函数沿两个轴对齐：vertical cross-stage consistency 把下游 pairwise preference 写回上游 fusion score；horizontal CPPA 把几十个任务的成对目标压成双向 preference evidence，使可微项从 O(MN²) 降到 O(N²)；AGRR 在属性 group 内做相对优势，抑制模型通过偏爱高 reward 属性区间“作弊”。

训练 / Serving：训练时在同一 computation graph 联合优化；Serving 时两个 agent 仍按原 cascade 分别导出，shared embedding table 复制到各阶段，因此论文明确指出联合训练本身不增加在线 Serving latency。这是工业价值非常高的一点：训练改造大，线上拓扑改造小。

实验：公开 RecFlow 含约 42K users、9.3M requests、38M exposure samples、1.9B stage-level records，候选规模 8000→3000→500→100→10→6；工业数据还覆盖 1M+ request-level samples。RecFlow 上 UniRec ranking NDCG@10/30/50 = 0.0990/0.1870/0.2409，pre-ranking NDCG@10/30/50 = 0.0993/0.1892/0.2429；cross-stage ASH=0.9978、Kendall τ=0.6318、Spearman ρ=0.8072，均为表中最好。

线上 A/B：一周、20% 随机线上流量；相对生产 fusion baseline：LT7 +0.142%、ActiveUsers +0.189%、AppUsageTime +0.616%、TotalWatchTime +0.675%、VideoWatchTime +0.755%、LongView +1.028%、Like +2.367%、Follow +1.573%、Collect +1.890%，论文报告无下降指标，随后全量部署。

优势 / 局限：优势是把“stage consistency”从 teacher-student regularizer 提升成 joint optimization，并兼顾 multi-objective fusion 的计算复杂度与 attribute bias。局限是目前只覆盖 pre-ranking + ranking fusion，未把 recall 与 rerank 纳入；共享表示也会增加训练耦合、实验归因与版本管理复杂度。

工程启发：对现有粗排/精排体系，最现实的路线不是一上来做 one-model full-stack，而是先找真正决定每阶段最终排序的 fusion / calibration layer作为联合优化切口；指标也不要只看单阶段 AUC，要显式建立 ASH / top-K survival / pair consistency。

Deep Dive 02 · RAG Serving

REVA：把“每次 query 都压缩一次”改成“历史 attention 形成可复用 evidence view”

Research Impact Score / 研究价值 9.1/10工业成熟度 ★★★★☆创新性 ★★★★☆与你方向的相关度 ★★★★★是否官方开源 是是否有线上 A/B 否阅读优先级 S

现有问题：RAG context compressor 往往逐 query 调一个 auxiliary model 或做重写，压缩后 token 少了，但 compressor latency 可能把收益吃掉；论文还观察到 advanced compressor 对简单 truncation 的收益并不稳定。与此同时，85%～92% query 至少命中一个历史见过的 document，说明 document-level reuse 空间很大。

方案：离线/异步读取目标 generator 自己的 attention trace，把 query/response token 到 document token 的 attention 聚合成 word-unit importance；对日期、数字、连字符、专名等做 protected span；再按 document 建立 budget-agnostic score store。在线只做 lookup、quota allocation、排序选择和原顺序文本渲染，不运行当前 query 的 compressor/attention pass。

关键工程设计：compatibility key 包含 document text key、generator、tokenizer、prompt template、scoring mode、corpus version，避免“旧证据分数”在模型/模板/语料变化后被误复用。每个 word unit 主要存 score sum + count，16-bit 下约 4 bytes；113K HotpotQA query 的 score store 约 1GB。未覆盖 document 自动 fallback 到 prefix truncation。

结果：四个 benchmark 上相对先进压缩器 generation quality 提升 1.0～5.8 points；compression overhead 降低 5.3～15.6×，在线额外延迟 <40ms。mixed any-seen 设置也稳定优于 local truncation，例如 NQ F1/EM 33.68/22.56 → 38.12/25.23。

适用 / 局限：特别适合高复用知识库、客服、内部文档、热门 SKU/政策文档。冷文档、快速变更 corpus 与 generator upgrade 会降低 coverage；attention 不是完美 causal attribution，因此它更像可复用 prior 而不是 ground-truth evidence selector。

研究方向：把 REVA 与 KV reuse、document-side reranker state、freshness TTL、online click/answer feedback 联合起来，形成统一 evidence asset store。

Deep Dive 03 · Structured / Agentic RAG

VikingRAG：把 Agent 的“找路经验”写回检索系统，只有证据不足时才升级到多轮 Agent

Research Impact Score / 研究价值 9.0/10工业成熟度 ★★★★☆创新性 ★★★★★与你方向的相关度 ★★★★★是否官方开源 是是否有线上 A/B 否阅读优先级 S

背景：企业文档的目录、章节、段落结构本身就是检索信号。DeepRead 类结构化 Agent RAG 能提高准确率，却需要多轮 Search/List/Grep/Read，prompt 与历史轨迹不断膨胀。

VikingRAG：先构建 hierarchical semantic storage，Agent 只观察局部 search result、目录片段、lexical hit 与主动 Read 的对象；retrieval 按 evidence gap 逐轮继续，而非把全局目录一次塞进上下文。

Experience Edge：一次成功多轮检索后，把 source URI → target evidence URI 的路径与历史 query 表示物化成有向 edge。新 query 先普通 vector search，再仅在历史 query 与当前 query 相似度超过阈值时沿 experience edge 做多跳扩张，相当于把昂贵的 Agent path 编译成可复用检索资产。

Adaptive Escalation：先尝试一轮 experience-augmented retrieval；constraint-aware evidence adequacy checker 判断证据足够则直接回答，只有不足才升级到 agentic multi-round。相比 VikingRAG-E，E+ 平均只用其 49.8%～81.1% tokens、73.1%～89.8% latency。

实验：6 个结构化文档数据集，格式含 PDF/Markdown/DOCX/TXT，最大 corpus 8.78M tokens；对比 MoDora、BookRAG、DeepRead、KohakuRAG、LightRAG、HippoRAG-2、SQL-AgenticRAG、NaiveRAG。基础 VikingRAG 在保持强准确率时只消耗 SOTA 的 11.6%～51.9% tokens；加入 experience reuse + escalation 后为 5.1%～32.5%。

局限：experience edge 会陈旧，需要删除/更新与反向索引维护；相似 query 不等于同一证据路径；adequacy checker 的 false positive 比 false negative 更危险。未来值得做 edge confidence、TTL、versioned corpus 与 traffic-aware experience distillation。

Deep Dive 04 · Retrieval Sufficiency / Control Plane

Your Retriever Already Knows：RAG 是否“检索够了”，可能不需要再问一个 LLM

Research Impact Score / 研究价值 8.9/10工业成熟度 ★★★★☆创新性 ★★★★☆与你方向的相关度 ★★★★★是否官方开源 是（代码+数据）是否有线上 A/B 否阅读优先级 S

问题：RAG 最危险的状态不是“没答案”，而是 retrieval 已失败但系统不知道，于是 generator 仍自信输出。作者受捷克核监管机构 SÚJB 的私有部署场景驱动，比较 score-based QPP、本地 LLM judge 与 hybrid。

GeneralQPP：完全不读 document content，只从 retrieval score profile 与 query surface 提取 24 个 non-lexical features：15 个 distribution-shape（top gap、decay、skewness、bimodality、concentration、elbow 等）、5 个 query surface、4 个 global score range。它本质上预测的是“这条 score curve 看起来像成功检索还是失败检索”。

结果：ViDoRe 8 个视觉检索域、14,514 queries：weighted AUROC=0.856，2ms/query；Classic QPP pool 0.835，本地 Qwen3.5 judge 0.649，GeneralQPP 高 +0.207 且约快/便宜 3000×。SÚJB production-motivated case 含 1,510 synthetic queries；hybrid 在 Hit@5 AUROC 0.911、adversarial detection 0.954。S1-Lean 在 leave-one-domain-out 上用 13 features 恢复到 0.719。

Serving 意义：这类 confidence signal 可以直接驱动 top-K 扩大、dense→hybrid fallback、是否调用 reranker、是否升级到 Agent / web search，甚至决定拒答。最值得注意的是：LLM judge 更适合当 feature，而不是默认作为 standalone controller。

局限：SÚJB 没有真实用户日志，使用合成 query；结论针对当前 local multimodal judge 与 modest target supervision，不能泛化成“所有 LLM judge 都差”。

Deep Dive 05 · Model Routing

SWRouter：多轮模型路由的瓶颈，往往先是“给 Router 看什么历史”

Research Impact Score / 研究价值 8.8/10工业成熟度 ★★★☆☆创新性 ★★★★☆与你方向的相关度 ★★★★☆是否官方开源 未确认是否有线上 A/B 否阅读优先级 A+

核心问题：单轮 router 只需 query→model，但多轮对话里当前 query 可能依赖旧 turn，也可能已经换话题。全历史拼接带来 information confusion，只看当前 turn 又 information loss。

方法：先用 embedding cosine similarity 对连续 turn 做 window segmentation：相似度低于阈值就开启新 window，否则累加为语义连续上下文。router 再对 context-enhanced prompt 做 model selection。训练同时使用 sample-LLM contrastive loss（拉近 query 与强候选模型 embedding）和 sample-sample contrastive loss（保持语义 cluster）。

评估：作者特别把 prompt construction accuracy、evaluation accuracy、router performance 拆开，避免把“上下文构造更好”误算成“router 模型更好”。ShareGPT + MT-Bench 上最佳 individual LLM 平均 24.63%，Conv-ID Context 32.67%，SWRouter 40.89%；阈值 τ=0.91 最好，说明性能对 segmentation policy 很敏感。

Serving：推理只需 window construction + 单次 router forward + 被选 LLM；论文报告 similarity calculation 只占总推理时间极小比例。对 recommendation/search 更一般的启发是：routing policy 与 context construction 不应分开设计，否则 router 学到的是被 prompt builder 污染后的问题。

局限：最优阈值可能 domain-specific；局部连续相似不保证长程事实依赖；真实 routing 还要加入 cost、latency、privacy、tool availability 与 cache affinity。

Deep Dive 06 · Retrieval Storage

GLIE：late-interaction embedding 不一定要“存全量”，可以把少量向量当成生成代码

Research Impact Score / 研究价值 8.8/10工业成熟度 ★★★☆☆创新性 ★★★★★与你方向的相关度 ★★★★★是否官方开源 是是否有线上 A/B 否阅读优先级 A+

背景：ColPali 一类 visual document late-interaction 方法每页约存 1000 个 vectors，检索质量高但 storage 太重。传统 pooling / subset compression 在极小预算下掉点明显。

关键观察：这些 token vectors 精确落在 unit sphere 上，并集中在 intrinsic dimension 约 5～6 的低维 manifold。标准 k-means centroid 落在球内，会系统性低估 MaxSim；仅把 centroid 重新 normalize 到球面就最多 +0.093 nDCG@5。

GLIE：每页只存 k≪N 个 refined anchor vectors。索引阶段 encoder 冻结，小型 cross-attention refiner 从 normalized centroids 出发；共享 decoder 可把 k 个 code 重建成 N 个 unit vectors。线上 Stage 1 对全库只算 k-vector MaxSim；Stage 2 仅对 top-L（默认 20）候选解码回 full vectors 并精确重排。

训练：refiner + decoder 共约 415K 参数；以 per-query-token MaxSim matching、listwise KL 与 geometry-related losses 训练，不以 reconstruction error 为主要目标。论文的核心思想是“保持检索 decision，而非像素式还原 embedding”。

结果：4 vectors/page 时保留近 80% uncompressed nDCG@5，而最佳 prior post-hoc 约 70%；模型在 1000 training pages 上不足 3 GPU-minutes 即可拟合。官方 repo 还报告对 ViDoRe v1 10/10 subsets、v2 4/4 subsets 各预算均优于既有 post-hoc baseline。

局限 / 未来：decoder 仍有明显 oracle gap；适合组合 quantization，因为“少存 vectors”和“每个 vector 少 bits”是正交维度。视频、多页文档、超大 token set 可能是更高价值场景。

Deep Dive 07 · Temporal Retrieval

TimelyRAG：当旧版与新版 90% 文本都一样，语义相似度本身无法回答“哪个版本现在有效”

Research Impact Score / 研究价值 8.7/10工业成熟度 ★★★☆☆创新性 ★★★★☆与你方向的相关度 ★★★★★是否官方开源 是（代码+Benchmark）是否有线上 A/B 否阅读优先级 A+

问题定义：法律、政策、学校规章、Terms of Service 不是“新快照完全替代旧文档”，而是 amendment 只改少数 clause，版本间高度语义重叠。普通 dense/sparse retrieval 很容易把内容相近但时间无效的旧 clause 排前面。

方法：TimelyRAG 是 retriever-agnostic 两阶段框架：第一阶段用 BM25/dense/late-interaction 拿 top-N；第二阶段把 semantic score 与 temporal compatibility 融合。时间信号拆成 Query Insert Time、Query Event Time、Document Insert Time、Document Event Time；若 query event time 落在 clause validity interval 内则时间距离为 0，否则按最近边界惩罚，并有 causality constraint 防止“未来文档回答过去问题”。α(Q) 依据 query 是否有显式事件时间与 granularity 自适应调整时间权重。

Benchmark：TimelyQABench 覆盖 law、university、company policy、terms of service 四类 regulation-heavy domain，共 12,000 synthetic QA；版本被刻意设计为高语义重叠 hard negatives，并用 GPT-4o、Claude-3.7-Sonnet、Qwen2.5-72B 多模型验证。

结果：不同 backbone retriever 上最高 +28.6% nDCG@10、+19.1% Hit@10。它的工程价值不是替换第一阶段，而是作为轻量 temporal reranker 插入已有检索链路。

局限：benchmark 主要是合成法规数据；现实中的 effective date 解析、retroactive clause、timezone、版本冲突与文档 provenance 更复杂。第一阶段没召回正确版本时，第二阶段无法恢复。

今日收束：对推荐 / 搜索工程与职业技能的启发

1）跨阶段优化会成为推荐系统的重要主线：不只是蒸馏，而是 joint training、shared state、stage consistency metric、Serving decoupling。
2）“可复用资产”正在扩张：从 embedding / KV cache 到 evidence score、agent retrieval trace、temporal metadata；算法工程师需要同时懂 model 与 state lifecycle。
3）控制面比单一大模型能力更值钱：retrieval sufficiency、context window、model router、temporal validity、escalation 都是独立可优化 controller。
4）检索压缩要盯最终 decision：GLIE、昨天的 decision-aware quantization 都说明，未来 embedding 系统应围绕 top-k / MaxSim / prune decision 设计，而不只是 MSE。
