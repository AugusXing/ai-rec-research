生成式推荐进入交易闭环：多目标 Token 蒸馏、隐空间重排与工业级 Serving

10 篇一手研究 / 技术报告。最有分量的证据集中在淘天拍立淘多模态生成式检索、Refiner 精排残差推理、KL-MOPD 多目标策略蒸馏；辅以 REGER 的 SID 偏好结构、AutoRSE 的算法工程 Agent 评测及 LinkedIn/eBay 生产基础设施。

今日核心结论：生成式推荐不再只讨论“生成得出物品”，而开始明确分拆 业务目标如何监督每步生成、隐空间如何修正候选预测、成本预算如何决定执行路径、哪些工作有真实线上 A/B。建议以 PailitaoMMSearch2.0 → Refiner → KL-MOPD 为主线，并用 REGER / LinkedIn Scoring 研究你的评价列表 Reward 和 Generator 一致性。

最值得读 · 四个趋势

① 真实业务 A/B 终于更多

拍立淘 2.0：商品详情 PV +17.90%、交易笔数 +27.04%、GMV +8.94%；Refiner：PV-CTR +0.75%、GMV +0.46%；KL-MOPD：广告收入 +1.63%、GMV +2.20%。这三者分别对应候选生成、候选精修、多目标监督，口径不可横向简单比较。

② Teacher → Generator 的 token 化

REGER 把判别式商品概率投影为 SID 合法前缀上的下一 token 条件分布；KL-MOPD 再针对每个位置动态分配双教师权重。两篇形成“监督投影 / 优化加权”的清晰接力。

③ 推理加计算要有收益曲线

Refiner 在分数空间修正而非文本 CoT；拍立淘证明 2B Low-think 在精度/延迟上可能优于更大的 High-think。增加推理步骤不必然有效。

④ 生产优化并不都靠大模型

LinkedIn prefill-only Multiple-Item Scoring 使 Serving 吞吐 1.9×；eBay 无损压缩 HNSW 图边减少 44.3% 内存。工程创新需要与模型创新分开评估。

PailitaoMMSearch2.0 · PailitaoMMSearch2.0: Scaling Generative Retrieval to Unified End-to-End Multimodal Search

一句话核心结论：把“生成商品 SID”从特定相似图搜升级为相似 / 编辑 / 搭配三意图共用的端到端检索，价值来自训练数据生产、RL 与线上 Serving 三者一致，而非单纯放大模型。

背景 / 业务动机

图搜用户可能需要“找同款”“换颜色/属性”或“为这件衣服搭配短裤”。传统相似向量召回/改写+排序分别建模，意图路由与业务监督耦合，冷启新意图缺乏真实点击数据。

现有问题与核心矛盾

共享 SID 不能自动解释检索关系：同图像下同款、属性编辑与互补搭配的目标彼此冲突；若只按旧入口行为训练，新意图和尾部要求会漏；长链思考又与大流量延迟冲突。

技术方案与关键模块

以原始图片 I、文字指令 Q 和可选上下文 C 输入原生 VLM；商品使用三级 SID、每级 8192 个码，直接 beam decode 合法商品。Data Scaling 通过 Coarse-Filter→Fine-Filter→Query-Text-Gen→可选 CoT-Gen→Quality-Control 的组合工具链覆盖冷启、真实流量精修和持续生产；Intent Scaling 共用模型，Scenario Scaling 在模型规模、思考预算和 beam 宽度上寻找质量—延迟帕累托点。

训练方法 / Loss / 数据构建

CPT 联训商品标题、属性、SID、用户行为及通用语料；混合 No/Low/High-think 的多意图 SFT；RL 对各意图的 Good/Excellent 质量均衡优化。Sample–Beam rollout：采样 reasoning trajectory，但商品 SID 走与线上多候选一致的 beam 解码，减少训练动作和线上输出形态不一致。

推理 / Serving / 上线接口

一次 VLM 请求直接返回最终商品列表；既可做原生端到端检索，也可与已有召排链路的候选在末端交织。论文 2B Low-think 配置单 GPU 平均 278ms；0.8B No-think 136ms，但后者质量弱；不能把平均延迟等同 P99。

实验设置与 Baseline

相似、属性编辑、搭配三种意图，自动评审在独立人工标注集上校准；比较专用召排流水线、通用大模型及 0.8/2/4B 版本，并做 CPT、SFT、RL 和预算消融。

离线指标 / 原文关键数字

2B Low-think：macro NDCG 0.918，Excellent Rate 55.1%，均时 278ms；相对 SFT，标准 RL Macro ER 49.03%→52.70%，加入 Sample–Beam 后至 55.00%（总 +5.97pp）。注意旧召排在“相似/编辑”某些 ER 切片仍更强。

真实线上 A/B / 证据等级

拍立淘多模态搜索 A/B：约 10% 分流、约 14 天，商品详情 PV +17.90%，订单数 +27.04%，GMV +8.94%，CTR +0.58pp，CVR +0.37pp，文中报告 p<0.05；测试的是完整系统，不能归因到某单一模块。

效率与成本收益

容量不是越大越好：2B Low-think 与 4B High-think 的质量接近而平均延迟约 278ms vs 1133ms；任务简单时 High-think 未必收益，生产需按难度建立 budget policy。

与主流方法的优势、代价

相对 CLIP 检索+意图 router，最大优势是端到端学习“检索关系”；代价是 SID 目录更新、beam 有效性、训练数据构造及黑箱 Judge 偏差。与旧版 Pailitao-MMSearch 有传承，但新论文是多意图、多场景统一化，跨版本线上提升不能直接相减。

适用场景

可迁移到图片评价、商品评价列表、搭配购物、多模态评论问答：把用户最终意图、可接受编辑与互补关系显式融入样本。

局限与尚未解决的问题

训练与评估都含自动评审器，可能存在同源偏差；全链路 A/B 未提供逐模块增益；SID 更新、未见过商品、不同流量入口迁移与评价满意度指标仍未彻底回答。

未来研究方向

让生成器同时接收静态物品语义与动态商品更新；将业务 Reward、质量评审和交付候选合法性联合对齐；验证 Query adaptive reasoning / Beam budget 的 P95/P99。

推荐搜索工程落地与职业技能启发

评价列表可拆“找事实证据/补互补视角/纠正单一观点”三种列表意图，用可组合工具链生产高质量 Reward 样本；在交易+满意度双目标下先做离线配对、曝光校正，再设计在线实验。

Refiner · Latent Residual Reasoning for Ranking in Generative Recommendation

一句话核心结论：不是让生成模型输出一段思维链，而是在非文本隐藏空间让“每步修改候选分数”变成可监督动作，可能是复杂精排与列表 Reward 更实用的推理形态。
Research Impact Score / 研究价值9.0/10（本站按六维权重评估）
工业成熟度高：工业离线数据与 1% 流量线上 A/B
创新性高：连续隐空间逐步残差修分+History Queries+冻结主干 LoRA
与你方向的相关度极高：评价候选多任务打分、List Reward 估计
是否官方开源未核验官方代码仓库
是否有线上 A/B有：7 天 A/B，PV-CTR +0.75%、UV-CTCVR +0.21%、GMV +0.46%
阅读优先级S+

背景 / 业务动机

工业排序要同时处理多候选、多任务（点击与成交）、用户长历史；单次输出未必能完成细粒度比较；文本 CoT 推理逐字生成太慢且不适配 ID-based Ranker。

现有问题与核心矛盾

传统一次候选 scoring 无显式修错轨迹；简单增加 latent reasoning token 不能保证每步对最终分数有帮助，且上线训练通常不能频繁重训全量大基座。

技术方案与关键模块

先用 MTGR 等生成式 Ranker 产生 K×T 初始分数，候选之间采用特殊 attention mask 阻止候选互泄漏；在用户历史前引入可学习 History Query，得到紧凑用户状态；每个 reasoning step 用隐变量产生 residual ΔS_r，累计 S_r=S_0+ΣΔS_t。主干冻结，附加 LoRA 和 reasoning head。

训练方法 / Loss / 数据构建

基座用 CTR/CTCVR 的 BCE；Refiner 保留基座原分数，训练每一步累计预测对标签的 MSE，L_reasoning=Σ_r MSE(S_r,Y)，即每步都受“剩余误差”约束。工业应结合 ranking/calibration loss 对概率边界和稀疏正例稳定性额外评估。

推理 / Serving / 上线接口

工业以单步 refinement 控制延迟；每日冻结当天更新的 MTGR checkpoint，仅在 Refiner 增量参数上训练，使用前一日 Refiner 热启动，避免离线训练/线上模型版本漂移。论文未披露统一 P99 成本，需单独实测。

实验设置与 Baseline

Steam、MovieLens10M，工业 CTR/CTCVR 数据；对比 xDeepFM、DIN、SASRec-ranking、MTGR 与 ReaRec，消融 history query、残差、推理步数和不同用户群。

离线指标 / 原文关键数字

Steam MTGR AUC 0.7698→0.7872、GAUC 0.7397→0.7594；工业 CTR AUC 0.7404→0.7417，CTCVR AUC 0.8553→0.8574；每步延长在离线存在质量—延迟权衡。

真实线上 A/B / 证据等级

1% 生产流量、每天百万级曝光，7 天 warm-up 后连续 7 天实验：PV-CTR +0.75%、UV-CTR +0.12%、UV-CTCVR +0.21%、订单数 +0.19%、GMV +0.46%；论文未给所有指标置信区间，不能自行推断显著性。

效率与成本收益

相比全模型 SFT，仅增训 LoRA/heads；额外 latency 随 refinement depth 增大。在线只选一步，并未证明多步始终性价比更好。

与主流方法的优势、代价

相对经典 DIN/DeepFM 主要增加候选关联用户状态的推理能力；相对文字 CoT 无逐 token 文本解码；相对 ReaRec 可对每步累计分数直接监督。局限是额外 MSE 与真实排序业务目标仍有差异。

适用场景

已经有强候选级精排/重排 Base Ranker 的系统；尤其适合高价值、长历史、难区分近似候选，而不建议在高 QPS 低预算链路无条件叠加多步。

局限与尚未解决的问题

候选交互 mask、基座形态存在依赖；跨业务指标不保证泛化；MSE 直接回归标签可能带来不准校准；线上深度固定为 1。

未来研究方向

按候选不确定度/组内冲突自适应停止；从 Pointwise MSE 走向 Listwise 交易+满意度 Reward 的 residual update；用 IPS/DR 修正曝光偏差。

推荐搜索工程落地与职业技能启发

最小实验：冻结现有评价 List-level Reward 或候选多任务模型，在相同曝光 List 上增加 1-2 步 residual head；对成交、满意度、校准、NDCG、P99 同时做增益成本曲线，避免只优化 RMSE。

KL-MOPD · Discrepancy-Aware Multi-Objective On-Policy Distillation for Generative Recommendation

一句话核心结论：双目标蒸馏不能只在 item/list 终点相加：SID 解码每个 token 都是一个截断风险点，权重应随当前 token 的 student–teacher gap 变化。

背景 / 业务动机

广告和推荐必须兼顾点击、交易价值与体验；Generator 一旦在 SID 的某个早期 token 偏向一个教师，另一目标的优秀物品可能永久退出 beam，事后重排无从补救。

现有问题与核心矛盾

Vanilla Multi-Objective On-Policy Distillation 对所有 token 固定教师融合系数，但 token 层难度不平衡、哪个教师更难学又沿路径变化，造成局部不对齐和多目标目标漏召。

技术方案与关键模块

先训练点击教师和价值教师，固定初始学生 π_θ0；对每个生成步 t 和教师 j 计算 KL(teacher_j || student_init) 表征初始蒸馏难度，据此定权 α_j,t。后续 rollout 用学生分布采样序列，对各 teacher 的 token 分布进行加权 KL 对齐；从 item-level 多目标移动到 prefix-level 多目标。

训练方法 / Loss / 数据构建

L_KL-MOPD≈E_{y~πstudent}[Σ_t Σ_j α_{j,t} KL(πstudent(.|prefix_t)||πteacher_j(.|prefix_t))]；符号是工程示意，精确 KL 方向和规范化以论文公式为准。核心创新是一次预校准 token 权重，而非每轮追踪梯度/动态更新教师权重。

推理 / Serving / 上线接口

训练期多教师，在线仍只运行单个学生 Generator + 原有 SID beam；不强制增加额外教师 Serve。需要确认预校准权重在数据更新、SID tokenizer 迭代后是否失效。

实验设置与 Baseline

公开数据 3 组，TIGER 和 REG4Rec 两类 backbone；工业广告数据超 10 亿交互、约 4900 万用户、1.58 亿广告；离线 Top100/Top200 的 click/value/joint utility，5 天线上 A/B。

离线指标 / 原文关键数字

公开 benchmark 联合目标相对最强对照平均 +4.12%；工业 u_cv@100 MOPD 0.3139→KL-MOPD 0.3236，@200 0.3548→0.3665，平均 +3.19%。

真实线上 A/B / 证据等级

工业广告随机 A/B，10% control +10% treatment、5 天，广告收入 +1.63%、GMV +2.20%，论文报告 p<0.05；无评价满意度指标，也不是任何单独内容重排的直接线上证据。

效率与成本收益

α 只在训练前计算一次，训练循环相对 MOPD 几乎无额外动态权重计算；但教师分布计算/存储与 token 对齐依然有成本；线上保持单模型 Serve。

与主流方法的优势、代价

相比简单 click/value 加权 loss，可处理多 token 阶段性瓶颈；相比动态 TrustMOPD 不需要逐轮复杂权重优化；代价是初始化差距可能不代表训练中后期梯度需要，且默认双目标加和不等于帕累托约束。

适用场景

商品生成式召回、CTR+CVR 双目标；可类比“成交概率+评价满意度”的 List Generator，但须区分 SID token 和评价 ID/List token 的分布。

局限与尚未解决的问题

理论结论依赖可加目标和特定假设，线下/线上基线为论文自己配置；静态 α 对偏好漂移和多于两目标的扩展需检验。

未来研究方向

推荐搜索工程落地与职业技能启发

将生成式评价重排的两个 Reward teacher（成交、满意度）分别蒸馏到不同的列表生成位置；除 List reward 外记录 prefix survival、各位置教师 KL、类型覆盖及重复率，对比固定 α、动态 α 和预校准 KL α。

研究工作流而非线上推荐 Serving；实现需要 GPU 预算控制、运行日志、沙箱、参数可追溯、验证集隔离和失败回滚，绝不可直接自动合入生产排序策略。

实验设置与 Baseline

3 个前沿 LLM ×3 类 harness（受适配限制共 7 个组合），六任务；每任务三次独立运行，单 H200/16vCPU/32GB、12 小时上限。

离线指标 / 原文关键数字

5/6 任务出现基座改进，平均相对提升 16.1%；在 HSTU 案例 idea-injected 0.0674→0.0831（+23.29%），而 self-generated ideas 仅 0.0681（+1.04%）；这是特定对照设置，非全任务通用增幅。

真实线上 A/B / 证据等级

无线上随机 A/B；只验证研究代理对离线推荐任务的改进，不代表可安全自动推送线上。

效率与成本收益

工程成本来自 LLM 调用和 12h GPU trial；论文没有给和真人算法团队相同约束下的完整人效 ROI，应用时需记录每获得 1bp lift 的总 GPU/工程小时。

与主流方法的优势、代价

比 AutoML 更会读代码/实现复杂思路；比人工专家更擅长大规模试错；但缺少可靠创新假设生成、合理因果分解和跨流量泛化。

适用场景

用于有稳定 offline evaluator、明确实验预算、可复现实验脚本的推荐小组；可让 Agent 执行候选假设而保留人来决定研究方向。

局限与尚未解决的问题

隐藏测试标签有助公平，但离线指标仍可能奖励投机；模型/harness 版本更新快，Leaderboard 有漂移风险；真正创新分数包含主观评估。

未来研究方向

加入 failure analysis→结构化 Idea Library、Reward Model 诊断、多实验 Bayesian 资源分配、论文跨场景转移以及受控线上审核。

推荐搜索工程落地与职业技能启发

团队可建设“评价生成式重排 AutoRSE”沙箱：固定曝光 List、成交满意度校准与 A/B 归因约束，由人给出 Reward/数据质量假设，让 Agent 自动实现 Loss/消融与离线报表，不允许自动改线上的 Reward 定义。

LinkedIn Semantic Scoring · From Generation to Scoring: Scaling LLM-Based Semantic Labeling at LinkedIn

一句话核心结论：大量独立 YES/NO 标签决策不该通过生成一个长列表完成：把任务改成一个候选一次判别的 prefill-only score，再通过 masked attention 打包 MIS，可以同时减少顺序依赖和 Serving 成本。
Research Impact Score / 研究价值8.4/10（本站按六维权重评估）
工业成熟度高：LinkedIn 生产标签打分，Serving 性能已验证
创新性中高：prefill-only answer-token scoring 与 Multiple-Item Scoring

是否有线上 A/B无：生产吞吐对照，非用户行为随机 A/B
阅读优先级S+

背景 / 业务动机

工业标签生成器经常“一个实体+几百候选标签”打包进 prompt，要逐个生成 Yes/No，输出顺序、格式错误和逐 token decode 都让吞吐与可靠性变差。

现有问题与核心矛盾

在每个标签判别本应条件独立时，packed generation 使不同候选答案相互影响，且多个标签还共享后续文本状态。

技术方案与关键模块

训练时单 candidate prompt，用 answer token（YES/NO）的 logit 作为分数，推理只 prefill 不输出长序列；MIS 将很多 candidate 和公共上下文放同一序列，同时用 Attention Mask 禁止标签候选间彼此关注，防止序列顺序污染。

训练方法 / Loss / 数据构建

基于单候选判断标签的监督进行微调，正负标签 token 的 logit/概率作为独立评分；加入候选互不可见 mask 保证多候选 batch 与单候选近似一致。论文未将它称为端到端推荐交易 loss。

推理 / Serving / 上线接口

Offline Ray Data API 将 MIS 变成可复用批推理算子；线上 SGLang 对 MIS 作专门支持；在 p99 <1 秒约束下，论文报告整体吞吐 1.9×。

实验设置与 Baseline

LinkedIn 个人资料资格标注，比较多标签一次生成与单候选 semantic scoring，做候选顺序置换和参考标签一致性评价，离线吞吐与线上服务吞吐独立测试。

离线指标 / 原文关键数字

候选重排只改变最多 0.01% 决策；达到同等标签一致性时打包生成需约 4.7× 训练 pair；MIS 线下吞吐 1.24×，Serving 吞吐 1.9×（同 p99 一秒约束）。

真实线上 A/B / 证据等级

已在生产标签系统部署，但论文没有报告随机用户 CTR/CVR A/B；吞吐改进不能等价于成交增长。

效率与成本收益

主要省掉 list decode，并通过 packed attention 共享公共上下文；在候选很少时 mask 编排和 padding 开销可能不值得，需压测每批候选量的拐点。

与主流方法的优势、代价

相比 Text Generation 的优势是分数可排序、可校准、顺序更稳定；相比常规 Cross Encoder 每候选单独 forward，MIS 提升共享计算效率；代价是不能天然建模跨候选依赖，必要时要后接 Listwise 层。

适用场景

评价文本的质量标签、信息性、是否覆盖尺码/物流、候选槽位满意度以及作为 List Reward 的候选级中间评价器。

局限与尚未解决的问题

只测独立标签任务，不能把 Masked MIS 用于需要候选之间多样性、去重与位次竞争的最终评价 List 直接替代。

未来研究方向

从独立标签 semantic scoring + Listwise Set Aggregator 组合，搭配不确定性分桶、动态路由至更大模型、线上 Reward 质量诊断。

推荐搜索工程落地与职业技能启发

将评价内容多维属性（客观性/可信度/价格相关/图文对应）从 LLM 长文本审核改为 masked batched scoring；人工复核难例，最后把候选特征输入真正的 List-level Reward，做 QPS/P99/标注一致性联合评估。

eBay HNSW Compression · Lossless Compression of Proximity Graph Indexes for Efficient Approximate Nearest Neighbors Search

一句话核心结论：向量压缩以后 HNSW 的边邻接列表常成为内存大头；对图节点离线置换制造局部连续性，可用快速整数解码同时省内存且维持搜索性能。
Research Impact Score / 研究价值8.5/10（本站按六维权重评估）
工业成熟度高：eBay 自 2025 年生产部署，论文报告 edge memory -44.3%
创新性中高：节点离线重排 + SIMD Stream VByte 无损编码
与你方向的相关度高：超大规模相似评价/商品向量索引成本
是否官方开源官方 kANNolo 代码与论文复现实验仓库链接可核验

背景 / 业务动机

商品和评价 embedding 规模大时，量化 vectors 已较成熟，但每层 HNSW 邻接 ID 的内存仍可能推高热数据成本和 NUMA 访存。

现有问题与核心矛盾

在线 HNSW 每次路由都需要快速访问邻接边，若一般压缩比高但解码慢，会直接放大搜索尾延迟和服务成本。

技术方案与关键模块

预处理图的 vertex permutation 增强相邻节点 ID 局部性；对邻接表排序/差分，然后用 SIMD-friendly Stream VByte 等整数编码；访问邻接时快速解压后仍维持原图边信息，因此称 lossless graph encoding。

训练方法 / Loss / 数据构建

不是学习模型，无训练 Loss；主要优化图 permutation、bit-packing、compression ratio 与 ANN traversal latency 的工程组合目标。

推理 / Serving / 上线接口

索引构建时重排 ID 与引用，查询时 decode 邻接 list 并遍历，必须检查 mmap、cache locality、更新图/增量建图和兼容 HNSW 当前服务版本。

实验设置与 Baseline

图像、Dense/Sparse 文本、商品 embedding 四类公开数据与 eBay 生产 HNSW；比较多种可直接随机访问邻接表的压缩与吞吐配置。

离线指标 / 原文关键数字

离线图边存储最多可缩至约 52.7% 压缩比例（注意与“节省 52.7%”不是同一句）；生产报告边存储减少 44.3%，在同 Recall 和在线负载下没有测到延迟退化。

真实线上 A/B / 证据等级

是已部署的 eBay 生产索引压缩观测，不是商品点击或收入随机 A/B；不应标“有线上 A/B”。

效率与成本收益

资源收益直观：多租户节点能装更多 vector graph，减少峰值内存/缓存开销；但预构建重排、增量插入和索引迁移有额外维护成本。

与主流方法的优势、代价

传统 PQ/SQ 压的是向量，本文压的是图边；相对字典/entropy coding，SIMD 简单整数 codec 牺牲一点极致比率换搜索路径速度。

适用场景

评价向量 ANN、文本混合召回、商品多模态 index；尤其是 graph edge memory 明显超过 vector memory 的配置。

局限与尚未解决的问题

对动态图高频 add/delete 的效果、跨不同 M/efSearch 配置和数据中心多机真实延迟尾部需要额外测试。

未来研究方向

构建增量友好的 permutation、分片级 graph codec、边结构与 vector quantization 联合预算分配。

推荐搜索工程落地与职业技能启发

给评价检索集群做 graph memory profiling，拆 vector bytes vs edge bytes；在相同 Recall@K/P99/QPS 和更新吞吐下 A/B 对比编码前后内存节省，不做业务价值泛化。

CEP / SCI · When Connectivity Misleads: Guiding Agentic Search with Contrastive Evidence Paths

一句话核心结论：多跳图检索里高连接度文档常被 PPR 推高，但它不一定支持答案；将最强证据路径与背景随机游走概率对比，可减少“高连接度假相关”的上下文污染。
Research Impact Score / 研究价值8.0/10（本站按六维权重评估）
工业成熟度中：BrowseComp-Plus、TREC-COVID 离线 Agent benchmark

背景 / 业务动机

Agent 会在跨文档图中展开来源，工具调用有预算，选错热门 hub 文档会把真正证据挤出观察窗口。

现有问题与核心矛盾

PPR 等扩散给大量连接的节点累积高分，且打平了“为什么从某证据连接到这个候选”的路径结构。

技术方案与关键模块

Contrastive Evidence Paths：记录 query-conditioned graph 到候选的 strongest path score，并以同图 background visitation distribution 校准对比，修正结构性 hub 偏置；Structured Corpus Interaction 将候选及其来源路径呈现在可查询地图中，Agent 可回访 anchor、扩展缺失证据。

训练方法 / Loss / 数据构建

核心是查询时证据路径排序与图访问对比校准，而不是另训一个端到端 Reward；Agent 搜索策略使用选出的可解释路径进行下一步工具选择。

推理 / Serving / 上线接口

需要构建/维护链接图、记录路径 lineage，并对节点展开设置预算；图传播和路径保持增加 CPU/IO，实际线上 P99 依赖图规模和增量更新速度。

实验设置与 Baseline

BrowseComp-Plus 与 TREC-COVID，回答正确率、nDCG@10、Gold Recall、Agent 工具调用数与总生成成本，多基线包括图扩散。

离线指标 / 原文关键数字

论文摘要称相对最佳任务对照，工具调用最大减少超过 50%、总生成成本最大减少超过 40%；“最大”指特定设置，不能理解为所有任务平均节省。

真实线上 A/B / 证据等级

没有用户业务线上 A/B；仅 Agentic Search benchmark 与成本模拟。

效率与成本收益

省 token/工具调用，但路径打分有前处理与图索引成本；成本指标应分 Retriever 图计算与 LLM 生成两部分报告。

与主流方法的优势、代价

相对静态检索 Ranker 多一层可追溯 Evidence Graph，适合多跳；相对简单 PageRank 能消除 hub 偏置；但需要高质量图边与 query-specific path seed。

适用场景

评价 RAG 中基于用户问题检索跨评论事实链，例如“续航差是否只在某版本发生”；可尝试把评论间引用/同款变体关系作为图。

局限与尚未解决的问题

图的错误连接会影响 strongest-path；证据路径评分不直接等于人类满意度与交易效益；成本数据没有真实电商线上验证。

未来研究方向

List-level evidence utility、实时路径去偏、图/文本混排与对曝光/商品热度的联合校准。

推荐搜索工程落地与职业技能启发

对评价检索设置“热门评价 hub 负例”，比较 BM25+dense、PPR 和 CEP 路径校准，观察最终证据覆盖、页面满意度和工具 token 成本，再让生成式重排消化证据列表。
