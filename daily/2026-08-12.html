01 · Sona Technical Report

Yandex Music · Generative Recommendation

一个共享 User Encoder 的生成式模型，在真实线上实验中开始直接替换 15+ Candidate Generators + Pre-ranking + Ranking。

背景与问题

成熟工业推荐通常由多路召回、粗排、精排构成，不同阶段重复学习用户表示，并积累大量特征与系统复杂度。Sona 试图统一 Candidate Generation 与 Ranking。

技术方案

核心由 Shared User Encoder、Semantic-ID Generative Decoder、Ranking Module 构成；Item Semantic ID 同时利用内容与协同行为；长历史通过 History Compression 建模；Ranker 使用当前 Generator rollout 的候选进行 Teacher Distillation。

效果

线上指标相对提升
Active Users+4.53%
Total Listening Time+6.30%
Likes+11.42%

以上为 Yandex 作者报告的线上 A/B 结果。

局限与未来

Catalog Coverage 仍低于传统 Cascade；尚未 Full Traffic；未来重点包括 Exploration、RL、MoE、Sparse/Linear Attention、Persistent KV Cache 与 Test-time Scaling。

02 · Context Interference for Search Agents

Retriever 找到了正确资料，不代表 LLM 能正确使用；Context Quality 正在成为 Search Agent 的新瓶颈。

方案：Retriever 与 Reasoner 之间加入 Context Refiner，只保留当前 Query 真正需要的 Evidence；进一步把 Refinement 放进 RL rollout，形成 CRRL。

效果：作者在多项 QA Benchmark 上报告准确率提升，同时平均 Retrieval 次数明显下降。

工程启发：未来搜索系统可能从 Document Ranking 继续演化出独立的 Evidence / Context Ranking 层。

03 · TimeRoute

多模态推荐不应使用固定 Fusion Weight，而应根据“用户 × 时间”动态选择模态。

Time-aware Modal Router 为不同用户生成动态模态分布，并通过 Diffusion-based Graph Reconstructor 在传播前抑制过时模态。公开数据集上有较好离线提升，但尚无线上 A/B。

04 · NVIDIA Nemotron 3.5 Lightning

Agent 开始形成“强模型规划、小模型执行”的模型级 Cascade。

30B 总参数、约 3B active parameters 的 MoE，定位 tool call、validation、delegation 等高频执行任务。其意义更接近 Agent Serving 分层，而不是单纯模型榜单竞争。

05 · NeMo Switchyard

Model Routing 正在成为 Agent Infra 的独立一层。

根据任务难度、质量、成本、Latency 与 Agent State 在 Small / Frontier / Specialized Models 间动态路由。对推荐工程师而言，它本质上非常像一个新的 Ranker / Policy 问题。
