周末系统深挖：
Adaptive Retrieval、RAG KV Cache、Model Routing 与 Coverage Audit

今天最值得关注的不是“又多了几个模型名字”，而是一组非常工程化的共同问题：检索到底要读多深、Context 到底缓存到多细、什么时候值得上大模型、Agent 如何维护跨轮证据状态，以及推荐系统该怎样评估“没被推荐的人/物”。这些工作都在把 AI 系统从固定 Pipeline 推向 request-aware 的动态执行。

时间口径说明：今天是周六，arXiv 官方长期采用工作日公告机制（官方年报说明 submissions are announced five days a week），因此过去 24 小时没有新的周末公告批次。今天不把旧论文伪装成“刚发布”，而是从最近一批尚未在本站深挖的工作中，补齐对 Retrieval / RAG Serving / Model Routing / Recommendation Evaluation 最有长期价值的 6 篇。论文的 v1 提交时间均在下文明确标注。

今日核心结论

  • Retrieval depth 正从超参数变成运行时状态。EAHR 不再固定 Dense/Sparse 各取 Top-L，而是根据当前 Query 的排名边界决定要继续读多少候选，并且保持 complete-list RRF 的精确 Top-K。
  • RAG 的“上下文压缩”开始进入 KV Cache 粒度。CoinRAG 不是只压文本，而是识别细粒度 information nuggets，直接复用这些片段的离线 KV 表示，把 relevance 与 prefill cost 绑到一起优化。
  • Model Routing 的关键不是 Router 多聪明，而是失败是否可预测。Pre-Inference Routing 给出一个很实用的判断：便宜模型必须“有足够失败空间”，而且失败要能被廉价特征提前识别，否则 Routing 只会增加复杂度。
  • Agentic Retrieval 正从“反复 Search”走向“维护 Belief State”。DocMemo 用 Bayesian belief、Thompson sampling 和跨轮 memory 让证据选择变成动态探索问题，这和推荐里的 exploration / bandit 思想越来越接近。
  • 推荐质量不能只看被召回集合上的排序。餐饮 AI 推荐的 census audit 显示，真正的大问题可能是 entry/coverage 与数据陈旧，而不是 hallucination；音乐 GenRec 的实验也提醒我们，表示模型在分类上的强弱并不直接等价于推荐价值。

重点论文 01 · Hybrid Retrieval / RAG Serving · v1 2026-08-07

Exact Adaptive Hybrid Retrieval Without Fixed Top-L Cutoffs

Chunran Zhang · Dense + Sparse Retrieval · Exact weighted RRF · Adaptive Execution

EAHR 最重要的观点是：Hybrid Retrieval 的“每路取多少候选”不应该是离线调好的常量，而应该是当前请求的执行状态。它把一个看起来像工程超参的问题，重新定义成“为了保证最终 Top-K 精确，需要继续读取多少排名”的算法问题。

1. 背景：固定 Top-L 为什么会悄悄改变你定义的 Ranker

常见 Hybrid Search 会让 Dense Retriever 与 BM25/Sparse Retriever 各自返回 Top-L，再用 RRF 或 weighted RRF 融合。工程上通常把 L 视为速度/效果旋钮，但这里有一个被忽略的问题：如果真正想优化的是“完整两条排名列表上的 weighted RRF Top-K”，截断后把未读项贡献视为 0，得到的其实已经是另一个 Ranking Function。更麻烦的是，Query 分布或 Corpus 更新后，历史上合适的 L 未必继续有效。

2. 核心方案：Exact Result 固定，Execution Depth 自适应

EAHR 反过来定义目标：最终输出必须与 complete-list weighted RRF 的有序 Top-K 完全一致，然后让系统按需扩展两路排名。Dense 侧用可恢复的 exact ranking 机制 PVS，Sparse 侧用 PBM；Fusion 过程中持续维护“尚未读取部分还能贡献多少分”的上界。如果这个上界已经不可能改变当前 Top-K，就安全停止；否则继续向相关通道请求更深的 ranks。

Dense ranking↘Bound unseen score→Can Top-K still change?→Stop / Read deeper↗Sparse ranking

3. 实验：快很多，但不承诺每个 Query 都快

证据结果意义
Exactness150 / 150 query-snapshot combinations全部复现 complete-list ordered Top-20
TREC-DL 201923.35×exhaustive batch / EAHR 的 paired geometric-mean latency ratio
TREC-DL 202030.28×同上
Hard / anti-correlated queries可能更慢最坏情况下需要读完两边，论文明确不承诺 per-request speedup

4. 和传统 Top-L 调参相比，真正多了什么

传统做法是“在历史 Query 上找一个 L，使平均效果/延迟不错”；EAHR 是“对每个请求证明当前未读内容已经不可能改变结果”。前者是经验性的静态预算，后者是带正确性条件的动态预算。这个差别对长期运行的 Search/RAG 很重要：Corpus、Embedding Model、用户意图漂移之后，不需要重新相信一个旧 cutoff。

5. 对推荐/搜索的启发

这类思想很容易映射到推荐系统：多路召回源不一定都要固定取 N；粗排不一定每个请求都评相同深度；LLM Re-ranker 也不一定要固定 rerank Top-100。未来更值得做的是 “结果稳定性 bound → 动态计算预算”，而不只是训练一个 Router 猜难度。

6. 局限 / 未解决

  • 需要各通道支持可恢复、可界定的精确 ranking；很多近似 ANN 系统并不能直接套用。
  • 难 Query 可能没有任何加速，甚至付出额外 bound 管理开销。
  • 论文目标是 exact RRF；如果线上目标本身是 learned fusion / neural ranker，如何构造安全 stopping bound 仍是开放问题。

重点论文 02 · RAG × KV Cache · v1 2026-08-07

CoinRAG: Contextualized Information Nugget KV Cache Reuse for Long-Context RAG

Gyuwan Kim · Cheoneum Park · Tao Yang · Long-context RAG / KV Reuse / Prefill Optimization

CoinRAG 把一个很关键但常被分开的目标合在一起：检索到什么 Context 与 这些 Context 要花多少 Prefill Compute。它不是简单“先检索、再压缩”，而是把可复用 KV cache 的粒度直接做成 retrieval 设计的一部分。

1. 现有 Chunk-level KV Reuse 的问题

长上下文 RAG 为降低 prefill 延迟，会预计算并复用 Retrieved Chunk 的 KV 表示。但 Chunk 往往混有大量与当前 Query 无关的信息：即使不用重新 encode，冗余 Token 依然占 KV 容量、Attention 计算和 Context Window。于是“缓存了”并不等于“计算足够细”。

2. 核心设计：Information Nugget 作为缓存与检索的共同最小单元

CoinRAG 通过两阶段 Retrieval，在已检索 Chunk 内进一步识别 Query-relevant 的细粒度 semantic nuggets；这些 nugget 的 KV 表示可以离线预计算并切片复用，同时保留 chunk-level context 以避免把细粒度片段完全去语境化。直观地说：过去是“这整块文档已经缓存，所以全拿进来”，现在变成“只拼当前 Query 真正需要的缓存片段”。

3. 结果：优化的是 Pareto Frontier，而不是单点 F1

实验作者报告
LongBench multi-hop QA在标准 fast-prefill latency budget 下，平均答案 F1 相对提升 5.3%
效率形成新的 accuracy–prefill latency Pareto frontier，并降低 operational cost

4. 为什么这对推荐 Serving 也有价值

LLM 推荐和生成式重排同样会把用户长历史、商品文本、评论、会话 Context 放入 Prompt/Prefix。若将 User History 切成可复用 Interest Nuggets，理论上可以把“长期行为缓存”从整段 Prefix 复用推进到 query/item-aware cache composition。它与 TM20K 的 Token Merge 是两种互补思路：TM20K 在 Student 内压 Token，CoinRAG 则从可复用 KV 单元层面决定什么值得进入计算。

5. 局限 / 下一步

  • 两阶段检索本身也有成本；系统收益依赖 nugget 选择足够便宜且稳定。
  • 离线 KV 的可复用性会受到模型版本、RoPE/position、prefix 组合方式约束。
  • 如何在个性化推荐中维护频繁变化的 User Memory Cache，是比静态文档更难的问题。

重点论文 03 · Model Routing / Cost-aware Serving · v1 2026-08-06

Pre-Inference Routing for Cost-Efficient Document Field Extraction

Sreerekha Rajendran · Cheap/Strong Model Cascade · Predictable Failure · Cost-aware Routing

这篇最实用的地方不是 Router 本身，而是它回答了更前置的问题：你的业务到底值不值得做 Routing？很多团队直接训练复杂 Router，但如果小模型本来就几乎不失败，或失败根本无法提前预测，那么 Routing 注定没有收益。

1. 两个必要条件

  1. Cheap model 必须失败得足够多。如果大多数样本小模型已经能处理，把强模型放在旁边不会省多少。
  2. 失败必须能从廉价、推理前特征预测。例如图像质量、Layout、文本模式。如果只有跑完模型以后才知道难不难，就失去了 pre-inference routing 的意义。

2. 实验结果：不同数据域收益差异巨大

场景成本变化质量约束
Receipts−31% ～ −33%与 always-large 相比，质量差距保持在 0.02 F1 内
Degraded ad-buy forms−77%同上
Clean digital invoices / nutrition labelsRouting 无明显价值Cheap model 已足够强或失败不可预测

论文还验证了两组大小模型，成本差分别约 5× 与 3×。一个很重要的负结果是：Router 必须针对数据集重新训练，即使是同 genre 也不能可靠迁移。简单 Bag-of-Words Router 已能接近 engineered features，说明瓶颈更多在任务可分性而不是 Router 网络结构。

3. 对推荐 / LLM Re-ranking 的直接映射

这几乎就是“是否给某个请求启用昂贵 LLM Reranker”的标准决策框架：先估计 Cheap Ranker 的 failure rate，再看 Query/User/Candidate features 是否能预测这些 failures。只有两者都成立，Model Routing 才值得上线。相比“全量大模型 + 事后蒸馏”，这种 gating 更适合延迟/成本严格的推荐链路。

4. 训练与 Serving

Router 在强/弱模型之前执行，因此必须依赖低成本特征；校准后的路由器按预测困难度选择 extractor。Serving 上最大的优势是无需先运行两个模型再比较 confidence。代价是 Domain Shift 会直接伤害 Router calibration，需要持续回采 label 和重训。

5. 局限

  • 文档抽取和推荐 ranking 的 loss/失败定义不同，推荐里需要把“难度”定义到用户/候选/业务目标层面。
  • Routing policy 目前更像 supervised gating，尚未联合考虑 latency queue、GPU load、价格变化等系统状态。
  • 数据集级不可迁移意味着 Router 本身会变成新的维护对象。

重点论文 04 · Agentic Retrieval / Memory · v1 2026-08-07

DocMemo: Dynamic Evidence Discovery via Probabilistic Memory-Guided Retrieval

Hanshu Yao · Janfeng Zhong · Niu Lian · Jinpeng Wang · Multi-modal Document / Belief Memory / Thompson Sampling

DocMemo 的研究价值在于它不把“多轮检索”理解成简单的 Query Rewrite Loop，而是显式维护一个会变化的 Page Belief Distribution：每轮新证据都会改变下一轮应该探索哪些页面。

1. 为什么固定 Top-k 不够

几百页长文档里，真正证据往往稀疏、跨页、跨模态。单轮 Retrieval 一旦第一步错过关键页，后续 Reader 很难自救；很多 Iterative RAG 虽然会多轮搜，但“上一轮学到了什么”常常只留在对话文本里，没有明确的 relevance state。

2. 三层 Memory

  • Document Schema Memory：保存文档结构先验，知道章节/页面组织。
  • Page Belief Memory：维护每页相关性的动态概率估计。
  • Question Episodic Memory：记录当前 Query 的检索与推理轨迹，避免每轮从零开始。

检索时通过 Bayesian belief updating 更新页面概率，并用 Thompson sampling 在“继续利用高概率页”和“探索可能遗漏页”之间做权衡；还加入 spatial proximity propagation、结构感知的 adaptive-granularity access 和 visual region 证据。

3. 结果与工程意义

作者报告在 3 个长文档多模态 benchmark 上达到 SOTA。相比具体 SOTA 数字，我更看重方法抽象：Retrieval State 可以像 Bandit Belief 一样持续更新。这让 Agentic Search 和推荐系统的探索机制出现直接连接——下一轮读什么，本质上是基于当前不确定性的 action selection。

4. 对 Search/Rec 的迁移

对于商品/内容推荐，类似机制可以维护“用户当前意图假设”的 belief：某些行为证据加强一个 intent，另一些证据削弱它；下一次召回则主动探索最能消除不确定性的内容源，而不是无限扩大 Top-k。对复杂搜索 Agent，这比单纯把 history 塞进 Prompt 更接近真正可控的 memory state。

5. 局限

  • Bayesian/Thompson 的效果依赖 belief 更新质量，LLM 产生的错误证据可能被进一步传播。
  • 多轮探索天然增加 latency；还需要 cost-aware stopping。
  • 文档页面空间结构天然存在，而开放 Web Search 的“邻近关系”更难定义。

研究观察 05 · Recommendation Evaluation / Coverage · v1 2026-08-07

Invisible to the Machine: Auditing AI Restaurant, Cafe, and Bar Recommendation Against a Complete Market Census

Vladimir Pitenin · Production AI Recommendation Audit · Coverage / Visibility / Freshness

这篇不是新的推荐模型，但非常值得推荐工程师读：它第一次把 AI 本地推荐放到完整市场 Census上评估，因此能看到传统 sampled benchmark 看不到的“谁永远进不了推荐集合”。

1. 数据与评估设计

研究完整枚举 Bali 两个区域共 4,776 家餐饮场所，用 96 个 persona-conditioned queries，在 7 天内采集 4 个生产 AI 系统（ChatGPT、Claude、Gemini、Perplexity）共 2,208 个 search-grounded responses。因为有完整 denominator，它能把“进入答案的概率”和“进入后排第几”拆开研究。

2. 最值得记住的数字

指标结果
从未被任何系统推荐的场所85.6%
即使已有 ≥50 ratings，仍从未被推荐72.6%
完全虚构 mention0.08%
推荐已永久关闭场所93 次
跨系统 Top-20 Jaccard0.33–0.54

3. Entry 和 Rank 是两个模型问题

是否能“进入答案”更多与文档可见性有关：Review volume、独立网站、价格信息、第三方 Web mention 都显著相关，而 star rating 在 entry margin 上不显著；一旦已经进入候选集合，rating 才更能预测第一名。这和工业推荐非常像：召回 Coverage 与精排 Quality 必须分开诊断。

4. 最现实的失败不是 hallucination，而是 staleness

完全虚构非常少，但关闭门店仍反复出现，说明“事实过期”比凭空编造更实际。对推荐/搜索来说，这会把研究重点拉回数据 freshness、index update、entity lifecycle 和 source reliability，而不是只盯生成模型 hallucination rate。

5. 局限

  • 只覆盖两个地理市场和餐饮领域，不能直接推断到电商/内容推荐。
  • 生产系统内部 Retrieval/Ranking 不透明，只能观察输出相关性。
  • Visibility 的相关因素不等于因果因素。

研究观察 06 · Multimodal Rec / Semantic ID · v1 2026-08-07

From Classification to Recommendation: Audio Embedding Models for Content-Based Music Recommendation

Qingrui Li · Haowei Lou · Chengkai Huang · Quan Z. Sheng · Lina Yao · Audio Encoder / Sequential Rec / Semantic-ID GenRec

这篇回答了一个很容易被默认但其实未必成立的问题：一个在 Audio Classification / Audio-Text Alignment 上很强的表示模型，是否自然就是最好的推荐 Item Encoder？答案是：取决于它进入推荐系统的方式。

1. 实验覆盖三种推荐范式

作者系统比较 6 个代表性 Audio Encoder，并放入 content-based、interaction-based sequential recommendation、Semantic-ID-based generative recommendation 三类架构；同时控制 residual quantization 的 codebook width、quantization depth 与保留的 SID prefix，观察音频表示信息如何在 GenRec 中被离散化。

2. 三个重要结论

  • 直接使用预训练几何：Audio-text aligned 与 music-domain representation 通常更有效。
  • 加入交互训练以后：不同 Encoder 的差异显著缩小，说明行为 supervision 会重新塑造表示，预训练榜单并不能直接决定推荐表现。
  • Semantic ID 容量并非越大越好：增大 codebook / depth 不会稳定提升 GenRec，反而可能带来明显 instability。

3. 对 Semantic ID 研究的启发

过去一年很多 GenRec 工作把“更丰富的 SID”视为自然方向，但这篇给出一个有价值的负结果：离散表示的容量扩张不是无条件 Scaling Law。真正要优化的是 recommendation-relevant information 的可保留性、code utilization、prefix semantics 与训练稳定性。

4. 局限

只在两个音乐推荐数据集上验证，没有真实流媒体 A/B；不同音频领域、视频/电商多模态是否复现同样规律仍需验证。

今日趋势判断

真正的主线：从“更强模型”转向“动态分配每一次请求的计算”

把今天六篇放在一起看，方向非常一致：

  • EAHR：决定检索读多深；
  • CoinRAG：决定Context / KV 复用到多细；
  • Pre-Inference Routing：决定该用便宜还是昂贵模型；
  • DocMemo：决定下一轮应该探索哪份证据；
  • Coverage Audit：提醒我们先判断谁根本没进入候选集合；
  • Audio/SID Study：提醒我们表示容量增加是否真的转化成推荐价值。

这说明 Search / Rec / RAG / Agent 正在共享同一个系统问题：每个 Query、User、Candidate Set 的边际计算价值都不同。下一代系统的核心能力，很可能不是单一大模型，而是可验证的 stopping、routing、memory、budget allocation 与 coverage diagnostics。

对推荐算法工程师的研究优先级

  1. 最高：学习把“固定 Top-N / 固定模型 / 固定 Token Budget”改成 request-aware policy，并且量化成本收益。
  2. 高：补齐 Hybrid Retrieval、RAG KV Cache、Long-context Serving 的系统知识；这些会直接影响 LLM/GenRec 能否上线。
  3. 高：把 Recall Coverage / Freshness / Candidate Entry 作为独立诊断层，不要只看 AUC/NDCG。
  4. 中高：Agentic Retrieval 的 Belief / Exploration 思路与 Bandit、重排、多目标策略有明显可迁移性。
