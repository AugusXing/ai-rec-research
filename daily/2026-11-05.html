背景 / 业务动机

工业推荐在精排之后通常用规则、集合多样性与广告等业务收益进行重排与混排。逐 item 预估点击和转化虽然成熟，却不能表达顺序、跨内容类型的竞争、冗余或负面反馈覆盖。一整屏产品、视频、直播与广告的联合价值并非点分数简单求和，因此需要直接优化完整 List。

现有方法的问题与核心矛盾

常规两阶段 Generator–Evaluator 先生成多个 List，再用昂贵评估器在线选择。随着候选类型、约束与长期价值增多，在线计算与规则复杂度快速攀升。真正的工程问题不是“能不能生成列表”，而是能否在同等上游候选和硬约束下优化真正的业务 Reward，并在延迟预算内稳定执行。

技术方案、关键模块及结构示意

架构区分离线多头 List Reward Model 和在线 Policy。Reward Model 接收已曝光全 List，在序列末尾追加 EOS，使用 EOS 隐层预测点击、订单、GMV 等列表目标，并结合内容类型偏好与长期价值；Policy 把请求候选映射为可选 token，自回归一次选出无重复的最终 List。代码层面约束在 decode mask 中执行，软性打散规则可进入 Reward。

训练方法、样本与 Loss / Reward

先用自然曝光列表监督 RM：点击与订单采用加权分类/回归目标，GMV 经裁剪归一化，辅助 item head 避免仅凭 EOS 粗粒度信号过拟合。Policy 从真实 List 顺序 SFT/CE 预热，再 GMR-PO on-policy 采样，对多头 RM 回报作 rollout 内归一化与几何整合；额外规则 Reward 单独标准化，group-relative Advantage 配 PPO clipping 与 reference KL。RM Ensemble 用均值减与模型分歧相关的惩罚，这是经验保守化而非有覆盖保证的置信区间。

推理 / Serving 执行路径

线上只保留一套生成式 Policy，prefill 包含用户、候选特征与上游精排结果；decoder 约束采样/beam 保证品类份额、去重和位置规则。RM、多个教师及 RL rollout 不进入实时链路，不需要每个请求重复调用在线 Evaluator。服务需要保障候选动态词表的稳定映射、越界 token 防护、回退方案以及上下游特征一致性。

实验设置、数据集与基线

作者使用大规模真实电商多内容候选和历史完整曝光列表，做多目标训练与按时间切分的离线检验。比较旧 Generator–Evaluator、序列重排与多个 RM/约束消融。离线 RG 是 RM 对生成列表的估计增幅，不是随机 A/B 的实际转化百分比；不同数据集上的模型分数需按各自构造方式解读。

离线指标、关键数值与消融

扩大 Reward/Policy 模型、增加 on-policy rollout 能提升 RM 预估列表收益，但应特别关注 OOD 分数乐观偏差。训练端报告相对 eager 最高约 4.91× 加速、显存占用降低 81.8%；优化后推理模型路径可达 16.68× 加速、内存降低 72.7%。这两个 microbenchmark 绝不可被当作整体线上链路改善。

线上 A/B、归因与显著性边界

生产用户级随机 A/B 报告 GMV/u +2.63%、广告主价值 +2.06%、复购率 +2.03%，主要业务指标具有统计证据；重排与混排阶段端到端延迟降低约 13%。复购率以较长观测窗统计。对照与实验是完整新旧链路，因此不能将全部增益单独归因于 EOS 头、GMR-PO 或某条规则。

训练效率、Serving 性能与真实成本

训练需要 RM 多头标签、组采样、生成 rollout 与判别器集成，离线 GPU-hour 成本不低；但将评估器从请求路径移走，使运营成本更可控。工业落地应给出 RM 训练成本、Policy 每请求 token 数、候选池大小、decoder P50/P99、整体 GPU-ms，以及每千请求的真实增量交易价值。

相较主流方法的优势与代价

相比 MMR/手工业务权重，方法学习完整列表的多目标价值；相比在线 Generator–Evaluator，时延与模型服务链更简单。代价是优化目标由有偏历史日志训练，RM 可能被 Policy exploitation；列表级长期因果回报仍有跨时窗噪声，硬约束会压缩策略行动空间。

适用于商品评价重排/检索的落地建议

商品评价场景可先把 20–50 条候选评价编码为有序 token，附评价极性、属性、证据真实性、时效与质量分。使用真实曝光 List 的成交/满意度训练 EOS 双头 RM，同时加入差评覆盖、属性多样性和去重约束；再 CE warmup → 保守 RL/DPO policy。必须与规则混排在相同候选池下离线比对、做不同用户分桶 A/B。

局限性、尚未解决的问题

真实曝光 List 非随机，Reward 中的成交和满意度混合了买家偏好、候选生成、位置与商品质量；Ensemble 分歧不足以自动纠偏。复购反馈稀疏且跨窗口；更长列表扩增 decoding token。论文不能证明方法对淘宝评价业务会获得同幅度收益，也没有把每个 Loss 独立做生产 A/B。

未来研究、实验优先级与工程能力

研究优先级 P0：真实曝光 List RM 的多目标校准、Hard-negative、用户/商品/评价极性分桶、反事实支持集；P1：在 RM 不确定性下保守 RL 和可解释奖励约束；P2：在线效率/价值 Pareto。核心工程技能是 Reward 数据闭环、可重复 A/B、生成推理与系统性能，而非只改大模型参数。

背景 / 业务动机

商品检索中很多用户重复输入相同的 Query，但各自历史购买和偏好不同。用 7B 模型完整生成所有 SID token 有很强的质量潜力，却让每个请求承担昂贵的自回归解码成本，难以覆盖高 QPS。

现有方法的问题与核心矛盾

直接缓存整个 Query 的 item list 会使多个用户看到同一结果，削弱个性化；简单以小模型代替大模型，则牺牲热门与长尾检索的质量。核心是确定哪些生成前缀只依赖 Query，哪些后缀必须依赖实时用户，并把缓存不足时的 fallback 作为真实链路的一部分。

技术方案、关键模块及结构示意

离线大模型 7B 为 Query 缓存 top prefix 集合；ReuseCut 根据历史 Query 的候选覆盖决定切分深度；在线 0.5B 网络在前缀树允许范围内，加入用户特征续写个性化 SID。Path KD 蒸馏大模型整路径概率；BudgetCut 按固定候选/branch 预算训练进一步分配生成宽度。

训练方法、样本与 Loss / Reward

四层 SID、每层 32 个 code。ReuseCut 用观察到的候选覆盖训练 Query→prefix depth 预测器；Path KD 学教师完整 SID Path 的概率；BudgetCut 先做 masked listwise on-policy distillation，随后用 GRPO 与 top-100 命中效用反馈优化 branch admission。注意分支的 Reward 是召回，不是商品成交。

推理 / Serving 执行路径

请求进入时先查 prefix cache，命中后组合个性化 0.5B decoder 与缓存子树约束，最终映射候选 SID 到 item；未命中走当前 0.5B end-to-end 路径，异步限速回填。TTL、热门 Query 漂移、商品上下架、前缀版本一致性和离线刷新都需要明确服务契约。

实验设置、数据集与基线

使用跨境电商工业数据约 338 万个商品，44,225 Test Query；对比 7B/0.5B E2E 与多种蒸馏/缓存召回。区分 Query-macro HR@100（至少一个正确 item 被命中）与 Recall@100（全部真值商品的覆盖比例），不要与全链路排序 A/B 混用。

离线指标、关键数值与消融

Prepared-cache 理想测试下 HR@100 85.82%、Recall@100 46.05%、mean latency 71.45ms；相比 0.5B E2E HR@100 高 3.83 个百分点，平均时延降低约 38.9%。7B E2E 虽 HR@100 相似，但 Recall@100 高达 50.96%，因此小后缀仍有损失。

线上 A/B、归因与显著性边界

14 天在线搜索广告实验，实验/对照各约 10% 流量，CTR 相对 +0.93%、RPM +1.05%，订单/请求 +0.78%，CVR 反而 -0.21%。真正改变的是召回通道，其它排序和竞价保持对照，不能称为整套推荐链路所有目标均改善。

训练效率、Serving 性能与真实成本

100 万缓存前缀 payload 约 256MB；刷新每日 10% 的估计成本为 2.44 A100 GPU-hour。prepared 的 71.45ms 与真实 Cache Miss 混合延迟不是一回事；在文中静态命中假设下推估混合均值约 100.21ms，对照不命中 117ms，实际收益明显小于 prepared 的 38.9%。

相较主流方法的优势与代价

相较完整 Query 结果缓存保留实时个性化；相较 7B 全在线节省请求 token。缺点是前缀会过早排除长尾 item，冷门 Query 无法复用，缓存版本和动态商品同步带来新风险。

适用于商品评价重排/检索的落地建议

评价召回可缓存商品/问题/属性共同语义前缀，实时结合用户近期是否关注负评、尺寸、使用场景续写评论 SID。应独立追踪小众质量问题的证据 Recall，保证缓存前缀不会剪掉低频但高价值评价。

局限性、尚未解决的问题

实验 Prepared 环境假定测试 Query 均已有缓存，不代表任一平台的真实命中分布；高频/长尾 Query 质量不同，商品/评价变更引起语义前缀漂移，离线 HR 与线上广告收益可能不一致。

未来研究、实验优先级与工程能力

优先探索按 Query 热度/类目/SID 深度动态切分；做覆盖率×P99×Full-Recall 三维 Dashboard，加入 miss fallback 与缓存失效演练。研究者应该同时懂 SID 算法、KV/Prefix Caching、召回统计和实际服务链路。

背景 / 业务动机

本地生活首页需要生成少量用户愿意点击、并能够真正执行的搜索 Query，同时面临长尾词、地域、实时天气/时间与候选多样性。标准语言 BPE 会压缩高频文本，却未必压缩真正有价值的长尾业务 Query。

现有方法的问题与核心矛盾

直接 SFT 复制曝光点击对会继承位置偏差，固定行政区 token 缺精细时空上下文，硬打散 Beam 又往往损伤准确率。论文试图共同修正表示、监督和最终序列解码。

技术方案、关键模块及结构示意

OA-BPE 的 merge 利用曝光、CTR/CVR 与业务价值计算 token 选择；STAR 把多尺度地理坐标与时间信息转成连续表示并门控融合；MARS-DPO 按查询可执行性、实际反馈、距离构造偏好；SDBS 在 Beam 上渐进式奖励差异。

训练方法、样本与 Loss / Reward

先做通用/领域 SFT，再将真实曝光点击转化为正负偏好对；根据 CTR/CVR、可执行性、区域适配形成复合奖励，选 Reward 接近的 hard negative，多负 DPO + SFT Anchor 避免 policy 过度漂移。昂贵大 LLM 判断可执行性主要发生在离线，不是线上每个请求调用。

推理 / Serving 执行路径

线上上下文含用户最近位置、时间和搜索行为；生成器 Beam 直接输出 top-5 查询建议，Sigmoid diversity 优化候选间差异。需要对定位授权、缓存与安全策略设置边界，防止不合时空的推荐词。

实验设置、数据集与基线

对比不同生成式 Query 推荐系统并做移除 OA-BPE/STAR/DPO/SDBS 的消融；离线包括 HR@5、MRR@5、地理距离 GeoC@5、可执行性 Exec@5、多样性 IDiv@5，分冷启动与长尾 Query 分组。

离线指标、关键数值与消融

相较最强生成基线 HR@5 提升约 5.6%、GeoC@5 降低 40.3%、Exec@5 高 1.9%。长尾 Query token 长度中位数从 7.2 减至 5.9；标准 Beam 的 IDiv@5 0.231，SDBS 为 0.211，但 HR@5 保持 13.2；更激进 DBS 使 HR@5 降至 8.7。

线上 A/B、归因与显著性边界

一周真实流量随机 A/B 每组约 20%：模块 CTR +1.88%、搜索量 +0.177%、搜索 DAU +0.105%。搜索整体量和模块点击不是同一口径，不能把点击改善等同成交改善。

训练效率、Serving 性能与真实成本

离线生成训练需要复杂 Hard-negative mining 与大 Judge，线上只执行较短序列的 beam；Tokenization 可能减少 token 但论文未提供可对应的线上 GPU-ms/整体 P99 改善，不应自行推导成本比例。

相较主流方法的优势与代价

优于只在生成结果后加去重规则，因为表示与监督一起反映业务目标；缺点是有价值的业务词随地域、季节变化，词表、Reward 和 DPO 偏好需要持续校准，点击也有反事实选择偏差。

适用于商品评价重排/检索的落地建议

评价推荐可将尺寸、耐用度、负面体验等高信息密度短语/观点作为生成单元，用成交/满意度双目标偏好和 hard negative 训练，再用温和多样性约束平衡证据覆盖与准确性。

局限性、尚未解决的问题

论文目标是搜索 Query List，而非商品评价 List；多负 DPO 优化候选词条而不是整屏评价的因果效应。业务词价值加权可能固化热门偏好，地理信息也涉及隐私安全。

未来研究、实验优先级与工程能力

推荐同预算消融：Tokenizer 改动 / Reward 偏好 / Diversity 解码分别控制，比较未看过的负评覆盖、真实满意度、转化、token 成本和冷启动泛化；加强 DPO 数据校准能力。

背景 / 业务动机

LLM 增强推荐把长历史压成用户画像很流行，但很多方案只把用户记忆注入排序 Prompt。若候选实体缺少可比的属性结构，LLM 在召回之后才推理，用户的关键偏好可能早被粗召回阶段漏掉。

现有方法的问题与核心矛盾

只建 User Profile、忽略 Item Profile 会造成两侧语义不对齐；文本 Prompt 又受上下文预算限制，长期画像更新后有陈旧和噪声问题。论文主张把 Profile 变成检索期的计算对象。

技术方案、关键模块及结构示意

HARP 将过程设计为 Build→Transmit→Understand→Sync：用户、Item 各含偏好/品质/场景/受众通道，基于规则从商品属性/评论构造 Item Profile；相似用户历史的多通道 Homophily Gate 用于选择邻居候选，再把压缩画像输入冻结 LLM 重排。收到新行为后仅一次 Reflect 更新，规则 Critic 检查。

训练方法、样本与 Loss / Reward

方法名 Training-Free 指不更新 LLM 权重，不代表没有 LLM API 调用；首轮用户画像由 LLM 生成，更新仍调用 LLM，Item 画像尽量规则抽取。检索 gate 通过通道相似度和 floor 权重组合，无 DPO/GRPO 的可训练梯度。

推理 / Serving 执行路径

Serving 必须支持 User Profile 的异步更新和版本快照，Item Profile 可缓存于召回索引，检索邻居 Gate 先计算再交给 LLM reranker。评测仅十个候选，若要生产上万评论全库需先用轻量 ANN + 稀疏 gate，避免一条评论一轮 LLM。

实验设置、数据集与基线

Yelp、Books、MovieTV、Goodreads 四个 InstructRec benchmark，固定 GPT-4o-mini 主干、16 邻居、1 正+9 负十候选排序；对照 MemRec/iAgent 等已有方法。作者 README 说明目前完整的 Item channel profile 主要用于 Yelp，其它数据集匹配通道退化为中性，复现时不能按“全部四基准使用同一完整双画像”解读。

离线指标、关键数值与消融

按论文对已发表最强基线 Hit@1 相对高约 6.9%–24.0%，多检验校正 p<1e-9；主要作用来自检索前 homophily gating，画像更新是附加稳定性因素。不过固定十候选更容易体现排序优势，难反映万级候选漏检。

线上 A/B、归因与显著性边界

无真实线上 GMV/CTR A/B；离线来自已发布 benchmark 的对比，不得把显著性检验称为生产因果证据。

训练效率、Serving 性能与真实成本

冻结 LLM 避免大模型微调 GPU 花费，却需维护用户画像、规则词典、外部 API 和实时更新队列；方法没有提供生产环境端到端 P99/GPU-ms 优化比。

相较主流方法的优势与代价

对 Prompt-only 方案而言，HARP 让条件化状态在候选召回阶段就参与筛选，有助于缩减候选。风险在于本体抽取质量和画像漂移，更新规则不能证明能抵抗对抗式评价内容。

适用于商品评价重排/检索的落地建议

评价推荐可构建用户关心的型号、耐用、售后、差评敏感性 Profile，与商品评价的属性、极性、实际使用场景 Profile 做轻量匹配，优先提供有证据的候选再由 List Generator 完成成交/满意度优化；不应采集敏感个人属性。

局限性、尚未解决的问题

Profile 冷启动缺数据、跨域本体不一致且用户偏好很容易随购买阶段变化；小候选随机负例偏容易，且未证明从候选召回到完整曝光 List 的闭环。

未来研究、实验优先级与工程能力

推荐做三组在线离线对照：Prompt-only、Recall Profile-only、两者联合，重点看真实候选 recall、错误过滤负面观点率、解释一致性和服务成本；将画像版本、过期策略和用户可控性纳入设计。

背景 / 业务动机

很多推荐系统直接计算类目平均点击或用户满意度并用作模型评估或 Reward。实际上生产策略已经根据用户偏好筛选曝光，类目统计因用户群与视频构成变化而失真。

现有方法的问题与核心矛盾

仅做用户去均值可修复用户整体活跃度的差异，却无法自动校正用户×内容交互及内容组合。若自然曝光和随机插入两套日志的用户/视频支持集不一样，直接比较也有混杂。

技术方案、关键模块及结构示意

作者基于 KuaiRand 标准策略曝光与随机插入曝光，构造同一用户和视频都出现的 paired-support cohort；针对 38 类比较整体均值 level、去整体均值 shape、排名及 Top-K 决策。把选择偏差拆为同视频表现残差和视频混合组成差异。

训练方法、样本与 Loss / Reward

不训练新网络：对类别×用户 cell 既算 cell equal 也算 row weighted 的用户去均值估计；利用随机曝光 grand-mean 锚定水平，采用 cluster bootstrap 估计稳健不确定性，对多重 Top-K 决策用 family-wise 同时区间。

推理 / Serving 执行路径

系统部署角色是评价/推荐的数据质量和 Reward 校准服务，而非一个请求时运行的新模型。应记录生产策略、随机插入标志、候选集合、位置、用户视频 ID、数据版本和 propensity，以便长期监控重排的支持集漂移。

实验设置、数据集与基线

配对样本包含 12,472 用户、5,486 视频，按共同支持集和最低观测阈值分析 38 类。评估是 frozen future holdout，且展示不同权重/误差定义的稳健性。

离线指标、关键数值与消融

普通类别均值相对随机参考 absolute MAE 0.1935、centered MAE 0.0491、Spearman 0.7833。用户去均值加随机均值锚定，绝对 MAE 减约 80%，但 centered MAE 只减少约 21%。残差归因中的 within-video residual 约占 72.41%，video-mix 约 23.90%（按论文指定的 weighted squared error）。

线上 A/B、归因与显著性边界

没有对新策略的随机线上 A/B。个别 Top-K 类目选择 nominal regret 似乎改善，但跨六种比较后的 family-wise 区间包含 0，不应写成显著的普适商业收益。

训练效率、Serving 性能与真实成本

数据审计无需增加每次用户请求推理成本，但需要长期保留小比例随机探索流量、用户/视频支持集与实验归因血缘。无偏测量的成本是随机样本与统计稳定性，不能随意省略。

相较主流方法的优势与代价

与 IPS/DR 反事实估计是互补关系：先检查支持集重叠和统计量组成，再决定用何种校正；简单加权或去均值不是通用因果估计器。

适用于商品评价重排/检索的落地建议

针对评价列表，把“质量负面/物流负面/规格描述/买家秀”等观点维度分组，按相同用户、相同商品、相同候选池和评价位置比较自然 List 与随机混排 List；先验证成交+满意度 Reward 是否只是记住原始流量策略。

局限性、尚未解决的问题

共同支持集不消除未观测兴趣、历史动态或干预互扰；随机对照规模有限且是视频场景，不能证明在商品评价 List 上同样的幅度。锚定使用随机参考真实均值，部署时需要持续数据来源。

未来研究、实验优先级与工程能力

对评价算法团队优先 P0：分桶 Reward calibration、真实随机曝光小流量、位置/长尾评价 propensity；P1：IPS/DR 与 OOD Reward 保守优化；P2：在端到端 A/B 中同时追踪随机参考校准指标。

传统 Scaling Law 假设训练中持续获得新数据，把计算总 tokens 当作独立信息；数据受限领域模型规模、独立数据数量、学习率/Weight Decay 与最佳收敛步相互作用。

技术方案、关键模块及结构示意

定义 MAEL（Minimum Achievable Evaluation Loss）为训练轨迹上可达的最小验证损失，对非 Embedding 参数量和唯一训练样本数拟合乘法幂律，并研究训练到达最优点所需步数。

训练方法、样本与 Loss / Reward

在固定的 Dense Retriever 对比目标中，变化 Encoder 大小、独立监督对的数量及优化超参，保存多 checkpoint 取验证 MAEL；用 Weight Decay 近似 EMA 时标修正重复训练的过拟合，与单纯添加 regularization 对照。

推理 / Serving 执行路径

推理端仍是双塔 Encoder → 向量索引/ANN，不产生额外线上 Query 执行层。经验曲线用于在离线决定增加模型容量、追加 Hard-negative 人工标注还是改变训练 schedule；上线 GPU 内存与索引成本仍要另算。

实验设置、数据集与基线

35 个 BERT 系 Dense Retriever 的 MS MARCO 规模×样本量实验，检查检索验证集的 minimum Loss、MRR/Recall 与外推拟合质量。不同模型 checkpoint、学习率与数据量需要在相同数据去重口径下比较。

离线指标、关键数值与消融

论文报告乘法幂律拟合的说明力优于常用加性式，较低 MAEL 通常对应较好的检索有效性。在这个研究场景，增大预训练模型规模的微调计算效率约是增加独立域内数据的 1.46 倍；它不是任何生产业务通用的固定系数。

线上 A/B、归因与显著性边界

无生产推荐、搜索或广告线上 A/B，也不提供任何商品评价成交 A/B 证据。只能据此提出预算实验假设。

训练效率、Serving 性能与真实成本

扩大 Encoder 可能减少达到离线目标 Loss 的微调步，但 Serving 时向量维度/每个 Query 编码吞吐、索引成本会增长；需要对比全链路 GPU-ms 和候选质量，而不是只看 Fine-tuning FLOPs。

相较主流方法的优势与代价

优势是把真实有限数据与重复训练的最优点分开，避免错误训练预算；代价是跨预训练架构、负样本机制、域漂移与离线验证集规模仍有待重新拟合。

适用于商品评价重排/检索的落地建议

评价 Query–Comment 召回可按去重标签量分成若干训练规模，在相同 hard-negative 采样策略下训练不同大小双塔，测 MAEL 与 Recall/GAUC，再根据线上 P99/索引内存选择 Pareto 方案。

局限性、尚未解决的问题

MS MARCO 英文任务与多模态电商评价差异显著；MAEL 对最优 checkpoint 的估计受早停/重复测量影响；扩大模型可能影响线上业务成本而未带来更多满意度。

研究者应掌握有约束的 Scaling 实验设计、数据去重、最优训练停点、预算回报比，以及如何把训练曲线转成在线容量规划。

现有方法的问题与核心矛盾

技术方案、关键模块及结构示意

未来可做 Reward-aware source pairing、负面证据覆盖约束和动态协同 Source 置信度；优先验证同网络容量的改善是否来自数据质量。

现有方法的问题与核心矛盾

技术方案、关键模块及结构示意

Query-attentive readout 从当前图节点聚合证据摘要 z_l，GRU 将 z_l 与当前 Query 向量共同更新为下一跳 Query State；新 Query State 再引导 relation weighting 与 frontier boundary entity injection，形成 Graph→Query→Graph 的自适应回路。

训练方法、样本与 Loss / Reward

训练从多跳 QA 支持实体与文档监督形成相关性目标，更新图消息传播器及 Query recurrence；最终 Entity 分数从节点向量和初始 Query 的结合层读取。不是商品评价 DPO/RL 列表优化方案。

推理 / Serving 执行路径

Serving 先为可检索语料建立实体/文档图，每请求按有限 Hop 传播，更新 Query 状态并输出关联支持文档供回答模型；须限制每跳节点扇出、防止图更新延迟和 Query Drift 累积。

实验设置、数据集与基线

四个多跳 QA benchmark，与 G-Retriever、HippoRAG2、GraphRAG、GFM-RAG 等比较；同时报告 Macro Recall@K 与 Full Recall@K（必须命中一题全部支持文档），以及下游回答准确率。

离线指标、关键数值与消融

整体 Macro R@10 81.93%、Full Recall@10 70.38%，对比 GFM-RAG 76.95%、61.98%；论文报告 LLM Answer Accuracy 约提高 8 个百分点。Full Recall 指标尤其适合多证据完整性问题。

线上 A/B、归因与显著性边界

没有真实商业流量 A/B，也未证明提升评价列表最终转化。离线问答完整证据召回不等于推荐场景中的增量 GMV。

训练效率、Serving 性能与真实成本

图构建、在线多跳 GRU/邻居聚合增大 per-query cost，作者未给可直接迁移到工业的 QPS/P99 GPU-ms；低成本路径可使用小图、早停、蒸馏轻量 Query Reformulator。

相较主流方法的优势与代价

相较固定 Query 的 Graph Retriever，动态读出更贴近推理逐步细化的证据需求；风险是第一跳取到错误内容后产生语义漂移，后来越检索越偏，图本身还需长期维护。
