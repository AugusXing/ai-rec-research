Calibrated Decision Rewards: Training Language Models with a Judge That Knows How Sure It Is

Judge输出的分数不是概率。用可校准的二元/结构化决策概率，为RL提供可解释Reward。

Impact Score本站主观评分。分项依次为范式变化、工业证据、创新、相关度、后续空间、可复现性：91 / 62 / 93 / 98 / 92 / 38；权重依次25% / 20% / 20% / 15% / 10% / 10%。

背景与核心矛盾

商品评价生成式重排的Generator依靠Reward优化，但打分Judge往往无法解释其分数与真实正确率、成交/满意度的关系。答案键虽可靠，却无法覆盖开放式任务；未经校准的LLM分数可能被策略优化放大。

方法和关键模块

论文将LLM转为typed decision model，让其判断回答是否正确、首个错误步骤在哪，并读取单次前向的分类概率。通过调换选项顺序去偏，并使用约100条标注校准概率，避免把原始logit误当可信Reward。

训练与Loss

在Qwen3-1.7B上用GRPO训练策略，Reward由校准后的reference-free判断概率提供；设置答案键Reward、随机Reward与softmax Judge作为对照。该训练任务是数学答题，不应直接宣称对商品列表已优化转化。

Serving与实验设计

Serving时建议批量Judge推断与异步校准审计，记录Label窗口和Judge版本。论文评估MATH/MATH500、ProcessBench、置信校准ECE，并在模型原本困难的分布上检查过度自信。

离线结果及工业证据

MATH500正确率72.2%→76.8%，答案键Reward为76.9%，随机Reward仅增加0.65个百分点。困难题44.8%→51.7%；ECE=0.074，对照softmax Judge为0.141；ProcessBench F1=0.772，对照PRM为0.722。无商品推荐生产随机A/B。

效率、优劣与局限

单次typed判别加少量校准集降低了获得概率解释的标注门槛，但在线Judge仍消耗GPU/token；论文没有电商P99与成本。优点是可度量可靠性，弱点是极难样本仍可能过度自信且无法解决同源证据错误。

后续方向和推荐落地

基于真实曝光List按品类、差评比例、商品生命周期测Reward ECE/Brier和偏好pair翻转；先做同曝光候选池的离线校准、独立人审，再以成交与满意度进行随机A/B。重点学习概率校准和Reward漂移监控。

From Cases to Criteria: Reusing Evaluation Knowledge for Task-Specific Rubric Generation

背景与核心矛盾

不同商品、用户搜索意图下，用户重视的评价证据不同。单个固定Judge Rubric会忽略属性、真假、售后、负面风险；照搬历史Rubric又易混入旧场景细节。

方法和关键模块

作者构建Rubric Knowledge Graph，把评价维度、共享概念、局部概念、评价条款和来源query连接起来；先检索目标query相关概念与历史案例生成初稿，再逐条检索历史准则和source query修订成可执行判据。

训练与Loss

这是检索/知识复用驱动的Rubric合成，公开摘要并未定义可直接照搬的电商Reward模型Loss。工程可引入子Rubric的监督与人审label，但需与论文实际方法区分。

推理Serving与实验

在线可缓存类目级Rubric、按query触发轻量检索，异常query再调用大Judge并保留出处。论文在RubricBench与HealthBench比较人工Rubric匹配和下游Judge表现；无电商推荐流量与Serving P99。

离线结果与A/B证据

论文报告自动方法中整体最优，但已核实摘要未提供可引用的具体百分点；不臆测数值。没有可确认的商品评价列表随机线上A/B。

效率、优势、缺陷

图谱一次构建、多次复用有工程价值，但维护历史准则索引、检索和细化带来额外成本；错误的历史标注会被系统性传播。与简单Few-shot比，可追溯性更强，要求来源版本与质量过滤。

推荐落地和研究路线

建立类目/用户意图/观点类型/证据完整性Rubric图谱。比较固定/检索/人工Rubric的pairwise一致率、差评证据覆盖、真实成交标签关联；研究跨类目迁移、过时准则淘汰与可信样本挖掘。

How Much Should an Agent Remember? Deployment Lessons from Self-Distilled Memory for LLM Agents

背景与核心矛盾

长任务Agent会重复操作错误，推荐长序列模型也常受历史记录冗余、时效与算力预算影响；全量上下文既贵又可能污染当前判断。

方法关键模块

从轨迹抽取每次1–3条lesson、合并为带支持计数的guideline，按请求语义和模型能力选择要注入的经验。论文特别警示高支持度但错误的准则、合并丢失来源、工具报错被吞没等故障。

训练Loss与Serving

自蒸馏外部经验层，不要求微调底座或使用RL Loss。服务端按不同模型设置检索topK、缓存高置信共性知识、保留provenance与版本；对权限敏感经验做隔离。

实验与对照

AppWorld多步任务，对照无记忆、全量指南与小子集检索，覆盖强弱不同模型；报告任务和场景完成率，并揭示错误基线造成的虚假增益。

离线量化与线上证据

DeepSeek-V3.2用191条guideline任务完成+9.5个百分点、场景完成+16.1个百分点；gpt-oss-120b基线39.9%、199条全量51.2%、约29条筛选子集55.4%。IBM报告已在CUGA/watsonx Orchestrate部署，不是商品推荐用户随机A/B。

成本收益与局限

更少的指南可能减少prefill时间和上下文噪声，但需要抽取、合并、检索与审计成本；不同模型曲线不一致、记忆过时和权限变更会导致不可靠结果。

推荐落地与未来问题

在同一评价候选池上比较全历史、近端历史和能力条件下动态检索，测NDCG/重要差评覆盖/Token/端到端P99；维护用户可删除、时效可追踪的长期偏好。学习动态检索与记忆治理。

Rate-distortion Assessment for Hierarchical Content Summarization

有限Token/曝光槽位下，重点不是摘要变短，而是重要语义证据的失真有多大。

Research Impact Score / 研究价值：76/100工业成熟度：54/100创新性：88/100与你方向的相关度：92/100是否官方开源：未核验专属代码是否有线上 A/B：无推荐随机A/B阅读优先级：S

Impact Score本站主观评分。分项依次为范式变化、工业证据、创新、相关度、后续空间、可复现性：85 / 54 / 88 / 92 / 91 / 37；权重依次25% / 20% / 20% / 15% / 10% / 10%。

业务背景与核心问题

RAG把大量召回文本塞入上下文成本高，摘要缩短文本却可能删掉核心事实；推荐评价List只有有限展示位置，同样需要避免低频但重要的售后、负面证据被覆盖掉。

技术方案

从Shannon的Rate–Distortion理论出发，将源内容抽象为层级语义问答结构，在给定压缩预算下量化丢失多少关键问答信息，并利用该结构指导检索与生成。

训练与Serving

该研究是评估和信息筛选框架，不是新的生成式推荐RL Loss。可离线生成商品属性/观点层级树，在线按用户query加权选择互补证据，输出保留原评价引用和缓存版本。

实验与结果

在长上下文QA和RAG评估不同大模型的摘要压缩率与失真权衡，并声称相较当前基线有更好的Rate–Distortion性质；摘要中无可核实的定量百分点，不编造NDCG或A/B。

工业A/B与效率

无推荐线上A/B。离线QA层级生成带来token成本，在线可能减少prompt与重复段落，仍需要对预计算更新、查询条件、历史时效与P99做完整测量。

优劣与局限

相较embedding只测点相关性，信息失真更强调覆盖；但自动构造问答层级可能出现幻觉，用户关注度随商品与查询变化，不存在一组永久稳定的权重。

落地与下一步

将评价列表视为固定曝光预算下的语义压缩：构造观点重要性权重、移除单条评价计算边际失真、与真实成交/评价满意度关联；可研究List Reward的覆盖与信息冗余可解释分解。

背景与问题

推荐和研究Agent常有专家写的实验Runbook/技能；不经任务验证让LLM多轮改写，可能使最有价值的长尾异常处理知识逐渐丢失。

方法与关键模块

对专家Skill进行多轮无反馈自重写，比较技能表现与模型自然先验，发现陌生于模型的专家知识更易被删。SkillDiff直接标出这些知识，在不修改Skill正文的情况下提高可利用性。

训练Loss与Serving

研究强调无反馈演化，不是新GRPO训练Loss。Serving应保留原始专家Skill和版本，记录任务成功/失败与工具调用，经过回归集验证后才启用新版本；重要动作增加确定性检查和回滚。

实验与数值

经过30轮重写，每种模型在所测Benchmark均退化，SkillsBench平均降低15个百分点；SkillDiff不修改原文而使SkillsBench平均通过率提升4.8个百分点。

无可核验的商品评论推荐线上A/B。省去盲目重写的token并能降低知识损失，但维护Skill测试集、审计溯源和回归测试仍需投入。

优劣与局限

不同于持续摘要Skill，SkillDiff聚焦知识保真；局限是评估基准不可能覆盖全部新场景，而且专家原知识也可能过时或错误，仍需外部验证。

推荐落地

对研究Agent和推荐实验平台实现Skill版本化、异常测试集、模型参数/工具版本固定、自动回归；新经验只有通过真实任务指标后才进入公共知识库。
