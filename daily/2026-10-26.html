LARA：Agentic Retrieval 的归因断裂

When Agentic Retrieval Fails Silently: Framework and Production Evidence from a Creative AI Assistant

一句话：推荐/Agent 系统最大的隐性错误可能不是模型排序弱，而是行为标签已不能正确归因到检索列表；先补可追溯日志，再训练 Reward。

背景 / 业务动机

传统 CTR、MRR、NDCG 假设用户直接看到检索结果并迅速行动；但在 Agent 场景中，用户先看到生成物而非召回列表。淘宝评价生成式重排也类似：用户点击、下单或满意度反馈是经由内容消费、其他模块和时间延迟共同产生。

现有问题 / 核心矛盾

三个结构性移位：谁消费（Agent 先看）；何时行为发生（跨轮/跨 session）；谁促成结果（召回内容与 LLM 自身知识混合）。因此零点击未必失败，改写请求未必代表召回不准，最终任务成功也可能掩盖检索层错误。

技术方案与关键模块

LARA 的 Layer 1 在检索触发时记录完整 returned_asset_ids 并用离线相关性标注衡量 P@1、NDCG；Layer 2 分别统计 Genuine Positive Rate（用户主动使用）与 Agent Consumption Rate（Agent 消费）以及失败信号；Layer 3 统计任务完成、延迟和单位成功任务成本。加入 retrieval_id、returned_asset_ids、consumed_asset_id、source_retrieval_id 四个 lineage 字段，外加 retrieval_role 分类，串起跨轮归因。

训练方法 / Loss / 数据流程

本工作不是新检索网络，无训练 Loss。Layer 1 需要人标或 LLM-as-Judge 的固定相关性样本；推荐模型可据 lineage 构建有来源追踪的 List Reward 训练数据，区分真实曝光、Agent 内部使用和未呈现候选，避免把隐式消费当作直接点击监督。

推理与 Serving 方案

在检索 RPC 返回点写 retrieval_id 和完整候选快照；下游 Agent 使用/用户后续编辑/导出时写 consumed_asset_id 与 source_retrieval_id；日志可异步关联，不应把昂贵 evaluator 放进在线主链路。必须校验候选 ID、顺序、版本和 session 关联，未关联事件单独标注。

实验设置与 Baseline

研究 Adobe Express 同一检索设施上的图库与 Agent 助手，使用 2026 年 8 月生产会话；这是观测研究而非随机实验。作者说明当前生产日志还未实现完整 lineage 字段，因此部分业务行为指标仍基于时间近邻。

离线指标与关键实验数字

图库改写率 33.1%，Agentic chat 44.4%；Agent 全量改写率 31.2%。Agent 全部 prompt 中触发检索仅 0.31%，chat 子场景 10.7%（作者标为方向性）；绝不可把 0.31% 直接当作召回质量差或计划器正确率。

线上 A/B 与证据边界

有真实生产行为分布，但没有上线 LARA 前后的受控 A/B，也没有 GMV 等增量业务收益。较高改写率可能是逐步完善生成内容，不能机械当作检索失败。

效率、成本与收益

四字段日志增加索引/埋点与事件关联成本，理论上不需增加在线推理调用；需评估事件基数、跨 session join、回填及存储保留期。工作未报告可量化线上成本下降。

与主流方法的优劣势

优于只用 CTR/NDCG 或 session 成功率替代检索评价的因果解释力；弱于有随机化干预/反事实实验的因果识别强度，且离线相关性标注可能过期或被 judge 偏差污染。

适用业务场景

评价推荐 List 消费链、购物 Agent、RAG 证据链、复杂搜索结果合成；适合先做离线归因校验与数据审计，不是直接替换重排模型。

局限 / 未解决问题

样本规模受商业披露限制；缺失 lineage 的现有数据还无法证实归因效益；Layer 0（是否触发检索）留作未来问题，Agent 静默补救的答案质量仍需独立审核。

未来研究方向与工程 / 职业启发

把曝光 List→内容查看→引用→加购成交→满意度事件串成同一决策图；评估由日志匹配升级为随机化查询干预、interleaving 和列表级偏好建模。业务工程师优先掌握埋点因果图、反事实归因与 Reward 数据 QA。

GRIP：学习型稀疏召回的图索引逆袭

Getting a GRIP on Graph-Based Search for Learned Sparse Retrieval

一句话：不要再把“稀疏向量必选倒排索引”当成定论：在固定高召回阈值下，稀疏感知图搜索可能更快，但索引构建与存储并不免费。

Research Impact Score / 研究价值8.0/10 · 本站主观加权评分；分项[范式,工业,创新,相关,空间,可复现]：8/7/9/10/8/5

背景 / 业务动机

SPLADE 等 learned sparse 兼有 lexical 可解释性和神经泛化能力；传统图 ANN 的稀疏点积和随机访存耗时高，Seismic 一类专用倒排索引通常占优。大型评价/搜索系统同时维护 Dense 图与 Sparse 倒排会引入运维负担。

现有问题 / 核心矛盾

朴素 HNSW 为稀疏表示选择入口时不利用查询的非零 term；全维度打分浪费稀疏相似度；为了得到好图，ef_construction 必须达到约 2000，138M 级建图将极慢。

技术方案与关键模块

① 按每个 term 的 document 权重预存高价值入口，并由 query 非零 term 直接选种子；② 图遍历时只保留每篇文档幅度最大的 R 个非零分量作 sketch，最终候选仍用完整向量重评分；③ 用基于稀疏倒排计算的 Sparse PiPNN 分区建图替代昂贵的逐点 HNSW 插入，并做一次图优化。因为 SPLADE 权重非负，sketch 相似度是完整分数下界，但遍历路径仍近似、并不等同精确召回保证。

训练方法 / Loss / 数据流程

研究聚焦索引，不训练新的推荐模型；基于 SPLADE-CoCondenser、SPARSEUP 已学习稀疏表示，使用 held-out query 调 R 和 beam。实际训练关注主模型检索损失与索引质量分离，确保召回阈值是独立 holdout。

推理与 Serving 方案

离线建立 term→entry seeds、sketch、邻接图与完整向量存储；线上 query 选 seeds → sketch 图遍历 → 完整分数精排。可对稀疏召回和 Dense ANN 统一监控 Recall@K、P50/P99、QPS、RAM 和热更新工时。

实验设置与 Baseline

MS MARCO v1 8.84M、v2 138M passage，SPLADE-CoCondenser 和 SPARSEUP；主要对照 Seismic、原生 HNSW；固定 Recall@10 对比延迟（不是固定 latency 比质量），索引用 30 线程构建。

离线指标与关键实验数字

MS MARCO v2 在 95% Recall@10 时比 Seismic 延迟改善 2.5 倍；90%–98% Recall@10 范围改善 2.2–3.4 倍。v1 CoCondenser 改善 1.4–1.7 倍；SPARSEUP 在 98%–99% 高召回点 Seismic 仍更快。

线上 A/B 与证据边界

没有公开生产 A/B、点击/成交指标；仅可认为候选质量-时延曲线改善，不能外推 GMV。

效率、成本与收益

最重要的反向证据：v2 GRIP 建图 7.3 小时，Seismic 47 分钟；索引体积 GRIP 140GB vs Seismic 73GB。v1 GRIP 47 分钟 vs Seismic 2 分钟；因此全生命周期 TCO 未必优于倒排。

与主流方法的优劣势

相比标准 HNSW，利用稀疏 term 改进入口与建图；相比 Seismic 查询更快但建图/内存更重。更新频率高、RAM 紧张、Recall@10 极致点未必适用，应与 Lychee 的高精度筛查方案分别验收。

适用业务场景

稳定语料大规模搜索、SPLADE 式召回、商品评价关键词长尾匹配；不适合极频繁全量更新的稀疏索引直接无脑迁移。

局限 / 未解决问题

需验证动态插删、分片倾斜、过滤条件、在线负载、硬件、向量量化与精度漂移；论文集中 passage 点积，不保证业务列表指标。

未来研究方向与工程 / 职业启发

使用质量门槛下固定候选 Recall@K + P99 成本进行灰度；比较 Dense HNSW、Sparse Seismic、GRIP 与混合方案；掌握 sparse ANN 与索引构建成本、全链路容量模型。

BeNice!：循环模型跨轮共享 KV

BeNice! Closing Looping's Inference-Memory Gap via KV-Sharing

一句话：循环模型的参数量不随递归深度增长，但 KV cache 会；BeNice! 把“同一层多次循环”转化为可共享缓存的训练目标。

Research Impact Score / 研究价值8.1/10 · 本站主观加权评分；分项[范式,工业,创新,相关,空间,可复现]：8/7/9/8/8/9
工业成熟度作者公开代码及模型；收益主要来自模拟低显存推理测试

阅读优先级S+

背景 / 业务动机

Looped Transformer 同一 block 递归执行 T 次，以少参数换推理深度，但每个 recurrence 都新建历史 KV，长上下文和并发会导致显存线性增长；对于调用预算敏感的重排/Agent，吞吐比参数量更直接决定成本。

现有问题 / 核心矛盾

直接复制最后一次循环 KV 给前面轮次时，有些模型正常、有些发生严重质量坍塌。作者分析是第一轮引入与后续固定点不一致的 token-independent basis shift，纯静态深度训练无动力让 hidden states 收敛。

技术方案与关键模块

阶段一训练中随机采样 recurrence depth（stochastic depth），促进残差演化向相同固定点收缩；阶段二 BeNice! 同时优化常规 T-step 语言模型预测和 first-query/last-KV 的 hybrid predictor，纠正第一轮基底偏移，允许各轮共享最终 KV。可与 MLA、Kimi Delta Attention、FP8/更低比特缓存量化组合。

训练方法 / Loss / 数据流程

基于预训练语言模型的 CE / NLL 保持普通不共享质量，并加入 hybrid 共享 KV 预测约束；对每个 batch 采样 T，避免只在最大循环层优化。项目页称共享模型的 Core-Ext 差异≤0.06 points、validation perplexity 差异≤0.01；这是作者测试条件下，不是理论对任意网络保证。

推理与 Serving 方案

服务层将 recurrence KV 的深度维度复用以降低 HBM 需求；重点监控每 token KV 字节、prompt cache hit、TTFT P90、TPS/用户及 batch 接入饱和拐点。低负载时收益可能很小，高并发和长上下文最有机会兑现。

实验设置与 Baseline

Parcae 循环模型多个规模；对比普通 finetuning、朴素共享与 BeNice!，组合不同 mixer / KV 量化；系统数字来自模拟低显存、长上下文请求分布与调度，不是已确认的真实线上用户 A/B。

离线指标与关键实验数字

KV 命中率最多提高 31.4%（8.1 个百分点）；高负载约 2 req/s 时吞吐最多 +23.6%，p90 TTFT 从 139.2 秒降至 23.2 秒（-83.6%）；并发前沿在固定中位解码率下吞吐最高 +6.7%。这些属于特定模拟设置。

线上 A/B 与证据边界

选 chunk 算法时给每次文档修订计算 recompute ratio、embedding QPS、分块长度与 evidence recall，再进行缓存和增量 ANN upsert。尤其要区分更新输入 token 与用户查询时延；削减重嵌入可能提高吞吐但不必然加速查询。

实验设置与 Baseline

120 对中英 Wikipedia 相邻修订、240 个问题，116 文档三方案均成功；330 个可评分版本标签，固定 BGE-M3 CLS pooling 与 exact dot，最多取 100 候选打包至 2048 token；每文档成对 bootstrap 2000 次。

离线指标与关键实验数字

中文 Fixed 重算 68.4%、Recursive 55.7%、CDC 54.0%，对应 evidence recall 97.4/98.3/98.3%；英文 57.4/37.9/42.8%，recall 96.7/96.8/95.0%。CDC 中文 4/62 文档失败；论文强调未作非劣统计声明。

线上 A/B 与证据边界

无公开生产 A/B、真实 embedding 云账单；重算比例是 token workload proxy，不直接等于单位时间费用。

效率、成本与收益

说明可在证据召回损失有限的条件下降低约十几至二十百分点重算负担，但缓存 hit、模型 batch、更新调度和 chunk 长度变化会改变真实省钱幅度。

与主流方法的优劣势

相比传统静态 chunk 研究，显式建模文档修订生命周期；相比 stateful KARA 等复用器，本实验只比 stateless chunker，不能声称优于所有增量最优方案。

适用业务场景

知识库 RAG、商品说明更新、评论内容索引、政策文本与多语言内容库；特别适合频繁微小修改。

局限 / 未解决问题

只有 Wikipedia 且样本规模有限，标签未多位人类独立复核，静态近似检索实验没有线上过滤/业务多租户；CDC 有失败样本。

未来研究方向与工程 / 职业启发

将内容稳定的边界选择、Embedding 缓存、ANN Upsert 和版本回滚纳入同一 TCO 最优化；增加“每次内容修改每增加一次命中”的单位成本指标。

Jev-DLC: Decision-Level Continual Learning from Typed Feedback

背景 / 业务动机

个性化推荐反馈往往是 delayed 或用户主动更正，传统流水线依赖原始历史 replay / LoRA 更新，既难追踪 correction 方向又增加 Serving 成本。

现有问题 / 核心矛盾

只记正例 action 次数忽略偏好对比；只用 pairwise 方向又可能丢掉常用 action 身份。错误反馈晚到、临时反馈和版本不匹配还可能污染用户画像。

技术方案与关键模块

冻结 typed action scorer 不变，外层维护“重复 action 的保守通道”和“preferred-rejected 的快速修复通道”；每次 commit 后接 accept/revoke，依据 correction 给下一次决策追加两路校准分；采用有界最小更新、因果时间顺序与自适应通道权重。

训练方法 / Loss / 数据流程

没有运行时 LLM 反向传播；每次 typed feedback 更新用户状态的局部比较约束与动作计数/损失；使用顺序测试协议：只有先前 correction 可影响后续预测，禁止未来信息泄漏。

推理与 Serving 方案

在线每次只需一次冻结 scorer 评估候选 + 常数级轻量用户状态更新；不保留原始聊天历史，状态必须带 user_id、action vocabulary 和过期/重置策略，在线校准可独立灰度开关。

实验设置与 Baseline

作者构造 TCPA-Bench、TCPA-Repeat 及多个 feedback-depth 桶，与 Recent-4、在线梯度基线和历史 replay 等比较，按 user-macro accuracy 评估 correction 对后续决策的帮助。

离线指标与关键实验数字

TCPA-Repeat user-macro accuracy=44.83%，高于 Recent-4 2.43 个百分点；至少有两次此前反馈时 56.07%，领先最强对照 7.54 个百分点。需注意绝对精度仍有限，并非业务推荐 CTR。

线上 A/B 与证据边界

无生产 A/B 或长期满意度实验，也没有证据证明真实用户错误撤销率能稳定下降。

效率、成本与收益

论文设计不增加 scorer 调用和运行时梯度；节省历史上下文开销，但需要持久化的状态存储、冲突解决、隐私合规与数据治理。

与主流方法的优劣势

比 history replay 更低 token 成本，且纠错方向显式；比完整在线微调更轻量但表达能力有限，对新 item/action 以及语义漂移可能欠拟合。

适用业务场景

评价列表“替换/不喜欢此条”、搜索结果纠错、购物 Agent typed decision；无显式撤销语义的隐式点击不可等价套用。

局限 / 未解决问题

评估主要是合成/构造的 typed feedback，缺少线上真实噪声和隐式偏差；跨用户迁移、过期偏好与新 action 泛化不明确。

未来研究方向与工程 / 职业启发

结合 List-level reward 和 DPO，建立 correction provenance 与可反事实回放的偏好状态；推荐工程重点是 user-state 版本治理、反事实 paired preference 与低成本在线校准。

研究承接：LARA 先定义检索结果的测量对象及跨轮 lineage → Jev-DLC 利用明确纠错记录局部偏好 → IRAH 以可信离线指标搜 pipeline，而不是在评价器失真时继续优化；GRIP 以稀疏结构加快 ANN → FlexVDR 让视觉检索按查询动态支付预算 → BeNice! 在循环网络中降低 KV 的重复内存；BGAFlow 解决跨域信息污染 → Chunking 研究把内容修订的重新编码成本纳入全链路。
