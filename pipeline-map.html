召回 / 粗排 / 精排 / 重排 / 跨阶段统一

今天最重要的变化不只发生在某一层，而是在链路控制面：CORAL 用 Agent 持续调 retrieval budget / Serving treatment；PRO-Step 把 retrieval/reasoning 的 credit 下沉到每一步；Declarative Attention 让下游模型自己声明 context/attention 预算；Spotify Shunt 与 NVIDIA PAIR 则把 runtime routing 分别推到 worker 与 device。推荐系统正在从“各阶段各自优化”转成 Intent × Constraint × State × Compute × Experiment Feedback 的统一控制。

今日链路判断：在召回层，CORAL 证明候选源预算本身就是高杠杆优化对象，Persistent Discovery Context 提供历史 source/object prior，PRO-Step 要求 retrieval step 有证据级 reward；在精排层，DS-Frame 已经让样本决定是否进入 slow path；在重排层，GAREN / PRO-Step 让 reranker 与 search trajectory 更紧地融合；在跨阶段，Declarative Attention、Spotify Shunt、NVIDIA PAIR 说明 compute budget 要贯穿上下文、模型和设备。

Tab 02 · 粗排 / Pre-ranking

Candidate Preservation × Source Calibration × Stop / Route Signal

当前核心矛盾：候选来源已经从几个 ANN channel 扩展为 variable interest、GR beam、multimodal I2I、graph expansion、Agent tool retrieval、persistent memory。粗排不能只做“小精排”，还要解决 source 分布、候选重叠、预算与路径可追踪。

CORAL 启发：如果控制层在调 source budget，粗排必须反向提供 source retained ratio、incremental coverage、downstream value 与 unit serving cost，否则 Agent 只能看到粗粒度 outcome。

PRO-Step 启发：每个 candidate/path 可以带 evidence-validity / process-quality signal，而不是只留最终 relevance score。

Persistent Discovery Context 启发：历史 source/object memory 可做 routing prior，但粗排要负责 freshness 与冲突校验，避免旧 memory 直接污染候选。

Declarative Attention 启发：候选数、上下文数与下游 attention scope 可共享一个 stop/confidence controller，而不是每阶段固定 K。

评价建议：Top-K retention、source retained ratio、candidate overlap、incremental source value、long-tail/cold-start coverage、constraint violation、memory freshness、feature freshness、state build cost、p95/p99 与 downstream lift。

CORAL · Ranking/Serving Control Above the Model

CORAL 的意义在于：精排模型本身可能不变，Agent 仍可通过 segment treatment、budget 或 Serving allocation 改善系统 Pareto。未来 ranker 需要输出 uncertainty、expected marginal gain、compute demand 等控制信号，而不只是 score。

通过错误前缀训练缓解 teacher-forcing exposure bias；生产 user conversion +0.26%。它与 TAAL / PRO-Step 共同提示：generative state / trajectory 的错误传播必须显式训练。

精排值得押注：Time-to-event + Causal Value + Calibrated State + Adaptive Compute + Control Signal。下一代 ranker 不只决定 item score，还可能决定自己是否需要多算、请求哪些 context，甚至是否值得进入更贵模型。
Tab 04 · 重排与混排 / Re-ranking

Listwise Utility → Relevance Guard → Search-space Planning → Process Verification

PRO-Step · Process-level Credit

把“最终答案正确”拆成中间逻辑是否有效、当前证据是否支持。对应推荐/搜索，可对 query rewrite、source choice、candidate expansion、listwise decision 单独建立 reward / preference。

GAREN · Reranker as Retrieval Navigator

轻量 navigator 将 reranking signal 前移到 group expansion，决定下一轮候选空间；说明 reranker 不必等候选全集生成后才工作。

ICEGR RCPO · Relevance-guarded Business Preference

先限制语义相关集合，再用 click/pay/GMV 做 preference；避免商业 reward 把 relevance 冲掉。

TAAL PMI · Beam Survivor Calibration

只在完整 beam survivor 上做 O(B) PMI calibration，把生成式推荐的 rerank 扩展到 sequence level。

OC-SFT · Order-consistent LLM Scoring

presentation order 会影响 retained set；把 permutation consistency 训练进 scorer，代表 listwise stability 方向。

重排值得押注：Listwise utility、source/group quota、relevance guard、process validity、order invariance、risk/calibration、decision flip rate、search-space navigation、long-term value。

SPAR / ICEGR · Structure & Intent Contract

SPAR 让空间结构同时进入 SID、CPT、SFT；ICEGR 让 Query Intent 同时进入 SID construction、SFT、preference、beam serving。两者共同说明：跨阶段统一的关键是“约束/意图一致”，不是模型外形一致。

PRO-Step / CHIME · Credit & Memory Contract

PRO-Step 把 reward 下沉到过程，CHIME 在写长期 memory 前先做 outcome attribution。若与 CORAL 结合，下一代推荐自治系统会同时拥有：可操作控制面、A/B 反馈、过程 credit、结构化 memory 和 budget router。

跨阶段值得押注：Agentic Control Plane + Unified Budget Router + Process Credit + Structured Memory。最终 dashboard 不应只看 AUC/NDCG，而要同时看 source marginal value、constraint violation、decision stability、p95/p99、GPU-ms、dollar cost、实验增量与 memory attribution quality。
