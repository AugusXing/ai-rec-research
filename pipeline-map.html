召回 → 粗排 → 精排 → 重排 / 混排 → 跨阶段统一：今天新增的是 Intent、Set Coverage 与 State

今天最值得带回真实推荐链路的不是“再加一个 LLM”，而是三种新的中间表示：Hypothesis/Intent 告诉系统想构造什么供给；Missing Complement 告诉下一路召回应补什么；State/Trajectory 告诉系统用户或案例现在走到哪一步。它们让各阶段 executor 保持可控，同时给统一 controller 更强的决策信号。

链路总判断：未来一年更现实的工业架构是：多路召回 + intent planner + set-coverage controller + query/state-conditioned retrieval + foundation ranker + list-level alignment + mature final ranker + versioned user/session state + Agentic Serving/RecOps。训练目标会越来越联合，但在线仍需要按阶段隔离延迟、故障域和 rollback。

召回 / Retrieval

Semantic ID、Hypothesis-conditioned retrieval、multi-interest、set sufficiency、stateful case retrieval。

粗排 / Pre-ranking

Verifier、source survival、受控 generative fast lane、集合 coverage 检查。

精排 / Ranking

Foundation Ranker、long-history / language-readable user state、跨任务迁移。

重排与混排

Shelf/list alignment、约束、多目标、selective escalation 与 human/agent dual audience。

跨阶段统一

统一 intent/state/budget/controller，动态选择 source、model、tool、harness 与 Serving 路径。

Tab 01 · 召回 / Retrieval

从“每路固定 Top-K”走向“Intent + Address + Coverage + Budget + State”

链路矛盾：ANN、协同、多兴趣、生成式召回、搜索检索通常独立追求 relevance / Recall@K，导致 source overlap 高、长尾 intent 覆盖不足，而且 query 难度和用户 state 不同却拿相同 budget。

Spotify Hypothesis-Driven Shelf · Intent-conditioned Supply

先生成自然语言 shelf hypothesis，再用 constrained generative retrieval 在 catalogue 中履约。它把“召回 query”从用户 embedding / 固定模板升级成可读、可评估的动态推荐意图。

MSS-Complement · Set-level Sufficiency Retrieval

不是给候选逐个打 relevance，而是看已有集合覆盖了哪些必要事实、下一次检索还缺什么。Complete-MSS@5 从 Qwen3 embedding+rerank 的 61.4% 提到 73.0%。

RAFT · State-addressable Retrieval

将历史 case 拆成 timeline entries，按当前 active state 命中历史中间态，再回取后续 trajectory。推荐可迁移为 session/funnel-state recall。

VARG · Value-aware Semantic ID

让 SID 不只表达语义，还把 downstream value / ranker advantage 写进生成空间；Tmall 14-day A/B GMV +1.45%。

工程落点：召回 controller 的动作空间应从“source 各出多少 Top-K”升级为 intent / source / index / state / fan-out / coverage target / access budget / expert budget。建议新增 source overlap、marginal coverage、final-rank survival 与 incremental GMV/compute 指标。

Tab 02 · 粗排 / Pre-ranking

粗排从“统一轻模型过滤”走向“Source-aware Survival + Verifier + Controlled Fast Lane”

链路矛盾：召回池里有 item 不代表下游真正看得到；生成式候选分布与传统 ANN 候选不同，统一粗排可能误杀；盲目扩大 K 又会拉高延迟。

Generative Verifier / Recommendation Retrievers Need Verifiers

对 deep candidate pool 做额外 verification，使真正高价值 item 更可能进入 downstream consumed prefix；本质上把优化目标从 Recall@1000 改成“Survival@Consumed-K”。

VARG · Generative Reserved Quota

生成式候选通过受控 quota 接入成熟 final ranker，不强迫它先通过为传统 source 训练的 item-level pre-rank；体现“训练目标更联合、Serving 仍分阶段”的工业折中。

9/19 新启发：MSS-Complement 的 set sufficiency 可以进入粗排：如果当前 consumed prefix 已经高度重复，粗排不应继续按 pointwise score 填满，而应为缺失兴趣 / 属性 / source 留 quota。

工程落点：建立 source-specific calibration、survival curve、marginal coverage / compute、quota elasticity；任何 bypass 都保留安全、合规、多样性硬约束。

Tab 03 · 精排 / Ranking

Foundation Ranker + Versioned User State：从“最近行为监督”走向多时间尺度偏好建模

LazFormer · Transferable Foundation Ranker

一年行为 autoregressive pretraining，同时迁移 sparse+dense；residual adapter 隔离 ranking-specific feature；线上 Orders +3.38%、GMV +9.85%，A10 QPS 仅 -12.1%。

ChronicleRec / LION · Cacheable Long-term State + Mutable Preference Delta

ChronicleRec 将长期历史压成 target-independent cacheable state；LION 给持续偏好变化独立 sparse KV memory，避免频繁更新污染共享 decoder。

链路意义：精排输入逐步从“固定用户 embedding + recent seq”升级为 long-term backbone state + medium-term chronicle + high-frequency session/delta state。

9/19 新连接：RAFT 的 state-addressable trajectory 提示精排不仅可以读一个 summary，还可根据当前 funnel/session state 检索历史“类似阶段之后发生了什么”；Spotify RecSys 专题中的 Textual User Taste 则说明自然语言 preference state 正进入 foundation-model recommendation。

工程落点：所有 user state 都应具备 version、refresh cadence、TTL、feature lineage、fallback 与 rollback。研究重点从“序列长度”转向“状态放在哪里、多久更新一次、谁消费它”。

Tab 04 · 重排与混排

从 List Score 到“集合兑现、约束、Dual-audience 与 Selective Escalation”

Shelf Alignment · Title Promise ↔ Item Set

Spotify 在 retrieval 后再做 candidate selection 与 title/subtitle alignment，解决“标题承诺一个主题、实际 item 不兑现”的 set-level mismatch。它是典型的生成式 reranking / presentation alignment。

CoSQ / Selective Escalation

重排不只输出顺序，也要输出“当前 evidence / candidate 是否足够”。低置信时扩大 retrieval、切换强 reranker/model 或 abstain。

Dual-audience Reranking

当结果可能先被 Agent 消费，排序除了 engagement，还需要 machine-readable constraints、provenance 与可验证 outcome；未来 human-facing ranking 与 agent-facing selection 可能需要两套 utility 或联合目标。

工程落点：重排层要显式维护 diversity / novelty / business constraints / intent fulfilment / agent-readable attributes，并记录每次 list transform 的 provenance，便于回放与归因。

Tab 05 · 跨阶段统一

统一的不是“一个模型”，而是 Intent / State / Budget / Evaluation / Control Plane

阶段边界为什么不会消失：召回、粗排、精排、重排有不同候选规模、特征、延迟与故障半径；在线完全端到端化不利于 fallback、容量规划和实验隔离。

Query-conditioned Retrieval Controller

DiBud → ORDER → DRAG → DUPAR → MSS-Complement：controller 从“调 Top-K”扩展到选 index/source/retriever/generator/cache，并开始根据当前 state 缺口决定检索目标。

Model / Tool / Harness Routing

Harness Study 表明 planning、structured tools、context management 的收益随模型能力和 context budget 变化，因此 routing 动作空间必须超越 model selection。

Harness / Serving Economics

SoL-Pi 说明成本优化不能只盯 kernel/QPS；重复 context、observation、tool boundary 本身就是巨大的“应用层 Serving 成本”。

Agentic RecOps / Performance Control

AURA 从生产 engagement log 诊断 failure 并走向 code refinement；FlashVector 让 Agent 跨 kernel→graph→server→feature service 优化。未来控制面会同时负责质量、成本与变更安全。

统一目标建议：Expected long-term utility - latency cost - compute/token cost - risk penalty，并为每个 stage 保留 hard guardrail、shadow replay、canary、A/B 与 rollback。

工程优先级：如果当前团队还是传统多阶段推荐，最值得先做的不是一次性端到端生成，而是：① 给召回加 source overlap / coverage / survival 指标；② 把用户长期状态做 versioned cache；③ 建 query/session-conditioned budget controller；④ 为新生成式 source 建 reserved quota + mature final-ranker gate；⑤ 建集合级 judge / alignment；⑥ 把 Agent 的 context / tool / observation 成本纳入 Serving 指标。
