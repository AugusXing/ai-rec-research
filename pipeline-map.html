Recommendation Pipeline Map · 更新至 2026.09.17

把研究放回真实推荐链路：召回 → 粗排 → 精排 → 重排 / 混排 → 跨阶段统一

今天的变化不在某一个 stage，而在控制面：ORDER 让 Query 先选择 index / chunking / source / reranker；AURA 让 Agent 从生产日志定位推荐失败并走向代码级 refinement；FlashVector 让 Agent 跨 kernel / graph / server / feature service 优化 Serving。下一代推荐系统会保留 stage-local executor，但把更多配置、预算、状态与诊断交给统一 controller。

链路总判断：推荐 / 搜索不会简单被一个大模型“端到端吞掉”。更现实的形态是：多路召回 + query-conditioned retrieval plan + verifier / budget controller + foundation ranker + list-level reranker + versioned user state + Agentic RecOps / Serving control plane。训练目标更联合，在线执行仍按 stage 隔离故障域和成本。

召回 / Retrieval

Semantic ID、多兴趣、MoE Retriever、RAG index routing、budgeted hybrid retrieval。

粗排 / Pre-ranking

Consumed-prefix verification、generative fast lane、downstream-aware candidate filtering。

精排 / Ranking

Foundation Ranker、long-history state、continual memory、task-aware backbone。

重排与混排

List-level reasoning、first-move planning、selective escalation、约束与多目标。

跨阶段统一

共享 state / preference / cost / survival signal，Agentic diagnosis 与性能控制面。

Tab 01 · 召回 / Retrieval

召回从“固定多路 Top-K”走向“Address + Ownership + Budget + Route”

当前矛盾：传统召回把 ANN、协同、多兴趣、稀疏检索、生成式召回分别独立调参，然后每路固定出 Top-K。问题是不同 query 的难度、业务价值、source overlap、索引结构和 downstream survival 差异巨大，固定 K 既浪费成本又不能保证 final value。

VARG · Value-aware Generative Retrieval

把 RQ-VAE 语义前缀与 value-aware 末级 token 结合，Prefix-GRPO 对齐合法 SID、用户行为、搜索相关性和现有 ranker advantage；Tmall 14-day A/B GMV +1.45%。

Tab 02 · 粗排 / Pre-ranking

粗排从统一过滤器，分化成“常规 cascade + 受控 Generative Fast Lane + Verifier”

当前矛盾：召回池的 Recall@1000 并不能保证粗排真正消费的 Top-100 仍有足够 relevant / high-value item。为了保 recall 盲目扩大 K 会直接拉高粗排成本，而生成式候选强行走传统轻模型又可能因为特征/分布不匹配被错误过滤。

Recommendation Retrievers Need Verifiers

冻结 retriever，对 deep candidate pool 做 generative likelihood verification，再把更可能有价值的 item 推进 consumed prefix。它把 recall 指标从“池里有没有”改成“下游真正能不能看到”。

Tab 03 · 精排 / Ranking

落地优先级 · 推荐算法工程

如果你要把这些论文变成项目，先做什么？

P0：把现有 pipeline 的 source / Top-K / rerank / model cost 做成 request-level 可观测数据；没有 cost & survival telemetry，就无法做 routing。
P1：做 recall source 的 downstream survival / marginal GMV attribution，识别“召回到了但死在粗排”的问题。
P2：把 user state 从“每 request 重算”拆成 cacheable long-term state + mutable recent state。
P3：引入 query-conditioned route：先从 source / K / reranker 选择开始，再扩到 index / expert / model。
P4：建设 bad-case diagnosis harness 与 performance regression harness，为 AURA / FlashVector 式 Agentic RecOps 做准备。
P5：任何自动修改都必须经过 offline replay → shadow/canary → A/B → rollback gate，绝不能把 self-improving 等同于 self-deploying。
