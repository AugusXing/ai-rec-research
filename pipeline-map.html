召回 / 粗排 / 精排 / 重排与混排 / 跨阶段统一

今天最重要的链路变化，是“每一阶段各自算一遍”开始让位于“共享状态 + 可复用计算 + 动态预算”。召回侧，EPIC / HypRQ-VAE 分别把 Semantic ID 的 item posterior 与 long-tail geometry 做成一级问题；精排侧，UniCon 把一次曝光 context 变成统一建模单位；重排侧，DoPR 把 document-side LLM compute 离线资产化；跨阶段侧，SelfDR 与 CORAL 分别说明 reasoning path 与系统预算都可以被动态控制。

今日链路判断：召回要解决 namespace、item-level hypothesis 与 freshness；粗排的核心不是强塞更大的模型，而是共享上游 state 并学会 request-aware compute；精排正在从 user-item pair 走向 context/slate state；重排开始重构 offline/online boundary；跨阶段最终会统一 user/context state、item/document state、budget 与 experiment feedback。

Masked-diffusion SID 的问题是 partial code 对应很多完整 item，逐 token 决策可能提前杀死最优 item。EPIC 在每一步构造 personalized complete-item posterior，再 marginalize 回未决 SID 位；4 个 Amazon 数据集的 16 个 metric×dataset 组合均取得最佳均值，较每列第二名提升 1.2%–16.8%。代价是 inference latency 约 +34.2%。Paper

HypRQ-VAE · Hyperbolic Semantic ID for Long-tail Catalogue

Research Impact Score / 研究价值 9.1/10工业成熟度 ★★★☆☆创新性 ★★★★★与你方向的相关度 ★★★★★是否官方开源 是是否有线上 A/B 否阅读优先级 最高

把 Euclidean RQ-VAE 改成 hyperbolic quantization，用负曲率空间的指数体积扩张承载幂律 catalogue，再用 cascading reassignment 解决 collision。MovieLens tail Hit@10 相对 Euclidean TIGER 提升超过 52.71%；Instruments NDCG@10 相对 strongest baseline +14.0%。Paper · Code

链路承接：此前 SetMIR 解决 variable-size multi-interest 与 ANN query budget，ICEGR 解决 query-intent coherent SID + preference，SPAR 将地理 topology 写进 SID。EPIC / HypRQ-VAE 又把问题向前推进到 complete-item inference × representation geometry。下一步应联合 freshness、库存/地理/价格约束、prefix survival 与 dynamic catalogue。

Tab 02 · 粗排 / Pre-ranking

固定轻模型 → Shared State + Request-aware Compute

过去 24 小时没有一篇足够重要、且证据扎实的新粗排论文，本站不为“每个 Tab 都塞新 Paper”而降低筛选标准。当前更值得跟踪的是两条承接关系：

第一，state 复用。召回已经在输出 multi-interest / SID / context state，精排又在重新构造用户与候选上下文；粗排应该成为这些 state 的低成本消费者，而不是从 raw feature 重算一遍。

第二，动态计算。DS-Frame / AdaWidth 一类工作已经说明 easy/hard request 不必走相同深度；UniCon 的 context compression、DoPR 的 prefix budget 又提供了可借鉴的 policy：先估计 marginal utility，再决定保留多少 context、候选或层数。

值得押注：user/context state distillation、source-aware pre-rank、candidate-set aware shallow interaction、early-exit / width routing、粗排与精排共享 backbone cache，以及直接以 recall@K × latency × downstream value 训练 budget controller。

SelfDR · Reasoning Benefit without Online Reasoning Tax

Research Impact Score / 研究价值 9.0/10工业成熟度 ★★★★☆创新性 ★★★★☆与你方向的相关度 ★★★★★是否官方开源 是是否有线上 A/B 否阅读优先级 最高

用同一 LLM 依次训练 reasoner → reasoning-enhanced teacher → direct student，以 reverse-KL + ground-truth CE 蒸馏。Clothing 上 student 只输出 1 token，109.46ms/instance，几乎等于无 reasoning SOFT 109.48ms；而多种 test-time reasoning baseline 为 250–665ms。说明精排中的 reasoning 更适合作为训练期监督和 hard-case slow path，而不是默认线上输出。Paper · Code

链路判断：未来精排的核心输入不再只是 user embedding + item features，而是 historical contexts + current candidate/slate + reusable user state + request budget；模型能力与 Serving 压缩必须一起设计。

Tab 04 · 重排与混排 / Reranking & Blending

Full Cross-encoder Every Time → Reusable Prefix + Query-time Lightweight Scoring

DoPR · Reusable Compressed Document Prefix

Research Impact Score / 研究价值 9.5/10工业成熟度 ★★★★☆创新性 ★★★★★与你方向的相关度 ★★★★★是否官方开源 是是否有线上 A/B 否阅读优先级 最高

训练一个 document representation bottleneck，离线将选中的 document states 转成多层 prefix KV；同一文档被多个 query 反复召回时，线上只需跑 query + score token。Qwen3 0.6B/4B/8B 平均 NDCG@10 retention 97.1% / 99.3% / 99.5%，最高 8.04× latency speedup、8× document-state reduction。Paper · Code

对混排的启发：如果商品/内容的高成本语义状态能提前构建，混排阶段就可以把在线预算集中在 query/user 与 list interaction 上，而不是重复编码 item。下一步非常值得研究 prefix state + listwise/slate interaction + diversity/business constraints，以及 prefix 的冷热分层、量化、版本和失效策略。

跨阶段下一步：把召回的 source/interest budget、粗排 depth、精排 context keep ratio、重排 prefix budget、reasoning slow path、model/device route 放进一个 marginal utility per GPU-ms / dollar 的统一 controller；同时让 user/context state、item/document state 与实验结果可以跨 stage 复用。统一的目标不是“一模型吃掉所有阶段”，而是一套状态与预算 Contract。
