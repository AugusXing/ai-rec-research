召回 / 粗排 / 精排 / 重排 / 跨阶段统一

这里不按模型名字分类，而按工业推荐链路判断论文落在哪里。8 月 28 日的新变化尤其明显：召回开始可编程、精排开始拓扑化、用户状态开始跨阶段共享、研发闭环开始自动演进。这意味着未来的“跨阶段统一”不只是 One Model，也包括 Shared State、Shared Retrieval Language 与 Evolution Control Plane。

今天的链路判断：ProRetrieval / Live Catalogue 直接改变召回与搜索入口；Scaling GNN 把复杂图计算离线化后作为精排特征进入在线 ranker；MaskRec 是最典型的精排统一 Backbone；CoVeMem 目前是 Agentic ranking，但其 Collaborative State 更有价值的方向是跨召回/精排共享；Astar 则不属于一次请求的任何单阶段，它位于整条推荐链路的研发控制面。
Tab 01 · 召回 / Retrieval

从固定召回器到 Fresh、Programmable Retrieval

链路演进：Two-Tower ANN → Semantic ID / Generative Retrieval → Hybrid Dense×Structured → Typed Retrieval Program。传统召回优化的是 embedding 与 ANN；现在还要优化 namespace freshness、backend selection 与执行逻辑。

长期入口

继续沿 TIGER / OneRec / TAGR / Tlow / Dynamic SID / ProRetrieval 阅读：前一组解决“直接生成哪个 item”，后一组解决“复杂 query 应该调用哪些检索器”。最值得押注的是二者的混合 router。

Tab 02 · 粗排 / Pre-ranking

粗排没有消失，但研究重点从独立小模型转向 Budgeted Information Filtering

当前核心矛盾：粗排需要在数百/数千候选上保住精排排序，同时 latency 和 feature cost 极低。近期真正值得迁移到粗排的不是某个“粗排专用 Transformer”，而是 AdaWidth、candidate-aware state、teacher distillation 与动态 compute。

今天的新启发：Scaling GNN 选择把昂贵多跳图计算完全前移为离线 embedding，再让在线 ranker 只读一个 feature；同样思路可用于粗排：把 expensive state construction 离线/异步化，在线只做 cheap interaction。MaskRec 的 topology mask 也提示，粗排可通过限制 token connectivity 控制计算量，而不必直接砍掉所有序列信息。

值得押注：Teacher-preserving pre-rank、request-aware token pruning、candidate-aware small query token、动态 embedding width、Shared User State。评价不要只看 AUC，还要看 Top-K consistency、recall loss 与 p99 latency。

Tab 04 · 重排与混排 / Re-ranking

从 Score Fusion 到 Risk / Context / Evidence-aware Decision

主线：DPP/MMR 只显式处理相关性与多样性；近一年开始加入 CAIRO 式 context selection、risk-aware rerank、trigger state、EviGraph evidence process。今天没有新的纯 Re-ranking 论文进入 Top5，但 ProRetrieval 带来一个重要迁移：重排策略也可以程序化，把 diversity、business rule、risk filter、LLM judge 作为 typed operators 由 policy 选择，而不是长期维护手写流水线。

与 MaskRec 的连接：重排若逐渐前移到 unified backbone，核心问题会从“最后 20 个怎么调权重”变成“哪些 candidate-candidate / candidate-context 信息允许互相流动”。Topology-aware set modeling 值得重点跟踪。

值得押注：Listwise utility model、risk-aware constrained optimization、candidate-set graph、LLM judge distillation、programmatic reranking，以及将 diversity / monetization / safety / latency 合成可解释 constraint layer。

ES 的更高 reasoning coverage / Pass@K 对生成式召回有直接研究启发：跨阶段统一模型若只用 preference RL 压 Top-1，很可能损害 candidate coverage；未来应把 Recall Coverage、Novelty 与 Downstream Utility 联合进 policy objective。Paper

跨阶段终局判断：真正统一的推荐系统将至少共享四种资产：① User/Item State；② Semantic Namespace / Fresh Index；③ Teacher / Reward Model；④ Runtime / Retrieval Control Policy。Backbone 是否完全同一个反而是次要问题。

工程优先级：如果目标是未来 1–2 年推荐/搜索落地能力，优先补齐：召回：Semantic ID + Hybrid Retrieval + ANN/Index Freshness；精排：Long Sequence + Candidate-aware Interaction + Unified/Topology Routing；重排：Listwise Utility + Constraint/Risk；跨阶段：Shared State + Reward/Teacher + GPU Serving + Algorithm Agent / Experiment Infrastructure。
