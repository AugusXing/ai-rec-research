Stage 仍然是理解工业推荐系统的好坐标，但 2026 年的变化是：Stage 之前开始出现可学习的 Eligibility / Lifecycle Filter，Stage 内部出现 Elastic/Unified Model，Stage 之后的离线评估开始预测真实 Traffic Allocation。Pipeline 正从固定流水线变成可按请求、内容状态和系统预算调节的计算图。

00 · Eligibility / Lifecycle

排序之前先回答：这个候选还值得进入后续计算吗？

传统推荐常把 Freshness、Quality、Safety、Inventory 等都做成 Ranker Feature；Google Discover SDF 提供了更强的工业范式：把 Staleness 拆成 Relational Supersession 与 Intrinsic Decay，在 Request Path 之外计算并缓存，先过滤明显不值得排序的 Item。

02 · Pre-ranking / Early-stage Ranking

03 · Ranking

精排：Transformer-native → Sequence/Interaction Unified → Allocation-aware

模型结构只是其中一层；更高价值的问题已经变成：上游预测是否可信？序列与字段如何统一？每个请求该算多少？候选模型上线后会怎样改变整个系统的流量分配？

05 · Cross-stage Unification / Runtime / Evaluation

跨阶段统一：Model Graph + Dynamic Compute + System Counterfactual

真正值得押注的不是“把所有 Stage 一次性删掉”，而是让 Stage 共享表示、共享计算，并由一套 Runtime Policy 决定每个请求值得在哪些地方花多少预算；同时 Launch Decision 要预测这种选择对流量结构的后果。
