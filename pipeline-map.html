按线上链路看研究：召回 / 粗排 / 精排 / 重排与混排 / 跨阶段统一

传统 stage 仍然有用，但 2026 年最明显的变化是：召回开始带 ranking supervision，粗排开始吃 GPU/图特征，精排开始消费异步 user state，重排开始优化 context/slate utility，跨阶段开始出现 controller + counterfactual measurement。 因此这页同时标注“论文落在哪一段”与“它正在侵蚀哪一条 stage 边界”。

链路导航：召回 · 粗排 · 精排 · 重排与混排 · 跨阶段统一。当前优先投入：召回的 generative/heterogeneous portfolio；粗排的 GPU feature join；精排的 multi-timescale state；重排的 support/trust/set utility；跨阶段的 shared representation、controller、runtime 与 causal measurement。
Tab 01 · 召回 / Retrieval

从“相似度找候选”走向“目标、库存、长期状态与生成地址共同决定候选”

传统主线：BM25 / inverted index → DSSM / Two-Tower → ANN → multi-interest / long-history retrieval。现在形成三条并行路径：Semantic ID / Generative Retrieval、dense/sparse/late-interaction hybrid、hardware/inventory-tiered portfolio。

UNIQUE · Generative Code Retrieval + Ranking-supervised Representation

位置：Feed 第一阶段候选生成，同时向精排侵蚀。single-layer flat code + UIGN 生成 code distribution，随后 TDN 对 target 做判别式打分；retrieval 与 ranking 共享 early-fusion representation。

Tab 02 · 粗排 / Pre-ranking

从轻量 Pointwise Scoring 走向 GPU-resident Feature Join + Deep Pre-ranking

核心约束：粗排面对 10³–10⁴ 甚至更多候选，过去因此被默认“模型必须很小”。LinkedIn 的新证据表明，真正的先决条件是让高价值候选特征在 GPU 上能被低延迟 join。

Connected Content Retriever · Dense Graph Edge Features

位置：社交 Feed 粗排。网络内容索引 >1B，按 viewer network 收敛到数万；GPU sorted-search 在约 5–10ms 内 join viewer-author affinity 与文档特征，使 full deep ranking model 能直接用于 pre-ranking。

粗排的新工程问题

① feature join latency：模型快但查特征慢没有意义；② fan-out variance：候选数变化会破坏 batch efficiency；③ source-aware depth：不同召回源不必跑同样粗排深度；④ uncertainty escalation：top-band / 高不确定候选才升级更强模型。

值得押注：GPU feature store、graph edge cache、dynamic expert routing、P99-constrained FLOPs allocation，以及粗排与精排的模型容量重新分工。

Tab 03 · 精排 / Ranking

从 Feature Interaction 走向 Foundation Ranker + Multi-timescale User State + Continual Scaling

主线：Wide&Deep / DeepFM / DIN / DIEN → DCN / MMoE / PLE → long-sequence Transformer → HSTU/SORT/OneTrans → behavior pretraining / foundation ranking。

Multi-timescale State · MuSeR / Structured Memory 的共同启发

长期 preference、session intent、实时 feedback、文本 taste 更新频率完全不同。未来精排不应每请求扫描完整 history，而是消费多个带 freshness/TTL/version 的 state；ranker 负责 target-aware read，而 state service 负责异步维护。

Inherit4Rec · Continual Capacity Growth

位置：训练平台 / Ranking model lifecycle。D2D 解决模型扩容时 forward/update continuity；D2S 用 coactivation-aware partition 将 dense FFN 转为 sparse MoE，保留能力并控制激活成本。

Tab 04 · 重排与混排 / Re-ranking & Slate / Context

从规则/MMR 走向 List-level Reasoning、Evidence Sufficiency 与 Trust-aware Context Construction

为什么这一段潜力上升：最终候选规模小到可运行强 reasoning，同时要处理多样性、业务约束、生态与上下文预算；pointwise pCTR 已无法表达完整目标。

Answer-Oriented Context Construction · Support → Trust → Organization

位置：AI Search / RAG 最终 context stage。不再只问文档是否相关，而是是否支持回答、是否可信、在有限 token budget 内如何和其他证据组成最优 context。

MERIT-Rank / MSS-Complement · Reasoning + Set Sufficiency

MERIT-Rank 用 multi-trajectory reasoning 降低单链偏差；MSS-Complement 将目标从 point relevance 推到“当前集合还缺什么必要证据”。两者共同说明重排正在从 score(item) 转成 utility(item | current slate/context)。

RAVEL · Interactive Evidence Acquisition

clarifying question 的 reward 直接来自回答后 rank gain。把它迁移到推荐，可对应“什么时候追问偏好、什么时候扩候选、什么时候只重排现有 slate”。

值得押注：marginal slate gain、support/trust/novelty joint objective、uncertainty-triggered reasoning、verifier early exit、自然内容/广告/生态约束统一 list policy。

Tab 05 · 跨阶段统一 / Controller, Runtime & Measurement

真正的“全链路统一”不是删掉 stage，而是共享状态、目标、控制与归因

Shared Representation · UNIQUE

UNIQUE 给出一条现实路线：召回和排序共享 representation / training objective，但保留 code generation 与 target scoring 的不同 execution。它比“一模型吃掉全部 stage”更符合生产系统的回滚与 SLA 需求。

Learned Routing · Hybrid Retrieval + Google DLB

从 request 级选择 retrieval path，到 datacenter 级选择 serving cell，controller 的 action space 已经覆盖 model、inventory、hardware 与 deadline。下一步是把两层 router 合并成 quality-latency-cost-SLO policy。

State Ownership · H-Spec

H-Spec 说明 runtime 统一还包括“谁持有状态”。drafter 不再重复维护 KV，而是复用 target KV + last hidden state。

Experiment Verification · EvoPilot

Agentic R&D 要求 artifact、候选深度、数据窗口、metric definition 可比较；实验 verifier 与 counterfactual measurement 共同构成未来算法平台的“证据层”。

落地优先级

如果以推荐算法工程团队的 ROI 排序

近期（0–3 个月）：补齐 candidate source / model version / propensity logging；监控 feature-join latency、state freshness、distinct experts、KV footprint。
中期（3–9 个月）：做 GPU pre-rank PoC；把长期用户状态异步化；统一 retrieval/ranking 一部分 backbone；引入 retrieval confidence gate。
长期（9–18 个月）：训练 request-level controller，把 path/K/depth/model/hardware 变成可学习动作；构建跨阶段 counterfactual measurement 与 Agentic experiment verifier。
