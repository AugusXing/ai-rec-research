工程落地顺序

近期最现实的路径不是直接用 Generative Retrieval 替掉 ANN，而是：Dense ANN 主路径 + SID/Reasoning 监督 + Geometry-aware Compression + Query-value Router。RecPFN 适合冷启/跨域快速适配，CrossQ 适合需要 ColBERT 细粒度匹配但索引成本受限的搜索/RAG。

工程落地

最值得迁移的是 OneModel 的系统拆法：离线/增量维护 Shared User State，在线只做 candidate scoring；复杂 backbone 不一定进入每次 request 的完整 hot path。下一步要解决跨场景梯度冲突、低资源场景获益与高资源场景退化之间的动态路由。

跨阶段统一的落地结构

Foundation User / Item State→Dense / SID / Late-interaction Recall Router→Elastic Pre-rank→Foundation Ranker→Stateful Re-rank→Runtime / Cache / Hardware Policy

2026 年最值得研究的不是“是否取消召回/粗排/精排”，而是哪些 representation、teacher、memory 与 serving asset 可以跨阶段复用，哪些请求值得走更重的生成/推理路径。

推荐算法工程师精读顺序

按落地收益排序

第一层：精排主线——OneModel → RankMixer / OneRank，理解 Shared State 与 Transformer-native ranking；
第二层：召回主线——SSR-GRPO → Think-to-Personalize → CrossQ，理解结构监督、个性化 reasoning 与 index cost；
第三层：下一代适应——RecPFN，理解 synthetic prior + support retrieval + amortized inference；
第四层：系统化——CacheRoute → vLLM/SGLang Runtime Contract，理解模型收益如何真正变成稳定 QPS / SLO。
