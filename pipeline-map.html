按线上链路看研究：召回 / 粗排 / 精排 / 重排与混排 / 跨阶段统一

这页不按论文主题，而按“它会落到推荐/搜索链路的哪一段”组织。2026 年最明显的变化是：传统 stage 仍存在，但每个 stage 前后都在长出 Controller。9 月 22 日又把两个关键控制点补齐：召回前后的 confidence / inventory-path routing，以及跨 stage 之外的 experiment verification + global serving routing。

链路导航：召回 · 粗排 · 精排 · 重排与混排 · 跨阶段统一。当前优先投入：召回的 objective-specific generative policy + heterogeneous hybrid retrieval + confidence gate；重排的 multi-trajectory / set-level reasoning；跨阶段的 state/budget/controller；底层的 architecture-aware runtime、global routing 与 experiment verifier。
Tab 01 · 召回 / Retrieval

从“相似度找候选”走向“目标、库存层级、硬件、置信度与覆盖共同决定候选”

传统主线：BM25 / inverted index → DSSM / Two-Tower → ANN → multi-interest / long-history retrieval。2026 年形成三条并行路线：① Semantic ID / Generative Retrieval；② dense + sparse + late-interaction hybrid；③ hardware/inventory-tiered retrieval portfolio。

位置：搜索广告 / 高价值早期召回。objective prefix + sparse MoE-LoRA + objective-specific residual FFN，让 relevance / CTR / commercial value 各自形成 policy，再在 fixed candidate budget 下并行 beam search。

Tab 02 · 粗排 / Pre-ranking

从轻量 Pointwise Scoring 走向“候选价值 × 计算预算”的动态分配

核心约束：粗排面对 10³～10⁴ 候选，单候选预算远低于精排。重点仍是 interaction 压缩、蒸馏、量化、shared embedding 与 candidate pruning，而不是给每个候选跑完整 LLM reasoning。

Hybrid Retrieval 的启发：如果上游 GPU 路径已经做 interaction pre-ranking，粗排不应无视 source attribution 再从零统一打分；source/path 本身应成为 feature，甚至决定不同 candidate 使用不同粗排 depth。

Runtime 的启发：Qwen4 sparse FA、mHC fusion/overlap 都在按 shape 选择 fast path。迁移到粗排，就是 candidate uncertainty + source + request shape → feature/expert/depth path。top-band 候选升级强模型，明显负例早退。

值得押注：dynamic expert routing、top-band escalation、source-aware distillation、P99 约束下 FLOPs allocation、router/expert 不同量化精度，以及 recall confidence 进入 pre-rank budget。

Tab 03 · 精排 / Ranking

从 Feature Interaction 走向 Foundation Ranker + Multi-timescale User State

主线：Wide&Deep / DeepFM / DIN / DIEN → DCN / MMoE / PLE → long-sequence Transformer → HSTU/SORT/OneTrans 类 foundation ranking → generative behavior pretraining + adapters。

当前核心矛盾：模型能读更长历史，但长期 preference、session intent、实时反馈、自然语言 taste 与业务 context 的更新频率不同。每次从头重算完整 history 既贵，也难保证 state 一致性。

AutoViewMem · Write-time Structured User State

AutoViewMem 虽是 Agent memory 论文，但对推荐精排很有启发：把 preference/event/constraint/temporal update 拆成自配置 view，写入时结构化、读时仍用普通 Top-K。用户画像可从“一个 embedding”升级成“带 provenance/TTL 的多视图 memory”。

值得押注：long-term backbone + mid-term chronicle + short-term session；target-aware history retrieval；memory TTL/version/conflict；foundation ranker 与 small adapter 的多更新周期。

Tab 04 · 重排与混排 / Re-ranking & Slate Optimization

从规则 / MMR 走向 List-level、Reasoning、Coverage 与 Interactive Evidence

为什么这一段研究潜力上升：重排接近最终曝光，候选规模小到可以使用更强 reasoning；同时要统一多样性、业务约束、内容生态、广告/自然内容混排，比单候选 CTR 预测更接近真实目标。

MERIT-Rank · Multi-Trajectory Reasoning

位置：复杂 query 的高成本 reranker。从多视角生成 reasoning path，再由 joint reranker 汇总；PRPO 分阶段对齐 reasoning 与 ranking。

RAVEL · Retrieval-aware Clarification

Tab 05 · 跨阶段统一 / Cross-stage Controller & Serving Substrate

“One Model”不是终点，更可能的终点是“Shared Representation + Unified Controller + Verifiable Harness + Runtime Control Plane”

传统问题：召回、粗排、精排、重排分别训练，stage objective mismatch 严重；但把所有能力硬塞一个模型又会带来 Serving 成本、业务隔离、解释与回滚困难。

跨阶段长期 action space：{retrieval source/index, inventory tier, candidate budget, retrieval confidence action, pre-rank depth, rank model, rerank trajectories, business objective policy, memory view, model/tool, attention mode, precision, draft mode, hardware cell, halt/abstain, experiment admission}。优化目标应从单一 CTR/NDCG 升级为 task utility − latency − cost − risk under business constraints。

工程底座：state ownership/version、effective config validation、path attribution、retrieval confidence、hardware capability graph、latency model、dataset/evaluator fingerprint、correctness + performance + experiment-validity unified CI。

链路视角的研究优先级：未来 2–3 年推荐/搜索算法竞争力，优先顺序建议：① 召回的 generative + heterogeneous hybrid + confidence routing；② 重排/混排 reasoning + multi-objective；③ 跨阶段 controller / RL；④ foundation ranker 的 structured state/memory；⑤ architecture-aware Serving + global routing；⑥ verifiable algorithm-agent experimentation。单纯把传统精排再堆一层 MLP/Transformer，边际研究价值会继续下降。
