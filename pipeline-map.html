按线上链路看研究：召回 / 粗排 / 精排 / 重排与混排 / 跨阶段统一

这页不按论文主题，而按“它会落到推荐/搜索链路的哪一段”组织。2026 年最明显的变化是：传统 stage 仍然存在，但 stage 之间正在加入更多 Controller；与此同时，9 月 21 日的工程更新进一步说明，Controller 之下还必须有一个可靠的 Serving substrate，让 state/cache/precision/kernel 不破坏上层算法假设。

链路导航：召回 · 粗排 · 精排 · 重排与混排 · 跨阶段统一。当前优先投入：召回的 objective-specific generative policy + hybrid retrieval；重排的 multi-trajectory / set-level reasoning；跨阶段的 state/budget/controller；底层的 architecture-aware serving 与 retrieval infra correctness。
Tab 01 · 召回 / Retrieval

从“相似度找候选”走向“目标、语义、覆盖与基础设施状态共同决定候选”

传统主线：BM25 / inverted index → DSSM / Two-Tower → ANN → multi-interest / long-history retrieval。近两年出现两条并行路线：① Semantic ID / Generative Retrieval 直接生成 item/doc 地址；② dense + sparse + late-interaction 的 hybrid retrieval portfolio。

UniPolicy · Objective-specific Generative Retrieval

位置：搜索广告早期召回。objective prefix + sparse MoE-LoRA + objective-specific residual FFN，让 relevance / CTR / commercial value 各自形成 policy，再在 fixed candidate budget 下并行 beam search。

Retrieval Infra Correctness · Milvus RocksMQ Cache

9/21 的 Milvus cache ratio fix 是一个重要提醒：召回效果不仅由 embedding/index 算法决定。一个 malformed numeric default 被 silent-zero 后，会让 64GB 主机本应约 3.8GB 的 cache 退回 512MB 最小值。生产检索应该监控 effective config、cache hit/miss、index state 与 query latency，而不是只监控模型指标。

Tab 02 · 粗排 / Pre-ranking

从轻量 Pointwise Scoring 走向“高吞吐 Foundation Encoder + 动态候选预算”

核心约束：粗排面对 10³～10⁴ 候选，单候选预算远低于精排。重点仍是 feature/interaction 压缩、蒸馏、低精度、shared embedding 与 candidate pruning，而不是给每个候选跑完整 LLM reasoning。

年度演进：轻量 DNN / DCN → multi-task shared-bottom → Transformer / distillation → 更强 embedding/foundation encoder → candidate-aware compute budget。PTDG / MORE / UniRec 提示跨 stage shared representation 可以减少 train-serving mismatch，但仍需严格控制 FLOPs。

9/21 的新工程启发：Qwen4 sparse FA、GLM mHC fusion、vLLM mHC overlap 都在按 shape 选择 fast path。迁移到粗排，就是 candidate uncertainty + request shape → depth / expert / feature path。不要默认所有候选使用同样计算图。

值得押注：top-band escalation、dynamic expert routing、teacher-to-pre-ranker adaptive distillation、P99 latency 下的 compute allocation、量化精度按 feature/expert 语义分配。

Tab 03 · 精排 / Ranking

从 Feature Interaction 走向 Foundation Ranker + Multi-timescale User State

主线：Wide&Deep / DeepFM / DIN / DIEN → DCN / MMoE / PLE → long-sequence Transformer → HSTU/SORT/OneTrans 类 foundation ranking → generative behavior pretraining + adapters。

当前核心矛盾：模型能读更长历史，但“用户状态如何表示和更新”成为瓶颈。长期 preference、session intent、实时反馈、自然语言 taste 与业务 context 更新频率不同。

与最近工作的连接：ChronicleRec / DRIFT / LION / RAFT 等 state/memory 工作提示：精排不应每次从头读取完整历史，而应把历史变成 cacheable / mutable / state-addressable representation。9/21 Serving 的 state-layout / state-ownership 问题进一步提醒：用户 memory 一旦缓存化，也需要版本、TTL、ownership 与 rollback 语义。

值得押注：long-term backbone + mid-term chronicle + short-term session state；target-aware history retrieval；foundation ranker 与 small adapter 的不同更新周期；online calibration / counterfactual evaluation。

Tab 04 · 重排与混排 / Re-ranking & Slate Optimization

从规则 / MMR 走向 List-level、Reasoning、Coverage 与 Multi-Trajectory

为什么这一段研究潜力在上升：重排接近最终曝光，候选规模小到可以使用更强 reasoning；同时要统一多样性、业务约束、用户满意、内容生态与广告/自然内容混排，比单候选 CTR 预测更接近真实业务目标。

MERIT-Rank · Multi-Trajectory Reasoning

位置：复杂 query 的高成本 reranker。从多视角生成 reasoning path，再由 joint reranker 汇总；PRPO 分阶段对齐 reasoning 与 ranking。

位置：RAG / Agent Context Rerank，但可迁移到推荐 slate。它不再问“哪个 passage 最相关”，而是“当前集合还缺什么必要事实”。

Tab 05 · 跨阶段统一 / Cross-stage Controller & Serving Substrate

“One Model”不是终点，更可能的终点是“Shared Backbone + Unified Controller + Runtime Contract”

传统问题：召回、粗排、精排、重排分别训练，stage objective mismatch 严重；但把所有能力硬塞一个模型又会带来 Serving 成本、业务隔离、解释与回滚困难。

训练期 Controller · RetireOPD

Teacher 不再是永久 loss，而是根据 student competence 与 discrepancy 自动退出。

评估 / Action Controller · F²DR + MATCH

F²DR 把 Content / Trajectory / Answer 分开评估；MATCH 用 tool/source → argument key → argument value 的层级 gated reward。两者都在解决跨阶段 credit assignment。

Serving Controller · ODA / SwitchSD

每 token 决定是否 global attention；根据内部 copy-intent 切 neural draft / context copy。核心思想是把 execution choice 变成模型状态的函数。

9/21 新增：Architecture-aware Serving Substrate

Qwen4 Sparse FA、vLLM mHC overlap、SGLang GLM mHC fusion、MiMo V2 BF16 router + MXFP4 MoE、Spec KV correctness、Ascend SSM state layout 共同说明：上层 controller 决定了“做什么”以后，底层还必须知道“这个模型结构怎样正确地做”。

跨阶段长期 action space：{retrieval source/index, candidate budget, pre-rank depth, rank model, rerank trajectories, business objective policy, context/KV policy, model/tool, attention mode, precision, draft mode, kernel path, halt/abstain}。优化目标应从单一 CTR/NDCG 升级为 task utility − latency − cost − risk under business constraints。

工程底座：state ownership/version、effective config validation、precision policy、kernel crossover model、hardware capability graph、correctness + performance unified CI。

链路视角的研究优先级：未来 2–3 年推荐/搜索算法竞争力，优先顺序建议：① 重排/混排 reasoning + multi-objective；② 召回 generative + hybrid retrieval；③ 跨阶段 controller / RL；④ foundation ranker 的 state/memory；⑤ architecture-aware Serving 与 retrieval infra correctness。单纯把传统精排再堆一层 MLP/Transformer，边际研究价值会继续下降。
