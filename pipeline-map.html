把论文放回真实推荐链路里

同一篇论文在离线 benchmark 上都可能叫“Recommendation”，但落到生产里承担的是完全不同的 latency、candidate scale 与业务责任。这里按 召回 / 粗排 / 精排 / 重排与混排 / 跨阶段统一 分类，并固定记录研究价值、成熟度、创新性、相关度、开源、线上 A/B 和阅读优先级。

2026-08-27 链路判断：今天最明显的趋势是“阶段没有消失，但共享资产在增多”。召回侧 TAGR / Tlow / RetrievalFormer 重新定义 Item Namespace 与 Open Index；精排侧 WeMM + NMRL 把多模态表示变成可复用且任务原生的 feature；跨阶段侧 RecGPT-Mobile-V2 / AdaWidth 开始把 Compute Budget 做成请求级控制。未来统一的是 Representation / State / Reward / Runtime Contract，而不是简单取消 Pipeline。

召回 / Retrieval

百万～十亿候选 · 高覆盖 · 低延迟 · 新 Item 可入场

召回核心矛盾

从“ANN 检索一个向量”到“管理开放的 Semantic Namespace”

召回层最重要的变化不是某个 ANN 算法，而是候选表示本身：Random ID 对冷启动弱；Dense Embedding 对新 item 友好但存储 / serving 成本大；Semantic ID 能共享 token 参数却带来 collision / decode / freshness 问题。今天的 TAGR、Tlow、RetrievalFormer 分别击中了 freshness、token geometry、open index 三个关键点。

粗排 / Pre-ranking

数千～数万候选 · 性价比优先 · 教师蒸馏 / Representation Reuse

粗排核心矛盾

候选多、预算小：怎样把“精排知道的东西”以更低成本前移

粗排正从轻量 MLP / Two-tower 走向共享 representation + 轻量交互。今天 WeMM 的意义很直接：统一多模态 embedding 可以离线抽取后作为粗排语义 feature；AdaWidth 则进一步说明 query 侧甚至不必固定使用同一向量宽度。真正的研究空间是 teacher signal、候选难度、计算预算三者联合路由。

工程判断

粗排最值得研究的不是“把精排模型砍小一点”，而是共享 User State + Item Representation + Teacher Score，再根据候选难度分配交互成本。Densing / Matryoshka / distillation 会在这一层高度汇合。

精排 / Ranking

数百候选 · 多目标 · 强特征交互 · 线上收益核心层

精排核心矛盾

“更多 Feature / 更大 Encoder”不够，关键是监督是否真的属于这个 Representation

淘宝 NMRL 是当前精排最值得读的反例：把 CTR loss 直接端到端回传给多模态 encoder 不仅贵，还可能因为点击中的价格 / 位置 / 偶然性等非语义因素污染共享参数。更可行的路线是先从行为日志挖出可归因的 supervision，再训练 task-native representation。CRRN 则从 request side 证明“刚刚触发了什么”是非常高 ROI 的精排信号。

当前精读路线

DIN/DIEN → Long Sequence / Foundation Ranking → OneModel → CRRN → WeMM + NMRL。真正值得练的是 gradient conflict diagnosis、behavior attribution、task-native representation mining、request/trigger features 与多目标 loss。

重排与混排 / Re-ranking & Slate

几十候选 · 多目标约束 · Diversity / Risk / Business Value / Context

重排核心矛盾

从“最后再算一个更准分数”变成真正的 Decision Layer

当基础 ranker 已经很强，最后一层的价值越来越来自跨候选约束：多样性、即时意图、风险、商业价值、内容安全、来源证据与执行成本。Agent Tool Retrieval 的 Risk-aware rerank 与推荐 slate rerank 本质上是同一个多目标决策问题。

跨阶段统一 / Full-stack

统一的是资产与接口，不一定是物理 Pipeline

跨阶段核心矛盾

召回、排序、重排的目标不同，怎样共享能力而不把系统做成一个巨大黑盒

过去“全链路生成式推荐”容易被理解成把召回→精排→重排都塞进同一个 autoregressive model。近期工业工作给出的答案更克制：共享 User State、Item Representation / Semantic Namespace、Reward / Value Teacher、Runtime Budget；执行阶段仍按 candidate scale 和 latency 专门化。 TAGR 生成召回后仍进入 downstream rank；WeMM embedding 同时作为检索、排序和序列 feature；RecGPT 将 Query Recall 与传统 recall channel 做互补；AdaWidth / Densing 则提供跨层级预算控制。
