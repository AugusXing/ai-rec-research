工程落地顺序

近期最现实的结构是：Dense ANN 主路径 + SID 结构监督 / Generative Path + Support/Reasoning Adapter + Task-aligned Compression + Query-value Router。如果已经部署 GenRec，优先补 SID utilization、conditional utilization、churn、fresh-item coverage、decode depth 与 QPS 监控；这些指标比继续加深 decoder 更可能找到真实瓶颈。

跨阶段统一的落地结构

Shared User State / Semantic Item Asset→Dense / SID / Structured Recall Router→Elastic Pre-rank→Foundation Ranker→Context-aware Stateful Re-rank→Memory / Cache / Compiler / Hardware Policy

2026 年最值得研究的不是“取消召回/粗排/精排”，而是哪些 representation、semantic namespace、teacher、memory 与 serving asset 可以跨阶段复用，以及什么请求值得走更重的生成、澄清或 reasoning 路径。

推荐算法工程师精读顺序

按落地收益排序

第一层：Semantic ID 主线——Sona/OneRec → SSR-GRPO → Dynamic Single-Level SID → DoorDash SPID，理解 Item Token 从模型内部走向跨系统资产；
第二层：精排主线——OneModel → RankMixer / OneRank，理解 Shared User State 与 Foundation Ranking；
第三层：Context 主线——RecPFN → CAIRO → Clarify-Then-Search / EnSI-RAG，理解“选什么信息”如何成为算法模块；
第四层：系统主线——CacheRoute → LiLiCorr → AsmEvo，理解模型收益如何最终变成 QPS、Latency 与真实硬件收益。
