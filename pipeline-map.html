召回 / 粗排 / 精排 / 重排 / 跨阶段统一

按工业链路判断论文真正落在哪里。8 月 29 日的新变化把“链路优化”的含义进一步拉宽：召回不仅要学 item representation，还要内化 perception tool、管理 index rebuild；重排不仅要提高 nDCG，还要保证 decision stability；精排之外的页面动作开始直接优化 causal incrementality；跨阶段则需要统一 metric validity 与 serving correctness。

今天的链路判断：PailitaoGR 最适合放在多模态 / 生成式召回，它把 crop/OCR 从在线工具变成训练期 teacher；misi 属于 Retrieval Data Plane，强调 build / refresh / memory；OC-SFT 是最直接的重排基础能力，因为它优化“候选顺序变化时决策是否稳定”；Stageboost 属于精排之后的 action selection / 页面信号推荐，并用真实 eBay A/B 证明 causal value；Evidence-aware RAG 与 SGLang Top-K issue 则提醒整条链路还需要两个横向 contract：指标有效性与数值正确性。

Tab 02 · 粗排 / Pre-ranking

从独立小模型转向 Budgeted Information Filtering 与 Stable Candidate Preservation

当前核心矛盾：粗排需要在数百 / 数千候选上保持精排 Top-K，同时 feature cost 与 p99 latency 极低。越来越多高价值方法不是“再造一个粗排 Transformer”，而是把昂贵 state construction 前移，并把在线计算限制在 candidate-aware cheap interaction。

今天的新启发：PailitaoGR 的 teacher-rich/student-light 模板可以直接迁移到粗排：训练期 teacher 可以读取长序列、图、多模态工具，线上 student 只消费 compact state。misi 则说明 candidate generation 的预算应与 rebuild cost / index freshness 一起设计；OC-SFT 提醒粗排与精排的一致性不能只看 AUC，而要观察候选集合在输入扰动后的稳定性。

值得押注：Teacher-preserving pre-rank、request-aware token pruning、candidate-aware small query token、动态 embedding width、Shared User State；评价增加 Top-K consistency、candidate-set overlap、recall loss、latency 与 feature freshness。

Stageboost · Counterfactual Signal Recommendation

Research Impact Score / 研究价值 9.3/10工业成熟度 ★★★★★创新性 ★★★★☆与你方向的相关度 ★★★★★是否官方开源 否 / 未发现是否有线上 A/B 是阅读优先级 最高

eBay 的 View-Item 页面并非继续排商品，而是选择展示哪一个购买 signal。Stageboost 用两阶段 XGBoost + counterfactual estimation，把目标从“看到 signal 的用户是否会买”改为“展示这个 signal 是否造成增量”；线上整体 GMB +0.08%，Parts & Accessories +0.58%。Paper

Tab 04 · 重排与混排 / Re-ranking

从 Score Fusion 到 Context / Risk / Decision Stability

OC-SFT · Order-consistent LLM Scoring

Research Impact Score / 研究价值 9.4/10工业成熟度 ★★★☆☆创新性 ★★★★☆与你方向的相关度 ★★★★★是否官方开源 是是否有线上 A/B 否阅读优先级 最高

5 个 LLM scorer 的 nDCG@10 差异小于 0.010，但 presentation order 改变后 retained-set overlap 仅 0.66–0.84。OC-SFT 让同一 candidate 在不同 permutation 下保持一致得分，reader answer-flip rate 降至 0.125；单次推理的稳定性可超过 off-the-shelf scorer 十余次 permutation averaging。Paper · Code

与既有重排主线的连接：DPP/MMR 显式处理相关性与多样性；CAIRO、Risk-aware Rerank 加 context / constraint；ProRetrieval 提示 pipeline 可程序化；OC-SFT 再补上最基础的 contract：同一个候选集合不应该因为无意义的输入排列就产生完全不同曝光决策。

值得押注：Listwise utility model、candidate-set graph、order/permutation invariance、risk-aware constrained optimization、LLM judge distillation、programmatic reranking。评测固定增加 retained-set overlap、threshold stability、decision flip rate，而不再只报 nDCG。

跨阶段终局判断：真正统一的推荐系统至少共享五种资产：① User/Item State；② Semantic Namespace / Fresh Index；③ Teacher / Reward / Causal Value Model；④ Runtime / Retrieval Control Policy；⑤ Metric & Correctness Contract。Backbone 是否完全同一个反而是次要问题。

工程优先级：召回：Semantic ID + Hybrid Retrieval + Latent Perception + ANN lifecycle；粗排：Teacher Distillation + Stable Candidate Preservation；精排：Long Sequence + Candidate-aware Interaction + Causal Action Value；重排：Listwise Utility + Decision Stability + Constraint/Risk；跨阶段：Shared State + Validated Metric + Reward/Causal Model + GPU Serving Correctness + Experiment / Evolution Infrastructure。
