按线上链路看研究：召回 / 粗排 / 精排 / 重排与混排 / 跨阶段统一

这页不按论文主题，而按“它会落到推荐/搜索链路的哪一段”组织。2026 年最明显的变化是：传统 stage 仍然存在，但 stage 之间正在加入更多 Controller——目标路由、候选预算、证据覆盖、reasoning budget、KV/attention、teacher lifecycle 都变成可学习决策。

链路导航：召回 · 粗排 · 精排 · 重排与混排 · 跨阶段统一。当前最值得优先投入：召回的 objective-specific generative policy + hybrid retrieval；重排的 multi-trajectory reasoning；跨阶段的 state/budget/controller。
Tab 01 · 召回 / Retrieval

从“相似度找候选”走向“目标、语义与成本共同决定候选”

传统主线：BM25 / inverted index → DSSM / Two-Tower → ANN → multi-interest / long-history retrieval。近两年再出现两条并行路线：① Semantic ID / Generative Retrieval 直接生成 item/doc 地址；② dense + sparse + late-interaction 的 hybrid retrieval portfolio。

UniPolicy · Objective-specific Generative Retrieval

位置：搜索广告早期召回。通过 objective prefix、sparse MoE-LoRA、objective-specific residual FFN，让 relevance / CTR / commercial value 各自形成 policy，再在 fixed candidate budget 下并行 beam search 并分配 quota。

值得跟踪的历史路线

TIGER / RQ-VAE → HypRQ-VAE → OneRec / OneSearch → EPIC / Generative Verifier → VARG / GR4AD → UniPolicy。工程上同时保留 Two-Tower/ANN 与 sparse/late interaction，避免过早把所有流量押到 generative retrieval。

下一步：query-conditioned retriever router、multi-policy candidate quota、set-level coverage、incremental SID、rare-entity/lexical 与 semantic request 分流。

Tab 02 · 粗排 / Pre-ranking

从轻量 Pointwise Scoring 走向“高吞吐 Foundation Encoder + 动态候选预算”

核心约束：粗排面对 10³～10⁴ 候选，单候选预算远低于精排。研究重点仍是 feature/interaction 压缩、蒸馏、低精度、shared embedding 与 candidate pruning，而不是直接塞完整 LLM reasoning。

年度演进：轻量 DNN / DCN → multi-task shared-bottom → Transformer / distillation → 更强 embedding/foundation encoder → candidate-aware compute budget。PTDG / MORE / UniRec 等工作提示跨 stage shared representation 可以减少 train-serving mismatch，但仍需严格控制 FLOPs。

9/20 的间接启发：ODA 的“只有需要时才 global read”以及 SwitchSD 的“按内部状态切换 decoding 策略”虽然不是粗排论文，但它们对应一个可迁移思想：粗排也不必对所有候选使用同样算力。可做 uncertainty-aware depth、top-band escalation、dynamic expert routing。

值得押注：candidate uncertainty + groupwise budget；teacher-to-pre-ranker distillation 的 adaptive retirement；稀疏/低秩 expert；P99 latency 下的动态 compute。

Tab 03 · 精排 / Ranking

从 Feature Interaction 走向 Foundation Ranker + Multi-timescale User State

主线：Wide&Deep / DeepFM / DIN / DIEN → DCN / MMoE / PLE → long-sequence Transformer → HSTU/SORT/OneTrans 类 foundation ranking → generative behavior pretraining + adapters。

当前核心矛盾：模型已经能处理更长行为序列，但“用户状态如何表示和更新”成为新瓶颈。长期 preference、session intent、实时反馈、自然语言 taste 与业务 context 更新频率完全不同。

与最近工作的连接：ChronicleRec / DRIFT / LION / RAFT 等 state/memory 工作提示：精排不应每次从头读取完整历史，而应把历史变成 cacheable / mutable / state-addressable representation；Spotify textual taste/hypothesis 进一步说明可读 state 可能成为 ranker 的辅助通道。

值得押注：long-term backbone + mid-term chronicle + short-term session state；target-aware retrieval from user history；foundation ranker 与 small adapter 的不同更新周期；线上 calibration / counterfactual evaluation。

Tab 04 · 重排与混排 / Re-ranking & Slate Optimization

从规则 / MMR 走向 List-level、Reasoning、Coverage 与 Multi-Trajectory

为什么这一段研究潜力在上升：重排天然接近最终曝光决策，候选规模已经足够小，可以使用更强 reasoning；同时它要统一多样性、业务约束、用户满意、内容生态、广告/自然内容混排，比单候选 CTR 预测更接近真正业务目标。

MERIT-Rank · Multi-Trajectory Reasoning

位置：复杂 query 的高成本 reranker。从多视角生成 reasoning path，再由 joint reranker 汇总；PRPO 分阶段对齐 reasoning 与 ranking。

位置：RAG / Agent Context Rerank，但可直接迁移到推荐 slate。它不再问“哪个 passage 最相关”，而是“当前集合还缺什么必要事实”。

Complete-MSS@5 61.4%→73.0%；推荐里可映射成“当前 slate 已覆盖哪些兴趣/属性/生态目标，还缺什么”。

研究路线

MMR / diversity rule → listwise learning-to-rank → generative reranking → verifier / sufficiency → multi-trajectory reasoning。下一阶段最值得研究的是 coverage-aware multi-trajectory list optimization，并用 latency budget 只对高不确定 slate 触发 reasoning。

你如果押注重排，技能组合：LTR/listwise loss、constrained optimization、LLM reasoning/verifier、RL preference alignment、multi-objective experimentation、low-latency Serving。

Tab 05 · 跨阶段统一 / Cross-stage Controller

“One Model”不是终点，更可能的终点是“Shared Backbone + Unified Controller”

传统问题：召回、粗排、精排、重排分别训练，stage objective mismatch 严重；但把所有能力硬塞到一个模型又会导致 Serving 成本、可解释性、业务隔离和回滚困难。

RetireOPD · 训练期 Controller

适用位置：跨 stage distillation / Agent training。Teacher 不是永久 loss，而是根据 student competence 与 discrepancy 自动退出。

跨阶段长期方向：Controller 的统一 action space 最终可能包含：{retrieval source/index, candidate budget, pre-rank depth, rank model, rerank reasoning trajectories, business objective policy, context/KV policy, model/tool, attention/draft mode, halt/abstain}。优化目标应从单一 CTR/NDCG 升级为 task utility − latency − cost − risk under business constraints。

链路视角的研究优先级：如果目标是未来 2–3 年推荐/搜索算法竞争力，优先顺序建议是：① 重排/混排的 reasoning + multi-objective；② 召回的 generative + hybrid retrieval；③ 跨阶段 controller / RL；④ foundation ranker 的 state/memory；⑤ Serving 的 adaptive compute。单纯把传统精排模型再堆一层 MLP/Transformer，边际研究价值会继续下降。
