召回 / 粗排 / 精排 / 重排 / 跨阶段统一

按工业链路判断论文真正落在哪里。今天的关键变化是：召回层开始显式学习“几个兴趣应该发起检索、每个兴趣花多少 ANN 预算”；生成式召回把 SID、监督与 Preference 变成同一个意图对齐问题；多模态 I2I 从内容相似升级为行为相似；跨阶段统一则继续下沉到 beam survival、retriever RL 与 phase-aware Serving。

今日链路判断：SetMIR 是召回 control plane 的重要更新；ICEGR 是召回到曝光链路的 full-stack GR；CAMIE 是 I2I 表征层；TAAL 同时影响生成式召回候选生成与轻量重排；PAO 把 downstream reward 反传到 retriever；vLLM/SGLang/TRT-LLM 则说明跨阶段统一不等于统一执行路径——prefill/decode、request/token capacity、dtype conversion 都应按 phase 分化。

Tab 02 · 粗排 / Pre-ranking

Candidate Preservation × Cheap Interaction × State / Intent Distillation

当前核心矛盾：召回越来越丰富：多个兴趣、多个 modality、GR beam、工具检索都可能贡献候选，但粗排预算不能线性增长。粗排的价值从“一个小精排模型”转向 candidate preservation + source-aware calibration + cheap candidate-conditioned interaction。

SetMIR 启发：在进入粗排前就先做 query-level presence/NMS，避免冗余 source 候选吞噬预算；source metadata、interest id、retrieval path 可以成为粗排 feature。

ICEGR 启发：生成式候选可能直接插入最终曝光，也可能走传统过滤/排序。真正需要的是可控的 GR candidate quota、source calibration 与 safety/filter contract，而不是默认所有候选同分布。

CAMIE 启发：如果 item embedding 已经按行为共现对齐，粗排可以减少昂贵多模态交互，把更多预算留给跨候选 context。

评价建议：Top-K retention、source-level retained ratio、candidate overlap、long-tail coverage、feature freshness、state build cost、p95/p99 与 downstream lift；不要只看独立 AUC。

Tab 04 · 重排与混排 / Re-ranking

Context / Risk / Diversity → Stable, Relevant & Calibrated Decision

ICEGR RCPO · Relevance-guarded Business Preference

先把 beam candidate 约束到语义相关集合，再结合 click/pay/GMV 构造 preference；固定强度 DPO 会让人工 top-5 relevance 从 0.87 降到 0.58，而 relevance-calibrated preference 能避免商业 reward 把相关性“冲掉”。

TAAL PMI · Beam Survivor Calibration

TAAL 的 PMI 不是候选生成器，只在完整 Top-B survivor 上 O(B) rerank。它提醒生成式推荐的重排入口已经从 item list 延伸到 sequence/prefix level。

OC-SFT · Order-consistent LLM Scoring

presentation order 能让 retained set 翻转；把 permutation consistency 训练进 scorer，继续作为 listwise stability 的关键节点。

重排值得押注：Listwise utility、source quota、relevance guard、order invariance、risk constraint、calibration、decision flip rate、长期 value，以及 generative beam survivor 的 sequence-level calibration。

HyQuant / H-Scale · Precision Control

HyQuant 把关键 token 保高精度，其余低比特；H-Scale 把 NVFP4 scale 优化做成 sensitivity-aware post-process。它们与 phase-aware kernel 一起构成跨阶段 budget control。

SGLang / TensorRT-LLM · Capacity & Dtype Contract

SGLang 将 ragged CUDA graph 的 request capacity 与 packed-token capacity 解耦；TensorRT-LLM 把 E4M3 query 的 BF16 widen 融入 sparse decode kernel，避免独立 copy launch。两者都说明运行时正确的 abstraction boundary 会直接影响资源与性能。

统一判断：未来跨阶段模型不会只统一 backbone；还会统一 User/Agent State、Semantic Namespace、Query Intent、Retrieval History、Compute/Precision Budget、Metric Contract，同时允许执行路径按 source/phase/modalities 专门化。

2026.09.02 推荐链路新增判断：召回层正在成为“决策层”，而不再只是“向量搜索层”。 它要决定多少兴趣被激活、用 ANN 还是生成、beam 给多大、哪个 source 值得占预算；精排/重排则负责把相关性、时间、因果价值和商业偏好重新校准。跨阶段统一的关键是共享 intent/state 与预算，而不是删除这些不同职责。
