召回 / 粗排 / 精排 / 重排与混排 / 跨阶段统一

这个页面回答工程问题：一项工作最终改变链路的哪一段？替换什么、复用什么 state、增加多少在线成本、有没有真实 A/B？ 今天最重要的新判断是：状态复用与低比特压缩不能只看 hit rate / reconstruction error，必须验证它们有没有改变最终 retrieval / ranking decision。

今日链路判断：未来推荐链路不会简单从“五段式”变成“一个大模型”。更可能是：传统高吞吐 retrieval/ranking 主干继续存在，每一段都增加可复用 state layer，跨阶段 controller 再根据 freshness、compatibility、precision、SLO 与 hard-case uncertainty 决定复用、重算还是升级到更强模型。LiteRAG、KVShareArena、低比特向量检索与 MORE 分别从召回、runtime 与精排给出了新的证据。
Tab 01 · 召回

从“找候选”升级为“经营可检索空间 + 保证关键决策不翻转”

召回侧当前最关键的状态是：索引文本/扩展资产、Semantic ID namespace、dense vectors、graph structure。SAM-D2Q 负责离线扩展可检索表面，LiteRAG 负责低成本多跳结构检索，Low-bit Vector Search 则回答向量压缩后 top-k / graph prune 是否还保持原 decision。

Tab 02 · 粗排

不是“更小的精排”，而是低成本保留后续最有用的状态

粗排的核心仍是覆盖、吞吐和 state reuse。趋势不是把完整 cross-attention 前移，而是让 user/context 只算一次，候选做轻量 interaction，并把 uncertainty 暴露给后续 router。

Tab 03 · 精排

Task-aware Backbone + Dynamic Task Dependency

精排仍是推荐工业最成熟的收益区。过去多任务方法主要在 shared representation 之后做 expert/tower 分化；MORE 的关键推进是让 task-specific signal 从每层 backbone 内部就参与行为序列读取和特征混合。

Tab 04 · 重排与混排

Reusable Candidate State + Structured Decode + Verifiable Evidence

重排最核心的在线成本来自候选反复编码和列表逐 token 生成；搜索/RAG 的另一个风险是“解释看似有引用，但引用本身并非输入原文”。DoPR、hLLM、CHyD 分别针对三处问题。

Tab 05 · 跨阶段统一

统一的不是“一个大模型”，而是 Namespace、State、Policy、Runtime、Compatibility 与 Budget

跨阶段统一有两条路线：TGR 式 shared backbone/full-stack generation；以及把每一段最有价值的中间对象做成显式 contract。过去几天的工作越来越支持后者：state 只有在可以定位、版本化、验证 compatibility 并监控 decision preservation 时，才真正能规模化复用。

跨阶段状态图：Catalog State（Semantic ID / generated expansion / dense vectors / graph）→ User/Context State（sequence/context/atomic memory）→ Candidate State（reusable prefix/KV）→ Policy State（inventory-grounded guideline / Agent harness）→ Runtime State（GPU/host/SSD cache、dtype/scale/layout、device/load）→ controller 决定 recall/rank/rerank/Agent 路径。

2026-09-11 新增判断：Runtime State 还必须带 birth context / producer checkpoint / position / source dependency / precision 等 compatibility metadata；近似 state 的评价则要增加 decision flip，而不是只有 cache hit 或重构误差。

值得押注：跨阶段 state schema、version/TTL、一致性、experiment attribution、state-aware routing、precision policy、dynamic recompute，以及“何时刷新 state vs 何时重训模型”的自动 controller。

如果按落地优先级排序：成熟电商搜索先看 SAM-D2Q + decision-aware vector quantization；多目标精排先看 MORE / PTDG / UniCon；LLM rerank 先看 DoPR / hLLM；长上下文/RAG Serving 看 KVShareArena + selective recomputation；Agent/Search 先看 IGPO / RobustSGPO。如果已经开始做大模型推荐 Serving，把 state compatibility + SLO-aware compute controller 当成跨阶段基础设施，而不是推理团队的旁支。
