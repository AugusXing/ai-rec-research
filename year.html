过去一年，推荐系统真正发生了什么？

如果只按论文发布时间看，会看到大量彼此割裂的新名词；沿着“上一阶段解决什么 → 留下什么问题 → 下一篇工作如何推进”去看，主线反而越来越清晰：推荐正在从 Stage-specific Predictor，走向 Generative / Foundation / Policy Model + Adaptive Serving。

年度总判断：最值得关注的变化不是“LLM 进入推荐”本身，而是推荐系统的基本抽象正在变化：Item 变 Token、Ranker 变 Policy、Social Graph 变 Reasoning Space、长期历史变可压缩 Memory、业务目标变 Reward、模型选择变 Router。真正决定这些范式能否替代传统工业链路的，不再只有离线精度，而是 Serving、Alignment、Coverage、Calibration 与 Cost-aware Compute。8 月最新一批系统工作又把问题向前推了一步：连 Retrieval depth、KV cache granularity 与 evidence exploration 都开始变成 request-aware runtime decision。
主线 01 · Generative Retrieval

从“两塔召回”到“生成 Item Token”

上一阶段解决了什么：Two-Tower + ANN 把百万/十亿 Item 检索做到了极高吞吐，但 User/Item 独立编码限制了高阶交互，召回和后续 Ranking 的训练目标也天然割裂。

关键推进：OneRec-V2 把推荐转成 Item Token 自回归生成，并把真实观看/交互反馈带入 post-training；JD GenRec 等继续把 RL 和生成式召回结合。

留下的问题：生成空间如何组织？Fresh/Long-tail Item 怎么泛化？Beam/Decode 成本能否进入严格召回预算？

  • OneRec-V2
  • JD GenRec
主线 02 · Semantic ID

Tokenizer 从实现细节变成推荐基础设施

上一阶段留下的问题：如果 Item Token 只是任意 ID，生成模型难以利用内容语义、协同行为和跨域共享结构。

关键推进：FORGE 等工作让 Semantic ID 同时承载语义与协同信息；HD-Rec 进一步用层级量化，把“共享粗粒度 Codebook”和“域自适应细粒度 Codebook”结合，再用 Sparse Routing 解决跨域表示冲突。最新 Audio Embedding → GenRec 实证又给出一个重要负结果：扩大 SID codebook / depth 并不会稳定增益，容量过大反而可能引入明显不稳定。

问题如何变化：研究重点从“有没有 Semantic ID”转向“Token 粒度、Codebook 层级、Routing、Fresh Item Assignment、表示来源与训练稳定性怎么联合学习”。

  • FORGE
  • HD-Rec
  • Audio Embedding → GenRec
主线 03 · Scaling / Serving

从“模型越大越好”到“计算预算怎么分配”

上一阶段解决了什么：更长序列、更强 Transformer 显著扩展了用户兴趣建模能力；Netflix 等 Scaling 工作也开始给出任务相关的规模化证据。

真正卡住的地方：Prefill、Full Attention、KV Cache、显存、吞吐和在线延迟，并不会因为模型更准自动消失。

关键推进：TM20K 用 20K Full-Attention Teacher 保留完整信息，再让 Student 在线 Token Merge；作者报告 ADSS +1.036%、Serving Latency 仅 +5.6%。CoinRAG 则把 Serving 问题推进到 KV 复用粒度：不是整 Chunk 缓存后全吃，而是检索 query-relevant information nuggets 并组合离线 KV slice，在 LongBench multi-hop 下于 fast-prefill budget 获得平均 5.3% 相对 F1 提升。

下一阶段：固定压缩比例还不够，真正值得押注的是 User / Query / Target-aware token budget、KV composition 与 Per-request Model Routing。

  • Netflix Scaling
  • TM20K
  • Netflix GenRec
  • CoinRAG
主线 04 · Ranking Foundation Model

从“大 Encoder + 小 Head”走向 Transformer-native Ranking

上一阶段：MMoE/PLE/RankMixer 等把多任务排序做得非常成熟，但工业模型普遍仍是“强 Encoder → Shared Representation → 多个 MLP Predictor”。

关键推进：OneRank 直接挑战这条边界：Task Token、Mutual Invisibility、Candidate-aware Context、Cross-task Relational Attention、Dynamic Matching 都留在 Transformer 信息流里。Shopee 线上实验报告 GMV/UU +1.01%、Paid GMV/UU +1.17%、Bad Query Rate −2.29%。

问题如何变化：精排研究正在从 Feature Interaction / Expert Design 迁移到 Tokenization、Attention Mask、Cross-task Memory、List Context 与 Serving Layout。

  • RankMixer
  • OneRank
  • SORT
主线 05 · Foundation Model

从“行为 Pattern Matcher”到统一用户表示与下游适配

上一阶段留下的问题：只靠行为序列预训练，模型可能只是更强的 pattern matcher；更大的 representation 也不自动等于更好的业务对齐。

关键推进：OpenOneRec 把语言/推荐能力统一进 Foundation Model；WEBTOON 的 Progressive Alignment 则进一步把 Post-training 拆成 LP → FFT → RFT：先稳定 Head，再做全量适配，最后用 Reward Model 对齐稀疏业务目标。

新的核心问题：一个 Foundation Model 应该共享到什么粒度？不同 Surface 的 Reward 是否可共享？长期业务目标如何避免 reward hacking？

  • OpenOneRec
  • Progressive Alignment · 官方代码
主线 06 · RL / Preference Alignment

从 Next-item Label 到可学习的业务 Reward

上一阶段：监督学习高度依赖 click / conversion 等局部标签，长期留存、疲劳、多样性、探索和平台生态很难直接进入 loss。

关键推进：OneRec-V2、JD GenRec、GR2 将 RL/真实反馈带入召回和重排；Progressive Alignment 又把“Policy 学习”和“稀疏业务指标 Reward Modeling”显式拆开。

年度判断：Reward Design 的重要性已经开始超过“到底用 PPO、GRPO 还是别的优化器”。未来更大的风险是 Reward Model 偏差、Position Bias、Policy Collapse 与 Reward Hacking。

主线 07 · Reasoning / Re-ranking

从打分到列表级策略，再从“会 Think”到“少 Think”

上一阶段：传统 Re-rank 很擅长规则、多样性和多目标融合，但高度依赖手工策略；LLM 引入后，模型可以显式归纳偏好并做 Listwise Decision。

关键推进：GR2 用 Reasoning + RL 推动生成式重排，MetaStrategy 让 LLM 输出结构化策略、传统 Ranker 执行；REAM 则开始压缩 Recommendation Reasoning Length，把研究问题推进到 Adaptive Thinking Budget。

下一阶段：不是所有 Query/User 都值得运行昂贵 Reranker 或长 CoT。Routing、Calibration 与 Cost-aware Reranking 会成为工业落地核心。

  • GR2
  • MetaStrategy
  • REAM
主线 08 · Full-stack Generative Recommendation

传统 Cascade 的边界第一次被正面挑战

上一阶段：Generative Retrieval、LLM Ranker、Reasoning Re-rank 分别在各阶段突破，但工业系统仍保留召回 → 粗排 → 精排的独立模型和 User Representation。

关键推进：Sona 在 Yandex Music 用单一生成式模型替代 15+ Candidate Generators、Pre-rank 和 Rank，并报告 Active Users +4.53%、Listening Time +6.30%、Likes +11.42%。

为什么这篇重要：它把研究问题从“生成式推荐能不能在某个阶段超过基线”改成“推荐 Pipeline 的阶段划分本身还需不需要”。

仍未解决：大规模探索、长尾 Coverage、严格延迟与全场景迁移，因此短期更可能出现“统一表示 + 部分阶段融合”，而不是所有公司立即拆掉 Cascade。

  • Sona
主线 09 · Agentic Search / Context Ranking

从“Retrieval 相关性”转向“Evidence 对最终决策有没有用”

上一阶段：RAG 主要优化 Query–Document Similarity；Agent 出现后，同一个文档在不同 reasoning state 下的价值并不相同。

关键推进：Agentic-R / CoSearch 让 Retriever 与最终 Answer/Reasoner 联动；RISE 与 Context Interference 把“Context 本身的干扰”变成一等问题；MixRAGRec 把 KG retrieval granularity 交给 MoE Router。最新 EAHR 又把 Hybrid Retrieval depth 改成 query-specific execution state；DocMemo 则显式维护 Page Belief，并用 Bayesian update + Thompson sampling 做跨轮证据探索。

下一阶段：Context Ranking / Evidence Selection 很可能成为 Search Agent 中独立的一层，但它不再只是“再排一次分”：它会联合决定读多少、读哪路、何时停止、是否探索，以及哪些 Context 值得进入昂贵推理。

  • Agentic-R
  • CoSearch
  • Context Interference
  • MixRAGRec
  • EAHR
  • DocMemo
主线 10 · Model Routing / Auto Optimization

推荐工程师经验正在迁移到 Agent / LLM Serving

共同结构：ConnectionMind 是 Heavy LLM Policy / Teacher + Student GNN Serving；MetaStrategy 是 LLM Strategy + Traditional Executor；MixRAGRec 是 Query → Retrieval Expert Router；MISO 用模型内部状态减少 Ranking 模型黑盒调优轮数；Pre-Inference Routing 更进一步提出“先诊断 Routing 是否值得做”：Cheap Model 要有足够 failure rate，而且 failure 必须能从廉价特征提前预测。

年度判断：Planner/Executor、Router/Cascade、Calibration、Bandit、Distillation 这些推荐工程师非常熟悉的问题，会成为未来 Agent/LLM 系统的核心基础设施，而不是边缘工程技巧。真正成熟的 Routing 系统会把质量、延迟、GPU 负载、价格和不确定性联合进入 Policy。

  • ConnectionMind
  • MISO
  • Pre-Inference Routing

过去一年的演进压缩成一张路线

Two-Tower / MTL Ranker→Item-as-Token→Semantic ID→Foundation Model→RL / Reasoning→Unified Pipeline→Adaptive Compute
接下来最值得押注：① Transformer-native Ranking 是否能替代 MMoE/PLE 式 Predictor；② Request-aware Long-sequence / KV Compression；③ Recommendation Reward Model / Long-term Alignment；④ Reasoning / Reranking Router；⑤ Semantic ID × Cross-domain Routing；⑥ Agentic Search 的 Context Ranking + Adaptive Retrieval Depth；⑦ 大模型 Policy/Teacher + 小模型 Executor 的工业化 Serving；⑧ Recall Coverage / Freshness 的独立诊断与优化。
