过去一年，推荐 / 搜索真正发生了什么？

技术主线已经从“换一个更大 backbone”变成：Representation → State → Assignment → Domain Structure → Budget Allocation → Control Plane。9 月 4 日的新信号尤其强：Meta CORAL 让 LLM Agent 进入生产推荐系统控制面；Declarative Attention 让模型自己声明该看哪里；PRO-Step 把 RAG 的 credit 下沉到每一步；Spotify 与 NVIDIA 则把 routing 分别推进到 worker 与 device。系统竞争力正在从“模型分数”扩展为约束、实验、路由、可观测性与 utility-per-compute的联合设计。

年度总判断：User 表征从 Raw History → Long Sequence → Shared State → Variable Interest Set；Item 从 Random ID → Semantic Embedding → Structured / Fresh SID → Domain-aware SID；Retrieval 从固定 ANN → Multi-vector / Generative Retrieval → Group / Intent-aware Search → Dynamic Dispatch；Ranking 从统一 one-pass → time/causal decision → Fast/Slow conditional compute；Agent 从“读上下文回答”→“检索/调用工具”→“长期记忆”→“带 A/B 的系统控制面”；Serving 从固定模型、固定 top-k、固定 attention → request × source × model × context × attention × device 的预算路由。
主线 01 · Generative Retrieval

Next-item Generation → Semantic ID → Intent / Domain-coherent Full-stack Retrieval

上一阶段解决了什么：TIGER / OneRec / Sona 把候选检索写成 token generation；ICEGR 进一步让 SID、SFT、Preference 围绕 Query Intent 对齐，并给出真实电商线上 A/B。

留下的问题：语义一致并不保证业务世界可行。生成式系统可能在共现上正确，却违反地理、库存、预算、权限等硬约束。

关键推进：SPAR 将 geospatial structure 贯穿 SID → CPT → SFT：SI-SID 融合坐标、MG-CPT 学道路/距离/导航、TV-SFT 用 task vector 保留空间知识。四个 AMAP 工业数据集上，4B / 8B 相对 PLUM 平均 +28.54% / +38.32%。

下一阶段：Intent × Domain Constraint × Fresh Namespace × Prefix Survival × Cost-aware Decoding。真正值得做的不是再换一次 RQ-VAE，而是让 namespace、解码与业务约束一致。

主线 02 · Semantic ID

RQ-VAE → Dynamic / Query-aware SID → Domain-structured SID

上一阶段：Semantic ID 将随机 ID 变成可泛化的离散结构；Tlow 改 quantization geometry，TAGR 处理 live remapping，ICEGR 把 query intent 注入 SID；TAAL 指出 early-prefix survival 是 decoder bottleneck。

新矛盾：多数 SID 仍只是压缩 item/content embedding，业务硬结构只是附加 feature，无法保证 code topology 与真实世界 topology 一致。

关键节点：SPAR 提出更一般的命题：SID 应同时编码 what it is + what constraints govern it。

下一阶段：constraint-aware codebook、time-dependent SID、inventory/budget-aware SID、namespace versioning、online remapping 与 constraint-aware decoding。

主线 03 · Multi-interest Retrieval / Assignment

Single User Vector → Fixed K Interests → Variable Interest Set + Dynamic ANN Budget

关键节点：SetMIR 用 Hungarian one-to-one matching、presence score 与 query NMS 把多兴趣召回变成 set prediction；固定 10 个 ANN query 降到平均 6.70 个，R@10 保留 99.2%，线上整体 CVR +3.11%。

留下的问题：interest/source 被激活之后，仍缺统一 marginal utility 与 latency/TCO 目标。

承接：DS-Frame 在模型深度上学习 should-use-more-compute，ViSAR 在页面数上做 adaptive-k，9 月 4 日的 Declarative Attention 又让模型自己声明 should-attend-where。它们都在把 should-fire / how-much-budget 变成模型输出。

下一阶段：统一 budget controller 将横跨 interest head、retrieval source、candidate depth、reranker depth、beam width、attention scope 与 model route。

主线 04 · Scaling / Serving

固定 Runtime → Phase-aware Execution → Model-declared Compute → Device Routing

上一阶段解决了什么：FlashPrefill、HyQuant、H-Scale、vLLM/SGLang 的 runtime contract 将 prefill/decode、token sensitivity、precision 与 kernel path 分开优化；NVIDIA speculative decoding co-design 又把 acceptance、draft cost、KV 压力与 attention tile 放到同一个 Pareto。

2026.09.04 推进：Declarative Attention 不再由外部 selector 决定 sparse attention，而让模型在 reasoning 中输出 global / focus / local，vLLM 只需重写 KV block table；Gemma/Qwen attended tokens 分别下降 52.0% / 31.1%。

架构层信号：Graph Machine 保留 O(n) 可访问状态，但每个 sparse layer / KV head 只动态访问 2–4 / 4096 个位置，探索“长记忆 + 常数稀疏访问”。

运行时路由：Spotify Shunt 将 bulk read / boilerplate 强制分流到廉价 worker；NVIDIA PAIR 再将独立推理请求分发到局域网中合适节点。

下一阶段：Serving policy 会下沉到 request × phase × source × head × token × dtype × context-block × model × device，真正的目标函数是 quality / latency / p99 / memory / dollars 的联合 Pareto。

主线 05 · Foundation Model

Shared Backbone → Shared State → Specialized Supervision / Execution

上一阶段：OneModel、MaskRec 推动 shared backbone；CAMIE 说明 supervision geometry 往往比 backbone family 更关键；SPAR 用同一 LLM 同时承载空间 cognition 与行为推荐，却用 task vector 避免能力互相覆盖。

当前变化：DS-Frame 允许 easy/hard request 走不同深度；Declarative Attention 允许同一模型在不同 reasoning phase 使用不同 attention scope；Spotify Shunt 则进一步承认一些子任务根本不值得交给 frontier model。

下一阶段：Recommendation Foundation Model 更可能是 Shared Representation / State + Domain Adapter + Specialized Path + Budget Router，而不是“所有用户、所有阶段都走同一计算图”。

主线 06 · RL / Preference Alignment

Sparse Outcome Reward → Relevance Guard → Step-level Process Credit

上一阶段：ICEGR RCPO 用 relevance guard 包住 click/pay/GMV preference；PAO 在 frozen item index 下只对 positive-advantage candidate 更新，降低破坏 embedding manifold 的风险。

2026.09.04 推进：PRO-Step 训练 PRM 同时判断 logical validity 与 evidential grounding，再用 PRM-guided value tree search 生成 step preference，最终做 step-level DPO。核心变化是 reward 不再只看“最后答对没”，而问“这一步推理是否被当前证据支撑”。

下一阶段：推荐/搜索的 preference 也会从 final click/order 下沉到 query rewrite、source selection、retrieval path、beam prefix、rerank decision；reward 应联合 Relevance × Incremental Value × Process Validity × Latency/TCO × Safety。

主线 07 · Reasoning / Re-ranking

Score Fusion → Evidence-space Navigation → Process-grounded Reasoning

上一阶段：GAREN 将 reasoning retrieval 的“下一步”从 document neighbor 改成 semantic group：小 navigator 先选方向，大 reranker 再做细判断；BRIGHT reasoning nDCG@10=31.2 vs 最强 baseline 28.9。

2026.09.04 承接：PRO-Step 进一步指出，不仅“往哪搜”要学，搜索/推理轨迹中每一步也需要证据级 credit；Persistent Discovery Context 则让历史成功的 intent→object 映射成为未来 search 的 prior。

下一阶段：Reranking 会前移成 search-space planning、source/group routing、process verification、adaptive stopping，并和 retrieval policy 合流。

主线 08 · Full-stack Generative Rec

One Model → Shared Namespace → Cross-stage Contract → Agentic Control Plane

上一阶段：ICEGR 展示 SID 构造 → query SFT → preference → beam serving → 线上插流的工业全链路；SPAR 进一步要求 domain knowledge 跨 tokenization、CPT、SFT 持续保留。

2026.09.04 的更高层变化：CORAL 不再只优化某个模型，而是把 retrieval budget、Serving treatment 等控制变量纳入一个 LLM-native Harness，并通过真实 A/B 逐轮调整。

下一阶段：Full-stack 的“统一”不是统一模型尺寸，而是统一 Intent / Constraint / Namespace / State / Cost / Experiment Feedback，并由可审计 Agent 控制。

主线 09 · Agentic Search / Context Ranking

Query Rewrite → Trajectory Retrieval → Persistent Discovery → Model-declared Context

上一阶段：ITER 将历史 sub-query / visited docs 写入 retriever state；GAREN 提供 group-level evidence navigation；ViSAR 用 query-conditioned similarity 动态决定 page k。

2026.09.04 推进：Persistent Discovery Context 保存历史 intent→object 的成功发现，未来 retrieval 直接复用；Declarative Attention 则让 reader 自己声明需要 global / focus / local 哪一类上下文。

下一阶段 control loop：state → choose source/group → reuse memory → choose k/context → verify evidence → decide stop/continue，且 token/latency/tool cost 都是 policy 输入。

主线 10 · Model Routing

Fixed Model → Model Router → In-model Fast/Slow → Worker / Device Routing

上一阶段：Switchyard、AdaWidth、DS-Frame 将请求按价值路由到不同模型、宽度或推理深度；SetMIR 在 interest 级决定是否发 ANN。

2026.09.04 两个工业节点：Spotify Shunt 用 deterministic hook 识别 bulk read / code generation 并委托给廉价 worker，Java monorepo 平均 bulk-read token 节省约 90%；NVIDIA PAIR 根据 engine/model availability、queue/GPU utilization 将独立请求路由到不同本地节点。

下一阶段：Router 的 action space 会变成 source / model / depth / context / precision / device；训练目标需要直接使用 marginal utility per GPU-ms / dollar，而不只是 accuracy。

主线 11 · Agent Memory / Credit Assignment

Store Everything → Structured Memory → Attribute-before-Memorize

当前矛盾：长期 Agent 若只根据最终成败写经验，会把 planning error、execution error、环境波动混在一起，错误经验还会长期污染后续任务。

2026.09.04 关键节点：CHIME 将 memory 拆为 planning bank 与 execution bank，并先把 outcome 归因到 plan / execution / both / neither，再更新对应 bank；Persistent Discovery Context 则只持久化“意图→成功对象”这类可复用 discovery state。

下一阶段：memory 必须同时具备 credit attribution、freshness、confidence、conflict detection、scope/permission；推荐系统的实验记忆与 feature/search memory 也应遵守同样原则。

主线 12 · Agentic Recommendation Control Plane

Engineer-in-the-loop Tuning → LLM Proposal → Guardrailed Autonomous Experiment Loop

为什么这是新阶段：过去 Agent 多在研发侧写代码、做分析，或在用户侧对话推荐。CORAL 首次把 Agent 放到真实推荐系统 control plane：读取系统信号、检索历史、提出配置、经 deterministic optimizer 投影到预算约束、上线 A/B、把结果写回 memory。

工业证据：一个数百万用户 retrieval-budget 场景经过三轮出现 watch time +0.15%、sessions +0.16%，最大市场 sessions +0.77%；另一个 Serving-capacity 场景第一轮实现年化数百万美元节省，第二轮在 engagement 不变下将 savings 再扩大 44%。

留下的问题：多 Agent 并行调不同模块会不会干扰？如何做 causal attribution？如何处理 delayed reward 与实验流量成本？memory 中错误归因如何纠正？

下一阶段：Causal Attribution + Active Experimentation + Constrained Optimization + Agent Memory + Runtime Routing 会组成真正的推荐系统自治控制层。

未来 6–12 个月最值得押注：不是“再做一个 LLM+Rec wrapper”，而是把业务硬结构、动态预算、过程 credit、长期 memory、实验反馈与 runtime routing接成一个可观测、可约束、可验证的闭环。对工业推荐而言，这比单点模型结构更可能形成新的系统壁垒。
