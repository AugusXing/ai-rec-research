过去一年，推荐 / 搜索真正发生了什么？

主线不是“LLM 替代所有模块”，而是生成地址开始承载业务价值、预训练开始进入工业 Ranker、状态从隐式参数变成可缓存 / 可稀疏写入的资产、检索与 Agent 的工作量开始按请求预算化。9/16 的 VARG、LazFormer、LION、Question’s Gambit 与 DiBud，让这几条演进线第一次在同一天高度汇合。

年度总判断：接下来最值得押注的十个系统问题：① Semantic ID 是否能同时表达语义与业务价值；② generative path 如何与现有 ranker / cascade 对齐；③ foundation ranker 的 dense knowledge 怎样稳定迁移；④ 多槽位 / 多专家的 credit assignment 是否正确；⑤ 哪些 user state 应缓存、哪些 preference delta 应写入 sparse memory；⑥ retrieval depth 如何从固定 Top-K 改成真实资源预算；⑦ Agent 第一轮搜索是否值得单独训练；⑧ stage boundary 如何联合优化；⑨ beam/KV/speculative state 如何被 runtime 统一管理；⑩ self-improving system 如何验证每次 harness / kernel 变更。
主线 01 · Generative Retrieval

直接生成 Item → Semantic Namespace → Generated Index Asset → Retriever + Verifier → Value-aware / Ranker-aligned Generative Fast Lane

上一阶段解决了什么：TIGER / Semantic ID 路线证明 item namespace 可以被 decoder 生成；HypRQ-VAE 处理 long-tail codebook，EPIC 修复 token probability 与 item preference 的错位；SAM-D2Q 将昂贵生成结果离线写回 index；Generative Verifier 又把“深 top-K 中的 relevant item”推到真正被下游消费的短 prefix。

留下的问题：只把相关 item 生成出来还不够。工业搜索真正关心的是：同一语义簇里谁更有业务价值、生成路径与既有 ranker preference 是否一致、catalog 日更时 SID 是否稳定、生成候选如何进入原有 cascade。

9/16 关键推进：VARG 把 RQ-VAE 语义前缀与 value-aware 末级 token 结合，再用 Prefix-GRPO 对齐合法 SID、用户行为、搜索相关性与现有 ranker advantage；在线通过 reserved quota 绕过 item-level pre-rank 后交给成熟 final ranker。Tmall 14-day A/B：GMV +1.45%。

下一阶段：ANN / GR 双路召回 + budget router + verifier + final-ranker alignment。Semantic ID 不再只是 tokenizer 问题，而会与 business value、long-tail exploration、catalog refresh 和 downstream survival 联合设计。

主线 02 · Semantic ID / Full-stack Generative Rec

RQ-VAE → Long-tail Namespace → Item-level Posterior → Large-beam State-aware Serving → Value-aware Address

上一阶段：HypRQ-VAE 让 SID 更适配 power-law catalog，EPIC 把 item decision 与 partial-token likelihood 对齐；TGR 将 ranking / SID generation / page generation 串成 full-stack path；OneLA 则解决 large-beam recurrent state 复制，让生成式推荐真正进入 state-aware runtime。

9/16 的变化：VARG 进一步说明 SID 的末级地址可以显式编码业务 value ordering，而不只是“离散化 embedding”。这让 semantic namespace 从表示学习组件升级为业务排序资产。

下一阶段：研究重心从“怎么生成合法 ID”转向“地址如何长期稳定、如何随 catalog 增量更新、如何让地址本身承载可控先验、如何避免头部 value 先验挤压探索”。Serving 侧继续联合 beam budget、state layout、constraint decoding 与 dynamic verification。

主线 03 · Foundation Model / Industrial Ranking

Shared Embedding → Long-sequence Backbone → Generative Behavior Pretraining → Transferable Foundation Ranker

上一阶段解决了什么：HSTU / OneTrans / SORT 等把更强序列模型与统一建模带入 ranking，PTDG/MORE/UniRec 则继续改善 task-aware backbone 与 cross-stage fusion。但许多工业 ranker 仍主要依赖最近数周监督数据，dense backbone 很难像 LLM 一样从更长行为历史获得可迁移知识。

9/16 关键推进：LazFormer 先用一年行为做 autoregressive generative pretraining，再同时迁移 sparse + dense 参数；通过 transferable residual adapter 隔离 ranking-specific feature，通过 asymmetric multi-epoch 在 epoch 间重置 sparse 参数、保留 dense 参数累计学习。线上 GMV +9.85%，A10 QPS 仅下降 12.1%。

下一阶段：Foundation Ranker 的重点会变成 pretrain data governance、feature compatibility、adapter routing、long-sequence compression、sparse/dense 不同 learning clock、multi-domain transfer，而不是简单堆参数。

主线 04 · Lifelong / Continual User State

Recent Window → Target-aware Retrieval → Cacheable Chronicle → Preference-stage Drift → Sparse Mutable Memory

上一阶段：SIM/TWIN 从超长历史做 candidate-aware retrieval，精度高但重复计算；ChronicleRec 把长期历史压成带时间锚、target-independent 的 cacheable tokens；DRIFT 进一步指出历史越长不一定越好，应先按 preference drift 切阶段。

仍有问题：即使 serving 侧把用户历史变成 cache，训练侧持续用新流量 fine-tune 共享 decoder，仍会让高频偏好覆盖长尾 / inactive user 的稀有偏好，即 evolution conflict。

9/16 关键推进：Self-Evolving Memory / LION 用 sparse key-value memory 给 preference delta 一个局部写入空间，再用 consolidation loss 强化记忆，参数量不随用户数线性增长，官方代码已开放。

下一阶段：把训练期 mutable memory与Serving 期 cacheable user state统一：长期 backbone 低频更新，Chronicle / preference stage 中频更新，sparse memory / recent state 高频更新；所有状态都带 version、TTL、refresh policy 与兼容协议。

主线 05 · Multi-interest Retrieval / Credit Assignment

Multiple Interest Vectors → Diversity Regularization → Supervision Geometry / Exclusive Assignment

上一阶段：MIND / ComiRec 证明多个 user vector 能覆盖多峰兴趣，但 interest collapse 常被当成表示相似问题，用 orthogonality / contrastive diversity 正则处理。

9/15 关键推进：MIMA 把 request 内多 positive 做 Hungarian one-to-one assignment，让不同 interest 获得稳定 ownership；线上交易笔数 +5.60%。

9/16 的关联：LION 让不同 memory cell 只接收局部 preference update，VARG 让 SID prefix / value token 承担不同职责。三者共同说明：很多“collapse / interference”问题本质是梯度和状态 ownership 没被定义清楚。

下一阶段：soft assignment、dynamic slot count、interest identity across time、MoE expert ownership，以及把 recall source / interest / memory cell / downstream gain 做 counterfactual credit。

主线 06 · Scaling / Serving

Kernel 加速 → State Reuse → Runtime Contract → Adaptive Verification → Agent-generated Kernel → Request-level Compute Budget

上一阶段：FlashAttention、Paged KV、quantization 优化单模型；KVShareArena / ReST / OneLA 扩展到跨请求、beam ancestry 和 recurrent state；vLLM adaptive verification 开始按 acceptance 动态控制 speculative work；ForgeMegakernel 让 coding agent 自动生成 per-model kernel。

9/16 新信号：LazFormer 用 sparse attention + compression 把更深 ranker 的在线 QPS 损失压到 12.1%；MoE Retriever 又显示 query-time 可减少 expert 数而不重建 document index。这说明 dynamic compute 已从 LLM decode 延伸到 ranker 与 retriever。

下一阶段：统一的 runtime controller 会同时选择 sequence budget、retrieval access、expert budget、verify-K、beam、speculative depth、kernel variant，优化 P95 / cost / quality，而不是用固定模型配置服务所有请求。

主线 07 · Reasoning / Re-ranking

Cross-encoder → Structured Decode → Verifier-driven Repair → Output-side Verification → Ranker-aligned Generative Retrieval

上一阶段：hLLM 用 assignment 替代逐 token list generation；CHyD 将 evidence constraint 写进 decoding；Magenta 做 generate→verify→selective repair；Generative Verifier 把验证器插在 retriever 与 pre-rank 之间。

9/16 推进：VARG 不再只在召回后“验证”，而是在训练时就把现有 ranker advantage 写进 Prefix-GRPO reward，使 generative candidate 更容易被 downstream 接受。这是从 post-hoc verifier → train-time downstream alignment 的自然升级。

下一阶段：retriever / generator / verifier / ranker 的目标将逐步围绕 stage survival 和最终 business value 统一，但 serving 保持分阶段以控制成本和故障域。

主线 08 · Cross-stage Joint Optimization

Independent Stages → Teacher Alignment → Joint Fusion → Shared State / Contract → Generative Fast Lane

上一阶段：PTDG/MORE 让 task signal 更早进入 backbone；UniRec 让 pre-ranking/ranking fusion 同图优化；MIMA、ChronicleRec、Generative Verifier 分别重写 recall ownership、user state 与 recall→pre-rank boundary。

9/16 新推进：VARG 的线上架构提供一个非常现实的折中：不替换整条链路，而是生成少量候选走 reserved quota，绕过 item-level pre-rank，再由成熟 final ranker 接管。这是“训练更统一、Serving 仍 stage-local”的又一个工业范式。

下一阶段：每个 stage 除 score 外输出 confidence、state version、business prior、expected downstream gain、cost 与 failure reason；controller 决定下一 stage、是否扩召回、是否走 generative fast lane。

主线 09 · RL / Preference Alignment

Final Reward → Process Credit → Explore-vs-Execute → Prefix-level Business Alignment

上一阶段：SelfDR、SAM-D2Q、IGPO、RobustSGPO 把优化对象从最终答案扩展到 index / workflow；SAFARI 学 explore-vs-execute；MIMA 从监督结构解决 interest ownership。

9/16：VARG 的 Prefix-GRPO 把 reward 分解到合法性、行为、ranker advantage、搜索相关性，并对生成 prefix 层级加权。这比“最终买没买”更适合 constrained Semantic ID generation。

下一阶段：推荐 RL 会越来越像 structured credit assignment：哪个 prefix、哪个 interest、哪个 recall source、哪条 evidence、哪次 exploration 对最终收益负责，必须可分解而不是一把 reward 回传。

主线 10 · Agentic Search / Context Ranking / Model Routing

Fixed Query → Sufficiency Gate → Explore-vs-Execute → Gated Memory → First-move Planning + Access Budget

上一阶段：GeneralQPP 判断 evidence sufficiency；VikingRAG 复用 retrieval trace；Fugu / Gated-Memory Routing 决定模型与执行状态；SAFARI 学什么时候继续探索。

9/16 关键推进 1：Question’s Gambit 把 deep search 的第一轮独立成 clue decomposition → complementary queries → pooled rerank；GPT-5.5 在 BrowseComp-Plus 83.1→90.5。

下一阶段：controller 输出 first-move decomposition、retrieval source、access budget、verify-K、reranker/model/tool、state read/write、halt 的执行计划，并用 successful-task latency / cost 训练，而不是只优化单步准确率。

主线 11 · Retrieval Architecture / Model Routing

Dense Encoder → Decoder Retriever → MoE Retriever → Query-time Expert Budget

问题：更强 retrieval encoder 往往意味着更大 query latency，而 document index 一旦建好又不希望频繁重编码。

9/16 补位：MoE Language Models as Retrievers 显示 MoE 可用较少 active params 匹配更大 dense retriever，并可只在 query 侧减少 expert 数，不重训、不重建 document index。

下一阶段：将 expert budget 纳入 router：简单 query 少 expert，长尾 / 复杂 query 多 expert，再与 first-move、access budget、reranker escalation 联合调度。

主线 12 · Runtime Harness / Self-improving System

Static Prompt → Versioned Harness → Failure Attribution → Verifiable Code / Kernel Evolution

上一阶段：Ecdysis 指出 bad case 不应直接修改全局 harness，应先做 failure clustering；ForgeMegakernel 用 coding agent 生成 kernel，但由独立 mid-state oracle 校验 correctness。

9/16 的连接：VARG dual-loop catalog refresh、LazFormer pretrain→rank transfer、LION mutable memory 都进一步扩大“可更新状态”的范围。系统需要记录模型版本、SID 版本、user-state 版本、memory 版本与 index 版本，任何一层演化都必须能回滚和对比。

下一阶段：研究系统将把 versioned state + automatic evaluation + targeted mutation + safe rollback 作为默认能力，而不是把“模型重新训练成功”视为部署完成。
