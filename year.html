过去一年，推荐 / 搜索真正发生了什么？

主线不是“LLM 替代所有模块”，而是系统边界重划：Item ID 变成语义 namespace；用户状态从单向量走向 context / memory；retrieval 从静态 ANN / inverted index 走向 generative、可反馈、可资产化；ranking 从静态任务关系走向 context-aware / dynamic dependency；reranking 从逐 token generation 走向 reusable state + structured decode；Agent 从 prompt 拼接走向 inventory-grounded policy；Serving 则从单 kernel 优化继续扩展到 cache hierarchy、quantization contract、routing precision、compiler/toolchain。

年度总判断：未来 6–12 个月最值得押注的问题可压缩成八个：什么是正确的状态单位？什么计算应该离线资产化？哪些状态需要热更新？输出结构能否绕开 token-by-token decode？任务/候选/模型之间如何动态路由？反馈如何局部写回索引与 memory？cache / quantization / routing 如何形成统一 runtime contract？生产系统如何把 freshness、成本、正确性与质量放进同一控制面？
主线 01 · Generative Retrieval

生成 Item ID → 生成可被成熟检索系统消费的资产

上一阶段解决了什么：生成式召回证明用户序列可以直接生成离散 item namespace，Semantic ID 又让 token 带上 item 语义结构。

留下的问题：full generative retrieval 的 decode、catalog freshness、约束解码与在线成本高；工业搜索又不愿放弃倒排的低延迟、精确匹配与可解释性。

关键推进：SAM-D2Q 将 VLM + GRPO 放到离线索引构建侧，生成业务对齐 pseudo-query 写回 inverted index；线上仍是成熟 recall stack。

下一阶段：Generative Namespace + Offline Expansion + Sparse/Dense Hybrid + Freshness + Constraint + Serving Budget 的组合，而不是 decoder 单点胜负。

主线 02 · Semantic ID

RQ-VAE → Long-tail-aware Namespace → Item-level Posterior

上一阶段解决了什么：Semantic ID 让 item 不再只是随机整数，使 retrieval 与 sequence modeling 更容易统一。

留下的问题：power-law catalog 的 tail fidelity、partial SID 的 prefix survival、online insertion 与 versioning。

关键推进：HypRQ-VAE 用 hyperbolic geometry 承载幂律结构；EPIC 用 complete-item posterior 缓解局部 token likelihood 与完整 item preference 的错位。

下一阶段：namespace 必须原生支持 inventory/price/location constraints、online insertion、tail fairness 与版本兼容。

主线 03 · Scaling / Serving

Kernel Optimization → Reusable State → Cache / Numeric / Compiler Contract

上一阶段解决了什么：FlashAttention、paged KV、speculative decoding、quantization、disaggregated prefill/decode 把显性计算成本持续压低；DoPR、ReST 又证明 user/document state 可以 compute-once、reuse-many。

留下的问题：共享状态跨 GPU/host/worker 后，容量、一致性、量化 layout、metadata 与 failure recovery 变成新的尾延迟和可靠性瓶颈；低精度还会把 scale / fusion / router precision 变成跨模块 contract。

2026-09-09 关键推进：SGLang HiCache MLA host-dedup 让 TP ranks 不再默认各存一份 host cache；vLLM NVFP4 KV 把 backend capability 与 attention fusion 边界显式化；SGLang MoE router precision 表明低精度必须按功能角色分层。与此同时，CUDA Rust / cuTile Rust 把 kernel correctness 与编译期 ownership 推入 inference toolchain。

上一阶段解决了什么 → 还剩什么：过去重点是“算得更快”，现在要解决的是“这份 state 在哪、是否重复、以什么精度保存、谁能安全修改、哪个 backend 真支持这条 fusion”。

下一阶段：State Cache + Quantization Contract + Router + Compiler IR + Version/TTL 会共同组成 runtime control plane。对推荐 foundation model，这一层的重要性会快速接近模型结构本身。

主线 04 · Foundation Model / Multi-task Ranking

Shared Backbone → Context Unit → Dynamic Task Dependency

上一阶段解决了什么：统一 Transformer / foundation ranker 减少 feature engineering，多任务共享提升样本效率。

留下的问题：真实行为发生在 exposure/context 中，CTR→CVR→GMV 的依赖又不对所有 item/user 恒定。

关键推进：UniCon 把 context 当基本建模单位；PTDG 以 hard causal mask + item-conditioned low-rank graph 动态重连 task dependency。

下一阶段：shared context/slate state + dynamic task graph + adaptive compute + task-specific heads。

主线 05 · RL / Preference Alignment

Final Reward → Process Credit → Business-aligned Offline Asset

上一阶段解决了什么：推荐/搜索开始把 click/pay/GMV、grounding 与 reasoning correctness 写进 preference optimization。

留下的问题：高 QPS 链路无法默认支付长 CoT / 在线 policy token cost，reward 又随库存与流量漂移。

关键推进：SelfDR 把 reasoning teacher 蒸馏成 direct student；SAM-D2Q 把 GRPO 结果写成索引资产；IGPO 把长期策略放进可更新 guideline store，而不是频繁改模型权重。

下一阶段：slow reasoning offline + fast asset/student online + hard-case router。

主线 06 · Reasoning / Re-ranking

Full Cross-encoder → Reusable Prefix → Structured Assignment → Latent State

上一阶段解决了什么：LLM reranker 提高 listwise semantic quality。

留下的问题：document 重算、CoT、autoregressive list decode 三重在线成本。

关键推进：DoPR 复用 document-side state；hLLM 从一次 prefill 读 item-position matrix，再用 Hungarian assignment 得合法 permutation；LARK 用 latent visual checkpoints 缓解跨模态信息在多步推理中衰减。

下一阶段：reusable candidate state + structured decode + business constraints + cached latent reasoning。

主线 07 · Full-stack Generative Rec

One Model → Cross-stage Contract → 可复用状态与可验证控制面

上一阶段解决了什么：TGR 展示 ranking、Semantic ID generation、整页生成与 offline reasoning 的工业 full-stack 路线。

留下的问题：如果没有统一 state/version/serving/experiment contract，“一个模型”只会把复杂度搬进更大的 checkpoint。

关键推进：ReST、DoPR、SAM-D2Q、IGPO、AtomRec 分别定义 user state、document state、generated index asset、policy guideline、atomic memory 等可复用对象；今天的 HiCache / NVFP4 又把 runtime state 纳入同一问题。

下一阶段：统一 catalog namespace、user/context state、candidate state、policy/reward、runtime cache、budget 与 experiment controller。

主线 08 · Agentic Search / Context Ranking

Agent Trajectory → Inventory-grounded Policy → Atomic Evolving Memory

上一阶段解决了什么：Agent 通过 query planning、tool use、RAG trajectory 扩展固定 retriever；推荐 Agent 开始维护长期语义 memory。

留下的问题：动态 inventory 让 prompt 事实迅速 stale；coarse summary 覆盖兴趣阶段且缺乏 evidence。

关键推进：IGPO 分离长期 policy 与实时 inventory；AtomRec 把 memory 拆成可链接、局部演化 atomic units。

下一阶段：state observability、policy/memory versioning、trajectory replay、conflict resolution、TTL/privacy 与 cost router。

主线 09 · Model Routing / Feedback Loop

Static Route → Cache-aware Route → State-aware Control Plane

上一阶段解决了什么：routing 从单纯 load balancing 加入 prefix cache、device capability、cost/quality 等信号。

留下的问题：系统状态不只在 GPU KV；vector index、policy store、user memory、host cache、quant format 都会变化。

关键推进：SGLang KV Indexer / HiCache 将 cache ownership 暴露给 runtime；Embedding Surgery 让 feedback 写回 dense vectors；今天 MoE router precision 又提醒我们“routing”既是系统决策，也是模型数值决策。

下一阶段：Model Routing → State Routing：选择模型、state version、cache locality、precision path 与 reasoning budget。
