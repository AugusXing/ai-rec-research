过去一年，推荐系统真正发生了什么？

过去一年的主线并不是简单的“Transformer 更大”，而是推荐/搜索逐渐变成一个由 Foundation Representation、Generative / Semantic-ID Retrieval、Shared User State、Structured Supervision、Runtime Adaptation 与 Cost-aware Serving 共同组成的系统。今天加入 RecPFN 后，这条演进又多了一个重要分叉：Foundation Recommender 不一定要记住所有领域，也可以预训练一个“如何从少量目标域 context 中快速推断”的算法。

年度总判断：Item 从 ID 变 Token / Semantic ID；User 从场景特征集合变 Shared State；Ranker 从单业务模型变 Foundation；Embedding 从离线特征变可版本化资产；Reasoning 从一次性 CoT 变 Memory / Support Context；Retrieval 从固定 ANN 变 Dense × SID × Late Interaction 的多路径系统；Serving 从静态模型部署变成带有 Precision、Cache、Hardware、Determinism、Input Contract 的 Runtime Policy。2026 下半年最值得押注：Hybrid Dense×SID Retrieval、In-context / Amortized Recommendation、Unified Ranking Foundation、Task-aligned Index Compression、Continual Retriever–Reranker Learning、Stateful Memory、Agent Workflow Governance 与 Cost-aware Runtime Routing。
主线 01 · Generative Retrieval / Semantic ID

Two-Tower + ANN → Item-as-Token → SID 作为跨范式控制接口

上一阶段解决了什么：OneRec-V2、JD GenRec、Sona 把候选生成改写为 Item Token / Semantic ID 的自回归问题，让 Retrieval 能直接吸收序列建模和生成式训练。

留下的问题：纯生成路径有 Beam Cost、Prefix Error、Fresh Item Assignment、Coverage 与 SID churn；纯 Dense ANN 速度稳定，却缺少层级离散结构的显式监督。

关键推进：FSGR / DrIG 开始处理 identifier frequency、coverage 与可靠性；SIDScope 将 Tokenizer→Mapping→Generator 当成需要独立审计的 artifact contract；SSR-GRPO 更进一步，让 SID prefix 进入 dense retrieval 的 RL reward、hard negative、mask 和 Retrieval-DPO，而 Serving 仍走 ANN，Tmall 两周 A/B UCTCVR +0.99%、GMV +1.40%。

下一阶段：SID 很可能不是 Dense Retrieval 的替代品，而是 index bucket、reward、hard-negative curriculum、fresh-item routing 和 coverage audit 的控制层；真正值得做的是 query-aware Dense × SID × Generate hybrid router。

  • OneRec-V2 · Sona · FSGR · DrIG · SIDScope · SSR-GRPO
主线 02 · Foundation Model / In-context Recommendation

跨域预训练 → Shared Foundation → 预训练“如何适应新域”

上一阶段：RecGPT / UniSRec 类工作尝试把多个真实域汇总成 transferable recommender；OneModel 则从工业侧证明跨业务共享 Event Schema 与 User State 可行，将 Organic Rec、Ads、Merchant Recommendation 放在统一 long-context backbone 中，通过 scenario-aware modulation 保留业务差异，线上 Ads CTR +8.18%、广告价值 +3.43%。

留下的问题：把更多真实域混在一起并不自动等于 true zero-shot。推荐行为规律强依赖业务环境，新域仍可能需要重新 fine-tune。

2026-08-24 加入的新分叉：RecPFN 完全不用真实 clickstream 做预训练，而是在随机图 + latent-factor 的 SCM prior 上生成无限合成环境，让 6-layer ICL Transformer 学会从少量 support sequence 推断目标域 transition。新域无梯度更新：倒排索引选 context → 单次 forward 预测 next-item embedding → cosine Top-K。单 A100 预训练约 36h；在 8 个公开基准上零样本整体强于现有方法，Appliances HR/MRR 相比最佳零样本基线约 +53.2%/+48.1%，但 Yelp 仍退化。

下一阶段：Shared Foundation 与 PFN/ICL 并非二选一。更可能的系统是：全局 User/Item Foundation 提供 representation，Support/Memory Retriever 提供局部 domain evidence，轻量 ICL adapter 负责 request/domain adaptation；训练重点从“记住更多日志”转向“构造覆盖真实行为机制的 prior / simulator”。

  • OneModel · RecPFN · RecPFN Code
主线 03 · Retrieval / Index Geometry

Single Vector → Collaborative Geometry → Late Interaction 的任务对齐压缩

上一阶段：TTT-Embed、GEM、Think-to-Personalize 把 Query/User 表示从静态 encoder 推进到 test-time / reasoning-aware embedding；CoRRe 则把 LLM User Semantic 与 co-purchase graph / popularity 修正后的 Item Geometry 解耦，保留 ANN 工业路径。

索引问题开始成为算法问题：Variable-bit Quantization 证明 Matryoshka embedding 不同维度价值不均匀，固定 memory 下按结构分 bit 可让 PQ recall 最多 +8%、SQ +18%。CrossQ 从另一个方向指出 ColBERT token 也不应均匀压缩：传统 reconstruction loss 没保护真正决定 MaxSim 的 winner token 与 hard-negative margin；其 ranking-aligned conditional quantization 在 4 B/token 下 raw token storage 64× 压缩，在 8 B/token + light FT 下保持约 98% full-precision MRR@10。

下一阶段：索引会从“所有向量同一精度”变成 Query Value × Token Importance × Dimension Geometry × Freshness 的联合预算问题；Dense / Late Interaction / SID 也会共享同一套 index health、version 和 calibration 指标。

  • CoRRe · Variable-bit Quantization · CrossQ
主线 04 · Ranking Foundation / Long Sequence

Feature Interaction → Transformer-native → 跨业务共享 User State

上一阶段：RankMixer、OneRank、TM20K、UniDot 将精排从浅层 feature interaction 推向 Transformer-native、长行为序列和 sequence/interaction unified architecture。

关键推进：OneModel 的意义不只是更大的 Ranking 模型，而是把异构 action 映射为统一 Event Sequence，并将 User State 增量更新后缓存到低延迟 KV Store，请求时只做 vectorized candidate scoring。Foundation Ranking 的资产变成 Event Schema、User State、Content Representation 与 Serving Graph。

下一阶段：Dynamic Scenario Router、Conflict / Uncertainty Detection、共享 State 跨 Recall/Rank/Re-rank 复用；RecPFN 又提示“少量局部 support”可以作为 Shared State 的补充，而不是每个场景再复制模型。

  • RankMixer · OneRank · UniDot · OneModel
主线 05 · RL / Preference Alignment / Structured Supervision

Click Label → Semantic / Intent / Reward → Frequency-aware Teacher Budget

SSR-GRPO 用 SID + dense relevance 构造 retrieval reward；Think-to-Personalize 用 SFT→GRPO 把个性化 intent reasoning 直接对齐 Retrieval Utility；GateDiffInt 将 conversion signal 同时约束 diffusion 去噪和 LLM intent distillation；LLM Annotation × Click 则说明监督源也应动态分配：高频 Query 的真实 Click 更强，中低频 Query 更受益于 LLM relevance label。

下一阶段：Teacher 不再统一打标所有样本，Reward 也不再只有 CTR/CVR。更合理的是按 Frequency、Uncertainty、Business Value 与 Label Freshness 决定 Click、LLM label、SID structure、conversion、human feedback 的组合。

  • SSR-GRPO · Think-to-Personalize · GateDiffInt · LLM Annotation × Click
主线 06 · Reasoning / Re-ranking / Memory

一次性 CoT → 可复用 Experience → Continual Intent / Current State

rEDMRec 将推理经验蒸馏成可复用资产；SCoRD 用 Semantic Assistant + Dynamic Intent Memory 支持低成本持续更新；StateMem 则把长期 Memory 的目标从“检索历史事实”升级为显式 supersession、dependency propagation 与 current-state tracking。对重排来说，真正要表达的不是更多 history，而是当前还有效的 intent / constraint / state。

下一阶段：Re-ranking 与 Agent Memory 会共用 Relevance × Utility × Confidence × Drift × Supersession × Provenance 的 memory score；recommendation slate 的长期约束也可以进入 state machine，而不是只在最后一层规则混排。

  • rEDMRec · SCoRD · StateMem
主线 07 · Multimodal Foundation / AI Asset

多模态 Feature → Versioned Embedding Platform → Capability-aware Runtime

Netflix 的多模态个性化案例显示，大模型更现实的第一产品形态往往不是塞进 hot request path，而是将 CLIP / MediaFM 表示写入可版本化 Embedding Store，支持 backfill、rollback、projection cache 和 daily materialization；线上统一 Canvas + CLIP discovery metric +0.127%，query-aware artwork search playthrough +0.36%。

2026-08-24 的工程补充：Qwen Code 同一时间窗口增加 MiniMax image-generation provider schema 与真实 image content sniffing，说明多模态资产进入 Agent Runtime 后必须同时具备 capability metadata 与 input validation。Foundation Representation 的下一步不是“更多 embedding”，而是 version、format、quality、safety、freshness 都可被路由器理解。

  • Netflix Multimodal Asset Personalization · Qwen Code
主线 08 · Scaling / Serving

Dense Full Compute → Elastic Operating Point → Runtime Contract

Tevatron-Elastic、SilverTorch、TM20K 将 sequence length、precision、model granularity 和 GPU memory 拉进模型设计；FlashPrefill V2 把 block-sparse attention 与 FP8、Paged KV、Continuous Batching 接到 SGLang，128K 下 TTFT 最多 4.8×；ReCache 把动态 Tool/Skill Schema 变成可复用 Resource KV block；CacheRoute 进一步证明高 cache hit 不代表高 capacity，hot-key skew 与 load placement 必须联合优化。

今天的新增信号：vLLM 将多模态安全边界从 decode-size 前移到 streaming download byte budget；SGLang 在 Intel XPU 上固定 split-KV reduction order 支持 deterministic inference。它们说明 Serving 的成熟指标已从 throughput/latency 扩展到 admission、determinism、security、hardware portability 与 reproducibility。

下一阶段：统一 Runtime Router 根据 Utility、Latency、Context、Freshness、Precision、Cache Residency、Key Skew、Hardware、Determinism Requirement 与 SLO 决定模型/索引/算力路径。

  • FlashPrefill V2 · ReCache · CacheRoute · vLLM · SGLang
主线 09 · Agentic Search / Context Ranking

Tool Use → Workflow Governance → Evidence / Environment Reliability

PILOT 把 Agent 用于真实实验流程；PolicyGuide 加入 persistent workflow graph 与 proactive verifier；BrowseComp-Plus / ClimbMix 说明在 553M-doc 真实 corpus 上，evidence recall 会从理想化条件下的 84.3% 降到 21.4%，Search Calls +63%；Thinkingbox / EnvHarness 则把 stateful sandbox、重复可靠性和环境共演化纳入评估。

下一阶段：Agentic Search 不应只报 final answer accuracy，而要拆 Retriever、Planner、Reader、Tool Router、Evidence Provenance、Approval、Rollback 和 long-horizon pass^N。推荐运营 Agent 同样需要把实验显著性、流量保护、素材审核和策略归档放进 state machine。

  • PILOT · PolicyGuide · BrowseComp-Plus / ClimbMix · Thinkingbox
主线 10 · Full-stack Generative Rec / Model Routing

Stage-by-stage Pipeline → Unified Model，但不会取消 Runtime Routing

Sona 等 Full-stack Generative Recommendation 工作试图让召回、排序、重排共享一个生成式建模范式；与此同时 Adaptive Ranking、Adaptive RAG、FleetSieve、CacheRoute 又不断证明：请求价值、上下文长度、候选规模和硬件状态差异太大，不可能所有请求走同样的最大模型。

最终形态更可能是：模型层更统一，执行层更动态。Shared Foundation 负责能力，Router 决定什么时候走 Dense ANN、SID Generate、Late Interaction、Reasoning/ICL、heavy Ranker、light Ranker、compressed context 或 cached state。RecPFN 使这个观点更清晰：即使只有一个通用模型，support selection 本身仍是一种 routing。

  • Sona · Think-to-Personalize · RecPFN · FleetSieve
推荐精读路线

如果只沿一条路线读，建议这样串起来

OneRec-V2 / Sona→SIDScope / SSR-GRPO→OneModel→RecPFN→Think-to-Personalize→CrossQ / Variable-bit Index→CacheRoute / Runtime Policy

这条路线能看到推荐系统的核心矛盾如何从“表示学习”扩展为“表示如何生成、如何适应、如何索引、如何监督、如何在运行时分配资源”。
