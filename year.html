过去一年真正的主线：从“一个模型做更多”走向“表示、状态、执行路径、硬件与测量共同设计”

Semantic ID 让对象可生成；Generative Retrieval 把业务目标前移；Foundation Ranker 统一表示；Reasoning/Re-ranking 处理集合约束；Agentic Search 动态获取证据；Serving 把 attention/KV/precision/hardware 变成可路由资源。9 月 22–23 日的新工业证据进一步表明：stage 边界正在变软，但 execution path 不会消失；真正统一的是 state、representation、objective 与 measurement。

年度总判断：下一代工业推荐 / 搜索系统更像“Shared Representation + Multi-timescale User State + Heterogeneous Retrieval/Ranking Executors + Learned Controller + Counterfactual Measurement + Architecture-aware Runtime”。Controller 决定 {objective, retrieval path, inventory tier, candidate budget, evidence, reasoning, memory view, precision, draft, expert, hardware cell, halt}；measurement 层负责回答“这次改动真正改变了什么”；runtime 保证这些选择在真实硬件上既正确又经济。
主线 01 · Generative Retrieval

Semantic ID → Value-aware Generation → Objective-specific Policy → Retrieval/Ranking Shared Representation

上一阶段解决了什么：TIGER / RQ-VAE 让 item 具有 decoder 可生成地址；OneRec / OneSearch 把业务 value 前移；VARG / GR4AD 让生成策略直接感知 downstream value；UniPolicy 再把不同 objective 拆成共享 backbone 内的多个 policy。

留下的问题：生成式召回与下游 target-aware ranking 仍可能表示不一致；多层 residual code 还会产生 quantization error propagation 与长尾 code imbalance。

关键推进：UNIQUE 采用单层 flat quantization，并在同一个 early-fusion 表示里同时做 generative code retrieval 与 target-aware ranking。它没有抹掉两个 stage 的 execution 差异，而是让 ranking supervision 能反向塑造可生成地址。

主线 02 · Semantic ID

Hierarchical RQ Code → Long-tail Namespace → Value-aware Code → Flat / Versioned Address Layer

上一阶段：RQ-VAE 提供可生成离散地址；后续工作解决 code utilization、token likelihood 与 item posterior 错位、value-aware prefix。

新的阶段问题：地址一旦承担召回入口，就必须面对 catalog 增量、长尾冲突、code drift、跨版本兼容和 serving lookup。

9/23 的推进：UNIQUE 的 single-layer flat quantization 是强工业信号：层次化语义结构并非唯一答案，稳定、平衡、可在线映射可能比“代码树更漂亮”更重要。Balanced Quantization 把 code usage 直接变成训练约束。

下一阶段：flat/hierarchical hybrid、冷热 item 分层 namespace、online re-assignment、backward-compatible code version，以及把 code collision 与业务 exposure fairness 联合优化。

主线 03 · Scaling / Serving

Kernel / KV → Speculative Decoding → Architecture-aware Runtime → State Ownership + Learned Global Control

上一阶段：FlashAttention、Paged KV、continuous batching、speculative decoding 优化固定模型；随后 sparse attention、mHC、quantization 与 draft/target runtime contract 要求 Serving 理解模型语义；Google DLB 再把控制扩展到 datacenter cell。

9/23 的推进：H-Spec 直接挑战 drafter-side KV ownership：attention 复用 target KV、Mamba 仅注入 last hidden state，避免并发下额外 KV cache；Expert Coactivation 则把 DRAM→NPU 专家搬运成本写回 router 训练目标，吞吐 +21%。

主线 04 · Foundation Model / Ranking

Feature Interaction → Long-sequence Transformer → Foundation Ranker → Multi-timescale User State

上一阶段：DIN/DIEN、DCN、MMoE/PLE 到 HSTU/SORT/OneTrans，模型不断增加行为上下文和跨任务共享；生成式预训练进一步让行为序列具备 transferable representation。

核心矛盾：长期偏好、session intent、实时反馈与自然语言 taste 的更新频率不同。把 10⁵ 条历史每次都输入模型不是可持续的 state strategy。

关键推进：MuSeR 用时间压缩、多兴趣 state、异步 refresh/cache 与在线短期状态把超长历史移出请求关键路径；昨日 AutoViewMem 从 Agent memory 侧给出类似信号：结构化 state 可能比无限扩 context 更重要。

谨慎点：MuSeR 的公开消融提示，线上收益不能全部归因于 temporal compression；LLM 文本语义信号贡献很大。这反而强化一个判断：future foundation ranker 需要同时管理 ID state、semantic state 与 time-scale。

下一阶段：state store + foundation backbone；interest-level TTL；drift-triggered refresh；target-aware history retrieval；session/long-term state conflict resolution。

主线 05 · RL / Preference Alignment

Static Reward → Preference Optimization → On-policy Distillation → Downstream-utility RL

上一阶段：DPO/GRPO 与 on-policy distillation 把监督从静态标签推进到 policy-generated trajectories；RetireOPD 进一步处理 teacher 生命周期。

最近阶段：RAVEL 直接用 question→answer→retrieval 后的 rank improvement 训练 clarification policy，说明 RL 的高价值方向是“对齐系统 utility”，而不是只对齐语言表面偏好。

9/23 的连接：Answer-Oriented Context Construction 给出了更完整 reward decomposition：support、trust、organization、final answer。未来 Agentic Search 的 reward 可以从 final score 拆成 evidence gain、trust gain、context marginal utility、latency/cost。

下一阶段：ask/rewrite/retrieve/tool/halt 统一 action space；reward attribution 到 evidence；offline counterfactual + online RL 的组合。

主线 06 · Reasoning / Re-ranking

Cross-Encoder → Listwise → Multi-trajectory Reasoning → Reliable Context Construction

上一阶段：cross-encoder 解决 pair relevance；listwise/generative reranker 建模候选关系；MERIT-Rank 用多 trajectory 降低单链 reasoning 偶然性；MSS-Complement 把目标推进到 set sufficiency。

9/23 的推进：Answer-Oriented Context Construction 将“重排”再向前扩成 context construction：先判 Answer Support，再判 Trustworthiness，最后在预算内组织上下文。也就是说，最终 stage 的目标从“排序正确”升级为“为下游生成构造正确输入”。

主线 07 · Full-stack Generative Rec

Stage-wise Models → Generative Candidate → Shared Policy → Stage-collapsing but Heterogeneous Execution

上一阶段：生成式推荐试图把 recall/rank 收敛到单 decoder；随后工业实践发现，库存、延迟、回滚、业务隔离不允许所有 stage 真正消失。

关键转折：9/22 的 Hybrid GPU–CPU Retrieval 证明不同 inventory/hardware 路径应并存；9/23 的 UNIQUE 则证明不同 retrieval/ranking semantics 可以共享 early-fusion representation。两者合起来说明：统一的是 representation/objective，不是强迫 execution path 单一化。

下一阶段：shared user/item state + specialist executors；request-level stage collapse；source-aware ranker；generation/dense/sparse/graph retrieval 的统一 candidate accounting；跨 stage counterfactual logging。

主线 08 · Agentic Search / Context Ranking

Fixed Query → Adaptive Retrieval Plan → Interactive Evidence → Trust-aware Context Assembly

上一阶段：ORDER / DiBud 决定 source 与预算；RAVEL 学“下一步问什么”；RegimeAbstain 学“什么时候当前证据不够”。

9/23 的推进：Answer-Oriented Context Construction 将 evidence acquisition 与 final generation 之间补上 support/trust/organization 三个显式阶段，使 Agentic Search 从“多搜一点”走向“构建一组可靠、互补且预算受控的上下文”。

下一阶段：主动询问、source routing、freshness check、fact conflict resolution、context packing 和 abstention 统一成 stateful policy。

主线 09 · Model Routing / Controller

Static Router → Learned Latency Router → Hardware-aware Model Policy → Training-time Serving Objective

上一阶段：model routing 主要决定“小模型还是大模型”；随后扩展到 attention mode、precision、draft model、GPU cell 与 retrieval path。

9/23 的新边界：MoE Expert Coactivation 说明 controller 不一定只存在于 inference runtime；训练时的 router 就可以学习 serving-friendly activation pattern。H-Spec 则说明 state interface 本身也可成为 routing/architecture 设计变量。

下一阶段：模型质量、distinct experts、KV footprint、memory traffic、batch affinity、latency tail 与能耗联合优化；让 controller 从“选模型”变成“选执行计划”。

主线 10 · Measurement / Experimentation

Raw Engagement → Controlled A/B → Counterfactual Observability → Verifiable Automated R&D

为什么它现在成为主线：系统越复杂，指标越容易把内容质量、曝光位置、candidate source、模型行为和用户构成混在一起。没有可靠 attribution，自动化实验与 Agentic R&D 只会更快地产生错误结论。

关键工作：昨日 EvoPilot 强调 pairwise verifier 与可比较实验；今日 Netflix Counterfactual Observability 用 propensity、SNIPS/Hájek、incrementality 与历史 A/B 校准离线测量，11 组 row-removal A/B 的 weighted R²=0.8212。

未来 6–12 个月值得押注

5 个高杠杆研究问题

① Unified representation, heterogeneous execution：共享表示与目标，但保留最经济的执行路径。
② User state as a system：长期/短期/语义/负反馈 state 的 TTL、refresh、version、conflict。
③ Counterfactual cross-stage credit：一个候选从召回到曝光，哪个 stage 真正贡献价值。
④ Training-aware serving：让 router、quantization、draft/expert pattern 在训练时感知真实 memory/latency。
⑤ Reliable context / slate construction：从 pointwise relevance 转向 support、trust、complementarity 与 marginal utility。
