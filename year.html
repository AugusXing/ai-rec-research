2026-11-03 · 年度技术演进 · 9 项

“单点相关/单次预测”之后：List 覆盖、可靠性反馈与动态算力

Generative Retrieval / Semantic ID / Foundation Model

TIGER / Semantic ID 对象编码 → xPRT 跨段证据 → MILES-Rec 多 Query 意图集合

上一阶段解决可生成索引地址和语义候选，留下了多种需求只能被一个 Query 代表、同类证据重复的问题。MILES-Rec 引入互补匹配和顺序奖励；下一步用 SID + 多意图 List 构建真正不重复的商品评价证据召回。

RL / Preference Alignment / Full-stack Generative Rec

Outcome-only GRPO → MILES-Rec List/Query 双层 Advantage → Li²SAO 冷启动 Critic

上一阶段解决生成结果整体偏好拟合，留下局部贡献难归因、异步训练长尾和 Critic 冷启动偏差。MILES-Rec 给 Query token 局部优势；Li²SAO 分阶段建 Actor/Critic。未来必须解决有偏真实 List Reward 下的反事实估计与 value 校准。

Reasoning / Re-ranking / Agentic Search / Context Ranking

检索命中 → 多约束同一事实满足 → 过程可靠性决定是否补搜索

ProSearch 用 3–5 条条件暴露多约束绑定的错误；Metacognitive Search 用 before/after reliability 的差异指导检索；Multi-Tool Completeness 强调工具依赖集合是否齐全。下一阶段将证据完整率与 token 成本/真实用户价值共同优化。

Scaling / Serving / Model Routing

静态 ANN/完整 RAG Context → Fidelity Synopsis 与知识编译门控

上一阶段提高固定 P99 预算内的准确率，仍要求简单 Query 为最难 Query 买单。Fidelity Synopses 降 ANN 中位数成本到 0.72×；RAGFlow 知识编译 平均减 38% token；下一步比较真实精度/延迟/维护成本 Pareto，不把离线成本直接当线上收益。

推荐环境模拟 / Reward 校准

单轨迹响应预测 → BrowseFlow 事件分布 → 可检验的反事实仿真

BrowseFlow 用 extent + sparse-event flow 学习完整浏览分布，虽然 Event Energy Score 明显改善，但点击 AUC 不总是领先。下一步要把模拟器置于随机曝光试验验证其跨策略可信度，避免历史 policy bias。

2026-11-02 · 年度演进 · 8 篇补充精读

从“统一模型/单路由”转向“可信授权 + 多证据 + 预算分配”

Generative Retrieval / Semantic ID / Foundation Model

TIGER 可生成地址 → RoFiGR/GR4AD-X 前缀价值 → xPRT 跨段训练 / Contextual Embedding 多证据

已有 SID 工作改善可达性但不自动保证观点覆盖。xPRT 利用无标注文档跨段信号，Perplexity 用验证证据而非单 gold chunk 训练；未来要与 SID 索引联合衡量属性和差评覆盖。

Full-stack Generative Rec / User State

独立用户向量与 PRISM Event Code → FedRecAgent 条件化协作记忆

FedRecAgent 不动 LLM 参数，以本地私人记忆和条件—转移—理由共享跨人群经验；下一阶段是隐私泄漏验证、全库候选和工业 A/B，而不是仅凭 sampled NDCG 推断收益。

RL / Preference Alignment

静态 List Reward → CASH 动态许可 / EPCG → PIVOT 局部教师纠偏

CASH 以真实广告预算在线实验验证可靠性选择的研究价值；PIVOT 解决全失败 rollout 缺可学习信号。尚需将 Reward 反事实偏差与教师误差同时纳入多目标推荐生成。

Reasoning / Re-ranking / Agentic Search / Context Ranking

固定 TopK → Coverage-RAG → M-ER 有预算图探索 → Select/Spawn 策略评估

M-ER 用 MCTS 和 LLM 反思控制多跳图扩展，Search Policy 将继续看列表和新搜索放进共同的判断预算；未来联结真实 List 效用而非单纯多检索。

Scaling / Serving / Model Routing

单一 Router → Multi-Router → Multi-View MoE 固定专家预算内提质

Multi-View MoE 增强专家选择并用路由分歧改变专家输入，保持专家激活数和 all-to-all 量不变；下一阶段需做全链路 GPU-ms、负载不均、P99 与生产效果评估。

2026-11-01 · 年度演进增量 · 周末精读 9 篇

将“更多证据”转成“可计算、可监督、可审计的排序决策”

Generative Retrieval / Semantic ID

TIGER → 语义 SID → RoFiGR 协同粗层路由 → GR4AD-X Prefix Value

仅重构文本相似空间，早期 Beam 可能剔除协同高价值候选；RoFiGR 对齐 L1/L2 前缀和协同 teacher，延续 GR4AD-X 的早路由价值讨论。下一步做无偏价值前缀训练、动态树与长尾保证。

Scaling / Serving / Full-stack Generative Rec

全历史每层传播 → LWR Candidate Workspace；全 Beam 读历史 → PFA Progressive Focus

LWR 把证据读取和状态传播分开；PFA 把早期全局注意力和后续稀疏访问分开。两者体现独立调节历史规模、深度、解码步数和 KV 预算。下一步比较全链路 GPU-ms 与 P99，而非只看 FLOPs。

Foundation Model / User State / Cross-stage

静态 item embedding → PRISM User×Item Event Code → PALATE 共享 User Embedding

PRISM 通过上游多塔信息压缩个性化历史行为，与 PALATE 的用户级共享向量互补：事件级精度与用户级复用。下一步做时间穿越防护、跨天 embedding 兼容和真实交易 A/B。

RL / Preference Alignment / Model Routing

LLM 改配置后全训 → RecRSI 试训真排序探针 → 真实 List Reward 决策

RecRSI 用早期全库 NDCG 选实验，弥补仅用训练 Loss 的伪改进；连接 10/31 的 UGR/IPS/Position Bias 时，必须解决观测数据偏差与 outcome 目标之间的差异。下一步做多目标、风险控制和在线安全发布。

Reasoning/Re-ranking / Agentic Search / Context Ranking

相似 TopK → Coverage-RAG 互补证据 → Glance 共享 Generator → ZEST-Search 成本感知轨迹

Coverage-RAG 强调知识点覆盖；Glance 强调模型与 KV 复用；ZEST-Search 控制检索工具步数；AgenticDS 为数据/工具添加确定性契约。下一步联合优化证据真实性、用户价值与服务成本。

2026-10-30 · 年度演进增量 · 9 篇

Generative Retrieval / Semantic ID / Full-stack Generative Rec

TIGER / 通用历史 → 逐层历史读取 → 逐 token 监督对齐

原始 TIGER 让 item 可由 SID 解码，却把历史所有层语义混合；LESSRec 根据当前输出层级选择对应历史信息并补 item-level 全局序列。这与 10/29 REGER（prefix 教师）、KL-MOPD（位置级蒸馏）形成输入选择→监督投影→Loss 加权的路径。下一步需核验长历史 QPS、码本更新以及 Listwise Reward 是否可以迁移。

DuoLM 与 LoopRec 探索计算复用和按需推理深度，留下一项系统缺口：Looped 模型即便共享参数，跨 recurrence 的历史 KV 仍膨胀。BeNice! 通过随机深度训练及首轮 KV 兼容后训练处理这项显存成本，但效率主要来自模拟流量，下一步是生产级 P99、内存峰值和质量联合验证。

RL / Preference Alignment：从 List Reward 到可纠错的用户状态

此前 Raw-RAG 提醒压缩/生成状态可能损伤真实证据；LARA 说明 Agent 消费不应直接等于用户正反馈，Jev-DLC 将 typed prefer/reject correction 变为有界的动作和成对偏好记忆。未解决的是曝光反事实、延迟下单与非显式负反馈。下一阶段可以先做 List-level Reward 审计，再尝试轻量个性化校准与 DPO/RL 联合训练。

Agentic Search / Context Ranking：从固定工具链到自动结构搜索

RouteWeaver 关注工作流/Worker 路由，而 IRAH 将控制决策下沉到 RAG 的 chunk / embedding / reranker 结构及数值超参。LARA 是两者部署前的测量先决条件：如果行为无法归因，自动优化器会优化错误代理目标。下一步是 OOD 鲁棒性、人工审核与成本敏感控制。

Model Routing / Sparse Retrieval：查询时延不代表端到端经济性

GRIP 的 term-seeded sparse graph 在固定 Recall@10 下有显著查询提速，代价却是更高内存和建图时间；FlexVDR 让多向量 Query 决定预算。这要求将索引更新频率、质量曲线和峰值延迟共同写入 Router 成本函数。动态 Chunk 重算评估 又把跨版本重嵌入的 token 量加入 TCO，补上长期服务缺口。
