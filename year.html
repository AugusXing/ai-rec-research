过去一年真正的主线：从“统一模型”走向“共享状态 + 专家执行路径 + 条件化控制器”

推荐 / 搜索与 LLM 系统正在形成共同架构：representation、state、objective、measurement 越来越共享，execution path 却越来越专业化。Semantic ID 让对象可生成；Generative Retrieval 把业务价值前移；Foundation Model 统一表征；Reasoning / Re-ranking 优化集合与证据；Agentic Search 主动获取信息；Serving 按 KV、precision、prefill/decode 拆分；Model Routing 则继续升级为 memory / Skill / model / budget 的统一 activation policy。

年度总判断：下一代工业 AI / 推荐系统更像 Shared Representation + Multi-timescale State + Specialist Executors + Conditional Controller + Counterfactual Measurement + Architecture-aware Runtime。Controller 的 action 已从“选哪个模型”扩展到 {retrieval source, candidate budget, feature regime, context view, memory recall, Skill activation, reasoning depth, precision, KV owner, hardware cell, halt}。9/25 的 PaMER、SkillApt、TEMPS 与 GPT-6 Sol/Luna 让这条主线更加清晰：可用不等于值得激活，相关不等于值得付费。
主线 01 · Generative Retrieval

Semantic ID → Value-aware Generation → Shared Retrieval / Ranking Representation

上一阶段解决了什么：RQ-VAE / TIGER 类方法让 item 拥有 decoder 可生成地址；OneRec / OneSearch 将业务价值前移；VARG / UniPolicy 开始让生成策略感知 downstream objective。

留下什么问题：层次 residual code 的量化误差、catalog 增量导致 namespace drift，以及 retrieval representation 与 ranking supervision 仍可能不一致。

关键推进：UNIQUE 用 flat quantization + early-fusion representation 同时支持 generative retrieval 与 target-aware ranking，说明“共享表示、保留不同执行语义”比强行一个 stage 更现实。

主线 02 · Semantic ID

离散地址 → 可学习语义地址 → 可版本化对象身份

上一阶段解决了什么：Semantic ID 让推荐对象从 opaque item id 变成可被序列模型、生成模型共享的离散语义 token。

留下什么问题：长尾不平衡、新 item 增量分配、跨市场 / 多域 namespace、code collision 与版本回滚仍缺统一工业协议。

关键推进：UNIQUE 的 flat quantization 与 Spotify 将 Semantic ID 直接纳入 LLM reranker，说明 SID 正从“生成式召回内部表示”变成跨 stage 的 shared object language。

主线 03 · Foundation Model for Recommendation

Feature Interaction → Long-sequence Transformer → Foundation Ranker → Continual Capacity Growth

上一阶段解决了什么：DIN/DIEN、DCN、HSTU/SORT 等逐步把用户历史、特征交互和多任务统一到更大的 backbone。

留下什么问题：大模型训练成本高、行为状态更新频率不同、扩容常造成 prediction discontinuity，Dense→MoE 迁移又会破坏已有能力。

关键推进：Inherit4Rec 关注模型容量连续演进；Spotify Robust Fusion 则证明 LLM ranker 可以把 Semantic ID、文本与行为统计放入统一表示，同时用 missing-feature training 保持鲁棒。

主线 04 · Scaling / Serving

Kernel Optimization → KV Ownership → Phase-specialized Execution → Global Runtime Controller

上一阶段解决了什么：PagedAttention、speculative decoding、quantization 与 sparse attention 已显著降低单点 latency。

留下什么问题：FLOPs 降低不等于真实延迟下降，HBM traffic、KV duplication、prefill/decode 不同瓶颈、precision stability 与 batch shape 仍会主导成本。

关键推进：Flash-dLLM 联合 cache+verify；HySparse2 重定义 KV ownership；Disaggregated Quantization 将 prefill/decode 分开优化。

主线 05 · RL / Preference Alignment

Static Labels → Preference Optimization → On-policy Correction → Value-aware Execution

上一阶段解决了什么：DPO / RLHF / GRPO 等把单一监督学习扩展为 preference / reward optimization。

留下什么问题：offline preference 与真实策略轨迹存在 distribution shift；推荐系统还要处理 delayed reward、曝光偏差和多目标冲突。

关键推进：9/24 的 On-Policy Distillation 显示低比特模型必须在自身真实 prefix 上被 teacher 修正；同一思想可迁移到推荐 controller：让 policy 在自己会到达的 request regime 上学习 source/budget/model action。

主线 06 · Reasoning / Re-ranking

Pointwise Score → List/Set Utility → Learned Search Policy → Budgeted Reasoning

上一阶段解决了什么：listwise / setwise 方法把多样性、覆盖、约束与候选间相互作用放进最终排序。

留下什么问题：reasoning rerank 很贵，复杂 planner 未必优于强 retrieval baseline，且最终收益难以做 stage attribution。

关键推进：Beyond Repeated Sampling 训练小 search policy 先选思路；9/25 的 Context Planning Negative Result 则提醒 controller 必须在 budget-matched strong baseline 上创造真实增量。

主线 07 · Full-stack Generative Recommendation

Independent Stages → Shared Representation / Objective → Multiple Executors + Unified Measurement

上一阶段解决了什么：生成式推荐把 retrieval/ranking/generation 放入共同 token space，减少手工 stage interface。

留下什么问题：真实系统仍有不同 inventory size、SLA、特征可用性、硬件和回滚要求，因此“一个模型吞掉所有 stage”往往不现实。

关键推进：UNIQUE、Spotify Robust Fusion、LinkedIn deep pre-ranking 与 Netflix counterfactual observability 共同形成更现实的 full-stack 路线：共享 representation/state/objective，但保留 specialist executor，并统一测量。

主线 08 · Agentic Search / Context Ranking

Retrieve Documents → Construct Evidence → Memory / Skill Activation → Interactive Search

上一阶段解决了什么：RAG 将检索接到生成器；Answer-oriented Context Construction 把 relevance 推进到 support / trust / organization。

留下什么问题：检索到的 context/Skill 不一定值得加载；长程 Agent 历史会不断膨胀；时间等结构约束在纯 semantic embedding 中容易丢失。

关键推进：PaMER 学习何时压缩/恢复 memory；SkillApt 将 Skill retrieval 与 activation 解耦；TEMPS 将 temporal compatibility 作为独立 retrieval axis。

主线 09 · Model Routing

Fallback Rules → Learned Routing → Cost-aware Routing → Conditional Execution Control

上一阶段解决了什么：router 已能按 query 难度、SLO 或硬件负载选择不同模型和 serving cell。

留下什么问题：只按“难/易”路由没有显式连接业务价值、token 成本、失败风险、cache reuse 与 downstream reward。

关键推进：GPT-6 Sol/Luna 继续压低不同能力档位成本，使多层 model portfolio 更有价值；PaMER / SkillApt 又把 routing action 扩展到 memory 与 Skill activation。

2026.09.25 新增交叉主线 · Constraint-aware Retrieval

One Semantic Space → Semantic Backbone + Constraint-specific Axes

上一阶段解决了什么：dense / hybrid retrieval 已能很好建模主题相关性。

留下什么问题：时间、地理、新鲜度、价格、库存、可信度具有不同的几何与非对称关系，强行塞进单一 cosine space 会互相干扰。

关键推进：TEMPS 用独立 Gaussian temporal embedding + directional inclusion score，在冻结 semantic retriever 的前提下提升 retrieval 与 RAG。
