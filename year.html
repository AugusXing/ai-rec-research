Rolling 12-Month Review · 更新至 2026.08.18

过去一年，推荐系统真正发生了什么？

主线不再只是“模型变大”。推荐/搜索正在从 Stage-specific Predictor 走向 Generative / Foundation / Policy Model + Elastic Retrieval + Agentic Interaction + Request-aware Serving。越来越多工作开始把候选数、模型深度、Embedding 宽度、Reasoning Steps、Tool Calls 与停止时机都当成运行时决策。

年度总判断：Item 变 Token、Ranker 变 Policy、Social Graph 变 Reasoning Space、长期历史变可压缩 Memory、业务目标变 Reward、模型大小/检索深度变 Runtime State。进入 2026 年 8 月后，最值得押注的问题进一步收敛到 Reliable GenRetrieval、Semantic ID Coverage、Elastic Retrieval、Context Ranking、Uncertainty-aware Ranking、Cost-aware Stopping 与 Unified Request Router。
主线 01 · Generative Retrieval

Two-Tower + ANN → Item-as-Token → Reliable GenRetrieval

上一阶段解决了什么：OneRec-V2 / JD GenRec 把候选生成变成 Item Token 自回归生成，并把真实反馈/RL 引入 Post-training；Sona 更进一步，用单一生成模型替代 15+ Candidate Generator、Pre-rank 与 Rank。

留下的问题：自回归 Identifier 会有 Prefix Error、Token Frequency Bias、Fresh Item Assignment、Beam Cost 与候选覆盖问题。

最新推进：FSGR 从 Quantization + Training 两侧处理 SID Token Frequency Bias；DrIG 用 Dual-role Identifier + Set Prior 约束 Beam，并用 Dense Rerank 恢复精度。

下一阶段：Generate 与 ANN 不会简单二选一，更可能是 Query-aware Hybrid Retrieval：不同请求动态选择 ANN / GenRetrieval / Dense Recovery / Rerank Depth。

  • OneRec-V2
  • JD GenRec
  • Sona
  • FSGR
  • DrIG
主线 02 · Semantic ID

Tokenizer 从实现细节变成流量分配基础设施

FORGE 等工作让 SID 同时承载内容语义与协同行为；HD-Rec 用层级 Codebook / Routing 做跨域共享；2026 年 8 月的研究进一步说明：SID 不是只看 Reconstruction 或 Recall@K，Token Frequency、Codebook Coverage、Long-tail Exposure、层级稳定性、新 Item 分配都会改变真实推荐分布。

问题如何变化：Tokenizer 的评估会越来越像推荐系统本身的流量/公平性评估，而不是纯表示学习指标。

  • FORGE
  • HD-Rec
  • FSGR
主线 03 · Elastic Retrieval / Runtime Adaptation

Static Retriever → Test-time Adaptation → Elastic Operating Point

上一阶段：Dense Retriever 训练结束后，线上 Query → Embedding → ANN 基本是固定函数。TTT-Embed 开始冻结 Encoder/Index，仅利用 Reranker Reward 在 Test Time 优化 Query Embedding；GEM 进一步先 Reason，再生成 Embedding Token。

2026-08-18 补入：Tevatron-Elastic 把 Depth / Token / Embedding Width 统一成一个 Granularity 接口，一个 checkpoint 可以在部署时切换多个 Retriever/Reranker operating point。它把“压缩模型”改写成“按请求分配模型规模”。

下一阶段：统一 Router 判断：直接 Embed 还是 Test-time Optimize？跑多少层？Embedding 多宽？Top-K 多大？是否 Rerank？这会把 Retriever 与 Reranker 变成一个连续可调的计算系统。

  • TTT-Embed
  • GEM
  • Tevatron-Elastic · 官方代码
主线 04 · Ranking Foundation Model

Feature Tower → Transformer-native → Robust / Request-aware Ranking

RankMixer 等把多任务 Feature Interaction 做到成熟；OneRank 用 Task Token、Cross-task Attention、Candidate Context 与 Dynamic Matching 移除 Encoder–Predictor 边界。Meta Adaptive Ranking 进一步把 Request-oriented Computation Sharing、动态路由、Selective FP8、多卡 Serving 直接引入 Ranker。

2026-08 新变化：DrEM 把上游 pxtr Prediction Noise 视为一等变量，同时修正 supervision-side 与 feature-side 噪声；STAR 则说明结构化 Token、时间特征与 Target-aware Decode 仍有高 ROI。

下一阶段：Ranker 的输入不只是 Feature，而是 Feature + Uncertainty + Request Value + Compute Budget。

  • RankMixer
  • OneRank
  • DrEM
  • STAR
主线 05 · Long Sequence / Scaling / Serving

从“序列更长”到“每个 Token / KV / Layer 值不值得付费”

Netflix Scaling、OneRec-V2 等证明更长历史和更大模型有效，但 Prefill、Attention、KV Cache、HBM、QPS 很快成为第一约束。TM20K 用 Full-attention Teacher 学 20K 历史，再让 Student Token Merge；CoinRAG 把 KV Cache 复用粒度从 Chunk 推向 Query-relevant Nugget；SilverTorch 把 Index、Filter、ANN、Neural Rerank、Multi-task Scoring 收入统一 GPU Model Graph。

新的统一问题：哪些 Token、KV、Candidate、Layer、Expert 值得在这个请求上计算？Tevatron-Elastic 进一步说明，连 Retriever 的 Layer/Width 都可以成为请求级资源。

  • Netflix Scaling
  • TM20K
  • CoinRAG
  • SilverTorch
主线 06 · Foundation Model + Alignment

Pattern Matching → Foundation Representation → Business Reward Alignment

OpenOneRec 等把语言知识与推荐能力放进统一 Foundation Model；但更强表示不自动等于业务目标对齐。WEBTOON Progressive Alignment 将 Post-training 拆成 LP → FFT → RFT：密集行为学 Policy，稀疏业务指标训练 Reward Model 做最终 Alignment。

下一阶段：Reward Design、Calibration、Counterfactual Evaluation、长期留存/疲劳/生态/GMV 的统一，比“选 PPO 还是 GRPO”更重要。

  • OpenOneRec
  • Progressive Alignment · 官方代码
主线 07 · RL / Reasoning / Re-ranking

Score → List Policy → Adaptive Thinking

GR2、MetaStrategy 让模型显式生成列表级策略；REAM 把问题推进到 Recommendation Reasoning Length。Search-R1 Stopping 则把“是否继续检索”独立成 learned judge。

年度判断：工业 Reasoning Ranking 必须有 Router：哪类请求值得 Think？Think 多久？是否调用 Frontier Model？什么时候让传统 Ranker 执行？什么时候停止？

  • GR2
  • MetaStrategy
  • REAM
  • Search-R1 Stopping
主线 08 · Full-stack Generative Recommendation

传统 Cascade 的阶段边界被模型侧与系统侧同时侵蚀

Sona 在 Yandex Music 用单一生成式模型替代 15+ Candidate Generators、Pre-rank 与 Rank；SilverTorch 从系统侧把检索微服务改写成统一 GPU-native Model Graph。两条路线正在汇合：统一 User Representation + 可组合模块 + 动态 Request Routing，短期比“一次性拆掉全部 Cascade”更现实。

  • Sona
  • SilverTorch
主线 09 · Agentic Search / Context Ranking

Top-K Retrieval → Context Runtime → Relevance-guided Interaction

前半程：Agentic-R / CoSearch 联动 Retriever 与 Reasoner；Context Interference 把“证据越多不一定越好”变成一等问题；EAHR 让 Retrieval Depth 成为 Query-specific State；DocMemo 用 Page Belief 管证据探索；Search-R1 Stopping 学“什么时候不再搜”。

2026-08-18 补入两个强约束：RARG 让 Relevance 从 Top-K Gate 升级为 Corpus Interaction 的执行先验；BM25 Wins at Scale 在 28 个嵌套语料规模上显示，随着语料扩大，Global Candidate Ranking 的价值反而上升，Agent 更适合放在 Ranked Discovery 之后。

下一阶段：Context Ranking 会联合决定读多少、读哪路、先搜哪里、是否扩展、何时停止；指标应从 Recall@K 扩展到 Answer/Recommendation Utility ÷ Cost/Latency。

  • Context Interference
  • EAHR
  • DocMemo
  • Search-R1 Stopping
  • RARG
  • BM25 Wins at Scale
主线 10 · Model Routing / Dynamic Compute

推荐系统十年的 Cascade 思想正在迁移到 LLM / Agent Serving

Pre-Inference Routing 提醒一个重要经济学前提：Cheap Model 必须有足够 Failure Rate，并且 Failure 能由廉价特征预测，否则复杂 Router 没有价值。ConnectionMind、MetaStrategy 体现“大模型规划 / 小模型执行”；Tevatron-Elastic 则让“同一个 Retriever/Reranker 的 operating point”也能成为 Router 输出。

2026 下半年最值得押注：统一 Request Value Estimator。输入 Query/User/Context/候选/系统负载，输出 Retriever 类型与大小、Top-K、Ranker/Reranker 深度、Reasoning Steps、Context Budget、Stop Timing。

  • Pre-Inference Routing
  • ConnectionMind
  • MetaStrategy
  • Tevatron-Elastic
给推荐/搜索算法工程师的技能地图：未来 1–2 年最有复利的组合是 Ranking/Recall 基础 → Transformer/GenRec → Semantic ID / Retrieval → RL/Reasoning → GPU/Serving/KV Cache → Online Experiment / Calibration / Cost Modeling。能把离线模型增益翻译成真实 QPS、Latency、Coverage、GMV/Retention 与 TCO，并设计动态算力策略的人，会比单纯追模型结构更稀缺。
