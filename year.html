Rolling 12-Month Review · 更新至 2026.08.20

过去一年，推荐系统真正发生了什么？

主线已经从“把模型做得更大”转成 Generative / Foundation / Policy Model + Multimodal Embedding Platform + Lifecycle Filter + Agentic Experimentation + Request-aware Serving。最新变化进一步说明：强模型能力正在被移出热请求路径，沉淀成可预计算表示、可编辑记忆、可治理 Agent 和可审计接口。

年度总判断：Item 变 Token、内容变 Foundation Embedding、Ranker 变 Policy、Reasoning 变 Memory、Agent 变 Experiment Control Plane、Freshness 变 Eligibility、Offline Evaluation 变 System Counterfactual。2026 下半年最值得押注的问题收敛到 Reliable GenRetrieval、Semantic-ID Interface Health、Multimodal Embedding Infrastructure、Experiment Agents、Reasoning Memory、Uncertainty-aware Ranking 与 Unified Runtime Policy。
主线 01 · Generative Retrieval

Two-Tower + ANN → Item-as-Token → Reliable / Temporal GenRetrieval

上一阶段：OneRec-V2 / JD GenRec 把候选生成改写为 Item Token 自回归生成并引入真实反馈/RL；Sona 更进一步，以单一生成式模型替代 15+ Candidate Generator、Pre-rank 和 Rank。

留下的问题：Prefix Error、SID Token Frequency Bias、Fresh Item Assignment、Beam Cost、Coverage 与强时间场景中的时间表达。

最新推进：FSGR 从 Quantization + Training 处理 SID 频率偏差；DrIG 用 Dual-role Identifier + Set Prior + Dense Recovery 提高可靠性；DTE 将宏观周期与局部顺序解耦。

2026-08-20 新变化：SIDScope 把 Tokenizer 输出正式当成“下游 Generator 的接口”，要求独立检查 utilization、prefix collision、neighborhood alignment、popularity allocation、structural cost、refresh churn 与 path-to-item resolution。生成式推荐的可靠性问题已经从模型内部扩展到 Artifact Contract。

下一阶段：Generate 与 ANN 形成 Query-aware Hybrid Retrieval；Tokenizer 不只看 Reconstruction，还要带 Coverage、Traffic、Freshness、Churn 与 Handoff Validation。

  • OneRec-V2 · JD GenRec · Sona
  • FSGR · DrIG · DTE
  • SIDScope · 官方代码
主线 02 · Semantic ID

Tokenizer 从实现细节变成流量分配与接口治理基础设施

FORGE 让 SID 同时承载内容语义与协同行为；HD-Rec 用层级 Codebook / Routing 做跨域共享；FSGR 显示 Token Frequency、Codebook Coverage 与 Long-tail Exposure 会改变真实流量分布。

SIDScope 补上的关键缺口：“合法路径”并不等于“唯一恢复目标 Item”。其审计发现 valid target path 与 unique item resolution 可相差约 1.2–3.0 个百分点；仅修 mapping 也不能保证继承的 Generator 自动恢复。因此 Tokenizer → Mapping → Generator 需要像 API 一样做版本与兼容性检查。

下一阶段：Semantic ID 的发布流程会出现类似软件工程 CI：Artifact Audit → Prefix/Coverage Probe → Handoff Check → Generator Eval → Traffic Guardrail。

  • FORGE · HD-Rec · FSGR · SIDScope
主线 03 · Multimodal / Foundation Embedding

“多模态特征” → Versioned Embedding Platform → Production Personalization

过去：多模态常停留在把 CLIP/LLM embedding concatenate 到下游模型，模型效果与 Serving 基础设施被分开讨论。

Netflix 2026-08-20 的生产证据：Artwork 使用 CLIP 768-D 表示与 ID Embedding 联合进入 Two-Tower Item Tower；MediaFM 用视觉 SeqCLIP + wav2vec 2.0 + timed text 建立三模态视频表示。真正关键的是 Embedding Store + versioning + backfill/rollback + item projection cache + daily materialization：大模型不在 request path 在线跑，页面生成基本退化为 KV Lookup。

线上：统一 Canvas + CLIP 的 V3 核心 discovery metric +0.127%（p<0.005）；query-aware artwork search playthrough +0.36%；Eclipse holdback discovery +0.233%、streaming hours +0.184%。

下一阶段：推荐 Foundation Model 的“产品形态”可能首先是稳定 Embedding API，而不是一个端到端巨型在线模型；核心研究问题转向 embedding stability、version compatibility、cold-start uncertainty 与 downstream calibration。

  • Netflix Multimodal Asset Personalization
  • Netflix Foundation Model Blog
主线 04 · Retrieval / Index

Static Retriever → Test-time Adaptation → Elastic Model → Fresh Index

表示侧：TTT-Embed 冻结 Encoder/Index、用 Reranker Reward 在 Test Time 优化 Query Embedding；GEM 先 Reason 再生成 Embedding Token；Tevatron-Elastic 把 Depth / Token / Embedding Width 统一成 Granularity 接口。

基础设施侧：NeuRoute 将十亿级 ANN 的 Index Build Time 拉进 Recall–QPS Trade-off：BigANN-1B 约 0.82h、Deep1B 约 0.93h。Netflix 则补充另一条路线：Foundation Content Embedding 先版本化存储，再供 Retrieval / Ranking 复用。

下一阶段：统一 Router 决定 Retriever Type、模型运行粒度、Index Freshness、Top-K、是否 Test-time Adapt，并把 embedding version / freshness 一并作为 runtime state。

  • TTT-Embed · GEM · Tevatron-Elastic · NeuRoute
主线 05 · Ranking Foundation Model

Feature Tower → Transformer-native → Unified Sequence/Interaction → Intent / Allocation-aware

RankMixer、OneRank 与 Adaptive Ranking 推动大规模工业 Ranker 向 Transformer-native、Request-aware Compute 演进；DrEM 把上游 pxtr noise 当成一等变量；UniDot 用统一 Dot-product Primitive 融合 Feature Interaction 与多域序列。

GateDiffInt 新推进：提出 Noise–Intent Coupling，用 conversion signal 同时指导 diffusion 去噪与 LLM 四类意图（长期、短期、潜在、转化）的蒸馏，再把轻量 intent 与增强 sequence 融合做 CVR。论文在数亿 DAU 场景报告 GMV 增益并进入主流量。

Impression Share Prediction 补充评估层：Ranker 评估开始预测模型上线后如何重分配展示量，而不是只看 AUC/NE。

下一阶段：Ranker 输入不只是 Feature + Label，而是 Feature + Intent + Uncertainty + Request Value + Compute Budget + Allocation Consequence。

  • RankMixer · OneRank · DrEM · UniDot
  • GateDiffInt · Impression Share Prediction
主线 06 · Lifecycle / Freshness

Recency Feature → Learnable Eligibility → Lifecycle-aware Ranking

Google Discover SDF 将 Staleness 拆成 Supersession 与 Intrinsic Relevance Decay，在 Request Path 之外生成可缓存信号。长期 staleness report 约 -54.9%，同时减少 CPU/TPU hours。

下一阶段：Freshness、Quality、Inventory、Safety、Dedup、Policy 会形成独立 Eligibility Layer；更进一步从 Hard Filter 转为 uncertainty-aware Soft Eligibility。

  • Decomposing Staleness / SDF
主线 07 · Long Sequence / Scaling / Serving

从“模型更大”到“哪些 Token / Embedding / Layer / Reasoning 值得付费”

Netflix Scaling、TM20K、CoinRAG、SilverTorch 与 Tevatron-Elastic 把 Prefill、Attention、KV、HBM、Model Granularity 与 GPU Model Graph 变成模型设计的一部分。

2026-08-20 新补充：Netflix 的多模态系统说明 Foundation Model Serving 的关键策略可以是 precompute-first；rEDMRec 则把重复 Recommendation Reasoning 变成可编辑 Memory，在线 Student 不再调用 Teacher。两者都在做同一件事：把昂贵认知计算从 request path 迁移到可复用资产。

下一阶段：系统目标从单点 latency 变成 Utility / Latency / Freshness / Memory Reuse / Precompute Cost / Total Cost 的联合 Pareto。

  • Netflix Scaling · TM20K · CoinRAG · SilverTorch · rEDMRec
主线 08 · Foundation Model / Alignment / Continual

Foundation Representation → Business Reward → Controlled Semantic Injection

OpenOneRec 把语言知识与推荐能力放入统一 Foundation Model；WEBTOON Progressive Alignment 用 LP → FFT → RFT 对齐稀疏业务 Reward；TRACER 则指出 LLM Semantic Enhancer 可能压制 collaborative ID signal，需要 Confidence Gate 控制语义知识。

GateDiffInt 的补充：工业 Ranking 对 LLM 的更现实用法是 Teacher 离线生成结构化 intent，再蒸馏到轻模型，并用 conversion signal 约束语义。

下一阶段：外部知识、Foundation Embedding 与 LLM Intent 都不会无条件注入，必须有 Confidence、Version、Business Reward 与 Drift 管理。

  • OpenOneRec · Progressive Alignment · TRACER · GateDiffInt
主线 09 · RL / Reasoning / Memory

Score → List Policy → Adaptive Thinking → Information Gain → Editable Experience

GR2 / MetaStrategy 让模型显式生成列表策略；REAM 优化 Recommendation Reasoning Length；Ask to Be Sure 用推荐分布熵下降衡量一次追问是否真正减少不确定性。

rEDMRec 新推进：Teacher reasoning 被拆成长期偏好、短期上下文、Item Perception、Counterfactual Hard-negative 四类 Typed Memory，由 Controller 做 Add/Delete/Modify/Keep，再由 Student 在线检索。推理从“一次性 CoT”变成“可维护经验资产”。

下一阶段：Reasoning Router 不只决定 Think 多久，还要决定 Recall Memory / Update Memory / Ask User / Retrieve External Evidence / Stop，并考虑 memory freshness、duplication 与 privacy deletion。

  • GR2 · REAM · Ask to Be Sure · rEDMRec
主线 10 · Agentic Search / Experiment Agent

Top-K Retrieval → Context Runtime → Skill Retrieval → Governed Online Experimentation

Agentic-R / CoSearch、Context Interference、EAHR、DocMemo、RARG、BM25 Scaling 与 Skill2Query 推动 Agent 从“搜什么”扩展到“读多少、调用什么 Skill、何时停止”。

PILOT 是重要转折：Agent 不再只服务一次推理，而是在淘宝生产系统中驱动 Experiment Lifecycle。Experiment Manager 只能从合法指令包络中行动；Search Planner 按需构建 segment tree；Memory Curator 异步沉淀策略知识。线上 5 bucket 对比中，PILOT 最高 IPV +1.40%、Core IPV +1.60%、交易数 +0.96%、交易额 +1.50%，搜索效率 53.3%→93.3%。

下一阶段：Agentic Rec 可能先在研发层规模化：读实验 → 找 segment → 生成策略树 → 受约束上线 → 归因 → 写入 memory。Experiment Governance 与 Statistical Guardrail 将成为 Agent Infra 的核心。

  • Skill2Query · PILOT
主线 11 · Distillation / Training Optimization

Teacher Imitation → Outcome-calibrated / Budget-aware On-policy Distillation

GC-OPD：长上下文中 Teacher likelihood 与 verifier reward 会分歧，方法在 rollout group 内校准两者，再把 disagreement residual 分配到 token；Qwen3-4B / 8B 在五个长上下文 benchmark 上分别由 29.08→40.47、35.12→44.65。

Open-MOPD：多 Teacher 蒸馏的主要瓶颈不一定是梯度冲突，而是长序列域吞掉 token budget、不同专家收敛速度不同、异步 reward 变 stale。通过 token-share balancing、gap-aware budget 与 student reward refresh，headroom recovery 从 35.6% 提升到 83.4%。

对推荐的迁移：多场景、多任务 Foundation Ranker 同样需要动态训练预算，未来会从手调 loss weight 走向基于 learning gap / token share / reward freshness 的预算分配。

  • GC-OPD · Code
  • Open-MOPD · Project
主线 12 · Full-stack Unification / Dynamic Policy

统一不是删掉所有 Stage，而是统一资产、接口与策略层

Sona 从模型侧替代 15+ Candidate Generator / Pre-rank / Rank；SilverTorch 从系统侧把检索与排序微服务收进 GPU-native Model Graph；SDF 在更前面建立 Eligibility；Impression Share Prediction 在更后面预测上线后的流量后果。

2026-08-20 进一步明确：Netflix 的 Embedding Store、SIDScope 的 Artifact Contract、rEDMRec 的 Editable Memory、PILOT 的 Governed Agent 都不是传统“模型层”，却正在决定 AI 推荐是否能稳定规模化。真正统一的是 Representation / Memory / Artifact / Experiment / Runtime Policy。

2026 下半年值得押注：跨 Retrieval / Ranking / Reasoning / Tool / Eligibility / Experiment 的 Cost-aware Policy Layer，外加可版本化、可审计、可回滚的 AI 资产层。
