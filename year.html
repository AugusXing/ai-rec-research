过去一年，推荐 / 搜索真正发生了什么？

主线已经从“更大的 Ranking Transformer”扩展成五层共同演进：Representation → State → Control Plane → Validity → Budget Allocation。9 月 1 日的新进展把第五层补得非常清楚：系统不再平均地处理 page token、用户时间、Agent context、KV token 和量化 scale，而是学习/设计“哪里值得花更多信息与精度”。

年度总判断：User 从 Raw History → Long Sequence → Shared / Intent State → 可主动编辑 Memory；Item 从 Random ID → Semantic Embedding → Structured / Fresh SID；Retrieval 从固定 ANN → Late Interaction / Generative Retrieval → Typed Program → Trajectory-aware Search；Ranking 从多目标分类 → Unified Backbone → Causal / Time-to-event Decision；Serving 从固定精度 → request/token/scale-level budget。下一阶段真正的系统壁垒是：共享状态、可验证控制策略、因果/时间价值、精度与算力预算、端到端正确性的联合设计。
主线 01 · Generative Retrieval

Next-item Generation → Semantic ID → Fresh / Programmable Retrieval → Vision-first Production Retrieval

上一阶段解决了什么：TIGER / OneRec / Sona 把 item retrieval 写成生成问题；TAGR 处理 fresh SID；ProRetrieval 把 SQL / Text ANN / Image ANN 组合成可执行 retrieval program；PailitaoGR 又把 crop/OCR teacher 能力蒸馏进线上 student。

留下了什么问题：生成式召回解决了“如何表示和生成 item”，但企业 RAG/商品视觉搜索仍面临 token 数量、page-level memory、refresh 与 candidate rescoring 成本。Late Interaction 的表达力如果没有 index engineering，很难直接生产化。

2026.09.01 关键推进：PULSAR 用视觉页图、两阶段 pooling 与 exact MaxSim rescoring 将 Late Interaction 部署到 78K 文档 / 2.4M 页；在 ViDoRe V3 上以 <0.01 retrieval metric 损失换约 15.1× median vector-search 加速，并把 ingestion 从 OCR-first 变成 event-driven vision-first。

下一阶段：Generative SID、multivector late interaction、typed retrieval program 会共存，真正需要的是 request router：根据 query type、catalog freshness、视觉复杂度与 latency budget 选择“直接生成 / ANN / Late Interaction / 工具搜索”。

主线 02 · Semantic ID

RQ-VAE → Dynamic SID → Namespace Infrastructure → Granularity / Freshness Controller

上一阶段解决了什么：Semantic ID 把随机 item id 变成可泛化的离散语义结构；Tlow 改善 quantization geometry，TAGR 把 live item remapping 和 vocabulary stability 做成生产问题，PailitaoGR 进一步让 coarse-to-fine SID 控制视觉 attention granularity。

留下的问题：SID 与 continuous embedding、fresh index、multimodal page/item token 仍是两套基础设施；版本切换时如何保证历史行为和新 item 的兼容仍未彻底解决。

下一阶段：Continuous Embedding Service + Discrete Namespace Service + Freshness/Version Controller + Granularity-aware Perception 将逐渐合并，并和 request-level retrieval router 共享 control plane。

主线 03 · Scaling / Serving

More Params → Information Density → Runtime Contract → Sensitivity-aware Precision

上一阶段解决了什么：FlashPrefill、CacheRoute、AdaWidth、misi、vLLM/SGLang 的 graph/KV/quant fixes 让 compute、index memory、KV locality、build cost 和 correctness 成为一等指标。

留下的问题：统一 FP16/FP8/INT4 仍把所有 layer/head/token 当成同等敏感；NVFP4 甚至在 group size 16 上拥有海量 scale，自由度没有被充分利用。

2026.09.01 关键推进：HyQuant 保留 vertical-line token + local window 的高精度，其余 attention/KV 低比特，32K H100 kernel 相对 FA2 报告约 3.58×；H-Scale 则用 calibration activation 的对角 Hessian proxy 重新选择 NVFP4 per-group scale，推理零额外开销。

下一阶段：Serving precision 会从 model-level label 变成 request × layer × head × token × time policy，与 KV eviction、spec decode、model routing 联合优化；评测必须同时报告 accuracy、TTFT/TPOT、memory、capture/build cost 和 semantic correctness。

主线 04 · Foundation Model

Shared Backbone → Shared Representation → Shared State → Budgeted Capability

上一阶段解决了什么：OneModel/MaskRec 等把多业务、多域行为和非序列 feature 合到统一 backbone；tool-rich teacher → tool-light student 又让昂贵能力从 serving path 前移到 training path。

留下的问题：“共享”并不意味着所有信息永久放进 context，也不意味着所有 token 同精度。Foundation Model 需要知道哪些状态可丢、哪些应长期记忆、哪些应调用工具、哪些只需 cheap representation。

关键推进：ContextPilot 把 planning、soft offloading、long-term memory 加入 action space，并用细粒度 RL 学会主动维护 working context。

下一阶段：Recommendation Foundation Model 更可能是 Shared Backbone + External State + Budget Router + Capability Distillation，而不是把一切塞进一个无限长 prompt。

主线 05 · RL / Preference Alignment

Sparse Reward → Utility / Process Reward → Action-level Credit → Causal / Temporal Value

上一阶段解决了什么：SSR-GRPO、Think-to-Personalize、Astar 等把 retrieval utility、reasoning process、evolution reward 引入优化；Stageboost 则强调推荐动作需要因果增量而不是相关性。

2026.09.01 两个推进：ContextPilot 把 terminal reward 分解到真正关键的 context-edit snapshot；Timing-Aware Repurchase 则从“是否发生”切换到“何时发生”，提醒 reward/objective 还应该显式建模时间。

下一阶段：推荐 RL / preference optimization 应联合考虑 Reward Density × Credit Granularity × Causal Incrementality × Time-to-Event × Verification Cost。

主线 06 · Reasoning / Re-ranking

Score Fusion → Context / Risk → Decision Stability → Calibrated Decision

上一阶段解决了什么：OC-SFT 把 candidate-order stability 写进 listwise scorer；Risk-aware rerank 把约束/风险引入最后决策；Evidence-aware RAG 强调 metric validity。

新连接：Survival Repurchase 显示即使 ranking metric 几乎一致，probability calibration 仍可相差一个数量级。排序系统不能再默认“更高 nDCG/AUC = 更适合业务决策”。

下一阶段：重排/精排评测需要同时看 Ranking Quality、Calibration、Decision Stability、Causal Incrementality、Threshold Robustness。

主线 07 · Full-stack Generative Rec

One Model → Shared State / Namespace → Tool-rich Training → Budgeted Online Stack

上一阶段解决了什么：OneRec/TAGR 证明生成式召回可以覆盖真实流量；PailitaoGR 把工具能力前移到 training；Astar 让研发 control plane 自动演进。

留下的问题：Full-stack 如果只是把所有阶段“塞进一模”，会造成不可控的 context、KV、latency 和 fault domain。

下一阶段：更合理的 Full-stack 是：统一 policy 决定直接生成/检索/精排/工具调用；共享 state/namespace 提供数据面；budget/precision router 控制在线成本；evolution policy 管理训练侧升级。

主线 08 · Agentic Search / Context Ranking

Query Rewrite → Tool-use Search → Trajectory-aware Retrieval → Proactive Context Control

上一阶段解决了什么：Search-R1、ProRetrieval、CoVeMem 等让 Search 变成多步 program，并引入长期 state。

2026.09.01 关键推进：ITER 将主问题和历史 sub-query 注入 retriever，并把已经访问的 useful doc 转成后续 redundancy negative；ContextPilot 则解决“trajectory state 太长”问题，主动 fold/offload/memorize。

下一阶段：Agentic Search 的核心将是 Retriever State × Context Manager × Evidence Validity × Tool Cost 的联合 RL，而不是独立优化 search query。

主线 09 · Model Routing

Fixed Model → Request-aware Compute → Utility-per-Compute → State / Precision / Index Router

上一阶段解决了什么：AdaWidth、Adaptive Retrieval、RecGPT-Mobile-V2 等按请求调模型/宽度/token；misi 把 rebuild/memory 纳入索引成本。

2026.09.01 新信号：PULSAR 在 page representation 上做分级精度，HyQuant 在 token 上做混合精度，ContextPilot 在 context 上做信息预算。这些看似不同，其实都是 routing：把昂贵资源只给高边际价值的信息。

下一阶段：统一 Router 的 action space 会包括 retriever、candidate budget、embedding width、reranker depth、context retention、KV precision、model/device、index refresh 与 safe fallback，以业务 utility / latency / TCO / risk 联合优化。

主线 10 · Agent Infrastructure（新增）

In-process Harness → Durable State → Cross-process Failure Isolation

为什么成为新主线：当 Agent 从 demo 变成长时间在线任务，session state、tool side effect、process crash、hot upgrade 都不能再靠 prompt 层解决。

关键节点：Logos 把 plugin 变成独立进程，router 只保存可重建表，append-only transcript 成为 durable source of truth；80 个故障注入 session 恢复且不重复 effect。

下一阶段：Agent framework 会越来越接近 workflow / distributed systems：idempotency、replay、exactly-once boundary、permission、observability、cross-session state 都会成为研究对象。

2026.09.01 新增年度判断：过去一年“Scaling”的含义已经改变：不是只把参数、序列和 batch 拉大，而是学会把有限预算投给最值得的信息。Page token、User time、Agent context、Retrieval trajectory、KV token、Quant scale 都开始拥有显式 policy。这是推荐 / 搜索向“可控智能系统”演进的共同语言。
