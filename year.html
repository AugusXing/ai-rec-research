过去一年，推荐系统真正发生了什么？

主线已经从“模型更大”转成 Generative / Foundation Model + 可版本化 AI Asset + 跨业务 User State + Runtime Policy。2026 年 8 月下旬的新信号尤其清楚：模型能力正在被拆成可共享的 Representation、Memory、Workflow 与 Compute Budget，再由系统在请求时决定哪些能力值得付费。

年度总判断：Item 变 Token、内容变 Foundation Embedding、Ranker 变跨业务 Foundation、Reasoning 变 Cache/Memory、Agent 变 Workflow Runtime、Freshness 变 Eligibility、Serving 变 Dynamic Compute、Evaluation 变 End-state Reliability。2026 下半年最值得押注的问题收敛到 Reliable GenRetrieval、Unified Ranking Foundation、Reasoning-driven Retrieval、Semantic-ID Interface Health、Agent Workflow Governance、Memory Utility Audit 与 Runtime Cost Policy。
主线 01 · Generative Retrieval

Two-Tower + ANN → Item-as-Token → Reliable / Temporal GenRetrieval

上一阶段：OneRec-V2、JD GenRec 把候选生成改写为 Item Token 自回归生成；Sona 更进一步，用单一生成式模型替代大量 Candidate Generator、Pre-rank 与 Rank。

留下的问题：Semantic ID 频率偏差、Prefix Error、Fresh Item Assignment、Beam Cost、Coverage、强时间场景表达与 Tokenizer→Generator 接口可靠性。

最新推进：FSGR 处理 SID frequency / coverage，DrIG 处理 identifier reliability，DTE 显式建模时间结构；SIDScope 则把 Semantic-ID Artifact 当成需要独立审计和版本兼容的系统接口。

下一阶段：Generate 与 ANN 形成 Query-aware Hybrid Retrieval；Tokenizer 发布流程需要 Coverage / Prefix / Churn / Path Resolution / Handoff CI，而不是只看 reconstruction。

  • OneRec-V2 · JD GenRec · Sona
  • FSGR · DrIG · DTE · SIDScope
主线 02 · Unified Ranking Foundation

单场景 Ranker → Long-sequence Ranker → 跨业务 Shared Foundation

上一阶段：RankMixer、OneRank、TM20K、Adaptive Ranking、UniDot 推动 Ranking 从浅层 Feature Interaction 进入 Transformer-native、长序列、Request-aware Compute 与 Sequence/Interaction Unified。

2026-08-21 关键推进：OneModel 把小红书 Organic Recommendation、Feed Ads、Merchant Recommendation 的异构行为映射成统一 Event Sequence，以 action-oriented long-context backbone 学共享 User State，用 Scenario-aware Information Modulation 保留业务特化。统一训练中 Ads Click AUC 0.7682→0.7712、Merchant 同样获得 +3.0‰，高资源推荐流基本不退化。

生产闭环：User State 增量更新并缓存到低延迟 KV Store，请求时只做 vectorized candidate scoring；线上 Explore Feed Time Spent +0.33%、Engagement +1.25%，Feed Ads 广告价值 +3.43%、CTR +8.18%，Merchant DGMV +1.1867%、GPM +2.1585%。

下一阶段：真正的 Foundation Ranking 不只是一个更大的 Tower，而是共享 Event Schema、User State、Content Representation、训练预算与 Serving Graph。值得押注 Dynamic Scenario Router、Conflict/Uncertainty Detection，以及让统一 User State 跨 Retrieval / Ranking / Re-ranking 复用。

  • OneModel · RankMixer · OneRank · UniDot
主线 03 · Personalized Retrieval / Reasoning

Implicit History Fusion → Explicit Intent Reasoning → Cache + Distillation Serving

过去：个性化 Search/Retrieval 通常把 User History 当额外 Embedding，与 Query 做隐式交互；LLM Retriever 又常只是把大模型当静态 Encoder。

Think-to-Personalize：让 LLM 基于购买历史显式生成 latent intent / rewritten query，再形成 Dense Embedding。训练从 SFT 进入 GRPO，Reward 直接包含 Retrieval Utility，并用 Dynamic Positive Selection 防止错误 reasoning 污染 InfoNCE。

工业关键：完整 3B Teacher 不直接覆盖所有在线流量；T+1 为活跃用户 × broad query 预计算 personalized embedding，Cache miss 由 305M Student 处理。线上额外延迟 +0.15ms，Order Volume +0.46%。

下一阶段：Reasoning-driven Retrieval 的核心研究问题将从“能不能想得更好”转成 Reasoning Cache Freshness、Teacher→Student Transfer、Intent Uncertainty 与 Multi-turn / Real-time Incremental Personalization。

  • Think-to-Personalize · TTT-Embed · GEM
主线 04 · Multimodal / Foundation Embedding

多模态 Feature → Versioned Embedding Platform → Production Personalization

过去：多模态经常停留在 CLIP/LLM embedding concatenate；Foundation Model 效果与下游 Serving 被分开讨论。

Netflix 的转折：CLIP / MediaFM 表示经过 Embedding Store 版本化存储，支持 backfill / rollback，再做 Item Projection Cache 和 daily materialization；大模型不进入 hot request path。线上统一 Canvas + CLIP 的 discovery metric +0.127%，query-aware artwork search playthrough +0.36%。

下一阶段：推荐 Foundation Model 的第一产品形态可能是稳定的 Embedding API / Store，而不是端到端超大在线模型。Embedding Stability、Cross-version Compatibility、Cold-start Uncertainty 与 downstream calibration 会成为基础设施指标。

  • Netflix Multimodal Asset Personalization
主线 05 · Long Sequence / Serving / Dynamic Compute

Dense Full Compute → Elastic Operating Point → Runtime Cost Policy

Netflix Scaling、TM20K、SilverTorch、Tevatron-Elastic 已把 Sequence Length、Model Granularity、GPU Graph、HBM 与 Prefill Cost 拉进模型设计。

FlashPrefill V2：Block-sparse Attention 从 Prototype 走向 Serving Backend：Mean Correction 控精度，PackGQA + Warp Specialization + Ping-pong Pipeline 对齐 Hopper，支持 FP8、Paged KV、Continuous Batching 并接入 SGLang。128K 下相对 FA2 Attention 最多 47.26×，端到端 TTFT 最多 4.8×。

Adaptive Edge RAG：Context Compression 不应是固定 Ratio；Jetson AGX Thor 测量显示 7B–8B Generation 约占 90% latency / 91% GPU energy，中等压缩最多降低 53.2% GPU energy、48.2% SoC energy，说明压缩率应由 Query + Device Telemetry 动态决定。

下一阶段：统一 Router 根据 Utility、Latency、Context、Freshness、GPU/Device State 决定 Retriever、Top-K、Compression Ratio、Attention Density、Precision、Model Depth 与是否调用大模型。

  • FlashPrefill V2 · Adaptive Compression for Edge RAG · Tevatron-Elastic · SilverTorch
主线 06 · Ranking Intent / Uncertainty / Allocation

Feature + Label → Noise / Intent / Request Value / Traffic Consequence

DrEM 把上游 pxtr noise 当一等变量；GateDiffInt 用 conversion signal 同时约束 diffusion 去噪与 LLM 长期/短期/潜在/转化意图蒸馏，并在数亿 DAU Ranking 场景进入主流量；Impression Share Prediction 则把“模型上线后会如何重新分配曝光”纳入评估。

下一阶段：Ranker 输入会从 Feature + Label 扩展为 Feature + Intent + Uncertainty + Request Value + Compute Budget + Allocation Consequence，并与 OneModel 一类跨业务 Foundation 汇合。

  • DrEM · GateDiffInt · Impression Share Prediction
主线 07 · Lifecycle / Freshness

Recency Feature → Learnable Eligibility → Lifecycle-aware Ranking

Google Discover SDF 将 Staleness 拆成 Supersession 与 Intrinsic Relevance Decay，在 Request Path 外产生可缓存 Eligibility Signal；长期 staleness report 约 -54.9%，同时减少 CPU/TPU hours。

下一阶段：Freshness、Quality、Inventory、Safety、Dedup、Policy 会组成独立 Eligibility Layer，并从 hard filter 继续走向 uncertainty-aware soft eligibility。

  • Decomposing Staleness / SDF
主线 08 · Reasoning / Experience Memory

每次重新 CoT → Distilled Memory → Utility-audited Skill Store

rEDMRec：把 Teacher reasoning 拆成长期偏好、短期上下文、Item perception 与 counterfactual hard-negative experience，让轻量 Student 在线只检索 Memory。

2026-08-21 新补充：Break It Down, Pass It On 证明 Experience 并非越多越好：task-level skill 多数导致负迁移，subtask-level skill 平均更有效，文本技能优于代码技能。作者用 specificity + abstractness 构造 Skill Utility，可在真正执行任务前审计 Memory。

下一阶段：Memory Router 需要同时看 relevance、utility、confidence、freshness、provenance 与 privacy deletion，而不是简单 cosine Top-K。

  • rEDMRec · Break It Down, Pass It On
主线 09 · Agentic Runtime / Experiment Governance

Tool Agent → Experiment Agent → Workflow-governed Control Plane

PILOT：推荐 Agent 从建议生成上移到受权限、安全和统计服务约束的线上实验控制环。

PolicyGuide：将组织政策编译成 Workflow Graph，在每个用户轮次根据持久 Graph State 检查 open requests，并给出未满足步骤。τ²-bench GPT-5.4 的平均 Pass^4 0.42→0.62，Telecom 0.19→0.61。

下一阶段：实验 Agent / 搜索 Agent 不应只做 Action-level Guard；应维护审批、流量、统计显著性、回滚、归档等跨轮次 Workflow State，并将政策版本作为系统资产。

  • PILOT · PolicyGuide
主线 10 · Agent Training / Reliability

Static Benchmark → Adaptive Environment → Stateful Reliability

EnvHarness：在既有 Environment 外加可编程 Harness，让 EnvRigger 根据 Policy Failure 动态合成训练环境，跨五个 benchmark 最多 +9.0 points 且 execution steps -9.8%。

Thinkingbox：MCP-compatible 隔离 Sandbox 检查最终 Backend State 与副作用，507 个业务 Workflow 中最强模型 pass@1 65.36%，但 pass^20 仅 25.25%。这说明 Agent 的核心瓶颈已经从“会不会做一次”转成“能不能稳定做对”。

下一阶段：Agent Evaluation 会从 one-shot score 走向 pass^k、state invariant、side-effect audit、policy compliance 与 rollback correctness；训练环境则根据 failure cluster 自动 co-evolve。

  • EnvHarness · Thinkingbox · 官方代码
主线 11 · Distillation / Training Optimization

Teacher Imitation → Outcome-calibrated / Budget-aware Optimization

GC-OPD 处理长上下文 Teacher likelihood 与 verifier reward 的分歧；Open-MOPD 处理多 Teacher token share、learning gap 和 stale reward。其共同启发是：训练预算本身也要动态分配，而不是长期手调固定 loss weight。

对推荐的迁移：OneModel 一类多场景 Foundation Ranker 同样面临数据量、目标难度与业务价值不均，未来训练 Scheduler 很可能依据 learning gap / gradient conflict / token share / online value 自动分预算。

  • GC-OPD · Open-MOPD
主线 12 · Full-stack Unification

统一不是删掉所有 Stage，而是统一资产、状态与策略层

Sona 从模型侧跨 Stage；SilverTorch 从系统侧把 Retrieval/Ranking 收进 GPU-native Model Graph；SDF 建立前置 Eligibility；Netflix 建立 Versioned Embedding Store；SIDScope 建立 Artifact Contract；rEDMRec 建立 Editable Memory；OneModel 建立跨业务 Shared User State；PolicyGuide 建立 Workflow State。

2026 下半年最值得押注：一个跨 Retrieval / Ranking / Reasoning / Tool / Eligibility / Experiment 的 Cost-aware Runtime Policy Layer，下面连接可版本化、可审计、可回滚的 Embedding / SID / Memory / User State / Workflow 资产。
