过去一年，推荐 / 搜索真正发生了什么？

主线已经从“更大的 Ranking Transformer”扩展成六层共同演进：Representation → State → Assignment → Control Plane → Validity → Budget Allocation。9 月 2 日的新进展把第三层补得尤其清楚：多兴趣召回不只要学习多个向量，还要决定哪个兴趣应该被激活、哪个候选应该占用 ANN 预算；生成式检索不只要学习 SID，还要让 SID、监督数据和偏好优化围绕同一用户意图对齐。

年度总判断：User 从 Raw History → Long Sequence → Shared / Intent State → Variable Interest Set；Item 从 Random ID → Semantic Embedding → Structured / Fresh SID → Behavior-aligned Multimodal Space；Retrieval 从固定 ANN → Multi-vector / Generative Retrieval → Typed / Trajectory-aware Search → Dynamic Dispatch；Ranking 从多目标分类 → Unified Backbone → Causal / Time-to-event Decision；Serving 从固定精度 → request/token/phase-level budget。下一阶段真正的系统壁垒是：共享状态、动态 assignment、可验证控制策略、因果/时间价值、端到端意图一致性与算力预算的联合设计。
主线 01 · Generative Retrieval

Next-item Generation → Semantic ID → Intent-coherent Full-stack Retrieval

上一阶段解决了什么：TIGER / OneRec / Sona 把 item retrieval 写成生成问题；TAGR 处理 fresh SID；ProRetrieval 把 SQL / Text ANN / Image ANN 组合成 retrieval program；PailitaoGR 把 crop/OCR teacher 能力蒸馏进线上 student。

留下的问题：许多 GR 系统仍是“内容做 SID、日志做 SFT、交易做偏好优化”，三个阶段目标彼此错位；beam search 又会把正确 SID prefix 在早期永久剪掉。

2026.09.02 关键推进：ICEGR 把 Query Intent 贯穿 IA-SID、SQE-SFT 与 relevance-calibrated preference optimization，离线 Recall@20 +21.7%、NDCG@20 +26.6%；20% 流量两周 A/B 中 CTR +3.52%、订单 +15.96%、GMV +7.53%，0.5B 模型以 beam=50 部署在 67 张 L20、峰值 2,200 QPS、平均 156ms。TAAL 进一步指出 91.9%–96.6% 的 GR failure 发生在 SID 前两步，用 joint-prefix distribution + PMI calibration 提升 early-prefix survival。

下一阶段：Generative Retrieval 会从“模型生成 item”升级为 Intent-aligned SID × Prefix-survival-aware Training × Fresh Namespace × ANN/GR Hybrid Router；评测应拆成 SID quality、prefix survival、beam candidate recall、post-beam ranking 与 online utility。

主线 02 · Semantic ID

RQ-VAE → Dynamic SID → Query-aware SID → Prefix-survival Controller

上一阶段解决了什么：Semantic ID 把随机 item id 变成可泛化的离散语义结构；Tlow 改善 quantization geometry，TAGR 把 live item remapping 与 vocabulary stability 做成生产问题。

留下的问题：纯内容 SID 不一定等于用户搜索意图；分层 SID 的第一、第二级错误又具有不可逆性。

2026.09.02 推进：ICEGR 的 IA-SID 先用 query-product click 对齐 encoder，再注入 query-induced co-click 与历史 query intent；TAAL 则从 decoding 侧证明 early prefix 是系统瓶颈，并用 history-conditioned joint (c1,c2) transition 训练与轻量 PMI rerank 提高 survival。

下一阶段：Query-conditioned Semantic Code + Continuous Refinement + Freshness/Version Controller + Dynamic Beam Budget 会逐步合并。CHAP 也提供了另一种信号：离散 SID 可负责层级结构，continuous representation 负责细粒度 refinement，不必在两者之间二选一。

主线 03 · Multi-interest Retrieval / Assignment

Single User Vector → Fixed K Interests → Variable Interest Set + Dynamic ANN Budget

上一阶段解决了什么：MIND / ComiRec / KuaiFormer 等证明一个用户需要多个兴趣向量，但固定 K 个 head 容易 interest collapse，也让线上每次无条件发 K 个 ANN query。

2026.09.02 关键节点：SetMIR 把多兴趣召回改写成 set prediction：Hungarian one-to-one matching 给不同 interest query 独立监督，presence score 学“这个兴趣是否存在”，query-level NMS 去冗余，再按剩余兴趣数动态分配 ANN 深度。10 个固定 ANN query 可降到平均 6.70 个，R@10 保留 99.2%；生产一周 A/B 整体 CVR +3.11%，与同 embedding/index/quota 的 I2I source 对比 CTR +44%、CVR +51%。

下一阶段：召回 head 不只输出 representation，还应输出 should-fire probability、marginal utility、latency/TCO cost；跨 source 的预算分配会从规则系统变成可学习 control policy。

主线 04 · Multimodal Representation

Content Similarity → MLLM Embedding → Behavior-aligned Item Geometry

上一阶段解决了什么：ViT/BERT/MLLM 让商品文本和图像进入同一 embedding space，但“内容相似”并不等于“用户会连续互动/转化”。

2026.09.02 关键节点：CAMIE 用 co-engagement pair 对 Qwen3-VL-Embedding 2B 做 LoRA 对齐；同 backbone 从 pretrained 到 behavior-supervised，R@10 提升 37.7% relative，而在完全相同监督下 Qwen3-VL、SigLIP2、CLIP 的差距只有约 5.5pp。线上替换 Snap DPA multimodal/text I2I 后整体 CVR +1.911%，对 text control CTR +18.958%、CVR +13.12%。

下一阶段：多模态推荐首先应优化 pair mining / behavioral supervision / refresh，再考虑更大 backbone。纯视觉仍可能保留专用 visual tower；真正统一的是行为语义空间，不一定是所有 modality 共用一个 encoder。

主线 05 · Scaling / Serving

More Params → Information Density → Runtime Contract → Phase-aware Execution

上一阶段解决了什么：FlashPrefill、CacheRoute、AdaWidth、HyQuant、H-Scale 让 compute、KV locality、precision 与 correctness 成为一等指标。

2026.09.02 新信号：vLLM QSA Split 不再让 prefill/decode 共用 sparse indexer，GB300 prefill microbenchmark 提速 4.15×–9.37×，spec-decode 多请求最高 2.22×，Qwen3.8-Flash-Next E2E TTFT 在多个并发点下降约 9%–18%。SGLang 又把 ragged CUDA Graph 的 request capacity 与 packed-token capacity 解耦；TensorRT-LLM 将 MiniMax-M3 E4M3 q 在 kernel register 内直接 widen 为 BF16，消除每层单独 copy kernel。

下一阶段：Serving 会从 model-level config 变成 request × phase × layer × head × token × dtype policy；benchmark 必须拆分 prefill / decode / spec-decode，并同时报告 TTFT、TPOT、memory、capture/build cost 与 semantic correctness。

主线 06 · Foundation Model

Shared Backbone → Shared Representation → Shared State → Specialized Supervision

上一阶段解决了什么：OneModel/MaskRec 等把多业务、多域行为和非序列 feature 合到统一 backbone；ContextPilot 让 external state/context 成为可学习控制对象。

2026.09.02 新判断：CAMIE 的 matched-backbone 实验说明，在推荐场景中“统一 backbone”并不是终点，监督信号是否与真实行为一致往往比 backbone family 更决定最终 geometry；MERIT 又说明 teacher-forcing 的正确前缀会掩盖生成式用户兴趣模型在线错误传播。

下一阶段：Recommendation Foundation Model 更可能是 Shared Backbone + Behavior-aligned Objectives + External State + Specialized Heads/Adapters + Budget Router，而不是一个模型无差别承担所有 modality 与阶段。

主线 07 · RL / Preference Alignment

Sparse Reward → Utility / Process Reward → Relevance Guard → Geometry-preserving Retriever RL

上一阶段解决了什么：SSR-GRPO、Think-to-Personalize、Astar 等把 retrieval utility、reasoning process、evolution reward 引入优化；Stageboost 强调推荐动作需要因果增量。

2026.09.02 两个推进：ICEGR 的 RCPO 先约束候选到语义相关集合，再用 click/pay/GMV 形成业务偏好，并让 DPO 强度随 relevance/business margin 动态变化，避免业务价值压过相关性；PAO 则针对冻结 document/item index 的双塔 RL，只更新 positive-advantage retrieved item，不对 negative advantage 做 push-away，尽量保持既有 semantic manifold。

下一阶段：推荐/搜索 RL 应联合考虑 Relevance Guard × Advantage Geometry × Causal Incrementality × Time-to-Event × Index Rebuild Cost。

主线 08 · Reasoning / Re-ranking

Score Fusion → Context / Risk → Calibrated Decision → Beam-survivor Calibration

上一阶段解决了什么：OC-SFT 把 order stability 写进 listwise scorer；Risk-aware rerank 把风险引入最后决策；Survival Repurchase 显示 ranking 与 probability calibration 可以选择不同分布。

2026.09.02 新连接：TAAL 的 PMI calibration 只在已经生成的 Top-B survivor 中做 O(B) rerank，收益明显小于 joint-prefix training，但说明生成式推荐的“重排”会延伸到 token-prefix / sequence-level calibration；ICEGR 的 RCPO 则强调 business rerank 必须被 relevance constraint 包住。

下一阶段：重排评测需要同时看 Ranking Quality、Calibration、Decision Stability、Causal Incrementality、Prefix Survival、Threshold Robustness。

主线 09 · Full-stack Generative Rec

One Model → Shared Namespace → Cross-stage Objective Consistency

上一阶段解决了什么：OneRec/TAGR 证明生成式召回可以覆盖真实流量；PailitaoGR 把工具能力前移到 training；Astar 让研发 control plane 自动演进。

2026.09.02 关键节点：ICEGR 是目前最完整的工业证据之一：SID 构造、synthetic/real query SFT、preference optimization、beam serving、最终曝光插流和线上 A/B 被放进同一条链路。它同时说明 offline 更好的 7B 并不一定上线——最终选择 0.5B，是 accuracy × latency × GPU TCO 的系统权衡。

下一阶段：Full-stack 的“统一”将表现为 统一 intent/state/namespace 与 policy，而不是强迫每个阶段都跑同样昂贵的模型。

主线 10 · Agentic Search / Context Ranking

Query Rewrite → Tool-use Search → Trajectory-aware Retrieval → Proactive Context Control

上一阶段解决了什么：Search-R1、ProRetrieval、ITER 让 Search 变成多步 program，并把历史 sub-query / visited docs 作为 retrieval state；ContextPilot 主动 fold/offload/memorize 长 context。

下一阶段：Agentic Search 的核心将是 Retriever State × Context Manager × Evidence Validity × Tool Cost 的联合 RL。SetMIR 的动态 dispatch 也给 Agentic Search 一个直接启发：工具/检索 source 本身也应该拥有 should-fire probability，而不是每步固定调用。

主线 11 · Model Routing

Fixed Model → Request-aware Compute → Utility-per-Compute → Source / Interest / Phase Router

上一阶段解决了什么：AdaWidth、Adaptive Retrieval、HyQuant 等按请求、token 或精度调预算。

2026.09.02 新信号：SetMIR 在兴趣级决定是否发 ANN；ICEGR 在线以 0.5B 而非离线最强 7B 做 deployment；vLLM 按 prefill/decode 选择不同 sparse kernel。它们共同说明 routing 的粒度已经从“选模型”下沉到 选兴趣、选 source、选 beam、选 phase kernel。

下一阶段：统一 Router 的 action space 会包括 retriever/source、interest head、candidate/beam budget、embedding width、reranker depth、context retention、KV precision、model/device、index refresh 与 safe fallback。

主线 12 · Agent Infrastructure

In-process Harness → Durable State → Cross-process Failure Isolation

关键节点：Logos 把 plugin 变成独立进程，append-only transcript 成为 durable source of truth，证明长任务 Agent 的基础设施正在向 workflow/distributed systems 靠拢。

下一阶段：idempotency、replay、exactly-once boundary、permission、observability 与 cross-session state 会成为 Agent 产品化的基础研究问题。

2026.09.02 新增年度判断：过去一年最重要的变化不是“模型越来越统一”，而是系统开始学会在哪里分裂、在哪里共享：用户兴趣可以分裂成可变集合，但共享 item index；SID、SFT 与 preference 必须共享同一 intent；多模态 backbone 可以共享，但纯视觉仍可专用；prefill/decode 应分路，但共享 serving runtime。未来高价值工程能力是设计这种 shared state + specialized execution + learned assignment 的边界。
