Rolling 12-Month Review · 更新至 2026.09.14

过去一年，推荐 / 搜索真正发生了什么？

主线不是“LLM 替代所有模块”，而是系统边界重划、状态资产化、控制器轻量化、跨阶段联合优化，以及 runtime 从模型内优化扩展到 workflow / harness / hardware 层。9/14 的 GPT-6 Astra、Gated-Memory Routing、SAFARI、Ecdysis 与 vLLM/SGLang 更新进一步说明：下一代系统的竞争对象已经从单一模型权重扩展为整个 execution stack。

年度总判断：下一阶段最值得押注的不是“再加一个大模型”，而是六个系统问题：① stage boundary 能否联合优化；② 什么 state / trace 值得长期复用；③ cheap controller 如何决定预算与升级路径；④ router 能否输出 execution plan 而不是 model id；⑤ Agent 是否能学会何时探索、何时停止；⑥ harness/runtime 能否被系统化优化并安全灰度。
主线 01 · Generative Retrieval

直接生成 Item → 生成离线检索资产 → 图检索控制器 → 生成式 Embedding Codec → Budgeted Deep Retrieval

上一阶段解决了什么：Generative Retrieval / Semantic ID 证明 item namespace 可以由 decoder 直接生成；SAM-D2Q 把 VLM+RL 结果离线写回倒排索引，避免高 QPS 在线生成。

留下的问题：多跳关系、late-interaction 与 Agentic Retrieval 都可能把在线成本重新拉高；“能多检索”不代表“每次都该多检索”。

关键推进：LiteRAG 把图遍历改成算法 controller；GLIE 用少量 generative code 重建完整 representation；SAFARI 则从训练角度补上“什么时候应该主动继续找信息”。

下一阶段：Semantic Namespace + Hybrid Retrieval + Offline Generated Asset + Generative Codec + Confidence/Exploration Budget。召回不再只是 top-K，而是一个可以决定继续探索还是停止的动态过程。

主线 02 · Semantic ID

RQ-VAE → Long-tail-aware Namespace → Item-level Posterior → Namespace Runtime Contract

上一阶段：Semantic ID 让 item token 带语义结构；HypRQ-VAE 更适合 power-law catalog，EPIC 缓解 partial token likelihood 与完整 item preference 的错位。

关键推进：decision-aware low-bit vector search 提醒压缩不能只看 reconstruction；GLIE 把存储对象进一步变成“可再生 code”。

留下的问题：namespace version、online insertion、token collision、热 item 迁移、生成 code 与实际 ranking decision 的一致性仍不成熟。

下一阶段：Semantic ID 原生支持 version、online insertion、constraint decoding、low-bit / generative storage 与 decision certificate，并能被跨阶段 controller 理解和复用。

主线 03 · Scaling / Serving

Kernel 加速 → State Reuse → Compatibility Contract → Workflow Runtime → Startup / Hardware Contract

上一阶段：FlashAttention、Paged KV、speculative decoding、quantization 降低单次模型计算；DoPR / ReST、HiCache、SLOWeave 把 state reuse、cache ownership 与 deadline 放到 serving 层。

关键推进 1：KVShareArena 把 context × checkpoint compatibility 写成 benchmark；REVA 把 generator attention 变成可复用 evidence asset。

关键推进 2：AgentZip 将资源问题扩展到 sandbox memory；Tail-aware Scheduling 管 workflow P95 与 release budget。

9/14 新信号：vLLM 同时优化 JIT warmup 与 DeepSeek-V4 MegaMoE 启动兼容；SGLang 一端增加 NPU platform abstraction，一端继续跟进 DeepSeek-V4.1 FlashMLA 专用 kernel。Serving 的边界因此从 steady-state decode 扩展到 cold start、model architecture contract、hardware abstraction 与 recovery。

下一阶段：GPU batch + KV/state cache + sandbox memory + workflow release budget + cold-start readiness + hardware/model fast path 共同形成 runtime control plane。生产 benchmark 必须从平均 tokens/s 升级为 time-to-ready、P50/P95、cost/task、recovery 与 correctness 的联合矩阵。

主线 04 · Foundation Model / Multi-task Ranking

Shared Backbone → Task-aware Backbone → Cross-stage Joint Optimization → Small Controller + Frontier Executor

上一阶段：UniCon、PTDG、MORE 将 context、动态 task dependency 与 task-specific evidence flow 推进到 backbone；UniRec 把 pre-ranking/ranking fusion 放进同一训练图，验证 train-joint / serve-stage-locally。

9/13：MiniCPM5-2B 代表 1–3B 级 control-plane model：query understanding、gate、router、memory curator、轻量 verifier。

9/14：GPT-6 Astra 则代表另一端的 frontier executor：更适合 hard query、复杂工具、computer use、offline teacher 与高价值任务。它公开的 API 定价与 task-level cost 信号进一步支持“cheap controller + expensive executor”架构，而不是让最大模型覆盖每个在线请求。

下一阶段：task-aware ranker + shared state + small controller + frontier executor + candidate/request-adaptive compute。真正统一的是决策协议与状态，而不是强迫所有阶段共用一个模型。

主线 05 · RL / Preference Alignment

Final Reward → Process Credit → Attribute-relative Preference → Explore-vs-Execute Preference

上一阶段：SelfDR、SAM-D2Q、IGPO、RobustSGPO 将优化对象从最终文本扩展到 guideline、index asset、workflow；UniRec AGRR 把 group-relative 思想迁移到工业 multi-objective fusion；MiniCPM5 用多 RL expert + OPD 做“多专家训练、单模型部署”。

关键推进：SAFARI 解决一个更底层的问题：标准 SFT 的成功轨迹常删除试错，RL 又可能因为初始 policy 不探索而看不到高价值动作。它先构造 exploration-rich tree trajectory，再用 Monte-Carlo rollout 对 action 做 step-level value comparison，构造 contrastive preference。

上一阶段解决了什么：“最终有没有成功”。留下什么问题：成功前是否应该主动收集更多信息？下一篇如何推进：把 exploration 变成可学习的 decision boundary。

下一阶段：reward 同时覆盖 task quality、business constraint、latency/cost、information gain、tool reliability，并学习 request-level exploration budget，而不是统一增加 reasoning steps。

主线 06 · Reasoning / Re-ranking

Cross-encoder → Structured Decode → Constraint-aware Rerank → Verifier-driven Repair → Failure Attribution

上一阶段：DoPR 复用 document state；hLLM 用 assignment 代替逐 token list generation；CHyD 把 evidence constraint 写进 decoding；TimelyRAG 把时间有效性加到 rerank。

9/13：Magenta 把生成 → formalize → hard verifier → error attribution → selective repair 串成闭环。

9/14：Ecdysis 把 attribution 再向系统层推进：一次失败不一定值得改全局 runtime，先跨任务找 recurring failure pattern，再决定是否修改 harness。

下一阶段：推荐/搜索需要 semantic relevance + business/temporal/provenance constraint + verifier + stage attribution + cohort-level failure diagnosis。Bad case 治理将从“人工看 case”升级成系统化诊断与可回滚策略演进。

主线 07 · Full-stack Generative Rec

One Model → Shared State → Cross-stage Contract → Train-joint / Serve-decoupled → Adaptive Execution Stack

上一阶段：TGR 展示 ranking、Semantic ID generation、page generation 的 full-stack 路线；ReST、DoPR 定义跨请求可复用状态；UniRec 证明训练时联合、Serving 时分阶段是更现实的工业范式。

当前推进：MiniCPM5 / Astra 把执行模型分成 cheap controller 与 frontier executor；Gated-Memory Routing 进一步要求跨阶段只保留高价值 execution state；SAFARI 决定是否追加探索；Ecdysis 则治理 harness 的全局变化。

下一阶段：“Full-stack”不再指一个大模型吞掉所有 stage，而是 shared namespace/state + stage-local executor + adaptive controller + versioned harness + unified evaluation。

主线 08 · Agentic Search / Context Ranking

Prompt Agent → Dynamic Horizon → Experience Reuse → Proactive Exploration → Compact Stateful Control

上一阶段：Elastic Horizon、EdgeMem、ReActNet、RobustSGPO 把交互长度、memory、communication graph、workflow topology 变成可优化对象；VikingRAG 将成功 retrieval trace 物化成 experience edge。

9/14 两个关键推进：SAFARI 学习“什么时候主动探索”；Gated-Memory Routing 学习“探索过后什么值得保留、什么值得读回、什么时候该停”。两者拼在一起，才更接近一个成熟的 Agentic Search controller。

下一阶段：experience memory + evidence sufficiency + exploration value + dynamic horizon + compact state + tail-aware runtime。Search Agent 的核心不是“多轮”，而是每一轮的信息增益是否覆盖成本。

主线 09 · Model Routing / Feedback Loop

Model ID Router → Context-aware Router → Multi-model Orchestrator → Gated Execution State

上一阶段：SWRouter 联合 context window 与 model router；GeneralQPP 用廉价 score distribution 判断 retrieval sufficiency；Fugu 将 router 推到 cost/quality-aware multi-agent orchestration。

留下的问题：Orchestrator 需要理解执行进度。如果直接塞完整 trajectory，cost 随步骤增长，且噪声会污染后续选择。

9/14 关键推进：Gated-Memory Routing 用 Memory Write Gate + Retrieval Gate + Role/Backbone Router + Adaptive Halting，把 router 的输入从“全部历史”变成 learned compact state。它证明状态管理本身就是 routing policy 的一部分。

下一阶段：router 输出不再是 model id，而是context window、retrieval depth、reranker、tools、model pool、precision path、state read/write、agent count、halt 与 release budget构成的执行计划，并以 cost-per-successful-task、P95 和质量共同训练。

主线 10 · Runtime Harness / Self-improving System

Static Prompt → Hand-built Harness → Per-case Self-evolution → Cross-task Failure Attribution

上一阶段解决了什么：固定 prompt 不足以表达工具协议、错误恢复、上下文管理，于是出现越来越复杂的 agent harness。

留下的问题：如果每个失败都触发全局修改，runtime 会适配模型偶发错误，形成 model accommodation，甚至比人工 harness 更差。

关键推进：Ecdysis 把一批失败先做 cross-instance aggregation，再由 Analyst/Critic/Engineer 诊断系统性模式，最后交给 coding agent 实现 modification specification。训练最多 1.84× 加速，并报告相对 18.56% reasoning accuracy 提升。

下一阶段：failure clustering → causal attribution → shadow evaluation → versioned harness → canary/A-B → rollback。这条路线与成熟推荐系统的策略灰度、cohort 分析和 bad-case 平台高度同构。

当前年度精读顺序：推荐系统：PTDG → MORE → UniRec；检索：SAM-D2Q → LiteRAG → GeneralQPP / TimelyRAG → GLIE → SAFARI（exploration policy）；Serving：DoPR/ReST → KVShareArena → REVA → AgentZip / Tail-aware → vLLM/SGLang runtime contracts；Agent/Router：Elastic Horizon → VikingRAG → Fugu → Gated-Memory Routing → Ecdysis；Foundation/Executor：MiniCPM5 control model → GPT-6 Astra frontier executor。
