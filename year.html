过去一年，推荐 / 搜索真正发生了什么？

过去一年的主线并不是“LLM 替代所有推荐模块”，而是系统边界持续重划：Item 从 Random ID → Semantic ID → Fresh / Constraint-aware / Long-tail-aware Namespace；User 从单向量 → 长序列 → 多兴趣集合 → Context State；Retrieval 从固定 ANN → Generative / Agentic Retrieval；Ranking 从 pointwise feature fusion → context/slate-aware shared state；Reranking 从 full cross-encoding → reusable document state → structured assignment；Serving 从固定 graph → request / phase / prefix / dtype / model / device 的动态预算。9 月 6 日的新增信号尤其清楚：hLLM 证明生成式排序可以利用 permutation 结构消除 autoregressive decode，Faster Flash Decoding 证明 selector 本身也必须进入 kernel co-design，vLLM/SGLang 则把 speculative decoding、parallelism、MoE balance 与 cache consistency 继续下沉成 runtime contract。

年度总判断：未来 6–12 个月最有价值的研究，会集中回答六个问题：什么是正确的状态单位？什么计算应该离线资产化？什么输出结构可以绕开 token-by-token decode？哪些请求值得走昂贵路径？共享状态如何保证一致性与生命周期？反馈如何跨 retrieval/ranking/serving 闭环？
主线 01 · Generative Retrieval

Next-item Generation → Semantic Namespace → Intent / Constraint / Item-aware Generation

上一阶段解决了什么：TIGER、OneRec、Sona 等把 retrieval 从“向量搜邻居”改写为“生成 item 的离散标识”，让 sequence model 同时承载用户状态与候选生成；ICEGR 又把 query intent 贯穿 SID、SFT、preference 与 beam serving，证明生成式召回可以进入真实电商 A/B。

留下的问题：token-level next-code likelihood 并不等于 item-level preference；partial SID 在解码早期可能对应大量完整 item，promising item hypothesis 会因局部 token 决策提前死亡。与此同时，catalogue 的长尾、freshness 与业务约束没有自然体现在 Euclidean codebook 中。

下一篇关键工作如何推进：EPIC 在 denoising 每一步显式构造完整 item posterior，再 marginalize 回未决 SID 位；HypRQ-VAE 则从 namespace geometry 入手，用 hyperbolic space 对齐 power-law catalogue。

下一阶段：Generative Retrieval = Namespace Geometry × Item Posterior × Intent/Constraint × Freshness × Serving Budget。值得押注的是这些组件共同训练和在线更新，而不是再做一个孤立 tokenizer。

主线 02 · Semantic ID

RQ-VAE → Query/Domain-aware SID → Hyperbolic / Dynamic / Posterior-aware SID

上一阶段解决了什么：Semantic ID 将随机 item ID 变成可共享前缀的离散语义结构；Tlow 改善 quantization geometry，TAGR 处理 live remapping，ICEGR 把 query intent 注入 SID，SPAR 将地理 topology 写进 POI namespace，TAAL 指出 early-prefix survival 是 decoder bottleneck。

留下的问题：Euclidean codebook 容易偏向 head item；collision、long-tail fidelity、online insertion 与 namespace versioning 仍是生产难题。“SID 怎么编码”和“partial SID 怎么被 decoder 理解”也长期分开优化。

关键推进：HypRQ-VAE 用负曲率空间的指数体积扩张承载 power-law catalog，并以 cascading reassignment 解决 collision；EPIC 让 partial SID 对应的 feasible complete items 在每步 denoising 中直接竞争。

下一阶段：需要把 hyperbolic/domain-aware codebook、online remapping、item posterior、inventory/price/location constraints、prefix survival 放进同一个 namespace contract。

主线 03 · Scaling / Serving

Kernel Optimization → Runtime Contract → Reusable State / Dynamic Compute

上一阶段解决了什么：FlashPrefill、HyQuant、H-Scale、vLLM/SGLang/TensorRT-LLM 把 prefill/decode、precision、KV、CUDA Graph、speculative decoding 等执行路径显式化；Perplexity 的 GPU Embedding Serving 又说明 embedding / ranking / LLM 可以复用同一类 kernel、scheduler 与 runtime。

留下的问题：很多高成本计算并非每次请求都必须重做；稀疏 attention 的 selector/metadata 也会形成隐藏税。进一步地，跨 worker 的 prefix/KV/cache 已经从“优化细节”变成需要一致性、版本和生命周期语义的生产状态。

关键推进：DoPR 把 query-independent document state 离线资产化；Faster Flash Decoding 用 2-bit content-aware scan + top-δ + fused selector/attention kernel，报告最高 11.6× kernel speedup、2.37× E2E throughput；vLLM 在 9 月 5 日合入 EAGLE3 speculative decode + pipeline parallel，SGLang 同期继续强化 disaggregated cache 的 transactional publication 与 receiver liveness。

下一阶段：Serving 优化对象会从 kernel 扩展为 offline/online boundary、reusable prefix/state、cache transaction、spec-decode × TP/PP/EP、expert load balance、dtype/layout、request × device routing。

主线 04 · Foundation Model / Unified Ranking

Feature Fusion → Shared Backbone → Context-centric Shared State

上一阶段解决了什么：OneModel、MaskRec、OneTrans、HyFormer、RankMixer 等减少手工 feature cross，把行为序列与 ranking features 放进统一 backbone。

留下的问题：“序列 vs 非序列”仍是 feature-engineering 遗产。真实决策发生在一个展示 context 内：用户点击某 item 的意义取决于同时出现的竞争项、位置、query 与环境；flat token fusion 不会自动理解 impression boundary。

关键推进：UniCon 将一次 exposure/request 定义为 context unit，intra-context attention 学 Locality，inter-context attention 学 Dynamics；Meituan 搜索广告离线 AUC +0.0139，7 天 20% 流量 A/B：RPM +3.09%、CTR +2.07%、Revenue +2.95%。context compression 将 0.33B 模型计算从 801.29 降到 197.14 GFLOPs，AUC 仅损失 0.0001。

下一阶段：Foundation Ranking Model 更可能是 shared context/slate state + task-specific heads + adaptive compute，而不是把所有 field/token 塞进一个更大的 Transformer。

主线 05 · RL / Preference Alignment

Final Outcome Reward → Process Credit → Reasoning-as-Teacher

上一阶段解决了什么：ICEGR RCPO 用 relevance guard 包住 click/pay/GMV preference；PAO 在 frozen index 上只做 positive-advantage updates；PRO-Step 将 RAG reward 从最终答案下沉到 logical validity + evidence grounding 的 step-level credit。

留下的问题：Process reward 能提高 reasoning，但如果生产系统每次都输出完整 reasoning trace，在线 token/latency 成本太高。高 QPS 推荐更需要把“学习时慢思考”和“Serving 时快决策”解耦。

关键推进：SelfDR 训练 reasoner → reasoning-enhanced teacher → direct student，用 reverse-KL + dynamic weighting 把 reasoning posterior 蒸馏到不看 rationale 的学生；Clothing inference 为 1 output token、109.46ms。

下一阶段：Process RL for learning + Distillation for serving + Router for hard cases 会比“全量 CoT”更接近生产最优解。

主线 06 · Reasoning / Re-ranking

Full Cross-encoder → Reusable Document State → Structured Assignment

上一阶段解决了什么：Qwen3-Rerank/RankLLaMA 等证明 LLM cross-encoder 质量强；DoPR 进一步指出 document-side compute 可以被训练成可复用 prefix，从“每个 query 重算文档”走向 offline asset。

留下的问题：即使 document state 被复用，很多 generative reranker 仍逐 token 输出候选序号。排序结果天然是 permutation，继续采用自然语言式 autoregressive decoding 会引入不必要的顺序依赖和 latency。

关键推进：hLLM 从 prefill hidden states 读出 N×K item-position score matrix，再用 Hungarian algorithm 一次求解合法排列。LoRA + teacher ranking distillation 报告 28ms 端到端推理、64× speedup，同时保持与 teacher 相当的 ranking quality。

下一阶段：最值得研究的是 DoPR reusable state + hLLM structured decode + list/slate constraints：文档重计算和自回归解码这两类成本可以同时消掉。随后需要把 diversity、business rules、position bias 和 uncertainty 直接纳入 assignment。

主线 07 · Full-stack Generative Rec

One Model → Shared Namespace → Cross-stage Contract → Structured Decode / Control Loop

上一阶段解决了什么：ICEGR 展示 SID → query SFT → preference → beam serving → online insertion 的闭环；SPAR 证明 domain knowledge 需要从 tokenizer/CPT/SFT 全链路保留；CORAL 把 retrieval budget 与 Serving treatment 纳入 LLM-native live experiment control plane。

留下的问题：生成式推荐仍常把 namespace、decoder、rerank、runtime 当成分开的论文问题；但 EPIC/HypRQ-VAE/SelfDR/hLLM 已分别证明 item representation、partial-code inference、reasoning policy、decode structure 都会直接决定在线成本和质量。

关键推进：近期工作可以串成一条更完整的链：HypRQ-VAE 解决 item 如何编码 → EPIC 解决 partial code 如何保住 item hypothesis → SelfDR 解决复杂 reasoning 如何蒸馏成 cheap serving → hLLM 解决最终 list 如何不再逐 token 解码。

下一阶段：真正的 Full-stack Generative Rec 应统一 catalogue topology、user/context state、item posterior、preference reward、structured decoding、Serving budget 与 online experiment。

主线 08 · Agentic Search / Context Ranking

Query Rewrite → Trajectory Search → Structural Navigation → Interface-aware Execution

上一阶段解决了什么：ITER 将历史 sub-query/visited docs 写入 retriever state；GAREN 学 group-level evidence direction；SciLENS 把 citation graph traversal / visualization 直接变成 tools/actions；RuleMem 用可验证规则主动指导事实召回。

留下的问题：Agent 系统不仅会被 retrieval strategy 限制，还会被 chat template、tool parser、serialization 和 executor 契约限制；如果 tool call 在接口层被吞掉，评测和 RL 都可能把系统失败错误归因到模型。

关键推进：Interface-Induced Trajectory Censoring 显示同一模型只更换 serving adapter，BFCL 可从 0.00 变为 0.96/0.19；tau-bench 中 server-parsed calls 可从 0 到 636。R²Adapter 则把 hybrid RAG 改成 query-adaptive routing，Graph RAG usage 最高减少 59%而保持 comparable accuracy。

下一阶段：Agentic Search 会从“retrieve text”走向 route source/path → retrieve/induce structure → verify interface/tool contract → allocate context → execute → observe → stop。评测也应同时记录 raw generation、parse、execute、observation、final reward 的完整漏斗。

主线 09 · Model Routing

Fixed Model → Fast/Slow Path → Retrieval / Reasoning / State / Device Routing

上一阶段解决了什么：Switchyard、AdaWidth、DS-Frame 将请求按价值路由到不同模型/宽度/深度；SetMIR 在 interest 级决定是否发 ANN；Spotify Shunt / NVIDIA PAIR 把任务路由扩展到不同 worker / GPU node。

留下的问题：router action space 快速膨胀但信号分散。现在 context keep ratio、prefix budget、reasoning/direct path、Graph RAG invocation、speculative decode、parallelism、precision、device 都能被动态选择。

关键推进：R²Adapter 给出“昂贵 retrieval path 只用于真正受益请求”的清晰例子；DoPR 允许 inference prefix budget 与训练解耦；SelfDR 支持 direct/slow reasoning path；vLLM/SGLang 则把 runtime route 继续扩展到 spec-decode、MoE balance 与 cache state。

下一阶段：统一 router 的 action space 会是 source / interest / candidate depth / context keep ratio / prefix budget / retrieval path / reasoning depth / decode mechanism / model / precision / device，目标函数应直接是 marginal utility per GPU-ms / dollar。

主线 10 · 推荐链路统一

Stage-local Optimization → Shared State / Shared Budget / Shared Feedback

上一阶段解决了什么：传统召回、粗排、精排、重排各自优化；近一年开始出现 shared representation、generative retrieval、adaptive reranking 与 control plane。

留下的问题：同一 request 的 intent、context、cost constraint 在不同 stage 被反复重建；召回不知道 downstream reasoning cost，精排不知道 candidate source budget，rerank 又重新编码 document/item，并且常以 token generation 输出本可直接求解的 permutation。

关键推进：UniCon 证明 context/slate structure 对精排有效；DoPR 证明 rerank state 可以跨 query 复用；hLLM 证明最终排序可以从 autoregressive generation 转为 structured assignment；CORAL/R²Adapter/SetMIR 证明昂贵路径和系统预算可以被 controller 动态决定。

下一阶段：跨阶段统一不必是“一模型吞掉所有 stage”，更现实的是建立可复用的 user/context state、item/document state、namespace、cost signal、decode contract、experiment feedback，各 stage 在共同 contract 上 specialization。

未来 6–12 个月最值得押注：Structured Generative Reranking、Reusable Reranking State、Context/Slate Foundation Ranking、Long-tail + Fresh Semantic ID、Item-level Generative Posterior、Adaptive RAG、Reasoning Distillation、Transactional Cache/State、Unified Budget Router、Agentic Control Plane。这些方向共同回答一个问题：怎样用结构化 state、结构化输出和预算控制，让质量提升不再等价于“每次请求都多算一遍”。
