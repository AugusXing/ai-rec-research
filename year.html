过去一年，推荐 / 搜索真正发生了什么？

主线已经从“换一个更大模型”转向重写系统边界：Semantic ID 开始承载业务价值，Foundation Ranker 强调可迁移预训练，用户长期状态被拆成 cache / mutable memory，检索与 Agent 按请求预算化；到 9/17，Agent 又开始进入推荐系统研发与 Serving 控制面——诊断失败、修改代码、优化完整 Serving Stack、演化评估 Harness 本身都成为可学习过程。

年度总判断：接下来最值得押注的系统问题已经很清晰：① Semantic ID 怎样同时表达语义、业务价值与可增量地址；② generative path 如何和成熟 ranker/cascade 对齐；③ foundation ranker 的 dense knowledge 如何安全迁移；④ user state / preference delta 应写进哪里；⑤ retrieval depth 如何变成真实成本预算；⑥ query 是否应该动态选择 index / source / reranker / model；⑦ Agent 第一轮动作和 abstain/escalation 如何联合学习；⑧ 模型、Harness、索引、Serving state 如何用不同 learning clock 演化；⑨ 性能优化能否由 Agent 跨 kernel→graph→server→feature service 自动完成；⑩ self-improving recommender 如何从日志 diagnosis 安全走到 code patch 与 A/B。
主线 01 · Generative Retrieval

直接生成 Item → Semantic Namespace → Generated Index Asset → Retriever + Verifier → Value-aware / Ranker-aligned Fast Lane → Set-valued Fan-out

上一阶段解决了什么：TIGER / Semantic ID 证明 item namespace 可以直接被 decoder 生成；HypRQ-VAE 处理 power-law catalog；EPIC 修正 partial-token probability 与 item preference 的错位；SAM-D2Q 把昂贵生成结果离线写回 index；Generative Verifier 又提高 deep top-K 候选进入真正下游 prefix 的概率。

9/16 关键推进：VARG 让 SID 的末级 token 承担 value ordering，并用 Prefix-GRPO 对齐合法性、用户行为、搜索相关性和现有 ranker advantage；Tmall 14-day A/B GMV +1.45%。这标志着 generative retrieval 不再只优化 recall，而开始对最终业务 pipeline contract 负责。

新的旁支：Google Research 的 R4T / Retrieve-for-Train 把 set-valued retrieval 的“多样性、覆盖、互补性、groundedness”先用 RL 编译成训练数据，再蒸馏进 53.9M diffusion retriever，一次并行生成一组 retrieval directions，官方报告比 autoregressive fan-out 快 12–20×。这条线值得和推荐 slate / multi-interest recall 结合。

下一阶段：ANN/GR 双路召回 + set-valued fan-out + verifier + final-ranker alignment + budget router。Semantic ID 与 fan-out 目标会进一步和业务 value、探索、catalog refresh、downstream survival 联合。

主线 02 · Semantic ID / Full-stack Generative Rec

RQ-VAE → Long-tail Namespace → Item-level Posterior → Large-beam State-aware Serving → Value-aware Address

上一阶段：HypRQ-VAE 让 SID 更适配长尾；EPIC 把完整 item posterior 与 token likelihood 对齐；TGR 把 ranking / SID generation / page generation 串成 full-stack path；OneLA 解决 large-beam recurrent state 复制。

当前核心矛盾：地址不仅要“语义正确”，还要长期稳定、支持 catalog 增量、表达业务 prior，又不能因为 value ordering 把头部优势永久固化。

关键承接：VARG 的 value-aware SID 把 semantic namespace 升级成业务排序资产。下一步最值得看 incremental SID、可版本化 namespace、探索友好的 code assignment 与动态 beam / verify-K。

主线 03 · Foundation Model / Industrial Ranking

Shared Embedding → Long-sequence Backbone → Generative Behavior Pretraining → Transferable Foundation Ranker

上一阶段：HSTU / OneTrans / SORT 把更强序列建模带进 ranker；PTDG / MORE / UniRec 继续做 task-aware backbone、跨阶段融合和 unified training。

9/16 推进：LazFormer 用一年行为做 autoregressive pretraining，同时迁移 sparse+dense；ranking-specific features 走 residual adapter；asymmetric multi-epoch 在 epoch 间重置 sparse、保留 dense 累积学习。线上 Orders +3.38%、GMV +9.85%，A10 QPS 仅 -12.1%。

下一阶段：pretrain data governance、feature compatibility、adapter routing、long-sequence compression、sparse/dense 不同 learning clock、多域迁移，以及与 runtime sequence budget 联合设计。

主线 04 · Lifelong / Continual User State

Recent Window → Target-aware Retrieval → Cacheable Chronicle → Preference-stage Drift → Sparse Mutable Memory

上一阶段：SIM/TWIN 用 target-aware retrieval 读取超长历史，但 candidate-loop 重算成本大；ChronicleRec 把长期行为压成带时间锚、target-independent 的 cacheable tokens；DRIFT 先按 preference drift 切阶段。

9/16：LION 用 sparse KV memory 给 preference delta 独立写入空间，避免流式 fine-tune 把所有变化污染共享 decoder；consolidation loss 强化稀有偏好。

下一阶段：长期 backbone 低频更新、Chronicle/preference stage 中频更新、sparse memory/recent state 高频更新；所有状态带 version、TTL、refresh policy 与 rollback。

主线 05 · Multi-interest / Set-valued Recommendation

Multiple Interest Vectors → Exclusive Credit Assignment → Set-level Objective → Compiled Fan-out

上一阶段：MIND / ComiRec 证明多兴趣向量可覆盖多峰用户偏好，但 slot collapse 长期被当作表示相似问题。

9/15：MIMA 用 request 内 multi-positive + Hungarian one-to-one assignment 定义明确 ownership，线上交易笔数 +5.60%。

新的连接：R4T 把“多结果整体是否互补”作为不可分解 set-level reward，再把昂贵 RL 行为蒸馏成廉价 diffusion fan-out。MIMA 解决 slot credit，R4T 解决 set objective，两者可能在下一代多兴趣召回 / slate generation 汇合。

下一阶段：dynamic slot count、长期 interest identity、set-level diversity/value reward、counterfactual source credit、query-conditioned fan-out size。

主线 06 · Scaling / Serving

Kernel 加速 → State Reuse → Adaptive Budget → Agent-generated Kernel → Cross-stack Agent Optimization → State-lifecycle Serving

上一阶段：FlashAttention / Paged KV / quantization 优化单模型；KVShareArena / ReST / OneLA 扩展到跨请求、beam ancestry 与 recurrent state；adaptive verification 动态控制 speculative work；ForgeMegakernel 用 coding agent 自动生成 per-model kernel。

9/17 关键推进 1：FlashVector 把 Agent 优化从 kernel 推到完整 serving stack：GPU kernel、graph、NVIDIA Triton C++ server、Python feature service。Unity Vector 生产部署最高 2× throughput / 1.98× latency speedup，feature store 最高 1.6× throughput。

主线 07 · Reasoning / Re-ranking / Selective Escalation

Cross-encoder → Structured Decode → Verifier-driven Repair → Ranker Alignment → Answer-or-Abstain / Escalate

上一阶段：hLLM 用 assignment 替代逐 token list generation；CHyD 把 evidence constraint 写进 decode；Magenta 做 generate→verify→selective repair；Generative Verifier 在 retriever 与 pre-rank 间做 output-side verification；VARG 再把 downstream ranker preference 提前到 train-time reward。

9/17：CoSQ 让模型在回答前显式检查证据充分性，Grounded-CoSQ 将 wrong commitment 13.1%→8.9%，coverage 87.6%。在搜索系统里它更像一个 selective escalation signal：不确定时扩大 retrieval、调用更强 reranker/model，或直接 abstain。

下一阶段：confidence 不再只是一个 score，而是控制 retrieval depth、rerank、reasoning、human review 的策略变量；训练目标应变成 expected utility - latency - risk。

主线 08 · Cross-stage Joint Optimization

Independent Stages → Teacher Alignment → Joint Fusion → Generative Fast Lane → Agentic Diagnosis & Refinement

上一阶段：PTDG/MORE 让 task signal 提前进入 backbone；UniRec 统一 pre-ranking/ranking fusion；MIMA、ChronicleRec、Generative Verifier 分别重写 recall ownership、user state 与 recall→pre-rank boundary；VARG 用 generative reserved quota 接入成熟 final ranker。

9/17 关键推进：AURA 把优化视角再向外扩一层：不是只联合训练 stage，而是由 Agent 读取生产 engagement logs，发现用户体验 failure pattern，再结合 recommender code / data / training pipeline 提出并实现 code-level refinement。

主线 09 · RL / Preference Alignment

Final Reward → Process Credit → Prefix-level Alignment → Harness-aware RL

上一阶段：SelfDR、SAM-D2Q、IGPO、RobustSGPO 把 reward 从最终答案扩展到 workflow/index；SAFARI 学 explore-vs-execute；VARG Prefix-GRPO 把合法性、行为、ranker advantage 与搜索相关性分解到 prefix。

9/17：ScienceBuddy 提出 recursive-in-recursive：inner loop 固定 model 演化 harness，outer loop 在改进后的 harness 中用 RL 训练 model。held-out single-attempt accuracy 42.2→73.3%。

主线 10 · Agentic Search / Context Ranking / Routing

Fixed Query → Sufficiency Gate → Explore-vs-Execute → First-move Planning → Access Budget → Query-conditioned Index

上一阶段：GeneralQPP 判断 evidence sufficiency；VikingRAG 复用 retrieval trace；SAFARI 学何时继续探索；Question’s Gambit 把第一轮 clue decomposition 单独优化；DiBud 把 hybrid retrieval 的 fixed Top-K 改成真实 access budget。

9/17：ORDER 进一步指出：不只 retrieval depth 要动态，index / chunking / metadata filter / reranker / source 本身也应该 query-conditioned。离线为 semantic query cluster 构建不同 index，在线 nearest-centroid + QRe 路由，UMS 分配 multi-source budget。

主线 11 · Retrieval Architecture / Model Routing

Dense Encoder → Decoder Retriever → MoE Retriever → Query-time Expert Budget → Pipeline-level Routing

9/16：MoE Language Models as Retrievers 显示在相近 active params 下 MoE retrieval 可匹配更大 dense retriever，并可 query-time 减 expert，不重建 document index。

9/17 的连接：ORDER 让 routing 从“选几个 experts”扩成“选哪个 retrieval plan”；CoSQ 再提供 risk-aware escalation signal。下一代 router 很可能管理 model/expert/index/retrieval/rerank 一整套 compute graph。

主线 12 · Runtime Harness / Self-improving System

Static Prompt → Versioned Harness → Failure Attribution → Verifiable Mutation → Model-Harness Co-evolution

上一阶段：Ecdysis 强调 failure clustering 后再修改 harness；ForgeMegakernel 用 independent oracle 验证 agent-generated kernel；VARG/LION/ChronicleRec 让 SID、memory、user state 都变成可演化资产。

9/17：ScienceBuddy 把 harness evolution 直接纳入学习循环；FlashVector 把 production workload / benchmark / full-stack load test 变成性能 Agent 的 harness；AURA 则把 production logs 与 code context 变成 recommender diagnosis harness。

下一阶段：versioned state + versioned evaluator + targeted mutation + safe rollout + automatic rollback 会成为自改进系统默认能力。没有独立 evaluator 的 self-improvement，最终很容易变成自我确认。

主线 13 · Agentic Recommender Operations

Dashboard + SQL + Human Debug → LLM Log Analyst → Multi-agent Diagnosis → Code-level Refinement → Closed-loop RecOps

核心矛盾：推荐研发最大的人力瓶颈之一不是“不会再发明一个模型”，而是从海量指标和 session 中定位真正影响用户的 failure、找到对应 pipeline、提出有效改法并安全验证。

关键工作：AURA 提供 diagnosis→refinement 框架；FlashVector 提供 performance diagnosis→patch→load-test 框架。一个面向推荐质量，一个面向 Serving 效率，两者共同勾勒出“Agentic RecOps”。

下一阶段：将业务 bad case、数据质量、模型性能、Serving 成本放到同一个 incident graph；Agent 自动生成 hypothesis 与 patch，但所有修改必须经过离线 replay、shadow/canary、A/B 和 rollback gate。
