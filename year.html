Rolling 12-Month Review · 更新至 2026.08.19

过去一年，推荐系统真正发生了什么？

主线已经从“把模型做得更大”转成 Generative / Foundation / Policy Model + Lifecycle Filter + Elastic Retrieval + Agentic Interaction + Request-aware Serving。越来越多工作开始把候选资格、索引新鲜度、模型深度、Embedding 宽度、Reasoning Steps、Tool Calls、停止时机甚至 A/B 后的流量分配都当成可学习的系统状态。

年度总判断：Item 变 Token、Ranker 变 Policy、Freshness 变 Eligibility、Offline Evaluation 变 System Counterfactual、索引构建时间变召回质量的一部分、对话追问变 Information Gain。进入 2026 年 8 月后，最值得押注的问题进一步收敛到 Reliable GenRetrieval、Semantic ID Coverage、Elastic Retrieval、Lifecycle Filtering、Counterfactual Allocation、Uncertainty-aware Ranking、Context Runtime 与 Unified Request Router。
主线 01 · Generative Retrieval

Two-Tower + ANN → Item-as-Token → Reliable / Temporal GenRetrieval

上一阶段解决了什么：OneRec-V2 / JD GenRec 把候选生成改写为 Item Token 自回归生成，并引入真实反馈与 RL；Sona 更进一步，以单一生成式模型替代 15+ Candidate Generator、Pre-rank 和 Rank。

留下的问题：Prefix Error、SID Token Frequency Bias、Fresh Item Assignment、Beam Cost、Coverage 和强时间场景下的时间表达。

最新推进：FSGR 从 Quantization + Training 两侧处理 SID 频率偏差；DrIG 用 Dual-role Identifier + Set Prior + Dense Recovery 提高可靠性；Decoupled Temporal Encoding 则把宏观周期与局部顺序分开，让即时零售/外卖类场景的“此刻需求”进入生成式推荐。

下一阶段：Generate 与 ANN 更可能形成 Query-aware Hybrid Retrieval；同时 Item Tokenization 将与 Temporal Tokenization、Freshness Eligibility 联合设计。

  • OneRec-V2 · JD GenRec · Sona
  • FSGR · DrIG · Decoupled Temporal Encoding
主线 02 · Semantic ID

Tokenizer 从实现细节变成流量分配基础设施

FORGE 让 SID 同时承载内容语义与协同行为；HD-Rec 用层级 Codebook / Routing 做跨域共享；FSGR 进一步显示 Token Frequency、Codebook Coverage、Long-tail Exposure、层级稳定性与新 Item 分配会改变真实流量分布。

下一阶段：Tokenizer 的评估会越来越像推荐系统本身：不仅看 Reconstruction / Recall@K，还要看 Coverage、Gini、Freshness、冷启动和流量公平性。

  • FORGE · HD-Rec · FSGR
主线 03 · Retrieval / Index

Static Retriever → Test-time Adaptation → Elastic Model → Fresh Index

表示侧：TTT-Embed 冻结 Encoder/Index，仅利用 Reranker Reward 在 Test Time 优化 Query Embedding；GEM 先 Reason 再生成 Embedding Token；Tevatron-Elastic 把 Depth / Token / Embedding Width 统一成一个 Granularity 接口。

基础设施侧的新变化：NeuRoute 把十亿级 ANN 的 Index Build Time 拉进 Recall–QPS Trade-off：BigANN-1B 约 0.82h 构建，Deep1B 约 0.93h，而强图索引基线需要十几到几十小时。对快速变化的商品/内容库而言，Fresh Index 本身就是召回质量。

下一阶段：统一 Router 决定 Retriever 类型、运行深度/宽度、Top-K、是否 Test-time Adapt，并同时考虑 Index Age / Rebuild Cost。

  • TTT-Embed · GEM · Tevatron-Elastic
  • NeuRoute · 官方代码
主线 04 · Ranking Foundation Model

Feature Tower → Transformer-native → Unified Sequence/Interaction → System-aware Evaluation

RankMixer 把多任务 Feature Interaction 做到成熟；OneRank 用 Task Token、Candidate Context 与 Dynamic Matching 移除 Encoder–Predictor 边界；Meta Adaptive Ranking 将 Request-oriented Computation Sharing、动态路由、Selective FP8 和多卡 Serving 直接带进 Ranker。

2026-08 新推进：DrEM 把上游 pxtr Prediction Noise 当成一等变量；UniDot 再向前一步，用 Dot-product Token Primitive + 双 Bus Macro-block + FM Highway 统一非序列 Feature Interaction 与多域行为序列。与此同时，Impression Share Prediction 把“候选 Ranker 上线后会怎样重新分配展示量”做成离线任务，意味着 Ranker Evaluation 从 Accuracy 进入 System Counterfactual。

下一阶段：Ranker 的输入/评估不只是 Feature + Label，而是 Feature + Uncertainty + Request Value + Compute Budget + Allocation Consequence。

  • RankMixer · OneRank · DrEM
  • UniDot · Impression Share Prediction
主线 05 · Lifecycle / Freshness

Recency Feature → Learnable Eligibility → Lifecycle-aware Ranking

过去：Freshness 常被压缩成 content age、time-decay 或一个 Ranker Feature。

关键推进：Google Discover 的 SDF 将 Staleness 拆成 Supersession 与 Intrinsic Relevance Decay：大模型 Teacher 蒸馏关系型替代判断，多模态模型预测内容生命周期，并把信号缓存到 Request Path 之外。线上显示用户 staleness reports 长期下降约 54.9%，同时减少 CPU/TPU hours。

下一阶段：Candidate Pipeline 会出现更明确的 Eligibility Layer：Freshness、Quality、Inventory、Safety、Dedup、Policy 等先回答“值得进入后续 Ranker 吗”，再做个性化排序；进一步从 Hard Filter 走向 uncertainty-aware Soft Eligibility。

  • Decomposing Staleness in Recommender Systems / SDF
主线 06 · Long Sequence / Scaling / Serving

从“序列更长”到“哪些 Token / KV / Layer / Index 值得付费”

Netflix Scaling、OneRec-V2 证明更长历史和更大模型有效，但 Prefill、Attention、KV Cache、HBM 和 QPS 很快成为第一约束。TM20K 用 Full-attention Teacher 学 20K 历史再让 Student Token Merge；CoinRAG 把 KV 复用粒度推进到 Query-relevant Nugget；SilverTorch 把 Index、Filter、ANN、Neural Rerank、Multi-task Scoring 收入统一 GPU Model Graph；Tevatron-Elastic 则让 Retriever/Reranker 的运行点连续可调。

2026-08-19 的补充：NeuRoute 说明 Serving Economics 还应包含 Time-to-Index；SDF 说明上游可学习 Filter 能直接减少后续 CPU/TPU 支出。系统目标变成 Utility / Latency / Freshness / Total Cost 的联合 Pareto。

  • Netflix Scaling · TM20K · CoinRAG · SilverTorch
主线 07 · Foundation Model / Alignment / Continual

Foundation Representation → Business Reward → Controlled Semantic Injection

OpenOneRec 等把语言知识与推荐能力放入统一 Foundation Model；WEBTOON Progressive Alignment 将 Post-training 拆成 LP → FFT → RFT，用稀疏业务指标训练 Reward Model 做最终 Alignment。

新的反作用问题：TRACER 指出 LLM Semantic Enhancer 在 Continual Recommendation 中可能压制 collaborative ID signal，形成 Stability–Plasticity–Cognitivity 三难。它用 Procrustes Projection、Confidence-gated Condensation、Semantic Synchronization 控制语义知识注入。

下一阶段：Foundation Embedding 不应无条件拼接；所有外部知识都要带 Confidence/Gate，并在持续学习中显式管理 Drift 与 Forgetting。

  • OpenOneRec · Progressive Alignment
  • TRACER · 官方代码
主线 08 · RL / Reasoning / Conversational Recommendation

Score → List Policy → Adaptive Thinking → Information-gain Interaction

GR2、MetaStrategy 让模型显式生成列表策略；REAM 把问题推进到 Recommendation Reasoning Length；Search-R1 Stopping 学习何时不再检索。

2026-08-19 新推进：Ask to Be Sure 不再只优化“最终推荐 Item 是否命中”，而是把一次追问的价值定义为 Recommendation Entropy Reduction。这把 Conversational Rec 改写成 Active Preference Learning：问题本身要带来信息增益。

下一阶段：Reasoning/Conversation Router 需要联合优化：Think 多久、问不问、问什么、用户回答成本、Calibration 与长期 Utility。

  • GR2 · REAM · Search-R1 Stopping
  • Ask to Be Sure
主线 09 · Agentic Search / Skill Retrieval

Top-K Retrieval → Context Runtime → Skill Retrieval as Cold-start Recall

Agentic-R / CoSearch 联动 Retriever 与 Reasoner；Context Interference 说明证据越多不一定越好；EAHR 让 Retrieval Depth 成为 Query-specific State；DocMemo 用 Page Belief 管证据探索；RARG 让 relevance 指导 corpus traversal；BM25 Scaling Study 则证明大语料下 Global Candidate Ranking 仍是 Agent 的关键先验。

新的 Skill 层：Skill2Query 将 Skill 文档解析成结构化知识，再通过 style mimicking、template、parameter filling 生成 pseudo-query，用于 Index Augmentation / Query Expansion / Retriever Training。它本质上是 Agent Tool/Skill 的冷启动召回问题。

下一阶段：Agent Runtime 需要统一 Content Retrieval、Skill Retrieval、Context Ranking、Tool Cost 与 Stop Timing。

  • Context Interference · RARG · BM25 Wins at Scale
  • Skill2Query · 官方代码
主线 10 · Full-stack Generative Recommendation

传统 Cascade 的阶段边界被模型侧与系统侧同时侵蚀

Sona 从模型侧替代 15+ Candidate Generators、Pre-rank 与 Rank；SilverTorch 从系统侧把多个检索/排序微服务改写成统一 GPU-native Model Graph；UniDot 进一步从模型内部消除 Feature Tower 与 Sequence Tower 的硬边界。

短期更现实的方向：不是“一次性拆掉所有 Stage”，而是 统一表示 + 可组合 Stage + Eligibility Filter + 动态 Request Routing，让边界逐步变软。

  • Sona · SilverTorch · UniDot
主线 11 · Model Routing / Dynamic Compute / System Counterfactual

推荐系统十年的 Cascade 思想正在迁移到 LLM / Agent Serving

Pre-Inference Routing 提醒：Cheap Model 必须存在足够 Failure，且 Failure 能被廉价特征预测，复杂 Router 才有经济价值。Tevatron-Elastic、Search-R1 Stopping、EAHR 等把 Model Granularity、Retrieval Depth 与停止时机变成 Runtime State。

最新扩展：Impression Share Prediction 让 Router/Launch Decision 进一步考虑“这个模型上线后会怎样改变系统流量”；SDF 则让 Eligibility Filter 先减少无价值候选。未来统一 Request Value Estimator 不只选模型，还要预测 Compute → Allocation → Utility 的链式后果。

2026 下半年最值得押注：一套跨 Retrieval / Ranking / Reasoning / Tool / Eligibility 的 Cost-aware Policy Layer。

  • Pre-Inference Routing · Tevatron-Elastic · Impression Share Prediction
