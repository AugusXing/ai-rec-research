过去一年，推荐 / 搜索真正发生了什么？

主线不是“LLM 替代所有模块”，而是系统边界重划、状态资产化、控制器轻量化、跨阶段联合优化，以及 runtime 从模型内优化扩展到 workflow / sandbox 层。9/13 的 MiniCPM5-2B、Fugu、AgentZip 与 Tail-aware Scheduling 进一步说明：真正可扩展的 AI 系统，需要轻量控制模型、多专家编排与资源控制面协同。

年度总判断：下一阶段最值得押注的不是“再加一个大模型”，而是五个系统问题：① stage boundary 能否联合优化；② 什么 state / trace 值得长期复用；③ 什么决策应该交给低成本 controller；④ router 能否输出一条 cost/quality-aware execution plan，而不是只给 model id；⑤ Agent runtime 能否同时管理 GPU、KV、sandbox memory 与 workflow tail latency。
主线 01 · Generative Retrieval

直接生成 Item → 生成离线检索资产 → 图检索控制器 → 生成式 Embedding Codec

上一阶段：Generative Retrieval / Semantic ID 证明 item namespace 可以由 decoder 直接生成；SAM-D2Q 把 VLM+RL 结果离线写回倒排索引，避免高 QPS 在线生成。

留下的问题：多跳关系与视觉 late-interaction 都有高存储/高在线代价；GraphRAG 的在线 LLM traversal 也难满足稳定 SLA。

关键推进：LiteRAG 把 graph traversal 改成算法 controller；GLIE 把少量 late-interaction vectors 视为 generative code，先低成本召回，top shortlist 再重建完整 representation。

下一阶段：Semantic Namespace + Sparse/Dense/Graph Hybrid + Offline Generated Asset + Generative Codec + Decision-aware Fallback。

主线 02 · Semantic ID

RQ-VAE → Long-tail-aware Namespace → Item-level Posterior → Namespace Runtime Contract

上一阶段：Semantic ID 让 item token 带语义结构；HypRQ-VAE 更适合 power-law catalog，EPIC 缓解 partial token likelihood 与完整 item preference 的错位。

关键推进：decision-aware low-bit vector search 提醒压缩不能只看 reconstruction；GLIE 更进一步把存储对象从“压缩后的固定 vectors”变成“可再生 code”。

下一阶段：Semantic ID 原生支持 version、online insertion、constraint decoding、low-bit / generative storage 与 decision certificate。

主线 03 · Scaling / Serving

Kernel 加速 → State Reuse → Compatibility Contract → Evidence Asset → Workflow / Sandbox Runtime

上一阶段：FlashAttention、Paged KV、speculative decoding、quantization 降低单次模型计算；DoPR / ReST、HiCache、SLOWeave 把 state reuse、cache ownership 与 deadline 放到 serving 层。

关键推进 1：KVShareArena 把 context × checkpoint compatibility 写成 benchmark；REVA 把 generator attention 汇总成可复用 evidence asset。

关键推进 2：AgentZip 将 runtime 资源问题扩展到高 fan-out sandbox memory，最多 8.7× 压缩；Tail-aware Scheduling 将 ready 与 release 解耦，在争用下把 P95 workflow flow time 最多加速 3.50×；vLLM TokenSpeed MLA 则继续把 Blackwell/FP8 KV/MLA kernel 专用化。

下一阶段：GPU batch + KV/state cache + sandbox memory + workflow release budget + deadline controller 共同形成 Agent / LLM runtime control plane。

主线 04 · Foundation Model / Multi-task Ranking

Shared Backbone → Dynamic Task Graph → Task-aware Backbone → Cross-stage Joint Optimization → Small Control Model

上一阶段：UniCon、PTDG、MORE 将 context、动态 task dependency 与 task-specific evidence flow 推进到 backbone；UniRec 再把 pre-ranking/ranking fusion 放进同一训练图，验证 train-joint / serve-stage-locally。

新信号：MiniCPM5-2B 代表另一条更现实的 foundation 路线：主 ranker 未必变成 LLM，但 1–3B 模型可以成为 query understanding、retrieval gate、router、memory curator、轻量 verifier。它公开 Agent SFT/RL 数据、多阶段 checkpoint 与 speculative drafter，使“控制面小模型”开始具备完整工程闭环。

下一阶段：task-aware ranker + cross-stage fusion + small control model + candidate-adaptive compute + shared state。

主线 05 · RL / Preference Alignment

Final Reward → Process Credit → Attribute-relative Preference → Harness-level / Expert-distilled Optimization

上一阶段：SelfDR、SAM-D2Q、IGPO、RobustSGPO 将优化对象从模型输出扩展到 guideline、index asset、workflow；UniRec AGRR 把 group-relative 思想迁移到工业 multi-objective fusion。

新推进：MiniCPM5-2B 的 post-training 由 domain RL teachers → 16 experts → OPD 回蒸馏到单模型，说明“多专家训练、单模型部署”与“多阶段联合训练、分阶段 Serving”是同一种系统思想：训练结构可以复杂，Serving contract 必须简单。

下一阶段：reward 同时覆盖 task quality、business constraint、latency/cost、tool reliability 与 router policy。

主线 06 · Reasoning / Re-ranking

Full Cross-encoder → Reusable State → Structured Decode → Temporal Constraint → Verifier-driven Repair

上一阶段：DoPR 复用 document state；hLLM 用 assignment 代替逐 token list generation；CHyD 把 evidence constraint 写进 decoding；TimelyRAG 把 clause validity 加入 reranking。

新推进：Magenta 提供了可迁移的可靠性范式：生成 → formalize → hard verifier → error attribution → selective repair。对推荐/搜索，未来可映射为 retrieve/rank → business/evidence checker → 判断是召回缺失、rerank 错误还是生成格式错误 → 精确回退。

下一阶段：semantic relevance + business/temporal/provenance constraints + verifier + stage-specific repair。

主线 07 · Full-stack Generative Rec

One Model → Shared State → Cross-stage Contract → Train-joint / Serve-decoupled → Control-plane Model

上一阶段：TGR 展示 ranking、Semantic ID generation、page generation 的 full-stack 路线；ReST、DoPR 定义跨请求可复用状态；UniRec 证明训练时联合、Serving 时分阶段是更现实的工业范式。

当前判断：“统一”不等于一个模型吞掉所有阶段，更可能是统一 namespace/state/controller，执行器仍按 SLA 专用。Small control model 可以成为统一系统里的 glue layer。

主线 08 · Agentic Search / Context Ranking

Prompt Agent → Dynamic Horizon → Retrieval Trace Reuse → Adaptive Escalation → Runtime-aware Agent

上一阶段：Elastic Horizon、EdgeMem、ReActNet、RobustSGPO 把交互长度、memory、communication graph、workflow topology 变成可优化对象；VikingRAG 又将成功 retrieval trace 物化成 experience edge。

新推进：AgentZip 与 Tail-aware Scheduling 说明 Agent 的执行成本不能只用 token 数表示：sandbox 内存、restore bandwidth、released-work queue 与 P95 critical path 都会决定真实吞吐。

下一阶段：experience memory + evidence sufficiency + dynamic horizon + sandbox memory + tail-aware release + cost-aware escalation。

主线 09 · Model Routing / Feedback Loop

Model Routing → Context-aware Routing → Retrieval Sufficiency → Multi-model Orchestration → Execution-plan Controller

上一阶段：SWRouter 联合 context window 与 model router；GeneralQPP 用 2ms score distribution 判断 retrieval sufficiency；TimelyRAG 把 temporal validity 做成第二阶段 controller。

关键推进：Fugu Max / Ultra v2 把 router 从“选一个模型”推到“组织一组可替换专家”，并把 capability/cost Pareto frontier 直接作为产品目标。Fugu Max 优先单位成本，Ultra v2 优先 hard-task quality。

下一阶段：真正的 router 输出将是context window、retrieval depth、reranker、tools、state version、precision path、agent count、model pool 与 release budget构成的执行计划。

主线 10 · Recommendation Robustness

Input Anomaly → Cross-model Transfer → Decision-boundary Robustness

上一阶段：推荐反作弊多聚焦异常用户、robust aggregation 与单模型 attack success。

关键推进：RecGP 指出 transferable poisoning attack 的关键是把 adversarial fake users 推向 flat loss region；RecGP-RS 用 semantic-aware neighborhood sampling 在保留约 98% 攻击效果时减少 42% GPU memory。

下一阶段：推荐 robustness benchmark 应从同模型攻击扩展到 cross-architecture / cross-seed / cross-checkpoint transfer matrix + margin/gradient stability + 多阶段链路影响。

当前年度精读顺序：推荐系统：PTDG → MORE → UniRec → RecGP（鲁棒性侧）；检索：SAM-D2Q → LiteRAG → GeneralQPP / TimelyRAG → GLIE；Serving：DoPR/ReST → KVShareArena → REVA → AgentZip / Tail-aware Scheduling；Agent/Router：Elastic Horizon → VikingRAG → RobustSGPO → Fugu → MiniCPM5 control-model 路线。
