过去一年真正的主线：从“统一模型”走向“共享状态 + 专家执行路径 + 条件化控制器”

推荐 / 搜索与 LLM 系统正在形成共同架构：representation、state、objective、measurement 越来越共享，execution path 却越来越专业化。Semantic ID 让对象可生成；Generative Retrieval 把业务价值前移；Foundation Model 统一表征；Reasoning / Re-ranking 优化集合与证据；Agentic Search 主动获取信息；Serving 按 KV、precision、prefill/decode 拆分；Model Routing 则继续升级为 memory / Skill / model / budget 的统一 activation policy。

2026-10-27 · 年度演进增量 / 9 篇精读

从“模型规模与统一表征”，走向“价值分解 × 码路径可控 × 专职执行”

10/27 研究并不是 9 篇互不相干的模型，而在回答三种压力：业务目标跨层级错配、SID 生成路径的准确率/成本矛盾、检索与 Agent 执行能力的专业化。

分层交易价值→语义码路径控制→专职检索与重排→可验证技能复用

Generative Retrieval / Semantic ID：TIGER → TCBSA → IDM/CMM → Deco

TIGER/MiniOneRec 把物品编码成可生成 SID，解决内容和协同序列的统一索引，但留下“早期 Beam 漏召、逐码大模型冗余、并行输出缺乏商品协同”三个缺口。TCBSA 用协同模型给 SID prefix 加门控势能避免过早剪枝；IDM / CMM 将教师监督从 item space 映射到有效商品分布和 code marginal；Deco 则把“确定目标”与“写出多级码”解耦，重主干只做一次前向。后续值得研究三者共享 SID 字典、受约束候选输出、端到端 P99/Recall/GMV 的因果验收。

Scaling / Serving：多阶段检索的推理与索引全成本

MICE-P 用离线文档编码与有限交互结合接近 Cross-Encoder 质量，告诉我们 Serving 的瓶颈除了模型 FLOPs 还有压缩存储、解压与重建；Deco 从 SID 展开消除重型重复前向。下一步是同时优化 KV/cache、TopK、索引维护与动态路由，严格区分受控 throughput 与生产 QPS。

Foundation Model / Model Routing：通用决策强不等于重排强

System One / Decision vs Reranker 在同家族不同规模对照下发现专职相关性微调可明显优于一般 yes/no 决策训练；因此统一骨干不代表统一 Loss 最优。下一步是小模型处理多数 query，难例交给复杂交互式模型，并以相同候选池和业务约束比较 Pareto 前沿。

RL / Preference Alignment / Full-stack Generative Rec：从容器级回报到元素级价值

早期精排大多为单个列表或卡片预测一维 CTR/CVR；HGE / HSAE-PLL-RCEF 的 HSAE + PLL + RCEF 将动态 item set 与容器价值连接，且有 13 天 A/B 证据。迁移到评价重排时应先拆用户对内容的实际消费、购买与满意度，再训练 List Reward / DPO；System One / Decision vs Reranker 提醒不能用通用决策评分代替经过专训的相关性评估。尚未解决列表元素的边际因果贡献与归因偏差。

Reasoning / Re-ranking：从单点语义判断到检索链路可执行

MICE-P 处理 Cross-Encoder 的效率质量冲突；System One / Decision vs Reranker 区分 relevance ranking 和 decision calibration；PersonalQuery 暴露用户口语/错字下的排序不稳定。后续应统一 Recall@K、NDCG、Worst-Style、List Reward 与线上长链路转化，避免以“平均分更高”掩盖输入脆弱性。

Agentic Search / Context Ranking：SkillRep → Phronix

SkillRep 首先保证正确技能能被从 11 万级技能池检索出来，Phronix 再验证成功能力能被可执行地沉淀复用。二者分别解决 search 和 execution loop，不是直接互换。未来押注可验证的 Skill Maturity、权限安全、失败隔离和 task-completion reward。

2026-10-26 · 年度演进增量 / 8 篇精读

从模型更强，转向证据可溯源、索引全成本与自适应执行

这一天的八项研究跨越了检索质量、自动化控制、偏好状态和推理底层。它们构成的是“可观测证据 → 可选择的执行路径 → 可复用状态 → 可验证收益”的闭环，不意味着彼此构成同一端到端系统。

原始证据 / 归因→检索结构 / 动态预算→共享 KV / 偏好状态→指标与成本闭环

Generative Retrieval / Semantic ID：从生成地址到可验证的召回链

此前 OneChord 等工作优化 SID 一次解码与生成路径，但 SID 准确还不等于内容证据被正确消费。LARA 的贡献不是新的 SID，而是明确“候选返回→实际消费→任务成功”之间的 lineage。下一阶段要在生成式召回中记录 SID 版本、候选覆盖、实际曝光及错位的后效。

Scaling / Serving：从共享序列状态到减少循环内的 KV 重复

DuoLM 与 LoopRec 探索计算复用和按需推理深度，留下一项系统缺口：Looped 模型即便共享参数，跨 recurrence 的历史 KV 仍膨胀。BeNice! 通过随机深度训练及首轮 KV 兼容后训练处理这项显存成本，但效率主要来自模拟流量，下一步是生产级 P99、内存峰值和质量联合验证。

Foundation Model / 多向量搜索：从表示可裁剪到查询按需选择

Matryoshka 与 ColPali 式 late interaction 让视觉证据更细，但固定表示预算仍为简单查询支付高额成本。FlexVDR 联合路由 encoder depth / width / token，进一步把动态决策放到表示层。下一步是检索质量损失上限、异构文档索引成本与真实吞吐最优，而非只对比 FLOPs。

RL / Preference Alignment：从 List Reward 到可纠错的用户状态

此前 Raw-RAG 提醒压缩/生成状态可能损伤真实证据；LARA 说明 Agent 消费不应直接等于用户正反馈，Jev-DLC 将 typed prefer/reject correction 变为有界的动作和成对偏好记忆。未解决的是曝光反事实、延迟下单与非显式负反馈。下一阶段可以先做 List-level Reward 审计，再尝试轻量个性化校准与 DPO/RL 联合训练。

Reasoning / Re-ranking 与 Full-stack Generative Rec：从单一列表分数到执行图

多目标评价重排不能把全部责任压给 Generator；LARA 为列表候选、被消费条目和结果提供逐层评价，JevDLC 对用户主动修正提供低成本记忆，BGAFlow 则考虑跨域兴趣重叠不同造成的负迁移。三者分别解决监督、短时纠错和跨场景表征，而非可直接互换的重排器。

Agentic Search / Context Ranking：从固定工具链到自动结构搜索

RouteWeaver 关注工作流/Worker 路由，而 IRAH 将控制决策下沉到 RAG 的 chunk / embedding / reranker 结构及数值超参。LARA 是两者部署前的测量先决条件：如果行为无法归因，自动优化器会优化错误代理目标。下一步是 OOD 鲁棒性、人工审核与成本敏感控制。

Model Routing / Sparse Retrieval：查询时延不代表端到端经济性

GRIP 的 term-seeded sparse graph 在固定 Recall@10 下有显著查询提速，代价却是更高内存和建图时间；FlexVDR 让多向量 Query 决定预算。这要求将索引更新频率、质量曲线和峰值延迟共同写入 Router 成本函数。动态 Chunk 重算评估 又把跨版本重嵌入的 token 量加入 TCO，补上长期服务缺口。

内容与协同表征→SID / 训练分布对齐→按需计算与服务复用→版本、状态与逐样本验收

1. 生成式推荐开始补齐整个生命周期

UniSGR-V2 / TacGR、WeGR 分别强化目标特征与码本/奖励；OneChord、SID Topology Preservation、CAPE 将问题延伸到线上分数、目录更新和长尾记忆。新的判断标准是候选覆盖、排序、更新成本与业务增益共同成立。

2. 长序列扩展依赖计算复用与精细分配

TransX、DuoLM、ECHO 从系统不同层次减少重复历史计算；AURA、LoopRec 让推理深度随查询或 item 改变。模块 FLOPs、候选吞吐和总服务成本要分别比较。

3. 检索表示与物理索引继续协同优化

EVIE、Linear Compression Correction、FLINT、UIBK-Embedding、pplx-embed-v2-late 在多向量质量、压缩和模型部署间做权衡；Compact Sparse Indexes、AiSAQ-in-Filtering、RemoteANN 强调内存、过滤与对象存储访问。最终需固定质量阈值比较完整成本。

4. 评估从平均分走向状态和过程审计

Jev-Style Request Audit、Generative vs Dense Retrieval、Residual Routing Audit 检查输入包装、强基线和指标取舍；MemRevise、MemDerive、TREK 将长期 Agent 的失败定位到修订、依赖更新和冲突推理。

5. 线上证据用于确认场景，不用于跨论文排行

Instagram Debiasing、SPAR、FineSID 分别来自价值函数、分层生成和多模态 CTR；它们的指标、流量和对照不同，不应把提升百分比直接排序或相加。

2026-10-08 · 候选、监督与评估一致性

模型与执行路径之外，训练分布和评估口径也要对齐

沿着现有“共享表示与状态、分阶段执行”的主线，10/08 的工作把问题推进到实际候选、训练标签和验证方法。以下为本站跨论文分析，具体实验边界见各篇深读。

共享表示 / 分阶段执行→候选与监督对齐→强基线 / 逐样本验证→可维护的经验与评估状态

1. 生成式推荐延伸到下游训练语义

Missed Targets 研究漏召目标如何用于重排训练；S-2LS / SD-2LS 研究采样概率。二者提示：模型打分、实际候选与训练分布需要分别检查，不能用一个平均排序分数替代。

2. 检索质量延伸到标签与结构对照

VLM Teacher Signals 关注未标注相关页；Document Structure Ablation 用乱序标题隔离结构收益。建议在投入更大模型前，先确认标签和分块策略是否造成系统性误差。

3. 系统优化需要强基线和版本化评估

Quantize by Drift 保留均匀精度强基线；Judge Backbone Evolution 把升级退化追到样本级。接续 RAGFlip，版本治理应同时覆盖检索器与评估器。

4. Agent 记忆走向对象关系

ExperienceIndex 为现有 memory / activation 主线补充对象经验。工程上可继续研究内容版本、经验失效与建索引成本；迁移到推荐状态仍需独立验证。

主线 01 · Generative Retrieval

Semantic ID → Value-aware Generation → Shared Retrieval / Ranking Representation

上一阶段解决了什么：RQ-VAE / TIGER 类方法让 item 拥有 decoder 可生成地址；OneRec / OneSearch 将业务价值前移；VARG / UniPolicy 开始让生成策略感知 downstream objective。

主线 07 · Full-stack Generative Recommendation

上一阶段解决了什么：生成式推荐把 retrieval/ranking/generation 放入共同 token space，减少手工 stage interface。
