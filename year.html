过去一年，推荐 / 搜索真正发生了什么？

技术演进已经不再是一条“模型越来越大”的单线。更准确的结构是：Representation → State → Assignment → Domain Structure → Control Plane → Validity → Budget Allocation。9 月 3 日的 SPAR、DS-Frame、GAREN 与推理 co-design 又把两个新变量推到中心：业务世界中不可丢的结构约束，以及按请求价值动态分配计算。

年度总判断：User 从 Raw History → Long Sequence → Shared / Intent State → Variable Interest Set；Item 从 Random ID → Semantic Embedding → Structured / Fresh SID → Domain-aware SID；Retrieval 从固定 ANN → Multi-vector / Generative Retrieval → Trajectory / Group-aware Search → Dynamic Dispatch；Ranking 从统一 one-pass → causal/time-aware decision → sample-wise Fast/Slow Compute；Serving 从固定精度 / 固定 top-k → request × phase × token × draft × route 的预算控制。真正的系统壁垒正在变成：结构先验、共享状态、动态 assignment、可验证控制策略与 utility-per-compute的联合设计。
主线 01 · Generative Retrieval

Next-item Generation → Semantic ID → Intent / Domain-coherent Full-stack Retrieval

上一阶段解决了什么：TIGER / OneRec / Sona 把候选检索写成 token generation；TAGR 处理 fresh SID；ICEGR 进一步让 SID、SFT、Preference 围绕 Query Intent 对齐，并给出真实电商线上 A/B。

留下的问题：“语义一致”仍不等于“业务世界可行”。生成式系统可能在行为共现上正确，却违反地理、库存、预算、权限等结构约束。

2026.09.03 推进：SPAR 把 POI 的经纬度、方向、道路与可达性贯穿 SID → CPT → SFT：SI-SID 显式融合 geospatial embedding，MG-CPT 用 25 个地理数据集学习城市结构，TV-SFT 用冻结 task vector 防止空间知识被 behavior SFT 覆盖。四个 AMAP 工业数据集上，SPAR-4B / 8B 相对 PLUM 的平均相对增益为 +28.54% / +38.32%。

下一阶段：Generative Retrieval 会从“生成语义 item”走向 Intent × Domain Constraint × Fresh Namespace × Prefix Survival × Cost-aware Decoding。POI 是 geography；电商可能是 inventory/price/category；广告则可能是 audience/campaign/budget。

主线 02 · Semantic ID

RQ-VAE → Dynamic / Query-aware SID → Domain-structured SID

上一阶段解决了什么：Semantic ID 把随机 ID 变成可泛化的离散结构；Tlow 改 quantization geometry，TAGR 处理 live remapping，ICEGR 把 query intent 注入 SID；TAAL 指出 SID 的 early-prefix survival 是 decoder bottleneck。

留下的问题：多数 SID 仍主要压缩 item/content embedding，业务硬结构只是附加 feature，无法保证 code topology 与真实世界 topology 一致。

2026.09.03 关键节点：SPAR 的 SI-SID 把经纬度用多频 sinusoidal encoder 映射后与语义 embedding 融合，再做 RQ-Kmeans。它提出了更一般的命题：SID 应当编码“what it is” + “what constraints govern it”。

下一阶段：值得押注 constraint-aware codebook、time-dependent SID、multi-view SID、continuous refinement、namespace versioning 与 online remapping，而不只是继续更换 RQ-VAE 结构。

主线 03 · Multi-interest Retrieval / Assignment

Single User Vector → Fixed K Interests → Variable Interest Set + Dynamic ANN Budget

关键节点：SetMIR 用 Hungarian one-to-one matching、presence score 与 query NMS 把多兴趣召回变成 set prediction；10 个固定 ANN query 可降到平均 6.70 个，R@10 保留 99.2%，生产整体 CVR +3.11%。

留下的问题：interest/source 被激活之后，仍缺少统一的 marginal utility 与真实 latency/TCO 目标。

与 9 月 3 日的连接：DS-Frame 在模型深度上学习 should-use-more-compute，GAREN 在证据 group 上学习 should-expand，ViSAR 在 page 数上学习 adaptive-k。它们本质上都在把 should-fire / how-much-budget 变成模型输出。

下一阶段：统一的 budget controller 很可能横跨 interest head、retrieval source、candidate depth、reranker depth、beam width 与 model route。

主线 04 · Multimodal Representation

Content Similarity → MLLM Embedding → Behavior / Topology-aware Modality Trust

上一阶段解决了什么：CAMIE 证明在工业 I2I 中，用真实 co-engagement 对 pretrained multimodal space 做行为对齐，往往比更换更大 backbone 更有效。

2026.09.03 新节点：OrthoRec 从相反方向补全问题：并非所有 modality 都值得融合。CGOP 以 collaborative anchor 将模态特征分成平行/正交方向并净化冲突噪声；TAR-MoE 再决定每个 modality 注入多少；safe-SSL 避免强行对齐矛盾 pair。

下一阶段：多模态推荐将从“fusion architecture”转向 modality trust / conflict detection / behavioral supervision / specialist routing。统一 representation 不等于无条件相信所有 modality。

主线 05 · Scaling / Serving

More Params → Runtime Contract → Phase-aware Execution → Model–Hardware Co-design

上一阶段解决了什么：FlashPrefill、HyQuant、H-Scale、vLLM QSA Split 等把 prefill/decode、token sensitivity、precision 与 kernel path 分开优化。

2026.09.03 新信号：NVIDIA 的 speculative decoding co-design 指南把 draft length D 与 attention group size G、128-token tile、KV 压力、draft overhead、acceptance length 一起考虑；external draft、EAGLE-3、MTP、DFlash、DSpark、suffix/n-gram 必须放在同一 latency/throughput/training-cost Pareto 上比较。

另一个基础设施信号：A Power Law in Logarithm's Clothing 指出图向量搜索在很多现实规模区间可能表现为 N^c 的 sublinear power law，而非工程上常假定的近似 poly-log；这会直接改变 ANN capacity planning。

下一阶段：Serving policy 会下沉到 request × phase × head × token × dtype × draft × search-width，并同时报告 TTFT、TPOT、p99、memory、build/refresh cost 与 semantic correctness。

主线 06 · Foundation Model

Shared Backbone → Shared State → Specialized Supervision / Execution

上一阶段解决了什么：OneModel、MaskRec 等推动 shared backbone；ContextPilot 让 external state/context 成为显式控制对象；CAMIE 说明 supervision geometry 往往比 backbone family 更关键。

2026.09.03 新判断：SPAR 用同一 LLM 同时承载空间 cognition 与行为推荐，但用 task vector 防止能力互相覆盖；DS-Frame 则共享 backbone，却允许 easy/hard request 进入不同推理深度。

下一阶段：Recommendation Foundation Model 更可能是 Shared Representation / State + Domain Adapter + Specialized Path + Budget Router，而不是“所有用户、所有模态、所有阶段都走同一计算图”。

主线 07 · RL / Preference Alignment

Sparse Reward → Relevance Guard → Geometry / Cost-aware Alignment

上一阶段解决了什么：ICEGR RCPO 用 relevance guard 包住 click/pay/GMV preference；PAO 在 frozen item index 下只对 positive-advantage candidate 更新，避免破坏已有 embedding manifold。

当前留下的问题：reward 还经常忽略 serving cost、index rebuild cost、latency tail 与 causal incrementality。

下一阶段：Retriever / Router RL 的 reward 应联合 Relevance × Incremental Value × Latency/TCO × Index Stability × Safety Constraint。DS-Frame 的 cost-aware oracle 已经给出一个 supervised 版本的雏形。

主线 08 · Reasoning / Re-ranking

Score Fusion → Context / Risk → Prefix Calibration → Evidence-space Navigation

上一阶段解决了什么：OC-SFT 把 order stability 写进 listwise scorer；TAAL 将重排扩展到 generative beam survivor；ICEGR 证明 business preference 需要 relevance constraint。

2026.09.03 关键节点：GAREN 将 reasoning retrieval 的“下一步”从 document neighbor 改成 semantic group。Leiden community + group summary 形成 coarse evidence map，小 navigator 先选择扩展方向，大 reranker 再做细粒度判断。BRIGHT reasoning setting 中平均 nDCG@10 31.2，高于最强 baseline 28.9。

下一阶段：Reranking 不只发生在候选末端，还会前移成 search-space planning、group/source routing、adaptive stopping。

主线 09 · Full-stack Generative Rec

One Model → Shared Namespace → Cross-stage Objective / Constraint Consistency

上一阶段：ICEGR 是“SID 构造 → synthetic/real query SFT → preference → beam serving → 线上插流”的完整工业链路；它提醒 offline 更强的 7B 不一定比 0.5B 更值得上线。

2026.09.03 推进：SPAR 再增加一条 consistency：domain knowledge 不能只在输入或 SID 出现一次，而要跨 tokenization、CPT、SFT 持续保留。

下一阶段：Full-stack generative recommendation 的“统一”将是统一 intent / domain constraint / namespace / state / cost policy，而不是统一模型尺寸。

主线 10 · Agentic Search / Context Ranking

Query Rewrite → Trajectory-aware Retrieval → Group Navigation → Adaptive Context Budget

上一阶段：ITER 把历史 sub-query / visited docs 放进 retriever state；ContextPilot 主动 fold/offload/memorize 长 context。

2026.09.03 两个推进：GAREN 提供 group-level evidence navigation；ViSAR 则说明 reader context budget 不该固定 top-k，query-conditioned similarity structure 可以 training-free 地决定页面数，RAG latency 最多下降 58.7%。

下一阶段：Agentic Search 的共同 control loop 会是 state → choose source/group → choose k → verify evidence → decide stop/continue，并把 token/latency/tool cost 显式写进 policy。

主线 11 · Model Routing

Fixed Model → Model Router → In-model Fast/Slow Compute → Utility-per-Compute

上一阶段：AdaWidth、Adaptive Retrieval、Switchyard 等按请求在宽度、retriever、模型之间调预算；SetMIR 在 interest 级决定是否发 ANN。

2026.09.03 关键节点：DS-Frame 把 routing 下沉到 sequential recommender 内部：Fast System 处理 routine case，Slow System 做 K-step latent refinement，selector 用 prediction loss + compute cost 构造 oracle label并受 budget regularization。Beauty/SASRec 中 40.2% slow activation 的 NDCG@10=0.0453，高于 100% Slow 的 0.0431；normalized compute 约 1.80× vs 3.00×。

下一阶段：Router 的目标不应只是“难度分类”，而应直接预测 marginal utility per additional GPU-ms；还需处理动态 batch、p99、budget drift 与 online feedback。

主线 12 · Evaluation / Validity

Static Offline Metric → Decision Validity → Incremental Reusable Evaluation

上一阶段：研究开始强调 calibration、decision stability、causal incrementality 与 offline→online validity，而不满足于单个 AUC/nDCG。

2026.09.03 新节点：Incremental Pooled LLM Evaluation 把 retrieval qrels 当可复用资产：新增 system 只 judge 新贡献文档。4 个 benchmark + 生产金融新闻 QA 中，考虑 qrel uncertainty 后保留约 97% pairwise ordering；生产 document overlap 可复用 65–80% judgment，成本最高约降 4.9×。

下一阶段：评测系统本身需要 qrel cache、judge/version provenance、coverage、uncertainty、incremental refresh，像模型和索引一样被工程化。

2026.09.03 新增年度判断：最值得押注的研究问题已经从“如何训练更强表示”扩展为四个控制变量：Structure（现实业务有什么硬拓扑）、Assignment（哪个兴趣/source/group 应被激活）、Survival（正确候选能否穿过剪枝）、Budget（哪个请求值得多花算力）。SPAR、SetMIR/GAREN、TAAL、DS-Frame/ViSAR 分别是这四条线目前很清晰的代表节点。
