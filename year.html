过去一年真正的主线：从“一个模型做更多”走向“状态、目标与计算路径都可被控制”

推荐 / 搜索的演进已经不再是“传统模型 vs LLM”。过去一年更稳定的方向是：Semantic ID 让对象可生成；Generative Retrieval 把下游价值前移；Foundation Ranker 统一表示；Reasoning/Reranking 处理复杂约束；Agentic Search 让检索计划动态化；Serving 让计算路径动态化；RL / Distillation 让监督本身也有生命周期。9 月 20 日的新补充进一步把这条线汇到一个词：Controller。

年度总判断：下一代工业推荐 / 搜索系统更像“共享 Backbone + 一组可寻址 Policy / State / Executor + 学习型 Controller”。Controller 不只选 model，还要决定：当前优化哪个 objective、生成什么 intent、查哪个 source/index、需要多少候选、是否触发 reasoning、是否读全局 KV、用哪种 speculative strategy、teacher 是否继续参与训练，以及何时停止搜索。真正值得积累的能力已经从单点模型结构，转向多目标建模、状态表示、动态预算、在线实验与 Serving runtime。
主线 01 · Generative Retrieval

Semantic ID → Value-aware Generation → Intent-conditioned Fulfilment → Objective-specific Policy Portfolio

上一阶段解决了什么：TIGER / RQ-VAE 把 item 映射到可生成的 Semantic ID；OneRec / OneSearch 把 retrieve 与 rank 的目标逐步向生成模型前移；VARG / GR4AD 等工作进一步把价值、ranker advantage、商业指标写入生成 policy；Spotify Hypothesis-Driven Shelf Generation 又把“为什么推荐”抽成可读自然语言 intent，再由受约束检索完成目录履约。

留下的问题：工业系统同时关心 relevance、CTR、GMV/eCPM、生态与长期满意度。把它们压成一个 reward 会出现 gradient domination；单 policy beam search 也无法显式控制固定 candidate budget 中不同目标的配额。

9/20 关键推进：UniPolicy 把多目标生成式搜索广告改写为 objective-conditioned multi-policy alignment：objective prefix + sparse MoE-LoRA + objective-specific FFN，共享 backbone 但分离 policy；线上再用并行 multi-policy beam search 按目标分 candidate quota。

工业证据：7-day A/B：CTR +0.71%、RPS +1.58%、广告收入 +1.32%，serving latency 保持稳定。

下一阶段：从“人工配置 policy quota”走向 state-aware quota controller；多目标 policy 的自动扩缩容；长期价值与短期点击的可分解 credit；intent planner 与 objective policy 联动。

主线 02 · Semantic ID

RQ-VAE → Long-tail Namespace → Value-aware SID → 可版本化、可约束的生成地址层

上一阶段：Semantic ID 解决“怎样让 decoder 输出 item”，HypRQ-VAE 等处理长尾 catalog，EPIC 修正 token likelihood 与 item-level posterior 的错位，VARG 将下游 value/ranker 信号写入 prefix-level learning。

留下的问题：地址一旦同时承载语义、协同、商业价值，就面临 catalog 增量、code drift、跨版本兼容和探索空间收缩。

与 9/20 的连接：UniPolicy 说明“业务目标”不一定继续塞进 SID 本身，也可以通过 objective-conditioned policy 在同一 namespace 上生成不同候选；这有助于把“地址稳定性”和“目标可变性”解耦。

下一阶段：incremental / versioned SID、跨 policy 共享 codebook、cold-item code assignment、探索友好的 code regularization，以及 candidate quota 与 SID tree search 联合优化。

主线 03 · Foundation Model / Ranking

Feature Model → Long-sequence Transformer → Generative Pretraining → Transferable Ranker → Structured User State

上一阶段：HSTU / SORT / OneTrans 把长序列 Transformer 推进工业精排；LazFormer 等将全年行为做 autoregressive pretraining，再通过 adapter 适配 ranking-specific features；PTDG / MORE / UniRec 推进跨任务、跨场景共享。

留下的问题：容量不再是唯一瓶颈。更关键的是“哪些 state 进入 backbone、哪些 state 可缓存、哪些 state 需要高频更新”。长期 preference、短期 session、自然语言 taste、业务 feature 需要不同 learning clock。

下一阶段：foundation backbone + mutable user/session memory；textual preference 与 ID embedding 双通道；pretrain / finetune / online adapter 三层更新；与 controller 联合决定何时读取哪类 state。

主线 04 · RL / Preference Alignment

Static Reward → Preference Optimization → On-policy Distillation → Adaptive Teacher Lifecycle

上一阶段解决了什么：DPO/GRPO 类方法让模型能直接利用偏好与环境 reward；Agentic RL 再用 OPD/OPSD 提供 trajectory 中间 token 的 dense supervision，缓解只有终局 reward 的 credit sparsity。

留下的问题：teacher 有 privileged context 不代表它一定可靠；student 变强后，继续拟合 teacher 可能与 reward optimization 冲突，形成上限。固定 annealing schedule 也无法适配不同模型/任务的学习速度。

9/20 关键推进：RetireOPD 先独立训练 skill-conditioned teacher，再让 student 用 GRPO + OPD 联合学习；当 teacher-student discrepancy 停止收敛且 student 达到 teacher 的目标性能比例后，自动退休 teacher，只保留 RL。

结果：Qwen2.5 1.5B–7B 上，ALFWorld 相对 RL baseline +14.1%～18.8%，WebShop +11.8%～19.0%，并在所有设置超过自己的 skill-conditioned teacher。

下一阶段：per-skill / per-state retirement；teacher ensemble 动态路由；teacher 可重新激活；把 distillation cost 纳入训练 controller。

主线 05 · Reasoning / Re-ranking

Cross-Encoder → Listwise → Single Reasoning Trajectory → Multi-Trajectory Evidence Portfolio

上一阶段：Cross-encoder 提升精排相关性，listwise/generative rerank 开始显式建模候选间关系，reasoning reranker 用 LLM 对复杂 query-document pair 做解释式判断。

留下的问题：单条 CoT 很脆弱：一旦误解 query 或漏掉一种 evidence，排序会被整条推理链拖偏；更长的 CoT 并不等于更全面。

9/20 关键推进：MERIT-Rank 构造 Multi-Trajectory Reasoning Space，从 semantic / intent / evidence 等互补视角推理，再由 joint reranker 融合；Progressive Rank Policy Optimization 分阶段稳定 reasoning 与 ranking。

结果：4B 已超过多数 7B、部分 32B reranker on BRIGHT；论文报告相对同规模 eRank 约 +6.1%。

与 9/19 的承接：MSS-Complement 将“相关性”提升到 set sufficiency；MERIT-Rank 将“判断过程”提升到多证据 trajectory。二者合起来的下一步很自然：coverage-aware multi-trajectory list reranking。

下一阶段：trajectory router、uncertainty-triggered reasoning、verifier early-exit、listwise multi-trajectory、蒸馏到低延迟 reranker。

主线 06 · Agentic Search / Context Ranking

Fixed Query → Query-conditioned Retrieval Plan → State-conditioned Complement → Full-pipeline Reward

上一阶段：GeneralQPP 判断是否需要继续检索；DiBud 把固定 Top-K 变 access budget；ORDER 让 source/index/chunk/reranker 由 query 决定；DUPAR 把 cross-turn cache 变 retrieval state；MSS-Complement 进一步问“当前 state 还缺什么最小充分证据集合”。

9/20 新推进之一：F²DR 指出 DeepSearch 的 Reward Model 也必须理解完整工作流，而不是只打最终答案分，将评估拆成 Content / Trajectory / Answer，并构建 DeepSearch RM-Bench。

主线 07 · Retrieval Representation

BM25 → Dense Embedding → Late Interaction → Learned Sparse Revival → Hybrid Portfolio

上一阶段：Dense 向量成为默认召回，但 lexical exactness、rare entity、可解释性仍需 BM25/sparse；Late Interaction 用多向量提高细粒度匹配，但索引与 Serving 更复杂。

9/20 关键补充：SPARSEUP 用 149M ModernBERT + SPLADE-style head，并通过 logit shift、per-position top-k、case folding 控制 expansion，给出一个强开放 sparse baseline。

结果：BEIR-13 56.4 nDCG@10；控制 backbone/data 后比 DenseOn 低 1.52，但倒排兼容、可读 token weights、MS MARCO + Seismic >97% recall 时约 380µs/query。

下一阶段：不要问“dense 还是 sparse”，而是学习 query-conditioned hybrid route：rare entity / exact lexical / semantic / long-document 分流到不同 retriever，再由统一 coverage controller 合并。

主线 08 · Scaling / Serving

Kernel Optimization → KV/Cache → Adaptive Compute → State-conditioned Attention / Drafting

上一阶段：FlashAttention、Paged KV、quantization、speculative decoding 优化固定计算图；KVShareArena、OneLA、JustFit 等把问题推进到跨请求 state/KV lifecycle；SoL-Pi 再说明 Agent Harness 的 context/observation 数据流本身就是主要成本面。

9/20 推进 A：On-Demand Attention 冻结主模型，仅训练 recall head，让每个 decoding state 决定是否触发 global attention，并在 vLLM 实现 GPU-side conditional execution。

主线 09 · Full-stack Generative Recommendation

Retrieve-then-Rank → One-model Generation → Planner + Executor + Ranker 的重新分层

上一阶段：OneRec / OneSearch 证明全链路生成有可能减少 stage mismatch；Spotify shelf 工作说明更稳的工业路径也可能不是彻底端到端，而是“LLM 生成 intent → constrained retrieval 兑现目录 → 成熟 ranker 决定曝光”。

9/20 的新连接：UniPolicy 再次说明“统一”不等于“单一”：一个共享生成 backbone 内仍可维护多 objective policy。未来 Full-stack Generative Rec 更可能是统一参数底座 + 可分解控制面，而不是所有业务目标融成一个 decoder distribution。

下一阶段：planner / retriever / ranker 的联合 credit；离线预生成与在线 freshness；multi-policy candidate budgeting；生成 candidate 与传统 ranker 的 calibration。

主线 10 · Model Routing

Model Router → Retriever/Generator Router → Harness Router → Token/Layer-level Compute Router

演进：最初 routing 只是“简单 query 用小模型，难 query 用大模型”；之后扩展到 retriever + generator、tool、planning mode、context policy。9 月 19 日 Harness Study / SoL-Pi 说明 runtime policy 本身影响巨大；9 月 20 日 ODA / SwitchSD 又把 controller 粒度下沉到 token / decoding strategy。

年度最终判断：Model Routing 这个名字已经太窄。更准确的研究对象是 Execution Routing：对每个 request / state / token 选择 {model, retrieval plan, context state, tool, attention, draft, reasoning budget, halt}。

下一阶段：统一 cost model、quality predictor、uncertainty estimator 与 SLO-aware policy learning；线上用 counterfactual logging / bandit / constrained RL 学 execution policy。

2026 下半年最值得押注的研究问题：① Generative Retrieval 的 objective-specific policy 与 quota controller；② Multi-Trajectory / set-level reasoning rerank；③ user/session state 的可寻址 trajectory memory；④ dense+sparse+late-interaction 的 query-conditioned hybrid routing；⑤ token/layer/request 多粒度 adaptive compute；⑥ teacher / verifier / tool 的生命周期与层级 credit assignment；⑦ Full-stack evaluation：从最终 CTR/NDCG 扩展到 trajectory quality、cost、latency、coverage 与长期价值。
