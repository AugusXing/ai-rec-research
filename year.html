过去一年，推荐 / 搜索真正发生了什么？

主线不是“LLM 替代所有模块”，而是系统边界重划：Item ID 变成语义 namespace；用户状态从单向量走向 context / memory；retrieval 从静态 ANN / inverted index 走向 generative、可反馈、可资产化；ranking 从静态任务关系走向 context-aware / dynamic dependency；reranking 从逐 token generation 走向 reusable state + structured decode；Agent 从 prompt 拼接走向 inventory-grounded policy；Serving 从固定 graph 走向 state/cache/routing 的动态预算。

年度总判断：未来 6–12 个月最值得押注的问题可压缩成七个：什么是正确的状态单位？什么计算应该离线资产化？哪些状态需要热更新？输出结构能否绕开 token-by-token decode？任务/候选/模型之间的路由如何动态化？反馈如何局部写回索引和 memory？生产系统如何把 freshness、成本与质量放入同一控制面？
主线 01 · Generative Retrieval

生成 Item ID → 生成可被现有检索系统消费的资产

上一阶段解决了什么：生成式召回证明用户序列可以直接生成离散 item namespace，不必永远依赖 query/item 双塔 + ANN；Semantic ID 又让生成 token 带上 item 语义结构。

留下的问题：full generative retrieval 的 decode、catalog freshness、约束解码与在线成本仍高；大量工业搜索并不愿放弃倒排索引的低延迟、精确匹配与成熟生态。

关键推进：SAM-D2Q 给出另一条工业路线：让 VLM + RL 离线生成业务对齐的 pseudo-query，并写回 inverted index。它不是“LLM 替代 search engine”，而是“LLM 改善 search engine 的可检索表面”。

下一阶段：Generative Retrieval = Generative Namespace + Offline Expansion + Dense/Sparse Hybrid + Freshness + Constraint + Serving Budget。真正竞争会发生在这些组件如何协同，而不是某一种 decoder 单点胜负。

主线 02 · Semantic ID

RQ-VAE → Long-tail-aware Namespace → Item-level Posterior

上一阶段解决了什么：Semantic ID 让 item 不再是随机整数，而是具备共享 prefix 的离散语义结构，使 retrieval 与 sequence modeling 更容易统一。

留下的问题：平坦 Euclidean codebook 对 power-law catalog 的 tail fidelity 不够；partial SID 的局部 token likelihood 也不等于完整 item preference，容易让好 item 在早期 prefix 被误杀。

关键推进：HypRQ-VAE 用 hyperbolic geometry 承载幂律 catalog；EPIC 在 denoising 中显式构造 complete-item posterior，再 marginalize 回未决 SID 位。

下一阶段：namespace 必须原生支持 online insertion、versioning、inventory/price/location constraints、tail fairness 与 prefix survival，并与 retrieval serving contract 一起设计。

主线 03 · Scaling / Serving

Kernel Optimization → Reusable State → Approximation / Cache 成为 Runtime Contract

上一阶段解决了什么：FlashAttention、paged KV、speculative decoding、quantization、disaggregated prefill/decode 等把 LLM serving 的显性算力成本持续压低。

留下的问题：同一 document/user/context 被重复计算；稀疏 selector、cache routing、metadata、sampling 等“非 GEMM”路径开始成为尾延迟瓶颈；共享状态跨 worker 后又带来一致性与生命周期问题。

关键推进：DoPR 把 document-side states 离线资产化；ReST 把重用户序列状态 compute-once，再对候选轻量 decode；FlashInfer/SGLang/vLLM 的近期主线则把 proxy-compensated sparse attention、cache-aware routing、多模态 encode/prefill 解耦继续下沉为 runtime primitive。

下一阶段：Serving 的优化对象会从 kernel 扩展到 offline/online boundary、state cache、request/model/device router、approximation budget、cache transaction 与 version。

主线 04 · Foundation Model / Multi-task Ranking

Shared Backbone → Context Unit → Dynamic Task Dependency

上一阶段解决了什么：统一 Transformer / foundation ranking 减少手工 feature cross，多任务架构通过共享底座提升样本效率。

留下的问题：真实点击发生在一次曝光 context 中，而不是孤立 user-item pair；同时 CTR→CVR→GMV 的任务关系也并非对所有 item、用户、场景恒定。

关键推进：UniCon 把 exposure/context 当建模基本单位；PTDG 在 hard causal mask 下按 item 动态生成 task graph，并用 progressive masking 缓解 sparse conversion 的梯度冲突。

下一阶段：shared context/slate state + dynamic task graph + adaptive compute + task-specific heads 更可能成为大规模排序模型的稳定形态。

主线 05 · RL / Preference Alignment

Final Reward → Process Credit → Business-aligned Offline Asset

上一阶段解决了什么：推荐/搜索开始用 preference optimization 把 click/pay/GMV、grounding、process correctness 写入训练目标，而不仅优化 next-token likelihood。

留下的问题：高 QPS 系统无法默认支付长 CoT / 在线 RL policy 的 token 与 latency；reward 本身还会随库存、流量和季节漂移。

关键推进：SelfDR 把 reasoning teacher 蒸馏成 direct student；SAM-D2Q 更进一步，把 GRPO 的结果变成索引资产，线上零大模型推理；IGPO 则把“需要经常变”的部分放到 Policy Guideline，而不是模型权重。

下一阶段：slow learning / reasoning offline + fast student / asset online + policy router for hard cases 会比全量在线 CoT 更接近工业最优。

主线 06 · Reasoning / Re-ranking

Full Cross-encoder → Reusable Prefix → Structured Assignment → Latent Reasoning State

上一阶段解决了什么：LLM reranker 提升 listwise semantic quality，但 document 重算与 autoregressive output 带来明显 latency。

留下的问题：文档是可复用资产，排序输出又天然是 permutation，为什么每个 query 都重算全部 document、再逐 token 生成候选序号？多模态 reasoning 还会出现视觉信息随推理层数衰减。

关键推进：DoPR 离线复用 document state；hLLM 从一次 prefill 读出 item-position matrix，用 Hungarian assignment 得到合法排列；LARK 用 latent visual checkpoints 保存跨模态 reasoning 信息。

下一阶段：值得组合 reusable candidate state + structured/listwise decode + cached latent reasoning + business constraints，同时消掉文档重算、CoT 与 autoregressive rank decoding 三类成本。

主线 07 · Full-stack Generative Rec

One Model → Cross-stage Contract → 可复用状态与可验证控制面

上一阶段解决了什么：TGR 展示从排序、Semantic ID generation、整页生成到离线 reasoning 注入的工业 full-stack 路线；统一 namespace/backbone 开始跨召回、排序、重排共享知识。

留下的问题：“统一模型”如果没有统一 state/version/serving/experiment contract，只会把复杂度从多个模型搬进一个更大的 checkpoint。

关键推进：ReST、DoPR、SAM-D2Q、IGPO 分别指出四种可复用对象：user state、document state、generated index asset、policy guideline。Full-stack 的核心开始从“一个模型”转向“哪些状态跨阶段共享”。

下一阶段：统一 catalog namespace、user/context state、candidate state、reward、structured decode、budget 与 experiment controller，才是可生产化的 full-stack generative rec。

主线 08 · Agentic Search / Context Ranking

Agent Trajectory → Inventory-grounded Policy → Atomic Evolving Memory

上一阶段解决了什么：Agentic Search 通过 query planning、tool use、RAG trajectory 扩展固定 retriever 的能力；推荐 Agent 开始维护长期语义 memory。

留下的问题：动态 inventory 让 prompt 中的事实迅速过期；coarse memory summary 又会覆盖用户兴趣阶段，且很难给出可追溯 evidence。

关键推进：IGPO 将长期 policy 与实时 inventory evidence 分离；AtomRec 将用户/物品 memory 拆成可链接、可局部演化的 atomic units，并在推荐时检索多跳 evidence path。

下一阶段：Agent 的核心基础设施会是 state observability、policy/memory versioning、trajectory replay、conflict resolution、TTL/privacy 与 cost router，而不仅是 prompt template。

主线 09 · Model Routing / Feedback Loop

Static Route → Cache-aware Route → State-aware / Feedback-aware Control Plane

上一阶段解决了什么：model routing 从“请求进哪台机器”逐渐加入 load、prefix cache、device capability、cost/quality 等信号。

留下的问题：系统状态不只在 GPU cache；vector index、policy store、user memory 也会随反馈变化。如果 router 不知道“状态在哪、版本是什么、是否新鲜”，就无法真正优化端到端成本。

关键推进：SGLang 把 KV Indexer 纳入 cache-aware routing；Embedding Surgery 则把 feedback 直接写回 document vectors，提示未来 control plane 还需要感知 index version / feedback freshness。

下一阶段：Model Routing → State Routing：决定的不只是用哪个模型，而是使用哪份 user/document/cache/policy state、是否需要刷新、是否值得走昂贵 reasoning 路径。
