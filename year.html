过去一年，推荐 / 搜索真正发生了什么？

主线不是“LLM 替代所有模块”，而是系统边界重划 + 状态资产化 + 决策可验证：Item ID 变成语义 namespace；用户与候选状态开始复用；retrieval 从静态 ANN / inverted index 走向 generative、graph 与可反馈资产；ranking 从统一 backbone 继续走向 task-aware information flow；Agent 的 horizon、memory、workflow graph 从静态设计变成控制变量；Serving 则从 kernel 加速进入 state compatibility、deadline-aware scheduling、precision contract。

年度总判断：下一阶段最值得押注的核心问题可以归结为：什么状态值得复用？这份状态在新的 context / checkpoint / precision 下是否仍保持原 decision？什么控制环应该交给确定性算法，什么语义推理才值得支付 LLM 成本？ 2026-09-11 的 LiteRAG、KVShareArena 与低比特向量检索工作，把这三个问题同时推到了台前。
主线 01 · Generative Retrieval

直接生成 Item → 生成可复用检索资产 → 算法化 Graph Retrieval Controller

上一阶段解决了什么：生成式召回证明用户序列可以直接生成离散 item namespace；Semantic ID 又让 token 带有 item 语义；SAM-D2Q 进一步把 VLM + RL 的结果离线写回倒排索引，避免把昂贵生成放到高 QPS 在线链路。

留下的问题：多跳搜索仍可能需要结构信息，而 GraphRAG 若在 query-time 用 LLM 做图遍历、社区摘要和证据拼接，延迟与 token cost 会快速膨胀。

下一篇关键工作如何推进：LiteRAG 保留图结构，但把在线控制从 LLM 中拿出来：semantic / lexical / community anchor → query-adaptive expansion → compact reasoning chain。它把“Agentic Retrieval”从多轮生成改造成有预算边界的算法 controller。

下一阶段：Semantic Namespace + Sparse/Dense/Graph Hybrid + Offline Generative Asset + Deterministic Online Controller + Freshness，重点不再是 decoder 是否能替代全部 retrieval。

主线 02 · Semantic ID

RQ-VAE → Long-tail-aware Namespace → Item-level Posterior → Namespace Runtime Contract

上一阶段解决了什么：Semantic ID 让 item 不再只是随机整数，使 retrieval、ranking 与 sequence modeling 有机会共享 token space；HypRQ-VAE 用 hyperbolic geometry 更自然承载 power-law catalog，EPIC 则缓解 partial token likelihood 与完整 item preference 的错位。

留下的问题：tail fidelity、prefix survival、online insertion、版本迁移与 inventory constraint 仍然难；同时 namespace 一旦用于在线 ANN / generation，也会受到低比特存储与状态版本变化影响。

下一篇关键工作如何推进：Low-bit Vector Search 虽不是 SID 方法，却给下一阶段 namespace serving 一个关键评价范式：不要只看 representation distortion，要看真正影响 top-k / graph pruning 的 decision flip。

下一阶段：Semantic ID 需要原生支持 catalog version、online insertion、constraint decoding、tail robustness，以及与 ANN quantization / serving state 的兼容协议。

主线 03 · Scaling / Serving

算得更快 → 状态复用 → 动态预算 → 状态兼容性

上一阶段解决了什么：FlashAttention、Paged KV、speculative decoding、quantization、disaggregated prefill/decode 降低单次计算成本；DoPR / ReST 证明 document/user state 可以 compute-once、reuse-many；HiCache 又把 host cache duplication 和 ownership 显式化。

留下的问题：“能 cache”并不等于“能安全复用”。chunk 离开原始 context 后位置变化，多个独立 source 之间缺失 cross-attention，不同 producer checkpoint 还可能产生 distribution shift。固定 prefill chunk / 固定 recompute ratio 也会浪费 SLO budget。

关键推进 1：SLOWeave 将 prefill chunk size 从静态配置变成由 decode deadline 驱动的在线控制变量。

关键推进 2：KVShareArena 把 non-prefix KV reuse 拆成 context change × checkpoint change 两个轴，并用 PGR + recompute + KV bytes + TTFT 共同评价；它说明 multi-source 下仅 position alignment 可能跌到 no-cache floor 以下。

关键推进 3：KV concatenation-aware fine-tuning + selective recomputation 展示模型适配与 Serving 修复可以叠加：124k RULER 比 CacheBlend-only 高 9.7 分，SSD KV 场景 TTFT 约降 80%。

下一阶段：State Cache + Birth Context + Producer Fingerprint + Position / Cross-source Contract + Precision Layout + Deadline Controller 将共同组成 runtime control plane。

主线 04 · Foundation Model / Multi-task Ranking

Shared Backbone → Dynamic Task Graph → Task-aware Backbone

上一阶段解决了什么：统一 Transformer / foundation ranker 减少 feature engineering，多任务共享提升样本效率；UniCon 把 context 作为基本单位，PTDG 用 item-conditioned task graph 让任务依赖不再固定。

留下的问题：若任务区分只发生在 backbone 之后，前面已经把 click / interaction / chat 等任务所需证据压成一个 task-agnostic representation，末端 gating 无法恢复从未形成的任务特征。

下一篇关键工作如何推进：MORE 用 Shared / Private Anchor Tokens 让 task signal 跨层进入 sequence reading 和 feature mixing；陌陌线上 usage duration +3.0%、interaction +3.6%、deep chat +2.0%，同时 request-level shared compute 让 scoring latency 约下降 30%。

下一阶段：task-aware foundation ranker + dynamic task graph + shared request/user state + candidate-adaptive compute，把“多任务”和“Serving reuse”一起设计。

主线 05 · RL / Preference Alignment

Final Reward → Process Credit → Offline Asset → Harness-level Optimization

上一阶段解决了什么：推荐/搜索开始把 click/pay/GMV、grounding 与 reasoning correctness 写进 preference optimization；SelfDR 把 reasoning teacher 蒸馏成 direct student，SAM-D2Q 把 RL 输出离线写进索引，IGPO 把长期策略放进可更新 guideline store。

留下的问题：模型权重并不是唯一可优化对象。真实 Agent/算法研发流程还包含 prompt、handoff、agent topology、tool policy、evaluation harness；让 LLM 自由改这些配置时，名义搜索空间很大，但有效搜索空间往往很小。

下一篇关键工作如何推进：RobustSGPO 把 harness evolution 改成 typed edit planning + exact-target check + category archive + paired replay；在快手 AgentX workflow 上 held-out completion 60%→80%，20M-token budget score 3.77→4.14。

下一阶段：从 model preference optimization 扩展到 model + policy + tool + harness + evaluation 的多层优化，但必须配套 replay、版本与成本控制。

主线 06 · Reasoning / Re-ranking

Full Cross-encoder → Reusable State → Structured Decode → Verifiable Evidence

上一阶段解决了什么：DoPR 复用 document-side state，hLLM 从单次 prefill 读 item-position matrix 并用 Hungarian assignment 得到合法 permutation，绕开逐 token list generation。

留下的问题：即使 rank / answer 质量更高，高风险搜索仍需要可验证证据；soft faithfulness score 无法保证引用一定来自输入。

下一篇关键工作如何推进：CHyD 在 evidence extraction 模式中把合法 continuation 限制为检索上下文的连续 verbatim span，以 decoding hard constraint 保证引用来源。

下一阶段：reusable candidate state + structured assignment + business constraints + evidence pointer / hard grounding，将生成式 rerank 从“会解释”推进到“解释可验证”。

主线 07 · Full-stack Generative Rec

One Model → Cross-stage State Contract → Decision-preserving Runtime

上一阶段解决了什么：TGR 展示 ranking、Semantic ID generation、整页生成与 offline reasoning 的工业 full-stack 路线；ReST、DoPR、SAM-D2Q、IGPO、AtomRec 又分别定义 user state、document state、generated index asset、policy guideline、atomic memory 等可复用对象。

留下的问题：状态越多，系统越容易产生 stale / incompatible / duplicated state。若没有版本、producer、precision、freshness 与 evaluation contract，“统一”只会把复杂度从模型搬到 runtime。

关键推进：HiCache 解决 ownership/duplication；NVFP4 工作显式化 dtype/backend capability；KVShareArena 再把 context/checkpoint compatibility 与质量损失纳入统一基准；低比特向量检索把“状态压缩后是否还保持决策”变成可测指标。

下一阶段：统一 catalog namespace、user/context state、candidate state、policy state、runtime cache、decision certificate、budget 与 experiment controller。

主线 08 · Agentic Search / Context Ranking

Prompt Agent → Inventory-grounded Policy → Dynamic Horizon / Memory / Graph → Self-evolving Harness

上一阶段解决了什么：IGPO 分离长期 policy 与实时 inventory；AtomRec / EdgeMem 将长期记忆从粗 summary 推向可追溯 evidence；Elastic Horizon 把交互长度变成闭环控制变量；ReActNet 在推理时按任务生成 temporal communication graph。

留下的问题：Agent 的“模型能力”之外，workflow itself 仍可能是瓶颈；而自由文本自我修改常常只会改局部 instruction，难以稳定探索结构变化。

下一篇关键工作如何推进：RobustSGPO 把结构动作做成 typed operation，并用 archive 保留不同 edit category 的高质量 parent，使搜索真正覆盖 handoff / add-remove / routing 等结构改动。

下一阶段：state observability + typed workflow DSL + dynamic horizon + evidence memory + replay/evaluation + cost router。

主线 09 · Model Routing / Feedback Loop

Model Routing → State Routing → Decision-aware Control Plane

上一阶段解决了什么：routing 从 load balancing 加入 prefix cache、device capability、cost/quality 等信号；Embedding Surgery 让 feedback 能局部写回 dense vectors。

留下的问题：真正要路由的不只是“哪个模型”，还包括哪个 state version、哪份 cache、哪条 precision path、是否需要重算，以及低比特近似是否会改变 top-k decision。

下一篇关键工作如何推进：Low-bit Vector Search 用 boundary mass + residual tail 直接刻画 pairwise decision flip；KVShareArena 则为 cache reuse 提供 context/checkpoint compatibility gate。

下一阶段：Model Routing → State / Precision / Recompute / Reasoning Budget Routing，controller 目标函数从吞吐扩展为质量、成本、freshness 与 decision preservation。
