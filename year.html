Rolling 12-Month Review · 更新至 2026.08.25

过去一年，推荐系统真正发生了什么？

主线已经从“更大的推荐 Transformer”扩展为一个更完整的系统问题：Item 如何被编码、User State 如何复用、Context 如何选择、Index 如何压缩、模型如何适应新域、推理计算如何被路由。 2026-08-25 的两项工业工作把这条线进一步坐实：快手证明 Semantic ID 的 codebook 结构会直接决定 GenRec QPS 与线上收益；DoorDash 证明一套层级 Semantic Product ID 可以跨 Discovery Ranking 与 Search Reformulation 复用。Semantic ID 正从模型内部表示变成长期系统资产。

年度总判断：Item 从 ID → Embedding → Semantic Token → 可动态维护的 Semantic Asset；User 从场景特征 → Shared State → Support/Memory Context；Retrieval 从单 ANN → Dense × SID × Late Interaction × Structured Index；Ranking 从单业务模型 → Shared Foundation；Reasoning 从一次性 CoT → 可检索 Memory；Serving 从静态部署 → Precision / Cache / Decode Depth / Binary Optimization / Hardware Policy。2026 下半年最值得押注：Dynamic SID Platform、Hybrid Dense×SID Retrieval、Shared State + Context Adapter、Task-aligned Index、Clarification Router、Stateful Re-ranking、Agentic Compiler 与 Cost-aware Runtime Routing。
主线 01 · Generative Retrieval / Semantic ID

Item-as-Token → SID 结构监督 → Dynamic Semantic ID Platform

上一阶段解决了什么：OneRec-V2、Sona 将推荐改写为 Item Token / Semantic ID 自回归生成；FSGR / DrIG 开始处理 identifier frequency、coverage；SIDScope 把 Tokenizer→Mapping→Generator 当成独立 artifact；SSR-GRPO 又让 SID prefix 进入 dense retrieval reward 与 hard-negative curriculum，证明 SID 不必只服务生成式 Serving。

留下的问题：多层 RQ SID 有 Beam Cost、Prefix Error、Fresh Item Assignment 和版本 churn；更隐蔽的是条件码本稀疏——后级 codebook 全局看利用率高，但在每个 prefix 下有效容量很低。静态码本还会随着 item/traffic 变化而漂移。

2026-08-25 关键推进：快手的 Dynamic Single-Level Large Semantic Codebook 把多层 residual SID 改成一个大 semantic token + collaborative disambiguation token，并用 exposure-weighted clustering、EMA center、SID-switch penalty 做动态更新。15 亿样本显示 SID2 全局 utilization 93.31%，但 conditional utilization 仅 2.48%；新方案估算 AR decoding FLOPs -47.93%~-48.70%，单卡 QPS +28.57%~47.0%，五天 2.5% 线上流量主消费指标 +0.792%。

下一阶段：SID 将像 Feature Platform 一样需要 utilization、conditional utilization、version、churn、fresh-item coverage、rollback 与 serving cost 指标；真正的前沿是 Dynamic SID × Dense ANN × Query-aware Router，而不是争论“生成式召回是否彻底替代 ANN”。

  • OneRec-V2 · Sona · SSR-GRPO · Dynamic Single-Level Semantic Codebook
主线 02 · Cross-system Semantic Representation

Search / Rec 各自 Embedding → One Hierarchy, Multiple Task Adapters

上一阶段：搜索和推荐通常分别训练 query-item semantic embedding 与 collaborative item embedding，taxonomy、冷启与长尾治理重复建设。

关键推进：DoorDash 的 One Hierarchy, Two Systems 用同一套层级 Semantic Product ID 同时支持 Discovery Ranking 和 Search Query Reformulation。排序侧将用户历史在 SID prefix 上聚合 affinity/performance；搜索侧用 hierarchy 限制 reformulation 落在真实 catalog 语义空间。离线 ranking full config MRR@5 +6.98%、NDCG@5 +6.76%；21 天线上 full bundle subtotal +0.31%、carousel ATC +5.5%，搜索 Purchase MRR +0.558%。

留下的问题：同一 hierarchy 的最优粒度对不同任务并不相同；ranking 需要 collaborative residual，search 更依赖 query-conditioned fine semantics。共享资产一旦错误也会同时污染多个链路。

下一阶段：统一的是 Semantic Namespace / Hierarchy / Version，不是统一所有模型。每个任务通过 prefix selection、adapter、calibration 使用共享 SID；这会连接推荐召回、排序、搜索改写、广告 taxonomy 与运营理解。

  • DoorDash: One Hierarchy, Two Systems
主线 03 · Foundation Model / In-context Recommendation

跨域预训练 → Shared Foundation → 预训练“如何适应新域”

上一阶段：RecGPT / UniSRec 汇总多个真实域学习 transferable recommender；OneModel 从工业侧将 Organic Rec、Ads、Merchant Recommendation 统一为 Event Sequence + Shared User State，并用 scenario-aware modulation 保留业务差异，线上 Ads CTR +8.18%、广告价值 +3.43%。

留下的问题：更多真实域并不自动等于 true zero-shot，新国家、新类目、长尾业务仍可能需要 fine-tune。

关键分叉：RecPFN 不用真实 clickstream 做 foundation pretraining，而在随机图 + latent-factor SCM prior 上生成无限合成环境，让 ICL Transformer 学“序列推断算法”。部署时倒排索引选择 support sequence → 单次 forward 预测 next-item embedding → cosine Top-K，无梯度更新。

下一阶段：Shared Foundation 与 PFN/ICL 会组合：全局 User/Item State 提供稳定 representation，Support/Memory Retriever 提供局部 domain evidence，轻量 adapter 负责 request-level adaptation。

  • OneModel · RecPFN · RecPFN Code
主线 04 · Retrieval / Index Geometry

Single Vector → Collaborative Geometry → Structured / Task-aligned Index

上一阶段：TTT-Embed、Think-to-Personalize 把 query/user embedding 推向 test-time / reasoning-aware；CoRRe 将 LLM user semantics 与 collaborative item geometry 解耦；Variable-bit Quantization、CrossQ 证明索引压缩不应只最小化 reconstruction，而应保护 downstream Top-K 与 hard-negative margin。

新推进：EnSI-RAG 把 long-document RAG 从 chunk vector index 推向 entity-centered structure record，并保留 passage provenance；CAIRO 则从另一端表明，进入 LLM reranker 的 item context 也应由 user-item profiler 选择，而不是无限堆 metadata。

下一阶段：Index 的基本单元会从“一个向量”扩展为 dense vector、SID prefix、entity relation、user-specific profile、memory record；Router 根据 query intent 与成本决定走哪种 representation。

  • CrossQ · CAIRO · EnSI-RAG · EnSI-RAG Code
主线 05 · Ranking Foundation / Long Sequence

Feature Interaction → Transformer-native → Shared State + Semantic Hierarchy

RankMixer、OneRank、TM20K、UniDot 把精排推进到 Transformer-native 与长行为序列；OneModel 将异构 action 统一为 Event Sequence，并把 User State 增量维护到低延迟 KV Store，请求只做 candidate scoring。DoorDash 的 SPID 又补上 item 侧：共享语义 hierarchy 可以让 ranking 跨长尾商品聚合统计，而不必每个 product 都依赖稠密历史。

下一阶段：精排资产会由 Event Schema、Shared User State、Semantic Product Hierarchy、Content Representation 和 Serving Graph 共同组成；Dynamic Scenario Router 决定每个业务使用多少共享层、多少 task-specific adapter。

  • RankMixer · OneRank · OneModel · DoorDash SPID
主线 06 · RL / Preference Alignment / Structured Supervision

Click Label → Semantic / Intent / Reward → Frequency-aware Teacher Budget

SSR-GRPO 用 SID + dense relevance 构造 retrieval reward；Think-to-Personalize 用 SFT→GRPO 对齐 personalized intent reasoning 与 Retrieval Utility；GateDiffInt 用 conversion 同时约束 diffusion 与 intent distillation；LLM Annotation × Click 说明不同 query frequency 需要不同 teacher signal。

下一阶段：监督将按 Frequency、Uncertainty、Business Value、Label Freshness 动态组合 Click、Conversion、LLM label、SID structure、Human Feedback；SID 的动态码本还要求 reward 对 version/churn 具有鲁棒性。

  • SSR-GRPO · Think-to-Personalize · GateDiffInt
主线 07 · Reasoning / Re-ranking / Memory

一次性 CoT → 可检索 Experience → Prefill-side Reasoning Memory

rEDMRec 把推理经验蒸馏成资产；SCoRD 维护 continual intent；StateMem 显式处理 supersession 与 current state。Memory-Augmented Compression 又从 Serving 角度给出更底层的解释：decode token 昂贵，很多推理信息可以预先抽象成 pattern/constraint/operation memory，在 query 时检索并放进 prefill，替代一部分在线 CoT。相对 Chain-of-Draft，多个 reasoning benchmark 大幅恢复准确率，同时相对标准 CoT 延迟约 1.14~1.49× 加速。

下一阶段：推荐重排、Agent Memory 与 Reasoning Cache 会共享同一问题：memory 的 relevance、utility、freshness、supersession、provenance 与 retrieval cost 如何联合打分。真正有价值的不是“记更多”，而是“缓存当前仍有效、能替代昂贵生成的状态”。

  • StateMem · Memory-Augmented Compression
主线 08 · Scaling / Serving

Dense Full Compute → Runtime Contract → Agentic Binary Optimization

FlashPrefill V2、ReCache、CacheRoute 把 sparse attention、resource KV、cache locality 与 load placement变成 Runtime Policy；vLLM/SGLang 又把 streaming input guard 与 deterministic execution 纳入运行时合同。今天的 AsmEvo 把边界继续下移：Agent 可直接优化已编译 AMDGPU code object，并用 differential verification 保证 ABI/功能一致。MI308X KernelBench 29/30 加速、几何均值 1.35×；生产 vLLM/SGLang Triton HSACO 4/4 加速、几何均值约 1.18×。

同时出现的 LiLiCorr 说明 decode acceleration 也在走“轻量结构校正”路线：parallel drafter 一次给出多位置候选，再用低成本 token-transition compatibility 恢复 joint coherence，相对 vanilla DFlash acceptance +12%~19%、throughput +4%~13%。

下一阶段：模型工程师会越来越需要读 Compiler/Kernel/Runtime：最终 Router 不只选模型，还选 precision、draft strategy、cache residency、binary specialization、hardware 与 determinism level。

  • CacheRoute · AsmEvo · LiLiCorr
主线 09 · Agentic Search / Context Ranking

Tool Use → Evidence Reliability → Clarification Before Search

PILOT、PolicyGuide 将 Agent 放入真实工作流；BrowseComp-Plus / ClimbMix 揭示真实 553M-doc corpus 上 evidence recall 崩塌。Clarify-Then-Search 把失败再往前推一层：用户 query 可能根本没有定义完整问题。518 条真实查询上，不澄清 restore score 约 19.434；2 个澄清问题后多种模型提升约 +6.2~+7.6，3 问时最好约 +8.9。

下一阶段：Agentic Search 应增加 Clarification Router：根据 intent entropy、query underspecification、预计 tool cost、用户耐心决定是否先问 1 个高信息增益问题。评估也要拆 Clarifier、Retriever、Planner、Reader、Evidence Provenance 与 Approval/Rollback。

  • BrowseComp-Plus / ClimbMix · Clarify-Then-Search · Project
主线 10 · Full-stack Generative Rec / Model Routing

Stage-by-stage Pipeline → Shared Semantic Assets，但执行路径更动态

Sona 尝试让召回、排序、重排共享生成式建模；OneModel 共享 User State；DoorDash 共享 Semantic Product Hierarchy；快手动态 SID 又把 codebook 本身变成可运维资产。与此同时 Adaptive Ranking、RecPFN、CacheRoute 不断证明：即使模型能力更统一，请求的价值、上下文、候选规模和硬件状态差异太大，执行层仍必须动态。

最终形态更可能是：Shared Foundation + Shared User State + Shared Semantic ID/Content Asset，下面由 Router 决定 Dense ANN、SID Generate、Late Interaction、Support ICL、Heavy/Light Ranker、Stateful Re-rank、Memory/Cache 与 Hardware path。统一的是资产和能力，不是让所有请求走同一路径。

  • Sona · OneModel · Dynamic SID · DoorDash SPID
推荐精读路线

如果只沿一条路线读，建议这样串起来

OneRec-V2 / Sona→SIDScope / SSR-GRPO→Dynamic Single-Level SID→DoorDash SPID→OneModel / RecPFN→Clarify / Context Selection→AsmEvo / Runtime Policy

这条路线能看到推荐系统的核心矛盾如何从“模型表示”扩展为“表示如何编码、如何跨任务复用、如何持续更新、如何选择上下文、如何在运行时付费”。
