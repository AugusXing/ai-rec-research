过去一年，推荐系统真正发生了什么？

主线已经不再只是“把推荐 Transformer 做得更大”。过去一年的工作正把推荐 / 搜索系统拆成更长期的资产：User State 如何压缩成高信息密度 token、Item 如何形成可动态维护的 Semantic Namespace、Context 如何按价值主动分配、Reward 如何真正对齐推荐 Utility、Runtime 如何决定每个请求值得付多少计算。 8 月 26 日的新工作进一步证明：当 Raw History、Context Window 和参数量开始饱和，下一阶段的 Scaling 单位会从“更多”变成“更密、更准、更主动”。

年度总判断：User 从 Raw History → Long Sequence → Shared State → Densed Behavioral Tokens；Item 从 ID → Embedding → Semantic Token → Dynamic / Asymmetric Semantic Grammar；Retrieval 从单 ANN → Dense × SID × Structured Index；Ranking 从单业务模型 → Foundation Ranker + Trigger/Request State；Reasoning 从可读 CoT → Utility-aligned Reward / Stateful Memory；Search 从一次性 Top-K Context → Clarification + Causal Context Allocation；Serving 从静态模型部署 → Precision / Cache / Decode / Compiler / Hardware Routing。最值得押注的不是取消 Pipeline，而是让 Representation、State、Semantic Namespace、Teacher、Memory 与 Runtime Budget 跨阶段复用。
主线 01 · Generative Retrieval

Item-as-Token → Structured SID → Token Grammar 开始按任务分化

上一阶段解决了什么：OneRec-V2 / Sona 将 next-item 推荐改写成自回归生成；FSGR / DrIG 处理 identifier frequency 与 coverage；SSR-GRPO 又让 SID prefix 反过来监督 Dense Retrieval，说明 Semantic ID 已从“生成器内部编码”走向可跨模块使用的结构监督。

留下的问题：多层 SID 带来 decode depth、prefix error 和码本稀疏；更深一层的问题是：用户历史与预测目标是否必须使用完全相同的 token grammar？如果每个历史 item 都固定拆成 4 个原子 token，Transformer 会把大量注意力浪费在 item 内部重组。

2026-08-26 关键推进：Semantic Subword Tokenization (SST) 只压缩 history side，把高频相邻 SID atom 合并成 semantic subword，而 target side 继续保持固定 SID 与原 constrained decoding trie。三类 GenRec backbone 均获益；Yelp 上 history 可变 / target 固定优于 fixed/fixed，而 target 也变成 subword 后反而明显退化。

下一阶段：GenRec 的 tokenizer 会从“全局统一”走向 History Grammar × Target Grammar × Serving Constraint 分开优化；真正值得研究的是 user-conditioned merge、frequency-aware target curriculum、以及 tokenizer version 与 online serving 的兼容性。

  • OneRec-V2 · Sona · SSR-GRPO · Semantic Subword Tokenization · Code
主线 02 · Semantic ID / Item Representation

静态 RQ-VAE → Dynamic Codebook → Collaborative Structure 进入生成动力学

上一阶段：SIDScope 开始把 Tokenizer→Mapping→Generator 当成可独立审计 artifact；快手 Dynamic Single-Level SID 揭示多层残差码本的 conditional utilization 很低，并用“大单层 semantic token + collaborative disambiguation token”缩短生成路径，线上主消费指标 +0.792%，单卡 QPS +28.57%~47.0%。

2026-08-26 新分叉：ANR-DiffRec 指出 content-semantic SID 仍可能忽略 collaborative structure，于是把 item co-occurrence 同时注入 SID construction 与 diffusion noise rescheduling；SST 则从另一个角度表明“SID 是否好”不能只看 codebook，本质还包括 token 在 history / target 两侧怎样被消费。

下一阶段：SID Platform 需要同时管理 utilization、conditional utilization、collaborative consistency、fresh-item assignment、version/churn、subword vocabulary 与 decoder compatibility。未来更可能出现 Dynamic SID × Collaborative Graph × Dense ANN × Task-specific Grammar，而不是单一路线完全替代另一条路线。

  • SIDScope · Dynamic Single-Level SID · ANR-DiffRec · Code
主线 03 · Scaling / Serving

Raw Scaling → Information Density → Runtime Budget

上一阶段：TM20K、OneModel 等工作把序列长度和模型规模继续推高；FlashPrefill、CacheRoute、LiLiCorr、AsmEvo 从 sparse attention、KV locality、speculative decoding 与 binary optimization 等方向降低推理成本。

新问题：模型和历史都不是无限 scaling。User Behavioral Densing Law 在支付宝约 100M–2B 用户、30–270 天历史、0.05B–0.4B 参数的工业实验中观察到：Raw User Scale、History Length 和 Encoder Size 都有明显边际收益衰减；模型 loss 继续下降时，下游 user representation quality 也可能停止增长。

关键推进：论文把“最小充分 tokenization capacity”与数据规模建立经验 law，并提出 ALGN 为不同用户 / 行为分配不同 residual token depth。Scaling 的问题因此从“能否吃更多 token”变成“单位 token 是否承载足够独特信息”。

下一阶段：训练预算与 Serving 预算会统一到一个 Dashboard：Raw Volume、Unique Information、Token Density、History Window、Model Size、Decode Depth、Cache Residency、QPS。推荐系统的效率优化将越来越从 kernel 级向 representation-level compute avoidance 前移。

  • User Behavioral Densing Law · CacheRoute · LiLiCorr · AsmEvo
主线 04 · Foundation Model

跨域预训练 → Shared User State → Densed State + In-context Adaptation

上一阶段：OneModel 把 Organic Rec、Ads、Merchant Recommendation 统一成 Event Sequence + Shared User State，并用 scenario-aware modulation 保留业务差异；RecPFN 则不依赖真实 clickstream 的跨域预训练，而在合成 SCM 环境上训练“序列推断算法”，新域只需 support retrieval + 单次 forward。

新的核心矛盾：Shared State 如果仍以原始长历史作为输入，计算和噪声会随业务扩张继续增长；Densing Law 说明“更多历史”本身不是 foundation capability。真正的 Foundation User Model 需要先解决 behavioral tokenization，再决定哪些局部 support / trigger / memory 进入请求级适配。

下一阶段：Densed Global User State + Support Retriever + Request/Scenario Adapter 会比“一套超长上下文吃全历史”更现实；同时需要 task-conditioned token budget，避免某个全局压缩方案损失强时效兴趣。

  • OneModel · RecPFN · RecPFN Code · Densing Law
主线 05 · RL / Preference Alignment

Sparse Accuracy Reward → Dense Utility Signal；Reasoning Trace 不再被当作效果代理指标

上一阶段：SSR-GRPO 用 SID + dense relevance 构造 retrieval reward；Think-to-Personalize 用 SFT→GRPO 对齐 personalized intent reasoning 与 Retrieval Utility；LLM Annotation × Click 说明 teacher signal 应随 query frequency 分配。

2026-08-26 关键反证：The Disconnect Between Better Descriptive Reasoning Trace Quality and Recommendation Effectiveness 在统一 Qwen3-1.7B backbone 上发现，更 grounded、更可读的 reasoning trace 并不稳定提升 Recall；在稀疏 prefix-match reward 下，70%–96% prompts 的 16 个 sampled generations 全部得到 0 reward，GRPO 根本没有有效 advantage。

下一阶段：LLM Rec 的评估应拆成 Recommendation Utility / Reasoning Quality / Explanation UX；RL 先看 reward hit-rate、zero-reward ratio 与 calibration，再讨论算法名。真正值得押注的是 conversion / retrieval utility / semantic consistency / human preference 的 dense multi-objective reward。

  • SSR-GRPO · Think-to-Personalize · Reasoning Trace ≠ Recommendation Effectiveness
主线 06 · Reasoning / Re-ranking

Score Fusion → Request Anchor / Risk / Context / State 多目标重排

上一阶段：CAIRO 让 LLM reranker 按 user-item 选择真正有用的 item profile；StateMem / SCoRD 将长期 memory 推向 current-state 与 supersession-aware；重排开始承担比“最后再排一次分数”更大的系统决策。

工业推进：CRRN 把 trigger-induced recommendation 中“刚刚为什么点这个 item”显式建模：Trigger-Target Interaction + Cascading Interest Fusion + Category-assisted Pairwise Loss。天猫线上 CTR +3.87%、IPV +5.75%，额外延迟只有约 2–3ms，说明 Request Anchor 是非常高 ROI 的精排 / 重排信号。

Agent 分叉：Risk-Aware Tool Reranking 将 relevance 与 operational risk 作为检索后的双目标，在执行前收缩危险 tool action space。这与广告 / 推荐 slate 中 relevance × risk × policy constraint 本质同构。

下一阶段：统一的 rerank objective 会同时考虑 intent / trigger relevance、risk、diversity、freshness、business value 与 token / execution cost；LLM 只是在其中一种 scorer，不再等于整个重排系统。

  • CRRN · CRRN Code · Risk-Aware Tool Reranking · Code
主线 07 · Full-stack Generative Rec

统一 Backbone → Shared Assets；但 History / Target / Request 仍需要不同执行语法

上一阶段：Sona 尝试让召回、排序、重排共享生成式建模；OneModel 共享 User State；Dynamic SID / DoorDash SPID 又分别让 codebook 与 product hierarchy 成为可跨系统复用的 item semantic asset。

今天的修正：Densing Law 与 SST 都在提醒：统一能力不等于统一输入形态。用户长期历史应先 densify；GenRec history token 可以 subword 化，但 target 仍需要稳定 decoding grammar；trigger-induced 页面又需要额外即时 state。真正的 Full-stack 模型更像 Shared Foundation + 多种 typed state / tokenizer / adapter，而不是所有链路共享完全相同的 token stream。

下一阶段：Shared User State / Semantic Item Asset / Teacher / Memory 统一，Recall / Rank / Re-rank 的 representation grammar 与 budget 动态；这会比“一个模型完成所有 stage 且每个请求走相同路径”更符合工业约束。

  • Sona · OneModel · Dynamic SID · SST
主线 08 · Agentic Search / Context Ranking

Top-K Context → Clarify First → Closed-loop Context Allocation

上一阶段：BrowseComp-Plus / ClimbMix 揭示真实大语料的 evidence recall 问题；Clarify-Then-Search 又把失败往前推进一层：用户 query 可能根本没有定义完整问题，因此应先根据 uncertainty 决定是否澄清。

2026-08-26 关键推进：The Laws of Context Allocation 证明，即使 query 已明确，一次性扩大 context 仍会出现 relevance dilution。它用 causal leave-one-out probe 测量 evidence 的真实贡献，再用闭环 submodular scheduler 把后续预算分给尚未覆盖的信息。预算匹配下，多轮 allocation 带来约 16.7–20.5 个百分点 portfolio recall 增益。

代价：2 docs × 12 rounds 的质量显著高于 24 docs × 1 round，但延迟约 17.5s vs 1.7s。因此 Context Allocation 必须与 query value / difficulty routing 联动，而不是所有搜索都进入多轮。

下一阶段：Clarification Router → Retriever → Causal Evidence Profiler → Context Scheduler → Reader 将成为 Deep Search 的标准拆分；与推荐的 candidate recall → coverage-aware rerank 非常接近。

  • Clarify-Then-Search · Laws of Context Allocation · Code · EnSI-RAG
主线 09 · Memory / Context Management

“记更多” → Typed Retention → Experience-Amortized Retrieval

上一阶段：rEDMRec 复用 reasoning experience；StateMem 处理 supersession；Memory-Augmented Compression 将可复用 reasoning 抽象放到 prefill，替代部分昂贵 decode-time CoT。

2026-08-26 两个新信号：Compaction Cliff 证明统一摘要会系统性丢 safety rules，多轮压缩后风险更严重，因此安全规则、用户偏好、任务状态与 episodic log 必须采用不同 retention / compaction policy；EARM 则把历史 query×memory 的 LLM relevance score 沉淀成稀疏经验矩阵，用 causal matrix completion 估计未观察 pair，把昂贵 reranking 跨 agent 生命周期摊销。

下一阶段：Memory Score 会融合 relevance、utility、confidence、freshness、supersession、provenance、risk 与 decode-savings；Retriever 也会拥有长期状态，而不是每个 query 都从零开始。

  • StateMem · Memory-Augmented Compression · Compaction Cliff · EARM
主线 10 · Model Routing

“选哪个模型” → Representation / Context / Risk / Runtime 的联合路由

过去 Model Routing 多集中在大小模型、推理深度与成本；现在 Router 的决策面快速扩大：Densing Law 决定 history token budget，SST 决定 history grammar，Context Allocation 决定 evidence slots 与 round 数，Risk-Aware Reranking 决定 action exposure，CacheRoute / AsmEvo 决定 runtime / hardware path。

最终形态：请求先判断价值与难度，再动态选择 Raw / Densed State、Dense ANN / SID / Structured Retrieval、Light / Foundation Ranker、Context Width / Round、Reasoning / No Reasoning、Memory / Cache、Precision / Draft / Binary / Hardware。统一的是可复用资产和控制接口，不是每个请求都走同一条流水线。

  • Densing Law · Context Allocation · CacheRoute · AsmEvo

OneRec-V2 / Sona→SIDScope / Dynamic SID→SST / ANR-DiffRec→Densing Law / OneModel→CRRN / Utility-aligned RL→Clarify / Context Allocation→Stateful Memory / Runtime Router
