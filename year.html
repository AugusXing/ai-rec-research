过去一年，推荐 / 搜索真正发生了什么？

主线不是“LLM 替代所有模块”，而是系统边界重划、状态资产化、控制器轻量化、跨阶段联合优化。2026-09-12 的 UniRec、REVA、VikingRAG、GeneralQPP 又把这条路线向前推了一步：阶段边界可以参与训练，历史执行可以变成资产，是否升级到更贵路径可以由便宜 controller 决定。

年度总判断：下一阶段最值得押注的不是“再加一个大模型”，而是四个系统问题：① stage boundary 能否联合优化；② 什么 state / trace 值得长期复用；③ 复用状态在版本、上下文、时间变化后是否仍兼容；④ 什么决策应该交给低成本 controller，什么才值得支付 LLM / Agent 成本。
主线 01 · Generative Retrieval

直接生成 Item → 生成离线检索资产 → 图检索控制器 → 生成式 Embedding Codec

上一阶段：Generative Retrieval / Semantic ID 证明 item namespace 可以由 decoder 直接生成；SAM-D2Q 进一步把 VLM+RL 结果离线写回倒排索引，避免高 QPS 在线生成。

留下的问题：多跳关系与视觉 late-interaction 都有高存储/高在线代价；GraphRAG 的在线 LLM traversal 也难满足稳定 SLA。

关键推进：LiteRAG 把 graph traversal 改成算法 controller；GLIE 则把少量 late-interaction vectors 视为 generative code，先低成本召回，top shortlist 再重建全量 representation。

下一阶段：Semantic Namespace + Sparse/Dense/Graph Hybrid + Offline Generated Asset + Generative Codec + Decision-aware Fallback。

主线 02 · Semantic ID

RQ-VAE → Long-tail-aware Namespace → Item-level Posterior → Namespace Runtime Contract

上一阶段：Semantic ID 让 item token 带语义结构；HypRQ-VAE 更适合 power-law catalog，EPIC 缓解 partial token likelihood 与完整 item preference 的错位。

留下的问题：tail fidelity、prefix survival、online insertion、catalog version、ANN storage 与生成约束仍未统一。

关键推进：09-11 的 decision-aware low-bit vector search 提醒：namespace/embedding 压缩不能只看 reconstruction，而要看 top-k / graph prune decision 是否翻转；09-12 的 GLIE 更进一步把存储对象从“压缩后的固定 vectors”变成“可再生 code”。

下一阶段：Semantic ID 需要原生支持 version、online insertion、constraint decoding、low-bit / generative storage 与 decision certificate。

主线 03 · Scaling / Serving

Kernel 加速 → State Reuse → Compatibility Contract → Reusable Evidence Asset

上一阶段：FlashAttention、Paged KV、speculative decoding、quantization 降低单次计算；DoPR / ReST 将 document/user state 变成 compute-once、reuse-many；HiCache、SLOWeave 开始优化 cache ownership 与 deadline。

留下的问题：“能 cache”不等于“能正确复用”。位置、source、checkpoint、precision、corpus version 都可能改变 state 语义。

关键推进 1：KVShareArena 把 context × checkpoint compatibility 写成 benchmark；KV concat-aware work 用训练适配 + selective recomputation 修复 reuse。

关键推进 2：REVA 不缓存 KV，而是缓存 generator attention 汇总出的 evidence score，compatibility key 显式包含 generator/tokenizer/template/corpus version，证明“轻状态”也能形成可复用 serving asset。

下一阶段：State Cache + Birth Context + Producer Fingerprint + Corpus Version + Precision Layout + Evidence Score + Deadline Controller 将形成 runtime control plane。

主线 04 · Foundation Model / Multi-task Ranking

Shared Backbone → Dynamic Task Graph → Task-aware Backbone → Cross-stage Joint Optimization

上一阶段：UniCon、PTDG、MORE 依次把 context、动态 task dependency 与 task-specific evidence flow 推进到 backbone 内部；MORE 已证明 task-aware backbone 可同时提升多目标与 Serving reuse。

留下的问题：即使每个 stage 内多任务优化更强，cascade stage 仍独立训练，pre-ranking 的最终 fusion 可能继续丢掉 ranking 真正偏好的 item。

关键推进：UniRec 把 pre-ranking/ranking fusion agent 放进同一训练图，通过 shared embedding、vertical consistency、horizontal preference aggregation 与 AGRR 做联合优化；线上 AppUsageTime +0.616%、TotalWatchTime +0.675%，并保持 stage-local Serving。

下一阶段：task-aware ranker + cross-stage fusion + shared request/user state + candidate-adaptive compute + stage survival metrics。

主线 05 · RL / Preference Alignment

Final Reward → Process Credit → Attribute-relative Preference → Harness-level Optimization

上一阶段：SelfDR、SAM-D2Q、IGPO 将 preference optimization 从直接模型输出扩展到离线索引资产、guideline store；RobustSGPO 又把优化对象扩大到 Agent harness / workflow。

留下的问题：跨 stage 的 reward 可能被 item attribute distribution 利用，出现“整体抬高某类高 reward 样本”而损害其它目标。

关键推进：UniRec 的 AGRR 借鉴 group-relative 思想，在属性组内计算 advantage，使整组统一抬升不能带来伪收益；这是 RL/preference alignment 向工业 multi-objective fusion 的直接迁移。

下一阶段：从 model reward 扩展为 stage reward + attribute group + business constraint + policy/harness evaluation。

主线 06 · Reasoning / Re-ranking

Full Cross-encoder → Reusable State → Structured Decode → Temporal / Evidence-aware Re-ranking

上一阶段：DoPR 复用 document state；hLLM 用 assignment 代替逐 token list generation；CHyD 把 evidence verbatim constraint 写进 decoding。

留下的问题：“相关”不代表“有效”。法规/政策版本高度相似时，语义 reranker 会把过时 clause 排到前面。

关键推进：TimelyRAG 把 query/document insert time、event time、clause validity interval 作为第二阶段 temporal compatibility，最高 +28.6% nDCG@10。

下一阶段：semantic relevance + business constraints + temporal validity + provenance + evidence hard grounding 共同定义 reranking。

主线 07 · Full-stack Generative Rec

One Model → Shared State → Cross-stage Contract → Train-joint / Serve-decoupled

上一阶段：TGR 展示 ranking、Semantic ID generation、page generation 的 full-stack 路线；ReST、DoPR 等开始定义跨请求可复用状态。

留下的问题：真正工业化不是简单“一个模型包打天下”，而是哪些阶段训练时该耦合、Serving 时该解耦。

关键推进：UniRec 给出重要范式：train jointly, serve stage-locally。这比直接统一所有 online graph 更容易落地，也为未来扩展到 rerank / recall 提供渐进路径。

下一阶段：统一 catalog namespace、user/context state、candidate state 与 experiment controller，但保留适合 SLA 的 stage-local execution。

主线 08 · Agentic Search / Context Ranking

Prompt Agent → Dynamic Horizon → Retrieval Trace Reuse → Adaptive Escalation

上一阶段：Elastic Horizon、EdgeMem、ReActNet、RobustSGPO 分别把交互长度、memory、communication graph、workflow topology 变成可优化对象。

留下的问题：Agent 每次都从零探索同一个知识库，重复支付 Search/List/Grep/Read 与长上下文成本。

关键推进：VikingRAG 把成功多轮 retrieval trace 物化成 experience edges；先走一轮非 Agent 路径，evidence checker 判不足才升级。它把 Agent 从默认执行器变成 expensive fallback。

下一阶段：experience memory + evidence sufficiency + typed workflow + dynamic horizon + cost-aware escalation。

主线 09 · Model Routing / Feedback Loop

Model Routing → Context-aware Routing → Retrieval Sufficiency → Unified Escalation Controller

上一阶段：routing 从负载均衡扩展到 quality/cost/cache-aware；Embedding Surgery 让 feedback 局部写回 retrieval representation。

留下的问题：多轮 routing 若上下文构造错误，模型选择再准也没用；RAG 若不知道 retrieval 是否失败，也无法决定何时升级到更贵路径。

关键推进 1：SWRouter 联合设计 semantic context window 与 router，并将 construction accuracy 与 router performance 分开测量。

关键推进 2：GeneralQPP 用 score distribution 在 2ms 预测 retrieval sufficiency，ViDoRe AUROC 0.856；TimelyRAG 则把 temporal validity 做成 reranking controller。

下一阶段：真正的 router 将不只选“哪个模型”，而是选 context window、retrieval depth、reranker、state version、precision path、Agent escalation 与 model。

当前年度精读顺序：推荐系统：PTDG → MORE → UniRec；检索：SAM-D2Q → LiteRAG → GeneralQPP / TimelyRAG → GLIE；RAG Serving：DoPR/ReST → KVShareArena → REVA；Agent：IGPO/EdgeMem → Elastic Horizon → VikingRAG → RobustSGPO。
