过去一年，推荐 / 搜索真正发生了什么？

主线不是“传统推荐 vs LLM”二选一，而是系统边界持续重写：地址从 ID 变 Semantic ID；召回从相似度变价值 / 覆盖 / 预算；Ranker 从单任务模型变 foundation backbone；用户状态从一个 embedding 变多时间尺度 state；RAG 从固定索引变 query/state-conditioned execution plan；Agent 从调用模型变成拥有 Harness、缓存、工具、验证器和成本控制面的运行时。9 月 19 日的新推进把这些线进一步汇到三个关键词：Intent、Complement、State。

年度总判断：下一代推荐 / 搜索系统最可能是“强 executor + 学习型 controller”而不是一个模型吞掉所有 stage。Executor 继续承担 ANN、constrained decoding、foundation ranking、list rerank 与规则约束；Controller 逐步学习：该生成什么 intent、该查哪个 source/index、集合还缺什么、该花多少 retrieval/reasoning budget、该读写哪类 user/session state、该用哪个 model/tool/harness、何时 abstain / escalate。工业竞争力将越来越取决于中间状态设计、预算控制、评估闭环与 Serving 可控性。
主线 01 · Generative Retrieval

直接生成 Item → Semantic Namespace → Value-aware Address → Retriever + Verifier → Intent-conditioned Catalogue Fulfilment

上一阶段解决了什么：TIGER / Semantic ID 证明 decoder 可以直接在 item namespace 上生成；HypRQ-VAE 处理长尾 catalogue；EPIC 修正 token likelihood 与 item preference 的错位；Generative Verifier 让 deep candidate 更容易进入下游 consumed prefix；VARG 再把 value / ranker advantage 写进 SID prefix reward。

留下的问题：直接生成 item 仍把“为什么推荐”与“目录里怎么找”绑在同一模型里，难以独立调规划、召回、文案与 Serving。

9/19 关键推进：Spotify Hypothesis-Driven Shelf Generation 把生成式推荐再向上抽象一层：先生成自然语言 content hypothesis，再做受约束 generative retrieval、candidate selection、shelf alignment，并离线预计算注入成熟 Home ranking。

下一阶段：intent planner 与 catalogue executor 解耦后，最值得研究的是：hypothesis → retrieval coverage → final-ranker survival → long-term satisfaction 的 credit assignment；以及 intent-conditioned fan-out / source budget。

主线 02 · Semantic ID / Full-stack Generative Rec

RQ-VAE → Long-tail Namespace → Item-level Posterior → Large-beam Serving → Value-aware SID → Natural-language Intent Layer

上一阶段：Semantic ID 主要回答“怎样给 item 一个可生成地址”；OneLA 等工作处理 large-beam recurrent state；VARG 让地址本身带 value ordering。

新矛盾：地址层越承载业务价值，越容易把长期探索、内容生态和人工可解释性压缩进不可读 token。Spotify shelf 工作提供另一种分层：自然语言 hypothesis 负责可读 intent，Semantic ID / constrained decoder 负责 catalogue fulfilment。

下一阶段：可版本化 SID、增量 catalog、intent→SID 的 constrained mapping、探索友好的 code assignment、offline shelf refresh 与在线 reranking 的一致性。

主线 03 · Foundation Model / Industrial Ranking

Shared Embedding → Long-sequence Transformer → Generative Behavior Pretraining → Transferable Foundation Ranker → Language-readable User State

上一阶段：HSTU / SORT / OneTrans 把 Transformer 推进工业精排；PTDG / MORE / UniRec 处理多任务与跨阶段共享；LazFormer 用一年行为做 autoregressive pretraining，再以 adapter 适配 ranking-specific features，线上 Orders +3.38%、GMV +9.85%。

当前问题：Foundation Ranker 不再缺容量，而是缺可迁移 state interface：长期偏好、短期 session、自然语言 taste、业务 feature 如何共同进模型，又如何更新而不全量重训。

9/19 信号：Spotify RecSys 2026 官方专题同时把 Textual User Taste、hypothesis-driven shelves 与 conversational agents 放在“Scaling Personalization with LLMs”下，说明 user state 正从 opaque embedding 逐步增加自然语言 / structured representation。

下一阶段：dense+sparse 不同 learning clock、language state 与 ID embedding 双通道、跨任务 distillation、pretrain data governance、foundation ranker 与 online budget controller 联合。

主线 04 · Lifelong / Continual User & Session State

Recent Window → Target-aware Retrieval → Cacheable Chronicle → Preference Drift → Sparse Mutable Memory → Stateful Trajectory Retrieval

上一阶段：SIM/TWIN 用 target-aware retrieval 读长历史；ChronicleRec 把长期行为压成 target-independent cache；DRIFT 按偏好变化分 stage；LION 用 sparse KV memory 写 preference delta，避免所有新信息都污染共享 decoder。

9/19 关键连接：RAFT 在 troubleshooting 中把 historical case 表示成 directed timeline entries，在线按当前 state 检索相似历史中间态，再返回 parent-case trajectory。这种“state node → future trajectory”的结构值得迁移到 session recommendation / funnel stage。

下一阶段：user state 不再只有“当前 embedding”，而是 versioned state graph / trajectory store；长期 backbone 低频更新、chronicle 中频更新、session state 高频更新，全部有 TTL / provenance / rollback。

主线 05 · Reasoning / Re-ranking / Context Selection

Pointwise Relevance → List-level Reasoning → Verifier → Selective Escalation → Missing-Complement / Set Sufficiency

上一阶段解决了什么：MMR / listwise ranker 缓解冗余；Generative Verifier 判断候选是否值得进入 consumed prefix；CoSQ 将 evidence sufficiency 变成 answer-or-escalate signal。

剩余矛盾：即使 reranker 更强，它仍常按 passage 单独打分。对已有大量 context 的 Agent，top-K 很可能反复覆盖同一事实。

9/19 关键推进：MSS-Complement / SERBench 将目标改为 state-conditioned Minimal Sufficient Evidence：找“当前 decision 还缺的最小证据集合”。Complete-MSS@5 从 Qwen3 embedding+rerank 的 61.4% 提到 73.0%，@8 从 72.4% 到 80.6%。

下一阶段：set-level sufficiency reward、marginal information gain、coverage-aware source routing、与 cost / latency 联合的 complement policy；推荐侧对应 multi-interest coverage 与 candidate-set gap filling。

主线 06 · Agentic Search / Context Ranking

Fixed Query → Evidence Sufficiency → Explore/Execute → Access Budget → Query-conditioned Index → State-conditioned Complement

演进：GeneralQPP 判断是否已有足够证据；SAFARI 学继续探索还是执行；Question’s Gambit 优化第一轮 clue decomposition；DiBud 将 hybrid retrieval 固定 Top-K 改成 access budget；ORDER 让 index / chunking / metadata / reranker / source 由 query 动态选择。

9/18→9/19 的关键跃迁：DUPAR 把 cross-turn cache 变 retrieval state；DRAG 联合路由 retriever/generator；今天 MSS-Complement 再进一步，连“检索目标”都由当前 state 的缺口决定。RAFT 则说明历史对象本身也应 state-addressable。

下一阶段：统一 controller 输出 first move、state read、source/index、set-coverage target、access budget、reranker/model/tool、halt/abstain；优化 successful-task utility - latency - cost - risk。

主线 07 · Model Routing

One Best Model → Query Difficulty Routing → Retriever/Generator Joint Routing → Model + Tool + Harness Joint Routing

上一阶段：SWRouter / DRAG 等工作证明不同请求不应固定使用同一模型或同一 retriever/generator 组合。

9/19 新证据：Harness Design Study 用 176 matched settings 证明 planning、structured tools、context management 的收益会随模型能力与 window budget 改变：弱模型需要 scaffold，强模型有时 bash-only 更便宜；context 紧时管理策略才真正重要。

主线 08 · Scaling / Serving

Kernel → KV / State Reuse → Adaptive Budget → Agent-generated Optimization → Harness Economics

上一阶段：FlashAttention / Paged KV / quantization 优化单模型；KVShareArena / OneLA 处理跨请求与 beam state；ForgeMegakernel、FlashVector 把 Agent 引入 kernel 到 serving stack；JustFit 将瓶颈提升到 state lifecycle。

9/19 关键推进：SoL-Pi 表明即使底层模型和 kernel 不变，仅优化 Harness 的 action、context、observation、evidence flow，也能在 EdgeBench 上将 recorded token traffic 降 44.7–49.0%，API cost 约降三分之一。

主线 09 · RL / Preference Alignment

Final Reward → Process Credit → Prefix-level Reward → Harness-aware / Set-level Reward

上一阶段：GRPO 类方法开始把最终结果 reward 拆到 prefix / workflow；VARG 用 Prefix-GRPO 同时对齐合法性、用户行为、搜索相关性与 ranker advantage；ScienceBuddy 让 harness evolution 与 model RL 递归交替。

9/19 的启示：MSS-Complement 将“证据集合是否充分”变成天然 set reward；Spotify shelf 将“hypothesis 是否匹配用户、shelf 是否兑现 hypothesis、最终 engagement”拆成多层评价。这两个方向都比单一 CTR / answer reward 更接近可解释 process credit。

下一阶段：将 set coverage、final-ranker survival、latency、token cost、abstention risk、长期满意度写进可分解 reward，并保留独立 holdout 防止 evaluator / policy 共谋。

主线 10 · Full-stack Generative Recommendation

Generative Recall → Unified Search/Rec LM → Full-page Generation → Hypothesis-driven Supply + Mature Ranker

核心矛盾：端到端生成很诱人，但成熟推荐系统已有强大的 catalog governance、ranker、实验平台与安全约束。完全替换的切换成本极高。

阶段性答案：当前最可信的工业路径不是“删除 pipeline”，而是让生成式模型创建新供给 / intent / fast lane，再通过约束执行器和成熟 ranker 消化。Spotify shelf 是这一路径的清晰案例；VARG reserved quota 也是同一工程哲学。

下一阶段：生成式模块与传统 stage 的共同 item/state schema、source-specific calibration、quota learning、fallback、版本治理与 rollback。

主线 11 · Agentic RecSys / Preference Delegation

Human Consumer → Conversational Assistant → Delegating Agent → Dual-audience Recommendation

上一阶段：Conversational Rec 主要把 Agent 当交互层，最终仍默认人做消费 / 决策。

9/19 新研究议程：Who Are We Recommending To? 提出 delegation spectrum：routine / 可验证 / 低风险任务更可能由 Agent 成为推荐结果的直接操作消费者；体验型 / 主观 / 高风险任务仍以人为最终判断者。

主线 12 · Evidence Governance / RAG Observability

Hidden Retrieval Pipeline → Traceable Evidence State → Editable Context → Feedback Data

9/19 新节点：FootprintRAG 把 evidence context 变成可检查、可修改、可追溯对象，连接 retrieval trajectory、evidence revision 与 provenance-aware synthesis。
