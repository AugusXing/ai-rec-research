过去一年，推荐系统真正发生了什么？

如果把过去一年的论文按时间排开，最明显的变化不是“Transformer 又大了一圈”，而是系统边界在重画：User History 被压成可复用 State / Dense Token，Item 从 ID 变成可维护的 Semantic Namespace，Embedding 从单模型 feature 变成跨召回 / 排序共享资产，Search Context 和 Serving Compute 开始按请求动态分配。8 月 27 日的新工作进一步把这条线推清楚：Representation 正成为 Recommendation / Search 的控制面，而 Freshness 与 Compute Budget 正成为一等公民。

年度总判断：User：Raw History → Long Sequence → Shared State → Densed / Intent-bearing State；Item：Random ID → Semantic Embedding → Structured SID → Fresh / Flow-normalized / Task-specific Token Infrastructure；Retrieval：单 ANN → Dense × Semantic Token × Structured Index；Ranking：业务专用模型 → Foundation / Native Representation + Trigger State；Alignment：Sparse Accuracy Reward → Utility / Value / Process Reward；Search：一次性 Top-K → Clarification / Evidence Graph / Context Allocation；Serving：固定模型 → Dimension / Reasoning / Model / Device Routing。最值得押注的是跨阶段共享的 Representation、State、Semantic Namespace、Teacher/Reward 与 Runtime Budget，而不是单独押某一个 Backbone。
主线 01 · Generative Retrieval

Next-item Generation → Structured Identifier → Freshness-aware Generative Retrieval

上一阶段解决了什么：OneRec-V2 / Sona 把 item recommendation 统一成生成任务；FSGR、DrIG 等开始修复 identifier frequency、coverage 与 constrained decoding；SSR-GRPO 又让 SID prefix 反过来监督 dense retrieval，说明生成式 identifier 正从“模型内部编码”升级成跨模块资产。

留下了什么问题：静态 SID 默认 catalog 语义稳定，面对直播 / 热点 / 快速变更商品时很快过期；多层 residual code 又带来 serial decode、collision 和 prefix error。与此同时，history 与 target 是否必须使用同一种 token grammar 也开始受到质疑。

关键推进：SST 将 history 侧高频 SID atom 合并为 semantic subword、target 侧保持稳定 constrained decoding；Tlow 用 Normalizing Flow 先把复杂 embedding 映射到低相关标准空间，再做独立 tokenization，兼顾并行 decode 与冷启动；TAGR 则把 active live ad 的 SID 分钟级刷新，并在 L20 GPU 上实现 >2500 QPS、<100ms 生成式召回。

下一阶段：Tokenizer 不再是一种算法，而是一套 Infrastructure：要同时管理 geometry、semantic/collaborative consistency、collision、version/churn、fresh assignment、history/target grammar 和 serving decode cost。最值得研究的是 Fresh SID × Dense ANN × Request-aware Generator 的混合架构。

  • OneRec-V2 · Sona · SST · Tlow · TAGR
主线 02 · Semantic ID

RQ-VAE → Dynamic / Single-level / Flow-based SID → Semantic Namespace Platform

上一阶段解决了什么：RQ-VAE 让内容语义进入离散 identifier，但多层码本 conditional utilization、serial dependency 与 code collision 逐渐成为主要成本；SIDScope 开始把 Tokenizer→Mapping→Generator 拆成可审计 artifact，Dynamic Single-Level SID 用大单层 token + collaborative disambiguation 缩短路径并改善 QPS。

留下了什么问题：“怎么量化”仍然建立在原 embedding geometry 上；如果原空间高度相关、长尾且非高斯，简单 PQ 很难工作，复杂 residual quantization 又带来串行依赖。静态 mapping 还无法处理 meaning 随时间漂移的 item。

关键推进：Tlow 把问题前移到 geometry：用 Flow 把语义表示变成标准正态、近似维度独立的 latent，再做独立量化；微信图片召回全局 UCTR +10.32%、新品 +11.64%。TAGR 从另一个维度解决动态性：保持 token vocabulary 稳定，但分钟级刷新 live ad → LSID 映射。

下一阶段：需要统一 Continuous Embedding Service + Discrete Namespace Service。WeMM-like universal embedding 负责跨模态语义，NMRL-like task-native adapter 写入业务偏好，Tlow / Dynamic SID 负责离散化，TAGR-like remapping 管 freshness；线上还要支持 version rollback 与 historical compatibility。

  • SIDScope · Dynamic Single-Level SID · ANR-DiffRec · Tlow · TAGR
主线 03 · Scaling / Serving

More Tokens / Bigger Models → Information Density → Request-level Compute Allocation

上一阶段解决了什么：TM20K、OneModel 等继续扩大历史与模型；FlashPrefill、CacheRoute、LiLiCorr、AsmEvo 从 attention、KV locality、speculative decode、binary optimization 降低单位 token 成本。

留下了什么问题：“能算更多”不代表“值得算更多”。User Behavioral Densing Law 在十亿级用户实验中看到 Raw User Scale、History Length、Encoder Size 都存在饱和；继续降低 training loss 不再提升下游 user representation quality。

关键推进：Densing Law 把 scaling unit 改成 minimum sufficient token capacity；RecGPT-Mobile-V2 把同一思想推进到 inference：按输入复杂度分配 reasoning budget、模型路径和 device/cloud path，CoT P50 62→14 token、accelerator 平均延迟 3.00→0.76s；AdaWidth 则按 query ranking stability 动态扩展 embedding width，在保持检索质量时少用 55–84% 维度。

下一阶段：推荐 / 搜索 Serving 会形成统一的 Utility-per-Compute Router：历史 token 数、embedding width、candidate 数、reranker depth、reasoning token、模型大小、device/cloud 都由请求级预期边际收益控制。算法工程师需要开始把 latency / memory / GPU budget 作为可学习 action，而不是固定配置。

  • User Behavioral Densing Law · CacheRoute · RecGPT-Mobile-V2 · AdaWidth
主线 04 · Foundation Model

Shared Backbone → Shared User / Item Representation → Recommendation-native Foundation Assets

上一阶段解决了什么：OneModel 将 Organic Rec、Ads、Merchant Recommendation 统一成 Event Sequence + Shared User State；RecPFN 通过合成 SCM 预训练序列推断能力，新域用 support retrieval + single forward 适配，说明 Foundation 能力未必等于“把所有真实日志一起预训练”。

留下了什么问题：共享 User State 仍会被 raw history 噪声拖累；共享 Item Embedding 又常与 CTR / conversion 目标存在 supervision gap。直接端到端把所有业务 loss 写入同一个 encoder，容易形成梯度冲突。

关键推进：WeMM-Embedding 形成 2B/4B/9B 多模态共享底座，并已进入微信检索、排序特征、序列建模，14 个线上 A/B 持续正收益；淘宝 NMRL 则给出重要边界：Recommendation-native 表示不能简单通过 raw CTR E2E co-training 获得，要先 Mine 出可归因于多模态语义的高质量 preference supervision，线上 CTR +1.5%、RPM +0.5%。

下一阶段：更现实的 Foundation Stack 是 Universal Encoder → Task-native Data/Adapter → Shared Representation Service → Scenario/Request Adapter，而不是一张 loss graph 端到端覆盖所有业务。表示质量、训练成本与线上可复用性会一起成为 Foundation Model 的评价标准。

  • OneModel · RecPFN · WeMM-Embedding · NMRL
主线 05 · RL / Preference Alignment

Sparse Reward → Dense Utility / Value Reward → Fresh but Stable On-policy Alignment

上一阶段解决了什么：SSR-GRPO 用 SID structure + relevance 构造 retrieval reward；Think-to-Personalize 用 SFT→GRPO 将 personalized reasoning 对齐 Retrieval Utility。同期的 Reasoning Trace 研究又证明，更漂亮的 CoT 并不稳定提升推荐 Recall，稀疏 prefix reward 甚至会让绝大多数 rollout 全 0 分。

留下了什么问题：Reward 要既足够 dense，又不能鼓励“为了短而短”或只追商业价值；生产环境 preference 变化很快，但持续 on-policy 更新又可能破坏稳定行为分布。

关键推进：RecGPT-Mobile-V2 用 quality gate + input-specific budget + multiplicative rank-safe reward 同时提高 query quality 与降低 reasoning token；TAGR 用 IOPO 周期性采 current-policy candidate 做 Behavior/Value-Aligned GRPO，中间插入 NTP maintenance，收入最终 +16.1%。EviGraph 则把 evidence construction 本身变成 process reward，说明 RL 监督开始向“可验证中间结构”迁移。

下一阶段：推荐 RL 应围绕 Reward Density / Freshness / Causal Utility / Stability 建立监控，而不是只讨论 PPO/GRPO 算法名。Conversion、长期价值、风险、覆盖与 compute cost 都会进入多目标 reward；on-policy update 更可能是间歇校正而非全程替代监督训练。

  • SSR-GRPO · Think-to-Personalize · Reasoning Trace Gap · RecGPT-Mobile-V2 · TAGR
主线 06 · Reasoning / Re-ranking

Score Fusion → Trigger / Context / Risk / Evidence-aware Decision Layer

上一阶段解决了什么：CAIRO 让 LLM reranker 为 user-item 选择真正有用的 profile context；StateMem / SCoRD 将 memory 从“历史摘要”推进到 current-state / supersession-aware；CRRN 将即时 trigger interest 与长期兴趣级联融合，天猫线上 CTR +3.87%、IPV +5.75%，额外仅约 2–3ms。

留下了什么问题：重排如果只输出一个 score，很难表达“为什么保留 / 淘汰”及风险约束；Agent 系统里这种问题更突出，错误 tool / evidence 一旦进入后续执行，代价远高于普通排序误差。

关键推进：Risk-Aware Tool Reranking 把 relevance × operational risk 作为显式双目标；EviGraph 更进一步，将 evidence 变成带 polarity 和 support edge 的 graph，使搜索执行与证据记录解耦，BrowseComp-Plus 35.9% vs 同架构无 RL 26.9%。

下一阶段：Re-ranking 会从“更贵的 scorer”变成 Decision / Constraint Layer：同时考虑 trigger relevance、freshness、diversity、risk、business value、evidence support 和 token/execution cost。对推荐来说，这意味着重排研究重新变得重要，因为它最适合承载跨目标约束。

  • CRRN · Risk-Aware Tool Reranking · EviGraph
主线 07 · Full-stack Generative Rec

统一 Backbone → 统一 Representation / State / Value Interface

上一阶段解决了什么：Sona / OneRec 类工作尝试让召回、排序、重排共享生成式建模；OneModel 从用户侧共享 state，Dynamic SID 从 item 侧共享 semantic namespace。

留下了什么问题：“一个模型全链路”很容易把不同阶段的 latency、candidate size、freshness 和 supervision 差异掩盖掉。召回需要开放索引和高覆盖，排序需要 task-native feature，重排要多目标约束；这些目标并不会因为 Backbone 统一而自动统一。

关键推进：TAGR 给出更现实的 full-stack 方向：Generator 只承担高价值生成式召回，但 token、intent、value signal 与下游 filtering/ranking 保持接口化；Tlow / WeMM / NMRL 又分别提供可跨阶段复用的 item token、embedding 与 task-native representation。RetrievalFormer 则提醒：Search + Rec 统一索引时，“新 item 无需 retrain 即可进入索引”是必须保留的能力。

下一阶段：Full-stack GenRec 更可能是 shared assets + specialized execution stages，而不是物理上取消 pipeline。真正统一的是 User State、Item Namespace、Embedding Teacher、Value/Reward 和 Runtime Budget。

  • Sona · TAGR · Tlow · RetrievalFormer
主线 08 · Agentic Search / Context Ranking

Top-K Context → Clarification / Causal Allocation → Evidence Graph

上一阶段解决了什么：RAG 从单轮 dense retrieval 发展到 iterative search；近期 Clarify-Then-Search 开始在不确定时主动询问，Laws of Context Allocation 又证明 Wider Context 会带来 relevance dilution，同预算下闭环多轮分配 evidence 比一次性塞更多文档更有效。

留下了什么问题：即使搜索到了相关网页，最终答案也未必有逐条可验证支撑。线性 Agent trace 同时承担 planning、memory、evidence，既难训练也难审计。

关键推进：EviGraph 把 executor 与 evidence recorder 解耦：冻结 verifier 提取 verbatim evidence + polarity，policy 只提出 graph edit，deterministic validator 检查结构；graph 同时承担 working memory 与 dense process reward。它把 RAG 的“context”从字符串集合升级为可验证 evidence state。

下一阶段：Agentic Search 会出现 Context Scheduler + Evidence Store + Verifier + Answerer 的明确分层；Context Ranking 不再只按 relevance 排文档，而要考虑 marginal evidence value、contradiction、source risk 和当前 graph coverage。

  • Laws of Context Allocation · EviGraph
主线 09 · Model Routing

Model Routing → Compute Routing：不仅选模型，还选维度、上下文、Reasoning 与设备

上一阶段解决了什么：Pre-inference routing / model router 主要回答“这个请求用哪个模型”，Serving 系统则分别优化 cache、precision、decode。

留下了什么问题：Model ID 只是计算预算的一种粒度。一个 query 可能不需要换模型，只需要更短 embedding、更少 history、更少 candidates；另一个 query 可能模型不变但需要更长 reasoning 或云端升级。

关键推进：AdaWidth 根据当前 ranking 是否稳定来逐步扩 embedding prefix；RecGPT-Mobile-V2 根据输入难度同时决定 reasoning budget、student/重路径和 device/cloud escalation；Densing Law 又从输入端给出最小充分 token capacity 的 scaling 视角。

下一阶段：Model Routing 将升级为 End-to-end Compute Routing，action space 包含 History Window、Embedding Width、Retriever Depth、Candidate K、Reranker、Reasoning Tokens、Model Size、Precision、Cache/Device。训练目标不是 latency 最小，而是“单位成本带来的预期 Utility 增量最大”。

  • AdaWidth · RecGPT-Mobile-V2 · Densing Law
