过去一年，推荐 / 搜索真正发生了什么？

主线不是“LLM 替代所有模块”，而是系统边界重划、状态资产化、监督结构重写、跨阶段联合优化，以及 runtime 从模型内优化扩展到 beam state / speculative verification / kernel generation。9/15 的 MIMA、ChronicleRec、OneLA 与 Generative Verifier 让推荐系统这条主线更清楚：下一阶段的增益越来越来自“谁被监督、什么被缓存、谁有资格进入下游、状态如何被执行”。

年度总判断：下一阶段最值得押注的八个系统问题：① stage boundary 能否联合优化；② 多槽位/多专家的 credit assignment 是否正确；③ 什么 user/document/execution state 值得长期复用；④ retriever 的深 top-K 如何变成 downstream 真正消费的短名单；⑤ cheap controller 如何决定预算与升级路径；⑥ generative rec 的 beam/state runtime 如何扩展；⑦ Agent 是否能学会何时探索、何时停止；⑧ harness/kernel/runtime 能否被系统化自动优化并验证。
主线 01 · Generative Retrieval

直接生成 Item → Semantic Namespace → Generated Index Asset → Retriever + Verifier

上一阶段解决了什么：Generative Retrieval / Semantic ID 证明 item namespace 可以由 decoder 直接生成；SAM-D2Q 将 VLM/RL 的结果离线写回 index，避免在线高成本生成；GLIE 用少量 generative code 重建完整 representation。

留下的问题：第一阶段“把 relevant item 放进 top-1000”并不等于它会进入粗排真正消费的 top-100；大 catalog 下深层候选混淆越来越严重。

9/15 关键推进：Recommendation Retrievers Need Verifiers 把轻量 generative verifier 挂在冻结 retriever 后，只验证 top-K，并用 token likelihood + reciprocal-rank fusion 把 relevant item 推入 consumed prefix。YaMBDa 规模越大，Recall@10 相对提升越明显。

下一阶段：Retriever → Verifier → Pre-rank 将成为值得验证的新边界：retriever 保覆盖，verifier 做输出侧纠错，pre-rank 再做高成本 feature interaction；verify-K 由 confidence/latency 动态控制。

主线 02 · Semantic ID / Full-stack Generative Rec

RQ-VAE → Long-tail Namespace → Item-level Posterior → Large-beam State-aware Serving

上一阶段：HypRQ-VAE 处理 power-law catalog，EPIC 缓解 partial token likelihood 与完整 item preference 的错位，TGR 将 ranking / SID generation / page generation 串到 full-stack。

留下的问题：生成式推荐真正部署后，beam 常到 128–512；recurrent linear attention 虽解决长 prompt，却给每个 beam 引入一份 state，显存/DRAM traffic 成为新瓶颈。

9/15 关键推进：OneLA 用 shared post-prefill state + append-only GDN Transition Records + beam ancestry index 表示所有 beam，只 replay 当前需要的 projection；端到端 decode 1.54–2.46×。

下一阶段：Semantic ID 的研究不应只看 tokenizer / codebook，还要联合 beam budget、state layout、constraint decoding、continuous batching 与 cost-aware search。Full-stack generative rec 的“全栈”真正开始包含 runtime。

主线 03 · Multi-interest Retrieval

Multiple Interest Vectors → Diversity Regularization → Supervision Geometry / Exclusive Assignment

上一阶段解决了什么：MIND / ComiRec 等证明多个 user vector 能提升多峰兴趣覆盖；后续通常用 orthogonality / contrastive diversity 减轻 interest collapse。

留下的问题：如果每个 training example 只有一个 positive，梯度经常反复流向同一个“最接近”的 interest，其他 slot 即使被正则推开也缺少明确职责。

9/15 关键推进：MIMA 将 request 内多个 positive 组成 set，用 Hungarian exclusive assignment 让不同正例一一监督不同 interest，并学习 interest activation probability 做跨 channel score calibration。7-day A/B：交易笔数 +5.60%、金额 +5.44%。

下一阶段：从“让多个向量不一样”转向“让多个 slot 有稳定 ownership”。值得延伸到 MoE expert collapse、multi-head query intent、creator/category specialist 与跨阶段 candidate ownership。

主线 04 · Lifelong User Modeling / Foundation Ranking

Recent Window → Target-aware Retrieval → Target-independent Compression → Temporally Anchored Cacheable State

上一阶段：SIM/TWIN 一类目标相关检索从超长历史里抽取与 candidate 相关行为，精度强但每个 candidate 重复检索；VISTA 类压缩将历史总结成少量 token，可复用但时序组织不足。

9/15 关键推进：ChronicleRec 用 recency-aware multi-granularity merge + interleaved causal query tokens + multi-horizon masking，将历史压成按时间组织的 Chronicle Tokens。它们 target-independent，可按用户缓存；训练约 4.8× 更快，线上 GMV +1.61%。

并行推进：DRIFT 说明“更长历史”本身可能引入 preference-inconsistent noise，于是根据 semantic/time/category drift 自适应切分兴趣阶段，再让 recent context 选择性读取长期 subsequence。

下一阶段：用户状态资产会分层：长期 Chronicle / preference-stage token 低频刷新，recent state 实时刷新，candidate interaction 只在最内层计算。研究重点转为 TTL、增量更新、版本兼容和跨 stage 复用。

主线 05 · Scaling / Serving

Kernel 加速 → State Reuse → Runtime Contract → Adaptive Verification → Agent-generated Megakernel

上一阶段：FlashAttention、Paged KV、speculative decoding、quantization 优化单次模型计算；DoPR/ReST/KVShareArena/REVA 把 state reuse、compatibility、evidence cache 与 deadline 引入 serving 层；9/14 又扩展到 cold-start/hardware contract。

9/15 新信号 1：vLLM adaptive verification 在线估计不同 draft position 的 acceptance probability，并按持续观测 refit，提示 speculative decoding 将从固定参数进入 request-adaptive control。

9/15 新信号 2：ForgeMegakernel 用 coding agent + 10-stage kernel knowledge base + mid-state correctness oracle，为不同模型生成专用 decode megakernel；对 SGLang 0.5.18 几何平均 1.21×。

9/15 新信号 3：OneLA 把 serving state 进一步扩展到 beam ancestry / transition log。至此 runtime control plane 管的不只 KV，还包括 draft acceptance、beam recurrent state、kernel variant、cache attempt scope、hardware fast path。

下一阶段：生产 benchmark 从 tokens/s 升级到 time-to-ready、P50/P95、state bytes、HBM traffic、acceptance waste、cost/task、recovery correctness 的联合矩阵。

主线 06 · Reasoning / Re-ranking

Cross-encoder → Structured Decode → Verifier-driven Repair → Output-side Verification

上一阶段：hLLM 用 assignment 替代逐 token list generation；CHyD 把 hard evidence constraint 写进 decoding；Magenta 做 generate→verify→attribute→selective repair；Ecdysis 把 failure attribution 提升到 harness 层。

9/15 推进：Universal Generative Verifier 把“verification”落到传统推荐 pipeline：不动 retriever，只验证其 top-K output，再决定谁进入更贵 downstream stage。这比全量 cross-encoder rerank 更像一个可插拔、可 shadow 的边界层。

下一阶段：验证器不只判断 semantic relevance，还将同时读取 freshness、business constraint、creator diversity、stage survival probability、cost，并输出“接受 / 重排 / 扩大召回 / 升级模型”的动作。

主线 07 · Cross-stage Joint Optimization

Independent Stages → Teacher Alignment → Joint Fusion → Shared State + Stage-local Executors

上一阶段：PTDG/MORE 改善 task-aware backbone；UniRec 让 pre-ranking/ranking fusion 进入同一训练图，证明 train-joint / serve-stage-locally 更现实。

9/15 的新补充：MIMA 明确 recall-side candidate ownership；Generative Verifier 占据 recall→pre-rank 边界；ChronicleRec 提供可跨 candidate 复用的 user state；OneLA 降低 generative path 的 runtime cost。它们共同说明跨阶段统一不一定来自“一个大模型”，而来自统一的 state / supervision / verification contract。

下一阶段：每个 stage 除 score 外，还输出 confidence、margin、evidence、state version、cost 与 failure reason，让 controller 决定下一 stage、预算和是否回退。

主线 08 · RL / Preference Alignment

Final Reward → Process Credit → Explore-vs-Execute → Structured Credit Assignment

上一阶段：SelfDR、SAM-D2Q、IGPO、RobustSGPO 把优化对象从最终输出扩展到 index/workflow；SAFARI 学习何时探索、何时执行。

9/15 的关联：MIMA 虽不是 RL，却再次验证“credit assignment 决定 specialization”。在推荐 / Agent / MoE 中，很多 collapse 可能不是 capacity 不足，而是多个 latent actor 收到相同或错位梯度。

下一阶段：把 group-relative / assignment / counterfactual credit 用到 multi-interest、multi-agent、multi-stage pipeline：明确某次最终收益应归因于哪个召回源、哪个 expert、哪段历史与哪次 exploration。

主线 09 · Agentic Search / Model Routing

Prompt Agent → Dynamic Horizon → Gated Execution State → Search/Verify/Stop Controller

上一阶段：GeneralQPP 判断 evidence sufficiency；VikingRAG 复用 retrieval trace；Fugu 做多模型 orchestration；Gated-Memory Routing 学习 compact state；SAFARI 学习 exploration value。

9/15 的连接：Retriever + Verifier 结构给 Agentic Search 一个更便宜的中间动作：不是直接升级到多轮 Agent，而是先用 verifier 判断候选是否值得继续。Chronicle-style cache 也可成为长期 agent memory 的结构化 state。

下一阶段：controller 输出 retrieval depth、verify-K、reranker、model、tool、state read/write、halt 的执行计划，并联合优化质量、P95 和 cost-per-successful-task。

主线 10 · Runtime Harness / Self-improving System

Static Prompt → Versioned Harness → Failure Attribution → Verifiable Code/Kernel Evolution

上一阶段：Ecdysis 说明一次 bad case 不该直接修改全局 harness，应先跨实例聚类失败再变更。

9/15 推进：ForgeMegakernel 将同样思想带到更底层：coding agent 负责生成优化实现，但独立 mid-state oracle 负责 correctness。系统自改进的关键不再是“Agent 会写代码”，而是生成与验证必须分权。

下一阶段：failure clustering → specification → agent-generated change → mid-state/unit/regression oracle → shadow → canary/A-B → rollback，覆盖 prompt、retrieval policy、CUDA kernel 与 serving config。

当前年度精读顺序：推荐召回：MIMA → Generative Verifier；长序列：ChronicleRec → DRIFT；生成式推荐：EPIC / TGR → OneLA；跨阶段：PTDG → MORE → UniRec；检索/Agent：GeneralQPP → VikingRAG → SAFARI → Gated-Memory Routing；Serving：DoPR/ReST → KVShareArena → OneLA → vLLM adaptive verification → ForgeMegakernel。
