Rolling 12-Month Review · 更新至 2026.09.24

过去一年真正的主线：从“统一模型”走向“共享状态 + 专家执行路径 + 学习型控制器”

过去一年推荐 / 搜索与 LLM 系统的共同变化，不是所有 stage 都被一个大模型吞掉，而是 representation、state、objective、measurement 越来越共享，execution path 却越来越专业化。Semantic ID 让对象可生成；Generative Retrieval 把价值目标前移；Foundation Model 统一表征；Reasoning / Re-ranking 处理集合约束；Agentic Search 学会主动获取证据；Serving 开始按 KV、precision、prefill/decode 与 hardware 拆分；Model Routing 则逐渐升级为全局 execution-policy learning。

年度总判断：下一代工业 AI / 推荐系统更像 Shared Representation + Multi-timescale State + Specialist Executors + Learned Controller + Counterfactual Measurement + Architecture-aware Runtime。Controller 的 action 不再只是“选哪个模型”，而是 {retrieval source, candidate budget, feature regime, context view, reasoning depth, precision, KV owner, draft policy, expert set, hardware cell, halt}。9 月 23–24 日的新工作进一步证明：统一的是系统语义，不是执行方式。
主线 01 · Generative Retrieval

Semantic ID → Value-aware Generation → Objective-specific Policy → Retrieval / Ranking Shared Representation

上一阶段解决了什么：TIGER / RQ-VAE 类工作让 item 拥有 decoder 可生成地址；OneRec / OneSearch 把业务价值前移；VARG / UniPolicy 等让生成策略感知 downstream objective。

留下什么问题：生成式召回与精排 target-aware supervision 仍可能表示不一致；层次化 residual code 容易积累 quantization error，catalog 增量又会制造 namespace drift。

关键推进：UNIQUE 用 flat quantization + early-fusion representation 同时支持 generative retrieval 与 target-aware ranking，说明“共享表示、保留不同 execution semantics”比强制单 stage 更现实。

下一篇关键工作应该解决：versioned codebook、incremental assignment、generation/dense/sparse/graph 多源候选统一 accounting，以及 retrieval loss 与 ranking/business loss 的动态权重。

主线 02 · Semantic ID

Hierarchical Code → Balanced Namespace → Behaviour-grounded ID → Versioned Address Layer

上一阶段：RQ-VAE 将连续 item 表示离散成层次 code；后续工作改善 code utilization、prefix semantics 与 value-aware address。

留下问题：Semantic ID 一旦进入线上 retrieval / rerank，就必须面对 cold item、长期漂移、code collision、跨版本兼容以及行为统计的偏差。

9/23–9/24 的推进：UNIQUE 强调 flat balanced code；Spotify Robust Fusion 则把 Semantic ID 与 query-item-country 行为成功率一起交给 LLM reranker，并通过 feature dropout 让 SID 在行为特征缺失时承担更大泛化责任。

下一阶段：Semantic ID 不应只是 item token，而应成为 可版本化、带置信度、行为校准且可跨 stage 共享的 address layer。

主线 03 · Scaling / Serving

Kernel / KV → Speculative Decode → State Ownership → Phase-specialized Execution

上一阶段解决了什么：FlashAttention、Paged KV、continuous batching、speculative decoding 把固定模型的效率做到更高；随后 sparse attention、mHC、quantization、draft/target contract 让 runtime 必须理解模型结构。

9/23 的转折：H-Spec 直接重写 drafter 的 KV ownership；Expert Coactivation 把 DRAM→NPU 专家搬运写进 router 训练目标。

9/24 的继续推进：Flash-dLLM 联合优化 cache 与 verify；HySparse2 让 prefill 提前退出并两级共享 KV；Disaggregated Quantization 明确让 prefill / decode 使用不同 precision、weights 与 storage placement。

下一阶段：Serving scheduler 应直接优化 {prefill path, decode path, precision, KV owner, cache refresh, draft strategy, expert set, batch class, GPU/NPU cell}，并让训练 loss 感知真实 hardware telemetry。

主线 04 · Foundation Model

Feature Interaction → Long-sequence Transformer → Foundation Ranker → Multi-timescale State + Missing-feature Robustness

上一阶段：DIN/DIEN、DCN、MMoE/PLE 到 HSTU/SORT/OneTrans，推荐模型不断扩大行为上下文与跨任务共享范围。

问题：长期偏好、session intent、实时反馈、自然语言 taste、行为统计的更新频率完全不同；把所有状态每次都放进 context 不可持续。

关键推进：MuSeR 用异步 multi-interest state 把 10⁴–10⁵ 行为移出请求关键路径；Spotify 进一步说明强行为统计需要显式训练 missing-feature regime。

下一阶段：Foundation Ranker 应原生消费多时间尺度 state，并为每类 state 建立 TTL、freshness、confidence、fallback 与 attribution；model input 不再只是“features”，而是 versioned state contract。

主线 05 · RL / Preference Alignment

Static Reward → Preference Optimization → On-policy Learning → Deployment-distribution Alignment

上一阶段：DPO/GRPO 与 on-policy distillation 把监督从静态 label 推向 policy trajectory；RAVEL 等工作用 downstream retrieval / answer utility 训练 clarification policy。

新的关键问题：模型上线后观察到的是自己策略诱导的状态分布，teacher-forcing 与真实部署 prefix 持续失配。

9/24 的推进：Train Where the Quantized Model Goes 证明这一点甚至会被量化误差放大：QAD 在固定 prefix 上很好，但长 reasoning rollout 会进入完全不同的错误区域；OPD 让 full-precision teacher 到 student 自己的 prefix 上纠偏。

下一阶段：将 retrieval error、tool error、quantization error 与 recommendation exposure bias 统一看成 deployment-distribution shift，用 off-policy logs + on-policy correction 共同训练。

主线 06 · Reasoning / Re-ranking

Cross-Encoder → Listwise / Set-wise → Multi-trajectory Reasoning → Learned Search Policy

上一阶段解决了什么：cross-encoder 建模 pair relevance；listwise / generative reranker 建模候选间关系；MERIT-Rank、MSS-Complement 等让目标从单条相关性提升到多轨迹、集合 sufficiency。

9/23 的推进：Answer-Oriented Context Construction 把最终目标改成 support → trust → organization，即“为正确回答构造上下文”。

9/24 的推进：Beyond Repeated Sampling 更进一步：不再把 test-time compute 用在近重复采样，而是训练小模型先生成概念 / 策略，成为大模型可复用的 semantic-level search policy。

下一阶段：reasoning rerank 将与 model routing 合流：controller 决定候选集合、evidence source、reasoning depth、verification budget 和 early exit。

主线 07 · Full-stack Generative Rec

Stage-wise Models → Generative Candidate → Shared Policy → Heterogeneous Stage-collapsing

上一阶段：生成式推荐试图用单 decoder 统一 recall/rank；工业实践随后发现库存规模、SLA、业务隔离与回滚要求使不同 executor 仍有价值。

关键转折：Hybrid GPU–CPU Retrieval 证明 inventory/hardware path 应共存；UNIQUE 证明 retrieval/ranking 可以共享表示；Spotify 则证明 behavioral feature availability 本身也是 execution regime。

下一阶段：全链路统一不再以“一个模型”为 KPI，而应看 shared state coverage、objective consistency、source attribution、candidate accounting 与 controller quality。request-level 可以 collapse stage，但 system-level 保留多 specialist。

主线 08 · Agentic Search / Context Ranking

Fixed Query → Adaptive Retrieval → Evidence Construction → Organization-scale Agent System

上一阶段：source routing / retrieval budget、clarification、abstention、support/trust/context packing 逐步让搜索从固定 DAG 变成 stateful policy。

9/24 的推进：Agensh 把 scaling axis 从 context/token 扩展到 agent count，去掉中央 orchestrator，让 worker 在 shared workspace / message / context 上自组织。它提醒我们：Agentic Search 的真正上限可能受 coordination protocol 而非单模型能力约束。

下一阶段：需要用 parallel efficiency、duplicate work、merge conflicts、tool cost 与 answer utility 联合度量；组织规模不应只追求更多 agents。

主线 09 · Model Routing

Small-vs-Large Router → Cost/Latency Router → Execution-plan Controller

上一阶段：router 主要决定模型大小；随后扩到 retrieval path、attention mode、precision、draft model、GPU cell。

9/24 的新边界：Learned Search Policy 说明小模型可以只负责“往哪里探索”；DQ 说明 controller 可以选 phase-specific precision；Spotify 说明 feature availability 也应成为 routing state；HySparse2 说明 KV owner / prefill exit 也可被架构化。

下一阶段：router 不再输出 model_id，而输出 execution plan：{state view, retrieval source, candidate budget, model, precision, context budget, reasoning policy, cache plan, verifier, halt}。

Cross-cutting · Measurement

Offline Metric → Online A/B → Counterfactual Observability → Trajectory-level Correctness

Netflix Counterfactual Observability 强调 raw engagement 不能直接解释模型增量；Spotify 的 feature-missing slice 强调 aggregate A/B 会掩盖 regime 差异；9/24 的 precision divergence 与 OPD 又说明静态离线 loss 不足以刻画 trajectory failure。

下一阶段测量体系：同时记录 source / stage provenance、feature availability、precision/kernel/batch regime、trajectory failure type、propensity 与 online incrementality。没有这种 observability，复杂 controller 很难可靠优化。

2026 Q4 · 值得押注

如果只选 6 个研究问题继续追

  1. Generative Retrieval 的 versioned Semantic ID：增量 catalog、code drift、跨 stage 兼容。
  2. LLM Rerank 的行为证据鲁棒性：feature uncertainty / propensity correction / cold-start fallback。
  3. Shared State + Specialist Executor：长行为、RAG memory、agent context 的统一 state-store 抽象。
  4. Learned Execution Policy：统一 retrieval source、candidate budget、model、reasoning、precision 与 halt。
  5. Training-aware Serving：让 router / quantization / KV architecture 直接感知 hardware cost。
  6. Counterfactual + Trajectory Measurement：把“模型效果”拆成真实增量、路径稳定性与系统成本。
