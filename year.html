过去一年，推荐 / 搜索真正发生了什么？

如果把过去一年的工作连起来，主线不是“LLM 替代所有推荐模块”，而是系统边界重新划分：Item 从 Random ID → Semantic ID → Fresh / Constraint-aware / Long-tail-aware Namespace；User 从单向量 → 长序列 → 多兴趣集合 → Context State；Retrieval 从固定 ANN → Generative / Agentic Retrieval；Ranking 从 pointwise feature fusion → context/slate-aware unified modeling；Serving 从固定 graph → request / phase / prefix / model / device 的动态预算；Agent 从回答问题 → 搜索证据 → 长期记忆 → 生产控制面。9 月 5 日的新进展又把这条线向前推了一步：UniCon 重定义 ranking 的建模单元，DoPR 重定义 reranking 的 offline/online 边界，EPIC/HypRQ-VAE 重定义 Semantic ID 的 item-level decision 与 geometry。

年度总判断：下一阶段最有价值的研究不会只是“把 backbone 再变大”，而是回答五个系统问题：什么是正确的状态单位？什么信息应该离线资产化？什么决策需要 item/list-level 而不是 token-level？什么请求值得多花算力？反馈如何跨 retrieval/ranking/serving 闭环？
主线 01 · Generative Retrieval

Next-item Generation → Semantic Namespace → Intent / Constraint / Item-aware Generation

上一阶段解决了什么：TIGER、OneRec、Sona 等把 retrieval 从“向量搜邻居”改写为“生成 item 的离散标识”，让一个 sequence model 同时承载用户状态与候选生成；ICEGR 又把 query intent 贯穿 SID、SFT、preference 与 beam serving，证明生成式召回可以接真实电商 A/B。

留下的问题：token-level next-code likelihood 并不等于 item-level preference；partial SID 在解码早期可能对应大量完整 item，promising item hypothesis 会因为局部 token 决策提前死亡。与此同时，catalogue 的长尾与业务约束没有自然体现在 Euclidean codebook 中。

下一篇关键工作如何推进：EPIC 在 denoising 每一步显式构造完整 item posterior，再 marginalize 回未决 SID 位；四个 Amazon benchmark 的 16 个 metric×dataset 组合均取得最佳均值，证明 item-level competition 应前移到生成轨迹内部。HypRQ-VAE 则从 namespace geometry 入手，用 hyperbolic space 对齐 power-law catalogue。

下一阶段：Generative Retrieval = Namespace Geometry × Item Posterior × Intent/Constraint × Freshness × Serving Budget。真正值得押注的是这些组件如何共同训练，而不是再做一个孤立的 SID tokenizer。

主线 02 · Semantic ID

RQ-VAE → Query/Domain-aware SID → Hyperbolic / Dynamic / Posterior-aware SID

上一阶段解决了什么：Semantic ID 将随机 item ID 变成可共享前缀的离散语义结构；Tlow 改善 quantization geometry，TAGR 处理 live remapping，ICEGR 把 query intent 注入 SID，SPAR 将地理 topology 写进 POI namespace，TAAL 指出 early-prefix survival 是 decoder bottleneck。

留下的问题：Euclidean codebook 往往偏向 head item；collision、long-tail fidelity、online insertion 与 namespace versioning 仍是大规模生产难题。更重要的是，“SID 是什么”与“解码时怎么理解 partial SID”长期分开优化。

关键推进：HypRQ-VAE 用负曲率空间的指数体积扩张承载 power-law catalog，并以 cascading reassignment 解决 collision；MovieLens tail Hit@10 相对 Euclidean TIGER 提升超过 52%。EPIC 则让 partial SID 对应的 feasible complete items 在每步 denoising 中直接竞争。

下一阶段：需要把 hyperbolic / domain-aware codebook、online remapping、item posterior、inventory/price/location constraints、prefix survival 放进同一个 namespace contract。

主线 03 · Scaling / Serving

Kernel Optimization → Runtime Contract → Reusable State / Dynamic Compute

上一阶段解决了什么：FlashPrefill、HyQuant、H-Scale、vLLM/SGLang/TensorRT-LLM 把 prefill/decode、precision、KV、CUDA Graph、speculative decoding 等执行路径显式化；Declarative Attention 更进一步让模型自己声明 global/focus/local attention scope。

留下的问题：很多高成本计算并非“每次请求都必须重做”。Search/RAG 尤其存在大量静态文档被不同 query 重复编码；embedding、reranking、LLM 又常被当成三套服务，导致 tokenizer/scheduler/kernel/runtime 重复建设。

关键推进：DoPR 将 query-independent document representation 压成 multi-layer prefix states，离线预计算后跨 query 复用；最高 8× document-state reduction、8.04× latency speedup，并保留 97.1%–99.5% 平均 NDCG@10。Perplexity 的 GPU Embedding Serving 又从工程侧证明 embedding 与 LLM 可共用 kernel、CUDA Graph、scheduler 与 Rust/Python runtime。

下一阶段：Serving 优化的对象会从 kernel 扩展为 offline/online boundary、reusable prefix/state、cache lifecycle、request × phase × dtype × model × device routing。

主线 04 · Foundation Model / Unified Ranking

Feature Fusion → Shared Backbone → Context-centric Shared State

上一阶段解决了什么：OneModel、MaskRec、OneTrans、HyFormer、RankMixer 等减少手工 feature cross，把行为序列与 ranking features 放进统一 backbone；CAMIE 等工作说明监督结构往往比单纯换模型家族更关键。

留下的问题：“序列 vs 非序列”仍是 feature-engineering 遗产。真实决策发生在一个展示 context 内：用户点击某 item 的意义取决于同时出现的竞争项、位置、query 与环境；flat token fusion 不会自动理解 impression boundary。

关键推进：UniCon 将一次 exposure/request 定义为 context unit，intra-context attention 学 Locality，inter-context attention 学 Dynamics，并让历史 context 与 target latent context 结构同构。Meituan 搜索广告离线 AUC +0.0139；7 天 20% 流量 A/B：RPM +3.09%、CTR +2.07%、Revenue +2.95%。context compression 将 0.33B 模型计算从 801.29 降到 197.14 GFLOPs，AUC 仅损失 0.0001。

下一阶段：Foundation Ranking Model 更可能是 shared context/slate state + task-specific heads + adaptive compute，而不是把所有 field/token 塞进一个更大的 Transformer。

主线 05 · RL / Preference Alignment

Final Outcome Reward → Process Credit → Reasoning-as-Teacher

上一阶段解决了什么：ICEGR RCPO 用 relevance guard 包住 click/pay/GMV preference；PAO 在 frozen index 上只做 positive-advantage updates；PRO-Step 将 RAG reward 从最终答案下沉到 logical validity + evidence grounding 的 step-level credit。

留下的问题：Process reward 能提高 reasoning，但如果生产系统每次都输出完整 reasoning trace，在线 token/latency 成本太高。推荐尤其是高 QPS 场景，需要把“学习时的慢思考”与“Serving 时的快决策”解耦。

关键推进：SelfDR 用同一 base LLM 训练 reasoner → reasoning-enhanced teacher → direct student，reverse-KL + dynamic weighting 将 teacher posterior 蒸馏到不看 rationale 的学生。Clothing inference 仅 1 output token、109.46ms，接近无 reasoning SOFT 的 109.48ms，而多种 reasoning baseline 为 250–665ms。

下一阶段：Process RL for learning + Distillation for serving + Router for hard cases 会比“全量 CoT”更接近生产最优解。

主线 06 · Reasoning / Re-ranking

Full Cross-encoder → Evidence Navigation → Reusable Document State

上一阶段解决了什么：GAREN 将 reasoning retrieval 的下一步从单 document neighbor 提升到 semantic group；PRO-Step 给每个 retrieval/reasoning step 过程 credit；传统 Qwen3-Rerank/RankLLaMA 等则证明 LLM cross-encoder quality 强但成本高。

留下的问题：pointwise reranking 会反复编码同一个 document；简单 embedding cache 又损失 cross-encoder 的深层交互。效率优化不能只靠小模型/量化，还要识别什么计算可以跨 query 摊销。

关键推进：DoPR 训练 document representation bottleneck，将 selected doc states 转成可复用 prefix；online 只跑 query + score token。它把 reranking 的研究问题从“哪个 scorer 更准”推进到“哪部分 scorer state 可以离线资产化”。

下一阶段：值得研究 query-adaptive prefix budget、quantized prefix、listwise prefix reuse、hot/cold prefix cache、reranker routing，并直接优化 NDCG / p99 / storage TCO 的联合 Pareto。

主线 07 · Full-stack Generative Rec

One Model → Shared Namespace → Cross-stage Contract → Production Control Loop

上一阶段解决了什么：ICEGR 展示 SID → query SFT → preference → beam serving → online insertion 的完整闭环；SPAR 证明 domain knowledge 需要从 tokenizer/CPT/SFT 全链路保留；CORAL 把 retrieval budget 与 Serving treatment 纳入 LLM-native live experiment control plane。

留下的问题：生成式推荐仍常把 namespace、decoder、rerank、runtime 作为分开的论文问题。EPIC 显示 decoder 必须理解 complete item；HypRQ-VAE 显示 namespace geometry 会系统性影响 tail；SelfDR 显示 reasoning policy 又影响 Serving cost。

关键推进：2026-09-05 的三篇工作形成清晰承接：HypRQ-VAE 解决“item 如何编码” → EPIC 解决“partial code 如何保住 item hypothesis” → SelfDR 解决“复杂推理如何不把在线成本带上去”。

下一阶段：真正的 Full-stack Generative Rec 应统一 catalogue topology、user/context state、item posterior、preference reward、adaptive decoding、Serving budget 与 online experiment。

主线 08 · Agentic Search / Context Ranking

Query Rewrite → Trajectory Search → Structural Navigation / Active Memory

上一阶段解决了什么：ITER 将历史 sub-query/visited docs 写入 retriever state；GAREN 学 group-level evidence direction；Persistent Discovery Context 保存 intent→successful object 映射；Declarative Attention 让 reader 自己选择 context scope。

留下的问题：Agent memory 与 retrieval 大多仍依赖 surface similarity；大型 evidence space 的 citation/category/topology 结构没有被当作可操作 action，长轨迹又容易 context exhaustion。

关键推进：SciLENS 在 12M 本地论文索引上将 citation graph traversal 与 visualization 直接变成 tools/actions，并用 rubric RL 奖励 planning 与 evidence grounding；RuleMem 从历史诱导可验证 Horn rules，让 rule body 主动改写事实检索，Guided Recall 平均 0.56→0.79。

下一阶段：Agentic Search 会从“retrieve text”走向 retrieve/induce structure → choose source/group/rule → allocate context → verify → stop。推荐中的类目图、兴趣图、候选源与 slate context 都可以映射到同一个范式。

主线 09 · Model Routing

Fixed Model → Fast/Slow Path → Worker / Context / Device / State Routing

上一阶段解决了什么：Switchyard、AdaWidth、DS-Frame 将请求按价值路由到不同模型/宽度/深度；SetMIR 在 interest 级决定是否发 ANN；Spotify Shunt 将 bulk read/boilerplate 分流到廉价 worker；NVIDIA PAIR 将独立推理请求路由到不同 GPU node。

留下的问题：router action space 正快速膨胀，但 routing signal 仍分散。今天 UniCon 的 context compression、DoPR 的 Kinfer、SelfDR 的 reasoning/direct path 都实际上提供了新的“可路由维度”。

关键推进：DoPR 允许不重训直接改变 inference prefix budget；SelfDR 说明普通请求可 direct serve、hard request 才需要 reasoning teacher/slow path；Perplexity 则在 runtime 层根据 batch/token shape 选择执行策略。

下一阶段：统一 router 的 action space 会是 source / interest / candidate depth / context keep ratio / prefix budget / model / reasoning depth / precision / device，目标函数应直接是 marginal utility per GPU-ms / dollar。

主线 10 · 推荐链路统一

Stage-local Optimization → Shared Context / State / Cost Contract

上一阶段解决了什么：传统召回、粗排、精排、重排各自优化；近一年开始出现 shared representation、generative retrieval、adaptive reranking 与 control plane。

留下的问题：同一 request 的 intent、context、cost constraint 在不同 stage 被反复重建；召回不知道 downstream reasoning cost，精排不知道 candidate source budget，rerank 又重新编码 document/item。

关键推进：UniCon 证明 context/slate structure 对精排直接有效；DoPR 证明 rerank state 可以跨 query 复用；CORAL/SetMIR/Declarative Attention 证明 budget 可以被 model/agent 控制。它们共同指向 Shared State + Shared Budget + Shared Feedback。

下一阶段：跨阶段统一不必是“一模型吞掉所有 stage”，更现实的是建立可复用的 user/context state、item/document state、namespace、cost signal、experiment feedback，各 stage 在共同 contract 上做 specialization。

未来 6–12 个月最值得押注：Context/Slate Foundation Ranking、Reusable Reranking State、Long-tail + Fresh Semantic ID、Item-level Generative Posterior、Reasoning Distillation、Unified Budget Router、Agentic Control Plane。这些方向共同回答一个问题：怎样用结构化 state 和预算控制，让质量提升不再等价于“每次请求都多算一遍”。
