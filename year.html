过去一年，推荐系统真正发生了什么？

主线已经从“模型更大”转成 Generative / Foundation Model + Structured Supervision + 可版本化 AI Asset + Continual Co-adaptation + Runtime Policy。8 月下旬的新信号进一步说明：Semantic ID 不只是生成输出，也可反向监督 Dense Retrieval；LLM 能力不只需要蒸馏一次，而要按漂移与价值持续更新；复杂模型的收益也必须先通过 Benchmark Capacity Probe。

年度总判断：Item 变 Token，SID 进一步变成 Reward / Hard-negative / DPO 接口；内容变 Foundation Embedding；Ranker 变跨业务 Foundation；Reasoning 变 Cache/Memory；Retriever 与 Reranker 变持续协同系统；Tool Schema 变 KV Asset；Serving 变 Dynamic Compute / Fleet Decision；Evaluation 从单一离线分数走向 End-state Reliability 与 Benchmark Validity。2026 下半年最值得押注的问题收敛到 Hybrid Dense×Semantic-ID Retrieval、Unified Ranking Foundation、Continual Retriever–Reranker Learning、Reliable GenRetrieval、Agent Workflow Governance、AI Asset Versioning、Benchmark Audit 与 Cost-aware Runtime Routing。
主线 01 · Generative Retrieval / Semantic ID

Two-Tower + ANN → Item-as-Token → Semantic ID 反向监督 Dense Retrieval

上一阶段解决了什么：OneRec-V2、JD GenRec 把候选生成改写为 Item Token 自回归生成；FSGR / DrIG 开始处理 SID frequency、coverage 与 identifier reliability；SIDScope 则把 Tokenizer→Mapping→Generator 当成需要独立审计的系统接口。

留下的问题：纯生成式 Retrieval 仍面临 Beam Cost、Prefix Error、Fresh Item Assignment、Coverage 与索引迁移成本；而纯 Dense ANN 又缺少离散层级结构对 Hard Negative 与 Reward 的显式监督。

2026-08-22 关键推进：SSR-GRPO 不再把 Dense 与 Generative Retrieval 当成二选一。Contrastive RQ-VAE 学 Item SID，Query 生成 SID；SID prefix 与 dense relevance 一起构成 GRPO Reward，并用于 fine-grained hard negative、mask 和 Retrieval-DPO。最终线上仍走 Dense ANN。Tmall 两周 A/B：UCTCVR +0.99%、GMV +1.40%。

下一阶段：SID 会成为跨范式控制接口：用于 retrieval reward、index bucket、hard-negative curriculum、coverage audit、fresh-item routing，再与 Dense ANN / Generative path 做 query-aware hybrid routing；同时需要 SID uncertainty、version churn 与 freshness health check。

  • SSR-GRPO · OneRec-V2 · JD GenRec · Sona
  • FSGR · DrIG · SIDScope
主线 02 · Unified Ranking Foundation

单场景 Ranker → Long-sequence Ranker → 跨业务 Shared Foundation

上一阶段：RankMixer、OneRank、TM20K、Adaptive Ranking、UniDot 推动 Ranking 从浅层 Feature Interaction 进入 Transformer-native、长序列、Request-aware Compute 与 Sequence/Interaction Unified。

关键推进：OneModel 把小红书 Organic Recommendation、Feed Ads、Merchant Recommendation 的异构行为映射成统一 Event Sequence，以 action-oriented long-context backbone 学共享 User State，用 Scenario-aware Information Modulation 保留业务特化。统一训练中 Ads Click AUC 0.7682→0.7712、Merchant 同样 +3.0‰，高资源推荐流基本不退化。

生产闭环：User State 增量更新并缓存到低延迟 KV Store，请求时只做 vectorized candidate scoring；线上 Explore Feed Time Spent +0.33%、Engagement +1.25%，Feed Ads 广告价值 +3.43%、CTR +8.18%，Merchant DGMV +1.1867%、GPM +2.1585%。

下一阶段：Foundation Ranking 的核心资产是共享 Event Schema、User State、Content Representation、训练预算与 Serving Graph。值得押注 Dynamic Scenario Router、Conflict/Uncertainty Detection，以及让统一 User State 跨 Retrieval / Ranking / Re-ranking 复用。

  • OneModel · RankMixer · OneRank · UniDot
主线 03 · Personalized Retrieval / Collaborative Index

Implicit History Fusion → Explicit Intent Reasoning → Semantic Query + Collaborative Index

过去：个性化 Search/Retrieval 通常把 User History 当额外 Embedding，与 Query 做隐式交互；LLM Retriever 又常只是把大模型当静态 Encoder。

Think-to-Personalize：LLM 基于购买历史显式生成 latent intent / rewritten query，再形成 Dense Embedding；SFT → GRPO，Reward 直接包含 Retrieval Utility。线上采用 T+1 personalized cache + 305M Student，额外延迟 +0.15ms，Order +0.46%。

CoRRe 的补充：另一条路线是不让 LLM 承担协同建模：LLM 只生成 User Semantic Profile，Item Embedding 再通过 co-purchase graph 做方向修正、Popularity 做模长校准，最终仍走 ANN。它把 User Semantic 与 Collaborative Index Geometry 解耦，便于离线物化与版本管理。

下一阶段：Reasoning Cache Freshness、Teacher→Student Transfer、Intent Uncertainty、Collaborative Index Calibration 与 Multi-turn Incremental Personalization 会汇合；Router 决定哪些 Query 值得 reasoning、哪些只需要廉价 dense lookup。

  • Think-to-Personalize · CoRRe · CoRRe Code · TTT-Embed · GEM
主线 04 · Multimodal / Foundation Embedding

多模态 Feature → Versioned Embedding Platform → Production Personalization

过去：多模态经常停留在 CLIP/LLM embedding concatenate；Foundation Model 效果与下游 Serving 被分开讨论。

Netflix 的转折：CLIP / MediaFM 表示经过 Embedding Store 版本化存储，支持 backfill / rollback，再做 Item Projection Cache 和 daily materialization；大模型不进入 hot request path。线上统一 Canvas + CLIP 的 discovery metric +0.127%，query-aware artwork search playthrough +0.36%。

下一阶段：推荐 Foundation Model 的第一产品形态可能是稳定的 Embedding API / Store，而不是端到端超大在线模型。Embedding Stability、Cross-version Compatibility、Cold-start Uncertainty 与 downstream calibration 会成为基础设施指标；CoRRe 进一步提示协同图也可作为 Embedding Store 的后处理层。

  • Netflix Multimodal Asset Personalization · CoRRe
主线 05 · Scaling / Serving / Model Routing

Dense Full Compute → Elastic Operating Point → Runtime / Fleet Decision

Netflix Scaling、TM20K、SilverTorch、Tevatron-Elastic 已把 Sequence Length、Model Granularity、GPU Graph、HBM 与 Prefill Cost 拉进模型设计。

FlashPrefill V2：Block-sparse Attention 走向 Serving Backend：支持 FP8、Paged KV、Continuous Batching 并接入 SGLang；128K 下端到端 TTFT 最多 4.8×。

Adaptive Edge RAG：Context Compression 不应是固定 Ratio；中等压缩最多降低 53.2% GPU energy、48.2% SoC energy，压缩率应由 Query + Device Telemetry 动态决定。

2026-08-22 新推进：ReCache 将动态 Tool/Skill Schema 拆成 composition-invariant Resource KV blocks，Invocation F1 82.3% vs Dense 82.4%，TTFT 3.655×、KV tensor memory -92.43%；FleetSieve 则把 profiling 目标从“测准全部 TP×Load 曲面”改成“只测会改变最终 SLO / GPU allocation 的配置”，在固定比较中减少 6.9% profiling GPU-seconds。

下一阶段：统一 Router 根据 Utility、Latency、Context、Freshness、GPU/Device State、Resource Cache Hit、SLO 与业务价值决定 Retriever、Top-K、Compression、Attention Density、Precision、Model Depth、Tool/Skill KV 与 Fleet Placement。

  • FlashPrefill V2 · ReCache · ReCache Code · FleetSieve · Tevatron-Elastic · SilverTorch
主线 06 · Ranking Intent / Uncertainty / Allocation

Feature + Label → Noise / Intent / Request Value / Traffic Consequence

DrEM 把上游 pxtr noise 当一等变量；GateDiffInt 用 conversion signal 同时约束 diffusion 去噪与 LLM 长期/短期/潜在/转化意图蒸馏，并在数亿 DAU Ranking 场景进入主流量；Impression Share Prediction 则把“模型上线后会如何重新分配曝光”纳入评估。

下一阶段：Ranker 输入会从 Feature + Label 扩展为 Feature + Intent + Uncertainty + Request Value + Compute Budget + Allocation Consequence，并与 OneModel 一类跨业务 Foundation 汇合。

  • DrEM · GateDiffInt · Impression Share Prediction
主线 07 · Lifecycle / Freshness

Recency Feature → Learnable Eligibility → Lifecycle-aware Ranking

Google Discover SDF 将 Staleness 拆成 Supersession 与 Intrinsic Relevance Decay，在 Request Path 外产生可缓存 Eligibility Signal；长期 staleness report 约 -54.9%，同时减少 CPU/TPU hours。

下一阶段：Freshness、Quality、Inventory、Safety、Dedup、Policy 会组成独立 Eligibility Layer，并从 hard filter 继续走向 uncertainty-aware soft eligibility；同样的 freshness contract 也会延伸到 SID、Embedding、Intent Memory 与 Tool KV Asset。

  • Decomposing Staleness / SDF
主线 08 · Reasoning / Experience Memory

每次重新 CoT → Distilled Memory → Utility-audited Skill Store

rEDMRec：把 Teacher reasoning 拆成长期偏好、短期上下文、Item perception 与 counterfactual hard-negative experience，让轻量 Student 在线只检索 Memory。

Skill Audit：Break It Down, Pass It On 证明 Experience 并非越多越好：task-level skill 多数导致负迁移，subtask-level skill 平均更有效，文本技能优于代码技能。

下一阶段：Memory Router 需要同时看 relevance、utility、confidence、freshness、provenance 与 privacy deletion；并与 SCoRD 的 Dynamic Intent Memory 合流，形成可持续更新而不是静态积累的 memory lifecycle。

  • rEDMRec · Break It Down, Pass It On · SCoRD
主线 09 · Agentic Search / Workflow Governance

Tool Agent → Search / Experiment Agent → Workflow-governed Control Plane

PILOT：推荐 Agent 从建议生成上移到受权限、安全和统计服务约束的线上实验控制环。PolicyGuide 将组织政策编译成 Workflow Graph，在每个用户轮次根据持久 Graph State 检查 open requests。

2026-08-22 搜索评测推进：BrowseComp-Plus 投影到与 benchmark 无关的 ClimbMix 553M-document corpus 后，最强 Agent 的 evidence recall 从 84.3% 降至 21.4%，Search Calls +63%，而 Answer Accuracy 只降约 5 points。这说明最终答案可能掩盖脆弱的 Retrieval / Evidence Chain。

下一阶段：Agentic Search / Context Ranking 必须分离 Retriever、Planner、Reader 与 Tool Router 评测；Experiment Agent 还要维护审批、流量、统计显著性、回滚和归档等跨轮次 Workflow State。

  • BrowseComp-Plus → ClimbMix · CMASS Code · PILOT · PolicyGuide
主线 10 · Agent Training / Reliability

Static Benchmark → Adaptive Environment → Stateful Reliability

EnvHarness：在既有 Environment 外加可编程 Harness，让 EnvRigger 根据 Policy Failure 动态合成训练环境，跨五个 benchmark 最多 +9.0 points 且 execution steps -9.8%。

Thinkingbox：MCP-compatible 隔离 Sandbox 检查最终 Backend State 与副作用，507 个业务 Workflow 中最强模型 pass@1 65.36%，但 pass^20 仅 25.25%。

下一阶段：Agent Evaluation 会从 one-shot score 走向 pass^k、state invariant、side-effect audit、policy compliance、evidence recall 与 rollback correctness；训练环境则根据 failure cluster 自动 co-evolve。

  • EnvHarness · Thinkingbox · Thinkingbox Code · BrowseComp-Plus → ClimbMix
主线 11 · RL / Preference Alignment / Continual Distillation

Teacher Imitation → Preference Optimization → Selective Continual Co-adaptation

过去：GC-OPD 处理长上下文 Teacher likelihood 与 verifier reward 的分歧；Open-MOPD 处理多 Teacher token share、learning gap 和 stale reward。

SSR-GRPO：在 Dense Retrieval 中把 SID-based Reward、GRPO 与 Retrieval-DPO 联合起来，并用 uncertainty-based trainable weights 动态平衡高方差 RL 与稳定监督。

SCoRD：进一步把问题从“一次 Teacher→Student”推进到非平稳数据流：只对约 20% low-confidence / hard sequence 调用昂贵 LLM 蒸馏，Semantic Assistant + Dynamic Intent Memory 支持 Retriever 增量学习，再把更新后的 Item Representation / drift signal 回流 Reranker。Books 语义生成 15.4h→1.4h。

下一阶段：训练 Scheduler 会依据 learning gap、gradient conflict、uncertainty、drift、token share、reward freshness 与 online value 自动分配 Teacher / RL / Distillation Budget。

  • SSR-GRPO · SCoRD · GC-OPD · Open-MOPD
主线 12 · Full-stack Generative / Unified Recommendation

统一不是删掉所有 Stage，而是统一资产、状态与策略层

Sona 从模型侧跨 Stage；SilverTorch 从系统侧把 Retrieval/Ranking 收进 GPU-native Model Graph；SDF 建立前置 Eligibility；Netflix 建立 Versioned Embedding Store；SIDScope 建立 Artifact Contract；SSR-GRPO 让 SID 反哺 Dense Retriever；rEDMRec / SCoRD 建立 Editable / Continual Memory；OneModel 建立跨业务 Shared User State；PolicyGuide 建立 Workflow State；ReCache 建立可复用 Tool KV Asset。

2026 下半年最值得押注：一个跨 Retrieval / Ranking / Reasoning / Tool / Eligibility / Experiment 的 Cost-aware Runtime Policy Layer，下面连接可版本化、可审计、可回滚的 Embedding / SID / Memory / User State / Tool KV / Workflow 资产。

主线 13 · Benchmark Validity / Evaluation

复杂模型胜出 → Capacity Probe → 证明“复杂度真的必要”

过去的问题：推荐论文常把 Transformer/LLM 在公开数据集上的小幅提升解释成“学到了更高阶序列结构”，但 benchmark 本身是否包含足够 higher-order dependency 很少被验证。

2026-08-22 关键推进：Spotify Research 的 Sequential Capacity Probes 用不学习高阶 sequence representation 的 PCTM / SeqRules 检验数据集。Beauty、Sports、Toys、MovieLens-1M 上 pairwise probe 都超过 SASRec/eSASRec，只有 MovieLens-20M 保留明显 higher-order gap。

下一阶段：每个长序列项目应先报告 last-item / pairwise / recency probe gap；benchmark 需要公开 higher-order dependency、full-catalog protocol、exposure bias、candidate leakage 与 sampling sensitivity。对 Agentic Search，则应拆分 evidence recall、answer accuracy、search calls 与 end-state correctness。
