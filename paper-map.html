Research Problem Map · 更新至 2026.09.09

不是按年份堆论文，而是沿“核心矛盾”读技术

Paper Map 持续回答：上一种方法解决了什么，为什么还不够，下一篇关键工作到底把矛盾推进到了哪里？今天新增两个系统型问题：GPU custom kernel 的性能与安全能否同时成立？多级 KV / latent cache 如何避免跨 rank 重复并形成可验证状态契约？它们与此前的索引、memory、policy、rerank state 一起指向“可复用状态 + 可验证 runtime”这条主线。

当前推荐精读路线：模型/推荐主线：SAM-D2Q → IGPO → PTDG → Embedding Surgery → AtomRec；系统主线：DoPR / ReST → SGLang HiCache → vLLM NVFP4 contract → cuTile Rust。前者回答“智能写进什么状态”，后者回答“状态怎么高效、安全地活在生产系统里”。
问题 01 · 倒排索引 vocabulary mismatch，但线上又不能跑大模型怎么办？

Doc2Query → Multimodal Expansion → Business-aligned Offline Asset

核心矛盾：keyword search 低延迟、精确匹配强，但 title 覆盖不了用户语言和视觉属性；在线 VLM 又太贵。

承接关系：BM25 / inverted index → Doc2Query → multimodal expansion → SAM-D2Q。

问题 07 · 同一文档为什么对每个 query 都要完整重算？

问题 08 · 可复用状态变多后，谁来管理 cache 的位置、重复和生命周期？

GPU-local KV → Prefix Cache → Multi-tier / Cross-rank State Cache

核心矛盾：把计算变成可复用 state 之后，瓶颈会从 FLOPs 转成容量、搬运、ownership 与一致性；如果每个 TP rank 都保存相同 host cache，reuse 本身也会制造巨大冗余。

承接关系：Paged KV → cache-aware routing / HiCache → MLA host-dedup。

Research Impact Score / 研究价值 8.3/10工业成熟度 ★★★★☆创新性 ★★★★☆与你方向的相关度 ★★★★★是否官方开源 是是否有线上 A/B 否阅读优先级 A+

核心推进：SGLang 只在 source rank 保留主 host cache，通过专用 NCCL group 分 chunk broadcast；同时对 FP4 scale、storage backend 做 eligibility gate，说明真正需要抽象的是 state schema，不是一块裸 buffer。

值得押注：NUMA-aware cache、remote cache、metadata/scale dedup、version/checksum、state-aware router、failure recovery。

问题 09 · FP8/FP4 量化为什么经常“能跑但不稳”？

Quantized Tensor → Quantized Runtime Data Structure → Capability Contract

核心矛盾：低精度收益跨越 model weight、activation、KV cache、router 与 fused kernel；不同 backend 支持矩阵不同，scale/layout 错位会造成 silent regression。

承接关系：weight-only quant → KV quant → backend-aware fusion → vLLM NVFP4 capability contract + FP32 MoE router precision。

问题 11 · Custom GPU Kernel 的性能与安全必须二选一吗？

CUDA C++ Unsafe Surface → GPU DSL → Ownership-aware GPU Programming

核心矛盾：attention / quant / MoE kernel 变化越来越快，raw pointer、异步 launch 与 memory alias 带来的 correctness 成本也越来越高；运行时安全检查又可能损伤性能。

承接关系：CUDA C++ / Triton → CUDA Tile IR → cuTile Rust / cuda-oxide。

代表 Paper：Fearless Concurrency on the GPU。cuTile Rust 通过 mutable tensor 的 disjoint partition、host-device ownership contract 与 tile abstraction，把大量 data race 变成编译期问题；B200 GEMM 报告约 2 PFLOP/s、约 96% cuBLAS，Grout 又跑通 Qwen3 inference。

成熟度：cuTile Rust 已有真实 inference testbed，cuda-oxide 仍 early alpha。

值得押注：Rust/C++/Python interop、safe fusion、自动 launch contract、compiler-assisted communication scheduling、FP4/MoE kernel primitives。

问题 12 · 分布式训练“loss 能算出来”就代表目标正确吗？

Model-local Loss → Parallel Adapter → Verifiable Training Contract

核心矛盾：context parallel / sequence parallel / packing 后，shift、mask、gather、reduction 分散在 model、Trainer 与 adapter；重复或遗漏一步都可能 silent corruption。

承接关系：standard next-token loss → context parallel → Transformers shift_labels contract fix。
