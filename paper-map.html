Research Problem Map · 更新至 2026.09.03

不是按年份堆论文，而是沿“核心矛盾”读技术

今天最值得加进技术树的四个矛盾是：Semantic ID 如何承载业务硬结构？推荐推理如何按样本价值分配算力？Reasoning Retrieval 如何跳出局部文档图的 bounded recall？RAG / ANN 的固定 top-k 与固定复杂度假设还能成立吗？ 它们把研究重心从“更好的 representation”推进到“结构、路由、导航与预算”。

今日推荐精读路线：如果只读 5 篇，按 SPAR → DS-Frame → GAREN → SetMIR → ICEGR。第一篇看 domain structure 如何进入生成式推荐；第二篇看 recommendation conditional compute；第三篇看 evidence-space navigation；第四篇看 variable interest set + ANN dispatch；第五篇看 Generative Retrieval 的 cross-stage intent coherence。做 RAG 再补 ViSAR / PULSAR；做 Serving 再补 NVIDIA speculative-decoding co-design 与 vLLM QSA Split。
问题 01 · Semantic ID 只编码“语义”够吗？

Semantic ID → Query-aware SID → Domain-structured SID

核心矛盾：item 内容相似不代表业务上可互换。POI 受距离/方向/可达性约束；商品受库存/价格/类目约束；广告受 campaign/budget/audience 约束。

承接关系：RQ-VAE / TIGER → Tlow / TAGR → ICEGR Query-aware SID → SPAR SI-SID。

Research Impact Score / 研究价值 9.3/10工业成熟度 ★★★★☆创新性 ★★★★★与你方向的相关度 ★★★★★是否官方开源 论文承诺数据；代码未发现是否有线上 A/B 否阅读优先级 最高

代表 Paper：SPAR。SI-SID 显式融合地理坐标；MG-CPT 学道路/距离/导航；TV-SFT 用 task vector 保存空间知识。四个 AMAP 工业数据集上 8B 相对 PLUM 平均 +38.32%，cold-start Recall@5 在上海/浙江相对 TextOnlyGR +47.6%/+48.0%。

值得押注：constraint-aware codebook、time-dependent SID、inventory/budget-aware SID、domain CPT、namespace versioning、constraint-aware decoding。

问题 02 · 为什么所有推荐请求都要跑同样深度？

Uniform One-pass → Conditional Compute → Learned Fast/Slow Routing

核心矛盾：短历史/主流兴趣通常容易，长历史/低流行 item 更难；统一 heavy inference 浪费算力，统一 light inference 又牺牲 hard cases。

承接关系：Early-exit / MoE / Model Routing → request-aware compute → DS-Frame。

Research Impact Score / 研究价值 8.8/10工业成熟度 ★★★☆☆创新性 ★★★★★与你方向的相关度 ★★★★★是否官方开源 是是否有线上 A/B 否阅读优先级 最高

代表 Paper：Recommender System as Slow and Fast Thinkers。Fast one-pass + Slow K-step latent refinement + cost-aware selector。Beauty/SASRec 上 40.2% slow activation 得到 NDCG@10=0.0453，高于 Slow Only 的 0.0431；normalized cost 1.80× vs 3.00×。

官方代码：GitHub。

值得押注：多级 depth、adaptive halting、uncertainty gate、GPU-batch-aware routing、bandit/RL router、marginal utility per GPU-ms。

问题 03 · Reasoning Retrieval 为什么会在文档图里越爬越窄？

Fixed Pool → Doc-level Graph Expansion → Group-level Evidence Navigation

核心矛盾：相关证据不在首轮 top-k 时，需要扩候选；但逐个 neighbor 评分只看到局部，很容易漂到单一语义区域。

承接关系：Retrieve-and-Rerank → SlideGAR / RGS → GAREN：Leiden group + group summary + small navigator + large reranker。

Research Impact Score / 研究价值 8.9/10工业成熟度 ★★★★☆创新性 ★★★★★与你方向的相关度 ★★★★★是否官方开源 是是否有线上 A/B 否阅读优先级 最高

代表 Paper：GAREN。BRIGHT reasoning rerank 平均 nDCG@10=31.2 vs 最强 baseline 28.9；去掉 navigator 后 nDCG@10 28.3→21.2、R@100 53.1→38.4。

官方代码：GitHub。

值得押注：query-adaptive groups、learned explore/exploit switch、group freshness、tool/source graph、navigator–reranker joint training。

问题 04 · 多兴趣召回为什么不能永远固定 K 个 Query？

Single Vector → Fixed Multi-interest → Variable Set Prediction + Dynamic Dispatch

核心矛盾：真实用户兴趣数量不同；固定 K 个 head 会 interest collapse，也无条件消耗 K 次 ANN。

承接关系：MIND / ComiRec / KuaiFormer → SetMIR：Hungarian assignment + presence + NMS + dynamic ANN depth。

Research Impact Score / 研究价值 9.4/10工业成熟度 ★★★★★创新性 ★★★★★与你方向的相关度 ★★★★★是否官方开源 未发现是否有线上 A/B 是阅读优先级 最高

代表 Paper：SetMIR。10 个 ANN query 经 presence+NMS 后平均 6.70，R@10 保留 99.2%；线上整体 CVR +3.11%。

值得押注：interest marginal utility、cross-source budget、latency/TCO-aware dispatch、candidate overlap-aware assignment。

问题 05 · Generative Retrieval 为什么会“每阶段都对，整体跑偏”？

Content SID → Log SFT → Business Preference → Intent-coherent GR

核心矛盾：内容 SID 不一定代表 query intent；日志覆盖长尾不足；GMV preference 又可能牺牲 relevance。

承接关系：TIGER / OneRec → Query-aware SID → Synthetic Query Expansion → Relevance-calibrated Preference → ICEGR。

Research Impact Score / 研究价值 9.1/10工业成熟度 ★★★★★创新性 ★★★★★与你方向的相关度 ★★★★★是否官方开源 未发现是否有线上 A/B 是，20% 流量两周阅读优先级 最高

代表 Paper：ICEGR。Recall@20 +21.7%、NDCG@20 +26.6%；线上 CTR +3.52%、订单 +15.96%、GMV +7.53%。

值得押注：cross-stage objective audit、fresh/query-conditioned SID、synthetic-to-real curriculum、GR/ANN joint router。

问题 06 · Semantic ID 生成失败到底错在哪一步？

Final NDCG → Prefix Survival → Early-branch Coverage

核心矛盾：层级 SID 前两步一旦被 beam 剪掉，后续无法恢复。

承接关系：RQ-VAE / LETTER-TIGER → beam diagnostics → TAAL joint-prefix target + PMI survivor calibration。

Research Impact Score / 研究价值 8.3/10工业成熟度 ★★★☆☆创新性 ★★★★★与你方向的相关度 ★★★★★是否官方开源 未发现是否有线上 A/B 否阅读优先级 很高

代表 Paper：TAAL。91.9%–96.6% failure 位于 SID 前两步；提示 prefix survival 应成为 GR 核心 dashboard。

值得押注：dynamic beam、uncertainty branching、SID construction × decoding joint training、error-state recovery。

承接关系：CLIP/SigLIP/MLLM → CAMIE behavior pair mining → OrthoRec collaborative-guided purification。

问题 08 · Retrieval 为什么默认每个 Query 都拿同样多候选？

Fixed Top-k → Adaptive Retrieval → Query-conditioned Budget

核心矛盾：简单 query 不需要大量 context，困难 query 又可能需要更多证据；固定 top-k 同时造成 latency 浪费与 recall 不足。

Research Impact Score / 研究价值 8.3/10工业成熟度 ★★★☆☆创新性 ★★★★☆与你方向的相关度 ★★★★☆是否官方开源 未发现是否有线上 A/B 否阅读优先级 很高

代表 Paper：ViSAR 在 visual late-interaction embedding space 构造 query-conditioned similarity matrix，training-free 决定页面数，最高降低 58.7% RAG latency，并保持/提升回答准确率。

值得押注：retrieval confidence、adaptive page/region count、reader-depth routing、verification-aware k、latency target controller。

问题 09 · HNSW/Vamana 的固定召回搜索成本真的近似 log(N) 吗？

Single-scale Benchmark → Scale Curve → Sublinear Power Law

Research Impact Score / 研究价值 8.6/10工业成熟度 ★★★★☆创新性 ★★★★★与你方向的相关度 ★★★★★是否官方开源 未确认是否有线上 A/B 不适用阅读优先级 很高

代表 Paper：A Power Law in Logarithm's Clothing。作者认为在现实规模、N 尚未远大于 intrinsic dimension 时，固定 accuracy 搜索成本会表现为 N^c 的 sublinear power law，之后才可能进入 subpolynomial/poly-log regime。

值得押注：iso-recall scale curve、query-hardness-aware search width、index build/insertion trade-off、billion-scale TCO model。

问题 11 · Retrieval Evaluation 为什么每加入一个系统都从头付费？

Static LLM Judge → Pooled Qrels → Incremental Reusable Evaluation State

Research Impact Score / 研究价值 8.2/10工业成熟度 ★★★★☆创新性 ★★★★☆与你方向的相关度 ★★★★★是否官方开源 未确认是否有线上 A/B 否；含生产评测阅读优先级 高

代表 Paper：Incremental Pooled LLM Evaluation。新 retriever 只 judge 新贡献文档；生产金融新闻 QA 中 65–80% judgment 可复用，最高约 4.9× 降低评测成本，并保留约 97% pairwise ordering（考虑 qrel uncertainty）。

值得押注：qrel provenance、judge versioning、uncertainty-aware model selection、evaluation cache invalidation、offline→online validity。

问题 12 · Agent Retriever、Context Manager 与 Tool Router 为什么必须共享 State？

Step-local Search → Trajectory-aware Retrieval → Shared Control State

承接关系：Search-R1 → ITER（main question + previous subqueries + redundancy negatives）→ ContextPilot（fold/offload/memory）→ GAREN group navigation / ViSAR adaptive context budget。

Research Impact Score / 研究价值 9.2/10工业成熟度 ★★★★☆创新性 ★★★★★与你方向的相关度 ★★★★★是否官方开源 部分工作已开源是否有线上 A/B 否阅读优先级 最高

核心矛盾：下一步搜什么取决于已见证据，但完整 trajectory 又消耗 context。未来 policy 需要共同决定 source/group、k、保留 context、verification 与 stopping。

值得押注：retrieval/context joint RL、coverage-aware state、tool should-fire probability、cross-session memory freshness、cost-aware stopping。

2026.09.03 Paper Map 新判断：现在最值得押注的四类结构变量是 Structure、Assignment、Survival、Budget。Structure 决定 representation 不能违反什么；Assignment 决定哪个兴趣/source/group 应被激活；Survival 决定正确候选能否穿过多阶段剪枝；Budget 决定额外算力应该花在哪个请求。推荐/搜索真正的下一代系统，会把这四个变量一起学习。
