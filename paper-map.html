问题 01 · 粗排与精排为什么各自变强了，整条链路仍可能变差？

Stage-wise Optimization → Teacher-Student Alignment → Joint Cross-stage Fusion

核心矛盾：pre-ranking 先决定 candidate survival，ranking 无法恢复已被过滤的 item；传统跨阶段方法通常只让下游监督上游，fusion 本身仍独立。

承接：COPR / Rethink / HCCP → task-aware ranking → UniRec：shared embedding + vertical consistency + horizontal preference aggregation + AGRR。

问题 11 · Router 需要执行历史，但为什么不应该直接读完整历史？

Query-only Router → Full-history Router → Gated Execution Memory

核心矛盾：只看 query 看不到中间进展；看完整 history 又导致 token/cost 随 trajectory 膨胀，并把冗余与错误步骤反复送入 controller。

关键推进：Gated-Memory Routing：Memory Write Gate 决定哪些 reasoning step 值得写入，Retrieval Gate 决定给当前 Agent 读哪些记录，Role/Backbone Router 选下一执行者，Adaptive Halting 决定是否结束。它把“state compression”正式纳入 routing policy。

证据：5 个 reasoning/code benchmark 平均最好，较最强 baseline +2.44pt；HumanEval inference cost -31.9%。

承接：SWRouter 解决“保留多少 context” → Fugu 解决“组织哪些专家” → Gated-Memory 解决“执行过程中哪些状态值得留给下一次决策”。

押注：state TTL/version、query-adaptive write/retrieve、cache-aware routing、跨召回/粗排/精排 compact state、online drift calibration。

问题 12 · 检索 / Agent 什么时候应该继续找信息，什么时候应该停止？

Reactive Execution → Prompted Exploration → Learned Explore-vs-Execute Boundary

核心矛盾：成功 demo 往往删掉试错，SFT 学到的是“知道答案后的最短路”；RL 如果初始 policy 几乎不探索，也无法发现信息收集动作的长期价值。

关键推进：SAFARI：先构造包含回溯与失败分支的 tree-structured trajectory，再通过 Monte-Carlo rollout 估计不同 action 的 future return，构造 contrastive preference，专门训练 explore-vs-execute decision boundary。

承接：GeneralQPP 回答“检索够不够” → Elastic Horizon 回答“多轮跑多久” → SAFARI 进一步学习“下一步探索是否有预期信息增益”。

押注：query uncertainty × business value × latency budget 联合探索；将 exploration action 具体化为 query rewrite、扩大 top-K、切召回源、图扩展与用户偏好澄清。

问题 13 · 一个 Agent bad case 出现后，是否应该修改全局 Harness？

Per-case Patch → Cross-instance Failure Aggregation → Versioned Harness Evolution

核心矛盾：一次失败既可能是模型偶发能力不足，也可能是 runtime/harness 的系统性缺陷。逐条失败就改全局规则，会把局部噪声固化到基础设施。

关键推进：Ecdysis 先聚合跨任务 recurring failures，再由 Analyst/Critic/Engineer 形成 modification specification，coding agent 只负责实现。它把 Agent 自我改进从“即时 patch”升级为“批量诊断后演化”。

Research Impact Score / 研究价值 9.1/10工业成熟度 ★★★☆☆创新性 ★★★★☆与你方向的相关度 ★★★★☆是否官方开源 是是否有线上 A/B 否阅读优先级 S

证据：相对 self-evolution，harness training 最多 1.84×，reasoning accuracy 相对 +18.56%，并展示跨模型迁移。

承接：Prompt optimization → runtime harness adaptation → self-evolving harness → Ecdysis 的 failure attribution。与推荐系统 bad-case 平台、cohort analysis、规则灰度天然相连。

押注：failure clustering、因果诊断、shadow traffic、自动 regression suite、canary/A-B、rollback 与 per-query/local patch vs global rule 的自动决策。

最值得押注的交叉点：Gated-Memory Routing × SAFARI × Ecdysis 可以组成一个很有潜力的闭环：请求执行时由 compact state controller 决定下一步；证据不足时按价值主动探索；失败后先跨请求归因，再决定是否更新全局 harness。对推荐/搜索而言，这比“把一个更大的 LLM 插到链路里”更像真正可上线的下一代架构。
