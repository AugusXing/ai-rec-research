主线 A

Generative Retrieval → Full-stack GenRec

从生成候选，到 Semantic ID，再到整个推荐 Cascade 被统一模型侵蚀。

1. Item-as-Token

OneRec-V2 把推荐改写成条件生成，并把真实反馈带入 post-training。

OneRec-V2→问题：如何 Scale / Serving？
2. Semantic ID 成为基础设施

FORGE 说明 Tokenizer 本身决定长尾、泛化和 Fresh Item；HD-Rec 再把 SID 推向“共享粗粒度 + 域自适应细粒度路由”。最新音乐推荐实证进一步说明：SID 容量并非越大越好，codebook/depth 扩大可能引入不稳定。

FORGEHD-RecAudio Embedding → GenRec
3. Foundation Model + Reasoning

OpenOneRec / OneReason 把语言知识和显式偏好推理接入推荐。

OpenOneRecOneReason
4. Full-stack Replacement

Sona 给出强线上信号：单一生成式模型开始直接替代 15+ 召回源、粗排和精排。

Sona
★★★★★ 当前矛盾：Coverage / Exploration / Serving 成本。
主线 B

Ranking：Feature Tower → Transformer-native

研究重点从“更复杂的 Feature Interaction”转向 Token、Attention、Task Memory 和 List Context。

1. Expert / Mixer 时代

RankMixer 等工作把多任务与序列建模做到成熟工业化，但仍保留 Encoder + Predictor 的阶段接口。

RankMixer
2. Transformer-native Multi-task Ranking

OneRank 直接移除 Encoder–Predictor 边界，用 Task Token、Cross-task Attention、Candidate Context 和 Dynamic Matching 完成统一预测。

OneRank
★★★★★ Shopee GMV/UU +1.01%。
3. Ranking Foundation Model / LLM-backed Ranking

SORT、Netflix GenRec 把规模化 Transformer / Context Engineering 推向更强 Ranker。

SORTNetflix GenRec→问题：什么时候真的值得付大模型成本？
4. Policy / Reasoning Layer

GR2 / MetaStrategy 让模型从“打分”变成列表级 Policy；REAM 继续追问 Reasoning Budget 怎么压。

GR2MetaStrategyREAM
主线 C

Long Sequence / Scaling / Serving

问题已经从“序列能不能更长”转向“哪些 Token / KV 值得在哪个阶段付费”。

1. Long Context

OneRec-V2 / Netflix Scaling 证明长行为和模型规模有价值，但 Prefill、Attention 与吞吐迅速成为第一约束。

OneRec-V2Netflix Scaling
2. Teacher 保真，Student 压 Token

TM20K 把序列扩到 20K：Full-Attention Teacher 学全信息，线上 Student 用 Token Merge 降成本。

TM20K
★★★★★ ADSS +1.036%，Serving Latency 仅 +5.6%。
3. KV Cache 也变成 Retrieval 资源

CoinRAG 把 Chunk-level KV reuse 推进到 query-relevant information nugget：检索粒度和 prefill compute 被一起优化。

CoinRAG
4. Adaptive Compute

下一步不是固定压缩，而是 User / Target / Query-aware token budget、KV composition、History Compression 与 Model Router 联合优化。

值得押注：Per-request Compute Allocation。
主线 D

Preference Alignment / Recommendation RL

真正难的越来越不是 PPO 还是 GRPO，而是 Reward 的语义和数据密度。

1. Feedback-aware Post-training

OneRec-V2、JD GenRec、GR2 开始把真实反馈 / RL 引入召回和重排。

JD GenRecGR2
2. Adaptation ≠ Business Alignment

Progressive Alignment 把 Recommendation Foundation Model 的后训练拆成 LP → FFT → RFT：密集行为学 Policy，稀疏业务指标训练 Reward Model。

Progressive Alignment
★★★★☆ 官方参考实现已开源。
3. Long-term Reward

下一个真正难题仍是留存、疲劳、探索、生态、GMV 与用户体验如何统一，以及如何避免 reward hacking。

主线 E

Agentic Search / RAG → Context Ranking

Retriever 从固定工具逐渐变成可学习的 Policy / Router / Adaptive Executor。

1. Answer-aware Retrieval
Agentic-R→相关性不等于最终答案价值。
2. Retriever + Reasoner Joint RL
CoSearch
3. Evidence Workspace / Context Refinement

RISE / Context Interference 把重点转向“给 Agent 什么证据、多少证据、什么时候清理”。

RISEContext Interference
4. Retrieval Granularity Router

MixRAGRec 用 MoE Router 决定 KG 检索粒度，并用多 Agent Policy Optimization 联训。

MixRAGRec
★★★☆☆ KDD 2026 Oral，代码公开。
5. Retrieval Depth 成为 Runtime State

EAHR 不预设 Dense/Sparse Top-L，而是通过 unseen-score bound 动态继续读取 ranks，同时保证 complete-list weighted RRF 的 exact Top-K。

EAHR方向：safe stopping / adaptive depth。
6. Memory 变成 Probabilistic Belief

DocMemo 用 Page Belief、Bayesian update 与 Thompson sampling 让多轮 evidence search 具备显式探索状态。

DocMemo
主线 F

Model Routing / Auto Optimization

推荐系统里成熟的 Cascade、Calibration、Bandit 思想正在迁移到 Agent / LLM Serving。

1. Frontier Model Everywhere

质量高，但成本、延迟和稳定性不可控。

2. Planner / Policy + Executor

ConnectionMind、MetaStrategy 等工作都呈现同一种分工：大模型发现路径/策略，小模型高并发执行。

ConnectionMindMetaStrategy
3. Routing 之前先判断“值不值得”

Pre-Inference Routing 给出很实用的必要条件：Cheap Model 要有足够 failure rate，并且 failure 必须能从廉价输入特征预测；否则再复杂的 Router 也没有经济价值。

Pre-Inference Routing
4. Internal-state-guided Optimization

MISO 开始把参数、激活、梯度等内部状态变成 Ranking Model 研发反馈，而不是只靠最终指标黑盒试错。

MISO
