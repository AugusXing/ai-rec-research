不是按年份堆论文，而是沿“核心矛盾”读技术

Paper Map 持续回答：上一种方法解决了什么，为什么还不够，下一篇关键工作把矛盾推进到了哪里？今天新增六个问题：跨阶段 fusion 如何真正联合优化、历史 attention / retrieval trace 如何变成资产、RAG 如何低成本判断检索失败、多轮 router 如何决定保留哪些历史、late-interaction embedding 能否生成式重建、时间有效性如何进入检索排序。

当前推荐精读路线：推荐主线：PTDG → MORE → UniRec；检索主线：SAM-D2Q → LiteRAG → GeneralQPP / TimelyRAG → GLIE；State/Serving：DoPR / ReST → KVShareArena → REVA；Agent：IGPO / EdgeMem → Elastic Horizon → VikingRAG → RobustSGPO。
问题 01 · 粗排与精排为什么各自变强了，整条链路仍可能变差？

Stage-wise Optimization → Teacher-Student Alignment → Joint Cross-stage Fusion

核心矛盾：pre-ranking 先决定 candidate survival，ranking 无法恢复已被过滤的 item；但传统跨阶段方法通常只让下游监督上游，fusion 本身仍独立。

承接关系：COPR / Rethink / HCCP → task-aware ranking → UniRec。UniRec 让两阶段 fusion agent 共享部分 embedding、在同一 computation graph 联合训练，并用 vertical consistency + horizontal preference aggregation + AGRR 协同多个目标。

关键证据：ASH 0.9978；快手一周 20% 流量 A/B，AppUsageTime +0.616%、TotalWatchTime +0.675%，已全量部署。

值得押注：扩展到 recall/rerank、stage survival metric、train-joint/serve-decoupled、跨阶段 calibration 与 shared state。

问题 02 · 多跳检索需要图，但 query-time 图遍历为什么一定要付多轮 LLM 成本？

LLM-driven GraphRAG → Query-conditioned Algorithmic Retrieval

核心矛盾：图能表达关系，但 LLM navigation/community summary 把 retrieval SLA 变成 generation SLA。

承接关系：Dense RAG → GraphRAG → Light/Linear RAG → LiteRAG，用 semantic/lexical/community anchor、动态扩张阈值和 hub penalty 把图探索改成预算化算法。

问题 03 · 为什么同一文档每次被召回都要重新压缩 / 重新找证据？

Per-query Compression → Reusable Evidence View

核心矛盾：在线 compressor 节省 prompt tokens，却可能新增更高 latency；热门文档又会被大量重复访问。

承接关系：truncation / prompt compressor → query-specific attention compression → REVA。它把 generator 历史 attention 按 document 聚合为 budget-agnostic score store，在线只做 lookup + materialization。

关键证据：质量 +1.0～5.8 points；compression overhead 5.3～15.6× 更低；在线额外延迟 <40ms。

值得押注：evidence TTL、generator compatibility、answer feedback 写回、与 KV/document state 统一管理。

问题 04 · Agent 为什么每次都从零探索同一知识库？

Agentic Multi-round Retrieval → Experience Edge → Adaptive Escalation

核心矛盾：结构化文档需要 Search/List/Grep/Read 多轮探索，但相似 query 往往重复走同一证据路径。

承接关系：ReAct / DeepRead → hierarchical structured RAG → VikingRAG。成功 trace 被物化为 source→target experience edge；新 query 先复用 edge，一轮证据足够就不启动 Agent。

关键证据：trace reuse + escalation 后 token 为强基线的 5.1%～32.5%。

值得押注：experience confidence/TTL、query clustering、edge provenance、false-positive-safe adequacy checker。

问题 05 · RAG 怎么知道“这次检索没成功”？

LLM Judge → Retrieval-score Distribution Controller

核心矛盾：retrieval failure 没有显式信号时，generator 会在证据不足时继续回答；再调用一个 LLM judge 又贵又可能过度自信。

承接关系：max score / classic QPP → LLM sufficiency judge → GeneralQPP。它从 top-score curve 的 gap、decay、skew、bimodality、concentration 等提取 24 个 non-lexical features。

关键证据：ViDoRe AUROC 0.856、2ms/query；高于 local Qwen3.5 judge 0.649，约快 3000×。

值得押注：confidence→topK/rerank/Agent escalation、online calibration、per-domain threshold、risk-aware refusal。

问题 06 · 多轮 Model Router 到底应该看到多少历史？

Single-turn Routing → Full-history Routing → Similarity-contracting Context

核心矛盾：全历史会 information confusion，只看当前 turn 会 information loss；若 prompt construction 错了，router 本身再强也无济于事。

承接关系：single-turn routers → Conv-ID history → SWRouter，用相邻 turn semantic similarity 切 window，并以 sample-LLM + sample-sample contrastive loss 学 router。

值得押注：context router 与 model router 联合、cost/cache/tool-aware routing、long-range dependency preservation。

问题 07 · late-interaction 每页上千 vectors，除了删/量化还能怎么办？

Store-all → Pool / Quantize → Store Code, Regenerate Evidence

核心矛盾：极致压缩会丢掉 MaxSim 需要的局部 evidence；但 token vector cloud 本身位于低维球面 manifold。

承接关系：ColPali → pooling / cluster merge → GLIE。k 个 anchor 同时是全库轻量索引与 decoder 的生成 code，top-L 候选再解码回 N vectors。

关键证据：4 vectors/page 保留近 80% uncompressed nDCG@5；spherical normalization 单独最多 +0.093。

值得押注：GLIE × low-bit quantization、better decoder、video retrieval、decision-aware codec training。

问题 08 · 高语义重叠的旧版/新版文档，如何知道哪个版本“有效”？

Semantic Relevance → Temporal Compatibility

核心矛盾：法规/政策 amendment 只改少数 clause，旧版与新版语义几乎相同；“最新”也不总等于“对 query 时间有效”。

承接关系：timestamp filtering / recency score → temporal retriever → TimelyRAG，把 query/document insert/event time 与 clause validity interval 写进第二阶段 reranking。

问题 09 · KV Cache 离开“出生上下文”后还能直接复用吗？

Prefix Cache → Non-prefix Reuse → Compatibility-aware Repair

核心矛盾：position、cross-source attention、producer checkpoint 都会让 reused KV 改变语义。cache hit rate 不能代表正确性。

承接关系：prefix caching → CacheBlend/repair → KVShareArena，用 context × checkpoint board 与 quality/recompute/bytes/TTFT 联合评价。

问题 10 · embedding 平均误差很小，为什么 top-k 仍会翻转？

Representation Distortion → Decision Flip Risk

核心矛盾：ANN 消费的是局部比较、top-k 边界与 graph prune，而不是平均 reconstruction。

承接关系：PQ/BBQ/RaBitQ → rank correlation → decision-level quantization analysis，以 boundary mass + residual tail 解释关键 pair flip。
