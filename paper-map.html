不是按年份堆论文，而是沿“核心矛盾”读技术

Paper Map 持续回答：上一种方法解决了什么，为什么还不够，下一篇关键工作把矛盾推进到了哪里？今日新增四个重点问题：小模型如何进入控制面、model router 如何升级成 execution-plan orchestrator、高 fan-out Agent 如何同时优化 sandbox memory 与 P95、推荐攻击迁移性为什么要看 loss landscape flatness。

问题 01 · 粗排与精排为什么各自变强了，整条链路仍可能变差？

Stage-wise Optimization → Teacher-Student Alignment → Joint Cross-stage Fusion

核心矛盾：pre-ranking 先决定 candidate survival，ranking 无法恢复已被过滤的 item；传统跨阶段方法通常只让下游监督上游，fusion 本身仍独立。

承接：COPR / Rethink / HCCP → task-aware ranking → UniRec：shared embedding + vertical consistency + horizontal preference aggregation + AGRR。

押注：扩展到 recall/rerank、stage survival、train-joint/serve-decoupled、shared state。

问题 10 · 1–3B 小模型在推荐 / 搜索系统里最应该放在哪？

Small Chat Model → Local Agent → Control-plane Model

核心矛盾：大模型适合 hard case，但把 query rewrite、routing、retrieval gate、memory curation 全部交给 frontier model 会让成本与尾延迟失控。

代表工作：MiniCPM5-2B。2.52B/128K，公开 base/midtrain/SFT/final、多种量化与 Agent/RL 数据；RL teachers 经 OPD 回蒸馏到单模型，并提供 DSpark draft model。

问题 11 · Agent 并发为什么不能只用 GPU tokens/s 来容量规划？

Model Runtime → Workflow Runtime → Sandbox-aware Runtime

核心矛盾：Agent 有 LLM、tool、sandbox、多轮依赖和高 fan-out；GPU 空闲不代表节点有容量，turn ready 也不代表应该立刻 release。

代表工作：AgentZip 利用 template/cross-sandbox redundancy，memory 最多 8.7×；Tail-aware Scheduling 用 mean-CVaR + released-work budget，在争用下 P95 最多 3.50× speedup。

问题 12 · 推荐投毒为什么能从 surrogate 迁移到未知 target model？

Attack Strength → Flatness → Cross-model Transfer Robustness

核心矛盾：surrogate 上的 sharp optimum 对参数变化极敏感，攻击强却不一定能迁移；推荐系统真实风险恰恰来自 attacker 不知道线上模型。

代表工作：RecGP 用 gradient penalty 将 fake-user solution 推向 flat loss region；RecGP-RS 再用 semantic-aware neighborhood sampling 降低二阶近似成本。
