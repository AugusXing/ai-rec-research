问题 01 · Generative Retrieval 怎样获得工具能力而不增加在线工具调用？

Raw Image → Explicit Crop/OCR Tools → Latent Tool Capability

核心矛盾：真实图搜 query 同时含目标商品、背景、文字、水印和其他物体。显式 crop/OCR 能提升识别，但会把生成式召回重新拉回多阶段串行链路。

承接关系：Image Encoder + ANN → Multimodal Generative Retrieval → Think-with-Images / Tool Use → PailitaoGR：训练期让 Crop/OCR Teacher 拥有更强输入，线上 student 只看原图。

Research Impact Score / 研究价值 9.8/10工业成熟度 ★★★★☆创新性 ★★★★★与你方向的相关度 ★★★★★是否官方开源 暂否；承诺接收后发布是否有线上 A/B 否 / 未披露阅读优先级 最高

代表 Paper：PailitaoGR。Target Enhancer + student-trajectory on-policy distillation + Region/Entropy attention guidance + selective OCR capability distillation；真实拍立淘日志上平均提升 13.8%，推理无需额外 crop/OCR call。

成熟度判断：真实工业日志与明确 serving 约束使其比纯 benchmark 更接近生产，但缺线上 A/B 与公开模型。

值得押注：Tool-rich Teacher → Tool-light Student、visual token routing、SID granularity control、将 OCR / graph / search / long-context teacher 能力统一蒸馏到线上 compact state。

问题 02 · 相同 Ranking Quality 为什么会做出不同决策？

nDCG Stability → Candidate-order Bias → Decision-consistent Scoring

核心矛盾：listwise LLM scorer 会受到候选 presentation order 影响。离线 nDCG 几乎相同，阈值保留集合、reader 输入和最终答案却可能完全不同。

承接关系：Pointwise / Pairwise Rerank → Listwise LLM Scoring → Permutation Averaging → OC-SFT 直接把 order consistency 写进权重训练。

Research Impact Score / 研究价值 9.4/10工业成熟度 ★★★☆☆创新性 ★★★★☆与你方向的相关度 ★★★★★是否官方开源 是是否有线上 A/B 否阅读优先级 最高

代表 Paper：Equal Ranking Quality, Different Decisions。5 个 scorer 的 nDCG@10 差异小于 0.010，但换顺序后 retained-set overlap 只有 0.66–0.84；OC-SFT 将 multi-document reader answer-flip rate 降到 0.125，并能用一次推理超过 off-the-shelf scorer 多次 permutation averaging 的稳定性。Official Code

成熟度判断：训练目标清晰、代码公开、推理成本优势明确；但尚缺真实推荐曝光 / 广告排序 A/B。

值得押注：Decision Stability、Threshold Robustness、candidate-set invariance、listwise calibration、将业务规则 / diversity constraint 与 order consistency 联合训练。

问题 03 · Offline Metric 到底被允许支持什么下游结论？

Topical Relevance → Evidence Support → Validity-by-Use

核心矛盾：RAG 中“这段 passage 能支持答案”看起来比主题相关性更合理，但一个更语义化的 metric 不等于它天然适合 retriever comparison、training、system selection 和 answer-quality prediction。

承接关系：nDCG / Recall → LLM-judged Relevance → Answer-support Evidence Metric → 逐用途验证 metric 的 downstream validity。

Research Impact Score / 研究价值 9.2/10工业成熟度 ★★★☆☆创新性 ★★★★☆与你方向的相关度 ★★★★★是否官方开源 否 / 未发现是否有线上 A/B 否阅读优先级 最高

代表 Paper：Assessing the Downstream Utility of Evidence-Aware Retrieval in RAG。5 个 retrieval benchmark 上，原 relevance 与 answer-support 排名 Kendall τ 约 0.378–0.746，Top system 5 个集合中 4 个变化；但把 answer support 用于 RankNet training 的收益很小且置信区间覆盖 0，direct evidence filtering 后不同 answer evaluator 对最终质量甚至给出相反判断。

成熟度判断：研究方法非常成熟，工业意义高，但它是评测框架而不是直接可部署模型。

值得押注：Metric Contract、offline-to-online validity test、proxy→decision→business outcome 追踪、LLM Judge causal validation、实验平台自动检测 surrogate failure。

问题 04 · 推荐的是“动作”而非 Item 时，怎样估计真实增量？

Outcome Prediction → Propensity-biased Recommendation → Counterfactual Action Value

核心矛盾：页面上的购买信号、角标、解释、优惠和通知都是 treatment。历史上出现在高意向用户身上的动作，会被普通 CTR/CVR 模型误判为“导致了结果”。

承接关系：CTR/CVR Prediction → Contextual Signal Ranking → Stageboost：先估计反事实，再选择最可能带来增量的 signal。

Research Impact Score / 研究价值 9.3/10工业成熟度 ★★★★★创新性 ★★★★☆与你方向的相关度 ★★★★★是否官方开源 否 / 未发现是否有线上 A/B 是阅读优先级 最高

代表 Paper：Stageboost。eBay 两阶段 XGBoost + counterfactual estimation，用于 View-Item 页面 signals；线上整体 GMB +0.08%，Parts & Accessories +0.58%。

成熟度判断：真实超大规模电商线上证据强；公开论文较短，具体反事实估计与 overlap / propensity 诊断细节披露有限。

值得押注：Uplift / HTE 与深度 ranking 融合、doubly-robust policy learning、短期转化 × 长期用户信任、多 treatment interference。

问题 05 · ANN 应该优化峰值 QPS，还是整个 Index 生命周期？

Graph Peak-QPS → Build / Refresh Bottleneck → Metric Inverted Sample Index

核心矛盾：推荐召回的真实成本包含 build time、peak build memory、artifact size、refresh cadence 和 query latency。频繁更新 catalog / embedding 时，峰值 QPS 不一定是首要矛盾。

承接关系：Tree / IVF → HNSW / Disk Graph → Fresh Index / Delta Update → misi 用随机 sample vocabulary + inverted posting + exact verification 换取低内存、并行构建与任意 metric 兼容。

Research Impact Score / 研究价值 9.1/10工业成熟度 ★★★★☆创新性 ★★★★☆与你方向的相关度 ★★★★★是否官方开源 arXiv 标注有代码；仓库 URL 待确认是否有线上 A/B 否阅读优先级 最高

代表 Paper：misi。10^8 vectors 在 64 CPU cores 上构建约 5,250s、3 GiB build RAM、可在 8 GB memory budget 下 NVMe serving；matched-recall build 比 graph baseline 快 3.7×，但纯 RAM 查询 graph 仍快 6–16×。

成熟度判断：系统假设和 trade-off 很明确，适合频繁 rebuild、受限内存、黑盒 metric 场景；并非通用 HNSW 替代。

值得押注：Index lifecycle optimizer、refresh-aware ANN routing、A/B 多索引共存成本、streaming rebuild、metric-generic retrieval。

问题 06 · 高性能 Kernel 怎样证明“真的算对了”？

Shape Correctness → Numerical Correctness → Semantic Set Correctness

核心矛盾：GPU kernel 即便没有 crash、输出 shape/index range/数量都正确，也可能返回语义错误的候选集合；这类 silent corruption 对稀疏 attention、Top-K routing 和 ANN 都尤其危险。

Research Impact Score / 研究价值 9.0/10工业成熟度 ★★★★★创新性 ★★☆☆☆（Correctness Issue）与你方向的相关度 ★★★★☆是否官方开源 是是否有线上 A/B 不适用阅读优先级 最高（Serving 用户）

代表 Issue：SGLang #36807。`fast_topk_v2` 对 k=2048 的 radix threshold bucket 使用固定 4096-entry shared-memory candidate buffer；64×256K 的复现中 64/64 rows Top-K 错误，每行 6–42 个选中项不在真实 Top-K，且普通 shape/range/count 检查不会报警。

成熟度判断：这是官方开源仓库中的 reproducible correctness report，不是新算法；截至今日 issue 仍 Open。

值得押注：Reference-kernel differential test、adversarial length/distribution sweep、fast-path overflow detector、safe fallback、semantic invariants 与 deterministic replay。

核心矛盾：结构字段、文本语义、图片语义和布尔逻辑共存时，单 ANN / RRF 的 action space 太固定。
