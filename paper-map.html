当前总技术树：推荐 / 搜索的共同瓶颈正在从“Backbone 表达能力”迁移到 Representation Geometry → Semantic Namespace → User State → Supervision / Reward → Runtime Budget。8 月 27 日最重要的更新是：TAGR 把 Fresh SID 跑进直播广告；Tlow 从 embedding geometry 重做 tokenizer；WeMM + NMRL 分别给出 universal representation 与 task-native supervision 的上下游边界；RecGPT / AdaWidth 开始把 compute 变成 request-level action。
问题树 A · Item Representation / Semantic ID

核心矛盾：Item 要同时“有语义、可生成、可更新、可低成本 Serving”

Random ID→RQ-VAE SID→Dynamic / Single-level SID→Flow-normalized Token→Fresh Semantic Namespace

承接关系：传统 SID 解决 random ID 无语义与冷启动 → Dynamic Single-Level SID 解决多层码本利用率 / 串行路径 → Tlow 进一步问“量化前空间本身是否适合量化” → TAGR 再把问题推进到非平稳场景：即使 token 很好，mapping 不新鲜仍然失效。

问题树 B · User Representation / Long Sequence

核心矛盾：更长历史 ≠ 更多有效信息

Raw Behavior Sequence→Long-context Transformer→Shared User State→Densed / Intent-aware State

承接关系：Long Sequence 解决短窗口遗忘 → OneModel 将跨场景 event 压成 shared user state → Densing Law 发现 user scale / history length / encoder size 都存在 scaling wall → RecGPT-Mobile-V2 和 TAGR 开始按请求 / 时间尺度选择真正有用的行为证据，而不是无脑加长。

问题树 C · Multimodal / Foundation Representation

核心矛盾：通用语义强，但业务目标不等于通用语义

Frozen CLIP/BERT Feature→Universal Multimodal Embedding→Recommendation-native Supervision→Cross-stage Representation Service

承接关系：通用 embedding 解决 ID 冷启动和内容理解 → WeMM 把任意图文视频输入统一成强 embedding，并进入检索 / 排序 / 用户序列 → NMRL 证明“直接 CTR E2E 联训”会被非语义点击因素污染，因此需要 Mine-Then-Train 筛出可归因 supervision。

问题树 D · Retrieval / Recall

核心矛盾：统一 Search + Rec 时，索引必须既开放又有高 warm accuracy

ID Softmax→Feature Dual Encoder→Semantic Token Retrieval→Hybrid Open Index

承接关系：ID-softmax 在 warm item 上强但新 item 必须等待 retrain → feature dual encoder 可立即编码新 item，却存在专用推荐精度 gap → RetrievalFormer 量化了这项 trade-off，并发现 ANN 不是主要问题，catalog-scale exact-quality training 才是核心瓶颈；Tlow / WeMM 则为 feature side 提供更强语义与紧凑 token。

问题树 E · Ranking / Re-ranking

核心矛盾：从“预测点击”升级到“任务原生表示 + 即时上下文 + 多目标约束”

ID Feature Ranker→Foundation Ranker→Trigger / Native Representation→Risk / Utility-aware Re-rank

承接关系：Foundation Ranking 解决多场景共享 → CRRN 证明请求时 trigger 是高 ROI signal → NMRL 证明共享内容表示要经 task-native mining → Risk-aware Tool Reranking 将 relevance 与执行风险写入最后决策层。重排的角色正在从“最后再算一次分”变成 constraint / decision layer。

问题树 F · RL / Preference / Reasoning

核心矛盾：不是“有没有 CoT”，而是 reward 是否真的对推荐 Utility 有信息

SFT→Accuracy Reward→Dense Retrieval / Value Reward→Quality-gated Adaptive Budget

承接关系：Reasoning Trace Gap 说明描述更漂亮不等于 Recall 更高，稀疏 reward 甚至让 GRPO 没有有效 advantage → RecGPT 用 quality gating + per-input budget 修复“短 CoT 奖励作弊” → TAGR 将当前 policy 的行为 / 价值反馈间歇写回 generator，解决 freshness 与稳定性冲突。

问题树 G · Agentic Search / RAG

核心矛盾：Relevant Context 不等于 Verifiable Evidence

Top-K RAG→Iterative Search→Context Allocation→Evidence Graph

承接关系：长 context 解决 recall 不足却带来 relevance dilution → Laws of Context Allocation 用闭环多轮分配 evidence → EviGraph 将搜索执行和 evidence recording 拆开，使用 verbatim evidence + polarity + support graph，并把 graph 作为 memory 与 process reward。
