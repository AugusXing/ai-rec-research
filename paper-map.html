Research Problem Map · 更新至 2026.09.25

不按论文年份堆列表，而按“核心矛盾 → 承接关系 → 下一步问题”组织

技术树中心已经从单模型能力转向 Shared State → Specialist Executor → Conditional Controller → Counterfactual / Trajectory Measurement。生成式召回、LLM 排序、Agentic Search、Long-context Serving 和 Model Routing 表面不同，本质都在回答：有限预算下，哪个状态应该被读、哪个执行路径值得走、收益如何被可靠归因。

当前最值得押注：① Semantic ID 与 retrieval/ranking 共享表示；② long-history 从 request-time encoding 转向 state system；③ retrieval relevance 与 activation utility 解耦；④ time/geo/freshness 等结构约束用独立 axis；⑤ model / memory / Skill / feature / budget 统一控制；⑥ 用 counterfactual 与 attribution 判断真正增量。
Problem 01 · 如何让召回与排序共享语义，但不牺牲工业执行弹性？

Generative Retrieval / Semantic ID / Unified Rec

RQ-VAE / TIGER→Value-aware Generation→UniPolicy→UNIQUE→Versioned Address + Multi-executor

核心矛盾：retrieval 需要高吞吐与可枚举地址，ranking 需要 target-aware discrimination；强行合成一个 stage 会牺牲 SLA，完全分离又会造成 representation mismatch。

代表 Paper：UNIQUE 用 flat quantization + early fusion 共享表示，但保留 generative retrieval 与 target scoring 的不同执行语义。

精读路线：RQ-VAE/TIGER → value-aware generative retrieval → UniPolicy → UNIQUE → Hybrid GPU–CPU Retrieval。

值得押注：versioned Semantic ID、incremental assignment、multi-source candidate accounting、ranking-supervised address learning。

Problem 02 · 如何把强行为统计安全地交给 LLM 排序？

Semantic + Behaviour Fusion / Missing-feature Robustness

Text Cross-Encoder→Semantic ID→Behaviour Token→Dual-view Robust Training

核心矛盾：CTR/QSS/CVR 等历史统计很强，却有曝光偏差、cold-start 与 freshness 问题；纯文本语义可泛化，但个性化不足。

代表 Paper：Spotify Robust Fusion 用 Semantic ID + QSS + dual-sample feature dropout，让模型“有行为证据时利用，没有时也能稳健退化”。

Research Impact Score / 研究价值 9.6/10 · 工业成熟度 ★★★★★ · 创新性 ★★★★☆ · 与你方向的相关度 ★★★★★ · 是否官方开源 否 · 是否有线上 A/B 是：search success 约 +2% · 阅读优先级 S+

精读路线：DIN/DIEN → LLM rerank → Semantic ID → Robust Fusion。

值得押注：feature uncertainty token、propensity correction、coldness gate、multi-source missing-feature training。

Problem 03 · 超长行为序列到底应该在线全算，还是变成用户状态系统？

Long Sequence → Multi-timescale State → External Memory

DIN/Transformer History→Long-context Encoder→MuSeR State→PaMER State-aware Memory

核心矛盾：长期偏好有价值，但 request-time 重算全部 history 昂贵；过度压缩又会丢掉后续突然需要的旧证据。

代表 Paper：MuSeR 将 10⁴–10⁵ 行为压成异步维护的多兴趣 state；PaMER 进一步从 pre-action hidden state 决定何时压缩与召回。

Research Impact Score / 研究价值 9.3/10 · 工业成熟度 ★★★★☆ · 创新性 ★★★★★ · 与你方向的相关度 ★★★★★ · 是否官方开源 未完整确认 · 是否有线上 A/B MuSeR 有；PaMER 无 · 阅读优先级 S+

精读路线：DIN/DIEN → long-sequence Transformer → MuSeR → PaMER。

值得押注：Recent State + Long-term Memory、state TTL、drift detection、learned recall gate、memory/KV 联合调度。

Problem 04 · 一个 embedding 能同时承担语义、时间、新鲜度与库存约束吗？

Semantic Retrieval → Constraint-specific Axes → Query-dependent Fusion

Single Dense Space→Hybrid Sparse+Dense→TEMPS Temporal Axis→Multi-axis Constraint Router

核心矛盾：主题相似通常近似对称，而时间包含、价格区间、地理与库存约束具有不同结构；全部压进一个 cosine space 容易互相干扰。

代表 Paper：TEMPS 冻结 semantic retriever，增加 Gaussian temporal embedding + directional inclusion score；TS-Retriever R@1 19.92→25.39。

Research Impact Score / 研究价值 8.9/10 · 工业成熟度 ★★★☆☆ · 创新性 ★★★★☆ · 与你方向的相关度 ★★★★★ · 是否官方开源 未确认 · 是否有线上 A/B 否 · 阅读优先级 S

精读路线：BM25+dense hybrid → temporal retrieval → TEMPS → multi-axis retrieval。

值得押注：constraint detection、axis gating、score calibration、geo/freshness/trust/inventory branches、与 Semantic ID 的组合。

Problem 05 · 检索到了以后，什么时候真的值得加载？

Retrieval → Activation → Memory / Skill / Model Unified Control

Always Load→Retrieve Relevant→PaMER State Gate→SkillApt Utility Gate→Value-aware Router

核心矛盾：相关性只说明“可能有用”，不能说明边际收益高于 token / latency / GPU 成本。

代表 Paper：SkillApt 基于 WITH/WITHOUT Skill 的反事实执行证据决定 LOAD/ABSTAIN；相同准确率下 activation 100%→31.5%，token -74.3%。

精读路线：retrieval confidence → memory gate → SkillApt → feature/model activation。

值得押注：marginal utility estimator、counterfactual activation labels、cross-model transferable gate、online bandit / RL。

Problem 06 · 推理 / 重排的 test-time compute 应该如何分配？

Repeated Sampling → Search Policy → Cost-aware Reasoning

Best-of-N→Verifier→Learned Search Policy→Budgeted Controller

核心矛盾：多采样能提高成功率但浪费 token；更复杂 planner 又未必超过强 retrieval / rerank baseline。

代表推进：Beyond Repeated Sampling 让小模型先生成搜索概念；Context Planning Negative Result 则要求所有 controller 做 budget-matched strong baseline。

Research Impact Score / 研究价值 8.9/10 · 工业成熟度 ★★★☆☆ · 创新性 ★★★★★ · 与你方向的相关度 ★★★★★ · 是否官方开源 部分未确认 · 是否有线上 A/B 否 · 阅读优先级 S

精读路线：Best-of-N → verifier → learned search policy → negative-result calibration。

值得押注：cost-aware early exit、source/model/depth joint routing、value-of-information、uncertainty-triggered reasoning。

Problem 07 · Serving 为什么越来越像算法问题？

KV Cache → IO-aware Fusion → Phase-specialized Precision → Global Scheduler

Paged KV→Spec Decode→Flash-dLLM→DQ / HySparse2→Global Runtime Controller

核心矛盾：FLOPs 下降不保证 latency 下降，HBM traffic、KV ownership、precision、batch shape 与 hardware topology 可能成为新瓶颈。

代表 Paper：Flash-dLLM 联合设计 cache+verify；HySparse2 做两级 KV sharing；Disaggregated Quantization 将 prefill/decode 分开量化。

Research Impact Score / 研究价值 9.4/10 · 工业成熟度 ★★★★☆ · 创新性 ★★★★★ · 与你方向的相关度 ★★★★☆ · 是否官方开源 部分 · 是否有线上 A/B 多为系统 benchmark · 阅读优先级 S+

精读路线：PagedAttention → speculative decoding → H-Spec → Flash-dLLM → DQ → HySparse2。

值得押注：multi-tenant KV allocator、P/D disaggregation、precision router、cache-aware model routing。

Problem 08 · 如何知道线上提升到底是谁创造的？

Offline Proxy → Counterfactual Observability → Trajectory / Attribution Diagnostics

核心矛盾：raw engagement 混合曝光偏差、内容质量、stage interaction 与策略变化；aggregate metric 又掩盖 cold-start、missing-feature 与长序列失败。

代表推进：Netflix Counterfactual Observability 用历史 A/B 校准离线增量；Spotify 做 feature-present/missing slice；Sequential Rec XAI Benchmark 则提醒 raw attention 并不等同于真实行为贡献。

值得押注：candidate provenance、stage attribution、propensity logging、faithful sequence attribution、trajectory failure taxonomy。

Problem 09 · 多档模型越来越多，Router 应该优化什么？

Capability Routing → Cost-aware Routing → Business-value Routing

Fallback Rule→Difficulty Router→GPT-6 Cost Frontier→Value / Dollar / Risk Policy

核心矛盾：“难题用大模型、简单题用小模型”没有显式优化业务价值、失败风险、latency 与 cache reuse。

代表进展：GPT-6 Sol/Luna 继续降低中低档模型价格并保持较强 Agent/Coding 能力，使多层模型组合的 ROI 更高。

Research Impact Score / 研究价值 9.2/10 · 工业成熟度 ★★★★★ · 创新性 ★★★★☆ · 与你方向的相关度 ★★★★☆ · 是否官方开源 否 · 是否有线上 A/B 已上线 API，非论文式 A/B · 阅读优先级 S+

精读路线：static fallback → learned model router → SLO-aware routing → cost-aware portfolio → unified execution controller。

值得押注：business value / dollar、risk calibration、cascade fallback、cache-aware routing、online contextual bandit。
