今天的技术树新增三个关键节点：Dynamic SID 把 Semantic ID 的研究问题从“怎样量化 item”推进到“码本怎样随流量长期演化”；DoorDash SPID 证明 Semantic Hierarchy 可以跨 Search 与 Recommendation 复用；Clarify-Then-Search / EnSI-RAG / CAIRO 则共同把 Context Selection 提升为一等算法模块。模型越统一，表示、索引、上下文和 Runtime 的接口反而越重要。

如何读这张图：每条主线先看“上一阶段解决了什么”，再看“留下的核心矛盾”，最后沿代表 Paper 到值得押注的问题。表中固定 7 字段：Research Impact / 研究价值、工业成熟度、创新性、与你方向相关度、官方开源、线上 A/B、阅读优先级。
主线 A

Generative Retrieval：Item Token → Dynamic SID Platform

上一阶段

OneRec-V2 / Sona 证明 Item-as-Token；SIDScope 把 tokenizer/mapping/generator artifact 化；SSR-GRPO 让 SID 反过来监督 Dense Retrieval。

核心矛盾

多层 RQ SID 有 decode depth、conditional codebook sparsity、fresh-item assignment 与 version churn；静态 codebook 会被新流量拖离当前语义分布。

关键推进

Dynamic Single-Level Large Semantic Codebook 用一个大 semantic token + collaborative disambiguation token 替代深层残差 SID，并加入 exposure-aware 动态更新；线上证明效果和 QPS 可以同时提升。

主线 B

Cross-system Representation：Search × Rec Shared Hierarchy

上一阶段

Search 与 Recommendation 各自维护 embedding / taxonomy，语义治理、冷启和长尾泛化重复建设。

关键推进

DoorDash One Hierarchy, Two Systems 用同一套 Semantic Product ID 支撑 Discovery Ranking 与 Search Query Reformulation；统一语义资产、保留 task-specific Serving。

核心矛盾

同一 hierarchy 对 ranking / reformulation 的最优粒度不同；shared representation 出错会形成跨系统 blast radius。

值得押注
Shared Semantic Namespace + Per-task Prefix/Adapter + Version Rollback；Search/Rec/Ads 共用 item semantic asset。
主线 C

Foundation Ranking → In-context Adaptation

上一阶段

RankMixer / OneRank 将精排 Transformer-native；OneModel 将 Rec / Ads / Merchant 统一成 Event Sequence + Shared User State。

核心矛盾

跨域预训练仍可能学成平均模型，新国家、新类目、长尾小域继续需要微调。

关键分叉

RecPFN 在合成 SCM 环境上预训练“序列推断算法”，新域只检索少量 support sequence 做一次 forward，无梯度更新。

主线 D

Context Selection：More Context → Right Context

问题变化

LLM 推荐/RAG/Deep Search 早期主要扩大 context；现在瓶颈变成冗余、冲突、信息不完整与选择成本。

三条新路线

CAIRO 按 user-item 选择商品 profile；EnSI-RAG 用 entity-structure index 定位证据；Clarify-Then-Search 在检索前先补全用户问题。

一条推荐精读路径

从“生成式推荐”读到“系统资产”

OneRec-V2 / Sona→SIDScope / SSR-GRPO→Dynamic Single-Level SID→DoorDash SPID→OneModel / RecPFN→CAIRO / Clarify→AsmEvo / CacheRoute

这条路线从 Item Token 开始，最终落到 Representation、Context 与 Runtime 三类长期资产；真正值得押注的问题多发生在模块接口，而不是某个 backbone 再增加几层。
