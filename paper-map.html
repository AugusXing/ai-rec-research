不是按年份堆论文，而是沿“核心矛盾”读技术

Paper Map 持续回答：上一种方法解决了什么，为什么还不够，下一篇关键工作把矛盾推进到了哪里？今天新增四个关键问题：Semantic ID 是否应该编码业务价值；生成式预训练 dense knowledge 如何安全迁入工业 Ranker；持续偏好变化应该写回共享主干还是独立 memory；Hybrid Retrieval 的 Top-K 到底是不是成本预算。

当前推荐精读路线：生成式召回：HypRQ-VAE → EPIC → Generative Verifier → VARG；工业 Ranking：PTDG → MORE → UniRec → LazFormer；长期 / 持续状态：ChronicleRec → DRIFT → LION；Agentic Search：GeneralQPP → SAFARI → Gated-Memory Routing → Question’s Gambit → DiBud；生成式 Serving：TGR / EPIC → OneLA → adaptive verification → ForgeMegakernel。
问题 01 · Semantic ID 只表达语义就够了吗？

Semantic Address → Item-level Preference → Value-aware / Ranker-aligned Address

核心矛盾：Generative Retrieval 的 token probability 决定 item 能否进入候选，但传统 SID 主要优化语义量化；同一语义桶内的商品价值、用户偏好和 downstream ranker preference 并没有直接写进地址。

承接：RQ-VAE / TIGER 让 item 可生成 → HypRQ-VAE 适配长尾 namespace → EPIC 修正 partial-token likelihood 与完整 item preference 错位 → VARG 用 value-aware 末级 token + Prefix-GRPO 把合法性、行为、搜索相关性、ranker advantage 联合起来。

证据：Tmall 14-day / 20% traffic A/B：GMV +1.45%，同时 UCTR/UCTCVR/PCTR 均提升；生成候选通过 reserved quota 进入成熟 final ranker。

成熟度：高。已经具备工业数据、在线架构、refresh contract 与真实 A/B，而不只是公开数据集。

押注：incremental SID、value-aware codebook 与 exploration 平衡、ranker survival reward、ANN/GR budget router、动态 beam / verify-K。

问题 02 · 推荐预训练为什么经常“预训练很强，线上 Ranker 迁不过去”？

Behavior Pretraining → Sparse-only Transfer → Sparse + Dense Transfer Contract

核心矛盾：工业 ranking 的 feature space 与预训练行为序列并不一致。直接迁全部参数容易 negative transfer；只迁 sparse embedding 又浪费 dense Transformer 在长历史里学到的模式。与此同时，多 epoch 训练会让 sparse 参数先过拟合、dense 参数还没学够。

关键推进：LazFormer：生成式行为预训练同时学习 sparse+dense；ranking-specific features 通过 transferable residual adapter 注入；asymmetric multi-epoch 在 epoch 间重置 sparse、持续更新 dense；再用长序列压缩和 hybrid sparse attention 控制成本。

Research Impact Score / 研究价值 9.7/10 · 工业成熟度 ★★★★★ · 创新性 ★★★★★ · 与你方向的相关度 ★★★★★ · 是否官方开源 未发现 · 是否有线上 A/B 是 · 阅读优先级 S+

证据：预训练约 1600 万用户 / 110 亿 token；ranking 约 1100 万用户 / 3.7 亿曝光；线上 Orders +3.38%、GMV +9.85%，A10 QPS 只下降 12.1%。

押注：跨场景 foundation ranker、adapter routing、预训练 state 与 Chronicle user cache 共用、不同 sparse/dense learning clock、request-level sequence budget。

问题 03 · 持续学习时，新偏好应该写回共享模型，还是写入独立状态？

Continual Fine-tuning → Anti-forgetting Regularization → Sparse Mutable Memory

核心矛盾：把所有流式新行为都更新到共享 generative decoder，会让高频行为主导梯度，稀有 / inactive user preference 被覆盖；per-user adapter 又随用户规模线性增参。

关键推进：Self-Evolving Memory / LION 用 query-driven sparse KV memory 只激活局部 cell，给 preference delta 独立写入空间；consolidation loss 再强化稀有偏好。参数规模约 2Nd，不随用户数线性增长。

承接：ChronicleRec 解决 serving 侧“历史如何缓存”，DRIFT 解决“哪些历史阶段值得读”，LION 进一步解决训练侧“新变化写到哪里”。

押注：统一 mutable memory + cacheable user state、memory TTL/compaction、drift-triggered write、分布式一致性与版本兼容。

问题 04 · Top-K 真的是检索预算吗？

Fixed Top-K → Score-based Early Exit → Certified Access Budget

核心矛盾：Hybrid Retrieval 中“各路取 Top-100”看起来固定，真实成本却不固定：query 重叠、list 排名和融合上界不同，exact RRF Top-K 需要的访问数呈长尾。Top-K 是输出规模，不是资源预算。

关键推进：DiBud 以 access budget 为输入，增量读取 sparse/dense list，只在可以数学认证相对次序时输出 exact RRF prefix，在固定成本下最大化 certified output。

Research Impact Score / 研究价值 9.0/10 · 工业成熟度 ★★★☆☆ · 创新性 ★★★★☆ · 与你方向的相关度 ★★★★★ · 是否官方开源 是 · 是否有线上 A/B 否 · 阅读优先级 S

证据：预算 2048 accesses 时 certified output 比 balanced access 高 7.86%；校准到 95% quality 后，held-out nDCG@20 95.05%–97.68%，访问量减少 65.92%–99.53%。

押注：heterogeneous cost（ANN probe / inverted posting / graph hop 成本不同）、P95-aware budget、与 reranker/LLM context budget 联合控制。

问题 05 · Deep Search 为什么第一轮就决定了后面的大部分上限？

Single Query → Iterative Search → Planned First Move

核心矛盾：如果第一轮 retrieval 把问题压进错误证据子空间，后续 Agent 多轮搜索常只是围绕错误证据继续扩展。复杂 query 的多个 clue 不应被一个搜索式绑在一起。

关键推进：Question’s Gambit 把 first move 独立成 clue decomposition → complementary queries → pooled results → rerank，然后再进入原 agent loop。

Research Impact Score / 研究价值 9.2/10 · 工业成熟度 ★★★☆☆ · 创新性 ★★★★☆ · 与你方向的相关度 ★★★★★ · 是否官方开源 是 · 是否有线上 A/B 否 · 阅读优先级 S

证据：GPT-5.5 在 BrowseComp-Plus accuracy 83.1→90.5，gold evidence recall 72.9→85.9。

承接：GeneralQPP 判断“够不够” → SAFARI 学“是否继续探索” → Question’s Gambit 学“第一步怎么走” → DiBud 学“走多深才符合预算”。

押注：first-move value predictor、简单 query bypass、并发 clue budget、end-to-end successful-task latency reward。

问题 06 · 多兴趣模型为什么最后学成几个几乎一样的向量？

Diversity Regularization → Multi-positive Exclusive Assignment

核心矛盾：传统方法把 collapse 当 representation similarity；但如果一个 training example 只有一个 positive，主损失本身会长期只更新同一个最匹配 interest。

关键推进：MIMA 将同 request 多 positive 形成 set，用 Hungarian one-to-one assignment 让不同正样本独占不同 interest，再学习 activation probability 校准各 channel。

押注：soft assignment、dynamic K、长期 slot identity、MoE expert / memory-cell ownership；先检查 credit assignment，再加更多正交 loss。

问题 07 · 超长用户历史应该每个 Candidate 都重新检索，还是压成可复用状态？

Target-aware Retrieval → Target-independent Compression → Temporally Anchored Cache

核心矛盾：SIM/TWIN 式 target-aware retrieval 精度强但 candidate loop 成本大；简单 summary token 可缓存，却常缺时间结构与互补性。

关键推进：ChronicleRec 用 recency-aware merge、interleaved query tokens、multi-horizon masking，让 Chronicle Tokens target-independent 且时间锚定，可每个用户只计算一次。

问题 08 · 为什么历史越长，推荐准确率可能反而下降？

Full History → Semantic Retrieval → Preference-stage Modeling

核心矛盾：历史中存在“语义相似但处于错误兴趣阶段”的行为；加长 sequence 或增大 retrieval K 可能引入 preference-inconsistent noise。

关键推进：DRIFT 用 semantic/time/category distribution drift 学 soft boundary，把历史切成 preference-consistent subsequence，再由 recent context 选择读取。

问题 09 · Relevant Item 已在 Top-K 池里，却没进入下游短名单，应该重训召回器吗？

问题 10 · Linear Attention 解决长 Prompt 后，为什么 Generative Rec 仍卡在大 Beam？

Per-beam Full State → Shared Context + Transition Log + Ancestry

关键推进：OneLA 只保留一份 shared prefill state，每步记录紧凑 transition record，用 ancestry index 表达 beam 分叉；end-to-end decode 1.54–2.46×。

问题 11 · 粗排与精排各自变强，整条链路为什么仍可能变差？

Stage-wise Optimization → Teacher Alignment → Joint Fusion → Generative Fast Lane

承接：COPR / Rethink / HCCP → PTDG / MORE → UniRec 的 shared embedding + vertical consistency + horizontal preference aggregation → VARG 的 reserved generative quota + final ranker。

核心判断：跨阶段统一不等于“一个大模型吞掉所有 stage”，更现实的是统一 state / supervision / verification contract，训练目标更联合，serving 仍保持 stage-local 与可回退。

押注：用 downstream survival、ranker advantage、business value 作为上游可蒸馏信号，同时保持 stage-level SLO 与故障隔离。

问题 12 · Retrieval Encoder 可以像 LLM 一样动态调算力吗？

Dense Retriever → MoE Retriever → Query-time Expert Budget

关键推进：MoE Language Models as Retrievers 在统一条件下可比相近 active params 的 dense 模型最高 +3.0 nDCG@10；最强配置用约 59% 更少 active params 匹配 8B dense，并可 query-time 减少 experts、无需重训练 / 重建 index。
