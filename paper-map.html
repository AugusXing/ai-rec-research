不是按年份堆论文，而是沿“核心矛盾”读技术

Paper Map 持续回答：上一种方法解决了什么，为什么还不够，下一篇关键工作把矛盾推进到了哪里？今天新增三类非常值得长期追踪的问题：GraphRAG 的控制环是否必须由 LLM 驱动？可复用 KV 离开出生上下文后还能不能保持正确？低比特 embedding 的平均误差很小时，ANN 为什么仍会做错关键决策？

当前推荐精读路线：检索主线：SAM-D2Q → LiteRAG → Low-bit Vector Search，从“生成检索资产”读到“在线图控制”再读到“近似表示如何保持最终 decision”；State/Serving 主线：DoPR / ReST → HiCache / SLOWeave → KVShareArena → KV Concat-aware + Recomputation；Agent 主线：IGPO / AtomRec → Elastic Horizon / EdgeMem → RobustSGPO。
问题 01 · 倒排索引 vocabulary mismatch，但线上又不能跑大模型怎么办？

Doc2Query → Multimodal Expansion → Business-aligned Offline Asset

核心矛盾：keyword search 延迟低、精确匹配强，但 title 覆盖不了用户语言和视觉属性；在线 VLM 又太贵。

承接关系：BM25 / inverted index → Doc2Query → multimodal expansion → SAM-D2Q。最关键的范式是把大模型与 RL 的智能写成可被成熟检索系统消费的离线资产。

值得押注：adaptive expansion budget、sparse+dense hybrid、生成 uncertainty、索引 TTL/versioning。

问题 02 · 多跳检索需要图，但 query-time 图遍历为什么一定要付多轮 LLM 成本？

LLM-driven GraphRAG → Query-conditioned Algorithmic Retrieval

核心矛盾：图能表达跨文档关系，但用 LLM 做 graph navigation、community summary 与 evidence aggregation 会把 retrieval SLA 变成生成 SLA。

承接关系：Dense RAG → GraphRAG Local/Global/DRIFT → Light/Linear Graph RAG → LiteRAG。LiteRAG 用 semantic/lexical/community anchor、动态扩张阈值和 hub penalty，把在线图探索改成可设预算的算法。

Research Impact Score / 研究价值 8.9/10工业成熟度 ★★★☆☆创新性 ★★★★★与你方向的相关度 ★★★★★是否官方开源 计划开源，当前未确认仓库是否有线上 A/B 否阅读优先级 S

关键证据：DistComp D1280 Q_total 0.798、1.42s/query；相对 GraphRAG Global/DRIFT，论文报告 100×+ latency reduction 和 99%+ cost reduction。

值得押注：graph freshness、hybrid sparse/dense anchors、query-adaptive hop budget、retrieval confidence → model router。

问题 03 · 量化后 cosine / rank correlation 都很好，为什么 top-k 还是会坏？

Representation Distortion → Decision Flip Risk

核心矛盾：ANN 不直接消费“平均 embedding 重构误差”，它消费的是大量局部比较：谁更近、谁被 prune、谁刚好跨过 top-k 边界。全局指标可能掩盖 hard-margin query 的灾难性翻转。

承接关系：binary/PQ/BBQ/RaBitQ → reconstruction/rank metric → decision-level quantization analysis。论文把 flip risk 分解为 exact margin 靠近 0 的 boundary mass + calibrated residual tail，并把同一思想扩展到 Vamana pruning trace。

Research Impact Score / 研究价值 8.8/10工业成熟度 ★★★★☆创新性 ★★★★★与你方向的相关度 ★★★★★是否官方开源 未确认是否有线上 A/B 否阅读优先级 S

关键证据：某 int4 设置整体 edge correlation 0.997、总体 flip 2.1%，但最难 20% margin 中 flip 达 10.1%；GIST 1-bit 随机 rotation 可将 flip 从 100% 降至 14.8%。

值得押注：query-adaptive bit-width、hard-margin fallback、index-build certificate、online decision-drift detector。

问题 04 · CTR→CVR→GMV 的依赖为什么对所有样本都一样？

Fixed Funnel → Dynamic Task Graph → Task-aware Backbone

核心矛盾：业务漏斗存在硬因果，但 task correlation 随 item/user/context 变化；如果区分任务太晚，backbone 已提前丢失任务特定证据。

承接关系：ESMM → MMoE / PLE → PTDG dynamic dependency → MORE task-aware information flow inside every backbone layer。

Research Impact Score / 研究价值 9.3/10工业成熟度 ★★★★★创新性 ★★★★★与你方向的相关度 ★★★★★是否官方开源 未确认是否有线上 A/B 是阅读优先级 S+

关键证据：MORE 陌陌线上 usage duration +3.0%、interaction +3.6%、deep chat +2.0%，同时 scoring latency 约 -30%。

值得押注：task graph × anchor/token routing、delayed reward、request-level user-state reuse、candidate-adaptive depth。

问题 05 · 生成式重排为什么还要自回归生成 N 个序号？

Autoregressive List → Permutation Structure → Single-pass Assignment

核心矛盾：排序输出是 permutation，不是开放文本；逐 token 生成 N 个位置支付了不必要的自回归依赖。

承接关系：listwise LLM reranking → constrained generation → hLLM / Hungarian assignment。

值得押注：assignment + diversity/business constraints、GPU batched matching、partial assignment、与 candidate state reuse 联合。

问题 06 · 同一 user/document 为什么对每个候选/query 都要重算？

Full Cross-encoder → Reusable Document / User State

核心矛盾：query/candidate 变化快，但 document/user history 大量重复；cross interaction 质量高却重复算贵。

承接关系：LLM reranker → prefix/KV reuse → DoPR；长用户序列方向对应 ReST。它们共同把“模型中间表示”升级为长期可复用 state。

Research Impact Score / 研究价值 9.0/10工业成熟度 ★★★★☆创新性 ★★★★★与你方向的相关度 ★★★★★是否官方开源 DoPR：是是否有线上 A/B ReST：是阅读优先级 S

值得押注：state quantization/versioning、跨 worker reuse、DoPR × structured decode、state freshness。

问题 07 · KV Cache 离开“出生上下文”后还能直接复用吗？

Prefix Cache → Non-prefix Reuse → Compatibility-aware Repair

核心矛盾：独立缓存的 chunk 进入新 prompt 后，position 变化；多个 source 原先没有互相 attention；producer checkpoint 变化后又可能出现分布 shift。只统计 cache hit rate 会把“错着复用”当成功。

承接关系：prefix caching → position correction / CacheBlend / KV repair → KVShareArena。它用 context change × checkpoint change 的二维 board 和 PGR 指标统一评价恢复质量与 recompute/bytes/TTFT。

Research Impact Score / 研究价值 8.8/10工业成熟度 ★★★★☆创新性 ★★★★★与你方向的相关度 ★★★★★是否官方开源 论文称已开放 package/leaderboard，URL待确认是否有线上 A/B 否阅读优先级 S

关键证据：multi-hop free alignment PGR 可到 -0.196；training-free repair 对同架构 checkpoint shift 多数稳定，而 producer-fitted adapter 更易失效。

值得押注：producer fingerprint、cache schema、dependency estimator、receiver-side rebuild、按 query 动态 recompute。

问题 08 · 长上下文 KV 复用是训练模型适应，还是在线选择性重算？

Block-aware Fine-tuning + Selective Recomputation

核心矛盾：完全独立 cache 快但缺 cross-chunk attention；full recompute 准但 TTFT 高。把两条路线当成二选一会浪费空间。

承接关系：chunk KV caching → Block-attention model / CacheBlend → KV concatenation-aware model + 15% recomputation。

Research Impact Score / 研究价值 8.7/10工业成熟度 ★★★★☆创新性 ★★★★☆与你方向的相关度 ★★★★★是否官方开源 未确认是否有线上 A/B 否阅读优先级 S

关键证据：124k RULER 56.7 vs CacheBlend-only 47.0；SSD KV 场景 TTFT 比 full attention 约 -80%。

值得押注：dependency-aware recompute ratio、SSD/host/GPU tier routing、与 KVShareArena compatibility score 联动。

问题 09 · 可复用状态变多后，谁来管理位置、重复、精度和生命周期？

GPU-local KV → Multi-tier State Cache → Runtime Contract

核心矛盾：计算转成可复用 state 后，瓶颈从 FLOPs 转成容量、搬运、ownership、一致性、dtype/layout 与 failure recovery。

承接关系：Paged KV → cache-aware routing → HiCache MLA host-dedup → NVFP4 capability contract → KVShareArena compatibility。

问题 10 · “模型引用了证据”能不能从 soft score 变成 hard guarantee？

Faithfulness Judge → Verbatim Span Constraint

核心矛盾：RAG factuality judge 只能事后打分，无法阻止模型在生成引用时改写或拼造不存在的 evidence。

承接关系：citation prompting → extractive hybrid generation → CHyD。进入 evidence mode 后，下一 token 只能是输入 context 某连续 span 的合法 continuation。

问题 11 · Agent 可以修改自己的 Harness，但为什么总是在改 Prompt 文案？

Free-form Self-edit → Typed Search-space Control

核心矛盾：“允许改任何组件”不等于 LLM 真会提出 handoff、routing、add/remove agent 等结构改动；自由文本 patch 还容易无效或污染非目标对象。

承接关系：prompt optimization → SGPO semantic gradient → RobustSGPO typed edit plan + exact-target check + category archive + paired replay。

问题 12 · Agent 的 horizon、memory 和通信拓扑为什么还是静态超参？

Fixed Agent Scaffold → State-aware Dynamic Controller

核心矛盾：更多 step、更多 memory、更多 agent 并不总能带来更多有效信息，反而消耗 token 和增加错误传播。

承接关系：prompt memory → IGPO / AtomRec → Elastic Horizon / EdgeMem / ReActNet → RobustSGPO workflow evolution。
