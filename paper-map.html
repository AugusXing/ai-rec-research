主线 A

Generative Retrieval → Reliable GenRetrieval

从生成 Item，到组织 Semantic ID，再到可靠解码、Coverage 与 Hybrid Recovery。

1. Item-as-Token

OneRec-V2 / JD GenRec 把召回改成条件生成，并把真实反馈 / RL 带入 Post-training。

OneRec-V2JD GenRec→问题：Identifier 怎么组织？
2. Semantic ID 成为基础设施

FORGE 统一语义/协同信息；HD-Rec 用层级 Codebook + Routing 做跨域；Audio/SID Study 说明容量不是越大越好。

FORGEHD-Rec
3. SID 公平性 / Coverage

FSGR 指出 Token Frequency Bias：高频 SID 被过预测、低频 SID 被低估；用 Balanced Quantization + Frequency Calibration 修正。

FSGR新指标：Codebook Coverage / Token Gini / Long-tail Exposure。
4. Prefix Error → Hybrid Recovery

DrIG 用 Dual-role Identifier 与 Set Prior 约束 Beam，再用 Dense Rerank 做精度恢复。

DrIG
★★★☆☆ 当前矛盾：Beam / ID / Rerank 成本如何按 Query 分配？
5. Full-stack Replacement

Sona 直接替代 15+ Candidate Generators、Pre-rank、Rank。

Sona★★★★★
主线 B

Ranking：Feature Tower → Transformer-native → Robust Policy

架构之外，输入不确定性、目标对齐与请求级算力开始成为核心变量。

1. Mature Multi-task Ranking

RankMixer 等把 Expert / Mixer 与序列建模做到成熟工业化。

RankMixer
2. Transformer-native Ranking

OneRank 用 Task Token、Cross-task Attention、Candidate Context 与 Dynamic Matching 移除 Encoder–Predictor 边界。

OneRank★★★★★
3. Structured / Target-aware Representation

STAR 表明 PCVR 中时间特征、Padding Contract、Structured Token 与 Target-aware Decode 仍是高 ROI 能力。

STAR
4. Noisy Upstream Prediction

DrEM 同时修监督侧与 Feature-side pxtr Noise，并在大规模短视频线上验证。

DrEM★★★★★问题：Uncertainty / Calibration 如何进入 Ranker？
5. List Policy / Reasoning

GR2 / MetaStrategy 让模型输出列表策略；REAM 开始压 Recommendation Reasoning Length。

GR2MetaStrategyREAM
主线 C

Retrieval Adaptation：Static Embed → Test-time Policy

Retriever 从固定 Query Encoder 走向可按请求追加计算的表示系统。

1. Static Dense Retrieval

训练完成后 Query → Embedding → ANN 基本固定；适配新任务通常依赖再训练。

2. Reranker Reward → Query Vector

TTT-Embed 冻结 Encoder / Index，只根据标量 Ranking Reward 优化 Query Embedding。

TTT-EmbedRetriever 与 Reranker 的边界变软。
3. Reasoning-before-Embedding

GEM 先生成 Reasoning，再生成 Embedding Token，使 Test-time Reasoning Budget 能改变 Retrieval Quality。

GEM
4. Runtime Router

下一步是判断：这个 Query 直接 Embed、做几步优化、先 Reason、还是直接 Rerank？

值得押注：Query Difficulty / Value Router。
主线 D

Long Sequence / Scaling / Serving

从“更长更大”转向“哪些 Token / KV / Expert 值得付费”。

1. Long Context

OneRec-V2 / Netflix Scaling 证明长行为和规模有效，但 Prefill、Attention、吞吐成为第一约束。

Netflix Scaling
2. Teacher 保真，Student 压 Token

TM20K：Full-attention Teacher 处理 20K 历史，线上 Student Token Merge。

TM20K★★★★★
3. KV Cache 也变成 Retrieval 资源

CoinRAG 从 Chunk Cache 推到 query-relevant information nugget + KV slice composition。

CoinRAG
4. Request-aware Compute

Meta Adaptive Ranking、SGLang 等把 Routing、FP8、多卡、Session Cache 与 Workload 绑定。

统一问题：每个请求到底值得算多少？
主线 E

Preference Alignment / Recommendation RL

从行为监督到可学习业务 Reward；难点从 Optimizer 迁移到 Reward 语义。

1. Feedback-aware Post-training

OneRec-V2、JD GenRec、GR2 把真实反馈 / RL 引入召回和重排。

JD GenRec
2. Adaptation ≠ Business Alignment

Progressive Alignment：LP → FFT → RFT；密集行为学 Policy，稀疏业务指标学 Reward。

Progressive Alignment★★★★☆
3. Long-term Reward

留存、疲劳、多样性、生态、GMV、体验如何统一，以及如何避免 Reward Hacking，仍是未解核心。

主线 F

Agentic Search / RAG → Context Runtime

检索不再只是 Top-K，相当一部分决策变成“读多少 / 读哪路 / 什么时候停”。

1. Answer-aware Retrieval
Agentic-R→相关性 ≠ 最终答案价值。
2. Joint Retriever + Reasoner
CoSearch
3. Context Interference / Refinement
Context Interference

证据越多不一定越好，Context 需要独立 Ranking / Refinement。

4. Adaptive Retrieval Depth

EAHR 让 Hybrid Retrieval Depth 成为 Query-specific State；DocMemo 用 Bayesian Belief + Thompson Sampling 管 Evidence Exploration。

EAHRDocMemo
5. Learned Stopping

Search-R1 Stopping 用独立 Judge 判断“证据是否够了”，减少 3.70% Retrieval Calls，但不声称总成本一定下降。

Search-R1 Stopping下一步：Utility / Cost Joint Policy。
主线 G

Full-stack Unification / Model-System Co-design

模型侧与系统侧同时侵蚀传统 Cascade 边界。

1. Model-side Unification

Sona 以单一生成模型替换 15+ 召回源、粗排与精排。

Sona★★★★★
2. System-side Unification

SilverTorch 把 Index、Filter、ANN、Neural Rerank、Multi-task Scoring 收进 GPU-native Model Graph。

SilverTorch★★★★★
3. Auto Optimization

KernelEvolve 等让 Agent 自动搜索 Kernel / Infrastructure 优化。

问题：统一后如何控制故障域、显存、版本与成本？
主线 H

Model Routing / Dynamic Compute

推荐系统成熟的 Cascade、Calibration、Bandit 思想正在迁移到 LLM / Agent。

1. Planner + Executor

ConnectionMind / MetaStrategy 都体现“大模型做策略、小模型高并发执行”。

ConnectionMindMetaStrategy
2. Routing 的经济学前提

Pre-Inference Routing：Cheap Model 要有足够 Failure Rate，且 Failure 必须可预测，否则 Router 没有经济价值。

Pre-Inference Routing
3. Unified Request Value Estimator

未来可能统一决定 Retriever、K、Ranker、Reasoning Steps、Rerank Depth 与 Stop Timing。

2026 下半年最值得押注。

推荐精读路线

  1. 生成式推荐：FORGE → OneRec-V2 → HD-Rec → FSGR → DrIG → Sona。
  2. 召回 / 检索：EAHR → TTT-Embed → GEM → Search-R1 Stopping，理解 Static Retrieval 如何变成 Runtime Policy。
  3. 精排 / 重排：RankMixer → OneRank → DrEM → GR2 / MetaStrategy → REAM。
  4. Serving / 系统：TM20K → CoinRAG → SilverTorch → Adaptive Ranking，重点看 Cost / QPS / Latency 如何进入算法设计。
  5. 未来选题：优先关注 Per-request Compute Allocation、SID Fairness、Uncertainty-aware Ranking、Context Stopping 与 Hybrid GenRetrieval。
