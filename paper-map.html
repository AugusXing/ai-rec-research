不是按年份堆论文，而是沿“核心矛盾”读技术

今天新增四条很清晰的问题链：视觉 RAG 如何在 Late Interaction 表达力与生产 TCO 之间折中？复购推荐为什么应该从固定 horizon 分类转向 time-to-event？Agent 如何同时管理 trajectory retrieval 与 context state？低比特 Serving 怎样从统一 bit-width 走向 token/scale-level sensitivity？

今日推荐精读路线：如果只读 5 篇，按 PULSAR → Timing-Aware Repurchase → ContextPilot → HyQuant → ITER。第一篇看生产级检索系统，第二篇看推荐目标重定义，第三篇看 Agent state/control，第四篇看 Serving precision budget，第五篇把 Agentic Search 和 session-based retrieval 连起来。做 Blackwell 量化再补 H-Scale，做 Agent Infra 再补 Logos。
问题 01 · 多模态 RAG 怎样同时保留视觉细节与低延迟？

OCR-first → Unpooled Late Interaction → Pooled Two-stage Late Interaction

核心矛盾：OCR/figure verbalization 会损失图表信息且 refresh 昂贵；ColPali-style multivector 又带来极高 RAM 与 MaxSim 成本。

承接关系：Text OCR RAG → Vision Encoder + Single Vector → ColPali/ColQwen Late Interaction → PULSAR：compact pooled prefetch + finer pooled MaxSim rescoring + event-driven refresh。

Research Impact Score / 研究价值 9.8/10工业成熟度 ★★★★★创新性 ★★★★☆与你方向的相关度 ★★★★★是否官方开源 完整系统未确认是否有线上 A/B 无；有生产部署/内部对照阅读优先级 最高

代表 Paper：PULSAR。ViDoRe V3 相对 unpooled ΔNDCG@10=-0.0088、ΔRecall@10=-0.0074，median vector-search 约 15.1× 更快、RAM 约 14× 更低；生产覆盖 2.4M 页。

值得押注：query-aware pooling、region-level second stage、visual/text dual-index router、refresh-aware multimodal index、端到端 fact recall × ingestion cost。

问题 02 · 推荐目标天然含时间时，为什么还要做多个 Binary Label？

Horizon Classifier → Survival/AFT → Ranking / Calibration Bifurcation

核心矛盾：7/14/30-day 各训一个模型浪费训练/Serving 资源，也让跨 horizon 概率可能不一致；binary task 还把 censoring 与具体时间抹掉。

承接关系：Binary CTR/CVR/Repurchase → Multi-task Horizon Model → Timing-Aware Repurchase：直接预测 time-to-event，再由同一 distribution 派生各 horizon score/probability。

Research Impact Score / 研究价值 9.5/10工业成熟度 ★★★★★创新性 ★★★★☆与你方向的相关度 ★★★★★是否官方开源 否 / 未发现是否有线上 A/B 未披露阅读优先级 最高

代表 Paper：Timing-Aware Repurchase。一个 AFT 替代三个分类器、总树数约 1/3；Log-Normal ranking 最佳，而 Exponential AFT 的 ECE ~1e-4，约比 Log-Normal 低一个数量级。

值得押注：Sequence Survival、competing risk、time-dependent utility、calibrated ranking、多 surface 共享 time-to-event foundation objective。

问题 03 · Agent Context 太长时，删除/摘要应该是 Heuristic 还是 Policy？

Truncation → Passive Summary → Proactive Tools → Fine-grained RL

核心矛盾：所有历史都保留导致 token/TCO 爆炸；粗暴摘要会丢证据；trajectory-level reward 又无法告诉模型“到底哪一次压缩/记忆是好动作”。

承接关系：Sliding Window → ReSum / Memory Agent → StateLM proactive context tools → ContextPilot：planning + soft offloading + long-term memory + context-aware branch sampling + snapshot credit。

Research Impact Score / 研究价值 9.5/10工业成熟度 ★★★★☆创新性 ★★★★★与你方向的相关度 ★★★★★是否官方开源 是是否有线上 A/B 否阅读优先级 最高

代表 Paper：ContextPilot，Qwen3-8B SFT avg 65.78 → RL 69.40；BrowseComp+ 48.84→54.18。Official Code

值得押注：token-cost reward、cross-session memory、memory freshness/forgetting、context manager × retriever joint RL、User State 与 Agent Memory 统一。

问题 04 · Deep Search Retriever 为什么不能只看当前 Sub-query？

Step-local Retrieval → Main-question-aware → Trajectory-relative Retrieval

核心矛盾：Agent 的后续检索目的取决于此前已覆盖的信息；“再次找到同一个 useful doc”可能反而是冗余。

承接关系：Dense Retriever → AgentIR/LRAT trajectory training → ITER：main question + previous subqueries 进入 query representation，visited useful docs 在后续成为 redundancy negatives。

Research Impact Score / 研究价值 9.2/10工业成熟度 ★★★★☆创新性 ★★★★☆与你方向的相关度 ★★★★★是否官方开源 论文声明链接，当前 404是否有线上 A/B 否阅读优先级 很高

代表 Paper：ITER，跨 6 个 agent backbone 相对 LRAT 平均 +7.5% InfoSeek-Eval、+13.5% BrowseComp-Plus。

值得押注：coverage-aware negative、session novelty reward、trajectory state compression、context-control × retrieval joint policy。

问题 05 · 4-bit 量化为什么不应该“一刀切”？

Uniform Quantization → Outlier-aware → Token-aware / Scale-aware Precision

核心矛盾：长上下文 attention 的信息价值高度不均；NVFP4 每 16 个权重一组的 scale 也高度敏感。统一低比特会把预算浪费在不敏感位置，同时伤害关键位置。

HyQuant · Token-aware Hybrid Precision

HyQuant 保留 vertical-line + local-window 高精度，其余 attention/KV 4-bit；32K kernel 相对 FA2 报告 ~3.58×。Code

H-Scale · Scale-aware NVFP4 Refinement

Research Impact Score / 研究价值 9.1/10工业成熟度 ★★★★☆创新性 ★★★★☆与你方向的相关度 ★★★★☆是否官方开源 未发现是否有线上 A/B 否阅读优先级 高

H-Scale 用 activation-derived diagonal Hessian proxy 从硬件合法 scale 中选择更好的 NVFP4 per-group scale，作为 PTQ post-process，零在线开销。

值得押注：request/layer/head/token precision router、KV+weight joint quantization、Blackwell native format co-design、accuracy-latency-memory 三目标 policy。

问题 06 · Agent 的 Fault Domain 应该和单个 Python 进程绑定吗？

In-process Plugin → External Tool Server → Cross-process Composition + Durable Transcript

Research Impact Score / 研究价值 8.5/10工业成熟度 ★★★☆☆创新性 ★★★★☆与你方向的相关度 ★★★★☆是否官方开源 未确认是否有线上 A/B 不适用阅读优先级 高

代表 Paper：Logos。Plugin=process，router 只持 routing table，session state 在 append-only transcript；80 sessions 四类 kill point 后恢复且不重复 effect，bus hop median 0.215ms。

值得押注：Agent idempotency、exactly-once boundary、durable replay、权限隔离、cross-language tools、state ownership。

问题 07 · 推荐/搜索的 Offline Metric 能否支持真实决策？

nDCG/AUC → Decision Stability → Calibration → Causal Value

承接关系：OC-SFT 说明相同 nDCG 可以产生不同 retained set；Evidence-aware RAG 说明更语义化的 relevance 不必然支持 training/system selection；Stageboost 用 counterfactual value 证明 action recommendation 需要因果增量；今天的 Survival Repurchase 再补一层：ranking 几乎相同，calibration 仍可相差 10×。

值得押注：Decision Stability、Calibration、Causal Incrementality、Time-to-event、offline→online validity contract。

问题 08 · ANN/Serving 的“快”应该怎样定义？

Peak QPS → Build/Refresh Economics → Runtime Correctness

代表节点：misi 把 build time / peak RAM / refresh 纳入 ANN 设计；vLLM/SGLang 最近的 graph/KV/top-k fixes 说明 silent semantic corruption 必须作为性能评测的一等维度；PULSAR 则把 ingestion cost、RAM、median/p95/p99、answer-fact recall 同表报告。

值得押注：Index lifecycle optimizer、correctness guard、safe fallback router、build/refresh-aware experimentation。
