Research Problem Map · 更新至 2026.09.04

不是按年份堆论文，而是沿“核心矛盾”读技术

今天技术树新增的核心问题是：生产推荐的控制面能否由 Agent 持续优化？模型能否自己声明哪里值得算？RAG 的 reward 能否落到每一步证据？长期 Agent 记忆应先归因还是先写？Model Routing 如何从“选模型”扩展到“选 worker / 设备 / 上下文”？这些问题共同把研究重心推向 Autonomous Control、Process Credit 与 Utility-per-Compute。

今日推荐精读路线：CORAL → Declarative Attention → PRO-Step → Graph Machine → CHIME。第一篇看真正生产级 Agentic Recommender control plane；第二篇看模型声明 compute scope；第三篇看 process reward；第四篇看动态地址式长状态；第五篇看长期 memory 的 credit assignment。做推荐召回再补 SPAR / SetMIR / ICEGR，做 Serving 再补 Spotify Shunt / NVIDIA PAIR / DS-Frame。
问题 01 · 生产推荐系统的控制面能否自动持续优化？

Manual Tuning → AutoML → LLM-native Control Harness

核心矛盾：推荐系统真正影响业务的不只是一个模型，而是 retrieval budget、source allocation、ranking weights、Serving treatment、缓存和人群策略。工程师只能低频探索很小配置空间，而且最优配置会随流量和供给持续漂移。

承接关系：Offline HPO / BO → Agentic analysis → live experiment loop → CORAL。

Research Impact Score / 研究价值 9.8/10工业成熟度 ★★★★★创新性 ★★★★★与你方向的相关度 ★★★★★是否官方开源 否是否有线上 A/B 是，两个大规模生产场景阅读优先级 最高

代表 Paper：CORAL。LLM Agent 读 observation / assessment / decision memory，使用分析/检索/数值优化工具提出配置；deterministic optimizer 将动作投影到预算可行集，再部署 A/B 并写回结果。

工业证据：retrieval-budget case 第三轮 watch time +0.15%、sessions +0.16%，最大市场 sessions +0.77%；Serving-capacity case 第一轮实现年化数百万美元节省，第二轮再扩大 savings 44%，engagement 不变。

值得押注：causal attribution、active experimentation、multi-agent interference、delayed reward、experiment traffic allocation、control-plane observability。

问题 02 · 模型能否自己告诉 Runtime“我现在需要看哪里”？

Dense Attention → External Sparse Selector → Declarative Attention

核心矛盾：长上下文 decode 每步读取完整 KV cache 很昂贵；传统 query-dependent sparse selector 即使稀疏，往往仍要扫描长上下文。

承接关系：Full Attention → fixed sparse / heavy-hitter → learned selector → model-declared global / focus / local scope。

Research Impact Score / 研究价值 9.1/10工业成熟度 ★★★★☆创新性 ★★★★★与你方向的相关度 ★★★★☆是否官方开源 vLLM integration 描述完整；独立官方仓库未确认是否有线上 A/B 否阅读优先级 最高

代表 Paper：Language Models Can Control Their Own Attention。模型通过 declarative tags 决定 full context、指定 chunk 或 local-only；vLLM 侧只需重写 block table。

关键结果：Gemma-4-31B / Qwen-3.6-27B attended tokens 平均 -52.0% / -31.1%，accuracy -1.27pp / -2.75pp；roofline decode cost 预计 0.71× / 0.77×。

值得押注：post-training declarative compute policy、attention scope × RAG top-k 联合控制、query/source/interest declarative routing、confidence-based recovery。

问题 03 · RAG 最后答对，不代表中间每一步都对

Outcome Reward → Process Judge → Evidence-grounded Step Preference

核心矛盾：最终答案 reward 无法定位 retrieval/reasoning 的错误传播；如果中间 step 仍按最终答案判，也会把偶然答对的错误证据路径当成好 trajectory。

承接关系：Outcome RL/DPO → Process Reward → PRO-Step logical validity + evidence grounding。

Research Impact Score / 研究价值 8.8/10工业成熟度 ★★★☆☆创新性 ★★★★★与你方向的相关度 ★★★★★是否官方开源 是，代码/模型/数据是否有线上 A/B 否阅读优先级 最高

代表 Paper：PRO-Step。先训练 generative PRM，再做 PRM-guided value tree search 生成 valid/flawed step pairs，最后 step-level DPO。

官方代码：GitHub。

值得押注：query rewrite/source selection/retrieval path 的 step reward、生成式推荐 prefix credit、business outcome × evidence validity 联合 preference。

问题 04 · 长序列一定要在“扫全历史”和“压缩历史”二选一吗？

Dense KV Scan → Compressed State → Sparse Dynamic Addressing

核心矛盾：Transformer 能保留细粒度历史，却每步扫描大量 KV；RNN/SSM 每步便宜，却将历史压进固定状态。

承接关系：Dense Attention / SSM → sparse retrieval memory → Graph Machine pointer-like dynamic edges。

Research Impact Score / 研究价值 8.5/10工业成熟度 ★★☆☆☆创新性 ★★★★★与你方向的相关度 ★★★★☆是否官方开源 checkpoint 已公开；独立代码仓库未确认是否有线上 A/B 否阅读优先级 很高

代表 Paper：Graph Machine。Qwen3-0.6B 75% layer 替换成 GM sparse layer，从头训练 15.7B tokens；每个 KV head 仅访问 2–4 / 4096 token。

当前成熟度判断：4-token retrieval 的 pretraining loss 可略好于 dense baseline，但尚无大模型、长上下文 downstream 与端到端 wall-clock 证据，不能把理论 sparsity 直接等价成生产加速。

值得押注：推荐超长行为序列 learned pointer、GPU-friendly irregular sparse memory、dynamic address 与 user-interest state 联合训练。

问题 05 · 长期 Agent 记忆应该“先写再想”，还是“先归因再写”？

Outcome Memory → Structured Banks → Attribute-before-Memorize

核心矛盾：任务失败可能来自 plan、execution、环境；按最终 outcome 直接写经验会污染长期 memory。

承接关系：episodic memory → self-evolving memory → CHIME credit-aware hierarchical memory。

Research Impact Score / 研究价值 8.4/10工业成熟度 ★★★☆☆创新性 ★★★★☆与你方向的相关度 ★★★★☆是否官方开源 论文承诺发布；完整代码尚未确认是否有线上 A/B 否阅读优先级 高

代表 Paper：CHIME。planning bank + execution bank；先把 outcome 归因到 plan / execution / both / neither，再只更新对应 bank。

值得押注：memory confidence/freshness、cross-task transfer、错误归因纠正、实验记忆与生产告警的统一 attribution。

问题 06 · 为什么 Agent 每次都要从零发现同一批数据对象？

Metadata Search → Trajectory State → Persistent Discovery Context

核心矛盾：数据型 Agent 会反复把相近意图映射到相同 table/dashboard/object，但成功的 discovery 往往任务结束就丢弃。

Research Impact Score / 研究价值 8.2/10工业成熟度 ★★★☆☆创新性 ★★★★☆与你方向的相关度 ★★★★★是否官方开源 未发现是否有线上 A/B 否阅读优先级 高

代表 Paper：Beyond Context Windows: Persistent Discovery Context for Data-Centric Agents。保存历史 intent→successful-object mapping，未来 retrieval 作为额外 prior；3 个 structured-data environment 均优于 metadata-only。

关键风险：论文也复现了 memory interference：错误或过时映射会稳定污染未来 discovery。这意味着 persistent retrieval memory 必须有 freshness、置信度和 conflict resolution。

值得押注：企业搜索 query→source memory、推荐 source router prior、freshness-aware retrieval memory、权限/租户边界。

问题 07 · Semantic ID 只编码“语义”够吗？

Semantic ID → Query-aware SID → Domain-structured SID

核心矛盾：item 内容相似不代表业务上可互换。POI 受距离/方向/可达性约束，商品受库存/价格/类目约束，广告受 campaign/budget/audience 约束。

承接关系：RQ-VAE / TIGER → Tlow / TAGR → ICEGR Query-aware SID → SPAR SI-SID。

Research Impact Score / 研究价值 9.3/10工业成熟度 ★★★★☆创新性 ★★★★★与你方向的相关度 ★★★★★是否官方开源 论文承诺数据；代码未发现是否有线上 A/B 否阅读优先级 最高

代表 Paper：SPAR。SI-SID 显式融合地理坐标；MG-CPT 学道路/距离/导航；TV-SFT 用 task vector 保存空间知识。四个 AMAP 工业数据集上 8B 相对 PLUM 平均 +38.32%。

值得押注：constraint-aware codebook、time-dependent SID、inventory/budget-aware SID、constraint-aware decoding。

问题 08 · 多兴趣召回为什么不能永远固定 K 个 Query？

Single Vector → Fixed Multi-interest → Variable Set Prediction + Dynamic Dispatch

核心矛盾：真实用户兴趣数量不同；固定 K 个 head 会 interest collapse，也无条件消耗 K 次 ANN。

承接关系：MIND / ComiRec / KuaiFormer → SetMIR。

Research Impact Score / 研究价值 9.4/10工业成熟度 ★★★★★创新性 ★★★★★与你方向的相关度 ★★★★★是否官方开源 未发现是否有线上 A/B 是阅读优先级 最高

代表 Paper：SetMIR。10 个 ANN query 经 presence+NMS 后平均 6.70，R@10 保留 99.2%；线上整体 CVR +3.11%。

值得押注：interest marginal utility、cross-source budget、latency/TCO-aware dispatch、candidate overlap-aware assignment。

问题 09 · Generative Retrieval 为什么会“每阶段都对，整体跑偏”？

Content SID → Log SFT → Business Preference → Intent-coherent GR

核心矛盾：内容 SID 不一定代表 query intent；日志覆盖长尾不足；GMV preference 又可能牺牲 relevance。

Research Impact Score / 研究价值 9.1/10工业成熟度 ★★★★★创新性 ★★★★★与你方向的相关度 ★★★★★是否官方开源 未发现是否有线上 A/B 是，20% 流量两周阅读优先级 最高

代表 Paper：ICEGR。Recall@20 +21.7%、NDCG@20 +26.6%；线上 CTR +3.52%、订单 +15.96%、GMV +7.53%。

值得押注：cross-stage objective audit、fresh/query-conditioned SID、synthetic-to-real curriculum、GR/ANN joint router。

问题 10 · 为什么所有推荐请求都要跑同样深度？

Uniform One-pass → Conditional Compute → Learned Fast/Slow Routing

核心矛盾：easy request 不需要 heavy inference，hard case 又不能被统一轻量化牺牲。

Research Impact Score / 研究价值 8.8/10工业成熟度 ★★★☆☆创新性 ★★★★★与你方向的相关度 ★★★★★是否官方开源 是是否有线上 A/B 否阅读优先级 最高

代表 Paper：Recommender System as Slow and Fast Thinkers。Beauty/SASRec 上 40.2% slow activation，NDCG@10=0.0453，高于 Slow Only 0.0431，normalized cost 1.80× vs 3.00×。

今日连接：DS-Frame 决定“算多深”，Declarative Attention 决定“看哪里”，Spotify/NVIDIA 决定“交给谁、在哪里算”。它们有望汇成统一 compute router。
