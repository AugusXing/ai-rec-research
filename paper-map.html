Research Problem Map · 更新至 2026.09.08

不是按年份堆论文，而是沿“核心矛盾”读技术

今天 Paper Map 新增五个关键问题：倒排检索如何吸收多模态与业务价值？动态 inventory 下 Agent 如何不频繁重训？多任务漏斗如何摆脱固定依赖？长期推荐 memory 如何避免 coarse summary 覆盖偏好阶段？静态 ANN 如何快速吸收反馈？它们共同指向同一趋势：未来的推荐/搜索模型，不只是“预测器”，还是一组可资产化、可更新、可约束的状态系统。

今日推荐精读路线：SAM-D2Q → IGPO → PTDG → Embedding Surgery → AtomRec。先看如何把大模型能力写回成熟搜索 infra，再看策略与动态事实如何解耦，然后看排序任务结构如何动态化，最后看 feedback 与 memory 如何局部写回系统状态。
问题 01 · 倒排索引 vocabulary mismatch，但线上又不能跑大模型怎么办？

Text Doc2Query → Multimodal Expansion → Business-aligned Offline Index Asset

核心矛盾：keyword search 低延迟、可解释、精确匹配强，但 merchant title 覆盖不了用户语言和视觉属性；在线 VLM/LLM 又太贵。

承接关系：BM25 / inverted index → Doc2Query → multimodal Doc2Query → SAM-D2Q。

代表 Paper：SAM-D2Q。Qwen3-VL-8B + information-gain SFT + visual counterfactual augmentation + GRPO，把 query demand、visual evidence 与 PV×CVR 商业价值对齐；离线生成 pseudo-query 写入索引，线上不跑模型。AliExpress A/B：GMV +3.38%、Pay Count +2.27%，P99 recall latency 仅 +0.2%。

成熟度：★★★★★。有完整 offline→index→A/B→reverse bucket 证据。

精读路线：先看数据筛选如何避免 summarization shortcut → 再看视觉 counterfactual → GRPO reward → index insertion/filter → A/B 与 reverse bucket。

值得押注：adaptive expansion budget、query-cluster-specific generation、dynamic commercial reward、hybrid sparse+dense expansion、生成 uncertainty 与索引 TTL/versioning。

问题 02 · Inventory 每天变化，Agent 策略难道也每天重训？

Static Prompt Patch → Model Fine-tuning → Inventory-grounded Policy Layer

核心矛盾：库存事实变化快，但“遇到某类库存证据应该怎么决策”的策略变化慢；把两者都写进 prompt 或模型权重会快速 stale。

承接关系：prompt engineering → trajectory optimization / RL → IGPO policy guideline store。

Research Impact Score / 研究价值 9.0/10工业成熟度 ★★★★★创新性 ★★★★★与你方向的相关度 ★★★★★是否官方开源 未确认是否有线上 A/B 是阅读优先级 S+

代表 Paper：IGPO。在线 probe inventory→构造 portrait→检索 stage-specific Policy Guidelines；离线 grouped stochastic rollout + judge + contrastive evidence + replay gate 更新 policy，不更新模型权重。14 天 A/B：CTR +3.17%、bad cases -38.9%。

成熟度：★★★★★。已生产部署，且对 inventory-absence、composite query 有分类型结果。

精读路线：重点看“policy vs environment facts”约束、all-fail exploration、guideline patch validation 与线上 bad-case taxonomy。

值得押注：policy DSL、guideline conflict resolution、uncertainty-aware inventory probe、跨模型 portability、policy store 与 experiment platform 联动。

问题 03 · CTR→CVR→GMV 的依赖为什么对所有样本都一样？

Fixed Funnel → Shared Experts → Personalized Task Dependency Graph

核心矛盾：业务漏斗存在硬因果，但 task correlation 随 item/user/context 变化；固定层级会让深层 sparse task 信号在传递中衰减。

承接关系：ESMM → MMoE / PLE → explicit task graph → PTDG。

Research Impact Score / 研究价值 8.5/10工业成熟度 ★★★★★创新性 ★★★★☆与你方向的相关度 ★★★★★是否官方开源 未确认是否有线上 A/B 是阅读优先级 S

代表 Paper：PTDG。用 item-conditioned low-rank adjacency 动态“重连” task graph，以 hard causal mask 防止语义反流；APM 按任务稀疏度给共享参数不同 mask。线上 CVR +1.2%、eCPM +1.9%，额外 E2E latency 约 8ms。

成熟度：★★★★★。结构创新、offline、线上与 latency 证据齐全。

值得押注：context-conditioned DAG、task routing × expert routing、连续容量分配、delayed reward 与跨阶段任务图。

问题 04 · Dense Index 发现错误后，必须重训 encoder / 重建 ANN 吗？

Static Document Embedding → Query Adaptation → Localized Embedding Surgery

核心矛盾：用户/编辑/LLM feedback 到来很快，但文档向量与索引更新很慢；全量 retrain 对少量局部 ranking error 性价比低。

承接关系：static dense retrieval → query adaptation / Rocchio → document-side localized update。

Research Impact Score / 研究价值 8.2/10工业成熟度 ★★★★☆创新性 ★★★★☆与你方向的相关度 ★★★★★是否官方开源 未确认是否有线上 A/B 否阅读优先级 A+

代表 Paper：Embedding Surgery。把 pairwise ranking feedback 写成 margin constraints，求解“满足约束同时最小化 embedding 扰动”的 convex QP，然后原位覆盖少量 ANN vectors。DL-Hard editorial feedback 下 nDCG@10 最高相对 +60.64%。

成熟度：★★★★☆。ANN in-place overwrite 很贴近生产，但缺线上 A/B 与长期连续更新的 geometry drift 研究。

值得押注：TTL surgery、constraint conflict detector、vector version/rollback、periodic consolidation into encoder、replica consistency。

问题 05 · 用户长期偏好为什么要压成一段不可追溯的 summary？

Profile Summary → Vector Memory → Evolving Atomic Collaborative Memory

核心矛盾：兴趣随时间分阶段演化，粗摘要会覆盖早期证据；纯向量邻居又缺乏“为什么相关”的关系类型与证据路径。

承接关系：user profile → LLM summary memory → graph/vector memory → AtomRec。

Research Impact Score / 研究价值 8.0/10工业成熟度 ★★★☆☆创新性 ★★★★★与你方向的相关度 ★★★★★是否官方开源 未确认是否有线上 A/B 否阅读优先级 A+

代表 Paper：AtomRec。memory 被拆成 atomic units，通过 semantic link 表示 shared topic、preference transition、cross-domain transfer 等关系，新交互只局部演化相关字段；推荐时做 multi-hop evidence retrieval。四公开集平均相对提升约 8.5%。

成熟度：★★★☆☆。概念强，但缺 TTL、privacy deletion、冲突消解、线上 A/B 等 memory infra 证据。

值得押注：verifiable links、memory compaction、temporal decay、privacy-safe deletion、跨模型升级 portability、memory cost router。

问题 06 · 生成式重排为什么还要自回归生成 N 个序号？

Autoregressive List Generation → Permutation Structure → Single-pass Assignment

核心矛盾：排序输出是 permutation，不是开放文本；逐 token decode 为强结构化输出支付了不必要的 N-step dependency。

承接关系：listwise LLM reranking → constrained generation → hLLM。

Research Impact Score / 研究价值 9.1/10工业成熟度 ★★★★☆创新性 ★★★★★与你方向的相关度 ★★★★★是否官方开源 未确认是否有线上 A/B 否阅读优先级 S

代表 Paper：hLLM 从一次 prefill hidden states 读出 item-position score matrix，再用 Hungarian algorithm 求合法 permutation；报告约 28ms E2E、最高约 64× speedup，同时保持 teacher 级 ranking quality。

值得押注：assignment + diversity/business constraints、GPU batched matching、partial assignment、slate reward。

问题 07 · 同一文档为什么对每个 query 都要完整重算？

Full Cross-encoder → Reusable Document State

核心矛盾：query 在变，document/item 大量重复；cross-encoder 质量高但 document-side compute 不能复用。

承接关系：MonoBERT/MonoT5 → LLM reranker → prefix/KV reuse → DoPR。

Research Impact Score / 研究价值 9.0/10工业成熟度 ★★★★☆创新性 ★★★★★与你方向的相关度 ★★★★★是否官方开源 是是否有线上 A/B 否阅读优先级 S

代表 Paper：DoPR 将 document representation 压缩后离线转成 multi-layer prefix state；线上只处理 query + score token。最高约 8.04× latency speedup，NDCG@10 retention 约 97.1%–99.5%。官方代码。

值得押注：quantized/versioned prefix、hot/cold tier、query-adaptive state budget、与 hLLM structured decode 组合。

问题 08 · Ranking 的基本单位应该是 user-item pair 还是曝光 context？

Pairwise Feature Fusion → Context / Slate State

核心矛盾：点击发生在候选集合与位置环境中；只记录 clicked item 会丢失“为什么在这一屏选它”。

承接关系：DIN/DIEN → page-aware CTR → unified Transformer → UniCon。

代表 Paper：UniCon 以 exposure/request 为 context unit，intra-context attention 学竞争关系、inter-context attention 学长期动态；线上 RPM +3.09%、CTR +2.07%、Revenue +2.95%。

值得押注：context state 跨粗排/精排/重排复用、counterfactual context supervision、listwise reward。

问题 09 · Semantic ID 的局部 token 与完整 item preference 如何统一？

Euclidean Codebook / Token Likelihood → Geometry + Item Posterior

核心矛盾：catalog 是长尾幂律，partial SID 又对应多个完整 item；只优化局部 token likelihood 会造成 tail distortion 与 early-prefix误杀。
