四组需要拆开验证的研究问题

候选问题：可训练的目标是否也是可返回的目标？

生成式召回 → 训练候选补全 → 组间概率竞争；聚类采样 → 簇质量校正。下一步应固定候选池，分开测试分布修正与排序损失。

标签问题：未标注是否被误当作不相关？

硬负例挖掘 → 教师判断与软监督 → 固定算力对照。应继续检验查询歧义、教师错误和跨学生迁移。

验证问题：代理改善是否代表真实增益？

量化漂移 → 均匀精度基线；结构前缀 → 安慰剂对照；裁判升级 → 逐样本回归。承接已有 Counterfactual / Measurement 主线，避免多个变化同时进入实验。

状态问题：记忆应锚定任务摘要还是具体对象？

通用推理经验 → 对象贡献与对象对关系 → 版本和失效管理。待解问题是语料变化后，历史经验还能否以可接受成本保持有效。

New Problem · 2026-09-27

Routing 的目标函数是否应同时包含质量、成本、可复现性与状态一致性？

新核心矛盾：如果 controller 只优化 accuracy/latency，它可能选择一个在 batch、speculative path、cache state 或低比特 backend 下行为不稳定的执行路径。未来 routing 需要把 determinism / state compatibility / precision safety 作为约束，而不只是后处理检查。查看日报 →

当前最值得押注：① Semantic ID 与 retrieval/ranking 共享表示；② long-history 从 request-time encoding 转向 state system；③ retrieval relevance 与 activation utility 解耦；④ time/geo/freshness 等结构约束用独立 axis；⑤ model / memory / Skill / feature / budget 统一控制；⑥ 用 counterfactual 与 attribution 判断真正增量。
Problem 00 · 全链路统一应该消灭 Cascade，还是只消灭重复表示？

Separate Stage Models → Shared Backbone / State → Stage-specific Execution

Independent Retrieval / Pre-rank / Rank→OneTrans→OneTrans-V2→Shared State + Specialist Executors

核心矛盾：召回、粗排、精排都在重复理解同一个用户，但候选规模、特征与 SLA 完全不同。完全分离浪费 representation / compute；完全同构执行又不符合工业约束。

代表 Paper：OneTrans-V2 的答案是“共享 user sequence 与 backbone，不共享所有执行语义”；这使三阶段联合优化、fine→pre-rank 蒸馏与 user-context cache 成为可能，同时保留 candidate shrink。正交分支 X-Rec 表明召回未必绑定 SID-AR，也可以生成 continuous ANN triggers。

精读路线：DIN/双塔 cascade → HSTU / foundation ranker → OneTrans → OneTrans-V2 → X-Rec。

值得押注：shared state contract、stage-aware expert routing、user-context cache、dynamic candidate budget、SID + continuous trigger hybrid。

Problem 00B · Recommendation Reasoning 如何获得可验证的 Credit？

Generic CoT → Predictive-utility Selection → Ranking-aware RL → Span-level Retrieval Credit

Reasoning SFT→Evo-Rec Best-of-N→NDCG-aware GRPO→Retrieval-grounded Span Credit

核心矛盾：最终 SID exact-match reward 太稀疏；reasoning 看起来合理，不代表真正提升 item ranking。

代表 Paper：Evo-Rec 先用 target likelihood 选择 reasoning，再用 NDCG ranking reward 优化；Retrieval-Grounded Credit 把 interest hypothesis 执行为 query，按 top-K 是否命中 target 给 span-level credit。

Problem 01 · 如何让召回与排序共享语义，但不牺牲工业执行弹性？

Generative Retrieval / Semantic ID / Unified Rec

RQ-VAE / TIGER→Value-aware Generation→UniPolicy→UNIQUE→Versioned Address + Multi-executor

核心矛盾：retrieval 需要高吞吐与可枚举地址，ranking 需要 target-aware discrimination；强行合成一个 stage 会牺牲 SLA，完全分离又会造成 representation mismatch。

代表 Paper：UNIQUE 用 flat quantization + early fusion 共享表示，但保留 generative retrieval 与 target scoring 的不同执行语义。

Problem 02 · 如何把强行为统计安全地交给 LLM 排序？

Semantic + Behaviour Fusion / Missing-feature Robustness

Problem 03 · 超长行为序列到底应该在线全算，还是变成用户状态系统？

Problem 06 · 推理 / 重排的 test-time compute 应该如何分配？

Problem 08 · 如何知道线上提升到底是谁创造的？

Problem 09 · 多档模型越来越多，Router 应该优化什么？
