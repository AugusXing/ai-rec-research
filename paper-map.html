Research Problem Map · 更新至 2026.09.06

不是按年份堆论文，而是沿“核心矛盾”读技术

今天技术树最重要的新节点是 hLLM：生成式重排的输出本质是 permutation，不必支付逐 token 自回归解码成本；它用一次 prefill 读出 item-position score matrix，再通过 Hungarian assignment 得到合法排列。与 DoPR 一起看，重排正在同时重构计算复用边界与输出解码边界。另外，Faster Flash Decoding 把 sparse selector 融入 kernel，R²Adapter 把 expensive Graph RAG 变成按 query 动态路由，Interface-Induced Trajectory Censoring 则提醒 Agent 能力必须在完整 model-interface funnel 上测量。

今日推荐精读路线：hLLM → DoPR → UniCon → CORAL。先看生成式排序如何从 autoregressive generation 改成 structured assignment，再看 document-side state 如何跨 query 复用，然后看 context/slate foundation ranking，最后看如何把这些预算维度交给生产 controller。做 Serving 再补 Faster Flash Decoding；做 Agent/RAG 再补 Interface-Induced Trajectory Censoring → R²Adapter。
问题 01 · 生成式重排为什么还要自回归生成 N 个序号？

Token Generation → Permutation Structure → Single-pass Assignment

核心矛盾：生成式 reranker 的输出不是开放文本，而是候选集合的一个排列。若仍按普通语言模型逐 token decode，就为一个强结构化输出支付 N 次顺序 forward pass。

承接关系：Listwise LLM reranking → constrained ordinal generation → hLLM / Hungarian assignment。

Research Impact Score / 研究价值 9.6/10工业成熟度 ★★★★☆创新性 ★★★★★与你方向的相关度 ★★★★★是否官方开源 否；截至今日未确认官方代码仓库是否有线上 A/B 否阅读优先级 最高

代表 Paper：hLLM: Single Pass Decoding for Generative Reranking。从 prefill hidden states 通过轻量 self-attention head 读出 N×K item-position score matrix，再用 Hungarian algorithm 求最优二分匹配；合法 permutation 由算法保证而非生成后修复。LoRA + teacher ranking distillation 报告 28ms 端到端推理、64× speedup，同时维持与 teacher 相当的 ranking quality。

成熟度判断：★★★★☆。问题定义非常贴近线上 reranking latency，实验速度收益巨大；但目前仍缺 production A/B、超大候选集合和复杂业务约束下的验证。

精读路线：先理解 output-space constraint → score-matrix head → Hungarian decoding → teacher distillation → latency decomposition；再对比传统 listwise autoregressive ranker 的 KV/cache 与 token dependency。

值得押注：position assignment + diversity/business constraints、partial assignment、candidate pruning、batched GPU assignment、与 slate reward / differentiable matching 联合训练。

问题 02 · LLM Reranking 为什么要反复重算同一篇文档？

Full Cross-encoder → Compressed Bottleneck → Reusable Document Prefix

核心矛盾：query 每次变化，但大量 document/item 会被不同请求重复召回；全 joint encoding 质量高，却把 document-side compute 每次重算。

承接关系：MonoBERT/MonoT5 → RankLLaMA/Qwen3-Rerank → prefix/KV reuse → DoPR。

Research Impact Score / 研究价值 9.5/10工业成熟度 ★★★★☆创新性 ★★★★★与你方向的相关度 ★★★★★是否官方开源 是是否有线上 A/B 否阅读优先级 最高

代表 Paper：DoPR。训练 document representation bottleneck，离线把 selected states 转成 multi-layer prefix states；线上只处理 query + score token。最高 8× document-state reduction、8.04× latency speedup，平均 NDCG@10 retention 97.1%–99.5%。官方代码。

值得押注：quantized/versioned prefix、hot/cold tier、query-adaptive prefix budget、listwise prefix reuse，以及与 hLLM 组合成“document state 离线资产化 + online O(1) structured decode”。

问题 03 · Ranking 的基本单位应该是什么？

User-Item Pair → Flat Tokens → Context / Slate Unit

核心矛盾：点击发生在一次曝光/候选集合中；同一 item 的价值受同屏竞争项、位置、query 与环境影响。只保存 clicked item 会丢掉“为什么在这一组候选里选它”。

承接关系：DIN/DIEN → DSIN/Page-aware CTR → OneTrans/HyFormer → UniCon context-centric modeling。

Research Impact Score / 研究价值 9.7/10工业成熟度 ★★★★★创新性 ★★★★★与你方向的相关度 ★★★★★是否官方开源 否是否有线上 A/B 是，7 天 20% 流量阅读优先级 最高

代表 Paper：UniCon。intra-context attention 学 Locality，inter-context attention 学 Dynamics；Meituan 搜索广告离线 AUC +0.0139，线上 RPM +3.09%、CTR +2.07%、Revenue +2.95%。

值得押注：context/slate foundation ranking、counterfactual context supervision、listwise reward、context state 跨粗排/精排/重排复用。

问题 04 · Semantic ID Diffusion 应在 Token 还是 Item 层做决策？

Position-wise Denoising → Complete-item Posterior → Token Marginal Feedback

核心矛盾：partial SID 对应多个合法 item；局部 token 合理不等于完整 item 最优，后置 rerank 可能太晚。

承接关系：TIGER autoregressive SID → LLaDA-Rec masked diffusion → EPIC inline item posterior。

代表 Paper：EPIC。在每一步构造 personalized complete-item posterior，再 marginalize 回 unresolved token；四个 Amazon benchmark 的 16 个 metric×dataset 组合均为最佳均值。

值得押注：item posterior × business constraints、partial-SID adaptive stopping、dynamic catalogue、prefix survival、GPU-friendly feasible-set lookup。

问题 05 · Power-law Catalogue 为什么要用平坦 Euclidean Codebook？

Euclidean RQ-VAE → Long-tail-aware Hyperbolic Semantic ID

核心矛盾：真实 catalogue 是 head 密集、tail 稀疏的幂律结构；Euclidean quantization 容易系统性偏向高密度 head。

承接关系：RQ-VAE/TIGER → LC-Rec/LETTER → Tlow → HypRQ-VAE。

Research Impact Score / 研究价值 9.1/10工业成熟度 ★★★☆☆创新性 ★★★★★与你方向的相关度 ★★★★★是否官方开源 是是否有线上 A/B 否阅读优先级 最高

代表 Paper：HypRQ-VAE。负曲率空间承载 power-law catalogue，cascading reassignment 解决 collision；MovieLens tail Hit@10 相对 TIGER 提升超过 52%。官方代码。

值得押注：learnable curvature、continual insertion、hyperbolic + domain constraints、tail-aware beam、namespace versioning。

问题 06 · Reasoning 的收益必须在线支付吗？

Test-time CoT → Reasoning Teacher → Direct Student

核心矛盾：reasoning 能提高复杂推荐判断，但高 QPS 场景无法默认支付完整 rationale 的 token 与 latency。

承接关系：LLM ranker SFT → CoT4Rec/RecR1 → teacher distillation → SelfDR。

代表 Paper：SelfDR。reasoner → reasoning-enhanced teacher → direct student；Clothing 上 1 output token、109.46ms，接近无 reasoning baseline，而多种 reasoning baseline 为 250–665ms。官方代码。

问题 07 · Sparse Attention 为什么常常“理论省 FLOPs、线上不够快”？

External Selector / Metadata → Content Scan → Selector-Compute Fusion

核心矛盾：稀疏 attention 若需要额外 metadata、全局 top-k 或独立 selector kernel，节省的 attention FLOPs 会被内存流量、同步和 kernel launch 吃掉。

承接关系：block sparse / KV selection → metadata-based selectors → Faster Flash Decoding。

Research Impact Score / 研究价值 9.2/10工业成熟度 ★★★★☆创新性 ★★★★★与你方向的相关度 ★★★★☆是否官方开源 是是否有线上 A/B 不适用；系统 benchmark阅读优先级 很高

代表 Paper：Faster Than Flash: Exploiting Attention Sparsity for Efficient Long-Context Decoding。用 2-bit content-aware key scan 替代外部 metadata，top-δ 动态选择相关 block，并将 selector 与 attention compute 融入同一 kernel；最高 11.6× kernel speedup、256K context、2.37× end-to-end throughput。官方代码。

值得押注：ranking/agent reader 的 long-context kernel、adaptive sparsity 与 CUDA Graph、selector result reuse、shape-aware kernel routing。

问题 08 · Agent 的 tool-call rate 真的是“模型能力”吗？

Model-only Metric → Model × Template × Parser × Executor Funnel

核心矛盾：模型可以生成合法 tool call，但 serving adapter 的 chat template/parser 契约不匹配，会在执行前静默吞掉轨迹，导致观测到的 tool-call rate 为 0。

承接关系：tool-use benchmark → parser-aware evaluation → Interface-Induced Trajectory Censoring。

Research Impact Score / 研究价值 8.9/10工业成熟度 ★★★★☆创新性 ★★★★☆与你方向的相关度 ★★★★☆是否官方开源 是，论文称释放 preflight check / repo是否有线上 A/B 否阅读优先级 高

代表 Paper：Interface-Induced Trajectory Censoring。同一模型仅替换 serving adapter，BFCL v4 结果可从 0.00 变为 0.96/0.19；tau-bench 中 server-parsed calls 可从 0 到 636。结论是 tool-call rate 是 model-interface stack 的属性，而非模型单体属性。

值得押注：tool-call preflight、raw-generation audit、training/eval interface parity、parser contract versioning、trajectory observability。

问题 09 · Graph RAG 为什么要对所有 Query 都支付高成本？

Fixed RAG Path → Query Complexity Routing → Rewrite on Uncertain Cases

核心矛盾：vanilla RAG 对简单 query 足够快，Graph RAG 对 multi-hop 更强但更贵；固定策略会对大量请求过度计算。

承接关系：vanilla RAG → Graph RAG → heuristic/LLM router → R²Adapter。

Research Impact Score / 研究价值 8.7/10工业成熟度 ★★★☆☆创新性 ★★★★☆与你方向的相关度 ★★★★☆是否官方开源 未确认官方代码是否有线上 A/B 否阅读优先级 高

代表 Paper：R²Adapter。轻量 routing + rewriting adapter 动态决定 vanilla / graph RAG；不确定但偏向 graph 的 query 会被重写以暴露 multi-hop 需求。三项 multi-hop QA 实验中 graph-based RAG usage 最高减少 59%，同时保持 comparable answer accuracy。

值得押注：retrieval cost-aware routing、uncertainty calibration、query decomposition、graph invocation budget，以及与 model/context routing 联合优化。

问题 11 · Embedding / Ranking / LLM 为什么要维护三套 Runtime？

Task-specific Serving → Shared Kernel / Scheduler / State Contract

核心矛盾：embedding、ranking、LLM 的流量形态不同，但 tokenizer、batching、GEMM/attention、CUDA Graph、scheduler 与 cache 问题高度重合。

Research Impact Score / 研究价值 9.3/10工业成熟度 ★★★★★创新性 ★★★★☆与你方向的相关度 ★★★★★是否官方开源 部分；vLLM/SGLang 开源，Perplexity 核心生产栈未整体开源是否有线上 A/B 不适用 / 未披露阅读优先级 很高

代表工程：Perplexity GPU Embedding Serving，以及 2026-09-05 vLLM 主线的 EAGLE3 + Pipeline Parallel。SGLang 同期继续强化跨阶段 cache publication 的事务语义。共同信号是：Serving 优化正从单 kernel 变成 parallelism × spec-decode × cache consistency × dtype/layout × scheduler 的系统契约。

值得押注：embedding/reranking/LLM shared scheduler、KV/prefix transaction、expert load balance、low-bit layout、end-to-end p99 observability。

问题 12 · 谁来统一决定系统把算力花在哪里？

Manual Tuning → Model Router → Agentic Control Plane

核心矛盾：source budget、candidate depth、context keep ratio、prefix budget、reasoning depth、Graph RAG invocation、model、precision、device 都变成可调动作，人工无法持续做联合最优。

承接关系：Switchyard/AdaWidth/DS-Frame → SetMIR → Declarative Attention → Spotify Shunt / NVIDIA PAIR → CORAL。

Research Impact Score / 研究价值 9.8/10工业成熟度 ★★★★★创新性 ★★★★★与你方向的相关度 ★★★★★是否官方开源 否是否有线上 A/B 是阅读优先级 最高

代表 Paper：CORAL。LLM Agent 读取 observation / experiment memory，由 deterministic optimizer 把动作投影到可行预算，再进入真实 A/B。今天新增可控维度包括 hLLM decode path、FFD sparsity、R²Adapter graph invocation、vLLM spec-decode/parallelism 与 SGLang cache state。

值得押注：marginal utility per GPU-ms、safe exploration、multi-stage routing、causal experiment memory、delayed business reward。

当前最值得押注的问题：Structured Generative Reranking、Reusable Reranker State、Context/Slate Foundation Ranking、Item-level Generative Posterior、Fresh & Long-tail Semantic ID、Adaptive RAG、Unified Serving Contract、Unified Budget Router。如果只选一条职业上最值得深挖的主线：建议沿 hLLM → DoPR → UniCon → CORAL 阅读，把输出结构、状态复用、精排建模与生产控制闭环串起来。
