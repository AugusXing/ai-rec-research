沿“核心矛盾”读论文，而不是沿发布时间堆论文

Paper Map 回答三个问题：上一阶段解决了什么？为什么仍不够？下一篇工作把矛盾推进到了哪里？ 9 月 21 日新增一条跨越论文与系统的主枝：Architecture-aware Runtime Contract。它把 Sparse Attention、mHC / cross-layer state、mixed-precision MoE、Speculative KV 与 retrieval cache correctness 串成一个研究问题：模型结构如何在真实硬件上保持“既正确又值得跑”。

当前优先精读路线：生成式推荐 / 召回：TIGER → OneRec / OneSearch → VARG / GR4AD → Spotify Hypothesis Shelf → UniPolicy；重排：Cross-Encoder → Listwise / Reasoning Rerank → MSS-Complement → MERIT-Rank；检索：BM25 → Dense → SPLADE → Late Interaction → SPARSEUP → Query-conditioned Hybrid；Agent RL：GRPO → OPD/OPSD → RetireOPD；Serving：FlashAttention / KV Cache → Speculative Decoding → ODA / SwitchSD → Sparse/mHC/Precision-aware Runtime；Agent Search：ORDER / DiBud → MSS-Complement → F²DR / MATCH。
问题 01 · 多目标生成式召回为什么不能只调 Reward Weight？

Single Reward → Reward Fusion → Objective-specific Policy Portfolio

核心矛盾：CTR、relevance、eCPM/GMV 梯度方向不同，一个 scalar reward 会让强目标压制弱目标；固定 beam search 又无法显式配置固定候选预算内的目标供给。

承接关系：OneRec / OneSearch 证明 generative retrieval 能接受业务 preference → VARG/GR4AD 把 value alignment 前移 → UniPolicy 让不同 objective 拥有独立 policy path、共享 backbone。

工业证据：7-day A/B：CTR +0.71%、RPS +1.58%、revenue +1.32%。

值得押注：learned quota controller、long-term objective、policy calibration、目标自动增删、interference measurement。

问题 02 · 生成式推荐一定要直接生成 Item 吗？

Static Template → Direct Item Generation → Intent Planning + Catalogue Fulfilment

核心矛盾：直接生成 item 把用户理解、主题规划、目录合法性、召回和文案绑在一个 decoder；静态 shelf template 又覆盖不了长尾兴趣。

关键工作：Spotify Hypothesis-Driven Shelf Generation 先生成自然语言 hypothesis，再 constrained generative retrieval、candidate selection、shelf alignment，并离线预计算进入 Home ranking。

承接：Semantic ID 解决“怎么生成地址” → value-aware policy 解决“生成哪些地址” → hypothesis layer 解决“为什么生成这些地址”。

值得押注：intent quality reward、intent→coverage→ranker survival 的跨阶段 credit、freshness / recompute budget。

问题 03 · 为什么单条 Reasoning Chain 不足以做复杂重排？

Cross-Encoder → Single-CoT Reranker → Multi-Trajectory Evidence Integration

核心矛盾：相关性包含 intent、evidence、constraint、context；单条 CoT 会把一次误判放大成最终 ranking error。

关键推进：MERIT-Rank 建立 Multi-Trajectory Reasoning Space，让多个互补 reasoning path 由 joint reranker 汇总，并用 PRPO 稳定训练。

Research Impact Score / 研究价值 9.3/10 · 工业成熟度 ★★★☆☆ · 创新性 ★★★★★ · 与你方向的相关度 ★★★★★ · 是否官方开源 否 · 是否有线上 A/B 否 · 阅读优先级 S+

承接：MSS-Complement 解决 Top-K 是否覆盖必要事实 → MERIT-Rank 解决单候选是否需要多视角判断 → 下一步是 set-level + multi-trajectory 的统一 list rerank。

值得押注：trajectory router、uncertainty-triggered reasoning、verifier early-exit、listwise multi-perspective RL。

问题 04 · Top-K 都相关，为什么 Agent 仍缺证据？

Pointwise Relevance → Diversity → Set Sufficiency → Missing Complement

核心矛盾：复杂决策需要一组互补事实，而传统 reranker 对 passage 独立打分，容易让 Top-K 被同一事实重复占满。

关键工作：MSS-Complement / SERBench 将任务定义成在当前 Agent state 下恢复缺失的 Minimal Sufficient Evidence。Complete-MSS@5 从 61.4% 提到 73.0%，@8 从 72.4% 到 80.6%。

问题 05 · Dense 是默认方案后，Sparse Retrieval 还有必要吗？

BM25 → Dense → Learned Sparse / Late Interaction → Query-conditioned Retrieval Portfolio

核心矛盾：Dense semantic matching 强，但 rare lexical/entity、可解释性和倒排兼容并不总占优；Late Interaction 质量高但索引/Serving 更复杂。

关键推进：SPARSEUP 以 149M ModernBERT 构建开放 learned sparse baseline，通过 logit shift、per-position top-k 与 case folding 控制 expansion。

Research Impact Score / 研究价值 9.0/10 · 工业成熟度 ★★★★☆ · 创新性 ★★★★☆ · 与你方向的相关度 ★★★★★ · 是否官方开源 是（Apache 2.0） · 是否有线上 A/B 否 · 阅读优先级 S

证据：BEIR-13 56.4 nDCG@10；MS MARCO + Seismic 在 >97% recall 时约 380µs/query。

值得押注：学习 query-conditioned dense/sparse/late route；稀疏 attribution；multilingual latent sparse vocabulary。

问题 06 · 长上下文与 Decode 为什么要固定计算路径？

Full Compute → Static Sparse → On-Demand Attention / Draft Switching → Execution Routing

核心矛盾：full attention / 单一 draft strategy 对所有 token 付同样成本；静态 local/sparse 又可能永久漏远程信息，固定 draft 则无法利用不同 request 的 copy structure。

代表工作：On-Demand Attention 用 recall head 决定何时 global read；SwitchSD 用 target hidden state 的 copy-intent probe 在 neural draft / context copy 间切换。

问题 07 · Teacher 应该监督 Student 多久？

Fixed Distillation → Annealing → Signal-dependent Teacher Retirement

核心矛盾：teacher 早期能提供 dense guidance，但 student 变强后继续模仿可能与 environment reward 冲突；固定退火不能适配不同学习速度。

关键推进：RetireOPD 监控 teacher-student discrepancy 与 relative competence，一旦 transfer 停滞且 student 足够强就移除 OPD。

问题 08 · DeepSearch / Tool Learning 为什么不能只看 Final Answer？

Final Score → Full-pipeline Reward → Hierarchically Gated Credit

核心矛盾：答案可能碰巧正确但 trajectory 很差；tool name 都错时若仍奖励 argument value，又会给 policy 错误 credit。

关键推进：F²DR 将 reward 拆为 Content / Trajectory / Answer；MATCH 再将 tool reward 按 name → key → value 逐级 gate，并让 curriculum 跟随模型能力边界。

问题 09 · 历史案例为什么不能只压成一个静态向量？

Whole-document Retrieval → Mutable Memory → State-addressable Trajectory

核心矛盾：整体相似不代表当前阶段相似。一个用户 session 在探索、比较、决策、复购阶段需要不同下一步。

代表工作：RAFT 将历史 case 拆成 directed timeline entry，按 active state 检索相似中间态，再返回 parent-case 后续 trajectory。

问题 10 · 模型结构进入生产后，为什么“支持模型”还远远不够？

Generic Runtime → Model-specific Kernels → Architecture-aware Execution Contract

核心矛盾：新模型不再只是换权重。Sparse attention 决定该看哪些 KV；mHC / hyper-connection 引入跨层 state；MoE router 对 precision 更敏感；speculative decoding 引入 draft/target 两套 KV；SSM/GDN 又依赖 state layout。若 runtime 把这些都当普通 tensor，结果可能是慢路径、错误路由或跨请求状态污染。

9/21 的代表证据：Qwen4 Sparse FA 按 context shape dispatch；vLLM mHC overlap 与 SGLang mHC fusion 同时用 16-token crossover 控制 fast path；MiMo V2 把 BF16 router 与 MXFP4 experts 分精度；vLLM Spec KV fix 把 dummy state invariant 下沉进 kernel；Ascend GDN 则通过统一 SSM state layout 降低 transpose 税。

成熟度：极高。这不是未来概念，而是今天已经合入主线框架的生产约束。

值得押注：自动 kernel crossover learning；state schema / ownership verifier；precision-aware router；hardware capability graph；compiler/runtime 联合优化；将 correctness regression 与性能 benchmark 放进同一 CI。

推荐 / 搜索迁移：未来 foundation ranker / generative retriever 也会拥有长序列、MoE、KV、session state、retrieval cache。最稀缺的工程能力会是把“业务模型结构”映射成“可验证、可回滚、可调度的执行契约”。

Paper Map 的押注结论：短期最值得投入的是 Multi-objective Generative Retrieval、Multi-Trajectory / Set-level Re-ranking、Query-conditioned Hybrid Retrieval、Stateful Memory、Adaptive Compute 与 Architecture-aware Runtime。它们共同指向一个系统形态：模型不是永远执行同一张图，而是根据 objective、state、uncertainty、budget 与 hardware 选择正确路径，同时保持状态语义不被破坏。
