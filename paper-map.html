沿“核心矛盾”读论文：每一篇都回答上一阶段没解决的问题

今天把技术树新增到三个关键节点：Intent Planning、Missing Complement、Stateful Trajectory。它们共同指向一个变化：推荐 / 搜索系统的中间层越来越重要——不是把所有能力塞进一个大模型，而是显式表示“想满足什么意图、当前缺什么信息、现在处于哪个状态”。

当前推荐精读路线：生成式推荐：TIGER / RQ-VAE → HypRQ-VAE → EPIC → VARG → Spotify Hypothesis-Driven Shelf；Agent Retrieval：GeneralQPP → DiBud / ORDER → DUPAR / DRAG → MSS-Complement；长期状态：ChronicleRec → DRIFT → LION → RAFT；Agent Harness：Ecdysis → ScienceBuddy → Harness Design Study → SoL-Pi；工业 Serving：KVShareArena → OneLA → JustFit → FlashVector → SoL-Pi；Agentic Rec：Conversational Rec → Re2A → Who Are We Recommending To?。
问题 01 · 生成式推荐一定要直接生成 Item 吗？

Static Template → Direct Item Generation → Value-aware SID → Natural-language Intent Planning + Catalogue Fulfilment

核心矛盾：直接生成 item 同时承担用户理解、主题规划、目录合法性、召回和文案，难诊断也难替换；静态 shelf template 又覆盖不了长尾兴趣。

关键推进：Hypothesis-Driven Shelf Generation 先生成自然语言 shelf hypothesis，再通过 constrained generative retrieval 完成目录履约，最后 candidate selection + shelf alignment，并全部离线预计算后注入 Spotify Home ranking。

承接关系：人工模板解决可控性 → Semantic ID 解决可生成地址 → VARG 解决 value/ranker alignment → Spotify 将“规划”和“目录履约”再次解耦。

成熟度：高。具备真实生产链路、离线评估和线上曝光证据，但不同内容类型收益不一致。

值得押注：intent quality reward、hypothesis→retrieval coverage→ranker survival 的多阶段 credit、动态 shelf budget、freshness / version / rollback。

问题 02 · Top-K 都很相关，为什么 Agent 仍然做不对下一步？

Pointwise Relevance → Diversity-aware Ranking → Set-level Sufficiency → Missing-Complement Retrieval

核心矛盾：relevance 是单 passage 属性，但复杂决策要求一组互补事实。Top-K 很容易被同一事实的近重复结果占满。

关键推进：MSS-Complement / SERBench 将检索问题重新定义为：在给定当前 Agent state 的情况下，恢复“下一步决策仍缺失”的最小充分证据集合。Complete-MSS@5 61.4%→73.0%，@8 72.4%→80.6%。

Research Impact Score / 研究价值 9.7/10 · 工业成熟度 ★★★☆☆ · 创新性 ★★★★★ · 与你方向的相关度 ★★★★★ · 是否官方开源 是 · 是否有线上 A/B 否 · 阅读优先级 S+

承接关系：dense retrieval → reranker → MMR/diversity → verifier/sufficiency gate → MSS-Complement 的 set construction。

成熟度：研究价值高、工业证据早期。最大难点是如何稳定判断“缺什么事实”。

值得押注：set-level loss、marginal sufficiency gain、coverage-aware source routing、与 retrieval cost 联合优化；推荐里对应 multi-interest / attribute gap filling。

问题 03 · 历史行为 / 案例为什么总被压成一个静态向量或文档？

Whole-document Retrieval → Long-history Tokens → Mutable Memory → State-addressable Trajectory

核心矛盾：同一个 case / session 在不同阶段需要不同建议；整体相似不代表当前状态相似。

关键推进：RAFT 将 closed case 拆成 directed timeline entries，按 active state 做 entry-level retrieval，命中后返回 parent-case trajectory；在每个 case progress 阶段都提升 Case Hit，并优于 vanilla RAG / GraphRAG。

承接关系：SIM/TWIN 的 target-aware long-history read → ChronicleRec cacheable state → LION mutable delta → RAFT state node + future trajectory。

值得押注：session stage index、success-conditioned trajectory retrieval、temporal hard negatives、state TTL / version / provenance。

问题 04 · 一个固定索引 / 固定 Top-K / 固定模型为什么要服务所有 Query？

Single Retriever → Hybrid Retrieval → Access Budget → Query-conditioned Index → Joint Retriever/Generator Routing

核心矛盾：query 的难度、source、时效性与所需证据类型不同，但传统系统把 index、source、top-K、reranker、generator 配置写死。

代表承接：DiBud 将 fixed Top-K 改成 access budget；ORDER 让 chunking / metadata / index / source / reranker query-conditioned；DRAG 联合选择 retriever 与 generator；DUPAR 用 cross-turn cache fast path + full-index slow path。

下一步：把 MSS-Complement 的“缺口”作为 controller 输入：不只决定去哪查，还决定下一路必须补什么 coverage。

成熟度：中高。工业形态很明确，但统一 controller 的线上稳定性与可解释 routing 仍不足。

值得押注：successful-task latency、source overlap、set coverage、P95 cost 与 abstention risk 的联合目标。

问题 05 · Agent Harness 有没有一种永远最优的配置？

Fixed Harness → Component Ablation → Model/Budget-aware Harness Routing

核心矛盾：planning、structured tools、context summary 往往被当成“加上总比不加好”，但它们会产生额外 token、调用和约束。

关键推进：An Empirical Study of Harness Design 在 176 matched settings 中发现：context 管理在 window 紧时才更有价值；rule elision 后再 LLM summary 最有效率；planning 对弱模型提升准确率，对强模型更像省成本；bash 强的模型用 bash-only 可比 structured tools 更便宜。

承接关系：完整 Agent 系统榜单 → component-level ablation → runtime harness policy。

值得押注：model capability probe、tool proficiency estimation、context pressure predictor、expected-success-per-dollar router。

问题 06 · 模型不变，Agent 成本还能降多少？

Prompt Compression → Context Management → Observation Store → Auto-researched Harness Economics

关键推进：SoL-Pi 从 152 个研究方向、535 个执行环境、3000+ runs 中筛出 Action Fusion、Online Context Compact、ObservationPack、Evidence-Preserving Reducer。EdgeBench 上 token traffic -44.7%~-49.0%，API cost 约 -1/3。

问题 07 · Semantic ID 只表达语义够不够？

Semantic Address → Long-tail Address → Item Posterior → Value / Ranker-aligned Address

承接：RQ-VAE/TIGER → HypRQ-VAE → EPIC → Generative Verifier → VARG。VARG 让末级 token 承担 value ordering，并用 Prefix-GRPO 对齐合法性、用户行为、搜索相关性与现有 ranker advantage；Tmall 14-day A/B GMV +1.45%。

值得押注：incremental SID、价值与探索平衡、catalog refresh、跨 ranker version 的 SID 稳定性。

问题 08 · 为什么大规模预训练知识难安全迁到在线 Ranker？

Task-specific Ranker → Shared Backbone → Generative Pretraining → Transferable Foundation Ranker

核心矛盾：大规模行为预训练有长期知识，但线上 ranking features、sparse IDs、更新周期与 latency 约束不同。

代表路线：PTDG / MORE / UniRec 处理 task-aware information flow；LazFormer 用 autoregressive behavior pretraining + residual adapter + asymmetric multi-epoch 迁移 sparse+dense，线上 Orders +3.38%、GMV +9.85%。

值得押注：natural-language taste 与 dense embedding 双表示、sparse/dense learning clock、跨域 adapter routing、runtime sequence budget。

问题 09 · RAG 的 evidence 为什么一直是不可见的中间产物？

Hidden Retrieval → Provenance Trace → Editable Evidence State → Feedback for Reranker

关键推进：FootprintRAG 将 text/figure evidence、query variants、retrieval trajectories 与 evidence revisions 可视化，并支持用户恢复可能被过滤掉的候选。

问题 10 · 推荐结果未来是给人看，还是给 Agent 看？

Human-only Utility → Conversational Assistance → Delegation Spectrum → Dual-audience Optimization

关键推进：Who Are We Recommending To? 提出 delegable / experiential 场景分化，并把 preference specifiability、outcome verifiability、decision stakes 作为 delegation spectrum 的维度。

Research Impact Score / 研究价值 9.0/10 · 工业成熟度 ★★☆☆☆ · 创新性 ★★★★☆ · 与你方向的相关度 ★★★★★ · 是否官方开源 不适用 · 是否有线上 A/B 否 · 阅读优先级 A+

核心矛盾：给人看的推荐需要吸引力、惊喜、解释；给 Agent 的推荐更需要机器可读属性、约束、可信 provenance 与可验证 outcome。两者目标不完全一致。

值得押注：dual-audience ranking、agent-readable item schema、delegation-aware exposure、GEO manipulation defense、human long-term utility 对 agent action 的 credit。

当前最值得投入半年研究的 6 个节点：① Intent-conditioned Generative Rec；② Set-level Sufficiency Retrieval；③ Stateful Trajectory / User State；④ Unified Model+Tool+Harness Routing；⑤ Foundation Ranker + Language-readable Preference；⑥ Dual-audience Agentic RecSys。如果做工程落地，优先选择能同时给出 offline gain、Serving budget 和 fallback 策略的问题。
