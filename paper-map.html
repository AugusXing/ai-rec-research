Research Problem Map · 更新至 2026.09.05

不是按年份堆论文，而是沿“核心矛盾”读技术

9 月 5 日技术树新增四个非常清晰的问题：Ranking 的基本单位究竟是 item/token 还是完整 context？LLM reranker 的 document compute 能否跨 query 复用？Semantic ID 应在什么 geometry 中组织长尾 item？Masked-diffusion 该在 token 层还是 complete-item 层做竞争？这些问题共同指向一个更大的变化：研究正在从“换模型”转向重新定义状态、计算与复用边界。

今日推荐精读路线：UniCon → DoPR → EPIC → HypRQ-VAE → SelfDR。第一篇看工业精排输入抽象如何变化；第二篇看 reranking offline/online boundary；第三篇看生成式推荐 item-level inference；第四篇看 SID geometry；第五篇看 reasoning 如何蒸馏成 cheap serving。做 Agent/RAG 再补 SciLENS → RuleMem。
问题 01 · Ranking 的基本单位应该是什么？

User-Item Pair → Flat Tokens → Context / Slate Unit

核心矛盾：用户点击不是脱离环境发生的。一个 item 的价值取决于同屏竞争项、位置、query、价格/距离与环境。传统序列模型保留“用户过去点了什么”，但经常丢掉“当时是在什么候选集合里点的”。

承接关系：DIN/DIEN → DSIN/Page-aware CTR → OneTrans/HyFormer unified token modeling → UniCon context-centric modeling。

代表 Paper：UniCon。用 context unit 对齐历史曝光与当前 target candidate set；intra-context attention 学 Locality，inter-context attention 学 Dynamics。Meituan 搜索广告 AUC +0.0139；线上 RPM +3.09%、CTR +2.07%、Revenue +2.95%。

成熟度判断：★★★★★。不仅有真实亿级数据、Serving SLA、candidate sharding、AOT C++ runtime，还给出完整 A/B。

精读路线：先读 Input Formulation → Target Context Supervision → Context Compression → Serving → Online A/B；然后回看 OneTrans/DSIN/CIM 理解它真正改变的是 abstraction 而非 attention block。

值得押注：context/slate foundation ranking、counterfactual context supervision、listwise reward、context state 跨粗排/精排/重排复用。

问题 02 · LLM Reranking 为什么要反复重算同一篇文档？

Full Cross-encoder → Compressed Bottleneck → Reusable Document Prefix

核心矛盾：pointwise reranker 的 query 每次变，但很多 document 在不同 query 下重复出现；全量 joint encoding 质量高，却把 document-side compute 每次重做。普通 embedding cache 又压得太早，失去 LLM 多层表示。

承接关系：MonoBERT/MonoT5 → RankLLaMA/Qwen3-Rerank → KV/prefix reuse ideas → DoPR。

Research Impact Score / 研究价值 9.5/10工业成熟度 ★★★★☆创新性 ★★★★★与你方向的相关度 ★★★★★是否官方开源 是是否有线上 A/B 否阅读优先级 最高

代表 Paper：DoPR。训练 document representation bottleneck，离线把 selected states 转成 multi-layer prefix states；线上只处理 query + score token。最高 8× document-side memory reduction、8.04× latency speedup，平均 NDCG@10 retention 97.1%–99.5%。官方代码。

成熟度判断：★★★★☆。方法、代码与 latency/memory benchmark 扎实，但缺 production A/B、cache invalidation 与亿级 storage 证据。

精读路线：先理解 structured attention bottleneck → offline prefix construction → online injection → cross-query reuse amortization，再看 Ktrain/Kinfer 解耦。

值得押注：quantized prefix、hot/cold tier、versioned prefix、query-adaptive budget、listwise reuse、prefix storage TCO。

问题 03 · Semantic ID Diffusion 应在 Token 还是 Item 层做决策？

Position-wise Denoising → Complete-item Posterior → Token Marginal Feedback

核心矛盾：partial SID 对应多个合法 item；每个位独立“看起来合理”并不等价于完整 item 是用户最想要的。若等生成结束才 rerank，目标 item 可能早已在 denoising 中被剪掉。

承接关系：TIGER autoregressive SID → LLaDA-Rec masked diffusion → EPIC inline item posterior。

Research Impact Score / 研究价值 9.3/10工业成熟度 ★★★☆☆创新性 ★★★★★与你方向的相关度 ★★★★★是否官方开源 否是否有线上 A/B 否阅读优先级 最高

代表 Paper：EPIC。构造 personalized complete-item posterior，再 marginalize 回 unresolved token；16 个 metric×dataset 组合均为 best mean，较每列第二名提升 1.2%–16.8%。

成熟度判断：★★★☆☆。机制验证充分，parameter-efficient adapter 很轻，但 inference +34.2% latency，尚无超大 catalogue 与线上证据。

精读路线：Feasible Item Set → Posterior Energy → Item-to-token Marginalization → Inline vs Post-hoc → Ambiguity/Cost Analysis。

值得押注：item posterior × business constraints、partial-SID adaptive stopping、dynamic catalogue、prefix survival、GPU-friendly feasible-set lookup。

问题 04 · Power-law Catalogue 为什么要用平坦 Euclidean Codebook？

Euclidean RQ-VAE → Long-tail-aware Hyperbolic Semantic ID

核心矛盾：真实 catalogue 是 head 密集、tail 稀疏的幂律结构；Euclidean quantization 倾向更好地表示高密度 head，tail item 更容易量化误差大、collision 多、被压缩掉。

承接关系：RQ-VAE/TIGER → LC-Rec/LETTER collision & diversity → Tlow geometry → HypRQ-VAE hyperbolic geometry。

Research Impact Score / 研究价值 9.1/10工业成熟度 ★★★☆☆创新性 ★★★★★与你方向的相关度 ★★★★★是否官方开源 是是否有线上 A/B 否阅读优先级 最高

代表 Paper：HypRQ-VAE。负曲率空间用指数体积扩张自然容纳层级/幂律分布，再用 cascading reassignment 保证唯一 SID。Instruments NDCG@10 相对 strongest baseline +14.0%；MovieLens tail Hit@10 相对 TIGER +52.71%。官方代码。

成熟度判断：★★★☆☆。开源和 long-tail analysis 很完整，但没有在线 remapping/fresh catalogue 与生产 scale。

精读路线：Hyperbolic RQ → Collision Reassignment → Overall Results → Head/Tail Split → Quantization Error。

值得押注：learnable curvature、continual insertion、hyperbolic + domain constraints、tail-aware beam、namespace versioning。

问题 05 · Reasoning 的收益必须在线支付吗？

Test-time CoT → Reasoning Teacher → Direct Student

核心矛盾：reasoning 能提升复杂推荐判断，但每次线上生成 rationale 会让 latency/tokens 成倍增长。推荐的业务 QPS 决定了“慢思考全量常开”很难成立。

承接关系：LLM ranker SFT → CoT4Rec/RecR1 test-time reasoning → teacher distillation → SelfDR self-distillation from reasoning。

Research Impact Score / 研究价值 9.0/10工业成熟度 ★★★★☆创新性 ★★★★☆与你方向的相关度 ★★★★★是否官方开源 是是否有线上 A/B 否阅读优先级 最高

代表 Paper：SelfDR。同一 LLaMA-3.1-8B 依次扮演 reasoner、teacher、student；reverse-KL + dynamic weight，把 rationale 带来的 posterior 蒸馏给 direct recommender。Clothing 109.46ms/instance、1 output token，接近无 reasoning SOFT；多种 reasoning baseline 为 250–665ms。官方代码。

成熟度判断：★★★★☆。工业思想很强，公开数据与代码完整，但还缺大流量 A/B 和 full-catalog scalability。

值得押注：hard-request router、process-reward teacher、uncertainty-triggered reasoning、multi-teacher calibration、reasoning cache。

问题 06 · Agent Search 只检索文本够吗？

Text Retrieval → Graph Navigation → Visualization as an Action

核心矛盾：多跳研究/搜索中的真正结构经常是 citation/category/entity graph；把结构全部转成文本既耗 context，又弱化全局 topology。Web API 还带来不稳定与不可复现。

承接关系：RAG → Web Search Agent → GAREN group navigation / ITER trajectory state → SciLENS structural navigation。

Research Impact Score / 研究价值 8.9/10工业成熟度 ★★★☆☆创新性 ★★★★★与你方向的相关度 ★★★★☆是否官方开源 是是否有线上 A/B 否阅读优先级 很高

代表 Paper：SciLENS。12M 本地论文 MongoDB+FAISS，工具包括 dense/BM25、citation traversal、shortest path 与 visualization；20-model consensus 合成数据，SFT + rubric RL 对 planning/evidence grounding 对齐。官方代码。

值得押注：推荐内容图/类目图导航、source graph routing、结构压缩后的 context allocation、tool outcome attribution。

问题 07 · Memory 为什么只能被动存 Fact？

Fact Store → Organized Memory → Active Rule Memory

核心矛盾：query 与事实间有 semantic gap，单纯 embedding retrieval 找不到“语义不近但逻辑上必要”的证据；事实召回后 LLM 还可能缺 reasoning skeleton。

承接关系：Mem0/Letta → A-MEM/GraphRAG → CHIME attribution-aware memory → RuleMem active rules。

Research Impact Score / 研究价值 8.7/10工业成熟度 ★★★☆☆创新性 ★★★★☆与你方向的相关度 ★★★★☆是否官方开源 否是否有线上 A/B 否阅读优先级 高

代表 Paper：RuleMem。从历史诱导自然语言 Horn clauses，用 Rule Perplexity Consistency 验证，再让 rule body 主动引导事实召回；Guided Recall 平均 recall 0.56→0.79。

值得押注：personalized preference rules、freshness/contradiction handling、rule confidence、rule-driven source routing、长期 user state。

问题 08 · Embedding / Ranking / LLM 为什么要维护三套 Runtime？

Task-specific Serving → Shared Kernel / Scheduler / Graph Runtime

核心矛盾：embedding 离线吞吐、在线 query latency 与 ranking batch 的流量形态不同，但核心 Transformer kernel、tokenizer、batching、CUDA launch 问题高度相似。三套栈会重复优化同样问题。

Research Impact Score / 研究价值 9.2/10工业成熟度 ★★★★★创新性 ★★★★☆与你方向的相关度 ★★★★★是否官方开源 核心生产栈未整体开源是否有线上 A/B 否；生产 benchmark阅读优先级 很高

代表工程：Perplexity Fast Embeddings on GPUs。Ivy(Rust gateway) → Tulip(Rust scheduler) → ROSE(Python model engine)，全模型 CUDA Graph、lazy capture、LazyTensor、ragged attention，并复用 LLM kernel。

值得押注：embedding/reranking/LLM shared scheduler、shape-aware kernel routing、tokenizer offload、end-to-end p99 observability、free-threaded Python + Rust interop。

问题 09 · 谁来统一决定系统把算力花在哪里？

Manual Tuning → Model Router → Agentic Control Plane

核心矛盾：source budget、interest count、candidate depth、context keep ratio、prefix budget、reasoning depth、model、precision、device 都变成可调动作，人工无法在不断漂移的流量中持续做联合最优。

承接关系：Switchyard/AdaWidth/DS-Frame → SetMIR dynamic ANN → Declarative Attention → Spotify Shunt / NVIDIA PAIR → CORAL production control harness。

Research Impact Score / 研究价值 9.8/10工业成熟度 ★★★★★创新性 ★★★★★与你方向的相关度 ★★★★★是否官方开源 否是否有线上 A/B 是阅读优先级 最高

代表 Paper：CORAL。LLM Agent 读观察、历史 experiment memory 与约束，通过 deterministic optimizer 投影到可行预算，再进入真实 A/B；retrieval-budget case watch time +0.15%、sessions +0.16%，Serving case 实现年化数百万美元级节省。

今日新增动作维度：UniCon 的 context keep ratio、DoPR 的 inference prefix budget、SelfDR 的 direct/reasoning path，都可以被未来 unified router 控制。

值得押注：marginal utility per GPU-ms、safe exploration、causal experiment memory、multi-stage routing、delayed business reward。

当前最值得押注的问题：Context/Slate Foundation Ranking、Reusable Reranker State、Item-level Generative Posterior、Fresh & Long-tail Semantic ID、Reasoning Distillation、Unified Budget Router。如果只选一条职业上最值得深挖的主线：建议沿 DoPR → UniCon → CORAL 阅读，把模型结构、Serving 和生产优化控制闭环串起来。
