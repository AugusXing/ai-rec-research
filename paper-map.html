Research Problem Map · 更新至 2026.09.22

沿“核心矛盾”读论文，而不是沿发布时间堆论文

Paper Map 回答三个问题：上一阶段解决了什么？为什么仍不够？下一篇工作把矛盾推进到了哪里？ 今天新增四条强主枝：Depth–Breadth Heterogeneous Retrieval、Retrieval Confidence / Abstention、Interactive Evidence Acquisition、Verifiable Agentic Experimentation。它们都指向同一件事：不是永远跑固定 pipeline，而是根据证据、成本和风险选择下一步。

当前优先精读路线：生成式召回：TIGER → OneRec / OneSearch → VARG / GR4AD → Spotify Hypothesis Shelf → UniPolicy → Hybrid Path Controller；检索：BM25 → Dense → SPLADE / Late Interaction → SPARSEUP → Hybrid GPU–CPU Retrieval → RegimeAbstain；Agentic Search：ORDER / DiBud → MSS-Complement → F²DR / MATCH → RAVEL；Serving：FlashAttention / KV → Adaptive Compute → Runtime Contract → Google DLB；算法 Agent：AutoRecLab → EvoPilot。
问题 01 · 多目标生成式召回为什么不能只调 Reward Weight？

Single Reward → Reward Fusion → Objective-specific Policy Portfolio

核心矛盾：CTR、relevance、eCPM/GMV 梯度方向不同，一个 scalar reward 会让强目标压制弱目标；固定 beam search 又无法显式配置固定候选预算内的目标供给。

承接关系：OneRec / OneSearch 证明 generative retrieval 能接受业务 preference → VARG/GR4AD 把 value alignment 前移 → UniPolicy 让不同 objective 拥有独立 policy path、共享 backbone。

问题 02 · 生成式推荐一定要直接生成 Item 吗？

Static Template → Direct Item Generation → Intent Planning + Catalogue Fulfilment

核心矛盾：直接生成 item 把用户理解、主题规划、目录合法性、召回和文案绑在一个 decoder；静态 shelf template 又覆盖不了长尾兴趣。

代表工作：Spotify Hypothesis-Driven Shelf Generation 先生成自然语言 hypothesis，再 constrained generative retrieval、candidate selection、shelf alignment。

问题 03 · 为什么单条 Reasoning Chain 不足以做复杂重排？

Cross-Encoder → Single-CoT Reranker → Multi-Trajectory Evidence Integration

核心矛盾：相关性包含 intent、evidence、constraint、context；单条 CoT 会把一次误判放大成最终 ranking error。

关键推进：MERIT-Rank 建立 Multi-Trajectory Reasoning Space，让互补 reasoning path 由 joint reranker 汇总；MSS-Complement 从另一侧把 pointwise relevance 推到 set sufficiency。

值得押注：trajectory router、uncertainty-triggered reasoning、coverage-aware list optimization、verifier early exit。

问题 04 · Top-K 都相关，为什么 Agent 仍缺证据？

Pointwise Relevance → Diversity → Set Sufficiency → Missing Complement

核心矛盾：复杂决策需要一组互补事实，而传统 reranker 对 passage 独立打分，容易让 Top-K 被同一事实重复占满。

代表工作：MSS-Complement / SERBench 将任务定义成在当前 Agent state 下恢复缺失的 Minimal Sufficient Evidence，Complete-MSS@5 从 61.4% 提到 73.0%。

值得押注：marginal sufficiency gain、set-level loss、coverage-aware source routing；推荐侧对应 multi-interest gap filling。

问题 05 · 超大库存下，个性化深度与覆盖广度为什么不该由一个检索器同时承担？

Single ANN Frontier → CPU/GPU Co-processing → Independent Depth–Breadth Retrieval Portfolio

核心矛盾：GPU 适合 interaction-heavy 深建模但 HBM 昂贵；CPU 适合超大库存却跑不起同等级交互模型。单一 homogeneous tier 会被迫在 personalization depth 与 inventory breadth 之间妥协。

关键推进：Hybrid GPU–CPU Retrieval 不再把 CPU/GPU 当一次 ANN 的协同设备，而是构建独立 inventory + model family：GPU 约 billion-scale 深路径，CPU 约 20× 更大广路径，并行执行后去重进共享 ranker。

证据：完整 Hybrid DCG@20 +4.51%，GSRR +2.01%；matched broad-inventory plan 中 accelerator 年化容量成本约 CPU 的 4×。

值得押注：learned pathway selector、candidate quota、inventory freshness-aware routing、generative/dense/sparse/late-interaction 的统一 portfolio。

问题 06 · 如果召回已经失败，为什么还要让 LLM 昂贵地“自信回答”？

Raw Similarity → Retrieval Confidence → Escalation / Abstention Policy

核心矛盾：Multi-hop retrieval failure 会集中在结构性 regime；单 top-score/margin 不稳定，而生成后的 semantic entropy 又发生得太晚。

关键推进：RegimeAbstain 用最多 9 个 query/ANN structural feature 学 calibrated Retrieval Confidence Score，计算 <1ms、无需额外 LLM。

Research Impact Score / 研究价值 9.1/10 · 工业成熟度 ★★★☆☆ · 创新性 ★★★★☆ · 与你方向的相关度 ★★★★★ · 是否官方开源 未确认 · 是否有线上 A/B 否 · 阅读优先级 S

证据：MuSiQue LLM-judge 场景 50% coverage 下 CWAR 39.5%→20.6%，ECE=0.035。

值得押注：confidence 不应只触发拒答，而应触发 {expand K, switch retriever, query rewrite, deep search, ask user, abstain}。

问题 07 · Agent 下一步应该问什么，为什么不能靠离线“好问题”标签？

Offline Question Ordering → Sequential Information Acquisition → Retrieval-aware RL

核心矛盾：一个问题的价值取决于它实际获得的回答以及回答如何改变排序；discriminative-looking question 与真实 rank gain 相关很弱。

关键推进：RAVEL 让 questioner 观察 current Top-4，生成 free-form question，并用完整 question→answer→retrieval loop 的 reciprocal-rank improvement 做 GRPO reward。

证据：Interactive-PEDES 第 5 轮 R@1 73.73，相对 LLaVA-ReID +5.79pp。

值得押注：将 ask/rewrite/retrieve/tool/halt 合并成同一 evidence-acquisition action space。

问题 08 · 长期 Memory 为什么不能只存成一个混合向量空间？

Flat Memory → Fixed Schema → Self-configuring Orthogonal Views

核心矛盾：偏好、事件、约束、时间更新混在一起会产生 semantic interference；query-time 加复杂 router 又增加 latency 和 failure mode。

关键推进：AutoViewMem 自动发现互补 view，把 disentanglement 前移到 write-time；每条 memory 带 view/timestamp/provenance，读取仍是统一 index 上普通 Top-K。

问题 09 · 长上下文与 Decode 为什么要固定计算路径？

Full Compute → Static Sparse → On-Demand Attention / Draft Switching → Execution Routing

核心矛盾：full attention / 单一 draft strategy 对所有 token 付同样成本；静态 sparse 又可能永久漏信息。

代表工作：On-Demand Attention 用 recall head 决定何时 global read；SwitchSD 在 neural draft / context copy 间切换；9/21 的 sparse/mHC/precision runtime merge 进一步要求执行路径理解模型内部 state。

问题 10 · Model 已经选好了，为什么“把请求发到哪台机器”仍值得学习？

Weighted Routing → RIF-aware Routing → Learned Latency Control + Affinity

核心矛盾：GenAI 请求 service time 跨多个数量级；connection count / 静态权重不能表达 continuous batching、异构硬件、prefill/decode 与实时 queue。

关键推进：Google DLB 通过 root/leaf 两级路由、peer probing、cell-specific latency model、discrete/flow routing 与 prefix affinity 建立 learned global control plane。

证据：p50 latency -17%、p95 -13%，平均可运行约 20% hotter；router compute 约 accelerator compute 的 0.04%。

值得押注：model selection 与 cell routing 联合；KV/cache locality；prefill/decode placement；quality-latency-cost-SLO 统一 policy。

问题 11 · Agent 能跑完实验，为什么仍可能得出完全错误的结论？

Code Agent → Executable Experiment Agent → Pairwise Evidence Admission

核心矛盾：一个 run “成功”不代表 control/treatment 可比较；code no-op、data window、evaluator drift、candidate depth、serving funnel 都可能让结论失效。

承接关系：AutoRecLab 解决自然语言 RecSys 实验如何通过 RAG/type check/execution feedback 跑起来；EvoPilot 更进一步解决生产实验如何被验证为“可承认的证据”。

关键证据：EvoPilot 发现 control/treatment 实际 K_eff=3000/600 的隐性 mismatch；修复后 matched offline +3.20pp，最终线上 GSRR +0.66%。

值得押注：dataset/evaluator fingerprint、artifact equivalence、自动 verifier synthesis、incident→CI guard、实验 provenance graph。

问题 12 · 模型结构进入生产后，为什么“支持模型”还远远不够？

Generic Runtime → Model-specific Kernels → Architecture-aware Execution Contract

核心矛盾：Sparse attention、mHC、MoE router precision、speculative draft KV、SSM state layout 都会让“同一个 tensor API”背后存在不同 correctness 与性能语义。

代表证据：9/21 Runtime 专场：Qwen4 Sparse FA、vLLM/SGLang mHC、MiMo V2 BF16 router + MXFP4 expert、Spec KV fix、Ascend GDN state layout、Milvus cache correctness。
