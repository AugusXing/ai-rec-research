Research Problem Map · 更新至 2026.09.20

沿“核心矛盾”读论文，而不是沿发布时间堆论文

Paper Map 的目标是回答：上一阶段到底解决了什么？为什么仍不够？下一篇工作把矛盾推进到了哪里？ 今天新增 7 个研究节点：多目标生成式 Policy、Multi-Trajectory Rerank、On-Demand Attention、Self-Retiring Distillation、开放 Sparse Retrieval、Full-pipeline DeepSearch Reward、Model-aware Tool Learning。

当前优先精读路线：生成式推荐 / 召回：TIGER → OneRec / OneSearch → VARG / GR4AD → Spotify Hypothesis Shelf → UniPolicy；重排：Cross-Encoder → Listwise / Reasoning Rerank → MSS-Complement → MERIT-Rank；检索：BM25 → Dense → SPLADE → Late Interaction → SPARSEUP → Query-conditioned Hybrid；Agent RL：GRPO → OPD/OPSD → RetireOPD；Serving：FlashAttention / KV Cache → Speculative Decoding → SoL-Pi → ODA / SwitchSD；Agent Search：ORDER / DiBud → MSS-Complement → F²DR / MATCH。
问题 01 · 多目标生成式召回为什么不能只调 Reward Weight？

Single Reward → Reward Fusion → Objective-specific Policy Portfolio

核心矛盾：CTR、relevance、eCPM/GMV 等目标梯度方向不同，把它们压成一个 scalar reward 会出现强目标支配弱目标；而固定 beam search 又无法在候选预算内显式配置各目标供给。

承接关系：OneRec / OneSearch 证明 generative retrieval 可以接受业务 preference → VARG/GR4AD 把 value alignment 前移 → UniPolicy 进一步让不同 objective 拥有独立 policy path，但共享 backbone。

工业证据：7-day online A/B：CTR +0.71%、RPS +1.58%、revenue +1.32%。

成熟度：高，已经是工业 generative retrieval 的可部署设计，但 policy quota 仍主要由业务配置。

值得押注：learned quota controller、long-term objective、policy calibration、目标自动增删、policy interference measurement。

问题 02 · 生成式推荐一定要直接生成 Item 吗？

Static Template → Direct Item Generation → Intent Planning + Catalogue Fulfilment

核心矛盾：直接生成 item 把用户理解、主题规划、目录合法性、召回和文案都绑在一个 decoder；静态 shelf template 又覆盖不了长尾兴趣。

关键工作：Spotify Hypothesis-Driven Shelf Generation 先生成自然语言 hypothesis，再 constrained generative retrieval、candidate selection、shelf alignment，并离线预计算进入 Home ranking。

承接：Semantic ID 解决“怎么生成地址” → value-aware policy 解决“生成哪些地址” → hypothesis layer 解决“为什么要生成这些地址”。

值得押注：intent quality reward、intent→coverage→ranker survival 的跨阶段 credit、freshness / recompute budget。

问题 03 · 为什么单条 Reasoning Chain 不足以做复杂重排？

Cross-Encoder → Single-CoT Reranker → Multi-Trajectory Evidence Integration

核心矛盾：相关性不是单一语义相似，而是 intent、evidence、constraint、context 等多因素；单条 CoT 会把一次误判放大成最终 ranking error。

关键推进：MERIT-Rank 建立 Multi-Trajectory Reasoning Space，让多个互补 reasoning path 再由 joint reranker 汇总，并用 Progressive Rank Policy Optimization 分阶段稳定轨迹。

Research Impact Score / 研究价值 9.3/10 · 工业成熟度 ★★★☆☆ · 创新性 ★★★★★ · 与你方向的相关度 ★★★★★ · 是否官方开源 否 · 是否有线上 A/B 否 · 阅读优先级 S+

结果：4B 模型在 BRIGHT 已超过多数 7B、部分 32B reranker；相对同规模 eRank 约 +6.1%。

承接关系：MSS-Complement 解决“Top-K 是否覆盖必要事实” → MERIT-Rank 解决“单个候选是否需要多视角判断”。下一步是 set-level + multi-trajectory 的统一 list rerank。

值得押注：trajectory router、uncertainty-triggered reasoning、verifier early-exit、listwise multi-perspective RL。

问题 04 · Top-K 都相关，为什么 Agent 仍缺证据？

Pointwise Relevance → Diversity → Set Sufficiency → Missing Complement

核心矛盾：复杂决策需要一组互补事实，而传统 reranker 仍对 passage 独立打分，导致 Top-K 被同一事实重复占满。

关键工作：MSS-Complement / SERBench 将任务定义为在当前 Agent state 下恢复缺失的 Minimal Sufficient Evidence。Complete-MSS@5 从 61.4% 提到 73.0%，@8 从 72.4% 到 80.6%。

值得押注：marginal sufficiency gain、set-level loss、coverage-aware source routing；推荐侧对应 multi-interest gap filling。

问题 05 · Dense 是默认方案后，Sparse Retrieval 还有必要吗？

BM25 → Dense → Learned Sparse / Late Interaction → Query-conditioned Retrieval Portfolio

核心矛盾：Dense semantic matching 强，但 rare lexical/entity、可解释性和倒排兼容并不总占优；Late Interaction 质量高但索引/Serving 更复杂。

关键推进：SPARSEUP 以 149M ModernBERT 构建开放 learned sparse baseline，通过 logit shift=15、per-position top-k=12、case folding 控制 expansion。

Research Impact Score / 研究价值 9.0/10 · 工业成熟度 ★★★★☆ · 创新性 ★★★★☆ · 与你方向的相关度 ★★★★★ · 是否官方开源 是（Apache 2.0） · 是否有线上 A/B 否 · 阅读优先级 S

证据：BEIR-13 56.4 nDCG@10；同 backbone/data 下比 DenseOn -1.52，但 MS MARCO + Seismic 在 >97% recall 时约 380µs/query，且 token-weight 可直接检查失败原因。

成熟度：中高，适合作为 hybrid recall 生产候选，不宜解读为“sparse 重新全面超过 dense”。

值得押注：学习 query-conditioned dense/sparse/late route；稀疏表征 attribution；multilingual latent sparse vocabulary。

问题 06 · 长上下文每一步都要读全历史吗？

Full Attention → Static Local/Sparse → On-Demand Global Recall

核心矛盾：full attention 在每个 decoding token 付全历史成本；static local 又会永久漏掉远程依赖。

关键推进：On-Demand Attention 用轻量 recall head 从 local-first state 预测 global read 的价值，只在需要时触发 global attention，同时保留完整历史 KV 供后续 recall。

Research Impact Score / 研究价值 9.4/10 · 工业成熟度 ★★★★☆ · 创新性 ★★★★★ · 与你方向的相关度 ★★★★☆ · 是否官方开源 否 · 是否有线上 A/B 否 · 阅读优先级 S+

证据：作者在 vLLM 做 GPU-side conditional execution；长上下文低 global-call setting 中主要 decoding FLOPs 可下降约 76%，单请求吞吐最高约 1.98×。

值得押注：token/layer 双粒度 controller、batch divergence、SLO-aware recall threshold、与 retrieval/KV compression 联合。

问题 07 · Speculative Decoding 为什么要固定一种 Draft Strategy？

Neural Draft vs Context Copy → Model-aware Dynamic Switching

核心矛盾：neural draft 泛化稳；context copy 在重复结构中更快，但 n-gram overlap 容易产生 false trigger。

关键推进：SwitchSD 用 target-model internal representation 的轻量 probe 判断 genuine copy-intent，再动态切 neural draft / context copy。

证据：copy-intent probe AUC >0.99；Llama/Qwen 上相对 EAGLE3 最高约 +15% throughput。

值得押注：把 decoding strategy 变成通用 execution action，与 ODA、reasoning effort、batch scheduling 一起由 runtime controller 选择。

问题 08 · Teacher 应该监督 Student 多久？

Fixed Distillation → Annealing → Signal-dependent Teacher Retirement

核心矛盾：teacher 早期能提供 dense guidance，但 student 变强后继续模仿可能与 environment reward 冲突；固定退火不能适应不同学习速度。

关键推进：RetireOPD 监控 teacher-student discrepancy 与 relative competence，一旦 transfer 停滞且 student 足够强，直接移除 OPD。

证据：ALFWorld +14.1%～18.8%、WebShop +11.8%～19.0% over RL baseline，并超过自己的 teacher。

值得押注：teacher re-entry、per-skill retirement、multi-teacher routing、distillation cost-aware training。

问题 09 · DeepSearch 为什么不能只评 Final Answer？

Answer Score → Content + Trajectory + Answer Full-pipeline Reward

核心矛盾：最终答案可能碰巧正确，但中间 retrieval/trajectory 极差；也可能 evidence 很好，但 answer synthesis 失败。只看最终 score 无法给中间 action 做 credit。

关键推进：F²DR 建立 Content / Trajectory / Answer 三维 reward framework，并提出 DeepSearch RM-Bench。

值得押注：把 latency/cost/source diversity/evidence sufficiency 加入 reward，形成真正的 task-success-per-dollar objective。

问题 10 · Tool Learning 的 Reward 为什么会“漏分”？

Additive Tool Reward → Hierarchically Gated Credit + Capability-aware Curriculum

核心矛盾：tool name 都错时仍给 argument value credit，会教坏 policy；固定 curriculum 很快偏离模型当前能力边界。

关键推进：MATCH 用 HTGR 按 tool name → arg key → arg value 逐级 gate，再用同一 reward 动态更新样本 difficulty，形成 curriculum-policy 闭环。

结果：API-Bank 72.19%、BFCL V3 62.87% overall accuracy。

值得押注：推荐/搜索里的结构化 action 同样可用 gated reward：先选 source，再选 retrieval mode，再选 top-K/filters；错误的父 action 不给子参数奖励。

问题 11 · 历史案例为什么不能只压成一个静态向量？

Whole-document Retrieval → Mutable Memory → State-addressable Trajectory

核心矛盾：整体相似不代表当前阶段相似。一个故障 case / 用户 session 在早期探索、比较、决策、复购阶段需要完全不同的下一步。

关键工作：RAFT 将历史 case 拆成 directed timeline entry，按 active state 检索相似中间态，再返回 parent-case 后续 trajectory。

值得押注：session-stage index、success-conditioned trajectory retrieval、temporal hard negatives、state TTL/version/provenance。

Paper Map 的押注结论：短期最值得投入的是 Multi-objective Generative Retrieval、Multi-Trajectory / Set-level Re-ranking、Query-conditioned Hybrid Retrieval、Adaptive Compute、Stateful Memory。它们共同指向同一个系统形态：不是让一个模型永远做同样的事，而是让系统根据 objective、state、uncertainty 与 budget 选择正确的执行路径。
