不是按论文年份，而是按“核心矛盾”读推荐与搜索

Paper Map 把工作放进问题链：一个方法解决了什么、为什么仍不够、下一篇如何承接。今天新增的节点共同指向一个主题：Recommendation / Search 的控制面正在可学习化——Evolution Direction、Retrieval Program、Collaborative Memory、Attention Topology、Fresh Index 都开始成为模型直接优化的对象。

推荐精读路线：如果只读今天 5 篇，按 Astar → ProRetrieval → CoVeMem → MaskRec → Scaling GNN。第一篇理解“算法研发闭环如何被学习”；第二篇理解“检索 action space 如何被程序化”；第三篇理解“Agent memory 如何从文本转成 state”；第四篇理解“统一 Ranking 如何控制信息拓扑”；第五篇理解“工业规模下 representation / sampler 为什么比新 GNN 层更关键”。
问题 01 · 系统如何学会“下一步改什么”？

Human Experimentation → Coding Agent → Self-Evolving Algorithm System

核心矛盾：代码、训练、评估已经高度自动化，但 evolution direction 仍依赖少数专家；通用 LLM 缺少业务内隐经验。

承接关系：AutoML/HPO 只能搜索预定义空间 → Coding Agent 自动实现人类 proposal → Astar 直接学习 proposal 本身，把 Git commit、实验曲线与 Reward Model 变成训练资产。

代表 Paper：Astar。Lazada 广告闭环连续自动迭代 20 次；Hitrate@200 +23.6%，线上 GMV +4.86%、广告收入 +1.82%。

成熟度判断：已经越过“Agent demo”阶段，真正进入生产算法研发流程；但跨业务迁移、Reward Model 偏置和长期多目标仍未解决。

值得押注：Experiment History Foundation Data、Evolution Reward Model、自动实验设计、成本感知 proposal ranking、失败实验反事实学习。

问题 02 · 复杂 Query 应该如何编排多个检索器？

One Retriever → Fixed Fusion → Executable Retrieval Program

核心矛盾：真实搜索同时有结构字段、文本语义、图片语义与布尔逻辑；单 ANN、RRF 或 self-query 都只有固定组合形式。

承接关系：BM25/Dense → Hybrid/RRF → Search-R1 式单后端 tool use → ProRetrieval 把 SQL/Text ANN/Image ANN 放入统一 DSL，让 LLM 生成可执行 program。

Research Impact Score / 研究价值 9.7/10工业成熟度 ★★★☆☆创新性 ★★★★★与你方向的相关度 ★★★★★是否官方开源 是 / 匿名仓库是否有线上 A/B 否阅读优先级 最高

代表 Paper：ProRetrieval。Qwen3-4B GRPO 电商 Hit@1 0.809，对 GPT-5.5 的 0.693；端到端约 50ms/query。

成熟度判断：DSL 与执行器形态非常工业化，但 benchmark 仍主要自动构造，尚缺真实流量 A/B。

值得押注：Cost-aware Program、执行失败自修复、多轮 retrieval planning、typed tools、candidate generation + rerank 统一 action language。

问题 03 · Agent Memory 应该存“文字”，还是存“状态”？

Text Profile → Collaborative Text Memory → Trainable Vector Memory

核心矛盾：自然语言记忆可读但损失协同结构，逐交互重写又昂贵；传统 CF state 信息强却无法直接被 LLM 理解。

承接关系：Profile Prompt → MemRec 等协同文本记忆 → CoVeMem 用 LightGCN state bank 保存 evidence，用 gated projector + LoRA 学会读取 soft-token memory。

Research Impact Score / 研究价值 9.5/10工业成熟度 ★★★☆☆创新性 ★★★★★与你方向的相关度 ★★★★★是否官方开源 否 / 未确认是否有线上 A/B 否阅读优先级 最高

代表 Paper：CoVeMem。对最强 text-memory Agent 在 20 个指标单元中 19 个持平或更优，并消除逐交互 LLM memory maintenance。

成熟度判断：结构方向非常合理，但当前候选集仅 10，且 memory bank 静态冻结。

值得押注：Streaming Vector Memory、分层 ANN Memory、跨召回/精排共享 State Store、memory update policy 与 privacy-aware local state。

问题 04 · 统一 Ranking Backbone 怎样避免“所有信号互相污染”？

Separate Modules → Full Token Mixing → Topology-constrained Unified Backbone

核心矛盾：分模块交互太晚；全连接 Transformer 又让无关 domain、feature、sequence 过度互相注意。

承接关系：DIN/DeepFM 等多模块 → OneModel/Unified Token → MaskRec 用 TopoMask 规定 token connectivity，DualQ 在 backbone 前显式构造 candidate-conditioned interaction。

Research Impact Score / 研究价值 9.4/10工业成熟度 ★★★★☆创新性 ★★★★☆与你方向的相关度 ★★★★★是否官方开源 否 / 未发现是否有线上 A/B 否阅读优先级 最高

代表 Paper：MaskRec。腾讯广告比赛 CVR Test AUC 0.824902→0.834640；去掉 DualQ 和破坏 dense token 组织都退化。

成熟度判断：工业 benchmark 强，线上 serving 未验证；Topology 仍靠人工设计。

值得押注：Learnable Sparse Topology、Request-aware Mask、跨阶段 Token Graph、Topology × Latency 联合学习。

问题 05 · GNN 到底怎样扩到真实推荐图？

Full ID Table / Naive Sampling → Hash Representation + Temporal Data Structure

核心矛盾：图推荐在论文规模常讨论 message-passing layer，在生产规模首先卡住的是数百 GB ID table、时间泄漏和高 degree 邻接扫描。

Research Impact Score / 研究价值 9.8/10工业成熟度 ★★★★★创新性 ★★★★☆与你方向的相关度 ★★★★★是否官方开源 是是否有线上 A/B 是阅读优先级 最高

代表 Paper：Scaling GNN for Friend Recommendation。194M 用户 / 28B 边，Multi-hash 2GB 替代约 203GB full table；Temporal binary-search sampler 595ms vs naive 1473ms；线上好友新增 +16%。

承接关系：GraphSAGE/PinSage → Industrial neighbor sampling → 本文把 ID representation 与 temporal correctness 同时做成一等系统设计。

值得押注：Online graph state、continuous memory、heterogeneous multi-hash、Graph×Sequence dual state、refresh cadence routing。

问题 06 · 多模态推荐怎样区分“内容是什么”与“内容怎么变化”？

Holistic Video Embedding → Static/Dynamic Factor → Preference-conditioned Flow

Research Impact Score / 研究价值 8.9/10工业成熟度 ★★★☆☆创新性 ★★★★☆与你方向的相关度 ★★★★☆是否官方开源 否 / 未发现是否有线上 A/B 否阅读优先级 高

代表 Paper：PrismRec。频域 Spectral Semantic Factorization 将 frame sequence 分为 static / dynamic factor，再按用户敏感度作为 Flow Matching condition；四数据集最高 +22.65%。

值得押注：内容 factor 与 Semantic ID 的联合 tokenization、frame-level dynamic preference、Flow/Diffusion 在候选生成中的 latency 约束。

问题 07 · Post-training 怎样避免只把最优路径越训越窄？

GRPO Pass@1 → Entropy Collapse → ES Reasoning Coverage

Research Impact Score / 研究价值 8.9/10工业成熟度 ★★☆☆☆创新性 ★★★★☆与你方向的相关度 ★★★☆☆是否官方开源 否 / 未发现是否有线上 A/B 否阅读优先级 高

代表 Paper：Understanding ES for LLM Reasoning。ES 在提升 Pass@1 同时保持更高 Pass@K；Sequential GRPO→ES 试图兼得单解精度与探索覆盖。

对推荐的迁移问题：生成式召回若只优化 Top-1 reward，是否也会出现 candidate entropy collapse？值得把 Coverage / Diversity / Novelty 作为 policy-level 指标。

问题 08 · 商品目录变化时，推荐索引怎样保持正确？

Static Index → Full Rebuild → Delta-aware Self-refresh

代表 Paper / System：Conversational Recommendation over Live E-Commerce Catalogues。Per-item hash 检测 new/changed/deleted/unchanged，仅对 delta enrichment + embedding，再同步 vector index；官方 GitHub 提供完整 Demo。

值得押注：Catalog CDC、Embedding Version、Hard Availability Filter、Fresh Semantic ID 与 deletion consistency 应统一成 Retrieval Data Plane。

值得押注的 6 个问题：① Self-Evolving RecSys：能否自动提出并验证模型演进方向？② Retrieval Programming：LLM 能否生成成本可控、可验证的检索程序？③ Vector Memory：用户长期状态能否跨 Agent / Recall / Ranking 共享？④ Learnable Topology：统一模型的信息连接能否按请求自适应？⑤ Fresh State：graph/index/SID 怎样增量更新而不全量重算？⑥ Coverage-aware RL：生成式推荐如何避免 preference optimization 把候选空间越训越窄？
