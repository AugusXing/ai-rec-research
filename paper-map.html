主线 A

Generative Recommendation 主链

从“生成候选”一路走到“替代整个 Cascade”。

1. Generative Retrieval / 端到端生成

核心变化：把 Item 当 Token，把推荐改写为条件生成问题。

OneRec-V2→问题转向：怎么 Scale、怎么低成本 Serving？
2. Semantic ID 成为基础设施

生成模型能不能泛化、覆盖长尾、支持 Fresh Item，很大程度取决于 Item Tokenizer。

FORGE→问题转向：Token 如何同时承载语义与协同信息？
3. Foundation Model

仅靠行为序列会让模型成为更强的 pattern matcher；下一步是把语言知识、指令和推荐统一。

OpenOneRec→问题转向：Foundation Model 是否真的会“理解”用户？
4. Reasoning / RL / Full-stack

从 next-item prediction 进入显式偏好归纳、列表决策和全链路统一。

OneReasonGR2Sona
★★★★★ 当前判断：Sona 已经给出“完整 Cascade 可被统一生成模型替代”的强线上信号，但 Coverage / Exploration / Serving 仍是关键短板。
主线 B

Ranking / Re-ranking：从判别模型到 Policy

重点不再只是“打一个更准的分”，而是让模型直接做列表级决策。

1. 判别式 Ranker

CTR/CVR/GMV 多目标模型 + hand-crafted feature 是成熟基线，但阶段割裂、特征维护重。

瓶颈：Feature Engineering 与 Stage-specific Representation。
2. LLM-backed Ranking

把用户历史和上下文 verbalize，尝试从 Feature Engineering 迁移到 Context Engineering。

Netflix GenRec
3. Reasoning + RL Re-ranking

让模型先理解偏好，再做 listwise decision；同时引入 RLVR / reward alignment。

GR2→问题转向：Reward Hacking 与推理成本。
4. LLM 作为 Strategy / Policy Layer

不让 LLM 直接生成 Item，而是生成结构化 Ranking Strategy，再交给成熟线上 Ranker 执行。

MetaStrategy
★★★★☆ 当前判断：短期工业落地上，“LLM Policy + Traditional Executor”可能比完全替代 Ranker 更稳。
主线 C

Recommendation RL / Preference Alignment

真正难的不是 PPO 还是 GRPO，而是 Reward 到底代表什么。

1. Offline Supervised Learning

优化 next-item / click label，容易被短期目标绑架。

2. 真实反馈进入 Post-training

OneRec-V2 开始把 watch duration / interaction feedback 更直接地带入策略优化。

OneRec-V2
3. GRPO / RLVR 进入召回与重排

JD GenRec、GR2 把 RL 带入 Generative Retrieval / Re-ranking，但同时暴露 reward hacking、position bias、policy collapse。

JD GenRecGR2
4. Long-term Reward

真正未解的是留存、疲劳、探索、生态与 GMV/体验的长期统一。

★★★☆☆ 当前判断：Reward Design 的重要性已经超过“用哪种 RL 算法”。
主线 D

Agentic Search / RAG：从 Retrieval 到 Context Ranking

Retriever 不再只是固定工具，而逐渐成为 Agent Policy 的一部分。

1. Retriever 只优化相关性

Query–Document Similarity 很强，但未必真正帮助最终回答。

2. Answer-aware / Agent-aware Retrieval

让“是否帮助最终回答正确”反过来训练 Retriever。

Agentic-R
3. Retriever + Reasoner Joint RL

Reasoning Agent 和 Generative Ranker 一起优化，检索成为可学习行动。

CoSearch
4. Interaction Space / Context Refinement

下一阶段不是“更多文档”，而是给 Agent 一个更干净、更可操作的 Evidence Workspace。

RISEContext Interference
★★★☆☆ 当前判断：Context Ranking / Evidence Selection 很可能成为下一代 Search/RAG 的独立 Ranking 层。
主线 E

Scaling / Serving：让“能做”变成“能上线”

生成式推荐最终要和毫秒级系统、巨大流量和成本约束正面冲突。

1. Context Encoding 成本

长行为序列使 Transformer 计算大量浪费在 Prefill / Encoding。

OneRec-V2
2. Scaling Law 变成任务相关

Netflix 的工作提示：不是所有推荐任务都能靠“继续增大模型”获得收益。

Netflix Scaling
3. Serving 特化

Prefill-only inference、History Compression、Distillation、MoE、KV Cache、Test-time Budget 都开始进入主线。

Netflix GenRecSona
4. Adaptive Compute

未来可能不是所有请求都调用同一模型、同一思考长度。

★★★☆☆ 当前判断：Per-request compute allocation 会和 Model Routing / Adaptive Reranking 合流。
主线 F

Model Routing：推荐工程师很值得迁移的方向

Agent Serving 正在复刻推荐系统里的 Cascade / Router / Ranker 思想。

1. Frontier Model Everywhere

质量高但成本和延迟不可控。

2. Planner / Executor 分工

强模型做规划与复杂推理，小模型做 Tool Calling、Validation、Routine Execution。

3. Learned Router

根据任务难度、质量、成本、Latency、当前 Agent State 动态选模型。

★★★☆☆ 当前判断：这个问题与“候选模型排序”高度同构，推荐/搜索工程师的 Ranking、Calibration、Bandit、Cascade 经验都可迁移。

推荐阅读路线

路线 1 · 想研究生成式推荐主架构

  1. OneRec-V2：先理解 Scale / Serving 为什么是第一道门槛
  2. FORGE：理解 Semantic ID 为什么决定生成空间
  3. OpenOneRec：理解 Recommendation Foundation Model 的目标
  4. OneReason：看显式 Reasoning 为什么不是简单加 CoT
  5. GR2：看 Reasoning + RL 如何进入 Re-ranking
  6. Sona：最后看 Full-stack Replacement

路线 2 · 想研究重排 / 生成式重排

  1. Netflix GenRec：LLM Ranker 与 Context Engineering
  2. GR2：Reasoning + RLVR 的直接重排路线
  3. MetaStrategy：LLM Policy + Traditional Executor 的渐进式路线
  4. 再结合每日 Reranker Study：研究何时值得调用昂贵 Reranker

路线 3 · 想研究 Search / RAG / Agent

  1. Agentic-R：Retriever 从 relevance 转向 answer-aware
  2. CoSearch：Retriever 与 Reasoner Joint RL
  3. RISE：Retrieval 变成 Interaction Space
  4. Context Interference：Context Refinement / Context Ranking
